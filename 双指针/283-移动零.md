# 283 移动零

- 难度：简单
- 标签：数组、**双指针**
- 力扣链接：https://leetcode.cn/problems/move-zeroes/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「方法一：双指针」。正文主解是 **一次遍历的双指针交换法**（官方推荐，操作次数最少）；另一种「快慢指针填 0」写法放在「复盘」作对比。

## 题目描述

给定一个数组 `nums`，编写一个函数将所有 `0` 移动到数组的末尾，同时保持非零元素的相对顺序。

**请注意** ，必须在不复制数组的情况下**原址**对数组进行操作。

**示例 1:**

```
输入: nums = [0,1,0,3,12]
输出: [1,3,12,0,0]
```

**示例 2:**

```
输入: nums = [0]
输出: [0]
```

**提示:**

- `1 <= nums.length <= 10^4`
- `-2^31 <= nums[i] <= 2^31 - 1`

**进阶：** 你能尽量减少完成的操作次数吗？

## 思路

> 本题主要参考力扣官方题解的「双指针」做法。

要求「原址」+「保持非零元素相对顺序」，意味着不能用新数组接结果，得在 `nums` 上动手脚。

**最朴素想法**：开一个新数组，扫一遍把非零的按顺序塞进去，剩下位置补 0。能做对，但违反「不复制数组」的要求。退一步，**不开新数组，但在原数组上「先收集非零、再补零」**也行——这就是「快慢指针填 0」法（复盘里讲）。它写起来直观，但要**两次遍历**：一次搬非零、一次补 0。

**官方主解（一次遍历）**：用「交换」代替「先搬后补」，一趟搞定。

定义两个指针：

- `left`：始终指向**已处理区间末尾的下一个位置**（也就是下一个非零元素该放的地方）。`[0, left)` 范围内是非零元素，`[left, right)` 范围内是已扫过的 0。
- `right`：**扫描指针**，从左往右遍历整个数组。

算法：

1. `left = right = 0`，开始时「已处理区间」为空。
2. `right` 往右走：
   - 若 `nums[right] != 0`：它是个非零元素，**应当落在 `left` 位置**。于是交换 `nums[left]` 和 `nums[right]`，然后 `left++`（已处理区间扩大一位）。
   - 若 `nums[right] == 0`：什么都不做，`right` 继续往前（这个 0 暂时留在 `[left, right)` 区间里）。
3. `right` 走到头时，所有非零元素都被依次交换到了数组前部，0 自然被「挤」到了末尾。

**举例** `nums = [0,1,0,3,12]`：

```
初始  left=0 right=0  [0,1,0,3,12]   nums[0]=0 → 跳过
      left=0 right=1  [0,1,0,3,12]   nums[1]=1≠0 → swap(0,1) → [1,0,0,3,12], left=1
      left=1 right=2  [1,0,0,3,12]   nums[2]=0 → 跳过
      left=1 right=3  [1,0,0,3,12]   nums[3]=3≠0 → swap(1,3) → [1,3,0,0,12], left=2
      left=2 right=4  [1,3,0,0,12]   nums[4]=12≠0 → swap(2,4) → [1,3,12,0,0], left=3
      right=5 越界，结束。结果 [1,3,12,0,0] ✓
```

**为什么满足「进阶：最少操作次数」？**

每个非零元素**最多被交换一次**（从 `right` 位置换到 `left` 位置后，`left` 就右移了，不会再碰它）。不存在「先搬过去再被覆盖」的重复搬运。赋值次数为「非零元素个数」量级，这是该问题的最优。

## 代码

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int n = nums.size(), left = 0, right = 0;
        // 不变式（invariant）：
        //   [0, left)        —— 已经就位的非零元素（相对顺序保持）
        //   [left, right)    —— 已经扫到、但值为 0 的位置（会被后续非零元素交换覆盖）
        //   [right, n)       —— 尚未扫描的部分
        while (right < n) {
            if (nums[right]) {           // nums[right] != 0 的简写（0 转 bool 为 false，非零为 true）
                // swap：C++ STL 算法，原型 swap(a, b) 交换两个同类型对象的值。
                //   - 这里把当前非零元素换到 left 指向的「下一个非零位置」。
                //   - 对 int 是直接三次移动（tmp=a; a=b; b=tmp），O(1)。
                //   - 注意 swap 还可用于任意类型（含自定义类），复杂度取决于该类型的移动代价。
                swap(nums[left], nums[right]);
                left++;                  // 已处理区间右扩一位
            }
            // nums[right]==0 时什么也不做：这个 0 留在 [left,right) 区间，等后面非零元素来交换
            right++;                     // 扫描指针始终右移
        }
    }
};
```

## 复杂度

- **时间**：O(n)
  - `right` 把数组扫一遍，每步最多一次 `swap`（O(1)），共 n 步。
  - 这也是「进阶」要求的最少操作：每个非零元素至多被交换一次。
- **空间**：O(1)
  - 原址操作，只用了 `left` / `right` 两个下标变量。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么 `if (nums[right])` 能判断「非零」？负数怎么办？

C++ 里 `int` 转 `bool` 的规则：**非零为 `true`，零为 `false`**。负数（如 `-5`）也是「非零」，转 bool 是 `true`，会被正确当作非零元素处理。所以 `if (nums[right])` 等价于 `if (nums[right] != 0)`，是力扣常见的简写。

如果题目改成「把所有偶数移到末尾」，就不能用这种隐式转换了，得显式写 `if (nums[right] % 2 != 0)`。

### Q2：`left` 和 `right` 交换时，会不会破坏非零元素的相对顺序？

**不会**。这是本解法最妙的地方。

关键在于交换发生的时机：只有当 `nums[right] != 0` 时才交换，且交换的目标位置 `left` 严格递增。也就是说：

- 第 1 个被处理的非零元素 → 换到位置 0；
- 第 2 个 → 换到位置 1；
- 第 3 个 → 换到位置 2；
- ……

**非零元素按「被 `right` 扫到的先后」依次落位**，而 `right` 是从左到右扫描的，所以相对顺序天然保持。被交换出去到 `right` 位置的呢？要么是 0（不影响），要么……其实当 `nums[right]!=0` 时，`left` 和 `right` 之间全是 0（见不变式），交换只是把这个 0 挪到 `right` 位置，非零元素不会互相错位。

### Q3：`swap(nums[left], nums[right])` 当 `left == right` 时是不是多余？

是的，当 `left == right` 时（数组开头还没有遇到 0 的时候）交换是「自己和自己换」，无意义。官方代码没有特判，因为这种自交换是无害的（值不变，只是多一次赋值）。如果想极致优化，可以加 `if (left != right) swap(...)`，但可读性下降，力扣上也没必要。

## 复盘

- **核心套路**：**「把符合条件的元素挪到数组前部，其余留在后部」** 这一类**原址划分**问题，标准做法是「双指针 + 交换」。`left` 标记边界、`right` 扫描，命中条件就交换。相对顺序由「`left` 严格递增 + `right` 单向扫描」保证。
- **不变式思维**：写双指针前先想清楚 `[0,left) / [left,right) / [right,n)` 三段各自是什么含义，循环体只要维护这个不变式即可。这是所有双指针/划分类题的通用思考方式。
- **「交换法」vs「填 0 法」对比**：见下面解法二。交换法一趟完成、操作最少；填 0 法两趟、更直观但多一次遍历。力扣官方推荐交换法。

### 解法二：快慢指针填 0（两次遍历，对比用）

思路更直白：用一个慢指针 `slow` 记录非零元素该放的位置，快指针 `fast` 扫描——遇到非零就赋值到 `slow`、`slow++`。一趟扫完后非零元素已全部靠前，最后把 `[slow, n)` 全部置 0。

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int slow = 0;
        // 第一趟：把非零元素前移（覆盖式赋值，不交换）
        for (int fast = 0; fast < (int)nums.size(); ++fast) {
            if (nums[fast] != 0) {
                nums[slow++] = nums[fast];   // slow 后移；注意这里直接覆盖，不保留原 slow 处的值
            }
        }
        // 第二趟：把 [slow, n) 全部置 0
        for (int i = slow; i < (int)nums.size(); ++i) {
            nums[i] = 0;
        }
    }
};
```

- **时间**：O(n)（两次遍历，常数倍于交换法）
- **空间**：O(1)
- **对比**：写法更易理解（先搬非零、再补零），但**每个非零元素被赋值两次**（一次搬到前面，最后一次也没逃过被覆盖的命运取决于位置）。交换法每个非零元素只动一次，操作次数更少，是「进阶」的最优解。
- **注意**：`nums[slow++] = nums[fast]` 是覆盖不是交换——当 `fast > slow` 时，`slow` 处原本的值（是个 0 或已被搬走的非零）会被覆盖，所以最后必须显式补 0；这点和交换法不同（交换法靠交换保留了信息，不用补 0）。
