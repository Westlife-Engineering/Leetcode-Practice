# 11 盛最多水的容器

- 难度：中等
- 标签：贪心、数组、**双指针**
- 力扣链接：https://leetcode.cn/problems/container-with-most-water/?envType=study-plan-v2&envId=top-100-liked

## 题目描述

给定一个长度为 `n` 的整数数组 `height`，有 `n` 条垂线，第 `i` 条线的两个端点是 `(i, 0)` 和 `(i, height[i])`（`0 <= i < n`）。

找出其中的两条线，使得它们与 x 轴共同构成的容器可以容纳最多的水。

返回容器可以储存的最大水量。

**说明**：你不能倾斜容器。

**示例 1：**

```
输入：height = [1,8,6,2,5,4,8,3,7]
输出：49
解释：图中垂直线代表输入数组 [1,8,6,2,5,4,8,3,7]。在此情况下，容器能够容纳水容量表示为蓝色部分。
```

**示例 2：**

```
输入：height = [1,1]
输出：1
```

**数据范围：**

- `n == height.length`
- `2 <= n <= 10^5`
- `0 <= height[i] <= 10^4`

## 思路

> 本题参考力扣题解列表中的「双指针」做法。
> 注：题解列表页动态渲染，初稿代码是这道题最经典的左右双指针解法；如需对齐某篇特定题解再贴 URL 替换。

### 暴力想法（O(n²)，会超时）

枚举所有两条线的组合 `(i, j)`，水量 = `min(height[i], height[j]) * (j - i)`，取最大值。n ≤ 10^5 会超时。

### 双指针优化（O(n)）

**核心问题**：能不能不枚举所有组合，而是**有方向地**移动指针排除掉一些不可能的情况？

**关键观察**：水量由两个因素决定
- **宽度** `j - i`（两条线的水平距离）
- **高度** `min(height[i], height[j])`（木桶效应，由较短的那条决定）

**算法**：
1. 初始化左指针 `left = 0`、右指针 `right = n - 1`，此时宽度最大。
2. 计算当前水量，更新答案。
3. **移动较矮的那一边**：
   - 如果 `height[left] < height[right]`，`left++`；
   - 否则 `right--`。
4. 直到 `left == right` 结束。

### 为什么移动较矮的一边是对的？

**反向想**：当前状态 `(left, right)`，宽度已经最大了。如果不移动较矮的一边，而是保留它、移动较高的一边：
- 高度还是受较矮边限制（`min` 没变甚至更小）；
- 宽度一定变小。

→ 所以**保留较矮边、移动较高边，所有结果一定更差**。这些组合可以安全跳过。
→ 因此**只能**移动较矮边去找更大可能。这就把 O(n²) 降到了 O(n)。

## 代码

```cpp
class Solution {
public:
    int maxArea(vector<int>& height) {
        // 双指针：left 从最左开始，right 从最右开始。
        //   - 初始时宽度 (right-left) 最大，逐步向内收。
        int left = 0;
        int right = (int)height.size() - 1;
        int ans = 0;

        // 两指针相遇前持续循环。
        //   - 每轮计算当前水量、更新答案、移动较矮的一边。
        while (left < right) {
            // min(a, b)：<algorithm> 里的函数，返回较小值。
            //   - 容器高度由较短边决定（木桶效应）。
            //   - 宽度 = right - left。
            int h = min(height[left], height[right]);
            int w = right - left;
            int area = h * w;

            // max(a, b)：返回较大值，维护全局最大水量。
            ans = max(ans, area);

            // 关键一步：移动较矮的一边。
            //   - 假设 height[left] 较矮，那保留 left、移动 right 的所有组合，
            //     高度受 left 限制不变甚至更小，宽度一定变小 → 必然更差，跳过。
            //   - 所以只能 left++，去寻找可能更高的左边界。
            if (height[left] < height[right]) {
                ++left;
            } else {
                --right;
            }
        }
        return ans;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 每轮循环至少移动一个指针，两指针一共最多移动 n 次。
- **空间**：O(1)
  - 只用了常数个变量。

## 复盘

- **核心套路**：题目要求 O(n) 且涉及"两个端点/边界" → 想到双指针（特别是左右相向型）。
- **关键 trick**：**每次移动较矮的一边**。直觉来自"木桶效应"——较矮边是瓶颈，保留它不可能找到更大解，所以只能移动它去找更大可能。
- **正确性来源**：不是贪心的"局部最优=全局最优"，而是**反证排除**——明确指出"保留较矮边的所有组合必然更差"，所以这些组合可以安全跳过。
- **STL 要点**：
  - `min(a, b)` / `max(a, b)`：`<algorithm>` 里的函数，力扣 C++ 环境默认可用。
  - 双指针是非常通用的套路，本题属于**左右相向双指针**（不同于「快慢指针」「滑动窗口」）。
