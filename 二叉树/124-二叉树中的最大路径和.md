# 124 二叉树中的最大路径和

- 难度：困难
- 标签：树、**深度优先搜索**、动态规划、**二叉树**
- 力扣链接：https://leetcode.cn/problems/binary-tree-maximum-path-sum/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/binary-tree-maximum-path-sum/solution/er-cha-shu-zhong-de-zui-da-lu-jing-he-by-leetcode-/)「二叉树中的最大路径和」（slug：`er-cha-shu-zhong-de-zui-da-lu-jing-he-by-leetcode-`）。正文主解是 **递归（贡献值法）**，官方只有这一个方法：在递归求「以当前节点为起点向下走的最大贡献值」时，顺手用一个全局变量 `maxSum` 维护「经过当前节点的最大路径和」。它和 [543 题「二叉树的直径」](./543-二叉树的直径.md) 是**完全同一个模板**——都是「后序遍历求子树某个量 + 在回溯时维护全局答案」的树形 DP，只是把「深度」换成了「最大单臂路径和」。二叉树组刷到这里，543 + 124 一起吃透，这个套路就彻底拿下了。

## 题目描述

二叉树中的 **路径** 被定义为一条节点序列，序列中每对相邻节点之间都存在一条边。同一个节点在一条路径序列中 **至多出现一次**。该路径 **至少包含一个** 节点，且不一定经过根节点。

**路径和** 是路径中各节点值的总和。

给你一个二叉树的根节点 `root` ，返回其 **最大路径和** 。

**示例 1：**

```

输入：root = [1,2,3]
输出：6
解释：最优路径是 2 -> 1 -> 3 ，路径和为 2 + 1 + 3 = 6
```

**示例 2：**

```

输入：root = [-10,9,20,null,null,15,7]
输出：42
解释：最优路径是 15 -> 20 -> 7 ，路径和为 15 + 20 + 7 = 42

```

**提示：**

- 树中节点数目范围是 `[1, 3 * 10^4]`
- `-1000 <= Node.val <= 1000`

## 思路

> 本题主要参考力扣官方题解「方法一：递归」。强烈建议先做 [543 题「二叉树的直径」](./543-二叉树的直径.md)，本题是它的困难版升级，骨架一模一样。

### 先吃透「路径」的定义（四个限定，比 543 更宽）

题目对「路径」下了四条限定，必须先吃透：

1. **是一条节点序列，相邻节点之间有边**：所以路径必须是**连通的**，不能从一棵子树跳到另一棵不相邻的子树。
2. **同一个节点至多出现一次**：路径里不能有环、不能重复走。
3. **至少包含一个节点**：所以哪怕所有节点值都是负数，答案也至少是「单个最大的负数」（不能取 0 当作「空路径」）。
4. **不一定经过根节点**：最长路径可能整段都在某个子树内部，根本没碰到根。

把这四条合起来看：**一条合法路径可以是「任意形状」的**——它可以是「从根到叶」的一条直线，也可以是「从左子树的某个节点往上走到当前节点、再往下走到右子树的某个节点」这种**中间拐弯**的形状。这正是本题和「根到叶最大路径和」类题目的根本区别：**路径允许在某个节点处拐弯**。

> 543 题求直径时，路径同样允许拐弯（任意两节点之间最长路径）。本题就是把「路径长度（边数）」换成「路径上节点值之和」，并且节点值可能是负数——难点全在「负值如何处理」。

### 核心观察：任何一条路径，都「以某个节点为最高点」

这是破题的关键。在二叉树里画一条路径，无论它怎么拐弯、走多长，**一定能找到路径上位置最高的那个节点**（也就是离根最近的那个节点），把它叫做这条路径的「**最高点 / 顶端 / 拐点**」。

以这个最高点为界，整条路径可以拆成三部分：

- 最高点节点自己（必选，因为路径至少含一个节点）；
- 一条从最高点**向左子树向下走**的支路（可能没有，也可能走若干步）；
- 一条从最高点**向右子树向下走**的支路（可能没有，也可能走若干步）。

```
        最高点 node
        /         \
   左支路          右支路
   （向下）        （向下）
```

**每条路径都唯一对应一个最高点**（路径上离根最近的那个节点）。于是「求全树最大路径和」可以转化成：**对树里每一个节点 `node`，都算一次「以它为最高点的最大路径和」，再取所有节点里的最大值。**

这和 543 题的「对每个节点都算一次左深+右深」是完全一样的思路。

### 关键概念：「最大贡献值」maxGain

为了算「以 `node` 为最高点的最大路径和」，先定义一个辅助量——**节点的最大贡献值**：

> `maxGain(node)` = **以 `node` 为起点、向下走（只能往左或往右选一支，不能拐弯）** 的路径，能取得的最大节点值之和。

注意几个要点：

- 它是「**以 `node` 为起点**」的，所以一定包含 `node->val`。
- 它是「**向下走、不拐弯**」的一条直线（要么一直往左、要么一直往右，到了某层可以停）。**不能既走左又走右**——因为一旦拐弯，`node` 就不再是「起点」而是「最高点」了，那是另一回事。
- 空节点的贡献值 = **0**（没有节点可取）。

有了贡献值，递推就清楚了。对于非空节点 `node`：

- 它可以**不走任何子节点**（路径就停在 `node` 自己），贡献 = `node->val`；
- 也可以**往左子树走**，但要左子树那一支的贡献为正才划算：贡献 = `node->val + max(左贡献, 0)`；
- 也可以**往右子树走**，同理：贡献 = `node->val + max(右贡献, 0)`；
- 三者取最大，并且「往左」和「往右」**只能选一支**（这是「不拐弯」的要求）。

合并起来：

```
maxGain(node) = node->val + max(0, maxGain(node->left), maxGain(node->right))
```

> 这里的 `max(0, ...)` 就是「**负贡献直接舍弃取 0**」——如果某棵子树作为一支往下走反而会让总和变小（子树贡献是负数），那这条支路干脆不要，相当于「支路长度为 0」。注意这不是「节点不要」，`node` 自己一定要（`node->val` 在外面），舍弃的只是「往下延伸的那一段」。

### 用贡献值拼出「以 node 为最高点」的最大路径和

现在回到「以 `node` 为最高点的最大路径和」。它由三部分相加：

```
以 node 为最高点的路径和 = node->val + max(0, 左贡献) + max(0, 右贡献)
```

为什么左右两边都能加，而 `maxGain` 里只能选一支？因为：

- 在「以 `node` 为最高点」的语境下，`node` 是拐点，左边一支往下、右边一支往下，两支在 `node` 处汇合，**符合路径定义**（每个节点只走一次，`node` 是顶端）。所以左右两支的（正）贡献都能算进来。
- 仍然要对每支做 `max(0, ...)`：如果某支贡献为负，宁可不走那支（取 0），也不要把总和拉低。

```
priceNewPath = node->val + max(0, 左贡献) + max(0, 右贡献)
```

**这个 `priceNewPath` 就是「以当前节点为最高点」的最优路径和**。每算出一个节点的 `priceNewPath`，就用它去更新全局答案 `maxSum`。

### 为什么返回值和更新答案的式子不一样？—— 本题头号难点

这是本题最容易卡住、也最关键的一步。注意递归函数 `maxGain` 里出现了**两个长得不一样的式子**：

```cpp
int leftGain  = max(maxGain(node->left),  0);   // 左子树最大贡献（负的当 0）
int rightGain = max(maxGain(node->right), 0);   // 右子树最大贡献（负的当 0）

// ① 更新全局答案的式子：左右都加
int priceNewPath = node->val + leftGain + rightGain;
maxSum = max(maxSum, priceNewPath);

// ② 递归返回值的式子：左右只取一个
return node->val + max(leftGain, rightGain);
```

为什么 ① 能「左右都加」，② 却「只能取一个」？

- **① 是在算「以 `node` 为最高点」的路径**：`node` 在顶端，左支向下、右支向下，两支共用 `node` 这个顶点，形成一条合法的拐弯路径。所以**左右两支的（正）贡献都能计入**。但这条路径**到此为止**，它是一个「候选答案」，用 `priceNewPath` 更新 `maxSum` 就完事，不向上传。

- **② 是 `maxGain` 要「向上回传」给父节点的东西**。父节点会把 `node` 当成「它的一支」（要么是父的左支、要么是父的右支），继续拼父自己的路径。而**父节点只能接 `node` 这一整支里的「一条不拐弯的路径」**——因为如果 `node` 内部已经拐了弯（左支 + 右支都走了），那么父再接上去，路径就会在 `node` 处出现「分叉」，违反「每个节点至多出现一次、路径是一条线」的定义。

  用图来理解：父节点 `P` 的左孩子是 `node`。`P` 想要往下延伸左支，它从 `node` 这里能接走的，只能是「`node` 往下走的某一条直线」（要么 `node → node->left → ...`，要么 `node → node->right → ...`），**不能把 `node` 的左右两条支路都接走**（那样 `node` 就分叉了）。所以 `node` 回传给 `P` 的必须是「左右贡献里挑一个较大的」加上 `node->val`，即 `node->val + max(leftGain, rightGain)`。

一句话记忆：

- **更新答案（在当前节点「闭环」）：左右两支都能用**，因为 `node` 是这条路径的顶点，两支在此汇合合法。
- **回传给父（继续往上接）：只能选一支**，因为父只能从 `node` 的一侧接续，不能让 `node` 分叉。

这就是「全局答案」和「递归返回值」职责分离的本质：**返回值携带的是「可供父节点继续拼接的半成品路径」（必须是一条直线），而全局答案记录的是「在某个节点处已经成型的完整路径」（可以拐弯）**。543 题里也是同一个道理（返回深度、维护直径），只是那里求的是「边数/节点数」，这里求的是「节点值之和」，多了「负值要舍弃」这一层处理。

### 为什么 `maxSum` 要初始化成 `INT_MIN`？

因为**节点值可能全是负数**（`Node.val` 范围 `[-1000, 1000]`）。题目要求「路径至少含一个节点」，所以即使全树都是负数，答案也只能是「最大的那个负数」（即「只选一个节点」的路径），**绝不能取 0**。

如果把 `maxSum` 初始化成 0，遇到全负树就会错误地返回 0（比真实答案大）。初始化成 `INT_MIN`（`<climits>` 里的整型最小值，约 −21 亿），保证任何真实节点值都会比它大，第一次更新就能把 `maxSum` 拉到合理范围。这是「求最大值、且候选可能全负」时的标准初始化手法。

> 顺带说明数据类型：节点数最多 `3 * 10^4`、每个值最大 `1000`，全树路径和最坏 `3 * 10^4 * 1000 = 3 * 10^7`，远在 `int`（约 ±2.1 * 10^9）范围内，所以全程用 `int` 即可，**不需要 `long long`**（这点和 [437 题](./437-路径总和III.md) 不同，437 题前缀和会溢出 int 才上 `long long`）。

### 手动推导 `root = [-10,9,20,null,null,15,7]`（结果应为 42）

先看清这棵树：

```
        -10           （节点旁标注：贡献值 maxGain）
        /   \
       9    20
           /  \
          15   7
```

从叶子往上算每个节点的 `maxGain`，并在每个节点处用 `priceNewPath = val + max(0,左) + max(0,右)` 更新 `maxSum`（`maxSum` 初值 `INT_MIN`）：

```
maxGain(15)                          // 15 是叶子
  左 nullptr → 贡献 0；右 nullptr → 贡献 0
  priceNewPath = 15 + 0 + 0 = 15     // 以 15 为最高点：就它自己
  maxSum = max(INT_MIN, 15) = 15
  return 15 + max(0,0) = 15          // 15 的贡献值 = 15

maxGain(7)                           // 7 是叶子，同理
  priceNewPath = 7
  maxSum = max(15, 7) = 15
  return 7

maxGain(20)                          // 20 的左右是 15、7
  左贡献 = max(maxGain(15), 0) = max(15,0) = 15
  右贡献 = max(maxGain(7),  0) = max(7, 0)  = 7
  priceNewPath = 20 + 15 + 7 = 42    // 【关键】以 20 为最高点：15 — 20 — 7
  maxSum = max(15, 42) = 42
  return 20 + max(15, 7) = 35        // 20 的贡献值 = 35（只能选一支：20→15）

maxGain(9)                           // 9 是叶子
  priceNewPath = 9
  maxSum = max(42, 9) = 42
  return 9

maxGain(-10)                         // 根节点
  左贡献 = max(maxGain(9),  0) = max(9, 0)  = 9
  右贡献 = max(maxGain(20), 0) = max(35, 0) = 35
  priceNewPath = -10 + 9 + 35 = 34   // 以根为最高点：9 — (-10) — 20→15
  maxSum = max(42, 34) = 42          // 仍然是 42（拐根反而更小）
  return -10 + max(9, 35) = 25       // 根的贡献值 = 25（向上回传，但已经没人接了）

最终 maxSum = 42 ✓
```

注意三点：

1. **最大路径和出现在节点 20**（`15 — 20 — 7`，和 42），而不是根节点（以根为最高点只有 34）。这印证了「路径不一定经过根」，必须每个节点都算一遍。
2. **节点 20 回传给根的贡献值是 35**（`20 → 15` 这条直线），**不是 42**。因为根只能接走 20 的一支，不能把 `15 — 20 — 7` 整条拐弯路径都接走（否则 20 会分叉）。这就是「返回值 ≠ 更新值」的活生生例子。
3. **根的贡献值是 25**（`-10 → 20 → 15`），是个正数但比 42 小，最后没人用得上这个回传值——没关系，`maxSum` 早在节点 20 那里就被更新成 42 了。

## 代码

> 主解：递归（贡献值法）。对应力扣官方题解「方法一：递归」。下面这份代码**与官方完全一致**，只补了 STL / 细节详注。

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解字段即可：
 *   - val：节点存的值（范围 [-1000, 1000]）
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
private:
    // maxSum：记录「全树最大路径和」的全局答案。
    //   - 为什么用成员变量（而不是 maxGain 的参数/返回值）？因为 maxGain 的返回值已经被
    //     「当前节点的最大贡献值」占用了，没法同时再回传「全局最大路径和」。成员变量让所有
    //     递归层共享同一个 maxSum，每层直接 max 更新即可，最直观。和 543 题用 ans 记直径同款手法。
    //   - 为什么初始化成 INT_MIN？因为节点值可能全为负（范围 [-1000,1000]），题目要求路径至少
    //     含一个节点，答案也可能是负数。若初始化成 0，全负树会错误返回 0。
    //     INT_MIN（<climits>，约 -2147483648）保证任何真实节点值都大于它，第一次更新即拉到合理值。
    //   - 这里用类内直接初始化（C++11 起支持），也可在构造函数或 maxPathSum 入口里赋值。
    int maxSum = INT_MIN;

public:
    // maxGain：返回「以 node 为起点、向下走（不拐弯）的最大路径和」，即节点的「最大贡献值」。
    //   - 副作用：递归过程中会顺手把 maxSum 更新成「以 node 为最高点的最大路径和」中的全局最大。
    //   - 这是典型的「后序遍历」：先递归算出左右子树结果，再在当前节点处合并 + 更新答案。
    int maxGain(TreeNode* node) {
        if (node == nullptr) {
            return 0;  // 空节点贡献值为 0（递归的「底」）：没有节点可取。
        }

        // 递归计算左右子节点的最大贡献值。
        //   - 先算左、再算右，是标准的「左 → 右 → 根」后序遍历顺序。
        //   - max(a, b)：STL 算法 <algorithm>，返回较大值，O(1)。
        //   - 【关键】max(..., 0)：只有子树贡献 > 0 时才选取；负贡献直接当 0（即「不走这一支」）。
        //     这不是「节点不要」，node->val 一定保留；舍弃的只是「往下延伸会拉低总和的那一段」。
        int leftGain = max(maxGain(node->left), 0);
        int rightGain = max(maxGain(node->right), 0);

        // priceNewpath：以 node 为「最高点（拐点）」的最大路径和。
        //   = node 自身 + 左支正贡献 + 右支正贡献。
        //   - 这里左右两支【都能计入】：因为 node 是这条路径的顶端，左支向下、右支向下，
        //     两支在 node 处汇合，是一条合法的拐弯路径（每个节点只出现一次）。
        //   - 这条路径「到此为止」，是一个候选答案，用 max 更新 maxSum 后就丢弃，不向上传。
        int priceNewpath = node->val + leftGain + rightGain;

        // 更新全局答案：每访问一个节点都更新一次，保证「最高点」无论在树的哪一层都不会漏。
        //   - 这正是「路径不一定经过根」的对策：在所有节点处都试一遍「以它为最高点」。
        maxSum = max(maxSum, priceNewpath);

        // 返回值：node 的「最大贡献值」= node 自身 + 左右贡献里较大者（只能选一支）。
        //   - 【与上面 priceNewpath 不同的原因】：这个返回值是要「向上回传」给父节点的，
        //     父节点会把 node 当成「它的一支」继续拼父自己的路径。父只能接走 node 的一条直线
        //     （要么 node→左、要么 node→右），不能把 node 的左右两支都接走（否则 node 会分叉，
        //     违反「路径是一条线、节点至多出现一次」的定义）。所以这里只能 max(leftGain, rightGain)。
        //   - 一句话：更新答案是「闭环成品（可拐弯）」，返回值是「供父拼装的半成品（必须直）」。
        return node->val + max(leftGain, rightGain);
    }

    int maxPathSum(TreeNode* root) {
        maxGain(root);    // 跑一遍递归，过程中 maxSum 被不断更新到全局最大路径和
        return maxSum;    // maxSum 在声明处已初始化为 INT_MIN，这里直接返回即可
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点在递归中只被访问一次（进入 `maxGain` 一次，算完左右贡献就返回），整体遍历这棵树一遍。官方原话「对每个节点访问不超过 2 次」，量级仍是 O(n)。
- **空间**：O(height)，其中 height 为二叉树的高度。**最坏 O(n)**。
  - 空间消耗来自**递归调用栈**，栈深度等于递归深度，也就是树的高度。
  - **最好情况**：树平衡时 height = O(log n)，空间 O(log n)。
  - **最坏情况**：树退化成一条链（每个节点只有一个孩子），height = O(n)，空间也变成 O(n)。本题 n ≤ 3 * 10^4，递归绝对安全。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么「更新答案」的式子（左右都加）和「返回值」的式子（左右取一）不一样？

这是本题最核心的难点，详细见「思路」里的专节。简要回答：

- **更新答案 `priceNewPath = node->val + leftGain + rightGain`**：算的是「以 `node` 为最高点的完整路径」，`node` 是顶点，左右两支向下、在 `node` 处汇合，是一条合法的拐弯路径，所以**左右两支的（正）贡献都能算进来**。这是一条「成品路径」，用来更新 `maxSum` 后就丢弃。

- **返回值 `node->val + max(leftGain, rightGain)`**：这是 `maxGain` 要回传给父节点的东西，父节点会把 `node` 当成「自己的一支」继续往上拼。父只能接走 `node` 里**一条不拐弯的直线**（要么往左、要么往右），否则 `node` 会分叉、违反路径定义。所以**只能选贡献较大的那一支**。

一句话：**更新答案是「在当前节点闭环的成品（允许拐弯）」，返回值是「供父节点继续拼装的半成品（必须是一条直线）」**。两者职责不同，所以式子不同。543 题里也是同一回事（返回深度、用左右深度之和更新直径），只是那里没有「负值要舍弃」这层，看起来更朴素。

### Q2：为什么要对子树贡献做 `max(..., 0)`？负贡献为什么要舍弃？

因为题目求的是**最大**路径和，而节点值可能为负（`[-1000, 1000]`）。如果某棵子树作为一支「往下走」反而让总和变小（它的贡献是负数），那这一支干脆**不要**，等价于「支路长度为 0」。

举个具体例子：节点 `node` 值为 5，左子树的贡献是 `-3`（即左子树里无论怎么走，总和都是负的）。那么从 `node` 往左走只会让总和从 5 变成 `5 + (-3) = 2`，比「停在 `node`」的 5 还小。所以 `max(-3, 0) = 0`，相当于「不走左支」，`node` 的贡献仍是 `5 + 0 = 5`。

注意三点：

1. `max(..., 0)` 舍弃的是「**子树作为一支往下延伸**」的负贡献，**不是舍弃 `node` 自己**。`node->val` 始终保留（在最外层）。
2. 这个「舍弃」只对「作为一支回传 / 拼到最高点」时生效。被舍弃的那棵子树**内部**的最大路径仍然会被考察到——因为递归会进入那棵子树、在它的每个节点处都用 `priceNewPath` 更新过 `maxSum`。所以「舍弃负贡献」不会漏掉任何答案，只是不让它「拖累」上层的路径。
3. 这也是为什么 `maxSum` 要初始化成 `INT_MIN` 而不是 0：万一全树都是负数，所有子树贡献都被 `max(..., 0)` 压成 0，但 `priceNewPath = 负节点值 + 0 + 0` 仍会是负数，`maxSum` 会正确地收敛到「最大的那个负数」（即只选一个节点）。

### Q3：`maxSum` 为什么初始化成 `INT_MIN`？初始化成 0 会怎样？

会错。因为**节点值可能全为负数**（范围 `[-1000, 1000]`），而题目明确「路径至少包含一个节点」。所以即使全树都是负数，答案也必须是「最大的那个负数」，不能是 0（0 对应「选 0 个节点」，是非法路径）。

- 初始化成 `0`：遇到全负树（如 `root = [-3]`）会返回 0，但正确答案是 -3。**错**。
- 初始化成 `INT_MIN`（`<climits>`，约 −21 亿）：任何真实节点值都大于它，第一次 `max` 更新就会把 `maxSum` 拉到合理的节点值范围，后续正常收敛。**对**。

这是「求最大值、且候选可能全负」时的标准初始化手法。对比 543 题：543 题节点数恒 ≥ 1、直径（边数）恒 ≥ 0，所以 `ans` 初始化成 0 或 1 都安全；本题多了「负值」这一层，必须用 `INT_MIN` 兜底。

### Q4：这题和 543 题「二叉树的直径」到底什么关系？

**同一个模板的两种实例**。骨架完全一样，都是「后序遍历求子树某个量 + 在回溯时用左右结果拼接、维护全局答案」。具体对应关系：

| 维度 | 543 题（直径） | 124 题（最大路径和） |
|---|---|---|
| 子树递归求的量 | 子树**深度**（节点数） | 子树**最大贡献值**（节点值之和） |
| 递归返回值 | `max(左深, 右深) + 1` | `node->val + max(左贡献, 右贡献)` |
| 更新全局答案的式子 | `ans = max(ans, 左深 + 右深 + 1)` | `maxSum = max(maxSum, val + 左贡献 + 右贡献)` |
| 全局变量初值 | `1`（节点数恒 ≥ 1） | `INT_MIN`（值可能全负） |
| 是否有「负值舍弃」 | 无（节点数都是正数） | **有**（`max(..., 0)` 舍弃负贡献） |
| 全局答案最后换算 | `ans - 1`（节点数 → 边数） | 直接返回 `maxSum`（就是路径和） |
| 复杂度 | 时间 O(n)，空间 O(height) | 时间 O(n)，空间 O(height) |

一句话：**543 求「最长」（数量），124 求「最大」（带权值和）**。124 比 543 多了两层处理：① 负贡献要舍弃（`max(..., 0)`）；② 全局初值要用 `INT_MIN` 兜底全负情况。理解了 543，124 只要把「深度」换成「贡献值」、再处理好负值，就通了。两题一起刷，树形 DP 的这个套路就彻底吃透。

## 复盘

### 可迁移套路

- **「树形 DP / 后序遍历维护全局最优」是通用模板，本题是其标杆级应用**。递归函数返回「子树的某个量」（这里是「以当前节点为起点的最大单臂贡献值」），在**回溯合并左右子树结果时**，顺手用「左结果 + 右结果 + 当前节点」去更新一个全局答案（这里是「以当前节点为最高点的拐弯路径和」）。返回值是「供父节点继续拼接的半成品（一条直线）」，全局答案是「在当前节点处已经成型的完整路径（允许拐弯）」——两者职责分离，是这套模板的精髓。
- **「树上最优路径」类问题的破题点**：任何一条路径都唯一对应一个「最高点」（路径上离根最近的节点）。于是「全树最优」=「对每个节点都算一次以它为最高点的最优，取最大」。把答案更新塞进递归（每层都更新），就能覆盖所有可能的最高点，不用担心「答案在子树深处」。
- **「负值处理」三件套**（凡是带权树题都要警觉）：① 子树贡献为负时 `max(..., 0)` 舍弃（不让它拖累上层）；② 全局答案初值用 `INT_MIN`（兜底全负情况，不能用 0）；③ 数据范围核对（本题 `3*10^4 * 1000 = 3*10^7` 在 int 内，不用 long long；但遇到更大范围如 [437 题](./437-路径总和III.md) 就得上 long long）。
- **全局答案用成员变量 + 确保初始化**：力扣复用 `Solution` 对象跑多个用例，成员变量要么类内直接初始化（本题 `int maxSum = INT_MIN;`），要么在入口函数里重置，否则会带上上一个用例的脏数据。这是所有「成员变量记答案」题目的共同注意点。

### 和 543 题的对比（二者是同一模板）

- **相同**：后序遍历递归骨架完全一致；都是「返回一个子树量 + 用左右量之和更新全局答案」；都靠「在每层递归里更新全局答案」来覆盖「最高点可能在任意层」的情况；全局变量都用成员变量。
- **不同**：543 求的是「数量」（边数/节点数，恒非负），124 求的是「权值和」（可正可负）。所以 124 多了 `max(..., 0)` 舍弃负贡献、多了 `INT_MIN` 兜底初值。其他几乎一一对应。

**建议**：把 543 和 124 的代码并排放，体会「同一个模板换一个量」的感觉。之后遇到 687 题「最长同值路径」、124 的各种变体（如带权最大路径、路径乘积等），都是改 `priceNewPath` 的合并式和 `return` 的回传式，骨架照抄。
