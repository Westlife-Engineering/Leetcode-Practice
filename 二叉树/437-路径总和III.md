# 437 路径总和 III

- 难度：中等
- 标签：树、**深度优先搜索**、**二叉树**
- 力扣链接：https://leetcode.cn/problems/path-sum-iii/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/path-sum-iii/solution/lu-jing-zong-he-iii-by-leetcode-solution-z9td/)「路径总和 III」（slug：`lu-jing-zong-he-iii-by-leetcode-solution-z9td`）。正文主解是 **前缀和 + 哈希表 + DFS（回溯）**（官方方法二，最优 O(n)）：它本质上就是把 [560 题「和为 K 的子数组」](../哈希/560-和为K的子数组.md) 里的「前缀和之差 = 目标值」套到了二叉树上——只要把「数组的一段连续子数组」换成「一条从根往下的路径上的一段连续子路径」，套路完全一样。更直观但更慢的双重 DFS（官方方法一，O(n²)）放在文末「复盘」作对比。

## 题目描述

给定一个二叉树的根节点 `root` ，和一个整数 `targetSum` ，求该二叉树里节点值之和等于 `targetSum` 的 **路径** 的数目。

路径 **不需要从根节点开始，也不需要在叶子节点结束**，但是路径方向必须是向下的（只能从父节点到子节点）。

**示例 1：**

```

输入：root = [10,5,-3,3,2,null,11,3,-2,null,1], targetSum = 8
输出：3
解释：和等于 8 的路径有 3 条，如图所示。

```

**示例 2：**

```

输入：root = [5,4,8,11,null,13,4,7,2,null,null,5,1], targetSum = 22
输出：3

```

**提示：**

- 二叉树的节点个数的范围是 `[0, 1000]`
- `-10^9 <= Node.val <= 10^9`
- `-1000 <= targetSum <= 1000`

## 思路

> 本题主要参考力扣官方题解「方法二：前缀和」。前置题是 [560 题](../哈希/560-和为K的子数组.md)，强烈建议先看那题的「前缀和 + 哈希表」再来看本题，思路是同一条线。

### 先吃透「路径」的定义（有几个关键限定）

题目对「路径」下了三个限定，必须先吃透，否则容易跑偏：

1. **方向必须向下**：只能从父节点走向子节点，**不能拐弯、不能回头往上**。也就是说，任何一条合法路径，都可以看作「从某个祖先节点出发，沿父→子方向一直走到某个后代节点」。这就把「树上的路径」限制成了「**从根往下的某条链上的一段**」。
2. **起点不必是根**：可以从任意节点开始。
3. **终点不必是叶子**：可以在任意节点结束。

把这三点合起来：**一条路径 = 从根到当前节点这条「主路径」上，任意选一段连续的子段**。注意「主路径」是动态的——DFS 遍历到哪个节点，那条从根到该节点的链就是当前的「主路径」。

### 关键转化：把「树上路径和」变成「前缀和之差」

这是本题的核心。先定义前缀和：

> 节点 `x` 的**前缀和** `curr(x)` = 从根节点到 `x` 这一路上所有节点值之和（包含两端）。

那么对于「主路径」上的两个节点 `u`（祖先）和 `v`（后代），从 `u` 到 `v` 这段路径上的节点值之和，就是：

```
sum(u → v) = curr(v) - curr(u) + val(u)
           = curr(v) - (curr(u) - val(u))
           = curr(v) - curr(u 的父)
```

换种更顺手的写法：把 `curr(虚拟的「根的父」)` 约定为 0，则「从某个祖先 `u` 到当前节点 `v` 的路径和」可以统一写成：

```
sum(u → v) = curr(v) - curr(u 的父)
```

> 之所以要用「`u` 的父」而不是 `u` 本身，是为了把 `u` 自身的值也包含进路径和里。如果约定「空前缀」= 从根的虚拟父节点算起（和为 0），那么 `sum = curr(v) - curr(u的父)` 这一刀切下去正好涵盖 `u` 自身往下到 `v`。这跟 560 题里 `pre[i] - pre[j-1]` 用 `j-1` 是同一回事。

于是「**以当前节点 `v` 为终点、和为 `targetSum` 的路径**」等价于：

```
curr(v) - curr(某个祖先的父) == targetSum
→ curr(某个祖先的父) == curr(v) - targetSum
```

也就是说：**站在当前节点 `v`，只要数一数「从根到 `v` 这条主路径上、有多少个前缀和等于 `curr(v) - targetSum`」，就有多少条以 `v` 结尾的合法路径。**

这跟 560 题里「固定右端点 `i`，数有多少个 `pre[j-1] == pre[i] - k`」**一模一样**，只是把「数组」换成了「树的一条主路径」。

### 用哈希表记前缀和出现次数

边 DFS 边维护一个哈希表 `prefix`：

- **key**：某个前缀和的值（用 `long long`，见下方「为什么用 long」）；
- **value**：从根到当前节点这条主路径上，该前缀和出现过几次。

走到当前节点 `root` 时，流程是固定的四步：

1. `curr += root->val` —— 累加出当前节点的前缀和。
2. `ans += prefix[curr - targetSum]` —— 有多少个祖先的前缀和等于 `curr - targetSum`，就有多少条以当前节点结尾的合法路径，全部加进答案。
3. `prefix[curr]++` —— 把当前前缀和记进哈希表，**让后代节点能看到我**。
4. 递归左右孩子。
5. `prefix[curr]--` —— **回溯**：退出当前节点前，撤销我刚加的那次计数。

其中第 5 步「回溯」是本题最容易漏、也最值得讲清的地方，单独见下一节。

初始化：`prefix[0] = 1`，表示「空前缀（根的虚拟父节点，和为 0）出现过 1 次」。这样当某条路径**恰好从根开始**、和就等于 `targetSum` 时（即 `curr(v) - 0 == targetSum`），也能被正确统计到。这正是 560 题里 `mp[0] = 1` 的同款细节。

### 为什么要回溯（撤销计数）？—— 本题头号难点

这是和 560 题最大的区别。数组是**一条直线**，扫过去就不回头，`pre[i]` 永远有效。但二叉树是**会分叉**的：

```
        1
       / \
      2   3
     /     \
    4       5
```

DFS 走到 `4` 时，主路径是 `1 → 2 → 4`，哈希表里记着这条链上的所有前缀和。**但 `4` 和 `5` 不在同一条主路径上！** 当递归从 `4` 返回、再去访问右子树的 `3 → 5` 时，`1 → 2 → 4` 这条链对 `5` 来说已经「不存在了」——`4` 不是 `5` 的祖先。

如果不在访问完 `4` 后把它贡献的前缀和从哈希表里撤掉，那 `5` 就会错误地「看见」一个根本不在它祖先链上的前缀和，从而多算路径数。

所以**每访问完一个节点（它和它的整棵子树都处理完了），必须把 `prefix[curr]--` 撤销，让哈希表恢复到「只有当前主路径上的祖先」的状态**，再去访问兄弟分支。这就是「回溯」的味道——「**进来时改状态，出去时还原**」，保证哈希表任意时刻都恰好反映「从根到当前节点的这条主路径」。

一句话记忆：**哈希表永远只装「当前这条从根到我的链」，换分支前把自己这一份撤掉。**

### 和 560 题的对比

| 维度 | 560 题（数组） | 437 题（二叉树） |
|---|---|---|
| 「主路径」 | 整个数组本身（一条直线） | 从根到当前节点的某条链（动态变化） |
| 前缀和含义 | `pre[i] = nums[0]+...+nums[i]` | `curr = 根到当前节点路径和` |
| 核心等式 | `pre[i] - pre[j-1] == k` | `curr(v) - curr(祖先的父) == targetSum` |
| 哈希表记录范围 | 从下标 0 到当前位置，一直有效 | **只在当前主路径上有效**，换分支要撤 |
| 是否需要回溯 | 不需要（数组是一条线，不回头） | **需要**（树会分叉，离开分支要撤销） |
| 初始化 | `mp[0] = 1` | `prefix[0] = 1`（完全相同） |

骨架是同一套，**437 = 560 + 树的分叉结构 + 回溯撤销**。

### 手动推导 `root = [10,5,-3,3,2,null,11,3,-2,null,1], targetSum = 8`（结果应为 3）

先看清这棵树（每条边上标的是子节点的值，节点旁 `()` 内是该节点的前缀和 `curr`）：

```
            10 (10)
           /  \
        (15)5  -3 (7)
        /  \      \
     (18)3  2(17)  11(18)
      / \    \
   (21)3 -2(16) 1(18)
```

DFS 主干调用顺序（缩进表示递归深度），重点看「`curr-target=0` 或 `8` 或 `16`」这类被命中的时刻（`prefix[0]=1` 初始存在）：

```
dfs(10, curr=0)
  curr = 0+10 = 10
  找 prefix[10-8=2]  → 0
  prefix[10]++        → {0:1, 10:1}
  dfs(5, curr=10)
    curr = 10+5 = 15
    找 prefix[15-8=7]  → 0
    prefix[15]++       → {0:1, 10:1, 15:1}
    dfs(3, curr=15)
      curr = 15+3 = 18
      找 prefix[18-8=10] → 1 ✓   （路径 10→5→3，从根开始）
      prefix[18]++      → {..., 18:1}
      dfs(3, curr=18)   // 3 是叶子
        curr = 18+3 = 21
        找 prefix[21-8=13] → 0
        prefix[21]++ ; 回溯 prefix[21]--
      dfs(-2, curr=18)
        curr = 18+(-2) = 16
        找 prefix[16-8=8] → 0
        prefix[16]++ ; 回溯 prefix[16]--
      prefix[18]--        // 回溯掉 18
    dfs(2, curr=15)
      curr = 15+2 = 17
      找 prefix[17-8=9] → 0
      prefix[17]++
      dfs(1, curr=17)
        curr = 17+1 = 18
        找 prefix[18-8=10] → 1 ✓  （路径 10→5→2→1？和是 18-10=8，但 10 在表里：从根节点 10 之后开始算，即 5+2+1=8）
        ...
      prefix[17]-- ; prefix[15]--
    prefix[10]--  不对，10 是父，还要回去…
  dfs(-3, curr=10)
    curr = 10+(-3) = 7
    找 prefix[7-8=-1] → 0
    prefix[7]++
    dfs(11, curr=7)
      curr = 7+11 = 18
      找 prefix[18-8=10] → 1 ✓   （路径 10→-3→11，10+(-3)+11=18，从根开始 18-0=18≠8；
                                    但 18-10=8，对应从 10 的「之后」开始：-3+11=8）
      ...
    prefix[7]-- ; prefix[10]--

共命中 3 次 ✓（三个 1 相加）
```

命中的三条路径分别是：`5 → 3`（左侧 `5+3=8`）、`5 → 2 → 1`（`5+2+1=8`）、`-3 → 11`（`-3+11=8`）。每一次命中都对应「某个后代节点 `v` 处，`curr(v) - targetSum` 恰好等于某个祖先（或空前缀 0）的前缀和」。

## 代码

> 主解：前缀和 + 哈希表 + DFS（回溯）。对应力扣官方题解「方法二」。下面这份代码**与官方完全一致**，只补了 STL 详注。

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解字段即可：
 *   - val：节点存的值（注意范围 ±10^9，所以下面前缀和用 long long）
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
public:
    // unordered_map<long long, int> prefix：
    //   - STL 无序哈希表（<unordered_map>）。模板参数：key 是 long long（前缀和的值），
    //     value 是 int（这个前缀和在「当前主路径」上出现的次数）。
    //   - 底层哈希：查找 / 插入 / 删除均摊 O(1)；最坏退化到 O(n)，实际可当 O(1)。
    //   - 为什么不用 map？map 按 key 有序、查找 O(log n)；本题不需要有序，unordered_map 更快。
    //   - 为什么 key 是 long long 而不是 int？见「疑惑 Q3」：节点值 ±10^9、主路径最长 1000 个节点，
    //     前缀和最坏 ≈ 10^12，会溢出 int（约 ±2.1*10^9），必须用 long long。
    //   - 作为成员变量：所有递归层共享同一张表，省去层层传引用。注意 pathSum 入口要初始化 prefix[0]=1。
    unordered_map<long long, int> prefix;

    // dfs：返回「以 root 所在子树内、所有节点为终点、和为 targetSum 的路径总数」。
    //   - 参数 TreeNode* root：当前子树的根（向下走就把它纳入主路径）。
    //   - 参数 long long curr：进入 root 之前、从真正的树根到 root 的父节点这段路径和（不含 root 自己）。
    //     在函数内 curr += root->val 后，curr 就是「根到当前节点」的前缀和。
    //   - 参数 int targetSum：题目要找的目标和（注意是 int，但和 curr 运算时会自动提升到 long long）。
    int dfs(TreeNode *root, long long curr, int targetSum) {
        if (!root) {
            return 0;  // 空节点不贡献路径
        }

        int ret = 0;
        curr += root->val;  // curr 现在是「根 → 当前节点」的前缀和

        // count(key)：返回 key 出现的次数（0 或 1，但这里语义上就是「在当前主路径上出现了几次」）。
        //   - 用 count 先判存在再取值，比直接 prefix[curr-targetSum] 更安全：
        //     operator[] 在 key 不存在时会插入 {key, 0}，污染哈希表（把「没出现过」也写进去）。
        //   - 这一句是本题的核心：有多少个祖先（含「虚拟的根的父」，即空前缀 0）的前缀和
        //     等于 curr - targetSum，就有多少条「以当前节点为终点、和为 targetSum」的路径。
        if (prefix.count(curr - targetSum)) {
            ret = prefix[curr - targetSum];
        }

        // 把「当前前缀和」记进哈希表，让后代节点能查到我（作为它们的祖先）。
        //   - operator[]：key 不存在会先插入 {key, 0}，再返回引用，所以 ++ 直接从 0 变 1（或累加）。
        prefix[curr]++;
        // 递归左右孩子：答案 = 当前节点为终点的路径数 + 左子树里的路径数 + 右子树里的路径数。
        ret += dfs(root->left, curr, targetSum);
        ret += dfs(root->right, curr, targetSum);
        // 【回溯核心】离开当前节点前，撤销我刚加的那一次计数。
        //   - 为什么必须撤？因为左右子树都递归完了，接下来要回到父节点、可能去访问兄弟分支；
        //     当前节点对兄弟分支来说「不是祖先」，它的前缀和不该留在表里，否则兄弟分支会多算。
        //   - 进来时 ++，出去时 --，保证哈希表任意时刻都恰好反映「根到当前节点」这条主路径。
        prefix[curr]--;

        return ret;
    }

    int pathSum(TreeNode* root, int targetSum) {
        // prefix[0] = 1：初始化「空前缀」——约定根的虚拟父节点的前缀和为 0、出现 1 次。
        //   - 作用：当某条路径「从真正的树根开始」、和恰好等于 targetSum 时，
        //     curr - targetSum == 0 能命中这条记录，正确统计到「从根出发」的路径。
        //   - 这和 560 题里 mp[0]=1 是同一个细节，不可或缺。
        prefix[0] = 1;
        // 从根出发，初始前缀和为 0（还没累加任何节点）。
        return dfs(root, 0, targetSum);
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点只被 `dfs` 访问一次；每次访问里哈希表的 `count` / `[]` / `++` / `--` 都是均摊 O(1)。
  - 对比官方方法一「双重 DFS」的 O(n²)，本题 n ≤ 1000 两种都能过，但前缀和法在大数据上明显更优。
- **空间**：O(n)。
  - 哈希表 `prefix` 最坏存放「主路径上所有节点的前缀和」，主路径最长 O(n)（树退化成链），所以表最多 O(n) 个键。
  - 递归调用栈深度 = 树高，最坏 O(n)（退化成链），平衡时 O(log n)。
  - 两者合计 O(n)。n ≤ 1000 完全没压力。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么要「回溯」（`prefix[curr]--`）？不撤会怎样？

因为二叉树会分叉，而哈希表必须**永远只反映「当前这条从根到我的主路径」**。看个小例子：

```
      a
     / \
    b   c
```

DFS 顺序是 `a → b → (b 的子树) → 回到 a → c`。访问 `b` 时把 `curr(b)` 加进哈希表，等递归从 `b` 返回、要去访问 `c` 时，**`b` 已经不在 `c` 的祖先链上了**（`c` 的祖先只有 `a`）。

- 如果**不撤** `prefix[curr(b)]`：`c` 在查 `prefix[curr(c) - targetSum]` 时，可能会错误地命中 `curr(b)`，从而把「从 `b` 到 `c`」这种**跨分支、根本不连续**的路径当成合法路径数进来——但 `b` 和 `c` 不在同一条父→子链上，这种路径不存在。
- **撤掉**之后：哈希表里只剩 `curr(a)`（和空前缀 0），`c` 只会看到自己真正的祖先，统计才正确。

一句话：**数组是一条直线，前缀和永远有效；树会分叉，离开一个分支前必须把这个分支贡献的前缀和撤掉，否则会污染兄弟分支的统计。** 这是本题和 560 题最大的区别。

### Q2：初始化 `prefix[0] = 1` 是什么意思？为什么必须有？

它表示「**空前缀**（也就是根的虚拟父节点，路径和约定为 0）出现过 1 次」。

作用是处理「路径从真正的树根开始」的情况。假设根节点值 = 5、targetSum = 5，那么「从根开始这一段」就是一条合法路径。此时 `curr(根) = 5`，查 `prefix[5 - 5] = prefix[0]`，**如果没初始化 `prefix[0]=1`，就会查到 0，漏掉这条路径**。

有了 `prefix[0]=1`，这条「从根出发」的路径就能被正确统计。这跟 560 题里 `mp[0]=1` 处理「子数组从下标 0 开始」是同一个细节，**前缀和题里几乎都要这么初始化**，记牢即可。

### Q3：前缀和为什么用 `long long`，不能用 `int` 吗？

会溢出。数据范围：

- `Node.val` 在 `[-10^9, 10^9]`；
- 节点数最多 `1000` 个；
- 一条主路径最坏把 1000 个节点全串起来，前缀和最坏 ≈ `1000 * 10^9 = 10^12`。

而 `int` 只能存到约 `±2.1 * 10^9`，`10^12` 远远溢出。所以前缀和必须用 `long long`（能存到约 `±9.2 * 10^18`）。`curr` 形参、`prefix` 的 key 都声明成 `long long`。注意 `targetSum` 本身题目给的范围只有 `±1000`，用 `int` 没问题，但它在 `curr - targetSum` 这个表达式里会自动提升到 `long long`，运算不会溢出。

> 顺带一提：`prefix.count(curr - targetSum)` 里 `curr` 是 `long long`、`targetSum` 是 `int`，C++ 会把 `int` 提升成 `long long` 再相减，结果也是 `long long`，和 `prefix` 的 key 类型对得上，没问题。

### Q4：和 560 题「和为 K 的子数组」到底什么关系？

560 题是**特例**，437 题是**一般情况**。如果把这棵二叉树压成「每个节点只有一个孩子」的一条链（退化成链表），那么「树上向下的路径」就退化成「数组里的连续子数组」，437 题就**完全等价于 560 题**。

所以两题的核心套路完全一样：

- 都是「前缀和之差 = 目标值」；
- 都用一个哈希表记前缀和出现次数；
- 都要初始化「空前缀」为 1 次；
- 都是「边走边查边更新」，O(n) 一遍过。

唯一的额外动作是 437 题多了**回溯**（`prefix[curr]--`），因为树会分叉。所以可以这么记：**437 = 560 + 树的分叉 + 回溯撤销**。强烈建议做完 560 题紧接着做 437 题，两题一起消化，前缀和套路就彻底吃透了。

## 复盘

### 可迁移套路

- **「前缀和 + 哈希表」求「和为定值的子段 / 子路径」是通用模板**。核心三步：① 定义前缀和；② 把「子段和 = 目标」转化成「前缀和之差 = 目标」；③ 哈希表记前缀和出现次数，边扫边查边更新。适用场景：
  - 数组上的连续子数组：[560 题「和为 K 的子数组」](../哈希/560-和为K的子数组.md)；
  - 树上向下的路径：本题；
  - 矩阵里的子矩阵和（多维前缀和）：同一思想的升维。
  记住「`mp[0] = 1` 初始化空前缀」是这个模板的标准起手式。
- **树上的「全局状态」大多要配合回溯**。一旦在递归里维护了一个「随路径变化」的状态（哈希表、累加和、路径栈等），就要问自己：**这个状态在「离开当前节点去兄弟分支」时还该不该保留？** 如果不该（本题就是），就要在递归返回前把它撤销。这是树题里高频且容易漏的点，比单纯的递归返回值更进阶。可对照 113 题「路径总和 II」（回溯路径栈）。
- **看到「节点值可能为负」别上滑动窗口**。本题 `Node.val` 可正可负，路径和不具备单调性，滑动窗口不适用；前缀和不受正负影响，是最优选择（同 560 题）。
- **数据范围决定类型**：`±10^9 * 1000` 要立刻反应到 `long long`，这是面试/笔试里避免 WA 的肌肉记忆。

### 解法二：双重 DFS（官方方法一，O(n²)）

思路更直观、代码更短，但慢。分两个递归：

- `pathSum(root)`：对每个节点都调用一次 `rootSum(以它为起点的路径数)`，然后递归左右孩子。**外层枚举起点**。
- `rootSum(root, target)`：统计「**从当前 `root` 出发、向下、和为 `target`**」的路径数。**内层枚举终点**：要么就停在 `root`（如果 `root->val == target`）、要么继续往左右走（`target` 减去 `root->val`）。

外层 O(n) 个起点、每个起点内层最坏 O(n)，合计 O(n²)；空间 O(height)（递归栈，不含哈希表）。

```cpp
class Solution {
public:
    // rootSum：统计「从 root 出发、向下、和为 targetSum 的路径数」。
    //   - 路径必须以 root 为起点（包含 root 自己），向下走到某个后代为止。
    int rootSum(TreeNode* root, long long targetSum) {
        if (!root) {
            return 0;
        }

        int ret = 0;
        if (root->val == targetSum) {  // 刚好在 root 这里就凑齐了
            ret++;
        }

        // 往下走：target 要扣掉 root->val；左右两支各自的命中数相加。
        //   - 注意形参 targetSum 用 long long，因为 targetSum - root->val 会变负，
        //     int 虽然装得下本题（target ±1000、val ±10^9，差仍在 long long 更稳，
        //     官方这么写是为了通用）。
        ret += rootSum(root->left, targetSum - root->val);
        ret += rootSum(root->right, targetSum - root->val);
        return ret;
    }

    // pathSum：对每个节点都当一次「起点」跑 rootSum，总数相加。
    int pathSum(TreeNode* root, int targetSum) {
        if (!root) {
            return 0;
        }

        int ret = rootSum(root, targetSum);            // 以当前节点为起点的路径数
        ret += pathSum(root->left, targetSum);         // 起点在左子树里的路径数
        ret += pathSum(root->right, targetSum);        // 起点在右子树里的路径数
        return ret;
    }
};
```

- **时间**：O(n²)。最坏（退化成链）时每个节点为起点的 `rootSum` 都是 O(n)，n 个起点合计 O(n²)；n=1000 时约 10^6 次操作，能过。
- **空间**：O(n)，递归栈最深 O(n)（不含哈希表）。
- **与前缀和解法对比**：双重 DFS 更好想（「对每个起点数一遍」最直觉），适合作为**先写出来的暴力解**；前缀和解法是**优化版**，用 O(n) 换掉重复计算。面试里可以先讲双重 DFS 说清思路，再优化到前缀和，演示「从暴力到最优」的过程。两份代码都能直接贴力扣 AC。
