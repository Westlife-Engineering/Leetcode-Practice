# 236 二叉树的最近公共祖先

- 难度：中等
- 标签：树、**深度优先搜索**、**二叉树**
- 力扣链接：https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/solution/er-cha-shu-de-zui-jin-gong-gong-zu-xian-by-leetc-2/)「二叉树的最近公共祖先」（slug：`er-cha-shu-de-zui-jin-gong-gong-zu-xian-by-leetc-2`）。正文主解是 **递归（深度优先搜索）**：在左右子树递归地找 `p` 和 `q`，靠「递归函数的返回值」表达「这棵子树里找到了谁」。这是 LCA 类问题的最经典模板；官方「方法二：存储父节点」放在文末「复盘」作对比。

## 题目描述

给定一个二叉树, 找到该树中两个指定节点的最近公共祖先。

百度百科中最近公共祖先的定义为：「对于有根树 T 的两个节点 p、q，最近公共祖先表示为一个节点 x，满足 x 是 p、q 的祖先且 x 的深度尽可能大（**一个节点也可以是它自己的祖先**）。」

**示例 1：**

```

输入：root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1
输出：3
解释：节点 5 和节点 1 的最近公共祖先是节点 3 。

```

**示例 2：**

```

输入：root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4
输出：5
解释：节点 5 和节点 4 的最近公共祖先是节点 5 。因为根据定义最近公共祖先节点可以为节点本身。

```

**示例 3：**

```

输入：root = [1,2], p = 1, q = 2
输出：1

```

**提示：**

- 树中节点数目在范围 `[2, 10^5]` 内。
- `-10^9 <= Node.val <= 10^9`
- **所有 `Node.val` 互不相同**。
- `p != q`
- **`p` 和 `q` 均存在于给定的二叉树中**。

## 思路

> 本题主要参考力扣官方题解「方法一：递归」。

### 先厘清「最近公共祖先」的定义

题目给的三个关键设定，必须先吃透：

1. **「公共祖先」**：某个节点 `x`，同时是 `p` 的祖先、又是 `q` 的祖先（从 `x` 往下能走到 `p`，也能走到 `q`）。
2. **「最近」**：在所有公共祖先里，`x` 的**深度尽可能大**——也就是离 `p`、`q` 尽可能近的那个。直观地说，`x` 是「从 `p` 往上走、从 `q` 往上走，两条向上的路径**第一次相遇**的那个节点」。
3. **「一个节点也可以是它自己的祖先」**：这是最容易忽略的一条。意思是——**如果 `p` 本身就是 `q` 的祖先，那 LCA 就是 `p` 自己**（反之亦然）。示例 2 就是这种情况：`p = 5, q = 4`，4 在 5 的子树里，所以 LCA = 5。

所以判断 LCA 时不能只盯着「左右子树各找到一个」这一种情形，还要考虑「当前节点本身就是 `p` 或 `q`、且它的子树里藏着另一个」的情形。

### 把问题拆成「在当前子树里找 p 和 q」

二叉树是递归结构，一棵子树 = 根节点 + 左子树 + 右子树。我们设计一个递归函数 `dfs(root, p, q)`，它的任务是：**在以 `root` 为根的子树里，找 `p` 和 `q` 的最近公共祖先**。

关键在于这个函数的**返回值约定**。它返回一个 `TreeNode*`，含义是「这棵子树里，**和 `p`、`q` 相关的那个节点**」，具体分三种情况：

| 在以 `root` 为根的子树里 | `dfs(root)` 应该返回什么 |
|---|---|
| 找到了 `p` 和 `q` 的 LCA | 返回这个 LCA 节点 |
| 只找到了 `p`（或只找到了 `q`） | 返回 `p`（或 `q`）本身 |
| `p` 和 `q` 都没找到 | 返回 `nullptr` |

**这个约定是整段递归的灵魂**：返回值非空，就代表「这棵子树里至少藏了一个目标节点（`p` 或 `q` 或它们的 LCA）」；返回 `nullptr` 就代表「这棵子树里一个目标都没有，跟 LCA 无关」。

> 为什么不直接返回「是否找到」，而要返回节点指针？因为我们要让答案能**沿着递归一层层往上传**。底层子树找到的 LCA，可以通过返回值被上层接住、继续上传，直到根。如果只返回 `bool`，答案就没地方放了（参考 [543 题](./543-二叉树的直径.md) 用成员变量绕开返回值占用，本题官方「方法一」也是成员变量 + `bool` 返回，但下面要讲的经典写法用「返回指针」更省事）。

### 递归的三种情形

在当前节点 `root` 处，先递归左右子树：

```
left  = dfs(root->left,  p, q)   // 左子树里找到的那个相关节点（或 nullptr）
right = dfs(root->right, p, q)   // 右子树里找到的那个相关节点（或 nullptr）
```

然后看 `left`、`right` 的情况决定怎么返回：

**情形 1：`left` 和 `right` 都非空。**
说明 `p`、`q` **分布在 `root` 的两侧**（一个在左子树、一个在右子树）。那么往上走的两条路径**刚好在 `root` 这里汇合**——`root` 就是它们第一次相遇的节点，也就是 LCA。**返回 `root`**。

**情形 2：只有一边非空（`left` 非空、`right` 为空，或反过来）。**
说明 `p`、`q` **都在 `root` 的同一侧子树里**（要么都在左子树、要么都在右子树）。LCA 也在那一侧，已经被递归找到了（就是那个非空的返回值）。**把非空的那一侧原样返回**就行——相当于把答案继续往上透传。

**情形 3：`left` 和 `right` 都为空。**
说明 `root` 的整棵子树里**既没有 `p` 也没有 `q`**。返回 `nullptr`。

### 递归终止条件（处理「当前节点本身就是 p 或 q」）

在进入左右递归之前，先做判断：

```
if (root == nullptr || root == p || root == q) return root;
```

这一行同时处理了三件事：

- **`root == nullptr`**：走到空子树，返回 `nullptr`（递归的「底」）。
- **`root == p`（或 `root == q`）**：当前节点本身就是目标之一。直接返回它，**不再往下递归**。

为什么遇到 `p`/`q` 就直接返回、不再往它的子树里钻？因为题目保证了**`p`、`q` 都存在于树中且互不相同**。假设当前节点是 `p`：

- 如果 `q` 在 `p` 的子树里，那根据「一个节点可以是自己的祖先」，`p` 自己就是 LCA——返回 `p` 就对了，没必要再往下确认 `q` 在哪。
- 如果 `q` 不在 `p` 的子树里（在树的其他分支），那 `p` 这棵子树只贡献 `p` 自己，也该返回 `p`。

无论哪种情况，遇到 `p`/`q` 就返回它自己都是正确的。**「提前返回」还顺带把「当前节点是 p 或 q」的情形并进了终止条件，不用单独写判断，非常优雅。**

> 这里的 `root == p` 是**比较指针**（两个指针指向同一个节点对象）。力扣树题里节点值唯一时也可以用 `root->val == p->val` 比较（见官方代码），但比指针更准确、不依赖「值唯一」的假设。本题提示已说「所有 `Node.val` 互不相同」，两种写法等价；用指针比较更通用。

### 为什么这样递归能找到「最近」公共祖先？

关键在「自底向上」的处理顺序。递归是**先处理完左右子树（叶子那边），再回到当前节点**——也就是后序遍历的味道。LCA 的判定「左右都找到 → 当前就是 LCA」只有在「从下往上回溯」时才会**第一次**触发：

- 在 LCA 的**下方**那些节点：`p`、`q` 都在它的某一侧子树里（情形 2），只会把答案往上传，不会判定「我是 LCA」。
- 到达 **LCA 本身**：`p`、`q` 首次分属它的左右两侧（情形 1），`left`、`right` 同时非空，判定「我就是 LCA」并返回自己。
- 在 LCA 的**上方**（更靠近根的节点）：答案已经被 LCA 占用并作为返回值传上来了，但 LCA 自己已经确定了，不会重复判定。

由于「首次满足情形 1 的节点」恰好就是深度最大（离 `p`、`q` 最近）的公共祖先，所以这套递归天然找到的是「最近」的那个。

### 手动推导 `root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1`（结果应为 3）

先看清这棵树（`p = 5`、`q = 1`）：

```
              3
           /     \
          5       1
         / \     / \
        6   2   0   8
           / \
          7   4
```

从 `dfs(3)` 开始往下递归（缩进表示递归深度），关键看每个节点「左右返回值」的组合：

```
dfs(3)
├─ dfs(5)                              // 5 == p，命中终止条件
│  └─ return 5                         // 直接返回 5，不再往下递归它的子树
├─ dfs(1)                              // 1 == q，命中终止条件
│  └─ return 1                         // 直接返回 1
├─ left=5, right=1  →  两个都非空！      // 情形1：p、q 分布在 3 的两侧
└─ return 3                            // 3 就是 LCA  ✓
```

根节点 3 这一层的判断里，`dfs(5)` 返回 5、`dfs(1)` 返回 1，两者都非空——说明 `p`（5）在左子树、`q`（1）在右子树，它们向上的路径在节点 3 汇合，所以 LCA = 3。

再推一个更绕的例子，验证「LCA 在子树内部」的情形。同一棵树，**`p = 5, q = 4`**（结果应为 5）：

```
dfs(3)
├─ dfs(5)                              // 5 == p，命中终止条件，直接返回 5
│  （注意：这里不再往下递归 5 的子树）
├─ dfs(1)
│  ├─ dfs(0) → nullptr                 // 0 的子树里既没 p 也没 q
│  ├─ dfs(8) → nullptr
│  └─ return nullptr                   // 1 的子树里啥也没有
├─ left=5, right=nullptr  →  只有一边  // 情形2：答案在左边，透传
└─ return 5                            // 最终返回 5  ✓
```

这次在根 3 处 `left=5, right=nullptr`，不满足「左右都非空」，于是把左边的 5 原样上传，最终答案还是 5。**关键在于 `dfs(5)` 命中 `root==p` 提前返回了 5**——它没去 5 的子树里找 4，但因为 5 本身就是答案，提前返回反而正好对。这就是「一个节点可以是自己的祖先」这条规则在代码里的体现。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解字段即可：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

class Solution {
public:
    // lowestCommonAncestor：在以 root 为根的二叉树中，找 p、q 的最近公共祖先。
    //   - 参数 TreeNode* root：子树根（裸指针，节点由力扣环境管理，无需手动释放）。
    //   - 参数 TreeNode* p / q：要找的两个目标节点指针（题目保证都存在、且 p != q）。
    //   - 返回值 TreeNode*：LCA 节点指针。
    // 这个函数本身只是个「入口壳」，真正干活的是下面的 dfs；之所以单独包一层，
    // 是因为力扣规定了对外的方法签名（类名、方法名、参数都不能改）。
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        return dfs(root, p, q);
    }

private:
    // dfs：在以 root 为根的子树里，返回「与 p、q 相关的那个节点」。
    //   返回值含义（这是整段递归的灵魂，务必记住）：
    //     - 返回 LCA 节点  ：若这棵子树里 p、q 的 LCA 已确定；
    //     - 返回 p 或 q 本身：若这棵子树里只出现了 p 或只出现了 q 中的一个；
    //     - 返回 nullptr    ：若这棵子树里既没有 p 也没有 q。
    //   即「返回值非空 = 这棵子树至少藏了一个目标节点」。
    TreeNode* dfs(TreeNode* root, TreeNode* p, TreeNode* q) {
        // 【递归终止条件】三合一，一行搞定：
        //   1. root == nullptr：走到空子树，返回 nullptr（递归的「底」）。
        //   2. root == p 或 root == q：当前节点本身就是目标之一，直接返回它，
        //      不再往下递归。这一步同时把「LCA 可以是 p 或 q 自己」的情形覆盖了
        //      （见思路里的解释），且避免了无谓的子树遍历。
        //   注意：这里比较的是「指针相等」（指向同一个节点对象）。题目保证所有节点值
        //   互不相同，所以也可以写成 root->val == p->val，但比指针更准确、更通用。
        if (root == nullptr || root == p || root == q) {
            return root;
        }

        // 先递归左右子树，拿到它们各自的「相关节点」（可能为 nullptr）。
        //   - 注意：因为上面遇到 p/q 就提前返回了，所以这里 root 既不是 p 也不是 q，
        //     是个普通内部节点，需要继续往下找。
        TreeNode* left  = dfs(root->left,  p, q);  // 左子树里找到的相关节点
        TreeNode* right = dfs(root->right, p, q);  // 右子树里找到的相关节点

        // 【情形1：左右都非空】p、q 分布在 root 两侧 → root 就是 LCA。
        //   两个非空说明：左子树贡献了一个目标、右子树贡献了另一个目标，
        //   它们向上的路径在 root 首次汇合，所以 root 就是最近公共祖先。
        if (left && right) {
            return root;
        }

        // 【情形2：只有一边非空】p、q 都在 root 的同一侧 → LCA 在那一侧，已被递归找到。
        //   下面这行是简写，等价于：
        //     if (left != nullptr) return left;
        //     else                 return right;
        //   - 当 left 非空时返回 left（LCA 或那个目标在左子树）。
        //   - 当 left 为空时，right 可能非空（返回 right，透传答案），
        //     也可能也为空（返回 nullptr，表示整棵子树啥都没找到）。
        //   注意 C++ 里 nullptr 转 bool 是 false、非空指针转 bool 是 true，
        //   所以 if(left) 等价于 if(left != nullptr)。
        if (!left) return right;   // left 为空：LCA 不在左子树，要么在右子树、要么整棵都没有
        return left;               // left 非空：right 必为空（否则上面情形1已返回），透传 left
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点在递归中至多被访问一次（遇到 `p`/`q` 时会提前返回，不再往它的子树钻，但整体仍是线性遍历）。最坏情况下要遍历大部分节点，整体 O(n)。
- **空间**：O(height)，其中 height 为二叉树的高度。
  - 空间消耗来自**递归调用栈**，栈深度等于递归深度，也就是树的高度。
  - **最好情况**：树平衡时 height = O(log n)，空间 O(log n)。
  - **最坏情况**：树退化成一条链，height = O(n)，空间也变成 O(n)。本题 n ≤ 10^5，退化成链时递归栈会比较深，但一般还在力扣的栈空间限制内（若担心栈溢出，可改用「方法二：存储父节点」的非递归解法，见复盘）。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么「最近公共祖先」可以是 `p` 或 `q` 自己？

这是定义规定的（题目原文：「**一个节点也可以是它自己的祖先**」）。直观理解：祖先的定义是「从某节点往下能走到目标」。从 `p` 往下当然能走到 `p` 自己，所以 `p` 算「它自己的祖先」。

于是当 `p` 本身就在 `q` 的祖先路径上时（即 `q` 在 `p` 的子树里），`p` 同时是 `p` 的祖先和 `q` 的祖先，自然是公共祖先；而且 `p` 离 `q` 很近（就在 `q` 上方不远处），没有比它更深的公共祖先了，所以 `p` 就是 LCA。示例 2（`p=5, q=4`，4 在 5 的子树里）就是这个情况，答案就是 5。

代码里靠「`root == p || root == q` 时提前返回」来覆盖这个情形——遇到 `p`/`q` 就直接返回它，不再去它的子树里找另一个，答案依然正确。

### Q2：`left` 和 `right` 都非空时，为什么当前节点就一定是 LCA？

因为「左右都非空」这个组合**只会出现在 LCA 这一个节点上**。

- 在 LCA **下方**的节点：`p`、`q` 要么都在它的左子树、要么都在它的右子树，递归返回值只有一边非空（情形 2），不会触发「左右都非空」。
- 在 **LCA 本身**：`p`、`q` 首次被分到了不同的子树（一个在左、一个在右），于是 `left`、`right` 同时非空，这里就是它们向上路径的汇合点。
- 在 LCA **上方**（更靠近根的节点）：答案已经被 LCA 占住并作为返回值传上来了，但 LCA 那个节点本身已经被确定，不会再判一次「左右都非空」——上方节点拿到的是「一侧是 LCA、另一侧 nullptr」，走的是情形 2 的透传。

「首次左右都非空」发生的节点 = 深度最大的公共祖先 = LCA，所以可以直接 `return root`。

### Q3：只在一侧找到（另一侧是 nullptr）时，为什么要把找到的那一侧原样返回？

因为「只在一侧找到」意味着 `p`、`q` **都在那一侧子树里**（题目保证 `p`、`q` 都存在，不可能一个在树外）。LCA 自然也藏在那一侧，而且**已经被递归找到了**——那个非空的返回值要么是 LCA、要么是 `p`/`q` 自己（如果另一个在它的子树里）。

所以不需要在当前节点这一层做任何判断，直接把那个非空的返回值**原样透传给上层**即可。当前节点不是 LCA（它只是路径上的过客），它的职责就是把子树里找到的答案继续往上传。

### Q4：会不会重复访问同一个节点，导致超时？

不会。每个节点在整次递归中**至多被访问一次**：

- 普通节点：进入 `dfs` 算左右子树，返回后就结束了。
- `p` 或 `q` 本身：命中 `root == p` 或 `root == q` 的终止条件，**直接返回、不再往下递归**，所以它的子树根本没被遍历到。

整体相当于对树做了一次后序遍历（遇到 `p`/`q` 剪枝），每个节点最多进 `dfs` 一次，时间 O(n)。最坏情况是 `p`、`q` 都在叶子且分居两侧，这时要遍历几乎所有节点才能确定 LCA，但仍是线性的，n = 10^5 完全没问题。

## 复盘

### 可迁移套路

- **「树的递归：左右子问题汇总判断」是 LCA 类问题的通用模板**。本题就是最纯粹的形态：递归函数返回「子树里和目标相关的那个节点」，靠「左右返回值是否同时非空」来判定当前节点是不是答案。换题时只需要改「相关节点的定义」和「汇总判断的方式」，骨架照抄。同类题：
  - **235 题「二叉搜索树的最近公共祖先」**：树是 BST，可以利用「值的大小关系」剪枝（当前节点值介于 p、q 之间就是 LCA），但递归骨架完全一样。
  - **1644 题「二叉树的最近公共祖先 II」**（p、q 可能不在树中）：要额外判断「到底找到了几个」，但递归返回值的约定可复用。
  - **多个节点的 LCA**（如 1676 题）：把「找两个」推广成「找一组」，约定不变。
- **「递归返回值复用」**：本题巧妙之处在于让 `dfs` 的返回值**同时承担两种含义**（LCA 节点 或 目标节点 或 nullptr），靠「是否为空」和「左右是否都非空」区分。这种「一个返回值表达多种状态」的技巧在树题里很常见，比「成员变量记答案 + 返回 bool」（官方方法一的写法）更简洁，但两种写法等价。
- **终止条件「三合一」**：`if (root == nullptr || root == p || root == q) return root;` 一行处理了「空子树」「当前是 p」「当前是 q」三种边界，是最优雅的写法。记忆时想成「遇到空的、或遇到目标的，就不往下走了」。

### 解法二：存储父节点（官方方法二，非递归）

官方「方法二」换了个完全不同的思路：**不递归判断 LCA，而是先把每个节点的父节点记下来，然后让 `p` 一路往上走到根、把沿途节点都标记「访问过」；再让 `q` 也往上走，它碰到的第一个「已访问」节点就是 LCA**。

直观理解：`p` 到根的路径是一条线，`q` 到根的路径是另一条线，两条线在 LCA 处**首次汇合**（LCA 以上都共用同一条到根的路）。所以让 `p` 先把自己的路径全标记，`q` 往上走时第一次撞到标记，那个点就是分叉点 = LCA。

```cpp
class Solution {
public:
    // unordered_map<int, TreeNode*>：STL 哈希表，key 是 int（节点值），value 是 TreeNode*（父节点指针）。
    //   - 用节点值做 key 要求「节点值唯一」（本题满足）。
    //   - fa[x] = y 表示「值为 x 的节点的父节点是 y」。
    //   - 查找/插入 O(1) 均摊（比 map 的 O(log n) 快）。
    // unordered_map<int, bool> vis：标记某个节点值是否在 p 的祖先路径上被访问过。
    unordered_map<int, TreeNode*> fa;
    unordered_map<int, bool> vis;

    // dfs：遍历树，记录每个节点的父节点（根的父设为 nullptr）。
    void dfs(TreeNode* root) {
        if (root->left != nullptr) {
            fa[root->left->val] = root;   // 左孩子的父是当前节点
            dfs(root->left);
        }
        if (root->right != nullptr) {
            fa[root->right->val] = root;  // 右孩子的父是当前节点
            dfs(root->right);
        }
    }

    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        fa[root->val] = nullptr;          // 根没有父节点
        dfs(root);                        // 建立完整的父指针表
        // 第一步：p 一路往上走到根，把沿途节点标记为「已访问」
        while (p != nullptr) {
            vis[p->val] = true;
            p = fa[p->val];               // 沿父指针上移；p 到根后 fa 返回 nullptr 退出循环
        }
        // 第二步：q 也一路往上走，遇到的第一个「已访问」节点就是 LCA
        while (q != nullptr) {
            if (vis[q->val]) return q;    // q 撞上了 p 的路径 → 这里就是汇合点
            q = fa[q->val];
        }
        return nullptr;                   // 理论上不会走到（题目保证 p、q 都在树中）
    }
};
```

- **时间**：O(n)。建父指针表遍历一次树 O(n)；p、q 各往上走至多 height 步，合计 O(n)。
- **空间**：O(n)。两个哈希表各存 n 条记录。比递归解法的 O(height) 空间大，但**不依赖递归栈**，树退化成链时也不会栈溢出（n = 10^5 退化链时这是更稳的选择）。
- **对比递归解法**：两者时间都是 O(n)；空间上递归是 O(height)（调用栈）、本法是 O(n)（哈希表）。平衡树下递归更省空间；退化成链时本法更安全。**主解推荐递归**（代码短、思路通用、可迁移性强），本法作为「避免栈溢出」的备选。

### 套路模板（LCA 类问题通用，可复用）

```cpp
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        return dfs(root, p, q);
    }
private:
    TreeNode* dfs(TreeNode* root, TreeNode* p, TreeNode* q) {
        if (root == nullptr || root == p || root == q) return root;  // 终止：空/命中目标
        TreeNode* L = dfs(root->left, p, q);                          // 左子树找
        TreeNode* R = dfs(root->right, p, q);                         // 右子树找
        if (L && R) return root;                                      // 左右都有 → 我是 LCA
        return L ? L : R;                                             // 只有一边 → 透传那边
    }
};
```

换 LCA 类新题时，骨架几乎不用改：终止条件看「目标怎么判定」，汇总判断看「左右结果怎么组合」。BST 的 LCA（235 题）只需把「递归左右」改成「按值大小走一边」，其余一致。
