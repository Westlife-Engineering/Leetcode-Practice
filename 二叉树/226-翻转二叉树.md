# 226 翻转二叉树

- 难度：简单
- 标签：树、**深度优先搜索**、广度优先搜索、**二叉树**
- 力扣链接：https://leetcode.cn/problems/invert-binary-tree/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/invert-binary-tree/solutions/fan-zhuan-er-cha-shu-by-leetcode-solution/)「方法一：递归」（slug：`fan-zhuan-er-cha-shu-by-leetcode-solution`）。正文主解是 **深度优先搜索（递归）**：交换当前节点的左右孩子，再递归翻转左右子树；BFS 层序遍历写法放在文末「复盘」作对比。

## 题目描述

给你一棵二叉树的根节点 `root` ，翻转这棵二叉树，并返回其根节点。

**示例 1：**

```
输入：root = [4,2,7,1,3,6,9]
输出：[4,7,2,9,6,3,1]
```

**示例 2：**

```
输入：root = [2,1,3]
输出：[2,3,1]
```

**示例 3：**

```
输入：root = []
输出：[]
```

**提示：**

- 树中节点数目范围在 `[0, 100]` 内
- `-100 <= Node.val <= 100`

> 「翻转」即**镜像**：对树里任意一个节点，把它原本的左孩子和右孩子互换位置；这棵树整体就变成了它在镜子里的样子。

## 思路

> 本题参考力扣官方「方法一：递归」。

### 翻转的本质 = 把每个节点的左右孩子交换一次

不要被「翻转整棵树」这个大词吓到。把它拆开看：一棵树由**若干个节点**组成，每个节点最多有两个孩子（`left` / `right`）。所谓「翻转」，不过就是**让每个节点都把自己的左右孩子交换一下**。

- 根节点 4 的左孩子 2、右孩子 7 → 交换成 左 7、右 2；
- 节点 2 的左孩子 1、右孩子 3 → 交换成 左 3、右 1；
- 节点 7 的左孩子 6、右孩子 9 → 交换成 左 9、右 6；
- 叶子节点（1、3、6、9）没有孩子，交换了个寂寞，不用管。

所有节点都这么交换一次，整棵树就翻转完了。**所以问题归约为：访问树里的每个节点，对它执行「交换左右孩子」这个动作。**

### 为什么递归天然适合

「访问每个节点 + 对它做点事 + 对它的子树重复同样的事」——这正是**二叉树递归**的标准模板。翻转操作还有一个特别友好的性质：**它对「当前节点」做的事（交换左右孩子）和「子树」做的事（继续翻转）互不干扰**——先交换还是后交换，最终结果都一样（下面 Q&A 会细说）。所以递归写起来几乎没有「顺序坑」，是树递归里最简单的一类。

### 先交换当前节点，还是先递归子树？

两种写法都对，结果完全相同：

- **写法 A（先交换后递归，即本笔记主解）**：先 `swap(root->left, root->right)` 交换当前节点的左右孩子，再 `invertTree(root->left)`、`invertTree(root->right)` 递归翻转（此时左右孩子已经被交换过，递归进去翻的就是新的孩子）。
- **写法 B（先递归后交换，即官方写法）**：先用 `left`、`right` 两个临时变量记下递归翻转后的左右子树结果，再把 `root->left = right`、`root->right = left` 挂上去。

两者等价，因为「翻转」这个操作**对每个节点只做一次、彼此独立**，交换动作和递归动作的先后顺序不影响最终形态。本笔记主解采用写法 A + `std::swap`，一行代码完成交换，最简洁直观；官方代码用写法 B，复盘里会贴出对比。

### 手动推导 `root = [4,2,7,1,3,6,9]` 翻转成 `[4,7,2,9,6,3,1]`

先把原树画出来（`[4,2,7,1,3,6,9]` 是层序序列，逐层从左到右填）：

```
原树：
        4
       / \
      2   7
     / \ / \
    1  3 6  9
```

从根节点 4 开始递归翻转，每个节点都执行「交换左右孩子」：

```
invertTree(4):
  先交换 4 的左右孩子：4 的左 2、右 7 → 左 7、右 2

        4
       / \
      7   2       ← 4 的孩子换好了
     / \ / \
    6  9 1  3     ← 这一层还是原来的顺序，继续递归
  再递归处理 4 的新左子树(7) 和新右子树(2)

  invertTree(7):  交换 7 的左右孩子 6、9 → 9、6
  invertTree(2):  交换 2 的左右孩子 1、3 → 3、1

所有节点都处理完，最终树：
        4
       / \
      7   2
     / \ / \
    9  6 3  1

层序输出 = [4,7,2,9,6,3,1]  ✓
```

可以看到：**根节点那一层的交换最先发生，然后交换的效果「传递」给子树**。因为左右孩子是被指针引用的，根节点交换左右孩子后，原来的左子树整棵跑到了右边、右子树跑到了左边，再递归进去翻转它们内部即可。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解一下字段即可：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 *   - 三个构造函数分别支持：无参（val=0,孩子皆空）、只给值、值+左右孩子
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
public:
    TreeNode* invertTree(TreeNode* root) {
        // 终止条件：空节点没东西可翻转，直接返回 nullptr。
        //   - 这是递归的「底」，没有它递归会一直往下走到空指针上、然后解引用崩溃。
        //   - 也顺手覆盖了「空树」的边界：root==nullptr 时函数直接返回 nullptr，结果 [] 正确。
        if (root == nullptr) {
            return nullptr;
        }

        // swap：C++ STL 算法（<utility>，力扣 C++ 模板已默认包含）。
        //   - 原型 swap(a, b) 交换两个同类型对象的值，这里是两个 TreeNode* 指针。
        //   - 对指针 swap 只是三次指针赋值（tmp=a; a=b; b=tmp），O(1)。
        //   - 效果：root 的左孩子指针和右孩子指针整体对调。
        //     原本 root->left 指向「左子树」，root->right 指向「右子树」，
        //     swap 之后 root->left 指向原右子树、root->right 指向原左子树。
        //   - 为什么用 swap 最简洁：一行就把「左右孩子互换」表达完，不用临时变量、不用写三行赋值。
        //   - 注意 swap 交换的是「指针本身」（让 left/right 指向变了），
        //     不是交换「指针指向的节点内容」，子树整棵跟着挪，节点内部的值和孩子都没动。
        std::swap(root->left, root->right);

        // 递归翻转左右子树。
        //   - 此时 root 的左右孩子已经交换过，root->left 是原来的右子树、root->right 是原来的左子树。
        //   - 但具体「递归翻的是哪一边」其实不影响结果——翻转是对每个节点独立做的动作，
        //     先翻左还是先翻右、翻的是交换前还是交换后的孩子，最终整棵树都会被翻一遍。
        //   - 函数返回 root：翻转完成后把当前（子树）根节点返回给上一层，方便上层挂接。
        invertTree(root->left);
        invertTree(root->right);

        return root;
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点被访问一次，访问时只做一次 `swap`（O(1)），总共 O(n)。
- **空间**：O(n)。
  - 取决于递归栈深度，而递归深度等于树高 h。平衡树 h = O(log n)，但树退化成一条链时 h = O(n)，所以最坏 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：先交换当前节点，还是先递归子树，有区别吗？

**没有区别，结果完全一样**。这是本题最容易绕晕的地方，但其实想通一点就透了：

翻转这个操作**对每个节点只做一次、彼此独立**。当前节点交换的是「它自己的左右孩子指针」，子树递归交换的是「子树内部节点的孩子指针」，两者操作的是**不同的节点**，互不覆盖。所以交换动作和递归动作谁先谁后，最终每个节点都被交换过一次，树的整体形态一致。

- 本笔记主解（先 swap 再递归）：`swap(root->left, root->right); invertTree(left); invertTree(right);`
- 官方写法（先递归再赋值）：`left = invertTree(root->left); right = invertTree(root->right); root->left = right; root->right = left;`

两者等价。主解用 `swap` 一行完成交换更简洁；官方写法用临时变量先存递归结果再挂回去，思路更显式（适合初学理解「先翻好子树、再交换位置」）。

### Q2：能不能用前序 / 中序 / 后序遍历来写？

**前序和后序都可以，中序要小心**。所谓「用 X 序遍历写」，差别只在「交换动作」和「递归进入子树」的相对时机：

- **前序（根→左→右）**：先交换当前节点的左右孩子，再递归。本笔记主解就是前序。最直观、最不容易错。
- **后序（左→右→根）**：先递归翻转子树，再交换当前节点的左右孩子。结果一样。
- **中序（左→根→右）**：要小心。中序是「递归左子树 → 交换当前节点 → 递归右子树」，但**交换之后当前节点的左右孩子已经对调了**，接下来「递归右子树」递归的其实是交换前的左子树。如果直接照搬中序模板，某些节点可能被翻两次或漏翻，逻辑容易写错。**建议初学就用前序或后序，避开中序的坑。**

记住一句话：翻转不在乎遍历顺序，因为交换动作对每个节点独立；但中序因为「左/右」在交换后会变，写起来要格外留心。

### Q3：`root == nullptr` 直接返回 nullptr，为什么不用特判？

这恰恰是递归的优雅之处——**空节点就是递归的终止条件**。递归函数 `invertTree` 的语义是「翻转以 root 为根的子树并返回根」。当 root 是空时，「翻转一棵空树」就是「什么都不做，返回空」，所以 `return nullptr`（或 `return root`，此时 root 本就是 nullptr）完全合理。

这个终止条件**同时覆盖了两种情况**：
1. 整棵树是空的（示例 3：`root = []`），一开始就命中，返回空；
2. 递归走到某个叶子节点的孩子（也是空），正常返回。

不用单独写「空树特判」，递归把边界自然吃掉了。

### Q4：`swap(root->left, root->right)` 交换的到底是什么？

交换的是**两个指针本身**（即 `root` 这个对象里的 `left` 成员和 `right` 成员所存的地址值），**不是**交换指针指向的节点内容。

举个具体例子，假设交换前：

```
root->left  = 0x1000  →  节点 2（带着它的子树 1, 3）
root->right = 0x2000  →  节点 7（带着它的子树 6, 9）
```

执行 `swap(root->left, root->right)` 后：

```
root->left  = 0x2000  →  节点 7（子树 6, 9 整棵跟着挪过来）
root->right = 0x1000  →  节点 2（子树 1, 3 整棵跟着挪过来）
```

节点 2 和节点 7 内部的 `val`、`left`、`right` **一个字节都没变**，变的只是 root 这个上层节点里「左指针和右指针分别指向谁」。这正是我们想要的：左右孩子整棵子树互换位置，子树内部结构保持原样（内部结构留给后续递归去翻）。

> 补充一个易混点：如果你写的是 `swap(*root->left, *root->right)`（带 `*` 解引用），那交换的就是「两个节点对象的内容」，会改动 val 和孩子指针，语义完全不同而且容易出 bug。本题要交换的是**指针**，不带 `*`。

## 复盘

### 可迁移套路

- **「树的递归」通用模板：处理当前节点 + 递归子问题**。本题是这套模板最朴素的体现：
  1. 写终止条件（`root == nullptr` 返回）；
  2. 对当前节点做事（交换左右孩子）；
  3. 递归处理子问题（翻转左右子树）。
  这套骨架能套到一大批二叉树题上：104 题最大深度（当前节点贡献 1，递归取子树最大深度）、101 题对称二叉树、543 题直径……差别只在「第 2 步对当前节点做什么」和「第 3 步怎么合并子问题结果」。
- **能用 `swap` 就别手写三行赋值**。C++ 的 `std::swap(a, b)` 一行表达「交换两个值」，比 `tmp=a; a=b; b=tmp;` 简洁且不易写错。凡是「左右互换」「两个对象对调」的场景，第一反应就是 `swap`。
- **复杂度基准**：树遍历时间一定是 O(n)（每个节点访问一次），空间取决于递归深度 = 树高 h，平衡 O(log n)、退化为链 O(n)。

### 解法二：BFS 层序遍历（官方思路的迭代版本）

递归本质是「用系统调用栈做深度优先」。如果不想用递归（比如树很深怕栈溢出），可以换成**显式队列做广度优先（层序）**：一层一层地把节点入队，每弹出一个节点就交换它的左右孩子，再把它的（非空）孩子入队，直到队列空。

```cpp
class Solution {
public:
    TreeNode* invertTree(TreeNode* root) {
        // queue<TreeNode*>：STL 队列，元素是「指向树节点的指针」。
        //   - 只能在队尾 push、队首 front 取出 + pop，先进先出（FIFO）。
        //   - push / pop / front 都是均摊 O(1)。
        //   - 语义：存放「已发现但还没处理」的节点，按「从上到下、从左到右」的层序顺序排队。
        if (root == nullptr) return root;   // 空树直接返回，避免把 nullptr 入队
        queue<TreeNode*> q;
        q.push(root);

        while (!q.empty()) {
            TreeNode* node = q.front();
            q.pop();                        // front 先取值再 pop，顺序不能反
            // 交换当前节点的左右孩子（和递归版做的事一模一样）
            std::swap(node->left, node->right);
            // 把交换后的（非空）孩子入队，留给后续循环处理
            //   - 必须判空：nullptr 入队没意义，且后面 node->left 会解引用空指针崩溃
            if (node->left)  q.push(node->left);
            if (node->right) q.push(node->right);
        }
        return root;
    }
};
```

- **时间**：O(n)，每个节点入队、出队、交换各一次。
- **空间**：O(n)，队列最多同时存「一层」的节点，最坏（满二叉树底层）约 n/2 个，仍是 O(n)。
- **对比**：和递归 DFS 思路完全一致（都是「访问每个节点 + 交换左右孩子」），只是遍历方式从「深度优先」换成「广度优先」。递归代码更短、更贴近定义；BFS 代码稍长但不依赖调用栈，适合树很深时避免栈溢出。初学优先掌握递归版，BFS 当作「树遍历通用套路」的练习。
