## 题目描述

给你二叉树的根结点 `root` ，请你将它展开为一个单链表：

- 展开后的单链表应该同样使用 `TreeNode` ，其中 `right` 子指针指向链表中下一个结点，而左子指针始终为 `null` 。
- 展开后的单链表应该与二叉树 **先序遍历** 顺序相同。

**示例 1：**

```
输入：root = [1,2,5,3,4,null,6]
输出：[1,null,2,null,3,null,4,null,5,null,6]
```

**示例 2：**

```
输入：root = []
输出：[]
```

**示例 3：**

```
输入：root = [0]
输出：[0]
```

**提示：**

- 树中结点数在范围 `[0, 2000]` 内
- `-100 <= Node.val <= 100`

**进阶：** 你可以使用原地算法（`O(1)` 额外空间）展开这棵树吗？

> 两个关键点先记住：① 展开后是一根**只有 `right` 指针**的右斜链表（所有 `left` 必须置空）；② 这根链表的节点顺序严格等于原树的**前序遍历**顺序。本文用「前序」和「先序」表示同一个意思（root → 左 → 右）。

## 思路

> 本题主要参考力扣官方题解「方法三：寻找前驱节点」。

### 先看清楚「展开」到底要做成什么样

把示例 1 的输入和输出画出来对比：

```
原树 [1,2,5,3,4,null,6]：            展开后 [1,null,2,null,3,null,4,null,5,null,6]：

        1                                    1
       / \                                    \
      2   5                                    2
     / \   \                                    \
    3   4   6                                    3
                                                  \
                                                   4
                                                    \
                                                     5
                                                      \
                                                       6
```

展开的**本质**就一句话：**把树的前序遍历序列 `[1,2,3,4,5,6]` 串成一根只有 `right` 的右斜链表**。原树的前序遍历是 `1 → 2 → 3 → 4 → 5 → 6`，展开后正好是这个顺序往右一路延伸。所以这题的难点不在「展开」，而在「**怎么原地、O(1) 空间地把前序顺序串起来**」。

### 暴力做法长什么样（用来理解，不是主解）

最直观的暴力：先做一次前序遍历把所有节点按顺序存进 `vector<TreeNode*>`，再扫一遍这个 vector，让每个节点的 `right` 指向下一个、`left` 置空。能过，但用了 O(n) 额外空间，不满足进阶的 O(1) 要求。这就是官方「方法一」，放复盘里。

进阶要求 O(1) 空间，所以不能用 vector、也不能用栈（显式栈也是 O(n) 空间）。能用的只有「常数个指针变量」。这就是「方法三：寻找前驱节点」要解决的事。

### 核心观察：左子树的前序最后一个节点 = 左子树的最右节点

对任意一个节点 `curr`，假设它有左子树和右子树：

```
        curr
        /  \
     左子树  右子树
```

前序遍历的顺序是 `curr → 左子树全部 → 右子树全部`。展开后 `curr` 的 `right` 该指向谁？**指向左子树的前序第一个**（也就是 `curr->left`）。那右子树该接在哪里？**接在左子树的前序最后一个节点后面**——因为前序是「左子树全部」之后才轮到「右子树全部」。

那「左子树的前序最后一个节点」是哪个？答案是 **左子树里一直往右走到底的那个节点**（左子树的最右节点）。

> 为什么「前序最后一个」=「最右节点」？这里有个直觉但需要想一想的结论：前序遍历的最后一站，**永远是「尽量往左钻、钻不动就回头、再尽量往右」能到达的最右下角**。但对「一棵子树前序的最后一个」而言，更简单的视角是：前序是「根→左→右」，**右孩子永远最后被访问**。所以「整棵子树前序的最后一个节点」就是「**沿 right 指针一直走到底**」那个节点（因为每到一个子树，只要它有右孩子，右孩子就是最后访问的；右孩子为空时本子树才结束）。于是「左子树的前序最后一个」=「从 `curr->left` 出发，沿 right 一路走到尽头」。

具体到代码：从 `curr->left` 出发，`while (predecessor->right != nullptr) predecessor = predecessor->right;` 走到底，这个 `predecessor` 就是我们要的「前驱」。

### 三步操作：找前驱 → 接右子树 → 挪左子树到右

把上面的观察落实成对 `curr` 这个节点的就地操作（只动 `curr` 和它两个子树之间的指针，不破坏子树内部结构）：

1. **找前驱**：`curr` 有左子树时，从 `curr->left` 一路向右走到底，找到 `predecessor`。
2. **接右子树**：把 `curr` 原来的右子树整个挂到 `predecessor->right` 上。这样前序顺序就变成 `curr → 左子树 → 原右子树`，正确串联。
3. **挪左子树到右**：把整个左子树挪到 `curr->right`（即 `curr->right = curr->left`），并把 `curr->left` 置空。现在 `curr` 这个节点就「展平」成了一个只有右孩子的节点。

做完这三步后，`curr` 这一层就处理完了，`curr = curr->right` 往右继续推进，对下一个节点重复同样的操作。

### 手动推导 `root = [1,2,5,3,4,null,6]`（结果应为 `[1,null,2,null,3,null,4,null,5,null,6]`）

原树：

```
        1
       / \
      2   5
     / \   \
    3   4   6
```

外层循环 `curr` 从根开始，每步只处理「curr 有没有左子树」，然后 `curr` 往右走一格：

```
初始 curr = 1：
  curr->left = 2（非空，进入操作）
    找前驱：从 curr->left=2 一路向右：2 -> 4（4 的 right 为空，停）  predecessor = 4
    接右子树：predecessor->right = curr->right = 5
            （节点 4 的右指针现在指向 5）
    挪左到右：curr->right = curr->left = 2；curr->left = nullptr
    curr 这一层处理完，树变成：
        1
         \
          2
         / \
        3   4
             \
              5
               \
                6
  curr = curr->right = 2

curr = 2：
  curr->left = 3（非空）
    找前驱：从 3 一路向右：3 的 right 是空，停。  predecessor = 3
    接右子树：predecessor->right = curr->right = 4
            （节点 3 的右指针现在指向 4）
    挪左到右：curr->right = curr->left = 3；curr->left = nullptr
    树变成：
        1
         \
          2
           \
            3
             \
              4
               \
                5
                 \
                  6
  curr = curr->right = 3

curr = 3：curr->left == nullptr，什么都不做，curr = curr->right = 4
curr = 4：curr->left == nullptr，什么都不做，curr = curr->right = 5
curr = 5：curr->left == nullptr，什么都不做，curr = curr->right = 6
curr = 6：curr->left == nullptr，什么都不做，curr = curr->right = nullptr

curr == nullptr，外层循环结束。
```

最终就是一根右斜链表 `1 → 2 → 3 → 4 → 5 → 6`，所有 `left` 为空，正是期望输出。

注意一个细节：处理 `curr = 1` 时，节点 5 原本是 `curr->right`，被「接」到了节点 4 的右边；此后 5 这个子树（包括它原来的右孩子 6）整棵跟着挪，内部相对结构在后续处理中也会被进一步展平（处理到 `curr = 5` 时它没左子树，直接跳过；6 同理）。整个流程靠「沿 right 推进」自然地把每个节点都过了一遍。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解一下字段即可：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 *   - 三个构造函数分别支持：无参（val=0,孩子皆空）、只给值、值+左右孩子
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
public:
    // 函数签名 void flatten(TreeNode* root)：
    //   - 参数 root：指向二叉树根节点的裸指针（力扣树题通用，节点由力扣环境管理，不用手动 delete）。
    //   - 返回值 void：要求「原地」修改树的结构（in-place），不返回新树，改的就是 root 这棵树本身。
    void flatten(TreeNode* root) {
        // curr：当前正在「展平」的节点。外层循环把它从根开始沿 right 一路往右推，
        //   每处理完一个节点就 curr = curr->right，直到走完这根未来的右斜链表。
        TreeNode *curr = root;
        while (curr != nullptr) {
            // 只在「curr 有左子树」时才需要展平操作；左子树为空的节点已经天然是「只有右」的形态，直接跳过。
            if (curr->left != nullptr) {
                // next：记下「curr 的左孩子」，等下整个左子树要挪到 curr->right。
                //   - 为什么先记？因为下一步要改 curr->right，但挪左子树用的是 curr->left 本身，
                //     这里给个语义清晰的名字 next，对应官方代码里的命名。
                auto next = curr->left;            // next 是 TreeNode*，auto 推导出来等价于 TreeNode*

                // predecessor：左子树的「最右节点」= 左子树前序遍历的最后一个节点。
                //   - 从 next（= curr->left）出发，沿 right 指针一直走到底。
                //   - 循环条件 predecessor->right != nullptr：只要有右孩子就继续往右，直到右孩子为空。
                //   - 为什么停在这里？因为「子树前序的最后一个 = 沿 right 走到底」（见「思路」分析）。
                //     前序是「根→左→右」，右孩子永远最后访问，所以一路向右就是前序末尾。
                auto predecessor = next;
                while (predecessor->right != nullptr) {
                    predecessor = predecessor->right;
                }

                // 关键三步之①：把 curr 原来的右子树，整个挂到前驱的右指针上。
                //   - predecessor->right 当前一定是 nullptr（否则上面的 while 不会停），可以直接挂。
                //   - 这一步的语义：「curr 的原右子树」在最终前序里紧接在「左子树」后面，
                //     所以把原右子树挂到「左子树前序最后一个」的右边，顺序就对了。
                //   - 注意：curr->right 在这一步被读取（赋值给 predecessor->right），
                //     但还没被覆盖，所以下一行还能用它做赋值（这里是改别人指向 curr->right，
                //     curr->right 自己暂时没动）。
                predecessor->right = curr->right;

                // 关键三步之②：把整个左子树挪到 curr->right（覆盖原来的右子树位置）。
                //   - 此时原来的右子树已经被 predecessor 接走，挂在左子树末尾，不会丢失。
                //   - curr->left 整棵子树（包括它内部所有节点）现在变成 curr 的右子树。
                //   - 必须用 next（= 原 curr->left）赋值，而不是直接 curr->right = curr->left：
                //     功能上等价，但 next 语义更清晰（先读 left、再赋给 right，避免读者混淆先后）。
                curr->right = next;

                // 关键三步之③：curr 的左指针必须置空（展开后所有 left 都是 nullptr）。
                //   - 这一步必须在「把左子树挪到右」之后再做（虽然顺序上 left 已被赋给 right，
                //     此时再置空 left 不影响 right）——若先置空 left，next 仍指向原左子树根，
                //     实际也能工作，但阅读顺序上「先挪后清」更直观。
                //   - 注意：这里改的是 curr 这一个节点的 left 成员，不影响已挪到 right 的子树内部。
                curr->left = nullptr;
            }
            // 推进到右孩子。无论上面有没有做展平操作，curr->right 现在都指向「前序下一个节点」：
            //   - 做了展平：curr->right 是原左子树根（前序下一个就是它）；
            //   - 没做展平（左子树空）：curr->right 还是原来的右子树根（前序下一个也就是它）。
            // 两种情况统一为「curr = curr->right」，非常优雅。
            curr = curr->right;
        }
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 外层循环每个节点被 `curr` 访问一次（`curr` 沿 right 一路走，不回头）。
  - 找前驱的 `while (predecessor->right != nullptr)` 看起来像嵌套循环，但**每个节点的 right 指针在整个算法过程中最多被这段代码「走过一次」**（走过的 right 在后续不会再被回访），均摊到每个节点是 O(1)。总时间是 O(n)，不是 O(n²)。
- **空间**：O(1)。
  - 只用了 `curr` / `next` / `predecessor` 三个指针变量，没有递归栈、没有显式栈、没有数组。完全原地，满足进阶要求。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么要找「左子树的最右节点」，而不是左子树的最左、最深的、或某个叶子？

因为展开后的链表是按**前序遍历顺序**串的，而「左子树前序遍历的最后一个节点」恰好就是「左子树一直沿 right 走到底的那个节点」。

- 前序是 `根 → 左 → 右`，**右孩子永远是子树里最后被访问的**。
- 所以一棵子树前序的最后一个节点 = 「不断优先走右孩子」能到达的最右下角，也就是 `while (predecessor->right) predecessor = predecessor->right;` 走到的那个。
- 我们要把「原右子树」接在「左子树前序最后一个」后面（这样前序顺序才对），所以才要找这个最右节点。

注意它不一定是「最深的」，也不一定是「最左的叶子」，而是「**沿 right 一路到底**」。如果左子树没有右孩子，前驱就是 `curr->left` 自己（左子树根）。

### Q2：三步操作的顺序能换吗？为什么「先接右子树、再挪左子树」？

**「先 `predecessor->right = curr->right`」必须在「`curr->right = next`」之前**，否则会丢链表。

- 如果先做 `curr->right = curr->left`（挪左到右），那 `curr` 原来的右子树就**从 `curr->right` 上脱落了**——你再也找不到它，更没法把它挂到 predecessor 后面。
- 先 `predecessor->right = curr->right` 把原右子树「转交」给前驱保管，之后 `curr->right` 改成什么都没关系，原右子树不会丢。

至于「置空 `curr->left`」这一步：放在最后最直观（挪完才清），但技术上放在「`curr->right = next` 之后」任意时刻都行（因为 left 的值已经赋给 right 了，清不清 left 不影响 right）。推荐就按代码里的顺序：找前驱 → 接右 → 挪左 → 清 left。

### Q3：左子树为空的节点怎么处理？需要特判吗？

**不需要特判，外层 `if (curr->left != nullptr)` 已经把它跳过了**。左子树为空的节点本身就只有右孩子（left 已经是 nullptr），已经满足「展平后只有 right」的形态，所以直接 `curr = curr->right` 往下走即可。这也是为什么推导过程中 `curr = 3, 4, 5, 6` 时都「什么都不做」。

对应边界情况：
- 空树 `root = []`：`curr = root = nullptr`，外层 while 直接不进入，函数什么都不做，符合期望输出 `[]`。
- 单节点 `root = [0]`：`curr = 0`，`curr->left` 为空，跳过，`curr = curr->right = nullptr`，结束。结果还是 `[0]`。

### Q4：为什么是 O(1) 空间？找前驱不是用了 while 循环吗？

O(1) 指的是**额外空间**只用了常数个指针变量（`curr` / `next` / `predecessor`），不随 n 增长。`while (predecessor->right)` 是「沿指针走」，**没有新开任何容器**（没有 vector、没有 stack、没有递归调用栈）。指针走动本身不占额外内存。

对比容易混淆的「用空间」的解法：
- 方法一「前序遍历存 vector」：vector 占 O(n)。
- 方法二「显式栈做前序遍历」：栈最坏占 O(n)（退化成链的树）。
- 递归解法（见复盘）：系统调用栈最坏 O(n)。
- 方法三（本主解）：只用 3 个指针，O(1)，是唯一满足进阶要求的写法。

至于「找前驱的 while 会不会让总时间变 O(n²)」——不会。可以这么算账：`predecessor` 这段代码「走过的每条 right 边」在整个算法里最多被走一次（因为走过之后那条边要么被改写、要么后续 `curr` 路径不会再回访）。所有节点加起来，predecessor 一共走的步数 ≤ n，所以总时间还是 O(n)。

## 复盘

### 可迁移套路

- **「前序遍历 + 指针重连」是树结构原地变换的通用思路**。凡是「把树重排成某种链表 / 路径」的题，先想清楚目标顺序对应哪种遍历（前序/中序/后序/层序），再看能否在遍历过程中「就地」改指针。本题目标顺序 = 前序，所以一切设计都围绕「前序下一个是谁」展开。
- **「找前驱 / 后继」是 Morris 遍历的核心技巧**。本题方法三的 `while (predecessor->right)` 找左子树最右节点，和 94 题「二叉树的中序遍历」的 Morris 算法里「找当前节点的前驱」几乎是同一段代码。把这套「沿 right 走到底找前驱」的代码块记住，遇到「原地遍历 / O(1) 空间树操作」直接能用。
- **「原地把左子树挪到右」的三步操作模板**：`predecessor->right = curr->right; curr->right = curr->left; curr->left = nullptr;`。先转移右子树防丢失，再挪左子树，最后清 left。这个顺序对一类「树重排」题都适用。
- **空间复杂度基准**：树原地操作能用「常数个指针」做到的就是 O(1)；凡是借助 vector、显式 stack、或递归（系统栈）的，最坏都是 O(n)。题目明确要求 O(1) 时，递归解法不合格。

### 解法二：前序遍历存数组再重建（官方方法一，对比用）

最直观的写法：先递归做一次前序遍历，把所有节点按访问顺序存进 `vector<TreeNode*>`，再扫一遍 vector，让前一个的 `right` 指向后一个、`left` 置空。

```cpp
class Solution {
public:
    void flatten(TreeNode* root) {
        // vector<TreeNode*>：动态数组，元素是「指向树节点的指针」。
        //   - push_back 在尾部追加；size() 取长度；at(i) 带越界检查地取第 i 个（比 [] 安全）。
        //   - 这里用它存「前序遍历顺序的节点」，长度恰为 n，所以空间 O(n)。
        vector<TreeNode*> l;
        preorderTraversal(root, l);
        int n = l.size();
        for (int i = 1; i < n; i++) {
            TreeNode *prev = l.at(i - 1), *curr = l.at(i);
            prev->left = nullptr;     // 展开后左指针全置空
            prev->right = curr;       // 右指针串成链表
        }
    }

    // 标准的前序遍历（根→左→右）：节点入数组，再递归左右。
    void preorderTraversal(TreeNode* root, vector<TreeNode*> &l) {
        if (root != NULL) {
            l.push_back(root);
            preorderTraversal(root->left, l);
            preorderTraversal(root->right, l);
        }
    }
};
```

- **时间**：O(n)，遍历 + 串接各扫一遍。
- **空间**：O(n)，vector 存全部节点；外加递归栈最坏 O(n)，总体 O(n)。不满足进阶。
- **对比**：思路最简单、几乎不会写错，适合作为「先求过、再求好」的第一版；要满足 O(1) 空间必须换成方法三。

### 解法三：递归（前序展开，对比用）

另一种常见思路是**递归**：假设 `flatten` 已经能把「左子树」和「右子树」各自展平成右斜链表，那只要把「左子树展平后的链表」插到 `curr` 和「右子树展平后的链表」之间即可。需要找到左链表的末尾来接右链表。

```cpp
class Solution {
public:
    void flatten(TreeNode* root) {
        if (root == nullptr) return;          // 空树直接返回
        flatten(root->left);                   // 先把左右子树各自展平
        flatten(root->right);

        // 此时左右子树都已经是右斜链表，把它们和 curr 拼起来：
        TreeNode *rightSub = root->right;      // 先记下原右子树（展平后的链表头）
        root->right = root->left;              // 把展平后的左链表挪到右边
        root->left = nullptr;                  // left 置空

        // 走到右链表（原左子树）的末尾，把原右子树接上去
        TreeNode *tail = root;
        while (tail->right != nullptr) {
            tail = tail->right;
        }
        tail->right = rightSub;
    }
};
```

- **时间**：O(n²) 最坏（退化成链时，每层都要走一遍右链表找尾巴）；可优化到 O(n) 但要返回尾巴指针。
- **空间**：O(n)，递归栈最坏深度 = 树高，退化成链时 O(n)。同样不满足进阶。
- **对比**：递归思路好理解，但找尾巴这一步让它比方法三逊色——方法三用「前驱」提前定位了接驳点，省掉了找尾的遍历，还顺手把空间降到 O(1)。这也是为什么官方把方法三作为进阶推荐解。
