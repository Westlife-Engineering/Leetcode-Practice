# 543 二叉树的直径

- 难度：简单
- 标签：树、**深度优先搜索**、**二叉树**
- 力扣链接：https://leetcode.cn/problems/diameter-of-binary-tree/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/diameter-of-binary-tree/solution/er-cha-shu-de-zhi-jing-by-leetcode-solution/)「二叉树的直径」（slug：`er-cha-shu-de-zhi-jing-by-leetcode-solution`）。正文主解是 **深度优先搜索（DFS）**：在递归求「子树深度」的过程中，顺手用全局变量 `ans` 维护「左子树深度 + 右子树深度」的最大值。它本质上是 [104 题「二叉树的最大深度」](./104-二叉树的最大深度.md) 的进阶——求深度的递归框架完全一样，只是**多了一个「在每个节点处更新答案」的动作**。

## 题目描述

给你一棵二叉树的根节点，返回该树的 **直径** 。

二叉树的 **直径** 是指 树中任意两个节点之间最长路径的 **长度** 。这条路径可能经过也可能不经过根节点 `root` 。

两节点之间路径的 **长度** 由它们之间边数表示。

**示例 1：**

```

输入：root = [1,2,3,4,5]
输出：3
解释：3 ，取路径 [4,2,1,3] 或 [5,2,1,3] 的长度。

```

**示例 2：**

```

输入：root = [1,2]
输出：1

```

**提示：**

- 树中节点数目在范围 `[1, 10^4]` 内
- `-100 <= Node.val <= 100`

## 思路

> 本题主要参考力扣官方题解「方法一：深度优先搜索」。

### 先厘清「直径」和「路径长度」的定义

题目有两个关键设定，必须先吃透：

1. **直径 = 任意两个节点之间最长路径的「长度」**。注意是「任意两个节点」，不是「根到某个叶子」。
2. **路径长度 = 经过的「边数」**，不是节点数。一条由 k 个节点串成的路径，含 k−1 条边，所以长度 = 节点数 − 1。

举个最简单的例子 `root = [1,2]`：

```
    1
   /
  2
```

最长路径是 `2 — 1`（两个节点之间就这一条），经过 **1 条边**，所以直径 = 1。如果错误地按「节点数」算就会得到 2，这是本题最常见的踩坑点。

### 核心难点：直径不一定经过根节点

直觉上很多人会想：「直径不就是 `根的左子树深度 + 根的右子树深度` 吗？」——这只对了一半。

这个公式**只在「最长路径恰好经过根」时成立**。但题目明确说「这条路径可能经过也可能不经过根节点」。看一个反例：

```
        1
       /
      2
     / \
    3   4
   /     \
  5       6
```

整棵树根 1 只有左子树。如果只在根处算「左深度 + 右深度」，根的右子树深度是 0，得到一个偏小的数。但真正的最长路径是 `5 — 3 — 2 — 4 — 6`，它**完全在根的左子树内部**，根本没经过根 1。

**结论：最长路径一定经过「某个节点」，但不一定是根。** 所以正确做法是——**对树里每一个节点 `node`，都算一次「以它为拐点的路径长度」，再取所有节点里的最大值**。

### 为什么是「左子树深度 + 右子树深度」？

这是本题最关键的观察。任意一条路径，都可以**以某个节点为「最高点」（拐点）**，看成两条向下的支路拼接而成：

- 一条从该节点**向左子树往下走**，最长能走多远 = 左子树深度；
- 一条从该节点**向右子树往下走**，最长能走多远 = 右子树深度；
- 两条支路在「该节点」处汇合，拼接成一条经过该节点的最长路径。

所以「以节点 `node` 为拐点的最长路径」对应的长度，就用 `左子树深度 + 右子树深度` 来衡量（如果按边数算，正好就是 L + R；如果按节点数算，是 L + R + 1，再 −1 还原成边数）。

> 「子树深度」就是「从该节点向下最多能经过的边数/节点数」——这恰好是 [104 题](./104-二叉树的最大深度.md) 算的东西。所以本题的递归骨架直接复用 104 题。

### 为什么要在「每个节点」都更新答案，而不是只在根？

因为最长路径的拐点不知道在树的哪一层。它可能是根、可能是某个内部节点、甚至可能是叶子（叶子作为拐点时，左右子树深度都是 0，贡献 0，自然不会成为最大）。

唯一稳妥的办法是**遍历每一个节点，在每一个节点处都用 `ans = max(ans, 当前节点的左深度 + 右深度)` 更新一次全局最大值**。递归恰好天然会访问到所有节点，所以我们把「更新答案」这一步塞进递归函数里，**每访问一个节点就顺手更新一次**。

### 和 104 题深度递归的区别（就多了一行）

104 题的递归是：

```cpp
int maxDepth(TreeNode* root) {
    if (root == nullptr) return 0;
    return max(maxDepth(root->left), maxDepth(root->right)) + 1;
}
```

本题把递归拆开写，**在合并左右子树结果时，多加一行更新全局答案**：

```cpp
int depth(TreeNode* root) {
    if (root == nullptr) return 0;
    int L = depth(root->left);    // 左子树深度
    int R = depth(root->right);   // 右子树深度
    ans = max(ans, L + R + 1);    // 【新增】以当前节点为拐点的路径节点数 = L+R+1，更新全局最大
    return max(L, R) + 1;          // 返回深度（和 104 题一模一样）
}
```

就这一行 `ans = max(ans, L + R + 1)` 的差别。所以这题的套路可以概括为：**「套用求深度的递归，在回溯合并时顺手维护一个全局最优」**——这是树形 DP 的最基本形态。

### 官方代码用「节点数」记录、最后再减一

官方 C++ 代码里 `ans` 记的是「路径经过的**节点数**」最大值（`L + R + 1`，那个 +1 就是当前节点自己），初始 `ans = 1`（至少根一个节点），最后 `return ans - 1` 把节点数换算成边数。

为什么不直接记边数？两种写法都对，效果一样：

- **记节点数（官方写法）**：`ans = max(ans, L + R + 1)`，初始 `ans = 1`，返回 `ans - 1`。
- **直接记边数**：`ans = max(ans, L + R)`，初始 `ans = 0`，返回 `ans`。

官方选前者是因为它和「子树深度按节点数算」口径一致（104 题的深度就是节点数），思路连贯。下面的「疑惑 Q2」会再对比这两种写法。本文代码部分**照抄官方**用节点数记法。

### 手动推导 `root = [1,2,3,4,5]`（结果应为 3）

先看清这棵树：

```
        1
       / \
      2   3
     / \
    4   5
```

从叶子往上算每个节点的 `depth`，并在每个节点处用 `L + R + 1` 更新 `ans`（`ans` 初值 1）：

```
depth(1)
├─ depth(2)
│  ├─ depth(4)                      // 4 是叶子
│  │  ├─ depth(nullptr) → 0
│  │  ├─ depth(nullptr) → 0
│  │  ├─ ans = max(1, 0+0+1) = 1   // 以 4 为拐点：节点数 1
│  │  └─ return max(0,0)+1 = 1     // 4 的深度 = 1
│  ├─ depth(5)                      // 5 是叶子
│  │  └─ return 1                  // 同 4，ans 仍为 1
│  ├─ ans = max(1, 1+1+1) = 3      // 【关键】以 2 为拐点：左深1+右深1+自己=3 个节点
│  └─ return max(1,1)+1 = 2        // 2 的深度 = 2
├─ depth(3)                         // 3 是叶子
│  └─ return 1                     // ans 仍为 3
├─ ans = max(3, 2+1+1) = 4         // 以根 1 为拐点：左深2+右深1+自己=4 个节点
└─ return max(2,1)+1 = 3           // 根 1 的深度 = 3

最终 ans = 4，返回 ans - 1 = 3  ✓
```

注意：以**节点 2** 为拐点时贡献了 3 个节点（`4 — 2 — 5`），以**根 1** 为拐点时贡献了 4 个节点（`4 — 2 — 1 — 3` 或 `5 — 2 — 1 — 3`）。最大节点数 4，对应 3 条边，所以直径 = 3。这个例子恰好「最长路径经过根」，但递归在每个节点都更新，保证即便答案在子树内部也能被捕捉到。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解字段即可：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
    // ans：记录「路径经过节点数」的全局最大值。
    //   - 为什么用成员变量（而不是 depth 的参数/返回值）？因为 depth 的返回值已经被
    //     「子树深度」占用了，没法同时再回传「全局最大节点数」。成员变量让所有递归层
    //     共享同一个 ans，每层直接 max 更新即可，最直观。
    //   - 初始化在 diameterOfBinaryTree 里做（ans = 1），因为力扣会复用同一个 Solution
    //     对象跑多个用例，必须每次入口处重置，否则会带上一个用例的脏数据。
    int ans;

    // depth：返回以 rt 为根的子树的「深度」（按节点数算，空树为 0）。
    //   - 和 104 题 maxDepth 的递归一模一样，只多了一行「更新 ans」。
    //   - 副作用：递归过程中会顺手把 ans 更新成「全局最大路径节点数」。
    int depth(TreeNode* rt) {
        if (rt == nullptr) {
            return 0;  // 空子树深度为 0（递归的「底」）。和 104 题一致。
        }
        int L = depth(rt->left);   // 左子树深度（先递归左，把左子树所有节点遍历到）
        int R = depth(rt->right);  // 右子树深度（再递归右）
        // 【本题核心】以 rt 为拐点的最长路径，经过的节点数 = L + R + 1
        //   （左支 L 个 + 右支 R 个 + rt 自己 1 个）。
        //   每访问一个节点都用 max 更新一次 ans，保证拐点无论在哪一层都不会漏。
        //   max(a, b)：STL 算法 <algorithm>，返回较大值，O(1)。
        ans = max(ans, L + R + 1);
        // 返回当前子树深度 = 左右子树更深者 + 1（自己）。和 104 题完全相同。
        return max(L, R) + 1;
    }

public:
    int diameterOfBinaryTree(TreeNode* root) {
        ans = 1;        // 至少经过根这一个节点；空树本题不会出现（节点数 >= 1）
        depth(root);    // 跑一遍递归，过程中 ans 被不断更新到最大节点数
        return ans - 1; // 题目要的是「边数」= 节点数 − 1
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点在递归中只被访问一次（进入 `depth` 一次，算完左右子树就返回），整体遍历这棵树一遍。
- **空间**：O(height)，其中 height 为二叉树的高度。
  - 空间消耗来自**递归调用栈**，栈深度等于递归深度，也就是树的高度。
  - **最好情况**：树平衡时 height = O(log n)，空间 O(log n)。
  - **最坏情况**：树退化成一条链（每个节点只有一个孩子），height = O(n)，空间也变成 O(n)。本题 n ≤ 10^4，递归绝对安全。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么直径不一定经过根节点？「根的左深度 + 右深度」错在哪？

「根的左深度 + 右深度」默认了「最长路径一定以根为拐点」，但题目明确允许路径不经过根。反例：

```
        1
       /
      2
     / \
    3   4
```

根 1 的右子树为空（深度 0），在根处算「左深 + 右深」会得到一个偏小的数。但真正的最长路径是 `3 — 2 — 4`，完全在左子树里，根本没碰到根。

正确做法：**对每个节点都算一次「以它为拐点的路径长度」，取最大**。因为最长路径一定「以某个节点为最高点」，至于这个节点是不是根，得靠遍历所有节点才能确定。递归天然访问所有节点，所以在递归里每层都 `ans = max(ans, L+R+1)` 就能覆盖所有可能拐点。

### Q2：路径长度到底是「边数」还是「节点数」？官方代码为什么最后要 `ans - 1`？

题目原文明确：**路径长度 = 经过的边数**。一条 k 个节点的路径含 k−1 条边。

但官方代码里 `ans` 记的是**节点数**（`L + R + 1`，那个 +1 是当前节点自己），所以最后 `return ans - 1` 把节点数换算回边数。为什么这么绕？因为「子树深度」按节点数算（和 104 题口径一致，空树深度 0、叶子深度 1），「左深 + 右深 + 1」正好是路径经过的节点数，思路连贯、不容易写错 +1 的位置。

也可以**直接记边数**，写法更短：

```cpp
// 直接记边数版（等价）
int ans = 0;
int depth(TreeNode* rt) {
    if (!rt) return 0;
    int L = depth(rt->left), R = depth(rt->right);
    ans = max(ans, L + R);   // 边数 = L + R（左右支路的边数相加，当前节点不计边）
    return max(L, R) + 1;
}
// 返回 ans 即可，不用减一
```

两种写法结果完全一样，选哪种看个人习惯。官方选「节点数」是因为和 104 题的深度定义统一。**关键是别记串了**：要么全程节点数最后减一，要么全程边数直接返回，不能 `ans` 记边数却 `L+R+1`。

### Q3：为什么用全局变量（成员变量 `ans`）记录最大值，不能用返回值吗？

因为 `depth` 的**返回值已经被「子树深度」占用了**。一个函数只能返回一个值，要么回传深度、要么回传最大直径，没法同时干两件事。

可选方案对比：

- **成员变量 `ans`（官方写法）**：所有递归层共享同一个变量，每层直接 `ans = max(ans, ...)` 更新。最直观、最好懂，**推荐**。
- **引用参数**：`depth(TreeNode* rt, int& ans)`，把答案通过引用传进去，效果一样，但函数签名多一个参数。
- **返回 `pair<int,int>`（深度 + 当前子树内最大直径）**：能避免全局变量，但代码啰嗦，对这种简单题得不偿失。

注意成员变量要在 `diameterOfBinaryTree` 入口处重置（`ans = 1`），因为力扣会复用同一个 `Solution` 对象跑多个用例，不重置就会带上上一个用例的脏数据。这是用成员变量唯一的坑。

### Q4：这题和 104 题「最大深度」到底什么关系？

104 题是**地基**，543 题是**进阶**：

- **相同**：递归函数的核心都是「`depth(node) = max(depth(左), depth(右)) + 1`」，求的都是子树深度，空树返回 0，叶子返回 1。
- **不同**：104 题只要根的深度（直接 `return depth(root)`）；543 题在每个节点处都「多看一眼」——用左右深度之和更新全局答案，最后返回的是这个全局答案，而不是根的深度。

一句话：**543 = 104 的递归骨架 + 「在回溯时维护一个全局最优」**。理解了 104，543 只是想通「直径 = max(每个节点的左深 + 右深)」这一步的事。

## 复盘

### 可迁移套路

- **「树形 DP / 后序遍历维护全局最优」是通用模板**。本题是最经典的入门例子：递归函数返回「子树的某个量」（这里是深度），在**回溯合并左右子树结果时**，顺手用「左结果 + 右结果 + 当前节点」去更新一个全局答案。同款套路见：
  - 124 题「二叉树中的最大路径和」：把「深度」换成「最大单臂路径和」，同样在节点处拼接左右两臂更新答案；
  - 110 题「平衡二叉树」：用左右子树高度判断是否平衡，顺便记录是否出现不平衡；
  - 687 题「最长同值路径」、685/124 都是「后序遍历 + 全局变量维护最优」。
- **「直径不一定过根」是树题里的高频陷阱**。凡是「树上最长/最值路径」类问题，都要想到**遍历每个节点当拐点**，不能只在根处算。把答案的更新放进递归（每层都更新），是最稳妥的写法。
- **全局答案用成员变量 + 入口重置**：力扣复用 `Solution` 对象，成员变量必须每次入口重置，否则跨用例污染。这是所有「成员变量记答案」题目的共同注意点。
- **「路径长度 = 边数 vs 节点数」要和题目定义对齐**。力扣树题里两种定义都出现过（本题是边数，104 题深度是节点数）。读题时圈出这一句，写代码时全程统一口径，最后再换算。

### 套路模板（可复用到一类「树上最优路径」题）

```cpp
class Solution {
    int ans;  // 全局最优，入口处重置
    int dfs(TreeNode* rt) {
        if (!rt) return 0;            // 递归的底
        int L = dfs(rt->left);        // 左子树贡献
        int R = dfs(rt->right);       // 右子树贡献
        ans = max(ans, L + R + 1);    // 【按本题：以 rt 为拐点的路径节点数】
        return max(L, R) + 1;          // 向上回传「子树深度」
    }
public:
    int diameterOfBinaryTree(TreeNode* root) {
        ans = 1; dfs(root); return ans - 1;
    }
};
```

换题时只要改两处：`ans = max(ans, ...)` 的合并式（决定「拐点处怎么拼」）、`return` 的回传式（决定「向上传递什么」）。其他骨架照抄。
