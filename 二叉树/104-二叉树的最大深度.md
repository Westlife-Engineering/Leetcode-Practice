# 104 二叉树的最大深度

- 难度：简单
- 标签：树、**深度优先搜索**、广度优先搜索、**二叉树**
- 力扣链接：https://leetcode.cn/problems/maximum-depth-of-binary-tree/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/maximum-depth-of-binary-tree/solutions/495832/er-cha-shu-de-zui-da-shen-du-by-leetcode-solution/)「二叉树的最大深度」（slug：`er-cha-shu-de-zui-da-shen-du-by-leetcode-solution`）。正文主解是 **深度优先搜索（递归）**：`max(左子树深度, 右子树深度) + 1`，这是最简洁直观的写法；广度优先搜索（BFS 层序遍历计数）放在文末「复盘」作对比。

## 题目描述

给定一个二叉树 `root` ，返回其最大深度。

二叉树的 **最大深度** 是指从 **根节点到最远叶子节点的最长路径上的节点数**。

**示例 1：**

```

输入：root = [3,9,20,null,null,15,7]
输出：3

```

**示例 2：**

```

输入：root = [1,null,2]
输出：2

```

**提示：**

- 树中节点的数量在 `[0, 10^4]` 区间内。
- `-100 <= Node.val <= 100`

## 思路

> 本题主要参考力扣官方题解「方法一：深度优先搜索」。

### 先厘清「最大深度」的定义

题目说得很明确：**最大深度 = 从根节点到最远叶子节点的最长路径上的「节点数」**（注意是节点数，不是边数）。

- 示例 1 的树形是 `3 -> 9 / 20 -> 15 / 7`：根 3 到叶子 15（或 7）经过 `3 → 20 → 15` 共 **3 个节点**，所以深度是 3。
- 一个单独的节点（根同时是叶子）深度是 1。
- **空树（`root == nullptr`）的深度规定为 0**——这是后面递归的基石。

> 顺带一提：本题语境下「深度」和「高度」数值上一样（都是从上往下数到最远叶子的节点数），但严格定义上「深度」通常是从根向下数、「高度」是从叶子向上数，方向相反。本题不用纠结这个区分，下面统一叫「深度」。

### 为什么自然想到递归？

二叉树本身就是一个**递归结构**：一棵树 = 根节点 + 左子树 + 右子树，而**左子树、右子树各自又是一棵二叉树**。所以凡是对「整棵树」要算的量，只要能拆成「对左子树算 + 对右子树算 + 合并」，就能递归。

「最大深度」恰好满足这个结构：**如果我已经知道了左子树的最大深度 `l` 和右子树的最大深度 `r`，那整棵树的最大深度就是 `max(l, r) + 1`**——左右子树里更深的那条路径，再往上接一个根节点（+1）。

### 递归式和终止条件

把上面的观察直接写成公式：

```
maxDepth(root) = max( maxDepth(root->left), maxDepth(root->right) ) + 1
```

- **递归终止条件**：`root == nullptr` 时返回 `0`。空子树没有节点，深度为 0。这是整个递归往下钻的「底」。
- **为什么 `nullptr` 返回 0 而不是 -1？** 因为题目定义深度是「路径上的**节点数**」。叶子节点 `maxDepth(叶子的空子树)=0`，套公式 `max(0, 0) + 1 = 1`，正好对应「叶子节点深度为 1」。如果返回 -1，叶子算出来就是 `max(-1,-1)+1 = 0`，与定义矛盾。（只有当题目把深度定义为「边数」时才考虑返回 -1 的写法，本题不需要。）

### 手动推导 `root = [3,9,20,null,null,15,7]`（结果应为 3）

先看清这棵树：

```
        3
       / \
      9   20
         /  \
        15   7
```

从叶子往上算每一层 `maxDepth`（缩进表示递归深度）：

```
maxDepth(3)
├─ maxDepth(9)                      // 节点 9 是叶子
│  ├─ maxDepth(nullptr) → 0        // 9 的左空子树
│  ├─ maxDepth(nullptr) → 0        // 9 的右空子树
│  └─ return max(0, 0) + 1 = 1     // 9 的深度 = 1
├─ maxDepth(20)
│  ├─ maxDepth(15)                 // 节点 15 是叶子
│  │  ├─ maxDepth(nullptr) → 0
│  │  ├─ maxDepth(nullptr) → 0
│  │  └─ return max(0, 0) + 1 = 1  // 15 的深度 = 1
│  ├─ maxDepth(7)                  // 节点 7 是叶子
│  │  └─ return 1                  // 同上，7 的深度 = 1
│  └─ return max(1, 1) + 1 = 2     // 20 的深度 = 2
└─ return max(1, 2) + 1 = 3        // 根 3 的深度 = 3  ✓
```

可以看到：每个节点的深度都依赖**它左右子树的深度**算出来，从下往上一层层汇总到根。这就是「分治」的味道——把原问题拆成同结构的子问题，子问题的解合并出原问题的解。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解一下字段即可：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 *   - 三个构造函数分别支持：无参（val=0,孩子皆空）、只给值、值+左右孩子
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
public:
    // 递归函数：返回以 root 为根的子树的最大深度（节点数）。
    //   - 参数 TreeNode* root：指向子树根节点的裸指针（力扣树题通用，节点由力扣环境管理，不用手动 delete）。
    //   - 返回值 int：该子树的最大深度。
    int maxDepth(TreeNode* root) {
        // 递归终止条件：空子树深度为 0。
        //   - 这是整个递归的「底」，没有它递归会无限往下钻 nullptr 的 nullptr……
        //   - 为什么返回 0 而不是 -1？见「思路」：题目定义深度是「路径上的节点数」，
        //     叶子的空子树返回 0，套 max(0,0)+1=1 正好让叶子深度为 1，与定义一致。
        if (root == nullptr) {
            return 0;
        }

        // max(a, b)：C++ STL 算法（<algorithm>），返回两个值中的较大值，O(1)。
        //   - 这里两次递归调用分别拿到左、右子树的最大深度。
        //   - 先把左右子树各自算完（递归），再在当前节点这一层「合并」：
        //       左右子树更深的那条路径 + 当前根节点本身（+1）= 当前树的深度。
        //   - max 的参数求值顺序未指定，但本题两次递归无副作用依赖，顺序不影响结果。
        // 返回值写法等价于：
        //   int l = maxDepth(root->left);
        //   int r = maxDepth(root->right);
        //   return (l > r ? l : r) + 1;
        // 三元运算符 ?: 和 max() 在这里完全等价，用 max 更直观地表达「取较大者」的意图。
        return max(maxDepth(root->left), maxDepth(root->right)) + 1;
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点在递归中只被访问一次（进入 `maxDepth` 一次，计算完就返回），所以整体是 O(n)。
- **空间**：O(height)，其中 height 为二叉树的高度。
  - 空间消耗来自**递归调用栈**，栈深度等于递归深度，也就是树的高度 height。
  - **最好情况**：树平衡时 height = O(log n)，空间 O(log n)。
  - **最坏情况**：树退化成一条链（每个节点只有一个孩子），height = O(n)，空间也变成 O(n)，极端时可能栈溢出。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么空节点 `nullptr` 要返回 0，而不是 -1 或 1？

关键看题目对「深度」的定义。本题明确说：**最大深度 = 从根到最远叶子路径上的「节点数」**。按这个定义推一下：

- **空树（没有任何节点）的深度必须是 0**：题目提示允许 `n=0`，一个节点都没有，路径上的节点数自然是 0。所以 `maxDepth(nullptr)` 必须返回 0。
- **验算叶子节点**：叶子（如节点 9）的左右孩子都是空，按公式 `max(maxDepth(空左), maxDepth(空右)) + 1 = max(0, 0) + 1 = 1`，叶子深度为 1，与「一个单独节点深度为 1」一致。✓

如果改成返回 -1：叶子会算成 `max(-1, -1) + 1 = 0`，叶子深度变成 0，与定义矛盾。**只有当题目把深度定义成「边数」（根节点的深度 = 0）时，才会用「`nullptr` 返回 -1、叶子返回 `max(-1,-1)+1=0`」那套写法**，力扣这类题（如 111 题「最小深度」按节点数算）大多还是返回 0。本题返回 0 即可。

### Q2：「深度」和「高度」有什么区别？这题到底算哪个？

严格定义上方向相反：

- **深度（depth）**：**从根往下**数，根的深度为 0（或 1，看定义），越往下越深。
- **高度（height）**：**从叶子往上**数，叶子的高度为 0（或 1，看定义），越往上越高。

但**本题的语境下两者数值相同**：题目要的是「根到最远叶子路径上的节点数」，无论你叫它「最大深度」还是「树的高度」，算出来都是同一个数。递归式 `max(左, 右) + 1` 本质是「子树高度加上当前节点」——从叶子往上看就是高度、从根往下看就是深度，殊途同归。不用纠结术语，记住「节点数、空树为 0」即可。

### Q3：完全二叉树和退化成链表，空间复杂度分别多少？

空间取决于递归栈深度 = 树的高度 height：

- **平衡 / 完全二叉树**：height = O(log n)。例如 n ≈ 10^4 个节点时 height ≈ 14 左右，递归栈很浅，毫无压力。
- **退化成链表**（每个节点只有一个孩子，整棵树成一条线）：height = O(n)。递归栈深度等于节点数，n = 10^4 还能扛住，但若 n 到 10^5、10^6 量级，递归写法就有栈溢出风险。这时应改用迭代写法（自底向上后序遍历，或层序 BFS），用显式数据结构（栈/队列）代替系统调用栈，空间同样是 O(n) 但不会触发栈溢出。

本题 n 上限只有 10^4，递归绝对安全，不必担心。

### Q4：能不能用迭代（非递归）来做？

可以。两种常见思路：

1. **BFS 层序遍历计数**（官方「方法二」）：用一个队列一层一层地处理，每处理完一层答案 +1，队列清空时答案就是最大深度。见「复盘」解法二。
2. **DFS + 显式栈模拟递归**：自己开一个 `stack`，把要回访的节点和「当前深度」压进去，手动模拟系统调用栈的行为。

本题递归写法只有两三行、n 又小，**递归是首选**；迭代解法更多是练手，为的是后续遇到「树很深必须避免栈溢出」「需要按层处理」等场景时有备选方案。

## 复盘

### 可迁移套路

- **「树的递归 = 左子问题 + 右子问题 + 合并」**。这是一切二叉树递归题的通用模板。凡是对「整棵树」要算的量（深度、节点数、是否平衡、直径、路径和……），第一步先问自己：**能不能拆成「对左子树算 + 对右子树算 + 在当前节点合并」？** 能拆就能递归。本题就是最纯粹的形态：`max(左深度, 右深度) + 1`。
- **递归终止条件优先想「最小边界」**：树题里最常见的终止就是「空节点返回什么」。本题空节点返回 0（对应「节点数」定义）。把这个边界定对，递归自然对。
- **「分治三件套」**：① 怎么拆子问题；② 子问题怎么合并；③ 边界返回什么。想清楚这三点，二叉树递归题基本无障碍。可对照 543 题「二叉树的直径」、110 题「平衡二叉树」、124 题「二叉树中的最大路径和」，都是同一套思路加不同的「合并」逻辑。

### 解法二：广度优先搜索（层序遍历计数，官方方法二）

思路：用队列**一层一层**地处理树。每次外层循环处理「当前层的所有节点」，把它们的孩子（下一层）全部入队，并把深度计数 `ans` 加 1。队列清空时，`ans` 就是最大深度。和普通 BFS 的区别在于：**不是逐个出队，而是按「整层」批量出队**，这样每完成一批就对应往下走了一层。

```cpp
class Solution {
public:
    int maxDepth(TreeNode* root) {
        if (root == nullptr) return 0;  // 空树深度 0，特判；否则队列会 push 一个 nullptr 后续判空混乱
        // queue<TreeNode*>：STL 队列，元素是「指向树节点的指针」。
        //   - 只能在队尾入队、队头出队：push 入队、pop 出队（无返回值）、front 看队头、empty 判空。
        //   - push / pop / front 都是 O(1)。
        //   - 语义：存放「当前层的所有节点」（处理中）+「下一层的节点」（陆续入队）。
        queue<TreeNode*> Q;
        Q.push(root);
        int ans = 0;  // 记录拓展了多少层，即最大深度
        while (!Q.empty()) {
            int sz = Q.size();  // 关键：先记下「当前层」的节点数，后续这一批全部出队才算一层
            // 内层循环：把「当前层」的 sz 个节点逐个出队，并把它们的孩子（下一层）全部入队
            while (sz > 0) {
                TreeNode* node = Q.front(); Q.pop();  // 先 front 取值再 pop，顺序不能反（pop 后队头已变）
                if (node->left)  Q.push(node->left);   // 左孩子非空才入队（避免 nullptr 污染队列）
                if (node->right) Q.push(node->right);  // 右孩子同理
                sz -= 1;
            }
            ans += 1;  // 处理完一整层，深度 +1
        }
        return ans;
    }
};
```

- **时间**：O(n)，每个节点恰好入队、出队各一次。
- **空间**：O(n)，最坏情况（完全二叉树的最后一层）队列里同时存约 n/2 个节点，量级 O(n)。
- **对比 DFS 递归**：两者时间都是 O(n)；空间上，DFS 是 O(height)（递归栈），BFS 是 O(n)（队列宽度）。**平衡树下 DFS 空间更省（O(log n) vs O(n)）**，但树退化成链时 DFS、BFS 空间都是 O(n)，只是 BFS 不会栈溢出。本题数据规模小，两种写法任选；面试里递归 DFS 更简洁，推荐作为主解，BFS 作为「能讲出第二种思路」的备用。
