# 102 二叉树的层序遍历

- 难度：中等
- 标签：树、**广度优先搜索**、**二叉树**
- 力扣链接：https://leetcode.cn/problems/binary-tree-level-order-traversal/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/binary-tree-level-order-traversal/solutions/2361553/er-cha-shu-de-ceng-xu-bian-li-by-leetcode-solutio/)「二叉树的层序遍历」（slug：`er-cha-shu-de-ceng-xu-bian-li-by-leetcode-solution`）。正文主解是 **广度优先搜索（BFS + 队列）**：用队列一层一层处理，处理每一层前先记下当前队列大小（即该层节点数），逐个出队收集，这是层序遍历的标准模板，务必背熟。

## 题目描述

给你二叉树的根节点 `root` ，返回其节点值的 **层序遍历** 。 （即逐层地，从左到右访问所有节点）。

**示例 1：**

```

输入：root = [3,9,20,null,null,15,7]
输出：[[3],[9,20],[15,7]]

```

**示例 2：**

```

输入：root = [1]
输出：[[1]]

```

**示例 3：**

```

输入：root = []
输出：[]

```

**提示：**

- 树中节点数目在范围 `[0, 2000]` 内
- `-1000 <= Node.val <= 1000`

## 思路

> 本题主要参考力扣官方题解「方法一：广度优先搜索」。

### 什么是「层序遍历」

前面 94、104 题做的都是「前/中/后序」这类**深度优先**遍历——沿着一条路一路走到底再回头。而**层序遍历**是另一种视角：**从上到下一层一层地访问，每一层内从左到右**。

拿示例 1 这棵树看：

```
        3          ← 第 1 层
       / \
      9   20       ← 第 2 层
         /  \
        15   7     ← 第 3 层
```

层序遍历的访问顺序是：先把第 1 层的 `3` 走完，再走第 2 层的 `9, 20`，最后走第 3 层的 `15, 7`。注意返回值是 **「二维」** 结构——**每一层单独成一个数组**，最终结果是 `[[3],[9,20],[15,7]]`，而不是把所有节点拍平成一个一维数组。这是本题和普通 BFS 最大的不同：**要能区分「哪些节点属于同一层」**。

### 为什么用队列（FIFO）天然适合层序

层序遍历的关键性质是：**父节点一定排在孩子前面，且同一层的节点从左到右依次被访问**。

- 一个节点的左孩子、右孩子是在「处理这个节点时」才被发现的，必须排到它后面；
- 同一层里，先被发现的节点（更靠左）也要先被处理。

**「先进先出」的队列恰好满足这个要求**：处理某个节点时，把它的左右孩子依次 push 到队尾；下一次从队头取节点，拿到的永远是「最早入队、还没处理」的那个——也就是同一层里更靠左的，或者更靠上一层的。所以 `queue` 是层序遍历的标配容器。

> 对比：94 题中序迭代用的是 `stack`（后进先出 LIFO），配合「一路向左压栈」实现深度优先；本题用 `queue`（先进先出 FIFO），实现广度优先。两套容器对应两类遍历，别搞混。

### 核心技巧：处理前先记下「当前层的节点数」

如果只是普通 BFS（一个一个出队、孩子入队），我们只能得到一个**拍平的一维序列**，无法区分层与层的边界。题目要的是**每层一个数组**，所以得想办法「按层批量出队」。

**官方的巧妙做法**：在处理每一层**之前**，先用 `int size = q.size();` 记下当前队列里有多少个节点——**这个数字恰好就是「当前这一层」的节点数**。然后内层循环固定执行 `size` 次出队，出队的同时把这些节点的孩子（下一层）push 进队列。

为什么这招是对的？关键在于一个**循环不变式**：每轮外层循环开始时，**队列里恰好装着「某一层的全部节点」，且从左到右排列**。第 1 轮队列里只有 `root`（第 1 层），处理时把它的孩子入队——于是第 1 轮结束时，队列里装的就是第 2 层的全部节点。以此类推，第 `i` 轮开始时队列里就是第 `i` 层。所以 `q.size()` 取到的正好是第 `i` 层的节点个数。

**绝对不能把 `q.size()` 直接写进 `for` 的循环条件里**——因为内层循环在出队的同时还在把下一层的节点 push 进队列，`q.size()` 是动态变化的，那样循环次数就不对了。必须先存到一个局部变量 `size`，循环判断这个固定值。

### 手动推导 `root = [3,9,20,null,null,15,7]`（结果应为 `[[3],[9,20],[15,7]]`）

按算法一步步跑（队列左边是队头、右边是队尾；`ret` 是最终返回的二维数组）：

```
初始  q=[3]                          ret=[]
──────────────────────────────────────────────────────
外层第 1 轮（处理第 1 层）：
  size = q.size() = 1
  ret.push_back(空数组)              ret=[ [] ]
  内层循环 i=1..1：
    i=1：node=q.front()=3, q.pop()   q=[]
          ret.back().push_back(3)   ret=[ [3] ]
          3->left=9 非空：q.push(9)  q=[9]
          3->right=20 非空：q.push(20) q=[9,20]
  一层结束                          ret=[ [3] ]，队列变成第 2 层
──────────────────────────────────────────────────────
外层第 2 轮（处理第 2 层）：
  size = q.size() = 2               （注意：此时不能再读 q.size()，必须先存好）
  ret.push_back(空数组)              ret=[ [3], [] ]
  内层循环 i=1..2：
    i=1：node=q.front()=9, q.pop()   q=[20]
          ret.back().push_back(9)   ret=[ [3], [9] ]
          9->left=空、9->right=空，不入队
    i=2：node=q.front()=20, q.pop()  q=[]
          ret.back().push_back(20)  ret=[ [3], [9,20] ]
          20->left=15 非空：q.push(15) q=[15]
          20->right=7 非空：q.push(7)  q=[15,7]
  一层结束                          ret=[ [3],[9,20] ]，队列变成第 3 层
──────────────────────────────────────────────────────
外层第 3 轮（处理第 3 层）：
  size = q.size() = 2
  ret.push_back(空数组)              ret=[ [3],[9,20], [] ]
  内层循环 i=1..2：
    i=1：node=15, q.pop()            q=[7]
          ret.back().push_back(15)  ret=[ [3],[9,20],[15] ]
          15 是叶子，孩子皆空，不入队
    i=2：node=7, q.pop()             q=[]
          ret.back().push_back(7)   ret=[ [3],[9,20],[15,7] ]
          7 是叶子，孩子皆空，不入队
  一层结束                          ret=[ [3],[9,20],[15,7] ]
──────────────────────────────────────────────────────
外层条件 !q.empty() → q 是空，退出循环

最终 ret = [[3],[9,20],[15,7]]  ✓
```

可以看到每一轮外层循环对应「处理一层」，`size` 固定了这一轮要出队多少个节点，出队的过程中孩子陆续入队、为下一轮做好准备。这是整套算法的灵魂。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解一下字段即可：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 *   - 三个构造函数分别支持：无参（val=0,孩子皆空）、只给值、值+左右孩子
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
public:
    vector<vector<int>> levelOrder(TreeNode* root) {
        // vector<vector<int>>：二维动态数组，即「数组的数组」。
        //   - 外层每一个元素 vector<int> 是「某一层所有节点的值」，按从左到右排。
        //   - 内层 vector<int> 用 ret.back().push_back(val) 追加当前层节点值。
        //   - 这是题目要求的返回类型：每一层单独一个数组，整体再装进一个外层数组。
        vector<vector<int>> ret;

        // 空树特判：根节点为空时直接返回空二维数组 ret（此时 ret == []，对应示例 3）。
        //   - 为什么这里特判？因为如果让 nullptr 进队列，后面 q.front()->val 会解引用空指针，
        //     程序直接崩。把空树挡在 BFS 外面更干净。
        if (!root) {
            return ret;
        }

        // queue<TreeNode*>：STL 队列，元素是「指向树节点的指针」。
        //   - 只能在 队尾入队、队头出队：push（队尾入）、pop（队头出，无返回值）、
        //     front（看队头，不弹出）、empty（判空）。push/pop/front 都是 O(1)。
        //   - 注意：queue 没有 back() 之外的随机访问，不能下标取，也不能遍历整个队列——
        //     它被刻意设计成「只能从两头操作」的受限制容器。
        //   - 语义：始终存放「某一层（或两层交界处）尚未处理的节点」，队头是最早入队、
        //     最该先处理的那个。
        //   - 为什么存「指针」而不是 TreeNode 对象？因为节点本身由力扣环境管理（树节点的
        //     生命周期由调用方负责），存指针避免拷贝整棵树，也避免双重释放。
        queue<TreeNode*> q;
        q.push(root);  // 把根节点入队，作为第 1 层的初始节点

        // 外层循环：每一轮对应「处理一层」。
        //   - 条件 !q.empty()：只要队列里还有没处理的节点，就还没遍历完。
        //   - 队列空了意味着最后一层的节点都没有孩子（都是叶子），整棵树遍历完成。
        while (!q.empty()) {
            // ★核心技巧★：先把「当前层的节点数」记到局部变量 currentLevelSize 里。
            //   - 为什么不能在内层 for 里直接写 i < q.size()？因为内层循环每出一个节点、
            //     就可能 push 进它的两个左孩子右孩子，q.size() 是动态变化的，
            //     循环次数就失控了（会把下一层的节点也当成当前层处理）。
            //   - 所以必须在进入内层循环「之前」把 size 固定下来，内层只循环这个固定次数，
            //     这样 push 进来的下一层节点会被留到下一轮外层循环再处理——层与层就分开了。
            int currentLevelSize = q.size();

            // ret.push_back(vector<int>())：给外层数组追加一个「空的一维数组」，
            //   - 这个空数组代表「当前这一层」的容器，下面用 ret.back() 访问它并往里塞值。
            //   - vector<int>() 是调用 vector 的默认构造，造一个临时的空 vector 传进去。
            //   - 注意 ret.back() 返回的是「最后一个元素的引用」，对它 push_back 就是
            //     往「当前层那个数组」里追加节点值。
            ret.push_back(vector<int>());

            // 内层循环：把「当前层」的 currentLevelSize 个节点逐个出队处理。
            //   - 用 i 从 1 到 currentLevelSize，固定循环次数——这正是「区分层」的关键。
            //   - 此循环过程中 push 进队列的孩子，全部属于「下一层」，本轮不会动它们。
            for (int i = 1; i <= currentLevelSize; ++i) {
                // 先用 front() 取队头节点，再用 pop() 弹出。
                //   - front() 只看不弹；pop() 只弹不返回值——所以必须两步走：
                //     先 front 拿到指针存到 node，再 pop 把它从队列里移走。
                //   - 顺序绝对不能反：如果先 pop，队头就变了，再 front 拿到的是下一个节点。
                auto node = q.front();
                q.pop();

                // 把当前节点的值塞进「当前层那个数组」（ret 的最后一个 vector）。
                //   - ret.back() 拿到当前层的 vector<int>&，push_back 在它末尾追加 val。
                //   - 也可以用 emplace_back(node->val)，效果一样；emplace_back 少一次
                //     拷贝构造（对 int 这种基本类型差别可以忽略）。
                ret.back().push_back(node->val);

                // 把当前节点的左右孩子依次入队（注意必须先左后右，保证同一层内从左到右的顺序）。
                //   - 只有孩子非空才入队：避免 nullptr 污染队列，否则后续 front()->val 会崩。
                //   - 这些入队的孩子会被留到「下一轮外层循环」处理——因为本轮内层循环
                //     的次数 currentLevelSize 是上一轮算好的固定值，不包含它们。
                if (node->left) {
                    q.push(node->left);
                }
                if (node->right) {
                    q.push(node->right);
                }
            }
        }

        return ret;  // 遍历完成，返回装着每一层数组的二维结果
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点恰好被入队一次、出队一次、值被 `push_back` 一次，整体 O(n)。
- **空间**：O(n)。
  - 空间消耗来自**队列**。队列中元素个数最多不超过 n。
  - 最坏情况：**完全二叉树的最底层**约有 n/2 个节点同时待处理，队列长度达到约 n/2，量级仍是 O(n)。
  - （对比：104 题递归 DFS 的空间是 O(height) = 树高，平衡树下比 BFS 更省；但 BFS 必须同时把一整层都放进队列，所以是 O(n)。层序遍历的代价就是要付出更多空间。）

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么必须先记下 `size = q.size()`，不能直接在内层 `for` 里判断 `i < q.size()`？

这是**本题最容易踩的坑**。`q.size()` 是**动态变化**的——内层循环每次出一个节点，紧接着又把它的左右孩子 push 进队列，队列长度随时在变。如果你写：

```cpp
for (int i = 0; i < q.size(); ++i) { ... }   // 错！
```

`i` 和 `q.size()` 同步增长，循环条件几乎一直成立，就会把下一层的节点也当成当前层一起处理掉，**层与层混在一起，结果不再是「每层一个数组」**。

正确做法是进入内层循环**之前**，把 `q.size()` 读到一个局部变量 `size` 里固定下来，内层只循环这个固定次数。这样本轮 push 进来的孩子（属于下一层）会原封不动留到下一轮外层循环——层与层的边界就被这个固定 `size` 切开了。记住口诀：**「先存 size，再按 size 出队」**。

### Q2：能不能不记 size，用别的办法区分层？

可以，但都更麻烦。常见的替代方案有两种：

- **二元组法**：队列里不存裸指针，而存 `pair<TreeNode*, int>`（节点 + 它所在的层数 `level`）。出队时根据 `level` 判断该塞进外层的哪个数组。这正是官方题解开头说的「最朴素方法」。它能做对，但要额外维护 `level` 字段，还要处理「新建一层数组」的时机判断，代码更长。**记 size 的做法巧妙地省掉了 `level` 维护**，用一个固定循环次数就切开了层，更优雅。
- **双队列 / 交替队列**：用两个队列分别存当前层和下一层，当前层空了就切到下一层。也行，但要管理两个队列，啰嗦。

面试和竞赛里**记 size 是公认的标准写法**，背熟它即可。

### Q3：空树（`root = nullptr`）怎么办？

代码开头已经特判：`if (!root) return ret;`，直接返回空二维数组 `[]`，对应示例 3。

为什么不靠 `while (!q.empty())` 自动处理？因为如果先 `q.push(root)` 把 `nullptr` 塞进队列，第一轮外层循环会进 `q.front()` 拿到 `nullptr`，然后 `node->val` 解引用空指针，程序直接段错误。所以必须在入队**之前**就挡掉空树。这也是为什么内层 `if (node->left)` / `if (node->right)` 要判空——同样的道理，避免把空指针塞进队列。

### Q4：队列为什么用 `queue`，不用 `deque` 或 `list`？

`queue` 是 STL 专门为「先进先出」场景设计的**容器适配器**（container adapter），它内部默认基于 `deque` 实现，但对外只暴露 `push/pop/front/back/empty/size` 这几个接口——**刻意屏蔽了随机访问等用不到的功能**。好处是：

- **语义清晰**：用到 `queue` 就说明这里只做「队尾入、队头出」，读代码的人一眼明白意图；
- **防止误用**：你没法对 `queue` 下标取值，也就不会写出「直接访问队列中间元素」这种破坏 FIFO 性质的错误代码。

`deque`（双端队列）虽然也能干这事（两头都能进出），但功能太多反而容易写错；`list` 也行但常数更大、内存更碎。层序遍历就是 `queue` 的标准用武之地，**看到「BFS 层序」就条件反射地用 `queue`**。只有在需要「双端都能操作」（如 239 题滑动窗口最大值里的单调队列）时才用 `deque`。

## 复盘

### 可迁移套路

- **「BFS 层序 = 队列 + 记录每层大小」是所有 BFS 题的通用模板**。记忆口诀：**外层 `while (!q.empty())` + 进层先存 `size = q.size()` + 内层 `for` 按固定 `size` 出队**。这三件套是层序遍历的招牌，背熟后能套到几乎所有「按层 / 按广度」处理的题上。

- **「记 size 区分批次」这个技巧可以迁移**。凡是要把一个序列**按某种边界切成若干批**处理，都可以用「先存当前批次长度、再按固定长度循环」的思路。比如 BFS 求最短路径要按「步数」分层、按层累加统计等，都是同一招。

- **BFS 的复杂度基准**：树/图上的 BFS 时间一定是 O(n)（每个节点入队出队各一次），空间取决于「队列同时最多装多少节点」——树的 BFS 是 O(n)（最底层约 n/2 个节点），这一点和 DFS 的 O(height) 不同，做空间分析时别套错。
