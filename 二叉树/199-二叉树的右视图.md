# 199 二叉树的右视图

- 难度：中等
- 标签：树、深度优先搜索、**广度优先搜索**、**二叉树**
- 力扣链接：https://leetcode.cn/problems/binary-tree-right-side-view/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/binary-tree-right-side-view/solutions/2071307/er-cha-shu-de-you-shi-tu-by-leetcode-solution/)「二叉树的右视图」（slug：`er-cha-shu-de-you-shi-tu-by-leetcode-solution`）。正文主解是 **广度优先搜索（BFS 层序遍历）**：直接复用 102 题「层序遍历」的模板，每一层处理时把**最后一个（最右）**节点的值加入结果。深度优先搜索（根→右→左，记录每层第一个访问到的节点）放在文末「复盘」作对比。

## 题目描述

给定一个二叉树的 **根节点 `root`**，想象自己站在它的右侧，按照从顶部到底部的顺序，返回从右侧所能看到的节点值。

**示例 1：**

```

输入：root = [1,2,3,null,5,null,4]
输出：[1,3,4]

```

**示例 2：**

```

输入：root = [1,2,3,4,null,null,null,5]
输出：[1,3,4,5]

```

**示例 3：**

```

输入：root = [1,null,3]
输出：[1,3]

```

**示例 4：**

```

输入：root = []
输出：[]

```

**提示:**

- 二叉树的节点个数的范围是 `[0,100]`
- `-100 <= Node.val <= 100`

## 思路

> 本题主要参考力扣官方题解「方法二：广度优先搜索」。官方还给了「方法一：深度优先搜索」，思路更绕一点（要维护哈希表记每层第一个见到的节点），放在复盘里对比。

### 「右视图」到底是什么意思

题目说「想象自己站在树的右侧，从上往下看，能看到哪些节点」。一开始容易想岔，其实只要画一棵树、从右边瞄一眼就立刻明白：

```
        1            ← 从右边看过去，第 1 层能看到 1
       / \
      2   3          ← 第 2 层：3 在最右边挡住了 2，只能看到 3
       \   \
        5   4        ← 第 3 层：4 挡住了 5，只能看到 4
```

站在右边视线扫过去，能看到的就是 `1, 3, 4`，正好对应示例 1 的输出 `[1,3,4]`。

所以**「右视图」的本质极其朴素：每一层只取最右边那个节点**。抽象成一句话：

> **答案 = 「每一层最右节点」组成的列表，从上到下排列。**

那「每一层最右」怎么拿到？只要能**一层一层地遍历**这棵树、并且知道每层从左到右的顺序，取每层的最后一个即可——这正是 **层序遍历（BFS）** 的拿手好戏。

### 复用 102 题「层序遍历」的模板

102 题（二叉树的层序遍历）已经把 BFS 层序的套路吃透了，核心三件套：

1. 用一个 `queue<TreeNode*>` 当队列；
2. 外层 `while (!q.empty())` 每轮处理一层；
3. **进入内层循环前**，先 `int size = q.size();` 把「当前层的节点数」固定下来，内层 `for` 循环固定 `size` 次——这一步是区分层与层的关键。

199 题和 102 题的区别只有一个：**102 要每层所有节点（二维数组），199 只要每层最后一个节点（一维数组）**。所以代码几乎照搬，把「每层收集整层」改成「每层只收集最后一个」即可。

### 怎么拿到「每层最后一个」

内层循环固定跑 `size` 次，用 `i` 从 `0` 到 `size-1` 计数。**当 `i == size - 1` 时，当前出队的节点就是这一层的最后一个，也就是最右节点**——把它的值塞进答案。其余位置（`i < size - 1`）只做「出队 + 把孩子入队」，不收集值。

> 为什么最后一个一定是最右？因为入队顺序是「先左孩子后右孩子」（见代码里 `push(left)` 在 `push(right)` 之前），所以同一层内队列从左到右排列，最后出队的就是最靠右的。102 题里也讲过这个不变式。

### 手动推导 `root = [1,2,3,null,5,null,4]`（结果应为 `[1,3,4]`）

先看清这棵树：

```
        1          ← 第 1 层
       / \
      2   3        ← 第 2 层
       \   \
        5   4      ← 第 3 层
```

按算法一步步跑（队列左边是队头、右边是队尾；`ans` 是最终答案）：

```
初始  q=[1]                                 ans=[]
──────────────────────────────────────────────────────
外层第 1 轮（处理第 1 层）：
  size = q.size() = 1
  内层 for i=0..0：
    i=0：node=q.front()=1, q.pop()           q=[]
          i==size-1（0==0）成立 → ans.push_back(1)   ans=[1]
          1->left=2 非空：q.push(2)           q=[2]
          1->right=3 非空：q.push(3)          q=[2,3]
  一层结束                                   ans=[1]，队列变成第 2 层
──────────────────────────────────────────────────────
外层第 2 轮（处理第 2 层）：
  size = q.size() = 2
  内层 for i=0..1：
    i=0：node=2, q.pop()                      q=[3]
          i==size-1（0==1）不成立 → 不收集
          2->left=空，不入队
          2->right=5 非空：q.push(5)          q=[3,5]
    i=1：node=3, q.pop()                      q=[5]
          i==size-1（1==1）成立 → ans.push_back(3)   ans=[1,3]
          3->left=空，不入队
          3->right=4 非空：q.push(4)          q=[5,4]
  一层结束                                   ans=[1,3]，队列变成第 3 层
──────────────────────────────────────────────────────
外层第 3 轮（处理第 3 层）：
  size = q.size() = 2
  内层 for i=0..1：
    i=0：node=5, q.pop()                      q=[4]
          i==size-1（0==1）不成立 → 不收集
          5 是叶子，孩子皆空，不入队
    i=1：node=4, q.pop()                      q=[]
          i==size-1（1==1）成立 → ans.push_back(4)   ans=[1,3,4]
          4 是叶子，孩子皆空，不入队
  一层结束                                   ans=[1,3,4]
──────────────────────────────────────────────────────
外层条件 !q.empty() → q 是空，退出循环

最终 ans = [1,3,4]  ✓
```

可以看到每一轮外层循环对应「处理一层」，只有当 `i` 走到 `size-1` 时才往答案里塞值——这正是「取每层最右」的精髓。整套流程和 102 题几乎一模一样，只是收集时机变了。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解一下字段即可：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
public:
    vector<int> rightSideView(TreeNode* root) {
        // vector<int>：动态数组，存「每层最右节点的值」，从上到下排。
        //   - 这就是题目要的返回类型：一维数组（不是 102 题的二维），因为每层只要一个值。
        //   - push_back(val) 在末尾追加一个元素，O(1) 均摊。
        vector<int> ans;

        // 空树特判：根为空直接返回空数组（对应示例 4）。
        //   - 不特判的话，nullptr 进队列后 q.front()->val 会解引用空指针直接崩。
        if (!root) {
            return ans;
        }

        // queue<TreeNode*>：STL 队列，元素是「指向树节点的指针」。
        //   - 只能在 队尾入队、队头出队：push（队尾入）、pop（队头出，无返回值）、
        //     front（看队头，不弹出）、empty（判空）。push/pop/front 都是 O(1)。
        //   - 注意：queue 没有 operator[]，不能下标取、不能遍历整个队列——
        //     它被刻意设计成「只能从两头操作」的受限制容器（容器适配器，内部默认基于 deque）。
        //   - 语义：始终存放「某一层尚未处理的节点」，队头是最早入队、最该先处理的那个。
        //   - 为什么存「指针」而不是 TreeNode 对象？节点本身由力扣环境管理（生命周期由调用方负责），
        //     存指针避免拷贝整棵树，也避免双重释放。
        queue<TreeNode*> q;
        q.push(root);  // 把根节点入队，作为第 1 层的初始节点

        // 外层循环：每一轮对应「处理一层」。
        //   - 条件 !q.empty()：只要队列里还有没处理的节点，就还没遍历完。
        //   - 队列空了意味着最后一层的节点都是叶子（没有孩子入队），整棵树遍历完成。
        while (!q.empty()) {
            // ★核心技巧★：先把「当前层的节点数」记到局部变量 size 里。
            //   - 为什么不能在内层 for 里直接写 i < q.size()？因为内层循环每出一个节点、
            //     就可能 push 进它的左右孩子，q.size() 是动态变化的，循环次数就失控了
            //     （会把下一层的节点也当成当前层处理，导致答案错乱）。
            //   - 必须在进入内层循环「之前」把 size 固定下来，内层只循环这个固定次数，
            //     这样 push 进来的下一层节点会留到下一轮外层——层与层就分开了。
            //   - 口诀：「先存 size，再按 size 出队」（和 102 题完全一致）。
            int size = q.size();

            // 内层循环：把「当前层」的 size 个节点逐个出队处理。
            //   - i 从 0 数到 size-1，固定循环次数——这正是「区分层」的关键。
            //   - 此循环过程中 push 进队列的孩子，全部属于「下一层」，本轮不会动它们。
            for (int i = 0; i < size; ++i) {
                // 先用 front() 取队头节点，再用 pop() 弹出。
                //   - front() 只看不弹；pop() 只弹不返回值——所以必须两步走：
                //     先 front 拿到指针存到 node，再 pop 把它从队列里移走。
                //   - 顺序绝对不能反：如果先 pop，队头就变了，再 front 拿到的是下一个节点。
                TreeNode* node = q.front();
                q.pop();

                // ★本题灵魂★：当 i == size - 1 时，说明这是当前层最后一个出队的节点，
                //   也就是「从左到右」里最靠右的那个——它就是右视图能看到的节点。
                //   - 为什么最后一个就是最右？因为下面入队顺序是「先左后右」，同一层内
                //     队列从左到右排列，最后出队的一定是最右节点。
                //   - 此时把它的值塞进答案；其余 i 不收集。
                if (i == size - 1) {
                    ans.push_back(node->val);
                }

                // 把当前节点的左右孩子依次入队（必须先左后右，保证同一层内从左到右的顺序）。
                //   - 只有孩子非空才入队：避免 nullptr 污染队列，否则后续 front()->val 会崩。
                //   - 这些入队的孩子会被留到「下一轮外层循环」处理——因为本轮内层循环
                //     的次数 size 是上一轮算好的固定值，不包含它们。
                if (node->left) {
                    q.push(node->left);
                }
                if (node->right) {
                    q.push(node->right);
                }
            }
        }

        return ans;  // 遍历完成，返回每层最右节点组成的答案
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点恰好被入队一次、出队一次，值最多被 `push_back` 一次，整体线性。官方也指出「树的形状无法提前知晓，不可能设计出优于 O(n) 的算法」，所以这已经是最优。
- **空间**：O(n)。
  - 空间消耗来自**队列**。队列中元素个数最多不超过 n。
  - 最坏情况：**完全二叉树的最底层**约有 n/2 个节点同时待处理，队列长度达到约 n/2，量级仍是 O(n)。
  - （对比：104 题 DFS 递归的空间是 O(height) = 树高，平衡树下比 BFS 更省；但 BFS 必须把一整层都放进队列，所以是 O(n)。层序遍历的代价就是要付出更多空间。）

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么取「每层最后一个」就是右视图？能不能取第一个？

关键在于**入队顺序**。代码里是「先 push 左孩子、再 push 右孩子」，所以同一层内队列从左到右排列，最后一个出队的就是**最右节点**——从右边看过去能看到的正是它。

如果改成「先右后左」入队，那么**第一个**出队的（`i == 0`）反而是最右节点，改成 `if (i == 0)` 收集也对。两种写法都行，只是「先左后右 + 取最后一个」更贴合 102 题的标准模板（层序默认从左到右），背一套就够了，所以推荐保持「先左后右、取最后一个」。

> 一句话：**入队顺序决定「最后一个」是哪一侧**。先左后右 → 最后一个是右；先右后左 → 最后一个是左。

### Q2：右视图和左视图的区别是什么？

把入队顺序和收集逻辑反过来就是左视图：

- **右视图**（本题）：先左后右入队，收集每层最后一个（最右）。
- **左视图**：先右后左入队，收集每层最后一个（此时最后一个是最左）；或者保持先左后右，改成收集每层第一个（`i == 0`）。

两道题本质完全一样，都是「层序遍历 + 取每层的某个特征节点」。把 BFS 模板吃透，左右视图随手改一行就能切换。

### Q3：某一层只有一个左孩子（没有右孩子），这个左孩子算不算右视图？

**算**。这点特别容易想错。看示例 1 的第 2 层：节点 `2` 只有右孩子 `5`、没有左孩子，但 `5` 依然出现在答案 `[1,3,4]` 之外的推导里（实际上示例 1 答案没包含 5，是因为第 3 层有更靠右的 4 挡住了它）。

关键理解：**右视图是「每一层最靠右的那个节点」，不管它是左孩子还是右孩子**。只要在它所在的层里、横向位置最靠右，从右边看就能看到它。比如这棵树：

```
    1
   /
  2
```

第 2 层只有节点 `2`（它是 `1` 的左孩子），但整层只有它一个，它就是第 2 层最右的，右视图是 `[1,2]`。算法能正确处理：第 2 层 `size=1`，`i=0==size-1` 成立，收集 `2`。

### Q4：能不能用 DFS（深度优先搜索）做？

可以，官方「方法一」就是 DFS。思路是**按「根 → 右 → 左」的顺序遍历**，这样对每一层来说，**第一个访问到的节点一定是最右的**（因为先走右子树）。维护一个「层数 → 节点值」的哈希表，只有当某层第一次被访问时才记录，遍历完按层数顺序输出即可。

DFS 写法时间空间也都是 O(n)，但需要额外的哈希表（或借助递归深度判断「是否首次到达该层」），思路比 BFS 绕一点。**本题首选 BFS**（直接复用 102 模板，直观、改动小），DFS 放在「复盘」对比。两者复杂度一致，面试里讲出任意一种都行，能讲两种加分。

## 复盘

### 可迁移套路

- **「层序遍历 + 取每层特征节点」是一大类题的通用模板**。记忆口诀：**外层 `while (!q.empty())` + 进层先存 `size = q.size()` + 内层 `for` 按固定 `size` 出队**。三件套是层序遍历的招牌，背熟后只要改「每层做什么」就能套到很多题上：
  - **102 层序遍历**：每层收集**所有**节点（二维数组）。
  - **199 右视图**：每层收集**最后一个**节点（本题）。
  - **107 层序 II**：自底向上层序，正常 BFS 后 `reverse` 结果即可。
  - **515 每行最大值**：每层收集**最大值**。
  - **637 行平均值**：每层收集**平均值**。
  - **429 N 叉树层序**：把「左右孩子」改成「孩子列表」即可。
- **「按特征位置收集」是本题的关键变体**。凡是要取「每层最右 / 最左 / 第 k 个」的题，都是「内层循环里用 `i` 判断当前位置，命中条件就收集」。本题 `i == size - 1` 就是取最右，改成 `i == 0` 就是取最左，非常灵活。
- **BFS 的复杂度基准**：树/图上的 BFS 时间一定是 O(n)（每个节点入队出队各一次），空间取决于「队列同时最多装多少节点」——树的 BFS 是 O(n)（最底层约 n/2 个节点），这一点和 DFS 的 O(height) 不同，做空间分析时别套错。

### 解法二：深度优先搜索（根→右→左，官方方法一）

思路：按「**根 → 右子树 → 左子树**」顺序做 DFS（注意这不是标准的前序「根左右」，而是「根右左」，目的是让每一层最先访问到的节点就是最右节点）。用一个数组 `ans` 按层数记录答案，递归时传入当前层数 `depth`：

- 如果 `depth == ans.size()`，说明**当前层还没被记录过**，这个节点就是该层第一个（最右）被访问到的，塞进 `ans`；
- 否则说明该层已经记过更靠右的节点了，跳过。

这样遍历完整棵树，`ans` 自然就是从上到下每层最右节点的列表。

```cpp
class Solution {
public:
    // 递归函数：以「根 → 右 → 左」顺序遍历，depth 是当前节点所在层（根为 0）。
    //   - ans 按引用传递，全局共享一份结果数组。
    void dfs(TreeNode* root, int depth, vector<int>& ans) {
        if (root == nullptr) return;  // 空节点直接返回

        // ★关键★：depth == ans.size() 说明「这一层还没被任何人记录过」，
        //   而我们按「根→右→左」遍历，第一个到这层的一定是最右节点 → 记下来。
        //   - ans.size() 同时表示「目前已经记录了多少层」，正好等于「下一个新层的下标」。
        //   - 例如根节点 depth=0、ans 为空（size=0），0==0 成立 → 记录根。
        //     之后往右子树走，depth=1、ans.size()=1，1==1 成立 → 记录右孩子，以此类推。
        if (depth == ans.size()) {
            ans.push_back(root->val);
        }

        // 先右后左！保证同一层里最右的节点最先被访问到。
        //   - 如果写反成「先左后右」，记录到的就是每层最左节点了（那就变成左视图）。
        dfs(root->right, depth + 1, ans);
        dfs(root->left,  depth + 1, ans);
    }

    vector<int> rightSideView(TreeNode* root) {
        vector<int> ans;
        dfs(root, 0, ans);  // 从根、第 0 层开始
        return ans;
    }
};
```

- **时间**：O(n)，每个节点访问一次。
- **空间**：O(height)，递归栈深度等于树高；平衡树 O(log n)，退化成链 O(n)。注意这里不需要像 BFS 那样开队列，只算递归调用栈，所以**空间上 DFS 通常比 BFS 更省**（O(height) vs O(n)）。
- **对比 BFS 主解**：两者时间都是 O(n)。DFS 代码更短、空间更省（递归栈 vs 队列），但思路稍微绕（要理解「`depth == ans.size()` 判断首次到达」）。BFS 直接复用 102 模板、改动最小、最不容易写错。**面试里 BFS 更稳，DFS 当作能讲出第二种思路的加分项**。

### 本题与 102 题的关系

199 就是 102 的「单点收集版」——把「每层收集整层」改成「每层只收集最后一个」，其余代码一字不改。所以**只要 102 的层序模板背熟，199 几乎是白送**。这两道题建议连着刷，强化「同一套模板、不同收集策略」的迁移能力。
