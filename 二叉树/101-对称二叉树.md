## 题目描述

给你一个二叉树的根节点 `root` ， 检查它是否轴对称。

**示例 1：**

```
输入：root = [1,2,2,3,4,4,3]
输出：true
```

**示例 2：**

```
输入：root = [1,2,2,null,3,null,3]
输出：false
```

**提示：**

- 树中节点数目在范围 `[1, 1000]` 内
- `-100 <= Node.val <= 100`

**进阶：** 你可以运用递归和迭代两种方法解决这个问题吗？

## 思路

> 本题参考力扣官方「方法一：递归」。

### 整棵树「对称」不好直接判断，得转换问题

题目问的是「整棵树是否轴对称」。直接盯着一棵树看，很难写出像样的递归——因为对称的判定要**同时比较左右两边**，而一个 `root` 指针要么往左、要么往右，没法同时兼顾两侧。

关键是做一次**问题转换**：一棵树对称，等价于它的**左子树和右子树互为镜像**。于是任务从「判断一棵树」退化成「判断两棵树的关系」，这就能用递归优雅地表达了。这一步转换是本题的核心难点，一旦想通，后面的代码几乎是顺水推舟。

### 「镜像对称」的递归定义

两棵树 `p` 和 `q` 什么时候互为镜像？只要同时满足下面三条：

1. **两个根节点的值相等**：`p->val == q->val`；
2. **`p` 的左子树 与 `q` 的右子树** 互为镜像；
3. **`p` 的右子树 与 `q` 的左子树** 互为镜像。

为什么是「`p` 的左 配 `q` 的右」这种**交叉配对**？想象沿树干中线放一面镜子——左半边在镜中翻到右半边，越靠左的位置，映出来的越靠右。所以「左」永远和对方的「右」对照。这正是「镜像」二字的含义，和「两棵树是否相同」(100 题) 的**同侧配对**不同，这是本题最容易写反的地方。

### 这三条怎么覆盖所有层？

关键在于第 2、3 条本身就是「互为镜像」的递归定义——**用同一个判定规则往下套**。对根的一对左右孩子检查完，会自动套到它们的孩子的孩子……一直递推到叶子节点（孩子为空）为止。换句话说：

- 一次 `check` 调用只看「当前两个节点值是否相等 + 递归地把它们的子树交叉对比」；
- 整棵树所有层上的对称节点对，都会在递归展开过程中被恰好访问一次。

没有任何一层会被漏掉，也没有任何一层会被重复比较。

### 两个边界（递归出口）

`check(p, q)` 在两种特殊情况下要直接返回，不能继续往下取 `->val`：

- **两个都为空** `!p && !q`：说明两边同步走到了空，这一对是对称的，返回 `true`。这是递归的「正常终点」。
- **一空一非空** `!p || !q`（在前面那条不成立时）：两边结构不一致（一边有节点、一边没有），肯定不对称，返回 `false`。

把这两个边界放在最前面，后面的 `p->val`、`p->left` 等取值才绝对安全（不会再遇到空指针）。

### 手动推导 `root = [1,2,2,3,4,4,3]`（应为对称，输出 `true`）

先画清楚树（`[1,2,2,3,4,4,3]` 是层序表示）：

```
          1
        /   \
       2     2
      / \   / \
     3   4 4   3
```

主入口 `isSymmetric(root)`：根节点 1 不空，调用 `check(2, 2)`（比较根的左、右子树）。

```
check(2, 2)：p->val==q->val (2==2) ✓
   ├─ check(p->left, q->right) = check(3, 3)
   └─ check(p->right, q->left) = check(4, 4)

   check(3, 3)：3==3 ✓
      ├─ check(3->left, 3->right) = check(nullptr, nullptr) → 都空 → true
      └─ check(3->right, 3->left) = check(nullptr, nullptr) → 都空 → true
      → 返回 true && true = true

   check(4, 4)：4==4 ✓
      ├─ check(4->left, 4->right) = check(nullptr, nullptr) → 都空 → true
      └─ check(4->right, 4->left) = check(nullptr, nullptr) → 都空 → true
      → 返回 true && true = true

   → check(2,2) 返回 (2==2) && true && true = true
```

整棵树返回 `true` ✓。

**再看一个反例** `root = [1,2,2,null,3,null,3]`（应为不对称）：

```
        1
       / \
      2   2
       \   \
        3   3
```

`check(2, 2)`：`2==2` ✓，然后递归 `check(2->left, 2->right) = check(nullptr, 3)`。此时 `!p && !q` 不成立（p 空但 q 非空），进入第二条 `!p || !q` → `true`，返回 **`false`**。整棵树 `false` ✓。

这正是「一空一非空」边界挡住了错误：两侧结构不同，递归立刻短路返回。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解字段即可：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 *   - 三个构造函数分别支持：无参（val=0,孩子皆空）、只给值、值+左右孩子
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
public:
    // check：判断「p 子树」和「q 子树」是否互为镜像。
    //   - 入参是两个节点指针，逐层往下成对比较。
    //   - 这就是题目「整棵树是否对称」转换后的小问题：「两棵子树是否镜像对称」。
    bool check(TreeNode *p, TreeNode *q) {
        // 边界 1：两个都为空。两边同步走到尽头，这一对对称，返回 true。
        //   - !p && !q：逻辑与，p、q 同时为 nullptr 才成立。
        //   - 这是递归的正常终止点（叶子节点的孩子都是空）。
        if (!p && !q) return true;

        // 边界 2：一空一非空。两边结构不一致，必然不对称，返回 false。
        //   - 能走到这里说明「两个都空」已不成立，即至少有一个非空；
        //     再判断 !p || !q，若为真就说明「一个空、一个非空」。
        //   - 这条必须放在取 ->val 之前，否则空指针取值会段错误。
        if (!p || !q) return false;

        // 走到这里 p、q 都非空，可以安全取值和取孩子了。
        // 三个条件用「短路 &&」串联：
        //   1) p->val == q->val：当前两个节点值必须相等；
        //   2) check(p->left,  q->right)：p 的左子树 与 q 的右子树 镜像对称（交叉配对！）；
        //   3) check(p->right, q->left )：p 的右子树 与 q 的左子树 镜像对称。
        // 顺序无所谓，但「左配右、右配左」不能写成「左配左、右配右」——那是「两树相同」(100 题) 而非「镜像」。
        // 短路：一旦前面为 false，后面的递归不再执行，节省时间也避免无谓的访问。
        return p->val == q->val
            && check(p->left, q->right)
            && check(p->right, q->left);
    }

    bool isSymmetric(TreeNode* root) {
        // 整棵树对称  <=>  根的左子树与右子树互为镜像。
        // 题目保证节点数 >= 1，root 一定非空，无需额外判空；
        //   即便万一 root 为空（虽不在数据范围），访问 root->left 也不会崩——
        //   但保险起见，工程代码可加 if (!root) return true;，这里按官方写法省略。
        return check(root->left, root->right);
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点最多被访问一次（每对对称节点只比较一次），整体遍历这棵树一遍。
- **空间**：O(n)。
  - 取决于递归栈深度，而递归深度等于树高 h。平衡树 h = O(log n)，但树退化成一条链（本题最坏形态，如每个节点只有一左一右往下长但极度不均）时 h = O(n)，所以最坏 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么要先把问题转换成「两棵子树是否互为镜像」，不能直接判断整棵树吗？

能直接判断的题，往往是「盯一个指针往下走」就能搞定的（比如求最大深度、判断是否平衡）。但「对称」本质是**两边对照**——必须同时看左右两个位置，一个 `root` 指针无法分身。

转换成 `check(左子树, 右子树)` 之后，问题变成了「两个指针的关系」，递归才好写：两个指针同步往**相反方向**走（p 往左时 q 往右，p 往右时 q 往左），就能覆盖所有对称位置。这是树题里非常常见的套路——**把「一棵树的性质」转成「两棵子树的关系」**（100 题「相同的树」、572 题「另一棵树的子树」、235 题「最近公共祖先」都用得到）。

### Q2：两个节点都为空时为什么返回 `true`？空不是「什么都没有」吗？

`true` 的含义不是「这两个空节点相等」，而是「**在这一对位置上，没有发现不对称**」。两边同步走到空，说明从根到这里的两条路径长度一致、沿途值也都对得上，所以这一侧的递归是「平安无事」的，应该返回 `true` 让上层继续判断别处。

反过来说，如果两个都为空时返回 `false`，那任何一棵树（哪怕完全对称）只要走到叶子节点就会被判错，整棵树永远返回 `false`，显然不对。**所以「都空 → true」是让递归能正常收尾的关键**。

### Q3：既然两个都为空返回 `true`，那「值相等」那一行还有必要单独判断吗？空节点不也是「相等」吗？

有必要，而且不能合并。「值相等」判断的是**两个非空节点**的 `val` 是否一致——走到那一行时，前面的两个边界已经保证了 `p`、`q` 都非空，可以安全取 `->val`。如果跳过这一步，就会出现「两边都有节点但值不同」却还往下递归的情况，那本该直接判 `false` 的问题被推迟甚至误判。

完整逻辑其实是**四态判断**：

| `p` 空？ | `q` 空？ | 落到哪条 | 结果 |
|---|---|---|---|
| 是 | 是 | 边界 1 | `true`（同步到空，平安） |
| 是 | 否 | 边界 2 | `false`（结构不同） |
| 否 | 是 | 边界 2 | `false`（结构不同） |
| 否 | 否 | 值相等 + 递归 | 看 `val` 和子树 |

四态缺一不可，顺序也得是「先判空、再取值」。

### Q4：根节点为空（`root == nullptr`）怎么办？

数据范围写的是节点数 `[1, 1000]`，**题目保证 root 非空**，所以官方代码直接访问 `root->left`、`root->right` 也没问题。

如果抛开范围限制严格讨论「空树是否对称」——一棵空树没有不对称的地方，按惯例应返回 `true`。工程代码里加一行 `if (!root) return true;` 更稳妥；但提交力扣时按官方写法省略即可，不影响通过。

## 复盘

### 可迁移套路

- **「树的问题转化为两子树关系」是树题的通用思考方式**。遇到「判断整棵树某性质」卡住时，先想想能不能拆成「左子树 vs 右子树」或「这棵树 vs 那棵树」的关系。本题（对称）、100 题（相同）、572 题（子树）、235 题（公共祖先）都是这一套。
- **镜像 = 交叉配对**：「左配右、右配左」是对称的标志，和「两树相同」的「左配左、右配右」是两套递归，别写串了。
- **递归先写边界再写主体**：涉及指针的递归，开头先把「都空」「一空一非空」两个边界挡掉，后面才能放心取 `->val`、`->left`，避免空指针。这是所有二叉树递归题的安全写法。
- **短路 `&&` 省时间**：多个递归条件用 `&&` 串联，前面判 `false` 后面就不执行，既正确又高效。

### 解法二：迭代法（队列 BFS 成对比较，官方方法二）

「进阶」要求会用迭代。把递归改成迭代的通用办法是**用队列代替系统调用栈**：每次从队列里**成对**取出两个节点比较，再把它们的孩子**按相反顺序**成对入队。

- 初始时把根节点入队两次（或把根的左右孩子成对入队）。
- 每轮循环弹出两个节点 `u`、`v`：
  - 都空 → 跳过（对应递归的「都空 → true」，继续看下一对）；
  - 一空一非空，或值不等 → 直接返回 `false`；
  - 否则把 `u->left` 与 `v->right`、`u->right` 与 `v->left` **成对**入队（交叉配对，和递归一致）。
- 队列空了都没发现不对称 → 返回 `true`。

```cpp
class Solution {
public:
    bool check(TreeNode *u, TreeNode *v) {
        // queue<TreeNode*>：STL 队列，元素是「指向树节点的指针」。
        //   - 只能在队尾入队、队头出队（先进先出 FIFO）。
        //   - push(x)：队尾入队；front()：看队头（不弹出）；pop()：弹出队头（无返回值）；empty()：判空。
        //   - push / pop / front 都是 O(1)。
        //   - 语义：存放「待比较的成对节点」，每次成对入队、成对出队。
        queue<TreeNode*> q;
        q.push(u); q.push(v);   // 初始一对：根的左右孩子（这里外层传 root,root，等价于先比左右）

        while (!q.empty()) {
            // 每轮弹出两个节点：注意 front() 看一眼、pop() 弹一次，分两步。
            u = q.front(); q.pop();
            v = q.front(); q.pop();

            if (!u && !v) continue;                 // 都空：这一对平安，看下一对
            if ((!u || !v) || (u->val != v->val)) return false;  // 一空一非空 或 值不等 → 不对称

            // 成对、交叉入队：u 的左 配 v 的右；u 的右 配 v 的左。
            //   - 和递归版 check(p->left,q->right) / check(p->right,q->left) 完全对应。
            q.push(u->left);
            q.push(v->right);

            q.push(u->right);
            q.push(v->left);
        }
        return true;   // 队列空了都没判错，说明整棵树对称
    }

    bool isSymmetric(TreeNode* root) {
        // 注意：这里官方传 check(root, root)，第一次循环 u==v==root，
        //   「值相等」必成立，然后把 root->left 与 root->right 成对入队，
        //   等价于从「比较左右子树」开始。和递归版殊途同归。
        return check(root, root);
    }
};
```

- **时间**：O(n)，每个节点最多入队、出队一次。
- **空间**：O(n)，队列里最多同时存 O(n) 个节点（满树时最底层约 n/2 个节点，成对即 ~n 个）。
- **对比**：和递归等价，只是把「系统调用栈」换成了「显式队列」。递归更简洁直观，迭代能避开深递归的栈溢出风险（虽然本题 n ≤ 1000 不至于）。掌握递归即可，迭代作为「进阶」的备用解法。
