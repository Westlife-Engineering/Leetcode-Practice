# 230 二叉搜索树中第 K 小的元素

- 难度：中等

- 力扣链接：https://leetcode.cn/problems/kth-smallest-element-in-a-bst/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/kth-smallest-element-in-a-bst/solutions/。)「二叉搜索树中第K小的元素」（slug：`er-cha-sou-suo-shu-zhong-di-kxiao-de-yua-8o07`）。正文主解是 **中序遍历（迭代栈）**，直接复用 [94 题「二叉树的中序遍历」](./94-二叉树的中序遍历.md) 的迭代模板，只是访问到第 k 个时立即返回，不必遍历整棵树；递归中序、记录子树节点数、平衡树等做法放在文末「复盘」。

## 题目描述

给定一个二叉搜索树的根节点 `root` ，和一个整数 `k` ，请你设计一个算法查找其中第 **k** 小的元素（k 从 1 开始计数）。

**示例 1：**

```
输入：root = [3,1,4,null,2], k = 1
输出：1
```

**示例 2：**

```
输入：root = [5,3,6,2,4,null,null,1], k = 3
输出：3
```

**提示：**

- 树中的节点数为 `n`
- `1 <= k <= n <= 10^4`
- `0 <= Node.val <= 10^4`

**进阶：** 如果二叉搜索树经常被修改（插入/删除操作）并且你需要频繁地查找第 k 小的值，你将如何优化算法？

## 思路

> 本题主要参考力扣官方题解「方法一：中序遍历」。

### 核心观察：BST 的中序遍历是升序序列

二叉搜索树（BST）的定义是：对任意节点，它的**左子树里所有值都比它小**、**右子树里所有值都比它大**，且左右子树各自也是 BST。

把这个性质和中序遍历（左 → 根 → 右）结合起来，会得到一个 BST 上**最常用**的结论：

> **对一棵 BST 做中序遍历，访问到的节点值序列是严格递增的（升序）。**

直观理解：中序「先左后根再右」，而 BST 里「左 < 根 < 右」，所以中序访问顺序恰好就是从小到大。

于是本题「找第 k 小」就等价于「**中序遍历里访问到的第 k 个节点**」。题目保证 `1 <= k <= n`，所以第 k 个一定存在。

### 为什么用迭代不用递归

递归中序（参考 94 题「复盘」里的递归写法）也能做：开一个全局计数器，每访问一个节点 `--k`，减到 0 就记下答案。但它有个硬伤——**递归没法在「找到答案」时立刻整体退出**，最坏会把整棵树都遍历完（即便答案在第 1 个就找到了）。虽说递归可以加个标志位提前剪枝，但写起来啰嗦。

**迭代栈**天然支持「找到即返回」：因为是我们自己在手动控制循环，弹出第 k 个节点那一刻直接 `return`，剩下的节点压不压栈、遍不遍历都不用管了。这就是迭代相对递归在这道题上的优势——**提前终止**。

### 手动推导 `root = [3,1,4,null,2], k = 1`

先画清这棵树（`[3,1,4,null,2]` 表示 3 的左右孩子是 1、4；1 的左孩子是 null、右孩子是 2）：

```
        3
       / \
      1   4
       \
        2
```

按 94 题那套「一路向左压栈 + 弹出访问 + 转右」的中序迭代模板走（`stk` 栈底在左、栈顶在右；访问一个节点就把它的值当作「下一个升序值」，并 `--k`）：

```
初始  root=3, k=1, stk=[]
─────────────────────────────────────────────────
外层(root=3≠空)：
  一路向左压栈：push(3), root=3->left=1        stk=[3]
                push(1), root=1->left=nullptr   stk=[3,1]   (栈顶是 1)
  到头了，弹出：root=stk.top()=1, pop           stk=[3]
  访问 1：    --k → k=0，命中！直接 return 1
─────────────────────────────────────────────────
（后面的节点 2、3、4 根本不会访问到——这就是迭代提前终止的威力）

最终返回 1  ✓（中序序列本应是 [1,2,3,4]，第 1 个就是 1）
```

对比一下完整中序 `[1,2,3,4]`：第 `k=1` 个是 `1`，第 `k=3` 个就是 `3`。只要计数器减到 0 的那一刻，当前被弹出的那个节点就是答案。

### 关于「进阶」的优化思路（先有个印象）

题目问：如果 BST 经常插入/删除、还要频繁查第 k 小，怎么优化？

朴素中序每次查询都要 O(H+k)，频繁查询就贵了。官方给了两个方向（复盘里会贴代码）：

- **方法二：给每个节点额外记「以它为根的子树的节点数」**（用哈希表存）。查询时从根往下走：若左子树节点数 `left >= k`，答案在左子树；若 `left == k-1`，答案就是当前节点；否则去右子树找第 `k-left-1` 小。查询 O(H)，但插入/删除要同步维护节点数。
- **方法三：用平衡二叉搜索树（AVL）**，每个节点存 `size`，插入/删除自动保持平衡。查询和修改都是 O(log n)。

正文只讲主解（方法一），这两个进阶做法放在「复盘」了解即可。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
public:
    int kthSmallest(TreeNode* root, int k) {
        // stack<TreeNode*>：STL 栈，元素是「指向树节点的指针」。
        //   - 只能在栈顶操作：push 压入、pop 弹出（无返回值）、top 看栈顶、empty 判空、size 看元素个数。
        //   - push / pop / top / size 都是 O(1)。
        //   - 语义：保存「一路向左时路过、但还没到访问时机」的节点，栈顶 = 当前最该先访问的节点。
        //   - 注意存的是指针不是对象本身，避免拷贝整棵树。
        stack<TreeNode*> stk;

        // 外层循环条件两个都不能少（和 94 题中序迭代一模一样）：
        //   - root != nullptr：说明还有一条「向左」的路要走，或某节点刚被访问、要去看它的右子树。
        //     （这里复用了参数 root 当作「当前指针」用，省一个变量；官方写法就是这样。）
        //   - !stk.empty()：说明虽然 root 暂时走到空了，但栈里还压着没访问的祖先节点，得回去处理它们。
        //   用「或」连接：只要还有「没访问到的节点」就继续。
        while (root != nullptr || !stk.empty()) {
            // 内层循环：从 root 一路向左，边走边压栈。
            //   - 为什么？中序要求「左在根前」，root 这条左链上越靠左的越该先访问，
            //     压进栈后，栈顶自然是最左的那个，稍后第一个被弹出访问。
            //   - 顺序：先 push(root) 再 root = root->left，保证 root 自己也被存住。
            while (root != nullptr) {
                stk.push(root);
                root = root->left;
            }

            // 走到这里说明 root 已经是 nullptr（左到头了），该轮到栈顶节点。
            //   - top() 看栈顶但不弹出；pop() 弹出但不返回值，所以要先用 top 取值再 pop。
            //   - 两句顺序不能反：pop 之后栈顶就变了。
            root = stk.top();
            stk.pop();

            // 此时 root 的左子树要么为空、要么已经全部访问完毕，按「左→根→右」，
            // 现在正是访问「根」root 的时机——它就是升序序列里的下一个值。
            //   - 每访问一个就把 k 减 1；题目保证 1<=k<=n，所以减到 0 时这个 root 就是第 k 小。
            --k;
            if (k == 0) {
                return root->val;   // 命中即返回，剩下的节点不再遍历——这就是迭代能提前终止的关键
            }

            // 还没到第 k 个，去访问 root 的右子树：把 root 指向右孩子，回到外层循环开头。
            //   - 若右孩子非空：外层进内层，一路向左压栈，对右子树重复同样流程。
            //   - 若右孩子为空：内层不进，外层靠 !stk.empty() 继续弹出上一个积压的祖先。
            root = root->right;
        }

        // 理论上不会走到这里（题目保证 1<=k<=n，循环内一定会 return）。
        // 加这行只是为了让编译器不报警告「控制可能到达非 void 函数末尾」。
        return -1;
    }
};
```

## 复杂度

- **时间**：O(H + k)，其中 H 为树高、k 为题目给定的名次。
  - 找到答案前，先要从根一路向左压到底（O(H) 次压栈），再弹出访问 k 个节点（O(k)）。找到第 k 个立即返回，后面的节点不碰。
  - 平均情况（平衡 BST）H = O(log n)，所以平均 O(log n + k)；最坏（树退化成一条链且要找的元素在最右下）H = O(n)，所以最坏 O(n)。
- **空间**：O(H)。
  - 取决于栈深度，而栈深度等于树高 H。平衡树 H = O(log n)，退化成链 H = O(n)，所以最坏 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么 BST 的中序遍历一定是升序？

这是 BST 题里**最核心、最该背下来**的性质。严格证明用归纳法：对任意一棵子树，设它的根是 `r`。中序是「先左子树，再 `r`，再右子树」：

- 左子树里的所有值都 `< r`（BST 定义）；
- 右子树里的所有值都 `> r`（BST 定义）；
- 左、右子树各自也是 BST，所以它们自己中序遍历也是升序（归纳假设）。

把「升序的左子树序列 + [r] + 升序的右子树序列」拼起来，由于「左子树最大值 < r < 右子树最小值」，整体仍是升序。**记住一句话：BST + 中序 = 升序序列**，这是 98 题「验证 BST」、230 题「第 K 小」、108 题「有序数组转 BST」等一系列题的共同钥匙。

### Q2：为什么迭代能「提前终止」，递归不行？

迭代里是我们**自己写循环**，循环体里 `if (k == 0) return root->val;` 这一句一旦命中，函数直接结束，后面无论还有多少节点压在栈里、还有多少右子树没访问，统统不管。

递归则不同：递归调用是系统在帮你压栈，一旦进入 `inorder(root->left)` 这种调用，必须等它整个返回后才能继续，**没法在递归深处直接跳过外层的剩余调用**。虽然可以加个全局 `found` 标志位让外层递归「检测到已找到就不再下钻」，但那相当于手动模拟提前终止，写起来比迭代绕。所以**凡是「遍历到某个条件就停」的 BST 题，迭代栈往往比递归更顺手**。

### Q3：`k` 是从 1 开始还是从 0 开始？

**从 1 开始**。题目原文「k 从 1 开始计数」，所以第 1 个被中序访问到的就是第 1 小（最小值）。代码里用 `--k`（先减再判断）配合 `if (k == 0)`：访问第 1 个节点时 `k` 从 1 减到 0，命中返回，正好是第 1 小。**别和数组下标从 0 开始搞混**——这里 k 是「名次」不是「下标」。

如果把 `--k` 写成 `k--`（先判断后减），逻辑就错了：访问第 1 个节点时 `k` 还是 1，`if (k==0)` 不成立，会少算一个。所以 `--k` 这个「前置自减」的位置很关键。

### Q4：`return -1` 这行兜底是不是多余的？

**逻辑上是多余的**（题目保证 `1 <= k <= n`，循环内一定会 `return`），但**不加编译器会报警告**「control may reach end of non-void function」（非 void 函数可能执行到末尾没返回值）。编译器看不到 `1<=k<=n` 这个数学约束，它只看代码结构，觉得 `while` 循环可能一次都不进（比如 `root==nullptr && stk.empty()`）、那就没 `return` 了。

所以加一个 `return -1`（或 `return 0`）纯属**安抚编译器**，正常用例永远不会走到。力扣上很多人写 `return root->val;` 放在循环外（配合循环内用 `break` 而不是 `return`），效果一样，只是把「命中」和「返回」拆成了两步。本笔记采用循环内直接 `return` 的写法，更贴近「找到即终止」的语义。

## 复盘

### 可迁移套路

- **「BST + 中序 = 升序序列」是 BST 题的通用性质**。凡是涉及「第 k 小 / 第 k 大 / 验证 BST / 中序有序」的 BST 题，第一反应就是把中序遍历搬出来。第 k 大只要把中序反过来（右 → 根 → 左）即可。这个套路和 94 题的中序迭代模板是配套的，建议两题一起复习。
- **「迭代栈模拟递归」是二叉树遍历的通用基本功**（详见 94 题）。本题只是把 94 题的「收集所有值」改成「访问到第 k 个就停」，框架完全一致：`while (curr || !stk.empty())` + 内层向左压栈 + 弹出访问 + 转右。会 94 题就会这题。
- **「遍历到某条件就停」优先选迭代**。递归擅长「整棵树都要走一遍」的场景；一旦要提前终止，迭代栈的 `return` 比 递归的标志位干净。

### 解法二：递归中序（对照主解，理解题意用）

和 94 题递归写法同源，加一个成员变量 `k` 边遍历边减。也能过，但不能提前终止（除非加 `found` 标志位）。

```cpp
class Solution {
public:
    int kthSmallest(TreeNode* root, int k) {
        // 用成员变量携带状态：k 剩多少个没访问、res 答案
        this->k = k;
        this->res = -1;
        inorder(root);
        return res;
    }
private:
    int k;
    int res;
    void inorder(TreeNode* root) {
        if (!root) return;
        inorder(root->left);
        if (k == 0) return;          // 已找到，剪枝（不加也行，只是会多遍历）
        --k;
        if (k == 0) { res = root->val; return; }
        inorder(root->right);
    }
};
```

- **时间 / 空间**：和迭代一样 O(H+k) / O(H)（加了剪枝才等同；不剪枝最坏 O(n)）。
- **对比**：递归版要靠成员变量传状态、靠 `if (k==0) return` 模拟提前终止，写起来不如迭代的 `return root->val` 干净。理解题意时可以用它，提交建议用迭代。

### 解法三：记录子树的节点数（官方方法二，对应「进阶」）

思路：预处理一遍，给每个节点算出「以它为根的子树共有多少个节点」（存进 `unordered_map`）。查询时从根往下走，靠左子树节点数 `left` 判断答案在哪一边：

- `left > k-1`：答案在左子树，进左子树继续找第 k 小；
- `left == k-1`：答案就是当前节点；
- `left < k-1`：答案在右子树，进右子树找第 `k-left-1` 小。

这样单次查询 O(H)，但插入/删除时要同步维护节点数。代码见官方题解「方法二」，此处不贴（避免正文并列多份代码）。**适用场景**：BST 修改不频繁、但查询很多。

### 解法四：平衡二叉搜索树（官方方法三，对应「进阶」极致优化）

把 BST 升级成 AVL（自平衡 BST），每个节点额外存 `size`（子树节点数）。插入/删除时自动旋转保持平衡，查询走「解法三」同样的逻辑。查询和修改都是 O(log n)，是「频繁插入删除 + 频繁查询」下的最优解。代码很长（官方题解方法三近百行），了解思想即可，面试一般不要求手写 AVL。
