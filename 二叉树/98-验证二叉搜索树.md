# 98 验证二叉搜索树

- 难度：中等
- 标签：树、**深度优先搜索**、**二叉搜索树**、**二叉树**
- 力扣链接：https://leetcode.cn/problems/validate-binary-search-tree/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/validate-binary-search-tree/solutions/525808/yan-zheng-er-cha-sou-suo-shu-by-leetcode-solution/)「验证二叉搜索树」（slug：`yan-zheng-er-cha-sou-suo-shu-by-leetcode-solution`）。正文主解是 **递归（带上下界 min/max）**：对每个节点检查它的值是否落在开区间 `(lower, upper)` 内，递归到左子树时把当前值设为新的上界、到右子树时把当前值设为新的下界；中序遍历法（BST 中序是严格升序）放在文末「复盘」作对比（和 [94 题](./94-二叉树的中序遍历.md) 相关）。

## 题目描述

给你一个二叉树的根节点 `root` ，判断其是否是一个有效的二叉搜索树。

**有效 二叉搜索树**定义如下：

- 节点的左子树只包含 **严格小于** 当前节点的数。
- 节点的右子树只包含 **严格大于** 当前节点的数。
- 所有左子树和右子树自身必须也是二叉搜索树。

**示例 1：**

```

输入：root = [2,1,3]
输出：true

```

**示例 2：**

```

输入：root = [5,1,4,null,null,3,6]
输出：false
解释：根节点的值是 5 ，但是右子节点的值是 4 。

```

**提示：**

- 树中节点数目范围在 `[1, 10^4]` 内
- `-2^31 <= Node.val <= 2^31 - 1`

## 思路

> 本题主要参考力扣官方题解「方法一：递归」。

### 先吃透 BST 的定义（本题最大的坑就在这）

题面对「有效二叉搜索树」给了三条，关键在于**前两条的主语是「整棵子树」、不是「直接孩子」**：

- 节点的**左子树**（整棵）只包含严格小于当前节点的数。
- 节点的**右子树**（整棵）只包含严格大于当前节点的数。

也就是说，**根的值必须大于左子树里「所有」节点的值、小于右子树里「所有」节点的值**，不只是和直接左/右孩子比。这一点稍不留神就会写成错误代码。

### 最常见的错误写法：只和直接孩子比

很多人第一反应是这样写（**这是错的**）：

```cpp
// ❌ 错误写法：只比较了节点和它的直接左右孩子
bool isValidBST(TreeNode* root) {
    if (!root) return true;
    if (root->left && root->left->val >= root->val) return false;
    if (root->right && root->right->val <= root->val) return false;
    return isValidBST(root->left) && isValidBST(root->right);
}
```

它看似合理，却放过了一类反例。看题目示例 2 的树 `root = [5,1,4,null,null,3,6]`：

```
        5
       / \
      1   4
         / \
        3   6
```

- 节点 5：左孩子 1 < 5 ✓，右孩子 4 < 5 ✗ —— 这里就被「根和右孩子比」抓出来了。
- 但**把右孩子改成 6**（即 `[5,1,6,null,null,3,7]` 这种结构），根 5 和右孩子 6 比没问题；可节点 3 藏在 5 的右子树里，**3 < 5 违反了「右子树所有节点都要大于根」**。上面那段错误代码在每个局部都通过（节点 6 的左孩子 3 < 6），却判不出全局违规。

**根本原因**：只往下看一层，丢了「祖先节点留下的约束」。节点 3 固然要比它的父节点 6 小，但因为它位于根 5 的右子树里，它还得比 5 大才行——这个 5 的约束，错误写法完全没传下去。

### 正解：递归时把「祖先的约束」作为上下界带下去

既然每个节点除了受父节点约束，还要受更上面所有祖先约束，那就**给递归函数加两个参数 `lower` 和 `upper`**，表示「当前节点必须严格落在开区间 `(lower, upper)` 内」。这两个界是**一路从祖先累积下来的**：

- 从根开始，根可以是任意值，所以初始 `lower = -∞`、`upper = +∞`。
- 进入某个节点，先检查 `lower < node->val < upper` 是否成立，不成立直接返回 `false`。
- **往左子树走**：左子树里所有节点都要**小于**当前节点，所以把**当前值设为新的上界**，下界不变 → `helper(左, lower, node->val)`。
- **往右子树走**：右子树里所有节点都要**大于**当前节点，所以把**当前值设为新的下界**，上界不变 → `helper(右, node->val, upper)`。

这样祖先的约束就被「夹」进了区间，越往下钻区间越窄，任何违规的节点都逃不掉。再回头看那个反例（右子树里藏了比根小的 3）：递归到节点 3 时，因为它是从根 5 往右走的，下界 `lower` 已经被更新成 5，检查 `5 < 3` 不成立，立即返回 `false`。

### 为什么是「开区间」`(lower, upper)` 不是闭区间？

题面写的是「**严格**小于 / 严格大于」，意味着**相等的值也算违规**（BST 不允许重复值）。所以判断条件必须用 `<=` / `>=`：

```cpp
if (root->val <= lower || root->val >= upper) return false;
```

对应数学上就是开区间 `(lower, upper)`。如果某天遇到「允许重复值的 BST」（左 ≤ 根 < 右那种变体），才需要改成半开半闭，本题不是。

### 为什么边界用 `LONG_MIN / LONG_MAX` 而不是 `INT_MIN / INT_MAX`？

题面数据范围是 `-2^31 <= Node.val <= 2^31 - 1`，正好是 `int` 的最小/最大值。如果用 `INT_MIN` 当初始下界，那么**根节点值恰好等于 `INT_MIN` 时**（比如 `[INT_MIN]` 单节点），`root->val <= lower` 即 `INT_MIN <= INT_MIN` 成立，会被误判成违规——可一个单独的最小值节点明明是合法 BST。所以下界要**比 `INT_MIN` 还小**才行，最省事的做法是把参数类型升到 `long long`，用 `LONG_MIN / LONG_MAX`（`long long` 的最小/最大值，量级约 ±9.2×10^18，远超 `int` 范围），从此节点值再极端也不会和边界撞车。

### 手动推导 `root = [5,1,4,null,null,3,6]`（结果应为 false）

```
        5
       / \
      1   4
         / \
        3   6
```

从根 5 开始，初始区间 `(-∞, +∞)`（用 `LONG_MIN, LONG_MAX` 表示）：

```
helper(5, -∞, +∞)
  5 在 (-∞, +∞) 内 ✓
  ├─ helper(1, -∞, 5)        // 往左：上界收紧为 5
  │    1 在 (-∞, 5) 内 ✓
  │    ├─ helper(null, -∞, 1) → true   // 1 的左空子树
  │    └─ helper(null, 1, +∞) → true   // 1 的右空子树
  │    return true
  └─ helper(4, 5, +∞)        // 往右：下界收紧为 5
       4 在 (5, +∞) 内？ 5 < 4 不成立 ✗
       return false          // ← 在这里就抓出来了
  return false  ✓
```

实际上根 5 的右孩子 4 本身就违规（4 < 5 却长在右子树），递归到 `helper(4, 5, +∞)` 时立即暴露。即使把这一层伪装成合法（比如右孩子改成 6 再挂个 3），约束也会顺着区间继续下传，迟早把违规节点揪出来。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解一下字段即可：
 *   - val：节点存的值（int 类型，范围可达 INT_MIN/INT_MAX）
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 *   - 三个构造函数分别支持：无参（val=0,孩子皆空）、只给值、值+左右孩子
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
public:
    // helper：判断以 root 为根的子树是否是合法 BST。
    //   - 参数 long long lower / upper：root 子树里「所有」节点的值必须严格落在 (lower, upper) 开区间内。
    //     这两个界是「从祖先一路累积下来的约束」：往左走时上界换成当前值、往右走时下界换成当前值。
    //   - 为什么用 long long 不用 int？题面数据范围是 [-2^31, 2^31-1]，正好等于 INT_MIN/INT_MAX。
    //     若用 INT_MIN 当初始下界，根节点值恰好等于 INT_MIN 时会被误判（INT_MIN <= INT_MIN 成立）。
    //     换成 long long + LONG_MIN/LONG_MAX，边界比任何 int 都宽，节点值再极端也撞不到边界。
    //   - 返回 bool：该子树是否合法。
    bool helper(TreeNode* root, long long lower, long long upper) {
        // 递归终止条件 1：空子树视为合法 BST（题面「空树」也算合法，虽然本题 n>=1，但递归会走到空节点）。
        if (root == nullptr) {
            return true;
        }

        // 核心检查：当前节点值必须严格落在 (lower, upper) 开区间内。
        //   - 用 <= 和 >= 而不是 < 和 >：题面要求「严格」小于/大于，相等的值也算违规（BST 不允许重复值）。
        //   - 一旦违规立即返回 false，不必再往下看（短路）。
        if (root->val <= lower || root->val >= upper) {
            return false;
        }

        // 两个递归调用，用 && 短路连接：左子树不合法就不必再看右子树。
        //   - 往左走 helper(left, lower, root->val)：
        //       左子树里所有节点都要 < 当前 root->val，所以把「上界」收紧为 root->val，下界 lower 不变。
        //   - 往右走 helper(right, root->val, upper)：
        //       右子树里所有节点都要 > 当前 root->val，所以把「下界」收紧为 root->val，上界 upper 不变。
        //   - 注意 root->val 是 int，传入 long long 参数会发生隐式类型提升（int → long long），安全无损。
        return helper(root->left, lower, root->val)
            && helper(root->right, root->val, upper);
    }

    bool isValidBST(TreeNode* root) {
        // 初始区间设为「整个 long long 范围」，相当于对根节点不加任何约束。
        //   - LONG_MIN / LONG_MAX：<climits> 头文件里的宏，long long 的最小/最大值（约 ±9.2×10^18）。
        //   - 力扣 C++ 模板已包含常用头文件，<climits> 可直接用，无需额外 #include。
        return helper(root, LONG_MIN, LONG_MAX);
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为二叉树节点个数。
  - 每个节点在递归中只被访问一次（进入 `helper` 一次，检查完区间就返回），所以整体是 O(n)。
- **空间**：O(height)，其中 height 为二叉树的高度。
  - 空间消耗来自**递归调用栈**，栈深度等于递归深度，也就是树的高度 height。
  - **最好情况**：树平衡时 height = O(log n)，空间 O(log n)。
  - **最坏情况**：树退化成一条链（每个节点只有一个孩子），height = O(n)，空间也变成 O(n)，极端时可能栈溢出。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么「只和直接孩子比」是错的？能给个具体反例吗？

题面定义是「左**子树**所有节点 < 根 < 右**子树**所有节点」，主语是**整棵子树**，不是直接孩子。错误写法 `root->left->val < root->val` 只看了往下**一层**，丢掉了祖先节点留下的约束。

构造一个能骗过错误写法的反例：

```
        5
       / \
      1   6
         / \
        3   7
```

每个局部都合法：5 的左孩子 1 < 5、右孩子 6 > 5；6 的左孩子 3 < 6、右孩子 7 > 6。错误写法会判它 `true`。但实际上节点 3 长在根 5 的**右子树**里，按定义它必须 > 5，而 3 < 5，所以**整棵树不是 BST**，正确答案是 `false`。

正解之所以能抓到，是因为递归到节点 3 时，下界已经从根 5 那里累积成了 5（`helper(6, 5, +∞)` → `helper(3, 5, 6)`），检查 `5 < 3` 不成立，立即返回 false。**区间把祖先的约束一路带下去了**，这就是带上下界递归的威力。

### Q2：为什么参数用 `long long`，不能用 `int` 配 `INT_MIN/INT_MAX`？

因为题面数据范围 `-2^31 <= Node.val <= 2^31 - 1` 正好覆盖了 `int` 的全部取值。如果用 `INT_MIN` 当初始下界，那么**根节点值恰好等于 `INT_MIN` 时**（比如输入就是 `[INT_MIN]` 这一个节点），判断条件 `root->val <= lower` 即 `INT_MIN <= INT_MIN` 为真，会被误判成违规——可一个单独的最小值节点明明是合法 BST。

把参数类型升到 `long long`、边界用 `LONG_MIN / LONG_MAX`（约 ±9.2×10^18），边界永远比任何 `int` 节点值都「更极端」，就再也不会撞车。代码里 `root->val`（int）和 `lower/upper`（long long）比较时，`root->val` 会隐式提升为 `long long`，安全无损。

> **进阶写法（不用 long long）**：如果坚持只用 `int`，可以把 `helper` 的边界改成「可选」语义——用指针 `TreeNode*` 表示「当前没有边界约束」，遇到 `nullptr` 表示那边不限制。官方题解的 C++ 版本选了更直观的 `long long` 方案，这里照抄。

### Q3：判断条件为什么用开区间（`<` / `>` 配 `<=` / `>=`）？闭区间行不行？

题面三次强调「**严格**小于」「**严格**大于」，意味着**相等的值也算违规**（经典 BST 不允许重复值）。所以条件必须写成 `root->val <= lower || root->val >= upper`，对应数学上的**开区间** `(lower, upper)`。如果写成 `root->val < lower || root->val > upper`（闭区间），就会放过「节点值等于边界」的情况，比如根的左子树里冒出一个和根相等的值，本该违规却被判合法。

> 如果某道题明确允许重复值（比如「左 ≤ 根 < 右」这种变体 BST），才需要把某一侧改成 `<=`，本题不是。

### Q4：数据范围说 `n >= 1`（至少 1 个节点），为什么代码里还要判 `root == nullptr`？

虽然题目保证整棵树至少有一个节点，但**递归过程中会走到空节点**（叶子节点的左右孩子都是 `nullptr`）。`helper` 的第一条 `if (root == nullptr) return true;` 处理的就是这些递归到底的空子树：空子树视为合法 BST，把递归「封底」。没有这一条，递归会一直往 `nullptr->left` 钻下去导致段错误。

至于 `[INT_MIN]` 这种单节点输入（根值等于 int 最小值）：`helper(INT_MIN 节点, LONG_MIN, LONG_MAX)` 检查 `LONG_MIN < INT_MIN < LONG_MAX`，显然成立，左右子树都是空返回 true，整体 `true`，正确（见 Q2，这正是因为边界用了 `long long`）。

## 复盘

### 可迁移套路

- **「BST 的核心性质：中序遍历得到严格递增序列」**。这是所有 BST 题的万能抓手。凡是要「验证 BST」「找第 K 小」「BST 转有序链表」的题，第一反应都该是「中序遍历」。本题的「复盘解法二」就是直接套这个性质。
- **「递归 + 上下界」是 BST 验证的标准解**。比中序遍历更直接地对应 BST 定义，不需要额外存序列。套路是：给递归函数加 `(lower, upper)` 两个参数表示「祖先累积的约束」，往左走收紧上界、往右走收紧下界。这种「把祖先信息作为参数往下传」的思路，在「最近公共祖先」「路径和」等树题里也反复出现。
- **遇到「所有节点都满足某性质」要警惕只看局部**。本题最大的坑就是「只和孩子比」忽略了祖先约束。类似地，「平衡二叉树」要算高度差、「二叉树的直径」要绕过根——都是要把子树信息往上汇总、不能只看一层。

### 解法二：中序遍历法（官方方法二，和 94 题一脉相承）

利用 BST 的核心性质：**对合法 BST 做中序遍历，得到的值序列一定严格递增**。所以只要中序遍历一遍，边遍历边检查「当前节点值是否严格大于前一个被访问的节点值」即可。有一处不满足就返回 false。

这里用 [94 题](./94-二叉树的中序遍历.md) 的「迭代法（显式栈）」模板来做中序遍历，顺手把「前一个值 `inorder`」记下来比较：

```cpp
class Solution {
public:
    bool isValidBST(TreeNode* root) {
        // stack<TreeNode*>：STL 栈，元素是「指向树节点的指针」。
        //   - 只能在栈顶操作：push 压入、pop 弹出（无返回值）、top 看栈顶、empty 判空，均 O(1)。
        //   - 语义：中序迭代里保存「一路向左时路过、但还没到访问时机」的节点。
        stack<TreeNode*> stk;
        // inorder：记录「中序遍历中上一个被访问节点的值」，用于和当前节点比大小。
        //   - 用 long long 并初始化为 (long long)INT_MIN - 1：比任何 int 都小，
        //     这样遍历到的第一个节点（最左叶子）即使值是 INT_MIN，比较 root->val > inorder 也能成立。
        //   - 思路同主解的 LONG_MIN：避免 INT_MIN 节点和初始值撞车。
        long long inorder = (long long)INT_MIN - 1;

        // 外层循环条件两个都不能少（和 94 题一模一样）：
        //   - root != nullptr：还有向左的路要走 / 要看某节点的右子树。
        //   - !stk.empty()：root 暂时走到空了，但栈里还压着没访问的祖先。
        while (!stk.empty() || root != nullptr) {
            // 内层：从 root 一路向左，边走边压栈。
            while (root != nullptr) {
                stk.push(root);
                root = root->left;
            }
            // 到头了，弹出栈顶 = 当前中序该访问的节点。
            root = stk.top();
            stk.pop();
            // 关键检查：当前节点值必须「严格大于」前一个访问的节点值。
            //   - 用 <= 而不是 <：BST 不允许重复值，相等也算违规。
            //   - 不满足直接返回 false，无需继续遍历。
            if (root->val <= inorder) {
                return false;
            }
            // 更新「前一个值」为当前值，然后转向右子树（中序的「右」环节）。
            inorder = root->val;
            root = root->right;
        }
        return true;  // 整趟中序都严格递增，是合法 BST
    }
};
```

- **时间**：O(n)，每个节点入栈、出栈、访问各一次。
- **空间**：O(height)，栈深度等于树高，最坏退化成链是 O(n)。
- **对比递归法**：两者时间空间复杂度完全一样（都是 O(n) / O(height)）。递归法更直接对应 BST 定义、不需要额外理解「中序升序」的性质；中序法把 BST 验证「转译」成「检查序列是否递增」，思路更巧妙，而且复用了 94 题的中序迭代模板——**会一道就能会一片**。面试时两种都能讲，递归法作为主解（代码更短）、中序法作为「我还会另一种思路」的加分项。
