> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/convert-sorted-array-to-binary-search-tree/solution/jiang-you-xu-shu-zu-zhuan-huan-wei-er-cha-sou-s-33/)「将有序数组转换为二叉搜索树」（slug：`jiang-you-xu-shu-zu-zhuan-huan-wei-er-cha-sou-s-33`）。正文主解是 **分治（中序遍历还原）——总是取中间位置左边的数字作根**：取数组中点作为根，再对左右两半递归建子树，天然保证高度平衡；「方法二（取右中点）」「方法三（随机选左/右中点）」见文末「复盘」。

## 题目描述

给你一个整数数组 `nums` ，其中元素已经按 **升序** 排列，请你将其转换为一棵 **高度平衡** 二叉搜索树。

**示例 1：**

```
输入：nums = [-10,-3,0,5,9]
输出：[0,-3,9,-10,null,5]
解释：[0,-10,5,null,-3,null,9] 也将被视为正确答案：
```

**示例 2：**

```
输入：nums = [1,3]
输出：[3,1]
解释：[1,null,3] 和 [3,1] 都是高度平衡二叉搜索树。
```

**提示：**

- `1 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- `nums` 按 **严格递增** 顺序排列

**关于「高度平衡」的定义：** 一棵二叉树中，**任意一个节点** 的左右两棵子树的高度差的绝对值不超过 1。（不只是整棵树的根要平衡，每个内部节点都要平衡。）

## 思路

> 本题主要参考力扣官方题解「方法一：中序遍历，总是选择中间位置左边的数字作为根节点」。

### 关键观察：有序数组就是某棵 BST 的中序遍历

二叉搜索树（BST）有一个重要性质：**对它做中序遍历（左→根→右），得到的序列是严格升序的**。反过来，题目给的 `nums` 已经严格递增，所以它**一定是某棵 BST 的中序遍历序列**。

但光有一条中序序列，**不能唯一确定** 一棵 BST——同一个升序序列能造出很多棵 BST（比如全部挂在右链上、全部挂在左链上，等等）。题目额外加了一条限制：**高度平衡**。

### 要平衡，根就得取「中间」元素

「高度平衡」要求任意节点的左右子树高度差 ≤ 1。让左右子树**节点个数尽量相等**，是让它们高度最接近的最直接办法。所以：

- **取数组中间元素作为根**，这样分给左右子树的元素个数要么相等、要么只差 1，左右子树天生就「势均力敌」。
- 根左半段 `[left, mid-1]` → 递归建左子树；根右半段 `[mid+1, right]` → 递归建右子树。
- 因为左右子树本身也是用同样的「取中点」规则递归构造的，所以它们**也是平衡 BST**——「平衡」的性质在每一层都成立。

这就是「**分治 + 取中点**」的建树模板。

### 为什么取中点就一定平衡？（直觉证明）

在当前区间 `[left, right]` 长度为 `n` 时：

- 若 `n` 是奇数，取中点后左右两半各 `(n-1)/2` 个，**完全对称**，最平衡。
- 若 `n` 是偶数，取左中点（或右中点）后左右两半分别是 `n/2 - 1` 和 `n/2` 个（取左中点时），**差 1**，仍然满足「高度差 ≤ 1」。

把这种「每层都尽量平分」的策略一层层传下去，整棵树每个节点的左右子树都满足高度差 ≤ 1，所以整棵树高度平衡。形式化证明可参考 1382 题「将二叉搜索树变平衡」的官方题解，构造方法与本题完全相同。

### 手动推导 `nums = [-10,-3,0,5,9]`（期望输出 `[0,-3,9,-10,null,5]`）

数组下标：`0:-10  1:-3  2:0  3:5  4:9`，全程用 `mid = (left + right) / 2`（整数除法，向下取整，即取左中点）。

```
helper(nums, 0, 4)：
  mid = (0+4)/2 = 2  → 根 = nums[2] = 0
  左 = helper(0,1)，右 = helper(3,4)

  helper(nums, 0, 1)：
    mid = (0+1)/2 = 0  → 根 = nums[0] = -10
    左 = helper(0,-1) → 空 (left>right，返回 nullptr)
    右 = helper(1,1)
      mid = (1+1)/2 = 1  → 根 = nums[1] = -3
      左/右都空 → 叶子
    所以节点 -10 的左孩子=null，右孩子=-3

  helper(nums, 3, 4)：
    mid = (3+4)/2 = 3  → 根 = nums[3] = 5
    左 = helper(3,2) → 空
    右 = helper(4,4)
      mid = (4+4)/2 = 4  → 根 = nums[4] = 9
      左/右都空 → 叶子
    所以节点 5 的左孩子=null，右孩子=9
```

最终建出的树：

```
        0
       / \
    -10   5
       \    \
       -3    9
```

层序输出就是 `[0,-10,5,null,-3,null,9]`——而题面说 `[0,-10,5,null,-3,null,9]` 与 `[0,-3,9,-10,null,5]` 都视为正确（两者都高度平衡），所以这棵树正确。

> 注意：示例输出 `[0,-3,9,-10,null,5]` 对应的是另一种合法构造（取了不同的中点），两种都对。力扣只要返回任意一棵高度平衡 BST 即可。

## 代码

```cpp
/**
 * Definition for a binary tree node.
 * 力扣预置的节点结构，提交时无需自己写，了解一下字段即可：
 *   - val：节点存的值
 *   - left / right：指向左右孩子的指针，没有对应孩子时为 nullptr
 */
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
};

class Solution {
private:
    // helper：把 nums 的闭区间 [left, right] 这一段构造成一棵「高度平衡 BST」并返回根。
    //   - vector<int>& nums：传引用，只读不拷贝（拷贝整个数组是 O(n)，递归里反复拷会爆时间和空间）。
    //   - int left / int right：闭区间下标。注意是「闭」区间，所以 left > right 表示区间为空。
    //   - 返回值 TreeNode*：构造出的子树根节点指针；空区间返回 nullptr。
    TreeNode* helper(vector<int>& nums, int left, int right) {
        // 递归终止条件：区间为空，没有元素可放，返回空指针。
        //   - 这是整个递归的「出口」，保证递归一定能停下来。
        if (left > right) {
            return nullptr;
        }

        // 取中间位置左边的数字作为根（即「左中点」）。
        //   - (left + right) / 2 是整数除法，自动向下取整，偶数长度时取靠左的那个中间元素。
        //   - 选左中点还是右中点都行（都平衡），官方方法一选左中点。
        //   - 为什么不用 (left + right + 1) / 2？那是「右中点」，对应官方方法二，也能 AC，只是建出的树形状不同。
        //   - 注意：left + right 在本题数据范围（<=10^4）下不会溢出 int；若区间非常大可用 left + (right-left)/2 防溢出。
        int mid = (left + right) / 2;

        // new TreeNode(nums[mid])：在堆上分配一个新节点，值初始化为 nums[mid]，左右孩子为 nullptr。
        //   - 力扣环境会接管这些节点的内存，提交代码一般不用手动 delete。
        //   - 注意是「new」出来的指针，不是栈上对象——递归返回后这个节点还活着，能被父节点挂上去。
        TreeNode* root = new TreeNode(nums[mid]);

        // 递归构造左子树：根左边的连续一段 [left, mid-1]。
        //   - 因为 nums 升序，左边那段都 < nums[mid]，挂在左孩子上正好满足 BST「左 < 根」的性质。
        //   - 同样用「取中点」规则，所以左子树本身也是平衡 BST。
        root->left = helper(nums, left, mid - 1);

        // 递归构造右子树：根右边的连续一段 [mid+1, right]。
        //   - 右边那段都 > nums[mid]，挂在右孩子上满足 BST「根 < 右」。
        root->right = helper(nums, mid + 1, right);

        return root;
    }

public:
    TreeNode* sortedArrayToBST(vector<int>& nums) {
        // vector<int>& nums：力扣传入的升序整数数组的引用，避免拷贝。
        //   - nums.size() 返回 size_t（无符号类型），减 1 后强转成 int 作为右端点下标。
        //   - 题目保证 nums 非空（length >= 1），所以 nums.size() - 1 >= 0，不会下溢。
        //   - 整个问题 = 把闭区间 [0, n-1] 构造成平衡 BST，直接交给 helper。
        return helper(nums, 0, static_cast<int>(nums.size()) - 1);
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 是数组长度。
  - 每个元素恰好被访问一次（在某次递归里被选为某棵子树的根 `nums[mid]`），递归总工作量 O(n)。
- **空间**：O(log n)。
  - 题目「空间复杂度不考虑返回值」（建出的那棵树不算额外空间），所以只看**递归调用栈**的深度。
  - 因为每层都把区间近乎对半分，递归深度等于树高 = O(log n)，比退化成链的 O(n) 好得多——这正是「平衡」带来的好处。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么取中间元素就能保证「高度平衡」？光看根节点左右子树节点数差 ≤ 1 不够吧？

关键在于**「平衡」是递归地保证的**，不是只看根那一层。取中点做了两件事：

1. 在**当前**这一层，让左右子树的节点数相等或差 1，根节点的左右子树天然「势均力敌」。
2. 左右子树本身也是**用同样的「取中点」规则**递归构造的，所以它们内部每个节点的左右子树也满足高度差 ≤ 1。

把这两条叠加起来：从根到任意一个内部节点，每一层都尽量平分，最终任意节点的左右子树高度差都不会超过 1。这正是「高度平衡」的定义。如果只看根那一层平衡、但子树里某处严重倾斜，那就不是平衡 BST 了——所以「每层都取中点」这个递归策略才是关键，而不是「只在顶层取一次中点」。

### Q2：数组长度是偶数时，取左中点 `(left+right)/2` 还是右中点 `(left+right+1)/2`？两种结果一样吗？

**两种都能 AC，但建出的树形状不同**（都是合法的高度平衡 BST，只是结构不同）。

以 `nums = [1,3]`（下标 0,1）为例：

- 取**左中点** `mid = (0+1)/2 = 0`：根是 `1`，左孩子空、右孩子 `3` → 树 `[1,null,3]`。
- 取**右中点** `mid = (0+1+1)/2 = 1`：根是 `3`，左孩子 `1`、右孩子空 → 树 `[3,1]`。

题面示例 2 明确说「`[1,null,3]` 和 `[3,1]` 都是高度平衡二叉搜索树」，所以选哪个都正确。官方方法一选左中点（最常见、最直觉），方法二选右中点，方法三则每次**随机**选左/右中点（能构造出所有可能的平衡 BST，但平时用不上）。本题取左中点即可。

### Q3：为什么空间复杂度是 O(log n) 而不是 O(n)？明明建出了 n 个节点。

注意题目约定的**「空间复杂度不考虑返回值」**：建出的那棵树（n 个节点）是**答案本身**，不算「额外」辅助空间。真正算额外空间的是**递归调用栈**的深度。

因为每层递归都把区间近乎对半分，递归深度就等于树高。**平衡 BST 的树高是 O(log n)**（这是「平衡」的核心收益），所以递归栈深度也是 O(log n)。对比一下：如果建出来的树退化成一条链（每个节点只有右孩子），递归深度会变成 O(n)，有栈溢出风险——但本题取中点正是为了**避免**退化成链。

### Q4：能不能用「迭代」代替递归？

可以。思路是把「待处理的区间」放进队列/栈里手动模拟递归，每次弹出一个区间 `[left,right]`、取中点建节点、再把左右两个子区间入队。但写起来比递归啰嗦得多（要同时维护「区间」和「它的父节点+左右标记」），可读性差，收益只是省掉递归栈——而这题递归深度本来就只有 O(log n)，根本不会栈溢出。所以**这题没必要写迭代**，递归是最自然的写法，迭代仅作为「理解递归本质」的练习。

### Q5：`nums.size() - 1` 为什么要 `static_cast<int>`？不转会怎样？

`nums.size()` 返回类型是 `size_t`（无符号整数）。虽然这里 `nums` 非空、`size()-1` 不会下溢，但把它直接当 `int` 用有两个隐患：

1. 如果哪天 `nums` 可能是空的，`size() - 1` 会因无符号下溢变成一个巨大的正数（`SIZE_MAX`），导致 `helper` 收到一个错误的右端点，越界访问。
2. `size_t` 和 `int` 混用时，编译器会把 `int` 隐式提升成 `size_t` 参与运算，负数下标（如 `mid - 1` 当 `mid=0` 时是 -1）会被解释成一个巨大的正数，导致难以察觉的 bug。

显式 `static_cast<int>(nums.size())` 后，所有下标运算都在 `int` 域里进行，负数能正确表示（`left > right` 的判断才靠谱）。这是 C++ 处理下标的一个常见好习惯。

## 复盘

### 可迁移套路

- **「有序序列 → 取中点分治建平衡 BST」是通用模板**。凡是题目给一个**升序/降序序列**（数组、链表均可）、要求构造**平衡二叉搜索树**，第一反应就是这套：
  1. 取序列中点作根；
  2. 左半递归建左子树，右半递归建右子树；
  3. 终止条件：区间为空返回空。
  相关题目：
  - **109 题「将有序链表转换为二叉搜索树」**：链表不能 O(1) 随机访问中点，要先转数组（快慢指针找中点也行，但模板本质相同）。
  - **1382 题「将二叉搜索树变平衡」**：先中序遍历拿到升序序列，再套本题模板。两题构造方法完全一致。
- **BST 的中序遍历是升序**，这是 BST 所有题目的「底层定理」。看到「有序数组 + BST」的组合，第一反应就是中序遍历这层联系（105 题「从前序与中序遍历序列构造二叉树」是逆操作：给你两种遍历序列还原树；本题只给一种中序序列，靠「取中点」消解不确定性）。
- **「分治取中点」=「让左右子问题规模尽量相等」**。这正是平衡二叉树、归并排序、快速选择等一堆算法的共同思想——只要一个问题能切成两个规模相近的子问题，取中点就是最自然的划分方式，复杂度里的 `log n` 也由此而来。

### 解法二：取右中点（官方方法二）

与方法一仅差一行：`mid = (left + right + 1) / 2`（偶数长度时取靠右的中间元素）。建出的树形状不同，但同样是高度平衡 BST。

```cpp
class Solution {
public:
    TreeNode* sortedArrayToBST(vector<int>& nums) {
        return helper(nums, 0, (int)nums.size() - 1);
    }
    TreeNode* helper(vector<int>& nums, int left, int right) {
        if (left > right) return nullptr;
        // 总是选择中间位置右边的数字作为根节点
        int mid = (left + right + 1) / 2;
        TreeNode* root = new TreeNode(nums[mid]);
        root->left = helper(nums, left, mid - 1);
        root->right = helper(nums, mid + 1, right);
        return root;
    }
};
```

- 时间 O(n)，空间 O(log n)，与方法一完全相同，只是结果树结构不同。

### 解法三：随机选左/右中点（官方方法三）

每次在两个中点里随机挑一个，能构造出**所有可能**的高度平衡 BST。平时做题用不到，了解即可。

```cpp
class Solution {
public:
    TreeNode* sortedArrayToBST(vector<int>& nums) {
        return helper(nums, 0, (int)nums.size() - 1);
    }
    TreeNode* helper(vector<int>& nums, int left, int right) {
        if (left > right) return nullptr;
        // 选择任意一个中间位置数字作为根节点
        int mid = (left + right + rand() % 2) / 2;
        TreeNode* root = new TreeNode(nums[mid]);
        root->left = helper(nums, left, mid - 1);
        root->right = helper(nums, mid + 1, right);
        return root;
    }
};
```

- 时间 O(n)，空间 O(log n)。`rand() % 2` 随机产生 0 或 1，从而在 `left+right` 和 `left+right+1` 之间随机选一个再除 2，等价于随机取左/右中点。
