# 763 划分字母区间

- 难度：中等
- 标签：**贪心**、哈希表、双指针、字符串
- 力扣链接：https://leetcode.cn/problems/partition-labels/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[划分字母区间](https://leetcode.cn/problems/partition-labels/solution/hua-fen-zi-mu-qu-jian-by-leetcode-solut-tucd/)」方法一。正文主解是 **贪心 + 哈希表（预处理每个字母最后出现的位置，再维护当前片段的结束位置）**，O(n) 时间、O(1) 空间；它和第 55 题「跳跃游戏」是同一类思路——**维护一个「区间结束位置」、扫到边界就切一刀**——只是这里「每个位置能延伸到哪里」由字母的最后出现下标决定。

## 题目描述

给你一个字符串 `s`。我们要把这个字符串划分为**尽可能多**的片段，同一字母最多出现在一个片段中。例如，字符串 `"ababcc"` 能够被分为 `["abab", "cc"]`，但类似 `["aba", "bcc"]` 或 `["ab", "ab", "cc"]` 的划分是非法的。

注意，划分结果需要满足：将所有划分结果按顺序连接，得到的字符串仍然是 `s`。

返回一个表示每个字符串片段的长度的列表。

**示例 1：**

```
输入：s = "ababcbacadefegdehijhklij"
输出：[9,7,8]
解释：
划分结果为 "ababcbaca"、"defegde"、"hijhklij"。
每个字母最多出现在一个片段中。
像 "ababcbacadefegde", "hijhklij" 这样的划分是错误的，因为划分的片段数较少。
```

**示例 2：**

```
输入：s = "eccbbbbdec"
输出：[10]
```

**提示：**

- `1 <= s.length <= 500`
- `s` 仅由小写英文字母组成

## 思路

> 本题主要参考力扣官方题解「方法一：贪心」。

题目有两个核心约束：**同一字母最多出现在一个片段里**（同一字母的所有出现必须落在同一段），以及**尽量多划分**（每段在满足上一条的前提下尽量短）。这两条结合，直接定死了「一段该到哪结束」。

### 核心观察：片段必须延伸到「它包含的所有字母的最后出现位置」

举例，假设当前片段已经包含了字母 `a`，而 `a` 在整个字符串里最后一次出现在下标 8，那么这个片段的结束位置**必须 ≥ 8**——否则下标 8 的那个 `a` 就漏到了下一段，违反「同一字母只在一个片段」。同理，片段里出现的 `b`、`c`……每个字母都把结束位置往后推。

所以一个片段的结束位置，等于「**片段内所有字母的最后出现下标的最大值**」。这个观察把问题结构化了：只要知道每个字母最后一次出现在哪，扫描时维护一个「当前片段的最远结束位置」，到了那个位置就切一刀。

### 第一步：预处理 `last[c]` —— 记录每个字母最后出现在哪

字母只有 26 个（题目保证全是小写字母），用一个长度为 26 的数组 `last` 就能装下。扫一遍字符串，对每个下标 `i` 写 `last[s[i]-'a'] = i`：

- **同一个字母出现多次时，后写的会覆盖前面的**（因为 `i` 单调递增），所以扫完之后 `last[c]` 自然就是字母 `c` 的**最后**出现下标。
- `s[i]-'a'` 把字母 `'a'..'z'` 映射到 `0..25`：`'a'-'a'=0`、`'b'-'a'=1`、……、`'z'-'a'=25`。这是字符哈希的常用技巧。

这一步本质是**哈希表**——以「字母」为 key、以「最后出现下标」为 value。因为 key 只有 26 种小写字母，用定长数组比 `unordered_map` 更快、更省，是字符频率/位置类题的标准做法。

### 第二步：贪心扫描，维护当前片段的结束位置 `end`

再用一次遍历（也可以和预处理合并成一次，但拆开更清晰），维护两个变量：

- `start`：当前片段的起始下标。
- `end`：当前片段**至少要延伸到的结束下标**（初始都为 0）。

对每个下标 `i`：

1. 读出 `s[i]` 这个字母的最后出现位置 `last[s[i]-'a']`，它给当前片段提供了一个「下界」——片段至少得到这里。于是 `end = max(end, last[s[i]-'a'])`。**取 `max` 是因为片段里可能有多个字母，每个都贡献一个下界，必须全部满足，所以取最大。**
2. 判断 `i == end`：如果当前下标恰好等于 `end`，说明从 `start` 到 `end` 这段里出现的**每一个字母，它的最后出现位置都 ≤ `end`**（否则 `end` 会被推到更右边，`i` 就追不上）。这意味着这段内的字母不会跨到下一段——刚好满足约束，可以在这里切一刀：记下片段长度 `end - start + 1`，然后 `start = end + 1` 开新段。

**为什么这是「尽可能多划分」？** 因为每次都是「在满足约束的前提下，遇到第一个可以切的位置就切」——这是贪心地取**最短**的合法片段。如果取更短，必然有字母跨段（非法）；取更长，则少切了一段（不是最多）。所以贪心取最短，片段数自然最多。

### 手动推导 `s = "ababcbacadefegdehijhklij"`

**预处理 `last`（扫一遍记下每个字母最后出现在哪）：**

```
字母:  a  b  c  d  e  f  g  h  i  j  k  l
最后:  8  5  7 14 15 11 13 19 22 23 20 21
```

（只有出现在串里的字母有意义；其余字母不影响本题。）

**贪心扫描（逐个字符维护 `end`，遇到 `i==end` 就切）：**


结果 `[9,7,8]`，对应 `"ababcbaca"` / `"defegde"` / `"hijhklij"`，与示例一致。

注意 `i=8` 那一刀：到 `i=8` 时 `end` 仍然是 8（因为 `a` 的最后位置就是 8，`b/c` 的最后位置更靠前），说明 `a/b/c` 这三个字母都被完整包进了 `[0,8]` 这段，不会漏到后面，所以在这里切是安全的。

## 代码

```cpp
class Solution {
public:
    vector<int> partitionLabels(string s) {
        // int last[26]：定长数组，用来当「哈希表」。
        //   - 下标 0..25 对应字母 'a'..'z'，存储「该字母最后一次出现的下标」。
        //   - 字母总数只有 26 个，用定长数组比 unordered_map<char,int> 更快、更省内存，
        //     这是「字符频率/位置」类题（字母表固定且很小）的通用技巧。
        //   - C++ 原生数组 last[26] 不初始化，里面是垃圾值。但因为下面预处理会从下标 0
        //     顺序写入每个出现过的字母，且扫描时只会读「s 中出现过的字母」对应的 last，
        //     所以不初始化也不影响正确性（官方写法如此）。
        int last[26];

        // 预处理：扫一遍字符串，记录每个字母「最后」出现的下标。
        //   - s[i] - 'a'：把字符转成 0..25 的下标（'a'-'a'=0, 'b'-'a'=1, ...）。
        //   - 同一字母出现多次时，后写的 i 更大，会覆盖前一次，扫完后 last[c] 自然就是「最后」位置。
        //   - s.size() 返回无符号 size_t，存进 int length 是为了循环里和 i、end 做有符号比较不出警告。
        int length = s.size();
        for (int i = 0; i < length; i++) {
            last[s[i] - 'a'] = i;
        }

        // partition：存放答案（每段长度）。vector<int> 是动态数组，末尾追加用 push_back。
        vector<int> partition;

        // start：当前片段的起始下标；end：当前片段「至少要延伸到」的结束下标。
        //   - 二者都从 0 开始。end 在扫描中会被各字母的 last 不断「顶到更右」。
        //   - 用两个变量就能滚出所有切点，所以空间是 O(1)（last[26] 也是常数 26）。
        int start = 0, end = 0;

        // 贪心扫描：对每个下标 i，先更新 end，再判断是否到了切点。
        for (int i = 0; i < length; i++) {
            // max(a, b)：<algorithm> 里的函数，返回 a、b 中较大者，O(1)。
            //   last[s[i] - 'a'] 是「当前字母的最后出现位置」。
            //   取 max：当前片段里可能有多个字母，每个字母都给片段一个「下界」（至少得到它最后出现的位置），
            //   必须全部满足，所以 end 只增不减，取所有下界的最大值。
            //   这一行就是「维护区间结束位置」的核心，和 55 跳跃游戏里的 maxRight=max(maxRight, i+nums[i]) 同构。
            end = max(end, last[s[i] - 'a']);

            // i == end：扫描指针追上了「当前片段的结束位置」。
            //   - 含义：[start, end] 这段里出现的每个字母，它的最后位置都 ≤ end（否则 end 会被推得更右），
            //     所以这些字母都被完整包在这段里，不会跨到下一段 → 满足约束，可以切一刀。
            //   - 这是贪心取「最短合法片段」的切点：遇最早的能切的地方就切，所以片段数最多。
            if (i == end) {
                // push_back(x)：在 vector 末尾追加元素 x（这里等价于 emplace_back）。
                //   end - start + 1 是当前片段 [start, end] 的长度（含两端，所以 +1）。
                partition.push_back(end - start + 1);
                // 切完开新段：下一个片段从 end+1 开始。
                start = end + 1;
            }
        }
        return partition;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 预处理扫一遍字符串记 `last`，O(n)；贪心再扫一遍划分，O(n)。合计 O(n)（两次遍历是常数倍，仍记 O(n)）。
  - 每一步只做 `max`、比较和赋值，都是 O(1)。
- **空间**：O(|Σ|) = O(1)
  - 额外空间只有 `last[26]` 这个定长数组（字母表大小 26，视作常数）；答案数组 `partition` 不计入（题目要求返回它）。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么要预处理「最后出现位置」，而不是「第一次出现位置」或「所有出现位置」？

因为约束是「同一字母的所有出现必须落在同一段」。**决定一段能不能在此结束的关键，是「段内字母最后一次出现在哪」**——只要段已经覆盖到段内每个字母的最后出现位置，后面就不会再出现这些字母，切开后不会跨段。

「第一次出现位置」没用：它告诉我们字母从哪开始，但不能保证之后不再出现。「所有出现位置」（比如开 `vector<int>` 存下标）信息太多反而没用——我们只关心「最远那个」，取 max 就行，预处理时让后写的覆盖前写的，自然得到的就是「最后」。

### Q2：`end = max(end, last[s[i]-'a'])` 为什么是取 `max` 而不是直接赋值？

因为一个片段里**可能有多个字母**，每个字母都给当前片段一个「下界」（片段至少得延伸到它的最后出现位置）。比如片段同时含 `d` 和 `e`，`last[d]=14`、`last[e]=15`，那么片段必须延伸到 `max(14,15)=15` 才能把两个字母都包进去。直接赋值会丢掉之前更远的下界，导致切早了、把字母切到下一段。`end` 必须是「目前见过的所有字母最后位置的最大值」，所以只能增、用 `max`。

### Q3：为什么 `i == end` 时就可以切了？会不会切早了？

不会切早。`i == end` 意味着扫描指针追上了 `end`，而 `end` 是「`[start, i]` 这段内**所有字母**最后出现位置的最大值」。追上说明 `end` 不再被推得更右——也就是说 `[start, end]` 内出现的每一个字母，它的最后位置都 ≤ `end`，全被这段包住了，不会漏到下一段。

反之，如果 `i < end`，说明 `end` 右边还有当前片段某个字母的出现位置（否则 `end` 不会被推那么远），这时切一定会让那个字母跨段，非法。所以 `i == end` 是「第一个合法切点」，刚好贪心地取了最短合法片段。

### Q4：这题和第 55 题「跳跃游戏」是什么关系？

两者结构同构，都是「**扫一个序列，维护一个『右边界』，到了就收尾**」：

| | 55 跳跃游戏 | 763 划分字母区间 |
|---|---|---|
| 维护的右边界 | `maxRight`：目前能跳到的最远下标 | `end`：当前片段至少要到的结束下标 |
| 右边界怎么更新 | `maxRight = max(maxRight, i + nums[i])` | `end = max(end, last[s[i]-'a'])` |
| 右边界的数据来源 | 「站在 `i` 最多能跳 `nums[i]` 步」 | 「字母 `s[i]` 最后出现在 `last[s[i]]`」 |
| 到达边界时的动作 | 不需要切（只判断 `maxRight` 能否覆盖末尾） | `i == end` 就切一段 |

区别在于：55 只问「最远能不能到末尾」（一个全局右边界够用）；763 要切**多段**，所以每次到 `end` 要「收尾、开新段」（`start = end + 1`），相当于多次重置右边界。可以把 763 看成「反复玩的 55」——每切一段就是跑了一次「维护右边界到收尾」的小循环。同样的「维护右边界」思想还能用来做「合并区间」类问题。

## 复盘

- **核心套路**：「**每个元素贡献一段覆盖区间，问怎么合并/切分**」这类问题，标准姿势是 **贪心维护一个右边界 `end`**：扫到元素就 `end = max(end, 该元素的覆盖右端)`，扫到 `end` 这个位置就收尾。一趟扫描 O(n)、O(1)。本题每个字母贡献的区间是「第一次出现 → 最后一次出现」，右端就是 `last[c]`。
- **和 55 跳跃游戏的对比**：两者都是「维护右边界」贪心。55 是「能不能跳到末尾」的**单段**判断（一个 `maxRight`）；763 是「切成尽量多段」的**多段**问题（每段一个 `end`，到 `end` 就切、开新段）。吃透 55 的 `maxRight` 思想，763 只是在「到边界就收尾、重置」这一点上多了动作。
- **字母表用定长数组代替哈希表**：字母只有 26 个时，`int last[26]` 比 `unordered_map<char,int>` 更快更省；`s[i]-'a'` 把字符映射到 `0..25` 是字符哈希的固定套路。凡是「只关心字母出现情况」的题（频率统计、字母异位词、本题的位置记录）都可以套用。
- **贪心正确性的根**：本题贪心之所以对，是因为「合法片段的结束位置有单调性」——`end` 一旦被推到某个位置，之前的字母都被包住了，不会再往回退；而每次在「最早的合法切点」切，保证片段最短、片段数最多。判断一个贪心题能不能贪，先问「维护的那个量有没有单调/最优子结构」，能答上来才放心。
- **可迁移**：本题思路同样适用于「无重叠区间」「合并区间」「用最少数量的箭引爆气球」等区间类贪心题——都是「按右端点维护、到点就收尾/计数」。
