# 55 跳跃游戏

- 难度：中等
- 标签：**贪心**、数组、动态规划
- 力扣链接：https://leetcode.cn/problems/jump-game/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[跳跃游戏](https://leetcode.cn/problems/jump-game/solution/tiao-yue-you-xi-by-leetcode-solution/)」。正文主解是 **贪心（维护最远可达位置）**，O(n) 时间 O(1) 空间；它是「贪心维护最远可达边界」这一可迁移套路的标准范例，也是第 45 题「跳跃游戏 II」的前置基础。

## 题目描述

给你一个非负整数数组 `nums`，你最初位于数组的 **第一个下标**。数组中的每个元素代表你在该位置可以跳跃的最大长度。

判断你是否能够到达最后一个下标，如果可以，返回 `true` ；否则，返回 `false`。

**示例 1：**

```
输入：nums = [2,3,1,1,4]
输出：true
解释：可以先跳 1 步，从下标 0 到达下标 1，然后再从下标 1 跳 3 步到达最后一个下标。
```

**示例 2：**

```
输入：nums = [3,2,1,0,4]
输出：false
解释：无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0，所以永远不可能到达最后一个下标。
```

**提示：**

- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 10^5`

## 思路

> 本题主要参考力扣官方题解「方法一：贪心」。

题目的关键信息有三条：**初始在第一个位置**（下标 0）、**每个元素代表「最大」跳跃长度**（可以跳得更少、不一定要跳满）、问的是 **能否到达最后一个下标**（只要存在一种跳法即可）。

### 朴素想法：DFS / 记忆化 / DP 会超时或浪费

最容易想到的是「模拟所有跳法」：从下标 0 出发，每一步可以跳 `1..nums[i]` 步，递归尝试所有落点，只要某条路径到达 `n-1` 就成功。这是暴搜，最坏 O(n · max(nums[i]))，数据范围 `n ≤ 10^4`、`nums[i] ≤ 10^5` 时必然超时。

加记忆化、改成「`f(i)` = 能否到达下标 `i`」的 DP 也行（`f(i) = 存在 j < i 使 f(j) 且 j + nums[j] ≥ i`），但单看「能不能到」，每个 `i` 都要回看前面所有 `j`，O(n²)。这能过，但远不够优雅——**题目只问「能不能」，根本不关心具体怎么跳**。一旦放下「怎么跳」的执念，就能做到 O(n)。

### 官方主解：贪心，只维护「最远能到哪」

核心观察是这一句话：**对于任意一个位置 `y`，只要存在某个可达位置 `x`，使得 `x + nums[x] ≥ y`，那么 `y` 也可达。**

换句话说，每个可达位置 `x` 都把「它后面 `[x+1, x+nums[x]]` 这一段连续位置」都点亮了。我们根本不用记住是谁点亮的、也不用记住跳几步，**只要记住「到目前为止，最远能点到的位置」** 就够了——这个位置记作 `maxRight`。

算法（从左到右扫一遍）：

1. 初始 `maxRight = 0`（起点下标 0 必然可达）。
2. 依次遍历下标 `i = 0, 1, ..., n-1`：
   - **若 `i > maxRight`**：当前位置 `i` 已经超过了「目前能到的最远位置」，说明 `i` 根本到不了。既然 `i` 都到不了，更靠后的位置更不可能，直接 `return false`。
   - **否则**（`i ≤ maxRight`，`i` 可达）：用 `i` 能更新的最远位置是 `i + nums[i]`，于是 `maxRight = max(maxRight, i + nums[i])`。
   - 若更新后 `maxRight ≥ n - 1`，说明最后一个下标已经落入「可达范围」，直接 `return true`。
3. 循环正常结束都没提前返回，说明始终没摸到 `n-1`，返回 `false`（不过实际上步骤 2 里 `i > maxRight` 会先触发，所以这行更多是兜底）。

**为什么这样贪心是对的？** 因为「可达性」是单调的：**如果位置 `k` 可达，那么 `0, 1, ..., k-1` 也都可达**（从到 `k` 的路径上随便早一步停下即可）。所以「最远可达位置」`maxRight` 一旦覆盖了某个下标，它之前的一切都不用再操心；而它能不能继续往前推进，只取决于「已扫到的可达位置里，谁能让 `i + nums[i]` 最大」。把这件事用**一个变量 `maxRight`** 就维护住了——不需要具体路径，不需要回溯。

### 用两个示例手动走一遍

**示例一** `nums = [2,3,1,1,4]`（`n = 5`，目标 `n-1 = 4`），`maxRight` 初始 `0`：

```
i=0  nums[0]=2  i<=maxRight(0) ✓  maxRight=max(0, 0+2)=2           (2 < 4，继续)
i=1  nums[1]=3  i<=maxRight(2) ✓  maxRight=max(2, 1+3)=4           (4 >= 4，return true) ✓
```

到 `i=1` 就已经覆盖到末尾，直接返回 `true`。

**示例二** `nums = [3,2,1,0,4]`（`n = 5`，目标 `n-1 = 4`），`maxRight` 初始 `0`：

```
i=0  nums[0]=3  i<=maxRight(0) ✓  maxRight=max(0, 0+3)=3
i=1  nums[1]=2  i<=maxRight(3) ✓  maxRight=max(3, 1+2)=3           (没推进)
i=2  nums[2]=1  i<=maxRight(3) ✓  maxRight=max(3, 2+1)=3           (没推进)
i=3  nums[3]=0  i<=maxRight(3) ✓  maxRight=max(3, 3+0)=3           (就是那道过不去的坎)
i=4  nums[4]=4  i>maxRight(3) ✗  → return false ✓
```

到 `i=4` 时发现 `4 > maxRight=3`，末尾下标不可达，返回 `false`。注意下标 3 的 `nums[3]=0` 就是「坎」——它把 `maxRight` 卡在 3，永远跨不过去。

## 代码

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int n = nums.size();
        // maxRight：「截至目前，能到达的最远下标」。
        //   - 初始为 0：题目保证最初位于第一个下标 0，所以下标 0 必然可达。
        //   - 含义是「[0, maxRight] 这一段里每个下标都至少存在一条路径能到达」。
        //   - 整个算法就靠这一个变量滚动推进，所以空间是 O(1)。
        int maxRight = 0;

        // for：从左到右扫描每个下标 i。
        //   - i < n 写成严格小于：下标 0..n-1 共 n 个，i 跑到 n 就停。
        //   - 这里没有提前 break 的条件放在循环头，靠循环体里的 return 退出。
        for (int i = 0; i < n; ++i) {
            // 关键判断：当前下标 i 是否落在「目前能到的最远范围」内？
            //   - 若 i > maxRight，说明 i 这个位置无论怎么跳都够不着
            //     （maxRight 之前的任何落点跳最远也到不了 i）。
            //     既然 i 都到不了，更靠后的位置更不可能，直接判负。
            //   - 这一步等价于官方写法的 if (i <= rightmost) {...} 的「反向提前返回」，
            //     逻辑完全一致，只是把「不可达」的情况显式 return false 出来。
            if (i > maxRight) {
                return false;
            }

            // 走到这里说明 i 可达：用 i 这个落点去更新「最远可达」。
            //   max(a, b)：<algorithm> 里的函数，返回 a、b 中较大者，O(1)。
            //   i + nums[i]：站在下标 i 最多能跳到的位置（题目说 nums[i] 是「最大」跳跃长度）。
            //   取 max 是因为之前的落点可能跳得更远，我们不能让 maxRight 倒退。
            maxRight = max(maxRight, i + nums[i]);

            // 提前剪枝：最远可达已经覆盖到最后一个下标 n-1，没必要再扫了。
            //   - >= 是因为 maxRight 可能直接越过 n-1（比如一步跳过头），同样算成功。
            if (maxRight >= n - 1) {
                return true;
            }
        }

        // 循环正常结束仍没返回：理论上前面的 if (i > maxRight) 会先触发 return false，
        // 这一行主要作兜底（例如 n==1 时循环里第一次就会 maxRight>=0 命中 true，也不会走到这）。
        return true;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 只遍历一遍数组，每个位置做常数次比较与 `max`，共 O(n)。
  - 命中 `true` 或 `false` 时会提前 `return`，平均情况比 O(n) 更快。
- **空间**：O(1)
  - 只用了 `maxRight`、`i`、`n` 三个整型变量，没有开额外数组。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么不关心「具体怎么跳」？不记路径会不会漏掉解？

**不会漏。** 因为「可达性」有**单调性**：如果某个位置 `k` 可达，那么 `0..k-1` 全都可达（从到 `k` 的那条路径中途随便停下即可）。所以「最远可达位置 `maxRight`」这个单一量就能刻画「目前哪些下标已经被点亮」——`[0, maxRight]` 这整段都可达，不需要区分是谁点亮的。只要 `maxRight` 能一路推到 `n-1`，就一定存在至少一种跳法（虽然算法本身没有记录这种跳法）。

这与「第 45 题 跳跃游戏 II」不同：那题要算「最少跳几次」，必须关心落点选择，所以会复杂一些。

### Q2：为什么 `if (i > maxRight)` 直接返回 `false` 就对？

因为 `maxRight` 是「到目前为止能到的最远下标」。如果连当前下标 `i`（注意 `i` 是从左到右依次扫描的）都超过了 `maxRight`，说明前面所有可达的落点，跳到极限也够不着 `i`。而后续的下标 `i+1, i+2, ...` 比 `i` 还远，更不可能到达——题目问的「最后一个下标」自然也到不了，所以可以果断返回 `false`。

反过来，只要 `i ≤ maxRight`，`i` 就一定可达（由 `maxRight` 的定义保证），可以放心用它去更新 `maxRight`。

### Q3：遇到 `nums[i] = 0` 怎么办？是不是一定失败？

**不一定。** `nums[i] = 0` 只表示「站在 `i` 不能再往前推进 `maxRight`」（因为 `i + 0 = i`，`max(maxRight, i)` 不会增大）。但它不一定是死局：

- 如果在踩到 `0` 之前，`maxRight` 已经被某个更靠前的落点推到了 `i` 之后，那么 `0` 这格只是「经过」，无伤大雅，照样能继续往后扫。示例一里其实就藏着一个 `1`（下标 2、3 都是小步长），但照样过。
- 只有当 `maxRight` 恰好卡在 `i`（即 `maxRight == i`）且 `nums[i] == 0` 时，后续 `i+1` 就会出现 `i+1 > maxRight`，从而触发 `return false`。示例二的下标 3（`nums[3]==0`，`maxRight` 卡在 3）正是这种情况。

一句话：**`0` 本身不可怕，可怕的是「最远可达位置被 0 锁死、无法继续推进」**。

### Q4：这题和第 45 题「跳跃游戏 II」是什么关系？

两者题面几乎一样（同一个数组、同一种跳跃规则），但问的东西不同：

- **第 55 题（本题）**：问 **能否** 到达末尾 → 只需维护 `maxRight`，O(n)。
- **第 45 题**：问到达末尾 **最少要跳几次** → 需要在「能到达」的基础上，再决定「每一步跳到哪个落点最优」，通常用「当前跳跃边界 + 下一步最远可达」的双变量贪心，或 BFS 分层。

可以把本题看作第 45 题的「阉割版」：只判断可达性、不算步数，所以更简单。先吃透本题的 `maxRight` 思想，再去做 45 题会顺畅很多。

## 复盘

- **核心套路**：「**能否到达 / 最远能到哪**」这类一维跳跃问题，标准姿势是 **贪心维护一个「最远可达右边界 `maxRight`**」：扫到 `i`，先看 `i` 是否被 `maxRight` 覆盖（否则不可达），再用 `i + nums[i]` 尝试把右边界往右推。一趟扫描 O(n)、O(1)。
- **贪心的「省略」哲学**：本题能贪心，关键在于「**只问能不能、不问怎么跳**」。当题目只要求判断可行性、而不要求具体方案时，往往可以丢掉路径细节、只维护一个全局极值（这里是 `maxRight`）。这是判断「该不该用贪心」的一个信号：**问的是「能不能 / 最值」，而不是「具体方案 / 方案数」**。
- **单调性是贪心正确性的根**：本题贪心之所以对，是因为「可达性单调」——`k` 可达则 `0..k-1` 全可达，于是最远位置一个量就够了。遇到新贪心题，先问自己「这个量有没有单调性 / 最优子结构」，能答上来才敢大胆贪。
- **迁移**：本题的 `maxRight` 思想直接服务于第 45 题「跳跃游戏 II」（那题要在此基础上加「步数计数」）；也和「覆盖区间合并」类问题同构（每个 `i` 贡献一段 `[i, i+nums[i]]`，问这些段能否连成 `[0, n-1]`）。遇到「每个点能覆盖一段范围」的题，先想到「维护最远右边界」。
