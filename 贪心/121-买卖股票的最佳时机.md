# 121 买卖股票的最佳时机

- 难度：简单
- 标签：**数组**、动态规划
- 力扣链接：https://leetcode.cn/problems/best-time-to-buy-and-sell-stock/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[买卖股票的最佳时机](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock/solution/mai-mai-gu-piao-de-zui-jia-shi-ji-by-leetcode/)」。正文主解是 **一次遍历（贪心：维护历史最低价）**，O(n) 时间 O(1) 空间；官方「暴力法」O(n²) 放在「复盘」作对比。力扣把本题分在贪心算法组，核心解法正是一次遍历贪心，所以落 `贪心/` 目录。

## 题目描述

给定一个数组 `prices` ，它的第 `i` 个元素 `prices[i]` 表示一支给定股票第 `i` 天的价格。

你只能选择 **某一天** 买入这只股票，并选择在 **未来的某一个不同的日子** 卖出该股票。设计一个算法来计算你所能获取的最大利润。

返回你可以从这笔交易中获取的最大利润。如果你不能获取任何利润，返回 `0`。

**示例 1：**

```
输入：[7,1,5,3,6,4]
输出：5
解释：在第 2 天（股票价格 = 1）的时候买入，在第 5 天（股票价格 = 6）的时候卖出，最大利润 = 6-1 = 5 。
     注意利润不能是 7-1 = 6, 因为卖出价格需要大于买入价格；同时，你不能在买入前卖出股票。
```

**示例 2：**

```
输入：prices = [7,6,4,3,1]
输出：0
解释：在这种情况下, 没有交易完成, 所以最大利润为 0。
```

**提示：**

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^4`

> 两个硬性约束要读清楚：**只能买卖一次**（不是多次），且 **必须先买后卖**（卖出日期严格在买入之后，不能反过来）。

## 思路

> 本题主要参考力扣官方题解「方法二：一次遍历」。

### 暴力想法：枚举所有买卖日 O(n²)

最直接的思路：两层循环，外层枚举买入日 `i`，内层枚举买入日之后的卖出日 `j`（`j > i`），算出利润 `prices[j] - prices[i]`，取最大。

```cpp
for (int i = 0; i < n; ++i)
    for (int j = i + 1; j < n; ++j)
        ans = max(ans, prices[j] - prices[i]);   // j 严格大于 i，保证先买后卖
```

数据范围 `n ≤ 10^5`，O(n²) = 10^10 量级，**会超时**。需要更快的做法。

### 贪心想法：遍历时记住「到目前为止的最低价」

换一个角度想：**如果我在第 `i` 天卖出，能赚多少？** 既然只能挑一天买入，那当然是挑「第 `i` 天之前的最低价」那天买入最划算。这样第 `i` 天卖出的最大利润就是：

```
prices[i] - min{ prices[0], prices[1], ..., prices[i-1] }
```

把「历史最低价」记成 `minPrice`，随着遍历推进不断更新它。对每一天：

- `price - minPrice` 就是「今天卖出」能赚的钱；
- 取所有天的最大值，就是答案。

这就是一次遍历贪心：**用最小的代价维护一个「到目前为止的最优买入点」**，每一步都基于历史最优做决策，不回头看。整个过程只需扫一遍数组、维护两个变量，O(n) 时间 O(1) 空间。

### 关键：先更新 maxProfit，再更新 minPrice

对每个 `price`，更新顺序是：

```
maxProfit = max(maxProfit, price - minPrice)   // 先用「旧的历史最低价」算今天的利润
minPrice   = min(minPrice, price)               // 再把今天的价格纳入「历史最低价」
```

**为什么这个顺序重要？** 如果先 `minPrice = min(minPrice, price)`，再用更新后的 `minPrice` 算 `price - minPrice`，那 `price - minPrice = 0`（因为 `minPrice` 此时就是 `price` 自己），相当于「今天买入、今天卖出」利润 0。虽然结果恰好是 0（本题允许利润为 0、且 `maxProfit` 初值就是 0，对最终答案无影响），但逻辑上违反了「必须先买后卖、且买卖日不同」的题意。**先算利润再更新最低价**，能干净地保证 `minPrice` 来自「今天之前的某一天」，符合题意。

### 用示例走一遍

`prices = [7,1,5,3,6,4]`（`minPrice` 初值 `INT_MAX`，`maxProfit` 初值 `0`）：

```
price=7   maxProfit=max(0, 7-INT_MAX)=0   minPrice=min(INT_MAX, 7)=7    ← 历史最低=7
price=1   maxProfit=max(0, 1-7)=0         minPrice=min(7, 1)=1          ← 出现新低 1
price=5   maxProfit=max(0, 5-1)=4         minPrice=min(1, 5)=1          ← 今天卖赚 4
price=3   maxProfit=max(4, 3-1)=2→4       minPrice=min(1, 3)=1          ← 仍 4
price=6   maxProfit=max(4, 6-1)=5         minPrice=min(1, 6)=1          ← 今天卖赚 5（峰值）
price=4   maxProfit=max(5, 4-1)=3→5       minPrice=min(1, 4)=1
返回 5 ✓   （第 2 天 1 块买、第 5 天 6 块卖）
```

再走一遍「价格一直跌」的 `prices = [7,6,4,3,1]`：

```
price=7   maxProfit=0   minPrice=7
price=6   maxProfit=max(0,6-7)=0   minPrice=6
price=4   maxProfit=max(0,4-6)=0   minPrice=4
price=3   maxProfit=max(0,3-4)=0   minPrice=3
price=1   maxProfit=max(0,1-3)=0   minPrice=1
返回 0 ✓   （每天卖都亏，不交易）
```

## 代码

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices) {
        // minPrice：「历史最低价」——到目前为止见过的最小买入价格。
        //   - 初始化成 INT_MAX（<climits>，力扣 C++ 模板已包含），表示「还没买过」。
        //     第一轮 price-INT_MAX 是一个很大的负数，max 不会选它，等价于「第一天先记录价格、不卖出」。
        //   - 为什么不用 prices[0] 初始化？用 INT_MAX 让循环对所有元素统一处理，
        //     不用特判第一天，写法更干净；这里也等价于「第一天只能买、不能卖」的语义。
        //   - INT_MAX 是 32 位有符号 int 的最大值（约 2.1×10^9）；题面 prices[i] ≤ 10^4，
        //     所以 price-INT_MAX 一定是负数，安全。
        int minPrice = INT_MAX;

        // maxProfit：「全局最大利润」——所有「今天卖出」候选的最大值。
        //   - 初始化成 0：题目要求「不能获取任何利润时返回 0」，
        //     所以答案天然有 0 兜底（价格一直跌就不交易，利润 0）。
        int maxProfit = 0;

        // 范围 for 循环：int price 逐个拷贝 prices 的元素（int 很小，直接拷贝，不必用引用）。
        //   - 注意顺序：先用「旧 minPrice」算今天卖出的利润，再用今天价格更新 minPrice。
        for (int price : prices) {
            // max(a, b)：<algorithm> 里的函数，返回 a、b 中较大者，O(1)。
            //   price-minPrice 就是「在历史最低价买入、今天卖出」的利润。
            //   这一步用的 minPrice 还没把今天算进去，保证「买在今天之前」。
            maxProfit = max(maxProfit, price - minPrice);

            // min(a, b)：<algorithm> 里的函数，返回 a、b 中较小者，O(1)。
            //   把今天价格纳入「历史最低价」候选，留给后续天数使用。
            minPrice = min(minPrice, price);
        }
        return maxProfit;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 只遍历一遍数组，每个元素做两次 `max`/`min`（各 O(1)），共 O(n)。
- **空间**：O(1)
  - 只用了 `minPrice`、`maxProfit` 两个变量，没有开额外数组。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么要维护「历史最低价」，而不是「全局最低价」？

因为**卖出日必须在买入日之后**。全局最低价可能出现在最后一天（如 `[7,6,4,3,1]` 的最低价 `1` 在第 5 天），那天之后没有「未来」可以卖出，用它当买入点没意义。

「历史最低价」特指**今天之前**的最低价——它能保证买入发生在卖出之前。我们边扫边维护 `minPrice`，到第 `i` 天时 `minPrice` 恰好是 `prices[0..i-1]` 的最小值，用它算出的 `prices[i] - minPrice` 才是合法的「先买后卖」利润。

### Q2：同一天能既买又卖吗？

题面明确说「选择在未来的某一个**不同的日子**卖出」，所以**不能同一天买卖**。代码里通过「先更新 `maxProfit`、再更新 `minPrice`」规避了这种情况：

- 如果反过来先 `minPrice = min(minPrice, price)`，那么 `price - minPrice = 0`，相当于「今天买、今天卖」，虽然利润恰好是 0、对答案无影响，但违反题意。
- 先算 `maxProfit` 再更新 `minPrice`，算利润时 `minPrice` 还是「今天之前的值」，天然满足「买卖日不同」。

### Q3：价格一直跌怎么办？

如 `[7,6,4,3,1]`：每天的 `price - minPrice` 都 ≤ 0，`maxProfit` 始终保持初值 `0`，最终返回 `0`，对应「不交易」。这正是把 `maxProfit` 初始化为 `0`（而非某个负无穷）的好处——题目允许「不交易、利润 0」，初值 `0` 就是「最差也至少不亏」的兜底。

### Q4：这题为什么算「贪心」而不是「动态规划」？

两种视角都成立，看你怎么定义状态：

- **贪心视角（本笔记主解）**：每一步用「历史最低价」做局部最优决策——「在最低价买、今天卖」是今天能做的最优。局部最优能拼成全局最优，因为「最低价」这个量随遍历单调地被维护，没有「回头改决策」的必要。所以是贪心。
- **DP 视角**：令 `dp[i]` 表示「前 `i` 天能获得的最大利润」，则 `dp[i] = max(dp[i-1], prices[i] - min(prices[0..i-1]))`。由于 `dp[i]` 只依赖 `dp[i-1]` 和一个滚动维护的 `minPrice`，压成两个变量后**代码和贪心完全一样**。

所以本题是「贪心和 DP 殊途同归」的典型：DP 推导到极致、滚动掉状态后，得到的就是贪心的形式。力扣把它归在贪心组，是看重它「一次遍历维护历史极值」这个直观的贪心解释。

## 复盘

- **核心套路**：「**一次遍历维护历史极值**」——遍历时维护「到目前为止的最小/最大值」，对每个元素用「当前值与历史极值的差/积/比」更新答案。本题维护历史最低价、`price - minPrice` 求最大利润，和 53 最大子数组和（Kadane：维护以 `i` 结尾的最大和）、买卖股票系列是同一类套路。
- **更新顺序的细节**：涉及「用历史值算当前结果、再用当前值更新历史」时，**先用后更**（先算 `maxProfit` 再更 `minPrice`）能保证语义正确、避免「同一天买卖」之类的越界。这是此类题的通用小心点。
- **初始化的选择**：
  - 求最大值、且答案天然有下界（本题利润 ≥ 0）时，答案变量用下界（`0`）初始化即可；
  - 涉及「减法 / 历史」的辅助变量（`minPrice`），用「哨兵」`INT_MAX` 初始化，避免特判第一个元素，写法更干净。
- **贪心 vs DP**：很多「一次遍历维护一个/两个变量」的简单题，贪心和 DP 殊途同归——DP 转移方程滚掉状态后就是贪心。做题时两种思路都试一遍，有助于理解状态定义。

### 解法二：暴力法（官方方法一，O(n²)，超时）

最朴素的思路：两层循环枚举所有 `(买入日 i, 卖出日 j)` 组合（`j > i`），取 `prices[j] - prices[i]` 的最大值。能过小数据，但 `n = 10^5` 时 O(n²) = 10^10，**会超时**。

```cpp
class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int n = (int)prices.size(), ans = 0;
        for (int i = 0; i < n; ++i) {
            for (int j = i + 1; j < n; ++j) {   // j 从 i+1 开始：保证卖出在买入之后
                // max：O(1)，取所有买卖组合利润的最大值。
                ans = max(ans, prices[j] - prices[i]);
            }
        }
        return ans;
    }
};
```

- **时间**：O(n²)
- **空间**：O(1)

> 暴力法是理解贪心优化的起点：它把「每个卖出日都要重新扫一遍前面的最低价」这步 O(n) 重复劳动，改造成「边扫边维护 `minPrice`」，就降到了 O(n)。
