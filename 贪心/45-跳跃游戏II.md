# 45 跳跃游戏 II

- 难度：中等
- 标签：**贪心**、数组、动态规划
- 力扣链接：https://leetcode.cn/problems/jump-game-ii/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[跳跃游戏 II](https://leetcode.cn/problems/jump-game-ii/solution/tiao-yue-you-xi-ii-by-leetcode-solution/)」。正文主解是 **正向贪心（维护跳跃边界 end + 最远可达 maxPos）**，O(n) 时间 O(1) 空间；官方「方法一：反向查找出发位置」放在「复盘」作对比。
>
> 本题是 55 题「跳跃游戏」的进阶：55 题问「能不能到达最后一个位置」（布尔），本题问「**最少跳几次**能到最后一个位置」（最少步数）。思路相通——都靠维护「最远可达位置」，只是本题还要数跳的次数。

## 题目描述

给定一个长度为 `n` 的 0 索引整数数组 `nums`。初始位置在下标 `0`。

每个元素 `nums[i]` 表示从索引 `i` 向后跳转的最大长度。换句话说，如果你在索引 `i` 处，你可以跳转到任意 `i + j` 处：

- `0 <= j <= nums[i]` 且
- `i + j < n`

返回到达 `n - 1` 的**最小跳跃次数**。**测试用例保证可以到达 `n - 1`**。

**示例 1:**

```
输入: nums = [2,3,1,1,4]
输出: 2
解释: 跳到最后一个位置的最小跳跃数是 2。
     从下标为 0 跳到下标为 1 的位置，跳 1 步，然后跳 3 步到达数组的最后一个位置。
```

**示例 2:**

```
输入: nums = [2,3,0,1,4]
输出: 2
```

**提示:**

- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 1000`
- 题目保证可以到达 `n - 1`

## 思路

> 本题主要参考力扣官方题解「方法二：正向查找可到达的最大位置」。

### 从 55 题带过来的直觉

55 题「跳跃游戏」的做法是：一边扫一边维护「目前能到达的最远位置」`maxPos`，只要 `maxPos` 能覆盖到末尾就返回 `true`。它只关心「能不能到」，不关心「几跳能到」。

本题题目**保证了一定能到达末尾**，所以不用再判「能不能到」，要回答的是「**最少要跳几次**」。

### 关键观察：每一跳都尽量「覆盖最大的范围」

「最少跳跃次数」该怎么贪？直觉是：**每一跳都跳到能让下一步覆盖最远的地方**。

注意这里有个反直觉点——「让下一步覆盖最远」**不等于**「跳到 `nums[i]` 最大的那个位置」。比如在位置 `i`，你能跳到 `i+1, i+2, ..., i+nums[i]` 中的任意一个。该选哪个落脚？应该选那个能让「下一跳最远可达 `j + nums[j]`」最大的 `j`。换句话说，**落脚点本身不重要，重要的是下一跳能探到多远**。

如果直接模拟「在每一跳的范围内枚举、选下一跳最远的落脚点」，写起来要嵌套循环、记落脚位置，比较绕。官方主解给了一个更清爽的等价写法——**不显式选落脚点，只维护两个边界变量**。

### 维护两个变量：当前一跳的边界 `end` + 下一跳的最远 `maxPos`

定义：

- `end`：**当前这一跳能到达的最远下标**（即「这一跳的右边界」）。在 `[0, end]` 范围内的所有位置，都属于「当前这一跳能落到的位置」。
- `maxPos`：**下一跳能到达的最远下标**。在扫描当前一跳的范围内每个位置 `i` 时，不断用 `i + nums[i]` 更新它。
- `steps`：已经跳的次数。

扫描规则（核心就两句）：

1. 遍历到位置 `i` 时，先更新下一跳最远：`maxPos = max(maxPos, i + nums[i])`。
2. **当 `i` 走到 `end`（当前一跳的边界）时，必须跳一次**：`steps++`，然后把 `end` 更新成 `maxPos`（下一跳的边界变成新的当前边界）。

### 为什么 `i` 走到 `end` 就必须跳一次？

可以这样理解：`end` 是「当前这一跳能覆盖的最远位置」。一旦扫描指针 `i` 抵达 `end`，说明**当前这一跳的「额度」已经用完**——再往后走就得靠下一跳了。所以此时计数器 `steps` 必须加 1，并把 `end` 推进到「下一跳能到的最远处」`maxPos`（在抵达 `end` 之前，`maxPos` 已经把这范围内所有位置的贡献都攒好了）。

### 为什么这样做得到的就是「最少跳数」？

因为**每一跳覆盖的范围都被压到了最大**。具体说：在当前一跳的范围内 `[旧 end 的左端, end]`，我们把所有位置 `i` 的 `i + nums[i]` 都看了一遍、取了最大值作为新的 `end`。也就是说，新 `end` 是「在当前这一跳能落脚的前提下，下一跳最远能到哪里」的最大值。**每一跳都把「下一跳的覆盖范围」推到尽可能远**，自然用的跳数最少。这和 BFS 的「层序遍历」思想一致：每一跳就是一层，`end` 是当前层的右边界，`maxPos` 是下一层的右边界。

### 用示例走一遍 `nums = [2,3,1,1,4]`

初始 `end = 0`、`maxPos = 0`、`steps = 0`。注意循环只到 `i = n-2 = 3`（**不用跳到最后一个位置**，到了就算这一跳已经抵达终点）。

```
i=0  nums[0]=2  maxPos=max(0, 0+2)=2   i==end(0)? 是 → 必须跳：steps=1, end=maxPos=2
                 (第 1 跳：从 0 出发，最远可到下标 2)
i=1  nums[1]=3  maxPos=max(2, 1+3)=4   i==end(2)? 否
i=2  nums[2]=1  maxPos=max(4, 2+1)=4   i==end(2)? 是 → 必须跳：steps=2, end=maxPos=4
                 (第 2 跳：覆盖范围扩到下标 4，已到末尾)
i=3  nums[3]=1  maxPos=max(4, 3+1)=4   i==end(4)? 否
循环结束（i 到 3 即 n-2 就停），返回 steps=2 ✓
```

可以看到：第 1 跳把边界从 `0` 推到 `2`，第 2 跳把边界从 `2` 推到 `4`（末尾），共 2 跳。中间 `i=1` 时虽然 `nums[1]=3` 很大，但因为它处在「第 1 跳的覆盖范围内」，所以**不单独计数**，只是用它的 `1+3=4` 把 `maxPos` 撑大，等扫描到 `end=2` 时才一次性「结算」成第 2 跳的边界。

## 代码

```cpp
class Solution {
public:
    int jump(vector<int>& nums) {
        int n = nums.size();
        int maxPos = 0;   // 下一跳能到达的最远下标：扫描过程中不断用 i+nums[i] 更新它
        int end = 0;      // 当前这一跳能到达的最远下标（当前层的右边界）；i 走到 end 就必须结算一次
        int steps = 0;    // 已经跳的次数

        // 关键：循环只到 i < n-1，不到最后一个位置。
        //   - 因为「到达最后一个位置」本身就是某一跳的终点，不需要再在末尾位置上「跳一次」。
        //   - 如果写成 i < n，会在 i == n-1 时又触发一次 i==end 的结算，多算一跳。
        for (int i = 0; i < n - 1; ++i) {
            // max(a, b)：<algorithm> 函数，返回较大者，O(1)。
            //   i + nums[i] 是「从当前位置 i 出发一跳能到的最远下标」，
            //   把它和已知的 maxPos 取大，就是在不断攒「下一跳能到的最远处」。
            maxPos = max(maxPos, i + nums[i]);

            // i 走到当前一跳的边界 end：当前这一跳的额度用完了，必须结算成一次跳跃。
            //   - steps++：跳一次。
            //   - end = maxPos：下一跳的边界「升级」成当前攒好的最远可达。
            //   - 注意 maxPos 不清零：它代表的是「在 [上一个 end, 当前 end] 这段扫描后」
            //     下一跳能到的最远，正好作为新 end。
            if (i == end) {
                end = maxPos;
                ++steps;
            }
        }
        return steps;
    }
};
```

> 官方原码多了一行 `if (maxPos >= i)` 判断，作用是「保证位置 `i` 当前是可达的」。由于本题题目**保证可以到达 `n-1`**，扫描路径上每个 `i` 必然可达，这行判断可省，代码更简洁。如果你把本题代码搬到「不保证可达」的变体（如 55 题）上，就需要保留这行判断来处理「中途某段 `maxPos < i` 走不过去」的情况。

## 复杂度

- **时间**：O(n)
  - 只遍历一遍数组（且只到 `n-2`），每个元素做一次 `max` 和至多一次赋值，都是 O(1)。
- **空间**：O(1)
  - 只用了 `maxPos`、`end`、`steps` 三个变量，没有开额外数组。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么循环到 `n - 1` 就停，而不是 `n`？

因为「到达最后一个位置」**本身就是一次跳跃的终点**，不需要再在末尾位置上额外「跳一次」。

举例 `nums = [2,3,1,1,4]`（`n=5`）：如果循环到 `i = 4`（末尾），在 `i = 2` 时 `end` 已被推到 `4`；那么 `i = 4` 时又会满足 `i == end`，再 `++steps`，结果变成 `3`——多算了一跳。实际答案 `2` 对应的是「第 2 跳的边界已经覆盖到末尾」，扫描到 `i = n-2 = 3` 就足以完成结算。

更本质地说：我们数的是「**为了前进而发起的跳跃次数**」。最后一次跳跃落地在末尾，本身已经在前一次 `i == end` 结算时算进去了（它的边界 `maxPos` 已经 ≥ `n-1`），末尾位置不需要再发起跳跃。

### Q2：为什么 `i == end` 就要跳一次？什么时候跳？

`end` 是「当前这一跳能覆盖的最远下标」。在 `[旧边界, end]` 这段范围内，所有位置都是「当前这一跳能落脚的」。一旦扫描指针 `i` 走到 `end`，意味着**当前这一跳的所有候选落脚点都已经被考察过**（它们的 `i + nums[i]` 都已经贡献进 `maxPos`），这一跳的「决策」完成了，必须结算：`steps++`，并让 `end = maxPos` 进入下一跳。

换个角度：这就像 BFS 的层序遍历。`end` 是当前层的右边界，`maxPos` 是在当前层扫描时攒出的「下一层右边界」。每跨过一层（`i` 抵达 `end`）就是一跳。

### Q3：为什么这样得到的就是「最少跳数」，而不是「某一种合法跳数」？

因为**每一跳都把覆盖范围推到了当前能达到的最大**。在 `[旧边界, end]` 这段里，我们考察了每一个可能的落脚点 `i`，并取 `maxPos = max(maxPos, i + nums[i])`——也就是说，「下一跳能到的最远处」是在**所有可能落脚点里取最大**得到的，没有浪费任何一次落脚机会。每一跳都把战线推到最远，自然跳数最少。

如果某一跳没选「能让下一跳最远」的落脚点，覆盖范围会更小，后续就需要更多跳来补——那就不是最优了。本算法等价于「在每一跳的范围内隐式选了最优落脚点」，只是不显式记录落脚位置，只记录「最远可达」。

### Q4：和 55 题「跳跃游戏」的区别是什么？

| | 55 跳跃游戏 | 45 跳跃游戏 II |
|---|---|---|
| 问什么 | **能否**到达末尾（布尔） | **最少几跳**到达末尾（整数） |
| 是否保证可达 | 不保证，要判 `maxPos < i` 走不过去的情况 | **保证可达**，可省略可达性判断 |
| 核心变量 | 只要一个 `maxPos`（最远可达） | 要 `maxPos`（下一跳最远）+ `end`（当前跳边界）+ `steps`（计数） |
| 何时更新答案 | `maxPos >= n-1` 即返回 `true` | `i == end` 时 `steps++` |

两题共用「维护最远可达」的骨架，45 题多了一层「按跳跃分层」的逻辑（用 `end` 划分每一跳的范围）。可以说 55 题是「一层一层探到哪算哪」，45 题是「数清楚探了几层」。

## 复盘

- **核心套路**：**「求最少步数/最少跳跃」类问题 → 贪心 + 分层（BFS 思想）**。每一跳对应一层，维护「当前层右边界 `end`」和「下一层最远可达 `maxPos`」，扫描指针 `i` 抵达 `end` 就结算一次。这个「分层 + 边界推进」的写法是这一类题（跳跃游戏 II、最少的加油次数等）的通用模板。
- **「贪每步覆盖最大范围」是贪心常用策略**：当目标是「最少次数完成某覆盖」时，每一步都把覆盖范围推到最大，往往就是最优。和 53 题 Kadane「每步都把累积贡献最大化」是同一种贪心味儿——**不纠结具体选哪个，只维护一个「最优边界」**。
- **和 55 题对照记忆**：55 题 = 1 个变量 `maxPos` 判可达；45 题 = 3 个变量 `maxPos`+`end`+`steps` 数层数。先理解 55 题的「最远可达」，再在它上面加「分层计数」就得到 45 题的解。

### 解法二：反向查找出发位置（官方方法一，O(n²) 时间 O(1) 空间）

官方「方法一」从终点倒推：每次找一个**最靠左的、能跳到当前位置**的位置作为上一步的出发点，直到回到下标 0。每找一次 `steps++`。思路直观（从终点「往回贪」），但找上一步要内层循环扫一遍，最坏 O(n²)，**数据范围 n ≤ 10^4 时可能勉强能过但不如正向贪心稳**。

```cpp
class Solution {
public:
    int jump(vector<int>& nums) {
        int position = nums.size() - 1;   // 从终点开始往前找
        int steps = 0;
        while (position > 0) {
            // 从左往右找第一个能跳到 position 的位置，它就是「最靠左的合法上一步」
            for (int i = 0; i < position; i++) {
                if (i + nums[i] >= position) {
                    position = i;          // 跳到这个位置
                    steps++;
                    break;
                }
            }
        }
        return steps;
    }
};
```

- **时间**：O(n²)——最坏每次 `while` 内层都要扫到接近 `position` 处。
- **空间**：O(1)。
- **何时用**：仅作为思路对照；实际提交首选正向贪心（方法二）。
