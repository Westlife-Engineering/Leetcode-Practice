> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/course-schedule/solutions/1/ke-cheng-biao-by-leetcode-solution/)「课程表」（slug：`ke-cheng-biao-by-leetcode-solution`）。正文主解是 **方法二：广度优先搜索（拓扑排序 BFS，即 Kahn 算法）**——建邻接表 + 入度表，把入度为 0 的课程先入队，然后 BFS 逐个「删除」并把后继的入度减一，新出现的入度为 0 的课程再入队，最后统计处理过的课程数是否等于 `numCourses` 即可判断有无环。DFS 三色标记判环法放在「复盘」作对比。

## 题目描述

你这个学期必须选修 `numCourses` 门课程，记为 `0` 到 `numCourses - 1`。

在选修某些课程之前需要一些先修课程。先修课程按数组 `prerequisites` 给出，其中 `prerequisites[i] = [ai, bi]`，表示如果要学习课程 `ai` 则**必须**先学习课程 `bi`。

- 例如，先修课程对 `[0, 1]` 表示：想要学习课程 `0`，你需要先完成课程 `1`。

请你判断是否可能完成所有课程的学习？如果可以，返回 `true`；否则，返回 `false`。

**示例 1：**

```
输入：numCourses = 2, prerequisites = [[1,0]]
输出：true
解释：总共有 2 门课程。学习课程 1 之前，你需要完成课程 0。这是可能的。
```

**示例 2：**

```
输入：numCourses = 2, prerequisites = [[1,0],[0,1]]
输出：false
解释：总共有 2 门课程。学习课程 1 之前，你需要先完成课程 0；并且学习课程 0 之前，你还应先完成课程 1。这是不可能的。
```

**提示：**

- `1 <= numCourses <= 2000`
- `0 <= prerequisites.length <= 5000`
- `prerequisites[i].length == 2`
- `0 <= ai, bi < numCourses`
- `prerequisites[i]` 中的所有课程对**互不相同**

> 读题要点：**`prerequisites[i] = [a, b]` 表示「要先修 b 才能修 a」**，也就是存在一条有向边 `b → a`（b 是 a 的先决条件）。这个方向最容易搞反：是 `b → a`（先修指向后修），**不是** `a → b`。示例 2 里 `[1,0]` 和 `[0,1]` 同时出现构成了 `0→1` 和 `1→0` 的环，所以不可能修完。

## 思路

> 本题主要参考力扣官方题解「方法二：广度优先搜索」（拓扑排序 / Kahn 算法）。

### 第一步：把题目翻译成图论问题（建模）

这是做本题**最重要的一步**——题目一个字都没提「图」，但本质就是个图论问题。

- 把每门**课程**看成一个**图的节点**，课程 `0` 到 `numCourses-1` 一共 `numCourses` 个节点。
- 把每条**先修关系** `[a, b]`（要先修 b 才能修 a）看成一条**有向边 `b → a`**（从先修课程指向后修课程）。

于是 `numCourses` 门课程和 `prerequisites` 条关系，就构成了一张**有向图**。例如 `numCourses=2, prerequisites=[[1,0]]` 就是一张两点图，边 `0 → 1`（0 是 1 的先修）。

那么「**能否修完所有课程**」等价于什么呢？想修完所有课，就得**按某种顺序排课程**，使得每门课在它所有的先修课都修完之后才上。这个排列在图论里有个专门的名字——**拓扑排序（topological sort）**：把图里所有节点排成一列，使每条有向边 `u → v` 都满足「u 排在 v 前面」。

- **能排出拓扑序列 ⟺ 图里没有环（有向无环图 DAG）**。因为环 `a→b→c→a` 意味着 a 要排在 b 前、b 排在 c 前、c 又排在 a 前，自相矛盾，排不出来。
- 所以「能完成所有课程 ⟺ 这张有向图无环 ⟺ 能做拓扑排序」。

**本题 = 判断有向图是否有环。** 官方给了两种判环方法，正文用 BFS 版（Kahn 算法），DFS 版（三色标记）放复盘。

### 第二步：拓扑排序 BFS（Kahn 算法）的流程

Kahn 算法用一个朴素直觉：**先修完「没有任何先修要求」的课，再把它们「删掉」，删掉后又会冒出新的「没有先修要求」的课，循环往复**。最后看是不是所有课都被「删」过——是就无环，不是就有环。

具体步骤：

1. **算每个节点的入度**（指向它的边数）。入度为 0 表示「没有任何先修要求」，这种课随时能修。
2. **把所有入度为 0 的节点入队**（它们是拓扑排序最前面的候选）。
3. **BFS 主循环**：只要队列非空，就取出队首节点 `u`（相当于「修掉这门课 / 从图里删掉它」），然后**遍历 `u` 的所有出边指向的后继 `v`**，把 `v` 的入度减 1（因为 `u` 已经修完，`v` 少了一个先修要求）。**如果 `v` 的入度减到了 0**，说明它的所有先修都修完了，把它也入队。
4. **统计处理过的节点数 `visited`**（每出队一个就 +1）。BFS 结束后，如果 `visited == numCourses`，说明所有课程都能修完（无环）；否则 `visited < numCourses`，说明剩下那些课程互相构成依赖环（比如示例 2 的 `0↔1`），谁的入度都减不到 0，永远入不了队。

注意：**队列里始终装着「入度为 0、待处理」的节点**，每处理一个就「删掉」它并把它后继的入度减 1，这天然避免了重复处理（入度减到 0 才入队，且每个节点入度只会被减到 0 一次）。这和 994 腐烂的橘子里「被感染后才入队」是同一种「染色后才入队」的防重复思路。

### 为什么 `visited == numCourses` 就能判定无环？

这是 Kahn 算法的关键不变式，值得想清楚：

- 如果**无环**：每个节点一定会在它所有前驱（先修）都被删掉之后，入度减到 0 并入队，最终都被处理一遍 → `visited == numCourses`。
- 如果**有环**：环上的节点彼此互为先修，入度永远不可能减到 0（删掉谁都需要先删掉另一个），所以它们**永远进不了队**，`visited` 只统计到环外的节点 → `visited < numCourses`。

所以 `visited == numCourses` 是「无环」的充要判据。这也意味着本题**不需要真的把拓扑序列存下来**，只要数处理了几个节点就够了——官方「优化」那段就是这个意思。

### 手动推导示例 1：`numCourses=2, prerequisites=[[1,0]]`（答案应为 `true`）

先建图。`[1,0]` 表示「先修 0 才能修 1」，即边 `0 → 1`。

```
邻接表 graph:  0 → [1]      （0 的后继是 1）
               1 → []
入度表 indeg:  indeg[0]=0, indeg[1]=1
──────────────────────────────────────────────
初始：把入度为 0 的节点入队 → q = [0]
       visited = 0
──────────────────────────────────────────────
BFS 第 1 轮：
  出队 u=0，visited=1
  遍历 graph[0]=[1] 的后继 v=1：
    --indeg[1] → indeg[1] 由 1 变 0，等于 0 了 → 入队 q=[1]
  队列现在 = [1]
──────────────────────────────────────────────
BFS 第 2 轮：
  出队 u=1，visited=2
  遍历 graph[1]=[]，没有后继，什么都不做
  队列现在 = []
──────────────────────────────────────────────
队列为空，退出 BFS
visited=2 == numCourses=2 → 返回 true ✓
```

对比示例 2：`prerequisites=[[1,0],[0,1]]` 会建出两条边 `0→1` 和 `1→0`，`indeg[0]=1, indeg[1]=1`，**初始没有任何节点入度为 0**，队列一开始就是空的，BFS 根本进不去，`visited=0 < 2`，返回 `false` ✓。这就是「有环则环上节点永远入不了队」的直接体现。

## 代码

```cpp
class Solution {
public:
    // canFinish：判断 numCourses 门课能否全部修完（即有向图是否无环）。
    //   参数 numCourses：课程总数，课程编号 0 ~ numCourses-1，对应图节点。
    //   参数 prerequisites：vector<vector<int>>&，每个元素 {a, b} 表示「先修 b 才能修 a」，
    //                       即有向边 b → a。注意方向别搞反。
    //   返回值：bool，true=能修完（无环），false=修不完（有环）。
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        // vector<vector<int>> graph：邻接表，graph[u] 存「u 指向的所有后继」。
        //   - 下标是节点编号 0 ~ numCourses-1，graph[u] 是一个 vector<int>。
        //   - 用 resize(numCourses) 开 numCourses 个空 vector，后面 push_back 填充。
        //   - 邻接表存稀疏图最省空间：O(V+E)；比邻接矩阵 O(V²) 划算得多。
        vector<vector<int>> graph(numCourses);

        // vector<int> indeg：入度表，indeg[u] 存「指向 u 的边数」（u 有几个先修课）。
        //   - resize(numCourses) 默认初值为 0（vector<int> resize 默认填 0）。
        //   - 入度为 0 的节点就是「没有任何先修、随时能修」的课，是 BFS 的起点。
        vector<int> indeg(numCourses);

        // —— 建图：把每条先修关系转成有向边 b → a ——
        //   - const auto& info：用 const 引用避免拷贝每个 {a,b} 小 vector。
        //   - info[0]=a 是后修课，info[1]=b 是先修课，方向是 b → a：
        //       * graph[b].push_back(a)：b 的后继里加上 a（b 指向 a 的边）。
        //       * ++indeg[a]：a 的入度 +1（a 多了一个先修 b）。
        //   - ⚠️方向是 info[1] → info[0]，不是反过来；搞反就 WA。
        for (const auto& info: prerequisites) {
            graph[info[1]].push_back(info[0]);
            ++indeg[info[0]];
        }

        // queue<int> q：STL 队列，元素是「入度为 0、待处理的课程编号」。
        //   - 只能 push(队尾入) / pop(队头出，无返回值) / front(看队头) / empty / size，全 O(1)。
        //   - 语义：始终装着「所有先修已修完、可以现在就修」的课程。
        queue<int> q;

        // —— 初始化：把所有入度为 0 的节点入队（拓扑排序最前面的候选）——
        //   - 这些课没有任何先修，是 BFS 的天然起点。
        //   - 有环时（如示例 2）这里可能一个都入不了，队列初始就空。
        for (int i = 0; i < numCourses; ++i) {
            if (indeg[i] == 0) {
                q.push(i);
            }
        }

        // visited：记录已经「修掉（出队处理过）」的课程数。
        //   - BFS 结束后比较 visited == numCourses 即可判定有无环。
        //   - 用单个 int 计数就够了，不必真的开数组存拓扑序列（官方「优化」思想）。
        int visited = 0;

        // —— BFS 主循环：队列为空时停止 ——
        //   - 每出队一个节点 = 「修掉这门课 / 从图里删掉它」，并把它的后继入度减 1。
        while (!q.empty()) {
            ++visited;                  // 出队即计数，表示又修掉了一门课
            int u = q.front();           // 看队头但不弹出（取值）
            q.pop();                     // 再弹出队头（pop 无返回值，必须先 front 再 pop）

            // 遍历 u 的所有后继 v：相当于「u 修完了，v 少了一个先修要求」。
            //   - graph[u] 是 vector<int>，范围 for 逐个取后继编号。
            //   - --indeg[v]：先减 1 再判断（前缀 --），把 v 的入度减掉这条 u→v 的边。
            //   - 如果减到 0，说明 v 的所有先修都修完了，入队等后续处理。
            for (int v: graph[u]) {
                if (--indeg[v] == 0) {   // 入度减到 0 → v 现在可以修了
                    q.push(v);
                }
            }
        }

        // 处理过的课程数 == 总课程数 → 无环，能修完；否则有环，修不完。
        return visited == numCourses;
    }
};
```

## 复杂度

- **时间**：O(V + E)，其中 `V = numCourses`（课程数 / 节点数），`E = prerequisites.size()`（先修关系数 / 边数）。
  - 建图遍历所有边一次 O(E)；初始化入队遍历所有节点一次 O(V)；BFS 每个节点最多入队出队各一次、每条边在出队时被「松弛」（后继入度减 1）恰好一次，合计 O(V + E)。
- **空间**：O(V + E)。
  - 邻接表 `graph` 存下所有边，占 O(V + E)；入度表 `indeg` 占 O(V)；队列最多同时存 O(V) 个节点。三者相加仍是 O(V + E)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：边的方向到底是 `b → a` 还是 `a → b`？为什么？

是 **`b → a`**（先修指向后修）。因为 `prerequisites[i] = [a, b]` 的语义是「要先修 b 才能修 a」，在拓扑序里 b 必须排在 a 前面，按照「每条有向边 u → v 都满足 u 排在 v 前」的定义，这条边自然就是 `b → a`。

**搞反了会怎样？** 建图变成 `graph[a].push_back(b)` 且 `++indeg[b]`，相当于把先修关系当成「后修指向先修」。逻辑上虽然也能判环（环的方向反转不影响「有没有环」），但**入度语义全反了**：原本入度为 0 表示「没有先修要求」，搞反后入度为 0 表示「没有人以它为先修」。对这题恰好不影响判环结果（因为环是对称的），但一旦做到 210 课程表 II 需要输出真实的拓扑序列，方向反了序列就全错。**养成习惯：先修关系一律建 `先修 → 后修` 的边**。

### Q2：为什么 `visited == numCourses` 就能判定无环？剩余没处理的是什么？

Kahn 算法的不变式：**只有入度被减到 0 的节点才会入队，而每个节点入队当且仅当它的所有前驱（先修）都已被处理**。

- 无环图里，每个节点最终都会等到所有前驱处理完、入度归零、入队一次 → `visited == numCourses`。
- 有环图里，环上节点彼此互为先驱，删谁都需要先删另一个，**入度永远减不到 0**，永远进不了队。所以 BFS 结束时剩下的 `numCourses - visited` 个节点，**正是构成环的那些节点**（以及只依赖环的节点）。`visited < numCourses` 就是「图里有环」的铁证。

可以这么记：`visited` 数的是「能修完的课」，剩下的就是「卡在环里永远修不完的课」。

### Q3：入度表 `indeg` 到底是干嘛用的？能不能只用邻接表？

入度表是 Kahn 算法的**核心数据结构**，它回答一个问题：「这个节点还有几个先修没修完？」具体作用：

1. **找 BFS 起点**：初始入度为 0 的节点就是「没有任何先修」的课，直接入队。
2. **动态维护「谁可以修了」**：每次删掉一个节点 `u`，就用 `--indeg[v]` 把 `u` 的所有后继的入度减 1。一旦某后继入度变 0，就说明它所有先修都修完了，可以入队。

光有邻接表是不够的——邻接表只告诉你「u 指向谁」，但不知道「v 还差几个先修」。入度表把「还差几个先修」这个状态显式存下来，每删一个前驱就更新，是 Kahn 算法能在 O(V+E) 内判环的关键。

### Q4：能不能用 DFS 判环？为什么这里选 BFS？

完全能，官方「方法一」就是 DFS 三色标记判环（代码见「复盘」）。两者复杂度都是 O(V+E) 时间 / O(V+E) 空间，判环结果一致。选 BFS（Kahn）做主解的理由：

- **更直观**：「先修完没有先修要求的课，再一层层删」这套正向思维更贴合直觉，DFS 三色标记的「访问中/访问过/未访问」状态机对新手偏抽象。
- **模板可复用**：Kahn 算法天然能输出拓扑序列（只要把 `++visited` 那行换成「把 `u` 追加到结果数组」），210 课程表 II 几乎逐行复用这套代码。DFS 输出拓扑序需要「逆后序」，反着存再翻转，绕一层。
- **不用递归栈**：BFS 用堆上的 `queue`，不会有 DFS 那种「链太深爆栈」的风险（本题节点数 ≤ 2000，DFS 一般也不会爆，但工程上 BFS 更稳）。

面试里两套都能讲：BFS（Kahn）主写、DFS 三色作为「另一种判环思路」提一句。

## 复盘

### 可迁移套路（最重要）

- **「拓扑排序 = 入度表 + BFS」是所有依赖 / 调序类问题的通用模板**。记忆口诀：**建图 + 算入度 → 入度 0 全入队 → 出队减后继入度 → 新的 0 入队 → 统计处理数判环**。凡题目里出现「先修 / 先决条件 / 依赖 / 编译顺序 / 任务排期」字样，第一反应就是拓扑排序判环 / 求序。同模板可套的题：
  - **210 课程表 II**：和本题几乎一样，只是把 `visited` 计数换成「拓扑序列数组」，最后判断序列长度是否等于 `numCourses`。
  - **310 最小高度树**：反复剥「叶子节点（度数为 1）」，本质是拓扑排序的无向图版本（剥洋葱法）。
  - **329 矩阵中的最长递增路径**：先拓扑排序（按值从小到大），再在拓扑序上做 DP。
  - **444 序列重建**（力扣会员题）：判断序列能否唯一重构超序列，判环 + 序列唯一性。
  - 编译器「能否按依赖关系编译所有模块」、任务调度「能否按先后依赖跑完所有任务」，本质都是这题。

- **「有向图判环 = 拓扑排序 / DFS 三色」二选一**。BFS（Kahn）靠「入度归零」判环，DFS 靠「访问中再被访问到 = 回边 = 环」判环。两套都能 O(V+E)，按场景选：要输出拓扑序优先 Kahn，只判环 / 要找具体环上节点优先 DFS。

- **「初始化时把所有起点一起入队」**这个技巧在 994 腐烂的橘子（多源 BFS）里已经见过，本题再次复用——只不过那里「起点 = 所有腐烂橘子」，这里「起点 = 所有入度为 0 的课程」。多源 / 多起点的 BFS 模板是一致的。

### 解法二：深度优先搜索（DFS 三色标记判环，对比用）

官方「方法一」：对每个未访问的节点做 DFS，用三色标记每个节点的状态——

- `visited[u] == 0`：白，**未访问**；
- `visited[u] == 1`：灰，**访问中**（在当前 DFS 递归栈里）；
- `visited[u] == 2`：黑，**已访问完毕**（它和它所有后继都已确认无环）。

判环逻辑：DFS 进入 `u` 时先染灰；遍历 `u` 的后继 `v`，如果 `v` 是灰色说明在当前搜索路径里又遇到了 `v`，也就是找到了**回边（back edge）**，存在环，直接标记失败。`u` 的所有后继都 DFS 完且没发现环，就把 `u` 染黑。只要发现环就不用再搜了，用一个全局 `valid` 标志短路退出。

```cpp
class Solution {
private:
    vector<vector<int>> edges;     // 邻接表，edges[u] 存 u 的所有后继
    vector<int> visited;           // 三色标记：0=未访问 1=访问中(灰) 2=已完结(黑)
    bool valid = true;             // 全局标志：发现环就置 false 并短路退出

public:
    // dfs(u)：从 u 出发深度优先遍历，途中若发现环就把 valid 置 false。
    void dfs(int u) {
        visited[u] = 1;            // 进入 u，染灰（放进当前递归路径）
        for (int v: edges[u]) {    // 遍历 u 的所有后继
            if (visited[v] == 0) {
                dfs(v);            // v 没访问过，递归进去
                if (!valid) {
                    return;        // 后续递归已经发现环，提前退出
                }
            }
            else if (visited[v] == 1) {
                // v 是「访问中」状态 → 当前递归路径里又遇到了 v → 回边 → 有环
                valid = false;
                return;
            }
            // visited[v]==2（黑）：v 已经确认无环，直接跳过
        }
        visited[u] = 2;            // u 的所有后继都查完且无环，染黑（完结）
    }

    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        edges.resize(numCourses);
        visited.resize(numCourses);
        for (const auto& info: prerequisites) {
            edges[info[1]].push_back(info[0]);   // 同主解：边 b → a
        }
        // 对每个未访问的节点都尝试 DFS（图可能不连通，要逐个起点试）。
        //   - 条件里加 && valid：一旦某次 DFS 发现了环，后面不用再试，提前退出。
        for (int i = 0; i < numCourses && valid; ++i) {
            if (!visited[i]) {
                dfs(i);
            }
        }
        return valid;
    }
};
```

- **时间**：O(V + E)，每个节点至多被 DFS 进入一次、每条边至多被遍历一次。
- **空间**：O(V + E)，邻接表 O(V+E) + 递归栈最深 O(V) + `visited` 数组 O(V)。
- **对比 BFS（Kahn）**：两者复杂度完全相同，都能判环。DFS 的优势是思路紧凑、能顺带定位环上节点；BFS（Kahn）的优势是正向思维直观、改输出拓扑序列成本最低。本题正文选 Kahn，210 课程表 II 也用同一套代码最顺。
