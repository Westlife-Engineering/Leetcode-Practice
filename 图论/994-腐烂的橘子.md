# 994 腐烂的橘子

- 难度：中等
- 标签：**广度优先搜索**、数组、矩阵
- 力扣链接：https://leetcode.cn/problems/rotting-oranges/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/rotting-oranges/solution/fu-lan-de-ju-zi-by-leetcode-solution/)「腐烂的橘子」（slug：`fu-lan-de-ju-zi-by-leetcode-solution`）。正文主解是 **方法一：多源广度优先搜索（多源 BFS）**——把所有初始就腐烂的橘子在第 0 分钟一起入队，然后一层一层往外感染（每处理完一层 = 过了 1 分钟），用「层数」即「经过的分钟数」。它本质上是 **102 题层序遍历的换皮版**：把树换成网格、把「左右孩子」换成「上下左右四个邻居」，分层处理的模板完全照搬。

## 题目描述

在给定的 *m x n* 网格 `grid` 中，每个单元格可以有以下三个值之一：

- 值 `0` 代表空单元格；
- 值 `1` 代表新鲜橘子；
- 值 `2` 代表腐烂的橘子。

每分钟，腐烂的橘子**周围 4 个方向上相邻**的新鲜橘子都会腐烂。

返回 直到单元格中没有新鲜橘子为止所必须经过的**最小分钟数**。如果不可能，返回 `-1` 。

**示例 1：**

```

输入：grid = [[2,1,1],[1,1,0],[0,1,1]]
输出：4

```

**示例 2：**

```

输入：grid = [[2,1,1],[0,1,1],[1,0,1]]
输出：-1
解释：左下角的橘子（第 2 行， 第 0 列）永远不会腐烂，因为腐烂只会发生在 4 个方向上。

```

**示例 3：**

```

输入：grid = [[0,2]]
输出：0
解释：因为 0 分钟时已经没有新鲜橘子了，所以答案就是 0 。

```

**提示：**

- `m == grid.length`
- `n == grid[i].length`
- `1 <= m, n <= 10`
- `grid[i][j]` 仅为 `0`、`1` 或 `2`

## 思路

> 本题参考力扣官方「方法一：多源广度优先搜索」。

### 为什么这题是「最短路径」，从而该用 BFS？

题目问的是「直到没有新鲜橘子为止必须经过的**最小分钟数**」。一个新鲜橘子被哪个腐烂橘子先感染到，就用哪个时间——本质是「从所有腐烂橘子出发，走到每个新鲜橘子的**最短步数**」。**求最短步数 / 最短时间这类问题，BFS 是标准答案**：BFS 一层一层往外扩，第一次访问到某个格子时走过的步数，就是到它的最短距离（因为更短的层数一定更早被处理）。

而 DFS 不行：DFS 会一条路走到底，第一次到达某个格子走的步数不一定最短，还得反复回退、反复更新，既慢又容易写错。所以网格上「最短感染时间」这类问题，看到「最小」「最少」「最短」字样，先条件反射想到 BFS。

### 关键观察：所有初始腐烂橘子「同时」开始感染（多源 BFS）

题面说「每分钟**每个**腐烂橘子都会使上下左右相邻的新鲜橘子腐烂」——也就是说**所有腐烂橘子是同步行动的**，不是排队一个一个来。

这恰好可以套用一个技巧：**把所有腐烂橘子在「第 0 分钟」一次性全部塞进队列**，作为 BFS 的「第 0 层」（类比 102 题里把根节点 `root` 入队作为第 1 层）。然后照常一层一层 BFS：

- 第 0 层 = 所有初始腐烂橘子（时间 = 0）；
- 第 1 层 = 这些橘子上下左右的新鲜橘子（时间 = 1，即第 1 分钟被感染）；
- 第 2 层 = 再往外的橘子（时间 = 2）；
- ……

官方把这种做法叫「**多源 BFS**」——起点不止一个。它有个很优雅的等价理解（官方原话）：想象一个虚构的「超级源点」在第 -1 分钟把那些初始橘子全变腐烂，那么所有初始腐烂橘子在 BFS 树里就属于同一层。多源 BFS 等价于「加个虚拟源点后的普通 BFS」，但代码里不必真去建这个超级源点——**直接把所有腐烂橘子一起入队**即可，效果一模一样，却省掉了「每个腐烂橘子各跑一次 BFS」的巨大开销。

### 和 102 题层序遍历的关系（核心）

这一题几乎就是 102 题「二叉树层序遍历」搬到网格上，对应关系：

| 102 层序遍历 | 994 腐烂的橘子 |
|---|---|
| 二叉树节点 `TreeNode*` | 网格坐标 `(x, y)` |
| `root` 根节点入队 | **所有**初始腐烂橘子入队 |
| 节点的左右孩子 | 坐标的上下左右 4 个邻居 |
| 每层一个数组 | 每层 = 1 分钟，记录层数 = 时间 |
| 处理前先存 `size = q.size()` | **完全一样的套路**：进层先存 `size`，内层按固定 `size` 出队 |

最关键的招数就是 **102 题那句口诀：「先存 size，再按 size 出队」**。这里它的作用有二：① 区分层与层（每层对应 1 分钟，层数就是经过的时间）；② 保证「同一分钟内，所有腐烂橘子同时感染各自邻居」。如果不存 size、直接一个一个出队，就会变成「一个腐烂橘子走完好几步、别的还没动」，分钟数全乱套。这块在 102 题笔记里已经反复强调过，本题完全复用。

### 两个必备的辅助统计

光会分层 BFS 还不够，还要解决两个问题：

1. **怎么判断无解返回 `-1`？** ——提前数一遍「初始新鲜橘子总数 `fresh`」。BFS 每感染掉一个就 `fresh--`。BFS 跑完后若 `fresh > 0`（还有橘子没被波及），就返回 `-1`。
2. **怎么知道答案就是「几分钟」？** ——每开始处理新的一层，`minutes++`（或每感染一个就更新 `minutes = dis + 1`）。最后一个被感染的新鲜橘子所在的那一层，对应的时间就是答案。注意**初始全是空格子 / 没有新鲜橘子时（如示例 3），答案是 0**——所以在「有腐烂橘子可入队」且「还有新鲜橘子」时才累加 `minutes`。

### 手动推导示例 1：`grid = [[2,1,1],[1,1,0],[0,1,1]]`（答案应为 4）

先把网格画出来，`R`=腐烂、`F`=新鲜、`.`=空：

```
初始：
  R F F      (0,0)=2
  F F .      fresh = 6（数所有 1）
  . F F

第 0 层入队：q = [(0,0)]   （只有 1 个初始腐烂橘子）
minutes = 0
──────────────────────────────────────────────
第 1 轮外层（处理第 0 层）：
  size = 1
  出 (0,0)：感染右 (0,1)→F 变 R、入队；感染下 (1,0)→F 变 R、入队
  本轮 fresh 从 6 → 4
  minutes = 1
  队列现在 = [(0,1),(1,0)]   ← 这是「第 1 层」（第 1 分钟被感染的）
──────────────────────────────────────────────
第 2 轮外层（处理第 1 层）：
  size = 2
  出 (0,1)：感染右 (0,2)→F 变 R 入队；下 (1,1)→F 变 R 入队
  出 (1,0)：感染右 (1,1) 已被感染跳过（grid 已是 2）；下 (2,0) 是空
  fresh 从 4 → 2
  minutes = 2
  队列现在 = [(0,2),(1,1)]   ← 「第 2 层」
──────────────────────────────────────────────
第 3 轮外层（处理第 2 层）：
  size = 2
  出 (0,2)：右越界；下 (1,2) 是空 → 不感染
  出 (1,1)：感染下 (2,1)→F 变 R 入队
  fresh 从 2 → 1
  minutes = 3
  队列现在 = [(2,1)]   ← 「第 3 层」
──────────────────────────────────────────────
第 4 轮外层（处理第 3 层）：
  size = 1
  出 (2,1)：感染右 (2,2)→F 变 R 入队
  fresh 从 1 → 0
  minutes = 4
  队列现在 = [(2,2)]
──────────────────────────────────────────────
循环条件 !q.empty() && fresh>0：
  fresh 已为 0，退出（即使队列里还有 (2,2) 也不必再处理，
  因为它不再需要感染任何人——答案已经确定）

返回 minutes = 4 ✓
```

注意循环条件写成 `while (!q.empty() && fresh > 0)` 的好处：一旦新鲜橘子已经全部被感染，就提前停，不必把队列里剩余的腐烂橘子再无意义地处理一遍。`fresh` 这个统计量既是「判无解」的依据，也是「提前终止」的开关，一举两得。

## 代码

```cpp
class Solution {
public:
    // int 返回：经过的最小分钟数；无法全部腐烂时返回 -1。
    // vector<vector<int>>& grid：二维网格的引用。
    //   grid[i][j]：0=空、1=新鲜、2=腐烂。
    //   传引用避免拷贝；方法内部直接改 grid（把被感染的 1 改成 2，充当「已访问」标记）。
    int orangesRotting(vector<vector<int>>& grid) {
        // queue<pair<int,int>>：STL 队列，元素是「坐标对 (x, y)」。
        //   - pair<int,int>：存两个 int 的结构体，用 .first / .second 访问，
        //     也可以用 C++17 结构化绑定 auto [x,y] = ... 一次拆开。
        //   - queue 只能 push(队尾入) / pop(队头出，无返回值) / front(看队头) / empty / size。
        //   - 语义：始终装着「已经腐烂、但还没去感染邻居的橘子」，
        //     同一时刻队列里的橘子都属于同一层（同一分钟被感染的）。
        queue<pair<int, int>> q;

        // fresh：当前还剩多少个新鲜橘子。
        //   - 用途有二：① BFS 结束后 fresh>0 就返回 -1（有橘子永远没被波及）；
        //     ② 做循环提前终止条件（fresh==0 时不必再扩散）。
        int fresh = 0;

        int n = (int)grid.size();        // 行数
        int m = (int)grid[0].size();     // 列数（题目保证每行列数相同）

        // —— 第一遍扫描：把所有初始腐烂橘子入队，顺便数出 fresh ——
        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < m; ++j) {
                if (grid[i][j] == 2) {
                    // emplace(i, j)：在队尾原地构造一个 pair<int,int>(i,j)。
                    //   - 等价于 q.push({i,j}) 或 q.push(make_pair(i,j))，但 emplace 少一次拷贝。
                    //   - 这些初始腐烂橘子算「第 0 层」（时间 0），全部一起入队 = 多源 BFS 的核心。
                    q.emplace(i, j);
                } else if (grid[i][j] == 1) {
                    ++fresh;             // 统计新鲜橘子总数
                }
            }
        }

        // minutes：经过的分钟数。从 0 开始，每开始处理新的一层就 +1。
        int minutes = 0;

        // 四个方向向量：右、下、左、上。
        //   - 用数组 + for 循环遍历四方向，比写四段重复代码更不容易漏。
        //   - dx[k]/dy[k] 是「行/列的偏移」，加到当前坐标 (x,y) 上得到邻居 (x+dx[k], y+dy[k])。
        int dx[4] = {0, 1, 0, -1};
        int dy[4] = {1, 0, -1, 0};

        // 外层循环：每一轮处理「一层」（= 1 分钟）。
        //   - 两个条件都要满足：① 队列非空（还有腐烂橘子没扩散）；② 还有新鲜橘子（fresh>0）。
        //   - 写 && fresh 是提前终止：一旦新鲜橘子都腐烂了就停，省掉无意义的扩散。
        while (!q.empty() && fresh > 0) {
            // ★核心技巧（和 102 题层序遍历一模一样）★：
            //   先把「当前层的橘子数」存到局部变量 size 里。
            //   - 绝对不能在内层 for 里直接写 i < q.size()：内层每出一个橘子、
            //     又会把它刚感染的新橘子 push 进队列，q.size() 一直在变，
            //     这样会把「下一层（下一分钟）」的橘子也当成当前层处理，minutes 就错了。
            //   - 必须先固定 size，内层只循环这个固定次数，新 push 进来的留到下一轮外层。
            int size = (int)q.size();

            // 进入新的一层，意味着又过了 1 分钟。
            ++minutes;

            // 内层循环：把当前层的 size 个腐烂橘子逐个出队，让它们去感染各自邻居。
            for (int i = 0; i < size; ++i) {
                // 结构化绑定（C++17）：把队头的 pair 拆成 x（行）、y（列）。
                //   - 等价于：auto p = q.front(); q.pop(); 然后 p.first / p.second。
                //   - 顺序：必须先 front() 拿到值、再 pop() 移除（pop 不返回值）。
                auto [x, y] = q.front();
                q.pop();

                // 沿四个方向尝试感染邻居。
                for (int k = 0; k < 4; ++k) {
                    int nx = x + dx[k];
                    int ny = y + dy[k];

                    // 越界 || 非新鲜橘子（空格 0 或已腐烂 2）→ 跳过。
                    //   - 只有 grid[nx][ny]==1（新鲜）才需要感染，这样天然避免重复访问：
                    //     被感染后 grid 改成 2，下次别的橘子再看到它就不会重复入队。
                    if (nx < 0 || nx >= n || ny < 0 || ny >= m || grid[nx][ny] != 1) {
                        continue;
                    }

                    // 感染：新鲜变腐烂。
                    grid[nx][ny] = 2;
                    --fresh;               // 新鲜橘子少一个
                    q.emplace(nx, ny);     // 新腐烂的橘子入队，下一轮去感染它的邻居
                }
            }
        }

        // BFS 结束：fresh==0 说明全部腐烂，返回 minutes；fresh>0 说明有橘子永远没被波及，返回 -1。
        //   - 示例 3（[[0,2]]）场景：初始 fresh=0，循环根本不进，minutes 保持 0，返回 0，正确。
        return fresh == 0 ? minutes : -1;
    }
};
```

## 复杂度

- **时间**：O(nm)，其中 n、m 分别为 `grid` 的行数与列数。
  - 每个格子最多被入队、出队各一次（被感染成腐烂后就再也不会重复入队，因为有 `grid[nx][ny] != 1` 这道闸门）；每出队一个橘子检查 4 个邻居，整体 O(4nm) = O(nm)。
- **空间**：O(nm)。
  - 空间消耗来自**队列**。最坏情况（整张网格几乎全是需要被感染的新鲜橘子）队列同时存 O(nm) 个坐标。
  - 本解法**没有开额外的 `dis` / `visited` 数组**——直接把被感染的新鲜橘子在原网格上改成 2 来当「已访问」标记，省掉了官方代码里 `dis[10][10]` 的额外空间（官方那版为了能同时记录「每个橘子被感染的时间」才用了 `dis` 数组；本写法只关心总分钟数，不需要逐格记录时间，所以更省空间）。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么所有腐烂橘子要「同时」入队，不能一个一个来？

因为题目里腐烂橘子是**同步**行动的：「每分钟**每个**腐烂橘子都会感染相邻新鲜橘子」。如果只拿一个腐烂橘子做起点跑完一整轮 BFS，再换下一个，那等于「让第一个橘子独自扩散好几分钟」——它扩散到的格子时间会被算得很小，而别的初始腐烂橘子的扩散能力被完全忽略了，时间全错。

正确做法是把**所有初始腐烂橘子在第 0 分钟一起塞进队列**，作为 BFS 的同一层（第 0 层）。这样 BFS 天然让它们「并排」往外扩——同一层里的橘子在「同 1 分钟」各自感染自己的邻居，邻居们组成下一层（第 1 分钟），完全贴合题意。这就是「**多源 BFS**」的含义：多个起点同时出发，求各自到每个格子的最短距离。代码上区别于普通 BFS 的就一句话——**初始化时用一个 for 把所有起点都 push 进队列**。

### Q2：为什么用 BFS 不用 DFS？

BFS 一层一层扩，**第一次访问到某格子时走过的步数就是最短步数**（更短的层一定先被处理完），天然求出「最短感染时间」。而 DFS 会一路钻到底，第一次到达某格子走的步数可能很长，事后还得用更短的路径反复覆盖更新，既慢又容易写错。**网格上「最短时间 / 最短步数 / 最少操作」这类问题，看到关键词就条件反射想到 BFS**。

### Q3：怎么判断无解返回 `-1`？空网格或没有新鲜橘子怎么办？

靠 `fresh` 这个统计量：

- **初始化**时数一遍所有 `grid[i][j] == 1` 的格子，得到 `fresh`。
- BFS 每感染一个新鲜橘子就 `--fresh`。
- 跑完循环后 `fresh > 0`，说明这些橘子从来没被任何腐烂橘子波及（比如示例 2 左下角那个被空格子隔断的橘子），返回 `-1`；`fresh == 0` 返回 `minutes`。

边界情况：

- **没有新鲜橘子**（如示例 3 `[[0,2]]`，`fresh == 0`）：`while` 循环条件 `fresh > 0` 直接不满足，循环一次都不进，`minutes` 保持 0，返回 0，正确。
- **没有腐烂橘子但有新鲜橘子**：初始队列为空，循环也不进，`minutes = 0` 但 `fresh > 0`，返回 `-1`，正确（新鲜橘子永远等不到腐烂源）。
- **全是空格子**：`fresh == 0`，返回 0。

所以 `fresh` 一个变量同时承担了「判无解」和「空场景下返回 0」两件事，是本题最关键的辅助统计。

### Q4：循环条件写 `!q.empty() && fresh > 0`，多加的 `fresh > 0` 有什么用？

这是**提前终止**优化。如果不加，就算新鲜橘子已经全感染完（`fresh == 0`），代码还会把队列里剩余的腐烂橘子一个个出队、去检查邻居——但这些邻居要么越界、要么不是新鲜橘子（都是空格或已腐烂），全是白干。加了 `fresh > 0` 后，一旦最后一个新鲜橘子被感染，下一轮判断直接退出，省掉这些无意义循环。**结果完全一样，只是少跑几轮空转**。注意 `minutes` 是在「进入每一层」时累加的，提前退出不会多算 1 分钟。

## 复盘

### 可迁移套路

- **「多源 BFS 求最短时间 / 最短距离」是经典模板**，记忆口诀：**初始化时把所有源点一起入队 → 外层 `while (!q.empty())` → 进层先存 `size = q.size()` → 内层按固定 `size` 出队 → 用层数当距离**。看到「多个起点同时扩散、求到每个目标的最短步数」，直接套这套模板，比每个起点各跑一次 BFS 快得多。

- **「在原数据上打标记 = 免开 visited 数组」**。本题把被感染的新鲜橘子直接在 `grid` 上从 1 改成 2，既表达了「已感染」又充当「已访问」，省掉一个 `visited` 二维数组。同类技巧在 73 题（用首行首列当标记数组）、200 题岛屿数量（把访问过的 '1' 改成 '0'）里都见过，是网格 BFS/DFS 的常用省空间手段。

- **「统计待处理目标数 + 每处理一个减一」用于判完成 / 判无解**。`fresh` 这个计数既是循环终止条件又是无解判据，比「最后再扫一遍网格找 1」更省一次 O(nm) 扫描。凡是「需要确认是否所有目标都被覆盖到」的题，都可以这样用一个计数器。

### 和 102 题层序遍历的关系

本题就是 **102 题「二叉树的层序遍历」在网格上的应用**，两题的 BFS 骨架几乎逐行对应：树节点 `TreeNode*` 换成坐标 `pair<int,int>`、`root` 入队换成「所有初始腐烂橘子入队」、`node->left/right` 换成「四方向邻居」、`size = q.size()` 这一句**完全一字不改**。所以 102 笔记里那句「先存 size，再按 size 出队」是整个 BFS 章节的总纲，吃透它就能套到几乎所有「分层 / 分步」的题。

### 后续相关题

「多源 BFS」这套模板可以原样迁移到很多题：

- **542. 01 矩阵**：求每个 0 到最近的 1 的距离——把所有 0 一起入队做多源 BFS，和本题把所有腐烂橘子入队一模一样。
- **286. 墙与门**（力扣会员题）：把所有门一起入队，BFS 填每个空房间到最近门的距离。
- **1162. 地图分析**：求离陆地最远的海域——把所有陆地一起入队做多源 BFS。
- **1926. 迷宫中离入口最近的出口**：单源 BFS 求最短步数，是本题退化到「只有一个腐烂橘子」的情形。
- **200. 岛屿数量**：同为网格上的搜索题，但那里是「数连通块个数」用 DFS/BFS 都行，和本题「求最短时间」的 BFS 动机不同，可对比着做。
