# 39 组合总和

- 难度：中等
- 标签：数组、**回溯**
- 力扣链接：https://leetcode.cn/problems/combination-sum/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/combination-sum/solutions/314482/zu-he-zong-he-by-leetcode-solution-2/)「组合总和」（slug：`zu-he-zong-he-by-leetcode-solution`）。正文主解是 **回溯 + 剪枝（`for` 循环 + `start` 索引 + 排序剪枝）**，这是组合型回溯最通用、最好记的写法；官方题解代码用的「选/不选二叉递归」放在文末「复盘」作对比。本题和 [46 全排列](./46-全排列.md)、[78 子集](./78-子集.md) 并称回溯三兄弟，正好串起「排列 / 子集 / 组合」三类最经典的回溯形态。

## 题目描述

给你一个 **无重复元素** 的整数数组 `candidates` 和一个目标整数 `target` ，找出 `candidates` 中可以使数字和为目标数 `target` 的 **所有 不同组合** ，并以列表形式返回。你可以按 **任意顺序** 返回这些组合。

`candidates` 中的 **同一个数字** 可以 **无限制重复被选取** 。如果至少一个数字的被选数量不同，则两种组合是不同的。

对于给定的输入，保证和为 `target` 的不同组合数少于 150 个。

**示例 1：**

```
输入：candidates = [2,3,6,7], target = 7
输出：[[2,2,3],[7]]
解释：
2 和 3 可以形成一组候选，2 + 2 + 3 = 7 。注意 2 可以使用多次。
7 也是一个候选， 7 = 7 。
仅有这两种组合。
```

**示例 2：**

```
输入: candidates = [2,3,5], target = 8
输出: [[2,2,2,2],[2,3,3],[3,5]]
```

**示例 3：**

```
输入: candidates = [2], target = 1
输出: []
```

**提示：**

- `1 <= candidates.length <= 30`
- `2 <= candidates[i] <= 40`
- `candidates` 的所有元素 **互不相同**
- `1 <= target <= 40`

## 思路

> 本题主解参考力扣官方题解「方法一：搜索回溯」的思路，但采用更通用的「`for` 循环 + `start` 索引」组织方式，并加上排序剪枝（官方题解给出的最朴素写法不带剪枝，放在复盘对比）。

### 题目要什么？

从 `candidates` 里挑数（**同一个数可以挑无限次**），凑出和正好等于 `target` 的所有组合。注意三点：

1. 同一个数可以重复用（`2` 能选成 `[2,2,2,...]`）。
2. `candidates` 本身**没有重复元素**（这点很关键，简化了去重）。
3. 答案里**不能有重复组合**：`[2,2,3]` 和 `[2,3,2]` 算同一个，只能出现一次。

### 这还是回溯！

这题本质上和 [46 全排列](./46-全排列.md) 一脉相承——都是在「决策树」上做 DFS + 选择/撤销选择。回溯三要素依然成立：

1. **路径 `path`**：当前已经选了哪些数，求和还差 `target`。
2. **选择列表**：`candidates` 里能挑的数。
3. **结束条件**：剩余 `target == 0`（凑齐，收集答案）；或剩余 `target < 0`（凑超了，回退）。

可以直接套 [46 全排列](./46-全排列.md) 那套「`for` + 做选择 → 递归 → 撤销选择」的模板，但要做**三处关键改造**——这正是「组合总和」区别于「全排列」的全部内容。

### 三个关键点（本题的全部难点都在这里）

#### 关键点 ①：同一个数能重复用 → 递归传 `i`，不是 `i+1`

在 [46 全排列](./46-全排列.md) 里，每个数只能用一次，所以 `used` 标记 + `for` 从 0 扫到尾。本题「同一个数可无限次选」，那就不需要 `used`——但我怎么表达「这个数还能再选」？

答案在**递归传给下一层的起点**：

- 如果递归调用写成 `backtracking(..., i + 1)`，意思是「下一层只能从 `i+1` 往后选」——也就是把 `candidates[i]` 永久排除了（这其实是 [78 子集](./78-子集.md) 那种「每个数选一次」的写法）。
- 如果递归调用写成 `backtracking(..., i)`，意思是「下一层仍然从 `i` 开始选」——也就是 **`candidates[i]` 还可以被再选一次**。这才符合「可重复使用」。

就差这么一个 `+1`，含义完全不同。**这是组合总和题最容易写错的地方。**

#### 关键点 ②：避免重复组合 → `for` 循环用 `start` 索引从 `i` 开始

题目要求 `[2,2,3]` 和 `[2,3,2]` 算同一个组合，只收一份。怎么保证只枚举一次？

办法是：**强制选数的顺序「不降」**。即后选的数在 `candidates` 里的下标 `>=` 先选的数的下标。这样 `[2,2,3]`（下标 0,0,1）会枚举到，而 `[2,3,2]`（下标 0,1,0）因为下标「往回跳」会被禁止。

实现上就是给递归函数加一个 `start` 参数，表示「这一层只能从 `candidates[start]` 开始往后选」：

```
void backtracking(candidates, target, start) {
    for (int i = start; i < n; ++i) {   // ← 从 start 开始，不从 0
        做选择 candidates[i];
        backtracking(candidates, target - candidates[i], i);  // ← 传 i，不是 i+1（见关键点①）
        撤销选择;
    }
}
```

- `for` 循环的 `i` 从 `start` 起步：保证「同层选数不回头」，去掉 `[2,3,2]` 这种重复。
- 递归往下传 `i`（不是 `i+1`）：保证「同一个数可重复用」（见关键点①）。

这两件事都靠 `start` / `i` 这两个下标完成，**没有用 `used` 数组**——这是组合型回溯和全排列型回溯在外观上最大的不同。

#### 关键点 ③：剪枝 → 排序后，当前数 > 剩余 target 就 `break`

不剪枝也能做对，只是慢。剪枝能让程序快很多，思路是：

1. **先给 `candidates` 排序**（`sort`）。排序不会改变答案，因为「可重复用 + `start` 去重」只关心下标顺序，与值大小无关；但排序后能给剪枝提供「单调性」。
2. 在每一层的 `for` 循环里，如果 `candidates[i] > target`（当前数已经比剩余目标和还大），那**这个数以及它后面的数（都更大）都不可能再选了**，直接 `break` 跳出整个循环。注意是 `break` 不是 `continue`——因为数组有序，后面只会更大，全都没戏。

剪枝的写法常直接揉进 `for` 的判断条件里：

```cpp
for (int i = start; i < (int)candidates.size() && candidates[i] <= target; ++i)
```

`candidates[i] <= target` 一旦不满足，循环自然结束，等价于 `break`。

> **为什么要先排序？** 因为剪枝依赖「`candidates[i]` 比剩余 target 大 → 后面更大 → 全 break」这个单调性。不排序，遇到一个大的 `break` 了，后面可能还藏着小的能用，就剪错了。**排序是这道剪枝能成立的必要前提。**

### 和 46 全排列、78 子集的对比（回溯三兄弟）

这三题是回溯组的核心，写法几乎一样，差别就在「能不能重复用 / 怎么去重 / 怎么剪枝」：

| 题 | 解的含义 | 能否重复用同一元素 | 怎么去重 | 递归传给下一层的起点 | 结束条件 |
|---|---|---|---|---|---|
| **46 全排列** | 排列（**管顺序**） | 否（每个用一次） | `used[]` 标记 + `for` 从 0 扫 | 无 `start`，每层都从头扫 | `path.size() == n` |
| **78 子集** | 子集（**不管顺序**） | 否（每个选/不选） | `for` 从 `start` 开始 | `backtracking(i + 1)` | 每进一层就收一份 |
| **39 组合总和** | 组合（**不管顺序**） | **是（可无限重复用）** | `for` 从 `start` 开始 | `backtracking(i)`（不是 `i+1`） | `target == 0` 收集 |

一句话记住：**全排列管顺序 → 每层从头扫；子集/组合不管顺序 → 用 `start` 去重；组合可重复用 → 传 `i` 不传 `i+1`。**

### 手动推导 `candidates = [2,3,6,7], target = 7` 的回溯过程

排序后仍是 `[2,3,6,7]`。下面把递归过程展开（`start` 是本层允许的最小下标，`target` 是剩余目标和）：

```
backtracking(start=0, target=7)  path=[]
├─ i=0 选 2: path=[2], target=5  → backtracking(start=0, target=5)
│  ├─ i=0 选 2: path=[2,2], target=3  → backtracking(start=0, target=3)
│  │  ├─ i=0 选 2: path=[2,2,2], target=1  → backtracking(start=0, target=1)
│  │  │     i=0: candidates[0]=2 > 1 → break（剪枝）✗
│  │  ├─ i=1 选 3: path=[2,2,3], target=0 → target==0，收 [2,2,3] ✓
│  │  │     i=2: candidates[2]=6 > 0 → break（剪枝）✗
│  │  (i=2: 6 > 3 break)
│  ├─ i=1 选 3: path=[2,3], target=2  → backtracking(start=1, target=2)
│  │     i=1: candidates[1]=3 > 2 → break（剪枝）✗
│  (i=2: 6 > 5 break)
├─ i=1 选 3: path=[3], target=4  → backtracking(start=1, target=4)
│  ├─ i=1 选 3: path=[3,3], target=1  → backtracking(start=1, target=1)
│  │     i=1: candidates[1]=3 > 1 → break（剪枝）✗
│  (i=2: 6 > 4 break)
├─ i=2 选 6: path=[6], target=1  → backtracking(start=2, target=1)
│     i=2: candidates[2]=6 > 1 → break（剪枝）✗
├─ i=3 选 7: path=[7], target=0 → target==0，收 [7] ✓
(i=4 越界，结束)

结果：[[2,2,3],[7]] ✓ 与示例 1 一致
```

注意每次 `target` 减到 0 就收一份并 `return`；只要 `candidates[i] > target` 就 `break`（靠排序保证后面更大、不用再看）。整棵树被剪掉了大量分支，这就是排序剪枝的威力。

## 代码

```cpp
class Solution {
public:
    // 两个成员变量，让所有递归层共用同一份：
    //   - ans：存所有合法组合的结果。vector<vector<int>> 是「二维动态数组」，
    //     外层每个元素是一个 vector<int>（一种组合）。
    //     push_back(某个vector)：末尾追加一个组合，均摊 O(组合长度)（要拷贝整个组合）。
    vector<vector<int>> ans;
    //   - path：当前正在拼的组合。vector<int> 动态数组，长度随「做选择/撤销」增减。
    //     push_back(x)：末尾追加，均摊 O(1)；pop_back()：删末尾元素，O(1)。
    //   - 注意：不像 46 全排列那样需要 used 标记数组——「同一数可重复用」+「start 去重」
    //     已经覆盖了选择列表的管理，不需要 used。
    vector<int> path;

    // 回溯主函数：参数含义
    //   - candidates：题目给的候选数集合（按引用传，避免拷贝；const 也行，这里跟着官方写法不加 const）。
    //   - target：当前剩余的「目标和」。每选一个数，target 就减去它；target==0 表示正好凑齐。
    //     注意 target 是「剩余值」，不是「已经累加的和」——用剩余值能直接做剪枝判断。
    //   - start：本层 for 循环允许的最小下标。
    //     ★ 关键点②：靠它去重——同层选数只能往后走，禁止回头，从而避免 [2,3,2] 这种重复组合。
    //     （对比 46 全排列：那里 for 每层从 0 扫，因为排列管顺序；本题不管顺序，所以从 start 扫。）
    void backtracking(vector<int>& candidates, int target, int start) {
        // 结束条件①：剩余 target == 0，正好凑齐，把当前 path 拷一份存进答案。
        //   - 注意是「拷贝」——后续撤销选择会改 path，但已存进 ans 的这份不受影响。
        //   - target 不会减到负数：剪枝条件 candidates[i] <= target 保证了
        //     只有「选了之后 target >= 0」的数才会被选，所以这里只需判 == 0。
        if (target == 0) {
            ans.push_back(path);
            return;
        }

        // 本层的选择列表：从 start 枚举到末尾。
        //   ★ 关键点②：i 从 start 起步（不是从 0），保证「同层选数下标不降」，去掉重复组合。
        //   ★ 关键点③（剪枝）：循环条件里的 candidates[i] <= target 是剪枝的灵魂——
        //     当前数已经比剩余 target 还大，就别选了；又因为数组已排序，后面的数更大，
        //     所以一旦不满足就整个 break（写进 for 条件里，自然结束循环）。
        //     这就是「排序 + 当前数>剩余target 就 break」的剪枝，能砍掉大量无意义分支。
        //   - candidates.size() 返回 size_t（无符号），和 int 比较时显式转 int 避免符号警告。
        for (int i = start; i < (int)candidates.size() && candidates[i] <= target; ++i) {
            // ===== 做选择（回溯三步之 1）=====
            // 把 candidates[i] 加进当前组合。
            path.push_back(candidates[i]);

            // ===== 递归（回溯三步之 2）=====
            // 进入下一层：剩余 target 减掉当前数；起点仍是 i（不是 i+1）。
            //   ★ 关键点①：递归传 i 而不是 i+1，是「同一个数可重复使用」的核心。
            //     传 i+1 → 下一层从 i+1 起步 → 当前数永久排除（这是 78 子集「每数选一次」的写法）；
            //     传 i   → 下一层仍从 i 起步 → 当前数还能再选一次（这才是「可无限重复用」）。
            //     就差这一个 +1，含义完全相反，本题最易写错处。
            //   - target - candidates[i]：把「剩余目标和」传下去，比传「已累加和」更便于剪枝。
            backtracking(candidates, target - candidates[i], i);

            // ===== 撤销选择（回溯三步之 3，回溯的「回」就在这里）=====
            // 递归回来后，把刚加进去的 candidates[i] 从 path 末尾拿掉，
            // 让同层 for 的下一个 i 能在干净的 path 上继续。
            //   - 这一句必须和 push_back 严格对称：push 一次、pop 一次。
            //   - 不需要像 46 全排列那样再改 used，本题压根没用 used。
            path.pop_back();
        }
    }

    vector<vector<int>> combinationSum(vector<int>& candidates, int target) {
        // ★ 关键点③的前置步骤：先排序，剪枝才成立。
        //   - sort：STL 算法，默认升序快排（内省排序 introselect），O(n log n)。
        //   - 为什么要排序？剪枝靠「candidates[i] > target 时后面更大、全 break」这个单调性。
        //     不排序，遇到大数 break 了，后面可能还藏着能用的小数，就会漏解。
        //   - 排序不会影响答案正确性：组合只看「选了哪些数（不计顺序）」，下标去重靠 start 保证。
        sort(candidates.begin(), candidates.end());

        // path / ans 清空（应对同一个 Solution 对象被多次调用；力扣虽每次新建实例，养成清空习惯更稳）。
        path.clear();
        ans.clear();

        // 从空 path、start=0、原始 target 开始回溯。
        backtracking(candidates, target, 0);
        return ans;
    }
};
```

## 复杂度

- **时间**：O(n^(target/min))，其中 `n = candidates.size()`、`min` = `candidates` 中的最小值。
  - 直觉：递归树最深 `target/min` 层（一直选最小的数），每层最多分 `n` 个分支，所以是 `n^(target/min)` 量级。这是带剪枝的「`for` 循环 + start」写法的常用上界。
  - 官方对朴素（不剪枝）写法给的是更松的 O(n × 2ⁿ) 上界（n 个位置每个选/不选），以及按「所有可行解长度之和」表示的 O(S)。实际运行由于 `candidates[i] <= target` 剪掉了大量分支，远小于这些上界。
  - 本题数据范围 `candidates.length ≤ 30`、`target ≤ 40`，规模很小，纯回溯也很快。
- **空间**：O(target/min)
  - 不计答案数组 `ans`（题目要求返回的空间通常不计入）。
  - 递归调用栈最深 `target/min` 层（一直选最小的数也只够选这么多次），`path` 同阶；两者相加 O(target/min)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么递归要传 `i` 而不是 `i+1`？

这是**组合总和区别于 78 子集的唯一一处代码差异**，也是本题最易写错点。

- 传 `i+1` → 下一层 `for` 从 `i+1` 起步 → `candidates[i]` 在这条分支里永远不会再被选 → 等价于「每个数最多选一次」。这是 78 子集（每个元素选/不选）的写法。
- 传 `i` → 下一层 `for` 仍从 `i` 起步 → `candidates[i]` 还能再被选一次 → 「同一个数可无限重复使用」。这才是组合总和要的语义。

可以这么记：**`start` 参数控制「能不能继续选这个数」**。`start = i` 表示「能继续选」，`start = i+1` 表示「不能再选了，下一个」。题目要求可重复用，所以传 `i`。

### Q2：为什么必须先 `sort`？不排序会错吗？

**不排序不会算错，但会慢；更严重的是剪枝会失效。**

剪枝条件 `candidates[i] <= target` 的「`break`」逻辑依赖单调性：「当前数太大 → 后面的数更大 → 全 break」。不排序的话，`candidates` 可能是 `[7,2,3,6]` 这种乱序，遇到 `7 > 5` 直接 `break` 后面就跳过了 `2,3`，这些本来能用的数被漏掉——**漏解**。

所以两个选择：
- 不排序：那就不能靠「单调性 break」，得把剪枝条件写成 `if (candidates[i] > target) continue;`（用 `continue` 不是 `break`，只跳过当前这个、继续看后面的）。能做对，但没有「砍掉一整段」的剪枝效果，慢。
- 排序：能用 `break`（写进 `for` 条件最简洁），剪枝效果最强，代价只是一次 O(n log n) 排序。本题 `n ≤ 30`，排序几乎免费。

笔记正文采用「排序 + break」的标准剪枝写法。

### Q3：剪枝到底怎么剪？`break` 和 `continue` 有什么区别？

剪枝的本质是「**提前判断这条路走不通，干脆别走**」。本题有两种剪枝：

1. **「当前数太大」剪枝**：`candidates[i] > target`。当前数比剩余目标和还大，选了就凑超了。
   - 数组**有序**时：后面更大，全都没戏 → **`break`**，整个循环结束。
   - 数组**无序**时：后面可能还有小的能用 → 只能 **`continue`**，跳过当前这个继续看下一个。
2. **「凑齐」终止**：`target == 0` 收集答案 `return`；「凑超」的情况其实被第 1 条挡在 `for` 条件外了，所以代码里不必单独判 `target < 0`。

`break` 比 `continue` 强：`break` 直接跳出整个循环（砍掉一整段），`continue` 只跳过本次迭代。排序让 `break` 成为合法且高效的选项。

### Q4：本题和 46 全排列、78 子集到底差在哪？

三题代码骨架几乎一样（`backtracking` + `for` + 做选择→递归→撤销选择），差别全在「能不能重复用 / 怎么去重」，见思路里的三兄弟对比表。归纳成三句话：

- **46 全排列**：管顺序，每个数用一次 → 用 `used[]` 标记，`for` 每层从 0 扫到尾。
- **78 子集**：不管顺序，每个数最多选一次 → `for` 从 `start` 开始，递归传 `i+1`。
- **39 组合总和**：不管顺序，**每个数可无限次选** → `for` 从 `start` 开始，递归传 `i`，外加排序剪枝。

把这三题放一起对照着看，回溯的「选择列表管理」就彻底通了。

## 复盘

### 可迁移套路

- **「组合型回溯」= 可重复选 + `start` 去重 + 剪枝**。本题是这类问题的母题，后续题目都是在这套基础上微调：
  - **40 组合总和 II**：`candidates` 有重复元素 → 排序后加 `if (i > start && candidates[i] == candidates[i-1]) continue;` 同层去重；且每个数只能用一次 → 递归传 `i+1`。
  - **77 组合**：每个数选一次、组合大小为 k → 递归传 `i+1`，结束条件 `path.size() == k`。
  - **216 组合总和 III**：只允许用 1~9、每个一次 → 同 77。
  - **17 电话号码的字母组合**：选择列表是「当前数字对应的字母」，跨数字不重复，模板一样。
  - **131 分割回文串**：用 `start` 表示「切割起点」，本质还是组合型回溯。
- **「剩余目标和」做参数比「已累加和」好**：前者能直接写剪枝条件（`candidates[i] <= target`），后者还要算「已和 + 当前数 <= 原始 target」，更绕。
- **排序是组合剪枝的通用前置步骤**：只要剪枝逻辑用到「后面的数更大」，就先排序。代价小、收益大。
- **回溯三要素（路径、选择列表、结束条件）+ 三步（做选择→递归→撤销选择）** 是所有回溯题的通用骨架，详见 [46 全排列](./46-全排列.md)。本题只是在「选择列表」管理上换了个写法（`start` 代替 `used`）。

### 解法二：选/不选二叉递归（官方题解代码，不带剪枝）

官方题解给出的写法思路不同：**不写 `for` 循环，而是对「第 `idx` 个数」做二叉决策**——要么跳过不用（递归 `idx+1`），要么选一次（递归 `idx`，因为还能再用）。每个位置只有「选 / 不选」两个分支，所以是一棵二叉决策树。

两种写法等价、能搜出同一批解，区别在「组织方式」：

- **选/不选二叉（本解法）**：每个数选几次靠「连续多次走'选'分支」表达；不带剪枝、靠 `idx == n` 终止。官方原话「只给出了最朴素不含剪枝的写法」。
- **`for` 循环 + start（正文主解）**：每个数选几次靠「在同一层重复进入 `i` 分支」表达；天然支持排序剪枝。是组合型回溯更通用的范式。

```cpp
class Solution {
public:
    // dfs：当前看到 candidates[idx]，剩余 target，已选列表 combine。
    //   对每个 idx 做「跳过 / 选一次」二选一，所以是二叉决策树。
    void dfs(vector<int>& candidates, int target, vector<vector<int>>& ans,
             vector<int>& combine, int idx) {
        // 终止条件：候选数全部看完。
        if (idx == candidates.size()) {
            return;
        }
        // 终止条件：正好凑齐，收一份。
        if (target == 0) {
            ans.emplace_back(combine);   // emplace_back 比 push_back 少一次拷贝（直接原地构造）
            return;
        }
        // 分支一：跳过 candidates[idx]，看下一个数。
        dfs(candidates, target, ans, combine, idx + 1);
        // 分支二：选一次 candidates[idx]（前提是不凑超）。
        //   注意递归仍传 idx（不是 idx+1），因为「可重复使用」，下一轮还能再选它。
        if (target - candidates[idx] >= 0) {
            combine.emplace_back(candidates[idx]);
            dfs(candidates, target - candidates[idx], ans, combine, idx);
            combine.pop_back();          // 撤销选择
        }
    }

    vector<vector<int>> combinationSum(vector<int>& candidates, int target) {
        vector<vector<int>> ans;
        vector<int> combine;
        dfs(candidates, target, ans, combine, 0);
        return ans;
    }
};
```

- **时间**：官方给 O(S)（S = 所有可行解长度之和），松上界 O(n × 2ⁿ)。
- **空间**：O(target)，递归栈深。
- **对比**：写法更「函数式」（每层只有两个分支），但**不带剪枝、跑得比主解慢**，且不像「`for` + start」那样能直接套到 40/77/216 等变体上。入门建议先掌握正文主解的「`for` + start + 剪枝」模板（更通用、可迁移性更好），再回头看官方这种二叉决策写法理解「同一问题的不同表达」。
