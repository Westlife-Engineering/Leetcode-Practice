# 22 括号生成

- 难度：中等
- 标签：字符串、动态规划、**回溯**
- 力扣链接：https://leetcode.cn/problems/generate-parentheses/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/generate-parentheses/solutions/2070752/gua-hao-sheng-cheng-by-leetcode-solution/)「括号生成」（slug：`gua-hao-sheng-cheng-by-leetcode-solution`）。正文主解是 **回溯 + 剪枝**：维护已用的左括号数 `open` 和右括号数 `close`，回溯地每次尝试「加左括号」或「加右括号」，靠两个剪枝条件保证拼出来的串一定是合法括号。这是回溯里「在生成过程中用约束剪掉非法分支」的经典题，和 46 全排列那套「做选择 → 递归 → 撤销选择」的模板一脉相承。官方题解还给了「暴力生成 + 事后校验」和「按长度递归（DP 思想）」两种解法，放在文末「复盘」作对比。

## 题目描述

数字 `n` 代表生成括号的对数，请你设计一个函数，用于能够生成所有可能的并且 **有效的** 括号组合。

**示例 1：**

```
输入：n = 3
输出：["((()))","(()())","(())()","()(())","()()()"]
```

**示例 2：**

```
输入：n = 1
输出：["()"]
```

**提示：**

- `1 <= n <= 8`

## 思路

> 本题主要参考力扣官方题解「方法二：回溯法」的思路。所谓「有效的括号组合」= 由 `n` 对括号组成、且每对都正确闭合的串（任意位置左括号数都不少于右括号数，且总数各 `n` 个）。

### 什么样的括号串才是「合法」的？

先把「合法括号」这件事想透，后面所有剪枝条件都是从它推出来的。一个由 `(` 和 `)` 组成、共 `2n` 个字符的串，是合法括号组合，当且仅当同时满足：

1. **总数对**：左括号 `(` 恰好 `n` 个、右括号 `)` 恰好 `n` 个（合起来 `2n` 个字符，对应 `n` 对）。
2. **任意前缀里左括号数 ≥ 右括号数**：从头扫到任意位置，目前看到的 `(` 数量都必须 ≥ `)` 的数量。一旦某一刻右括号比左括号多，说明出现了「还没开就先关」的非法情况（比如 `())(`，扫到第 3 个字符时右括号已经 2 个、左括号才 1 个，非法）。

这两条加起来就等价于「每对括号都正确闭合」。注意第 2 条是针对**每一个前缀**的，不是只看最终总数——`()()` 合法（每个前缀都满足左≥右），`)()(` 虽然左右各 2 个但不合法（第 1 个字符就是 `)`，瞬间右>左）。

### 回溯的决策树：每步只做「加左」或「加右」两种选择

把「拼括号串」看成一步步做决策：从空串开始，每一步决定**在末尾加一个 `(` 还是加一个 `)`**，一共要加 `2n` 步。这就是一棵二叉决策树：

- 第 1 层：加 `(` 还是 `)` ？
- 第 2 层：再加 `(` 还是 `)` ？
- ……
- 第 `2n` 层：串拼满 `2n` 个字符，收集答案。

如果像「方法一暴力法」那样**每一步都两种选择全试**，会生成 `2^(2n)` 个串、再逐个校验合法性——`n=8` 时就是 `2^16 = 65536` 个候选，其中大部分是非法的（比如一上来就 `)`），白费力气。

### 关键：在生成过程中用「剪枝条件」直接跳过非法分支

回溯 + 剪枝的核心思想：**不要等串拼完了再校验，而是在每一步「能不能加这个括号」时就用约束卡死**，非法的分支压根不往下走。这样生成的每一条路径天然合法，省掉事后校验。

把上面「合法括号两条要求」翻译成「当前这一步能不能加括号」的判断。维护两个计数器：

- `open`：当前串里**已经放了几个左括号**。
- `close`：当前串里**已经放了几个右括号**。

那么：

| 想加的括号 | 剪枝条件（满足才加） | 为什么这样写 |
|---|---|---|
| 加 `(`（左括号） | `open < n` | 总共只能放 `n` 个左括号，还没放满才能继续加。一旦 `open == n` 就不能再加左了，强行加会让总数超过 `n`，违反「总数对」。 |
| 加 `)`（右括号） | `close < open` | **右括号数必须严格小于左括号数**才能加。加完之后 `close+1 ≤ open`，保证「前缀左括号数 ≥ 右括号数」依然成立。如果 `close == open`（左右相等）就再加 `)` 会变成 `close > open`，瞬间非法。 |

**为什么这两个条件能保证生成的串一定合法？**

- 每次加 `)` 前都查 `close < open`，保证了「**任意前缀里左括号数 ≥ 右括号数**」这条不变式从头到尾不被破坏（第 2 条满足）。
- 当串拼到 `2n` 长度时，`open` 不可能超过 `n`（被 `open < n` 卡住）、`close` 不可能超过 `open`（被 `close < open` 卡住）。而总长度 `2n = open + close`，要满足这两个上限，唯一可能是 `open == n` 且 `close == n`——也就是左右各 `n` 个（第 1 条满足）。

所以只要沿着这两个剪枝条件走到底的串，**一定合法**，不需要额外校验。

### 回溯三要素（套 46 题那套）

1. **路径（`cur`）**：当前正在拼的字符串。
2. **选择列表**：固定就是「加 `(`」和「加 `)`」两种，但要过剪枝条件——`open < n` 时才能选左、`close < open` 时才能选右。
3. **结束条件**：`cur.length() == 2 * n`，串拼满了，收集答案。

注意本题和 46 全排列、17 电话号码的字母组合的区别：**这里没有 `for` 循环枚举选择列表**，因为选择固定就两种（加左 / 加右），直接用两个 `if` 分别处理即可。这是回溯模板的一个变体——当选择是「有限且固定的几个动作」时，写成多个 `if` 比套 `for` 更清晰。

### 手动推导 `n = 2` 的回溯树

`n = 2` 要拼 4 个字符，合法答案只有 2 个：`["(())", "()()"]`。把整棵剪枝后的决策树画出来（每个节点标 `cur (open,close)`，即「当前串 + 左括号数 + 右括号数」）：

```
                              "" (0,0)                         起点
                           /          \
                       加 (            加 ) ← close<open? 0<0 不成立，剪掉！
                     "(" (1,0)         ✗
                    /         \
                加 (           加 )
              "((" (2,0)     "()" (1,1)
                |              /        \
            open<n? 2<2 不成立  加 (        加 )
                ✗ 只能加 )   "()(" (2,1)   close<open? 1<1 不成立 ✗
              "(()" (2,1)        |
            open<n? 不成立      只能加 )
            只能加 )         "()( )" (2,2) → 长度 4 == 2n ✓ 存 "()()"
           "(())" (2,2) → 长度 4 == 2n ✓ 存 "(())"
```

执行流程（以最左那条分支为例，注意撤销选择是怎么起作用的）：

```
进入 "" (open=0,close=0)
  open<2 成立 → 加 '(' → cur="(" (1,0)
    进入 "(" (1,0)
      open<2 成立 → 加 '(' → cur="((" (2,0)
        进入 "((" (2,0)
          open<2? 2<2 不成立 → 不加左
          close<open? 0<2 成立 → 加 ')' → cur="(()" (2,1)
            进入 "(()" (2,1)
              open<2 不成立
              close<open? 1<2 成立 → 加 ')' → cur="(())" (2,2)
                进入 "(())"：长度 4==2n → 存 "(())"，return
              撤销：pop_back → cur="(()" (2,1)
            本层两个 if 都试完，return
          撤销：pop_back → cur="((" (2,0)
        本层 return
      撤销：pop_back → cur="(" (1,0)
      close<open? 0<1 成立 → 加 ')' → cur="()" (1,1)
        进入 "()" (1,1) ...（同理最终拼出 "()()"）
      撤销：pop_back → cur="(" (1,0)
    本层 return
  撤销：pop_back → cur="" (0,0)
  close<open? 0<0 不成立 → 不加右
本层 return，结束。答案 = ["(())", "()()"]
```

注意「撤销选择」的作用：第 4 步把 `)` 从 `cur` 拿掉、回到 `"(("`，后面才能继续尝试别的分支。每个 `if` 分支里都是「`push_back` → 递归 → `pop_back`」三件套成对出现，和 46 题完全一样的对称结构。

## 代码

```cpp
class Solution {
public:
    // 回溯主函数，参数含义（重点）：
    //   - ans：存所有合法括号组合的引用，所有递归层共用。
    //     vector<string> 是「字符串动态数组」，最终返回它。
    //   - cur：当前正在拼的字符串的引用。
    //     传引用是为了「做选择/撤销选择」时直接改它，所有层共用同一份，省去反复拷贝。
    //   - open：当前 cur 里已经放了多少个左括号 '('。
    //   - close：当前 cur 里已经放了多少个右括号 ')'。
    //   - n：题目给的对数（左右括号各最多 n 个，串总长 2*n）。
    // open/close 这两个计数器是本题的灵魂——所有剪枝条件都靠它们判断。
    void backtrack(vector<string>& ans, string& cur, int open, int close, int n) {
        // 结束条件：cur 拼满 2*n 个字符 → 收集一个完整合法组合。
        //   - cur.size() 返回 size_t（无符号），n*2 是 int，
        //     这里 n>=1 所以 n*2>=2 不会是负数，和 size_t 比较安全。
        //   - ans.push_back(cur)：把当前 cur 拷一份存进答案。
        //     注意是「拷贝」——后续 pop_back 会改 cur，但已存进去的这份不受影响。
        //   - 能走到这里说明 cur 一定合法（剪枝条件保证的），不用再校验。
        if ((int)cur.size() == n * 2) {
            ans.push_back(cur);
            return;
        }

        // ===== 剪枝条件 1：还能加左括号吗？=====
        // open < n：已经放的左括号还没到 n 个，可以再加一个 '('。
        //   - 为什么这样写：合法串里左括号总数恰好 n 个，open 达到 n 就不能再加，
        //     否则总数会超。这是「总数约束」翻译过来的剪枝。
        //   - 注意是 if 不是 while：这里只判断「能不能加一个」，加完递归下去，
        //     下一层会再次判断。回溯每层只做「一个选择」。
        if (open < n) {
            // 做选择：末尾追加 '('。
            //   - string::push_back(c)：末尾追加一个字符，均摊 O(1)。
            cur.push_back('(');
            // 递归：进入下一层，左括号数 +1（右括号数不变）。
            //   - open + 1 是「值传递」：本层的 open 不变，下一层用的是 open+1。
            //     这样不需要在递归回来后手动恢复 open（只有 cur 需要撤销）。
            backtrack(ans, cur, open + 1, close, n);
            // 撤销选择：把刚加的 '(' 从末尾拿掉。
            //   - string::pop_back()：删末尾一个字符，O(1)。
            //   - 这一句必须和 push_back 严格对称，漏掉 cur 会越拼越长、全错。
            //   - 注意 open 不用撤销（它是值传递，本层的 open 没变过）。
            cur.pop_back();
        }

        // ===== 剪枝条件 2：还能加右括号吗？=====
        // close < open：当前右括号数严格小于左括号数，可以再加一个 ')'。
        //   - 为什么这样写（核心）：合法括号要求「任意前缀里左括号数 ≥ 右括号数」。
        //     现在串里左 open 个、右 close 个，已经满足 open >= close（这是不变式）。
        //     要再加一个 ')'，加完变成 close+1，必须仍满足 open >= close+1，
        //     即 close < open。等号时不加（close==open 时再加就非法了）。
        //   - 举例：cur = "()"（open=1,close=1），此时 close<open? 1<1 不成立，
        //     不能加右——再加就变 "())"，扫到第 3 位右括号比左括号多，非法。
        //   - 这个条件同时保证了：右括号不可能超过左括号，也就不可能超过 n
        //     （因为 open <= n），所以不用单独写 close < n。
        if (close < open) {
            // 做选择：末尾追加 ')'。
            cur.push_back(')');
            // 递归：进入下一层，右括号数 +1。
            backtrack(ans, cur, open, close + 1, n);
            // 撤销选择：拿掉刚加的 ')'。
            cur.pop_back();
        }
    }

    vector<string> generateParenthesis(int n) {
        // result：存答案，初始为空。
        vector<string> result;
        // current：当前正在拼的串，初始为空。
        //   - 先声明为空 string，靠 push_back/pop_back 增减字符。
        string current;
        // 从空串、open=0、close=0 开始回溯。
        //   - 一开始 open=0< n，所以第一步只会加 '('（close<open 即 0<0 不成立，不会先加右），
        //     这也符合直觉——合法串第一个字符必须是 '('。
        backtrack(result, current, 0, 0, n);
        return result;
    }
};
```

## 复杂度

- **时间**：O(4^n / √n)（即第 n 个卡特兰数渐近界的量级）
  - 答案的个数 = 第 n 个卡特兰数 C_n = (1/(n+1)) * C(2n, n)，它被 4^n / (n√n) 渐近界定，习惯写作 O(4^n / √n)。
  - 每收集一个答案还要花 O(n) 把 `cur` 拷进 `ans`，但答案个数已经主导量级。
  - `n <= 8` 时卡特兰数 C_8 = 1430，非常快。
- **空间**：O(n)
  - 不计答案数组 `result`（题目要求返回的空间通常不计入）。
  - 递归调用栈深度等于串最长长度 `2n`，所以是 O(n)；`cur` 字符串长度最多也是 `2n`。两者相加仍 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么加右括号的条件是 `close < open`，而不是 `close < n`？

这是本题最容易写错的地方。直觉上「右括号最多 n 个」会让人想写 `close < n`，但这样**不能保证合法性**。

- `close < n` 只卡住了「总数」，没卡住「任意前缀左≥右」。比如 `n=2`，串拼到 `")"` 时 `close=1 < 2` 成立会通过，但这个串已经非法了（开头就是右括号）。
- `close < open` 才是真正的合法约束：它保证加完这个右括号后，`close+1 ≤ open` 仍然成立，即「到目前为止左括号数仍不少于右括号数」。
- 而且 `close < open` 加上 `open ≤ n` 已经隐含了 `close < n`（因为 close < open ≤ n），所以不用再单独写 `close < n`。

一句话：**左括号看总数（`open < n`），右括号看相对左括号（`close < open`）**。

### Q2：为什么串拼满 `2n` 时不用再校验合法性？

因为剪枝条件在「生成过程中」已经把所有非法分支卡死了。具体来说：

- 每次加 `)` 都查了 `close < open`，所以「任意前缀左≥右」这条不变式从头到尾成立。
- 串长度 `2n = open + close`，而 `open ≤ n`（被 `open < n` 卡）且 `close ≤ open`（被 `close < open` 卡），要满足 `open + close = 2n`，唯一解是 `open = n, close = n`。

所以能走到结束条件的串，**左右各 n 个 + 任意前缀左≥右，天然合法**。这就是「回溯 + 剪枝」比「暴力生成 + 事后校验」高效的根本原因：不浪费任何一次递归在非法分支上。

### Q3：卡特兰数是什么？为什么答案个数是它？

卡特兰数（Catalan number）是一组合计数序列，第 n 项记作 C_n，公式是 `C_n = (1/(n+1)) * C(2n, n)`。前几项：C_0=1, C_1=1, C_2=2, C_3=5, C_4=14, C_5=42, C_8=1430。

n 对括号的合法组合数恰好等于 C_n。一个直观理解：括号组合和「合法进栈出栈序列」「二叉树形态」「不相交弦的连法」等都是同一类问题，它们的计数都是卡特兰数。本题答案个数 = C_n，所以时间复杂度是 O(C_n × n)，渐近为 O(4^n/√n)。不用记推导，记住「括号合法组合数 = 卡特兰数」这个结论即可。

### Q4：能不能用动态规划做？

可以，官方题解「方法三」就是 DP 思想，思路很巧妙（见复盘）。但 DP 在本题**不如回溯直观**，而且写起来更绕（要用 shared_ptr 缓存或者二维 dp 表）。回溯是本题最自然的解法，面试也最常考回溯写法。DP 法作为思路拓展放进复盘，理解它有助于体会「括号串的递归结构」。

## 复盘

### 可迁移套路

- **「回溯 + 剪枝生成合法序列」是一大类问题的通用套路**。本题的精髓在于：**不要等序列生成完了再校验，而是在每一步「能不能做这个选择」时就把约束条件卡上去**，非法分支直接不递归。这样生成的每条路径都天然合法。后续遇到「生成满足某约束的所有序列」都往这个方向想：先想清楚约束是什么、再翻译成每一步的剪枝条件。
- **「选择是有限几个固定动作」时，用多个 `if` 代替 `for`**。46 全排列用 `for` 枚举 `nums`，17 电话号码用 `for` 枚举字母，是因为选择列表是一个集合。本题的选择固定就是「加左 / 加右」两个动作，写成两个 `if` 比套 `for` 更直白。这是回溯模板的常见变体——选择列表形态决定用 `for` 还是多个 `if`。
- **「做选择 → 递归 → 撤销选择」三件套永远成对**。本题每个 `if` 里都是 `push_back → backtrack → pop_back`，和 46 题的 `push_back/used=true → backtrack → pop_back/used=false` 结构完全一样。区别只在于本题 `open/close` 是值传递（不用撤销），只有 `cur` 需要撤销。
- **复杂度基准**：回溯生成合法序列的复杂度 = 「合法解个数 × 每个解的构造代价」。本题合法解个数是卡特兰数 C_n ≈ 4^n/(n√n)，构造代价 O(n)，所以是 O(4^n/√n)。和 46 全排列的 O(n·n!)、78 子集的 O(n·2^n) 是同一类公式。

### 解法二：按括号序列长度递归（官方方法三，DP 思想）

官方题解还给了一个很巧的递归思路。任意一个合法括号组合都可以写成 `(a)b` 的形式，其中 `a` 和 `b` 都是合法括号组合（可以为空）：

- 第一个字符一定是 `(`，和它配对的那个 `)` 把串分成两段：`(` 和 `)` 之间是 `a`、`)` 之后是 `b`。
- `a` 用掉 `i` 对括号、`b` 用掉 `n-1-i` 对括号（`i` 从 0 到 `n-1`）。

所以 `n` 对的答案 = 所有 `"( " + a_i + " )" + b_{n-1-i}` 的拼接，其中 `a_i` 是 `i` 对的答案、`b_{n-1-i}` 是 `n-1-i` 对的答案。这就是卡特兰数的递推关系。加个缓存（memo）避免重复计算就是 DP：

```cpp
class Solution {
    // cache[n] 缓存「n 对括号的所有合法组合」，shared_ptr 共享所有权避免拷贝。
    //   - shared_ptr<vector<string>>：智能指针，指向一个 vector<string>。
    //     多个 cache[n] 引用同一个 vector 时自动管理生命周期（引用计数）。
    //   - 初始化为 nullptr 表示还没算过。
    shared_ptr<vector<string>> cache[100] = {nullptr};
public:
    shared_ptr<vector<string>> generate(int n) {
        if (cache[n] != nullptr)
            return cache[n];                 // 算过了，直接返回（memo）
        if (n == 0) {
            // 0 对括号：只有一个空串。
            cache[0] = shared_ptr<vector<string>>(new vector<string>{""});
        } else {
            auto result = shared_ptr<vector<string>>(new vector<string>);
            // 枚举 a 用掉的对数 i，b 用掉 n-1-i 对。
            for (int i = 0; i != n; ++i) {
                auto lefts = generate(i);            // a 的所有合法组合
                auto rights = generate(n - i - 1);   // b 的所有合法组合
                // 笛卡尔积：每个 a 配每个 b，拼成 "(a)b"。
                for (const string& left : *lefts)
                    for (const string& right : *rights)
                        result->push_back("(" + left + ")" + right);
            }
            cache[n] = result;
        }
        return cache[n];
    }
    vector<string> generateParenthesis(int n) {
        return *generate(n);                  // 解引用 shared_ptr 拿到 vector<string>
    }
};
```

- **时间**：O(4^n / √n)，与回溯同阶（答案个数主导）。
- **空间**：O(4^n / √n)，要缓存所有子问题的答案，比回溯的 O(n) 大得多。
- **对比**：DP 法揭示了括号串的递归结构 `(a)b`，对理解卡特兰数很有帮助；但写起来要用智能指针 + memo，不如回溯直观，空间也更大。**面试和实战首选回溯 + 剪枝**，DP 作为思路拓展了解即可。

### 解法三：暴力生成 + 事后校验（官方方法一，对比用）

最朴素的办法：递归生成所有 `2^(2n)` 个由 `(` 和 `)` 组成的长度为 `2n` 的串，每个串都用一个 `valid` 函数校验合法性（用一个 `balance` 计数器扫一遍：遇 `(` 加 1、遇 `)` 减 1，过程中 `balance < 0` 或最后 `balance != 0` 即非法）。合法的才收进答案。

```cpp
class Solution {
    bool valid(const string& str) {
        int balance = 0;
        for (char c : str) {
            if (c == '(') ++balance;
            else --balance;
            if (balance < 0) return false;    // 右括号比左括号多，非法
        }
        return balance == 0;                  // 最后左右必须相等
    }
    void generate_all(string& current, int n, vector<string>& result) {
        if (n == current.size()) {
            if (valid(current)) result.push_back(current);
            return;
        }
        current += '(';  generate_all(current, n, result);  current.pop_back();
        current += ')';  generate_all(current, n, result);  current.pop_back();
    }
public:
    vector<string> generateParenthesis(int n) {
        vector<string> result;
        string current;
        generate_all(current, n * 2, result);
        return result;
    }
};
```

- **时间**：O(2^(2n) × n)，要生成 `2^(2n)` 个串、每个校验 O(n)。`n=8` 时是 `65536 × 16`，远比回溯慢。
- **空间**：O(n)（递归栈 + current）。
- **对比**：写法最简单直接，但生成了大量非法串再丢弃，效率低。理解了它，才能体会「回溯 + 剪枝」的精妙——**在生成时就卡掉非法分支，根本不浪费递归次数**。这也是从「暴力」优化到「回溯 + 剪枝」的最经典教学例子。
