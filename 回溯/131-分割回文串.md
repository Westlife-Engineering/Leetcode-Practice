# 131 分割回文串

- 难度：中等
- 标签：字符串、动态规划、**回溯**
- 力扣链接：https://leetcode.cn/problems/palindrome-partitioning/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/palindrome-partitioning/solutions/9914/fen-ge-hui-wen-chuan-by-leetcode-solutio-6jkv/)「分割回文串」（slug：`fen-ge-hui-wen-chuan-by-leetcode-solutio-6jkv`）。正文主解是 **回溯 + 动态规划预处理回文表**——先用一张二维表 `f[i][j]` 把「任意子串是不是回文」全部预算好（O(1) 查表），再回溯地枚举「在哪切」，每次切出的前缀必须查表确认是回文才往下递归。这是「分割型回溯」的母题写法；官方题解另一种「回溯 + 记忆化搜索」放在文末「复盘」作对比。本题和 [39 组合总和](./39-组合总和.md)、[46 全排列](./46-全排列.md) 同属回溯变体，是「把回溯套到字符串切割上」的典型。

## 题目描述

给你一个字符串 `s`，请你将 `s` 分割成一些子串，使每个子串都是回文串。返回 `s` 所有可能的分割方案。

**示例 1：**

```
输入：s = "aab"
输出：[["a","a","b"],["aa","b"]]
```

**示例 2：**

```
输入：s = "a"
输出：[["a"]]
```

**提示：**

- `1 <= s.length <= 16`
- `s` 仅由小写英文字母组成

## 思路

> 本题主解参考力扣官方题解「方法一：回溯 + 动态规划预处理」的思路。

### 题目要什么？

把字符串 `s` 切成几段，要求**每一段都是回文串**，问所有切法。注意三点：

1. 切出来的每一段都必须是回文（`"aa"`、`"a"` 算回文，`"ab"` 不算）。
2. 要列出**所有方案**，不是只算方案数。
3. 「分割」是把整个串从头到尾**完整切完**，不能切一半剩下不切。

### 本质：枚举所有「切法」，还是回溯！

这道题乍看和 [46 全排列](./46-全排列.md)、[39 组合总和](./39-组合总和.md) 不一样（那是挑数），但本质都是**在一棵决策树上做 DFS + 选择/撤销选择**。

把「在哪下刀」想成选择：从位置 `start` 开始，**下一刀可以切在 `start`、`start+1`、…、`n-1` 的任意位置**。每切一刀，就把 `[start, i]` 这一段当成一个子串，剩下的 `[i+1, n-1]` 交给下一层继续切。回溯三要素依然是：

1. **路径 `path`**：已经切下来的几段回文串。
2. **选择列表**：下一刀能切在哪（`i` 从 `start` 枚举到 `n-1`）。
3. **结束条件**：`start == n`，整串切完了，收一份答案。

可以直接套回溯模板，但要做**一处关键改造**——

### 关键点：切出来的前缀必须是回文才能继续（合法性剪枝）

不是「切在哪都行」：只有当 `[start, i]` 这段**是回文串**，这次切割才合法，才能把它收进 `path` 往下递归；否则这次切法直接跳过（`continue`）。这就是本题相对 [39 组合总和](./39-组合总和.md) 的唯一区别——**剪枝条件从「数值凑不凑得齐」换成了「子串是不是回文」**。

```
void backtracking(s, start) {
    if (start == s.size()) { 收集 path; return; }       // 整串切完
    for (int i = start; i < s.size(); ++i) {            // 枚举下一刀切在哪
        if (f[start][i]) {                              // ★ [start,i] 是回文才切
            path.push_back(s.substr(start, i-start+1)); //   把这段切下来
            backtracking(s, i + 1);                     //   剩下从 i+1 继续切
            path.pop_back();                            //   撤销
        }
    }
}
```

剩下的问题就是：**怎么快速判断 `[start, i]` 是不是回文？**

### 为什么需要 DP 预处理回文表？

最朴素的做法是每次现写一个 `isPalindrome(s, l, r)` 双指针判断，O(n) 一次。但回溯过程中同一个子串会被反复判断（不同切法会走到同一段），重复算很浪费。

官方主解的做法：**用一张 `f[i][j]` 表把所有子串是不是回文预先算好**，回溯时 O(1) 查表即可。

- `f[i][j]`：bool，表示子串 `s[i..j]`（闭区间）是不是回文串。
- 回溯里判断 `[start, i]` 是否回文，直接 `if (f[start][i])`，O(1)。

### 回文表的转移方程：`f[i][j] = (s[i]==s[j]) && f[i+1][j-1]`

这是动态规划里「区间 DP」最经典的转移，思路：

- 子串 `s[i..j]` 是回文，当且仅当**两端字符相等**（`s[i] == s[j]`）**且** 去掉两端后的内部子串 `s[i+1..j-1]` 也是回文（`f[i+1][j-1]` 为真）。
- 把「大区间 `f[i][j]`」拆成「小区间 `f[i+1][j-1]`」的子问题，从小算到大。

**边界（无需显式处理，靠初值）**：

- 单字符 `f[i][i]`：一个字符当然是回文 → `true`。
- 空串 `f[i][i-1]`（即 `i+1 > j-1` 的退化情况，长度为 2 的子串 `s[i..i+1]` 去掉两端后）：视为回文 → `true`。

最省事的写法是**把整个 `f` 表初始化为全 `true`**，然后只更新长度 ≥ 2 的子串（即 `j > i` 的格子）。这样上述边界自动满足，不用单独判长度。

**循环顺序**（重点）：因为 `f[i][j]` 依赖 `f[i+1][j-1]`（行号更大、列号更小），所以：

- **外层 `i` 从 `n-1` 往下到 `0`**（先算后面的行 `i+1`，再算前面的行 `i`）；
- 内层 `j` 从 `i+1` 到 `n-1`。

这样算 `f[i][j]` 时，它依赖的 `f[i+1][j-1]`（行 `i+1` 已经算完，列 `j-1` 也算过了）一定已经就绪。

> 也可以「按子串长度」递增来算（长度 1 全真，长度 2 看 `s[i]==s[i+1]`，长度 ≥ 3 套转移），效果一样。官方代码用的是「`i` 从后往前」这种写法，更紧凑。

### 手动推导 `s = "aab"` 的全过程

`n = 3`，下标 `0,1,2` 对应字符 `a,a,b`。

**第一步：DP 预处理 `f` 表**（初值全 `true`，只更新 `j > i` 的格子）：

```
i=2: j 从 3 → 越界，不更新
i=1: j=2: f[1][2] = (s[1]==s[2]) && f[2][1] = (a==b) && true = false
i=0: j=1: f[0][1] = (s[0]==s[1]) && f[1][0] = (a==a) && true = true
     j=2: f[0][2] = (s[0]==s[2]) && f[1][1] = (a==b) && true = false
```

最终 `f` 表（对角线 `f[i][i]` 是初值 `true`）：

```
        j=0    j=1    j=2
i=0     T      T      F
i=1     T      T      F        ← f[i][j] 且 i>j 的格子用不到，保持初值 T
i=2     T      T      T
```

读法：`f[0][1]=T` 表示 `"aa"` 是回文；`f[0][2]=F` 表示 `"aab"` 不是回文；`f[1][2]=F` 表示 `"ab"` 不是回文。

**第二步：回溯**（`start` 表示「从哪个下标开始切」，`path` 是已切下来的段）：

```
backtracking(start=0)  path=[]
├─ j=0: f[0][0]=T → push "a", path=["a"] → backtracking(start=1)
│  ├─ j=1: f[1][1]=T → push "a", path=["a","a"] → backtracking(start=2)
│  │  └─ j=2: f[2][2]=T → push "b", path=["a","a","b"] → backtracking(start=3)
│  │        start==3==n → 收 ["a","a","b"] ✓ ; pop "b"
│  │     pop "a"
│  └─ j=2: f[1][2]=F → 跳过（"ab" 非回文，不能切）
│  pop "a"
├─ j=1: f[0][1]=T → push "aa", path=["aa"] → backtracking(start=2)
│  └─ j=2: f[2][2]=T → push "b", path=["aa","b"] → backtracking(start=3)
│        start==3==n → 收 ["aa","b"] ✓ ; pop "b"
│  pop "aa"
└─ j=2: f[0][2]=F → 跳过（"aab" 非回文）

结果：[["a","a","b"],["aa","b"]] ✓ 与示例 1 一致
```

可以看到 `f` 表预算好后，回溯里每次切刀的合法性判断都是 O(1) 查表；非回文的前缀（`"ab"`、`"aab"`）被直接剪掉，整棵树被砍掉一大半分支。

## 代码

```cpp
class Solution {
public:
    // ===== 成员变量：让所有递归层共用同一份，避免反复传参 =====
    //   - f：回文判断表。vector<vector<bool>> 是「二维 bool 动态数组」，
    //     f[i][j]=true 表示闭区间子串 s[i..j] 是回文串。
    //     大小 n×n，O(n^2) 空间。读 f[i][j] 写 f[i][j] 都是 O(1)。
    //   - 注意：这里用 bool（而非官方的 int）是因为我们只关心「是/否」两种状态，
    //     bool 语义更直接、vector<bool> 还更省空间（每位 1 bit）。
    vector<vector<bool>> f;
    //   - ans：存所有合法分割方案。vector<vector<string>> 是「二维动态数组」，
    //     外层每个元素是一个 vector<string>（一种切法切出来的若干段）。
    //     push_back(某个vector)：末尾追加一个方案，均摊 O(方案长度)（要拷贝整个 vector）。
    vector<vector<string>> ans;
    //   - path：当前正在拼的切法。vector<string> 动态数组，元素随「做选择/撤销」增减。
    //     push_back(x)：末尾追加一段，均摊 O(1)；pop_back()：删末尾元素，O(1)。
    //   - 注意：官方代码把这个变量叫 ans，把存答案的叫 ret；为了和
    //     46 全排列/39 组合总和 保持一致、减少混淆，这里统一叫 path / ans。
    vector<string> path;
    //   - n：字符串长度，存成成员避免每层都算 s.size()。
    int n;

    // ===== 回溯主函数 =====
    //   - s：题目给的字符串（const 引用，不拷贝、不改原串）。
    //   - start：本轮「从下标 start 开始切」，即剩下的待切部分是 s[start..n-1]。
    //     ★ 对比 39 组合总和：那里 start 是「候选数下标」，这里 start 是「字符下标」，
    //       语义完全对应——都是「这一层从哪里开始往后选」。
    void backtracking(const string& s, int start) {
        // 结束条件：start 走到 n，说明整串已经从头到尾切完，path 里就是一组完整方案。
        //   - ans.push_back(path)：把当前 path 拷一份存进答案。
        //     注意是「拷贝」——后续撤销选择会改 path，但已存进去的这份不受影响。
        if (start == n) {
            ans.push_back(path);
            return;
        }

        // 本层的选择列表：枚举「下一刀切在 i 处」，即把 s[start..i] 作为下一段。
        //   ★ 「i 从 start 起步」：保证切割只往后走，不回头。这和 39 组合总和 的
        //     for (i=start; ...) 形态一致——分割天然有序，不会产生 [b,aa] vs [aa,b] 的重复。
        for (int i = start; i < n; ++i) {
            // ★★★ 合法性剪枝：只有 s[start..i] 是回文才切，否则直接跳过这个 i。
            //   - f[start][i] 已被 DP 预处理算好，这里 O(1) 查表。
            //   - 这就是「分割型回溯」相对普通组合回溯的关键区别：
            //     每一段切出来都必须满足「是回文」这个合法性约束。
            if (f[start][i]) {
                // ===== 做选择（回溯三步之 1）=====
                // 把 s[start..i] 这一段切下来，加进当前方案。
                //   - s.substr(pos, len)：STL 成员函数，返回从下标 pos 开始、长度 len 的子串
                //     （一个新 string 对象，O(len) 时间和空间）。
                //   - ★ 参数含义：第一个是「起点下标」start，第二个是「子串长度」
                //     i-start+1（不是终点下标！长度 = 终点 - 起点 + 1）。
                //     例如 start=0,i=1 → substr(0, 2) → s[0..1] 两字符 "aa"。
                //   - 踩坑：substr 第二个参数是「长度」不是「终点下标」，写错会越界或拿错串。
                //   - 第二个参数可省略：substr(pos) 表示从 pos 一直取到串末尾。
                path.push_back(s.substr(start, i - start + 1));

                // ===== 递归（回溯三步之 2）=====
                // 剩下从 i+1 开始继续切。注意传 i+1（不是 i）：
                //   每个字符只能被切进一段，不能重复用，所以下一段起点是 i+1。
                //   （对比 39 组合总和「同一元素可重复用」才传 i；本题字符不重复用。）
                backtracking(s, i + 1);

                // ===== 撤销选择（回溯三步之 3，回溯的「回」就在这里）=====
                // 递归回来后，把刚切下来的那段从 path 末尾拿掉，
                // 让同层 for 的下一个 i 能在干净的 path 上继续试别的切法。
                //   - 这一句必须和 push_back 严格对称：push 一次、pop 一次。
                path.pop_back();
            }
        }
    }

    vector<vector<string>> partition(string s) {
        n = s.size();

        // ★★★ DP 预处理回文表 f（回溯开始前一次性算好）★★★
        // 先把整个 f 表初始化为全 true：
        //   - f.assign(n, vector<bool>(n, true))：把 f 重置为 n 行 n 列、每个元素都是 true。
        //     vector<bool>(n, true) 构造一个长度 n、全 true 的 bool 数组；
        //     外层 assign(n, ...) 把 f 变成 n 个这样的数组（即 n×n 全 true）。
        //   - ★ 为什么要全 true？因为长度 ≤ 1 的子串（单字符 f[i][i]、空串 f[i][i-1]）
        //     天然是回文，它们不需要更新、保留初值 true 即可。后面只更新 j > i（长度 ≥ 2）的格子。
        f.assign(n, vector<bool>(n, true));

        // 按转移方程 f[i][j] = (s[i]==s[j]) && f[i+1][j-1] 填表：
        //   ★ 外层 i 从 n-1 往下到 0：因为 f[i][j] 依赖 f[i+1][...]，先算行 i+1 再算行 i。
        //   ★ 内层 j 从 i+1 到 n-1：只更新长度 ≥ 2 的子串（j > i）。
        //   - 算 f[i][j] 时它依赖的 f[i+1][j-1]（行 i+1 已算完、列 j-1 也算过了）一定就绪。
        for (int i = n - 1; i >= 0; --i) {
            for (int j = i + 1; j < n; ++j) {
                // 两端字符相等 && 去掉两端后的内部子串也是回文 → 整段是回文。
                //   - f[i+1][j-1]：对长度 2 的子串（j==i+1）会退化成 f[i+1][i]，
                //     此时 i+1 > i（空串），保持初值 true，所以长度 2 只看 s[i]==s[j]。
                f[i][j] = (s[i] == s[j]) && f[i + 1][j - 1];
            }
        }

        // path / ans 清空（应对同一个 Solution 对象被多次调用；力扣虽每次新建实例，养成清空习惯更稳）。
        path.clear();
        ans.clear();

        // 从下标 0 开始回溯（即「从整串开头开始切」）。
        backtracking(s, 0);
        return ans;
    }
};
```

## 复杂度

- **时间**：O(n · 2ⁿ)，其中 `n = s.length()`。
  - 最坏情况下 `s` 全是相同字符（如 `"aaaa"`），任意切法都合法，长度为 `n` 的字符串共有 `2ⁿ⁻¹ = O(2ⁿ)` 种分割方案（每两个字符之间「切/不切」二选一）。
  - 每种方案需要 O(n) 时间把对应分段拷进答案，所以回溯部分是 O(n · 2ⁿ)。
  - DP 预处理是 O(n²)，在渐进意义下小于 O(n · 2ⁿ)，可以忽略。
  - 本题数据范围 `n ≤ 16`，最坏 `16 × 65536 ≈ 10⁶` 量级，非常快。
- **空间**：O(n²)（不计返回答案占用的空间）。
  - 回文表 `f` 是 `n × n` 的，占 O(n²)。
  - 回溯递归栈最深 O(n)，`path` 也 O(n)，但 O(n) 在渐进意义下小于 O(n²)，所以总体 O(n²)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么要用 DP 预处理回文表？不能每次现写 `isPalindrome` 判断吗？

能，但会慢，且写起来更绕。朴素做法是回溯里每次切刀都调用 `isPalindrome(s, start, i)`（双指针从两端往中间扫），O(n) 一次。

问题在于：**回溯过程中同一个子串会被反复判断**。比如 `s = "aaaa"`，切 `[0,0]+[1,3]` 和切 `[0,1]+[2,3]` 都会用到「后面那段是不是回文」的判断，反复算同一个子串纯属浪费。

DP 预处理用 O(n²) 时间一次性把所有子串的回文性算好，之后回溯里每次判断都是 O(1) 查表。虽然总时间还是 O(n · 2ⁿ)（瓶颈在方案数太多、不在判断），但常数小很多、写起来也清爽——回溯函数里就一句 `if (f[start][i])`。

> 官方题解「方法二」给了一个折中方案：**记忆化搜索**——不预先算全部，而是「用到哪个子串才算哪个，算过的记进 `f` 表下次直接拿」。效果和预处理等价，但代码稍绕，见复盘。

### Q2：转移方程 `f[i][j] = (s[i]==s[j]) && f[i+1][j-1]` 是怎么想出来的？

核心是回文的定义：**正着读和倒着读一样**。把 `s[i..j]` 两端剥掉一层：

- 两端字符 `s[i]` 和 `s[j]` 必须**相等**（否则首尾不同，整个串肯定不是回文）；
- 剥掉两端后剩下的内部 `s[i+1..j-1]` 也必须是回文。

这两条**同时成立**，`s[i..j]` 才是回文。这就是 `(s[i]==s[j]) && f[i+1][j-1]`。

边界靠初值兜底：

- 单字符 `s[i..i]`：长度 1，天然回文 → `f[i][i] = true`（初值给的）。
- 长度 2 的子串 `s[i..i+1]`：转移里 `f[i+1][i]` 是 `i+1 > i`（空串），初值 `true`，所以退化成只看 `s[i]==s[i+1]`，正确。

所以整张表先全填 `true`，再只更新长度 ≥ 2 的格子，边界自动正确。

### Q3：`s.substr(start, i - start + 1)` 两个参数分别是什么意思？写错会怎样？

`string::substr(pos, len)` 是 STL 成员函数，返回一个**新 string**，内容是「从下标 `pos` 开始、长度为 `len`」的子串。

- 第一个参数 `pos`：子串的**起点下标**。这里 `start` 是「这一刀从哪开始切」。
- 第二个参数 `len`：子串的**长度**（不是终点下标！）。闭区间 `[start, i]` 的长度是 `i - start + 1`（终点减起点加一）。

**最常踩的坑**：把第二个参数当成「终点下标」写成 `substr(start, i)`。这样会少取一个字符——比如想切 `s[0..1]`（`"aa"`，长度 2），写成 `substr(0, 1)` 只会拿到 `"a"`。

记住口诀：**substr 第二个参数是「长度」，不是「终点」**。如果只想「从 pos 取到串末尾」，可以省略第二个参数：`s.substr(pos)`。

### Q4：本题和 [39 组合总和](./39-组合总和.md) 有什么区别和联系？

两题代码骨架几乎一模一样（`backtracking` + `for (i=start; ...)` + 做选择→递归→撤销选择），都是「组合型回溯」。区别只在两处：

| 维度 | 39 组合总和 | 131 分割回文串 |
|---|---|---|
| 选什么 | 从 `candidates` 里选**数** | 从 `s` 里切**子串** |
| 递归传给下一层的起点 | 传 `i`（同一元素可重复用） | 传 `i+1`（每个字符只切进一段） |
| 剪枝条件 | `candidates[i] <= target`（数值不超） | `f[start][i]`（切出的子串是回文） |
| 结束条件 | `target == 0` | `start == n`（整串切完） |
| 做选择的内容 | `push_back(一个数)` | `push_back(s.substr(...))`（一段子串） |

一句话总结：**分割型回溯 = 组合型回溯 + 「切点有序、不回头」+ 「切出的段必须满足某种合法性（这里是回文）」**。把 39 的剪枝条件换成「子串合法性」，把 `push_back(数)` 换成 `push_back(子串)`，就是 131。

## 复盘

### 可迁移套路

- **「分割型回溯」= 枚举切点 + 合法性剪枝**。本题是这类问题的母题，套路固定：
  - 用 `start` 表示「这一轮从哪开始切」；
  - `for (i = start; i < n; ++i)` 枚举「下一刀切在哪」；
  - 用一个**合法性谓词**（本题是 `f[start][i]` 回文判断）筛掉不合法的切法；
  - 合法就切下 `s[start..i]`、递归 `start = i+1`、撤销。
- **把昂贵的判断预处理成查表**。本题回文判断从 O(n) 降到 O(1)，靠的就是先用 DP 把所有子串的回文性预算好。这个「**预处理 + 回溯里 O(1) 查**」的思路在很多题里都适用（如 139 单词拆分、140 单词拆分 II 的字典预处理）。
- **区间 DP 的通用转移 `f[i][j] = g(s[i], s[j]) && f[i+1][j-1]`**。回文相关的题（5 最长回文子串、647 回文子串、1216 回文串切割）都是这个转移，记住即可。
- **回溯三要素（路径、选择列表、结束条件）+ 三步（做选择→递归→撤销选择）** 依然是所有回溯题的通用骨架，详见 [46 全排列](./46-全排列.md)。本题只是在「选择列表」上套了字符串切分语义、在「剪枝」上用了回文约束。

### 朴素回溯对比（不预处理，每次现判回文）

不写 DP 预处理，直接在回溯里双指针判断回文也能过（`n ≤ 16` 数据小），但每次判断 O(n)、常数更大。代码更短、不用维护 `f` 表，适合追求极简的场景：

```cpp
class Solution {
public:
    vector<vector<string>> ans;
    vector<string> path;

    // 现场双指针判断 s[l..r] 是否回文，O(n)。
    bool isPalindrome(const string& s, int l, int r) {
        while (l < r) {
            if (s[l++] != s[r--]) return false;
        }
        return true;
    }

    void backtracking(const string& s, int start) {
        if (start == (int)s.size()) { ans.push_back(path); return; }
        for (int i = start; i < (int)s.size(); ++i) {
            if (isPalindrome(s, start, i)) {           // ← 每次现判，O(n)
                path.push_back(s.substr(start, i - start + 1));
                backtracking(s, i + 1);
                path.pop_back();
            }
        }
    }

    vector<vector<string>> partition(string s) {
        ans.clear(); path.clear();
        backtracking(s, 0);
        return ans;
    }
};
```

- **时间**：最坏 O(n · n · 2ⁿ)（每次判断 O(n)，比预处理多一个 n），`n ≤ 16` 仍可过。
- **空间**：O(n)（只有递归栈，没有 `f` 表）。
- **对比**：写法更短、空间更省（O(n) vs O(n²)），但时间常数大、且重复判断同一个子串。`n` 大时（本题虽限 16，但变形题可能更大）会明显慢于 DP 预处理版。**主解的 DP 预处理是更通用、更可迁移的写法**（区间 DP 套路可复用到 5/647/1216 等题）。

### 解法二：回溯 + 记忆化搜索（官方题解代码）

官方题解「方法二」给出一个介于「朴素现判」和「全表预处理」之间的写法：**不预先算全部子串，而是「用到哪个子串才算哪个、算过就记进 `f` 表」**。`f[i][j]` 用 `0` 表示未算过、`1` 是回文、`-1` 不是回文，递归里第一次查到就递归算一次、之后直接拿结果。

效果和主解等价（每个子串最多算一次），区别只是「算的时机」：主解是回溯前一次性全算（自底向上 DP），方法二是回溯里按需算（自顶向下记忆化）。

```cpp
class Solution {
private:
    vector<vector<int>> f;            // 0=未算, 1=回文, -1=非回文
    vector<vector<string>> ret;
    vector<string>> ans;
    int n;

public:
    void dfs(const string& s, int i) {
        if (i == n) { ret.push_back(ans); return; }
        for (int j = i; j < n; ++j) {
            if (isPalindrome(s, i, j) == 1) {        // 查表，0/1/-1
                ans.push_back(s.substr(i, j - i + 1));
                dfs(s, j + 1);
                ans.pop_back();
            }
        }
    }

    // 记忆化搜索：第一次查到就递归算并写回 f[i][j]，之后直接返回记录值。
    int isPalindrome(const string& s, int i, int j) {
        if (f[i][j]) { return f[i][j]; }             // 非 0 表示已算过，直接返回
        if (i >= j) { return f[i][j] = 1; }          // 空串/单字符 → 回文
        return f[i][j] = (s[i] == s[j] ? isPalindrome(s, i + 1, j - 1) : -1);
    }

    vector<vector<string>> partition(string s) {
        n = s.size();
        f.assign(n, vector<int>(n));                 // 全 0（未算）
        dfs(s, 0);
        return ret;
    }
};
```

- **时间**：O(n · 2ⁿ)，与主解相同（每个子串最多算一次 O(n)，共 O(n²) 个子串，但被 O(n · 2ⁿ) 的回溯部分主导）。
- **空间**：O(n²)，与主解相同。
- **对比**：写法更「懒」（用到才算），但引入了 `0/1/-1` 三态编码，理解成本略高。入门建议先掌握主解的「自底向上 DP 预处理」版（`f[i][j] = (s[i]==s[j]) && f[i+1][j-1]` 这个转移最清晰、可迁移性最好）。
