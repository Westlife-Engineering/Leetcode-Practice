# 79 单词搜索

- 难度：中等
- 标签：**深度优先搜索**、数组、字符串、**回溯**、矩阵
- 力扣链接：https://leetcode.cn/problems/word-search/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/word-search/solutions/509715/dan-ci-sou-suo-by-leetcode/)「单词搜索」（slug：`dan-ci-sou-suo-by-leetcode-solution`）。正文主解是 **回溯（DFS + 标记/剪枝）**：双层 for 遍历每个格子作为起点，找到首字母匹配就进入 DFS，逐字符四方向匹配后续字母；访问过的格子用 `visited` 数组标记，回溯时撤销标记。这题是**网格回溯**的经典模板，可以看成 200 岛屿数量（网格 DFS）和 46 全排列（回溯「做选择 → 递归 → 撤销选择」）的结合体——既要用 200 的「四方向 DFS 扫网格」，又要套 46 的「标记 + 回溯撤销」。

## 题目描述

给定一个 `m x n` 二维字符网格 `board` 和一个字符串单词 `word` 。如果 `word` 存在于网格中，返回 `true` ；否则，返回 `false` 。

单词必须按照字母顺序，通过相邻的单元格内的字母构成，其中「相邻」单元格是那些水平相邻或垂直相邻的单元格。**同一个单元格内的字母不允许被重复使用**。

**示例 1：**

```
输入：board = [['A','B','C','E'],['S','F','C','S'],['A','D','E','E']], word = "ABCCED"
输出：true
```

**示例 2：**

```
输入：board = [['A','B','C','E'],['S','F','C','S'],['A','D','E','E']], word = "SEE"
输出：true
```

**示例 3：**

```
输入：board = [['A','B','C','E'],['S','F','C','S'],['A','D','E','E']], word = "ABCB"
输出：false
```

**提示：**

- `m == board.length`
- `n == board[i].length`
- `1 <= m, n <= 6`
- `1 <= word.length <= 15`
- `board` 和 `word` 仅由大小写英文字母组成

**进阶：** 你可以使用搜索剪枝的技术来优化解决方案，使其在 `board` 更大的情况下可以更快解决问题？

> 读题要点：网格元素是**字符**（带引号）；「相邻」是**上下左右四方向**（不含对角线）；最关键的一句是「**同一个单元格内的字母不允许被重复使用**」——这一条直接决定了必须做「访问标记 + 回溯撤销」，因为同一条搜索路径上走过的格子不能再走，但不同分支可以复用格子。

## 思路

> 本题主要参考力扣官方题解「方法一：回溯」。

### 把「找单词」想成「在网格上走路径」

把网格看成一张图，每个格子是一个节点，**上下左右相邻**的格子之间有边。要找单词 `word`，等价于**在图上找一条长度为 `word.length()` 的简单路径**（简单 = 不重复走同一格子），使得路径上第 `k` 步格子的字符恰好是 `word[k]`。

这个「长度固定、不能重复、要逐字符匹配」的特点，决定了它是个**回溯问题**（像 46 全排列），而不是简单的连通分量计数（像 200 岛屿）。

### 核心想法：每个格子都当起点试一遍，DFS 逐字符匹配

算法骨架就两层：

1. **双层 for 遍历每个格子 `(i, j)` 当起点**：
   - 只要 `board[i][j] == word[0]`（首字母匹配），就从这里进入 DFS，去匹配 `word` 的后续字符；
   - 任意一个起点能搜出整个 `word`，就直接返回 `true`；全部起点都搜不出才返回 `false`。
2. **DFS 函数 `check(i, j, k)`**：判断「从 `(i, j)` 出发，能否匹配 `word[k..]`（从第 `k` 个字符开始的后缀）」：
   - **剪枝 1（字符不匹配）**：若 `board[i][j] != word[k]`，立即返回 `false`；
   - **剪枝 2（已到末尾）**：若 `k == word.length() - 1`（且上一步字符已匹配），说明整个单词匹配完，返回 `true`；
   - 否则：**标记 `(i,j)` 已访问** → 向**上下左右四个方向**递归 `check(新坐标, k+1)` → 只要有一个方向返回 `true`，本层就 `true` → **回溯撤销标记**。

### 为什么必须「标记 + 回溯撤销」？

因为「同一个单元格不能重复使用」。在同一条搜索路径里，走过的格子不能再走（否则会 `AB→A→B` 这样原地打转），所以进格子时要**标记成已访问**，挡住回头路。

但**不同分支要能复用格子**：比如从 `(0,0)` 出发搜 `word`，试过「先右再下」失败了，现在要试「先下再右」——这两条路径都用到了 `(0,0)` 之外的某些格子，但它们是**不同路径**，互相不能干扰。所以一条分支走完（不管成功失败）、要回头试别的分支时，必须把它走过的格子**撤销标记**，让别的分支还能走。

这就是回溯的精髓（和 46 全排列的「做选择 → 递归 → 撤销选择」完全同构）：

- **做选择（进格子）**：`visited[i][j] = true`；
- **递归**：四方向 `check`；
- **撤销选择（出格子）**：`visited[i][j] = false`。

### 标记的两种写法

- **用 `visited` 数组**（官方题解的做法）：开一个 `vector<vector<int>> visited(h, vector<int>(w))`，0 表示未访问、1 表示已访问。优点是**不改原数组**；代价是 O(MN) 额外空间。
- **原地改 `board`**（200 岛屿的做法）：进格子时把 `board[i][j]` 改成一个特殊字符（比如 `'\0'` 或 `'#'`），回溯时恢复成 `word[k]`。省掉 `visited` 数组，空间更省，但**会临时改写输入**。两种完全等价，思路一一对应。下文「复盘」给出原地改的写法作对比。

### 手动推导示例 1 的搜索过程

`board = [['A','B','C','E'],['S','F','C','S'],['A','D','E','E']]`，`word = "ABCCED"`，搜 `A→B→C→C→E→D`：

```
A B C E
S F C S
A D E E

主循环从 (0,0) 开始扫：
(0,0)='A' == word[0] 'A' → 进入 check(0,0,0)
  board[0][0]=='A'==word[0]，不是末尾 → 标记 visited[0][0]=1
  四方向找 word[1]='B'：
    右 (0,1)='B'==word[1] → check(0,1,1)
      标记 visited[0][1]=1，找 word[2]='C'：
        下 (1,1)='F'≠'C'；右 (0,2)='C'==word[2] → check(0,2,2)
          标记 visited[0][2]=1，找 word[3]='C'：
            下 (1,2)='C'==word[3] → check(1,2,3)
              标记 visited[1][2]=1，找 word[4]='E'：
                下 (2,2)='E'==word[4] → check(2,2,4)
                  标记 visited[2][2]=1，找 word[5]='D'：
                    下越界；左 (2,1)='D'==word[5] → check(2,1,5)
                      k==word.length()-1 且字符匹配 → 返回 true ✓
                    (一直 true 往上冒)
主循环拿到 true，exist 直接返回 true
```

可以看到「找到首字母 → DFS 四方向逐字符匹配 → 标记/撤销 → 任一分支成功就 true」这套流程，正是网格回溯的标准走法。

### 反例：示例 3 为什么返回 false

`word = "ABCB"`。从 `(0,0)='A'` 出发搜 `A→B→C→B`：`A(0,0)→B(0,1)→C(0,2)` 之后，要找第二个 `B`，四方向里 `(1,2)='C'`、`(0,3)='E'`、`(0,1)` 已访问、`(-1,2)` 越界，没有 `B`。这条分支失败，回溯撤销 `(0,2)` 的标记，换别的方向试……所有分支都搜不出 `ABCB`，最终返回 `false`。原因就是**不能重复用格子**，从 `(0,0)` 出发的那条 `A→B→C` 路径里 `B` 已被用过，回头找不到第二个没被用过的 `B`。

## 代码

```cpp
class Solution {
public:
    // check：判断从 (i,j) 出发，能否匹配 word[k..]（从第 k 个字符开始的后缀）。
    //   参数 board：题目给的字符网格（引用，只读，不修改）。
    //   参数 visited：与 board 等大的标记矩阵，visited[i][j]==1 表示 (i,j) 已在当前路径访问过。
    //   参数 i/j：当前格子行列下标。
    //   参数 s：要匹配的单词（传引用避免拷贝，const 也可）。
    //   参数 k：当前要匹配 word 的第几个字符（从 0 开始）。
    //   返回值：bool，能否从 (i,j) 匹配出 word[k..]。
    bool check(vector<vector<char>>& board, vector<vector<int>>& visited,
               int i, int j, string& s, int k) {
        // ★剪枝 1（字符不匹配）★：当前格子的字符和 word[k] 对不上，立即返回 false。
        //   - 这是「提前退出」的关键，避免无意义地深入，让实际时间远小于理论上界。
        if (board[i][j] != s[k]) {
            return false;
        }
        // ★剪枝 2（已到末尾）★：能走到这里说明 board[i][j]==s[k] 已经匹配上了；
        //   若 k 已经是最后一个字符，说明整个单词都匹配完了，返回 true。
        //   - s.length() 返回 size_t（无符号），和 int 比较时减法注意类型，这里显式写减 1 安全。
        else if (k == (int)s.length() - 1) {
            return true;
        }

        // ===== 做选择（回溯三步之 1）：标记当前格子已访问 =====
        //   - 标记后，四方向递归里就不会再回头踩到 (i,j)，避免同一路径重复用格子。
        visited[i][j] = true;

        // 四方向增量。vector<pair<int,int>>：装 pair<int,int> 的动态数组。
        //   - pair<int,int>：两个 int 的有序对，first=行增量、second=列增量。
        //   - {0,1}/{0,-1}/{1,0}/{-1,0} 分别是 右/左/下/上 四个方向。
        //   - 和 200 岛屿里展开写四次 dfs 等价，这里用循环更紧凑。
        vector<pair<int, int>> directions{{0, 1}, {0, -1}, {1, 0}, {-1, 0}};

        bool result = false;   // 收集四个方向里有没有一个能匹配
        // for (const auto& dir: directions)：范围 for 循环，dir 是对每个 pair 的 const 引用。
        //   - const auto&：不拷贝、不改，最稳的只读遍历写法。
        for (const auto& dir: directions) {
            int newi = i + dir.first, newj = j + dir.second;   // 算出邻居坐标
            // 越界检查 + 未访问检查（两道剪枝合在一起）。
            //   - newi/newj 必须落在 [0,h) × [0,w) 内；
            //   - visited[newi][newj]==0 才允许进入，避免重复用格子。
            if (newi >= 0 && newi < (int)board.size() && newj >= 0 && newj < (int)board[0].size()) {
                if (!visited[newi][newj]) {
                    // ===== 递归（回溯三步之 2）=====：去邻居匹配 word[k+1]。
                    bool flag = check(board, visited, newi, newj, s, k + 1);
                    if (flag) {
                        // 短路优化：任一方向成功就不再试其它方向。
                        //   - 注意这里不能直接 return true，因为下面还要「撤销标记」，
                        //     否则 visited 会被留下「脏的 true」，影响外层其它起点的搜索。
                        result = true;
                        break;
                    }
                }
            }
        }

        // ===== 撤销选择（回溯三步之 3，回溯的「回」就在这里）=====
        //   - 本层不管成功还是失败，离开前都要把 (i,j) 的标记恢复成未访问。
        //   - 为什么？因为外层主循环还会从别的起点搜，那些路径要能复用 (i,j)。
        //     如果不撤销，第一次搜完留下的「已访问」会挡住后续所有用到 (i,j) 的路径，结果出错。
        //   - 这一句和「做选择」那一句 visited[i][j]=true 必须严格对称，少一个都不行。
        visited[i][j] = false;
        return result;
    }

    // exist：题目要求的方法签名。在网格里找 word，找到返回 true，否则 false。
    bool exist(vector<vector<char>>& board, string word) {
        int h = board.size(), w = board[0].size();   // 行数 h、列数 w
        // visited：h×w 的标记矩阵，初始全 0（未访问）。
        //   - vector<vector<int>>(h, vector<int>(w))：外层 h 个元素，每个是长度 w、全 0 的 vector<int>。
        //   - 用 int 而非 bool 也可以（力扣上 vector<int> 更直观），两者都能 AC。
        vector<vector<int>> visited(h, vector<int>(w));
        // ★双层 for 遍历每个格子当起点★：每个 (i,j) 都试着从它开始匹配 word[0]。
        //   - 真正的首字母匹配判断放在 check 里（board[i][j] != s[0] 直接 return false），
        //     所以这里不用先判 board[i][j]==word[0]，直接调即可。
        for (int i = 0; i < h; i++) {
            for (int j = 0; j < w; j++) {
                bool flag = check(board, visited, i, j, word, 0);
                if (flag) {
                    return true;   // 任一起点搜出整个单词，立刻返回 true
                }
            }
        }
        return false;             // 所有起点都搜不出，返回 false
    }
};
```

## 复杂度

- **时间**：O(MN · 3^L)，一个非常宽松的上界。其中 M、N 是网格行列数，L 是 `word` 的长度。
  - 每次 `check(i, j, 0)` 的时间复杂度为 O(3^L)：除了第一步可以走 4 个方向，**之后每一步最多走 3 个方向**（因为上一步刚走过的格子被标记了，走不回去，相当于「不走回头路」）。所以分支因子是 3，深度是 L。
  - 主循环对每个格子都调一次 `check(..., 0)`，共 MN 次，所以是 O(MN · 3^L)。
  - **实际远小于这个上界**：剪枝（字符不匹配立即 return、已访问跳过）会提前终止大量无效分支，真实运行时间小得多。
- **空间**：O(MN)。
  - `visited` 矩阵占 O(MN)。
  - 递归调用栈最大深度为 O(min(L, MN))（路径长度不可能超过格子总数），小于 `visited` 的开销，取较大者仍为 O(MN)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么要「标记已访问」？不标记会怎样？

因为题目规定**同一个单元格的字母不能被重复使用**。不标记的话，DFS 在网格里走就允许回头，会出现 `(0,0)→(0,1)→(0,0)→(0,1)→...` 这样在两个格子之间来回蹦、却假装拼出了长单词的荒谬情况，结果直接错。

标记的作用是**挡住回头路**：当前路径上走过的格子，本路径后续不能再踩。这和 200 岛屿里「沉岛染色」的目的一样——都是标记「已处理」，只不过本题标记是**临时的**（回溯时要撤销），而 200 是**永久的**（沉掉的岛不再恢复）。

### Q2：为什么时间复杂度是 3^L 不是 4^L？

虽然每步有上下左右** 4 个方向**可选，但**除了第一步**，之后每一步都有一个方向是「刚走过来的那个格子」，而它已经被标记为已访问、走不回去。所以从第二步起，每步最多只有 **3 个有效分支**。L 层递归的分支总数就是 4 × 3^(L-1) = O(3^L)。

换句话说，「不走回头路」这个约束直接把分支因子从 4 砍到 3，这是 3^L 的由来。

### Q3：怎么避免「同一分支重复用格子，又允许不同分支复用格子」？

靠**「进格子标记 + 出格子撤销」这对对称操作**：

- 进格子（做选择）：`visited[i][j] = true`——把当前格子挡住，本路径后续走不到；
- 出格子（撤销选择）：`visited[i][j] = false`——回头试别的分支前，把当前格子放出来，让别的分支还能用。

这正是 46 全排列里 `used[i] = true / false` 的网格版本。**做选择和撤销选择必须严格对称、成对出现**，这是所有回溯题的根本，少一句都会错。

### Q4：能不能不用 `visited` 数组，直接原地改 `board`？

可以，完全等价。进格子时把 `board[i][j]` 临时改成一个单词里不可能出现的特殊字符（比如 `'\0'` 或 `'#'`），既起到「标记已访问」的作用（和 `word[k+1]` 比对时必然不等），又不用额外开数组；回溯时再把 `board[i][j]` 恢复成 `word[k]`（注意要恢复成**原来那个字符**，也就是当前层匹配的 `word[k]`）。

好处是省掉 O(MN) 的 `visited` 空间（空间降到 O(L) 递归栈）；代价是**临时改写了输入数组**。如果面试官要求不能改输入，还是用 `visited` 更稳。原地改写法见「复盘」解法二。

### Q5：为什么 `check` 里短路成功后不能直接 `return true`，要先记到 `result` 再返回？

因为**返回前必须执行 `visited[i][j] = false` 这句撤销**。如果直接 `return true`，本层的标记就会留下「脏的 true」，等外层主循环从别的起点搜索时，`(i,j)` 这个格子会被误判成「已访问」而无法使用，可能导致正确答案搜不出来。

正确写法是：发现成功就 `result = true; break;` 跳出循环，**然后照常走到底部的 `visited[i][j] = false` 撤销语句**，再 `return result`。这样保证不管成功失败，撤销动作都不会漏。（这种「先记结果、统一撤销、最后返回」的写法，是回溯里保证撤销对称性的常见套路。）

## 复盘

### 可迁移套路（最重要）

- **「网格回溯 = 网格 DFS + 标记 + 回溯撤销 + 剪枝」是所有「在网格/矩阵上搜路径」问题的通用模板**。记忆口诀：**双层 for 找起点 → DFS 四方向递归 → 进格子做标记、出格子撤标记 → 字符不匹配/越界立即剪枝**。这套能套到一大片题上：
  - **980 不同路径 III**：网格上找满足条件的 Hamilton 路径，本质就是带约束的网格回溯。
  - **1219 黄金矿工路径和**：从固定起点出发挖矿，每个格子只能走一次，回溯求最大收益。
  - **51 N 皇后**：把「四方向」换成「逐列试放 + 检查列/对角线冲突」，仍是「做选择→递归→撤销」。
  - **17 电话号码的字母组合**：把「四方向」换成「当前数字对应的几个字母」，模板一样。

### 和 200 岛屿数量（网格 DFS）的对比（最容易混）

两题骨架很像——都是「双层 for 扫格子 + 四方向 DFS」，但有几个关键区别，对照着记最清楚：

| 维度 | 200 岛屿数量 | 79 单词搜索 |
|---|---|---|
| **目标** | 数连通分量个数 | 判断一条特定路径（单词）是否存在 |
| **DFS 做什么** | 把整座连通块染色（改 `'0'`） | 逐字符匹配 `word`，找一条路径 |
| **标记是否撤销** | **不撤销**（沉掉的岛永久消失） | **必须撤销**（不同分支要复用格子） |
| **是否回溯** | 不是回溯，是普通 DFS（染色是一次性的） | **是回溯**（撤销是核心） |
| **剪枝** | 几乎不用 | 关键（字符不匹配/越界/已访问立即剪） |
| **复杂度** | O(MN) | O(MN · 3^L) |

一句话总结：**200 是「遍历连通块、标记不撤销」，79 是「搜特定路径、标记要撤销」**。判断一道网格题该用哪种，就问自己：「走过的格子要不要还原？」要还原 → 回溯；不要 → 普通 DFS 染色。

### 解法二：原地改 board（省掉 visited 数组）

和主解思路完全一致，只是把「`visited[i][j]=true/false`」换成「把 `board[i][j]` 改成特殊字符再恢复」。进格子时存原字符、改成 `'\0'`，递归四方向后恢复成原字符（就是当前层匹配的 `word[k]`）。

```cpp
class Solution {
public:
    // dfs：原地改 board 当标记，省掉 visited 数组。k 是当前匹配到 word 的第几个字符。
    bool dfs(vector<vector<char>>& board, string& word, int i, int j, int k) {
        // 越界 或 字符不匹配 → 剪枝返回 false。
        //   注意：越界判断要写在 board[i][j] 访问之前，否则可能越界段错误。
        if (i < 0 || i >= (int)board.size() || j < 0 || j >= (int)board[0].size()
            || board[i][j] != word[k]) {
            return false;
        }
        // 能走到这里说明 board[i][j]==word[k] 已匹配；若已是最后一个字符，成功。
        if (k == (int)word.length() - 1) {
            return true;
        }
        // ===== 做选择：临时把当前格改成 '\0'，既标记已访问，又保证后续比对必然不匹配 =====
        //   - '\0' 是 C 字符串结尾符，大小写英文字母里不可能出现，是安全的哨兵值。
        //   - 也可以用 '#'、' ' 等任意「单词里不会出现的字符」。
        char tmp = board[i][j];
        board[i][j] = '\0';
        // 四方向递归匹配 word[k+1]，短路或：任一成功即 true。
        //   - || 是短路求值，前面 true 就不评估后面，省时间。
        bool result = dfs(board, word, i - 1, j, k + 1)
                   || dfs(board, word, i + 1, j, k + 1)
                   || dfs(board, word, i, j - 1, k + 1)
                   || dfs(board, word, i, j + 1, k + 1);
        // ===== 撤销选择：恢复成原来的字符（就是本层匹配的 word[k]，等于 tmp）=====
        //   - 这一句必须执行，不能漏；好在上面 || 短路不影响这里（result 已算完）。
        board[i][j] = tmp;
        return result;
    }

    bool exist(vector<vector<char>>& board, string word) {
        int h = board.size(), w = board[0].size();
        // 双层 for 找起点，首字母匹配判断已并入 dfs 第一行的字符比对里。
        for (int i = 0; i < h; i++) {
            for (int j = 0; j < w; j++) {
                if (dfs(board, word, i, j, 0)) {
                    return true;
                }
            }
        }
        return false;
    }
};
```

- **时间**：O(MN · 3^L)，与主解相同（决策树形态一样）。
- **空间**：O(L)，只有递归栈（深度最长 L），省掉了 `visited` 的 O(MN)。
- **对比**：写法更紧凑（越界和字符判断合并成一行、四方向直接用 `||` 短路）、空间更省，是力扣社区最常见的 AC 写法；主解（官方代码）用 `visited` 更直观、不改输入，适合讲解。两种都应掌握，面试时按需选择。
