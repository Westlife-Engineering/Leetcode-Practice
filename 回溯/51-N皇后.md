# 51 N 皇后

- 难度：困难
- 标签：数组、**回溯**
- 力扣链接：https://leetcode.cn/problems/n-queens/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/n-queens/solutions/397821/nhuang-hou-by-leetcode-solution/)「N 皇后」（slug：`nhuang-hou-by-leetcode-solution`）。正文主解是 **回溯（基于集合的冲突检测）**：逐行放皇后，每行枚举放在哪一列，用 `columns`/`diagonals1`/`diagonals2` 三个集合分别记录「已占用的列」「已占用的主对角线」「已占用的副对角线」来快速判冲突。这是回溯组最难、也是最经典的一道题——它把 46 全排列那套「做选择 → 递归 → 撤销选择」的模板升级成了「在多个维度的约束下搜索解」，是回溯思想的巅峰代表。官方题解还给了「方法二：基于位运算的回溯」（用三个整数代替三个集合，常数更优），放在文末「复盘」作对比。

## 题目描述

按照国际象棋的规则，皇后可以攻击与之处在**同一行或同一列或同一斜线**上的棋子。

**n 皇后问题** 研究的是如何将 `n` 个皇后放置在 `n×n` 的棋盘上，并且使皇后彼此之间不能相互攻击。

给你一个整数 `n` ，返回所有不同的 **n 皇后问题** 的解决方案。

每一种解法包含一个不同的 n 皇后问题 的棋子放置方案，该方案中 `'Q'` 和 `'.'` 分别代表了皇后和空位。

**示例 1：**

```
输入：n = 4
输出：[[".Q..","...Q","Q...","..Q."],["..Q.","Q...","...Q",".Q.."]]
解释：如上图所示，4 皇后问题存在两个不同的解法。
```

**示例 2：**

```
输入：n = 1
输出：[["Q"]]
```

**提示：**

- `1 <= n <= 9`

## 思路

> 本题主要参考力扣官方题解「方法一：基于集合的回溯」的思路。皇后规则是「同行、同列、同斜线都不能有两个皇后」，本题的关键在于把这三条约束翻译成「放皇后时能 O(1) 判冲突」的机制。

### n 皇后到底在求什么？

要在 `n×n` 的棋盘上放 `n` 个皇后、彼此互不攻击。因为**同一行不能有两个皇后**，而一共只有 `n` 行、要放 `n` 个皇后，所以**每一行恰好放一个**。于是问题立刻简化成：

> 给每一行挑一个列号 `queens[row]`（范围 `0 ~ n-1`），使得任意两行的皇后不共列、不共斜线。

`queens[row] = c` 表示「第 `row` 行的皇后放在第 `c` 列」。一个合法解就是一个长度为 `n` 的「行→列」映射。这就是回溯要枚举的解空间。

### 冲突检测的三个维度：列、主对角线、副对角线

「同行」已经被「逐行放、每行一个」自动避免了，所以剩下的约束只有三类。**这三个维度是本题的灵魂**，务必想透：

| 维度 | 判断方法 | 用什么集合记录 |
|---|---|---|
| **同列** | 两个皇后在第 `c` 列 → 冲突 | `columns`：已占用的**列号** `c` |
| **同主对角线**（左上↘右下） | 同一条线上 `row - col` 相等 | `diagonals1`：已占用的 `row - col` |
| **同副对角线**（右上↙左下） | 同一条线上 `row + col` 相等 | `diagonals2`：已占用的 `row + col` |

前两行最关键。为什么同一条对角线可以用 `row-col` 或 `row+col` 来标识？

**主对角线（左上到右下）**：在这条斜线上，每往下一行 `row` 加 1、同时往右一列 `col` 也加 1，所以 `row - col` **全程不变**。例如 `(0,0)`、`(1,1)`、`(3,3)` 都在主对角线上，它们的 `row-col` 都是 `0`。再看 `(0,1)`、`(1,2)`、`(2,3)`，`row-col` 都是 `-1`，也是同一条主对角线。**`row-col` 相同 = 在同一条主对角线上**。

**副对角线（右上到左下）**：每往下一行 `row` 加 1、同时往左一列 `col` 减 1，所以 `row + col` **全程不变**。例如 `(3,0)`、`(2,1)`、`(1,2)`、`(0,3)`，`row+col` 都是 `3`，是同一条副对角线。**`row+col` 相同 = 在同一条副对角线上**。

于是判一个位置 `(row, col)` 能不能放皇后，只需查三个集合里**有没有** `col`、`row-col`、`row+col` 这三个 key：都没有就能放，任一已存在就冲突。

> 小贴士：`row-col` 可能是负数（如 `row=0,col=3` 时是 `-3`），但 `unordered_set<int>` 完全支持负数 key，不用做 `+n-1` 这种偏移处理。这是集合写法相对「数组下标」写法省心的地方。

### 回溯三要素（套 46 全排列那套模板）

1. **路径（`queens`）**：长度为 `n` 的数组，`queens[row]` 表示第 `row` 行的皇后放在哪列。还没放的位置暂时填 `-1`。
2. **选择列表**：对当前 `row` 行，枚举 `col` 从 `0` 到 `n-1`，用三个集合过滤掉冲突的列。
3. **结束条件**：`row == n`，即 `n` 行都放完了，把 `queens` 转成棋盘字符串存进答案。

代码骨架和 46 全排列**几乎一模一样**，只是「能不能选」的判断从「`used[i]` 标记」升级成了「查三个集合」。核心依然是「做选择（放皇后 + 三个集合 `insert`）→ 递归下一行 → 撤销选择（三个集合 `erase`）」三件套成对出现。

### 怎么把 `queens` 数组转成题目要的输出格式？

题目要求返回 `vector<vector<string>>`，每个解是一张 `n×n` 棋盘，每行一个字符串：皇后位置是 `'Q'`、其余是 `'.'`。给定 `queens`（`queens[i]` 是第 `i` 行皇后的列号），逐行构造：每行先造一个 `string(n, '.')`（即 `n` 个点），再把第 `queens[i]` 位改成 `'Q'`，拼起来就是一张棋盘。这是 `generateBoard` 函数做的事。

### 手动推导 `n = 4` 的一种解

4 皇后有 2 个解：`[".Q..","...Q","Q...","..Q."]` 和 `["..Q.","Q...","...Q",".Q.."]`。看第一种，`queens = [1,3,0,2]`（第 0 行放第 1 列、第 1 行放第 3 列……）：

```
行0 列1:  . Q . .
行1 列3:  . . . Q
行2 列0:  Q . . .
行3 列2:  . . Q .
```

逐行回溯是怎么找到 `queens[0]=1` 的？以 `row=0` 这层为例（一开始三个集合都空）：

```
进入 row=0（集合全空），枚举 col:
  col=0：列0空、diag1=0-0=0空、diag2=0+0=0空 → 可放 → 放 queens[0]=0，三个集合 insert {0,0,0}
    进入 row=1，枚举 col:
      col=0: 列0已占 → 跳
      col=1: diag1=1-1=0 已占 → 跳
      col=2: 列2空、diag1=1-2=-1空、diag2=1+2=3空 → 可放 → 放 queens[1]=2，insert {列2, -1, 3}
        进入 row=2，枚举 col:
          col=0: 列0已占 → 跳
          col=1: diag1=2-1=1空、diag2=2+1=3 已占 → 跳
          col=2: 列2已占 → 跳
          col=3: 列3空、diag1=2-3=-1 已占 → 跳
        四列全冲突 → 本层 for 走完，直接返回（没收集到解），说明 queens[1]=2 这步走死了
        回溯 row=1：撤销 col=2 → erase {列2, -1, 3}
      col=3: 列3空、diag1=1-3=-2空、diag2=1+3=4空 → 可放 → 放 queens[1]=3 ...
        （后续继续探索 row=2，此处省略；这条 col=0 的总分支最终走不出 4 行合法解）
    回溯 row=0：撤销 col=0 → erase {列0,0,0}
  col=1：列1空、diag1=0-1=-1空、diag2=0+1=1空 → 可放 → 放 queens[0]=1，三个集合 insert {列1,-1,1}
    进入 row=1，枚举 col:
      col=0: 列0空、diag1=1-0=1空、diag2=1+0=1 已占 → 跳
      col=1: 列1已占 → 跳
      col=2: 列2空、diag1=1-2=-1 已占 → 跳
      col=3: 列3空、diag1=1-3=-2空、diag2=1+3=4空 → 可放 → 放 queens[1]=3
        进入 row=2 ... 最终找到 queens=[1,3,0,2] 的合法解 ✓
```

注意「撤销选择」的关键作用：`col=0` 这条分支走死后，回溯时必须把 `{列0,0,0}` 全 `erase` 掉，`col=1` 这条分支才能在干净的集合状态上继续判断。集合里的记录和 `queens` 数组一样，必须**做选择和撤销选择严格对称**——`insert` 了什么就 `erase` 什么。

## 代码

```cpp
class Solution {
public:
    vector<vector<string>> solveNQueens(int n) {
        // solutions：存所有合法棋盘方案。vector<vector<string>> 是「字符串二维动态数组」，
        //   外层每个元素是一张棋盘（vector<string>，共 n 个字符串），最终返回它。
        auto solutions = vector<vector<string>>();
        // queens：长度 n 的「行→列」映射，queens[row]=c 表示第 row 行的皇后放在第 c 列。
        //   vector<int>(n, -1)：构造 n 个初值为 -1 的 int（-1 表示该行还没放皇后）。
        //   所有递归层共用这一份数组，靠赋值 c / 赋回 -1 来「做选择 / 撤销选择」。
        auto queens = vector<int>(n, -1);
        // columns：记录「已被占用的列号」。unordered_set<int> 是「int 的哈希集合」，
        //   - insert(x)：插入元素 x，均摊 O(1)；重复插入无效果。
        //   - erase(x)：删除元素 x，均摊 O(1)。
        //   - find(x)：返回指向 x 的迭代器，找不到返回 end()；用 `find(x) != end()` 判断「是否存在」，O(1)。
        //   - 与 set<int>（红黑树，O(log n)）相比，unordered_set 哈希实现 O(1) 更快，且本题 key 范围小无哈希冲突顾虑。
        auto columns = unordered_set<int>();
        // diagonals1：记录「已被占用的主对角线（左上↘右下）」，用 row-col 作为 key。
        //   同一条主对角线上 row-col 恒相等，所以把「放皇后时的 row-col」存进集合，
        //   之后只要某位置算出的 row-col 已在集合里，就说明和它共主对角线，冲突。
        auto diagonals1 = unordered_set<int>();
        // diagonals2：记录「已被占用的副对角线（右上↙左下）」，用 row+col 作为 key。
        //   同一条副对角线上 row+col 恒相等。key 可能是负数（diagonals1 的 row-col），
        //   unordered_set<int> 支持负数 key，无需偏移。
        auto diagonals2 = unordered_set<int>();
        backtrack(solutions, queens, n, 0, columns, diagonals1, diagonals2);
        return solutions;
    }

    // 回溯主函数，参数含义：
    //   - solutions：答案数组引用，所有层共用。
    //   - queens：当前各行皇后所在的列，引用，做选择/撤销时直接改。
    //   - n：棋盘边长（共 n 行 n 列）。
    //   - row：当前正在放第几行（0 到 n）。递归每深入一层 row+1，递归深度最多 n。
    //   - columns/diagonals1/diagonals2：三个冲突检测集合的引用，随做选择/撤销而增减。
    void backtrack(vector<vector<string>> &solutions, vector<int> &queens, int n, int row,
                   unordered_set<int> &columns, unordered_set<int> &diagonals1, unordered_set<int> &diagonals2) {
        // 结束条件：row == n 说明 n 行都放好了皇后，得到一个合法解。
        //   把 queens（行→列映射）转成题目要的棋盘字符串，存进答案。
        if (row == n) {
            vector<string> board = generateBoard(queens, n);
            solutions.push_back(board);   // 拷贝一份棋盘存进答案，后续撤销选择不会影响已存进去的这份
        } else {
            // 本层选择列表：枚举当前 row 行的皇后放在哪一列 col（0 ~ n-1）。
            for (int i = 0; i < n; i++) {
                // ===== 冲突检测 1/3：同列 =====
                // columns.find(i) != columns.end() 表示第 i 列已经有皇后了。
                //   find 返回迭代器：找到返回指向 i 的迭代器（不等于 end()），找不到返回 end()。
                //   这种写法比 count(i) 也直观，两者在 unordered_set 上都是 O(1)。
                if (columns.find(i) != columns.end()) {
                    continue;             // 列冲突，跳过这个位置
                }
                // ===== 冲突检测 2/3：同主对角线 =====
                // diagonal1 = row - i 标识「当前位置所在的主对角线」。
                //   同一条主对角线上 row-col（这里是 row-i）相等，已在集合里就说明冲突。
                int diagonal1 = row - i;
                if (diagonals1.find(diagonal1) != diagonals1.end()) {
                    continue;
                }
                // ===== 冲突检测 3/3：同副对角线 =====
                // diagonal2 = row + i 标识「当前位置所在的副对角线」。
                //   同一条副对角线上 row+col（这里是 row+i）相等。
                int diagonal2 = row + i;
                if (diagonals2.find(diagonal2) != diagonals2.end()) {
                    continue;
                }
                // 三类冲突都通过 → 当前位置 (row, i) 可放皇后。

                // ===== 做选择（回溯三步之 1）=====
                // 1) 在 queens 数组记下「第 row 行皇后放在第 i 列」。
                queens[row] = i;
                // 2) 把当前列、主对角线、副对角线登记为「已占用」。
                //    insert 均摊 O(1)；三个集合共同保证后续行不会和本行冲突。
                columns.insert(i);
                diagonals1.insert(diagonal1);
                diagonals2.insert(diagonal2);

                // ===== 递归（回溯三步之 2）=====
                // 进入下一行，去放第 row+1 行的皇后。
                //   三个集合是引用，刚才 insert 的内容对下一层可见，下一层的冲突检测就在此基础上进行。
                backtrack(solutions, queens, n, row + 1, columns, diagonals1, diagonals2);

                // ===== 撤销选择（回溯三步之 3，回溯的「回」就在这里）=====
                // 递归回来后，把刚才做的选择原样撤掉，让同层后续循环（别的 col）在干净的集合状态上判断。
                //   - queens[row] 赋回 -1：表示这一行重新变回「没放皇后」。
                //   - 三个集合 erase 掉刚才 insert 的 key，撤销「占用登记」。
                // 这几句必须和「做选择」那几句严格对称，少一句或 erese 错 key 都会全错。
                queens[row] = -1;
                columns.erase(i);
                diagonals1.erase(diagonal1);
                diagonals2.erase(diagonal2);
            }
        }
    }

    // 把 queens（行→列映射）转成题目要求的棋盘字符串数组。
    //   返回 vector<string>：n 个字符串，每个长度 n，皇后位是 'Q' 其余是 '.'。
    vector<string> generateBoard(vector<int> &queens, int n) {
        auto board = vector<string>();
        for (int i = 0; i < n; i++) {
            // string(n, '.')：构造一个长度 n、全是 '.' 的字符串。
            //   这是 string 的「填充构造」签名 string(size_t count, char ch)，O(n)。
            string row = string(n, '.');
            // 把第 i 行的 queens[i] 位改成 'Q'（其余位保持 '.')。
            row[queens[i]] = 'Q';
            // push_back：把这一行字符串拷一份追加进棋盘，均摊 O(n)（拷贝长度 n 的串）。
            board.push_back(row);
        }
        return board;
    }
};
```

## 复杂度

- **时间**：O(N!)
  - 回溯的决策树形态：第 0 行最多 N 种选法、第 1 行最多 N-1 种（被列约束砍掉一列）、第 2 行更少……加上对角线约束还会进一步剪枝。最坏情况下叶子数上界是 N!，所以整体时间复杂度是 O(N!)。
  - 每个合法解还要花 O(N²) 把棋盘字符串构造出来（N 行、每行长度 N），但 N! 已经主导量级。
  - `n <= 9` 时 9! = 362880，实际被对角线约束大幅剪枝后远小于此，运行很快。
- **空间**：O(N)
  - 不计答案数组 `solutions`（题目要求返回的空间通常不计入）。
  - 递归调用栈深度最多 N，`queens` 数组长度 N，三个集合每个元素个数都不超过 N。总和仍是 O(N)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么主对角线用 `row-col`、副对角线用 `row+col` 来标识？

这是最常被卡住的一点。直觉上「斜线」怎么用单个数字表示？答案是利用「同一条斜线上行号列号的固定关系」：

- **主对角线**（左上到右下，方向 ↘）：沿着它走，每往下 1 行就同时往右 1 列，`row` 和 `col` **同步增加**，所以 `row - col` **不变**。例如 `(0,0)→(1,1)→(2,2)`，差都是 `0`；`(0,1)→(1,2)→(2,3)`，差都是 `-1`。每条主对角线都有自己的「差值」，所以 `row-col` 就是这条主对角线的唯一编号。
- **副对角线**（右上到左下，方向 ↙）：沿着它走，每往下 1 行就同时往左 1 列（`col` 减 1），`row` 增加 `col` 减少，所以 `row + col` **不变**。例如 `(3,0)→(2,1)→(1,2)→(0,3)`，和都是 `3`。`row+col` 就是这条副对角线的唯一编号。

记住口诀：**「差同主对角，和同副对角」**。把这两个数当成 key 存进集合，就能 O(1) 判断「当前位置所在斜线有没有被占」。这是 N 皇后类问题的通用技巧，做 52 题（N 皇后 II，只数解的个数）、37 题（解数独）也会用到类似「把约束映射成可 O(1) 查询的 key」的思想。

### Q2：为什么要「逐行放」、每行恰好一个？能不能像全排列那样随便放？

因为题目要求放 `n` 个皇后、棋盘只有 `n` 行、且同一行不能有两个皇后。**每行恰好放一个**是「不攻击 + 数量恰好」共同决定的必然结果，不是随便选的策略。

这样做的好处是把「同行冲突」这一维**直接消除**——根本不需要检查它。剩下只需处理「同列、同主对角线、同副对角线」三类冲突。如果不逐行放，就得额外维护「同一行里有没有多个皇后」的检测，徒增复杂度。所以「逐行回溯、每行枚举列」是 N 皇后的标准建模方式，几乎所有解法都这么写。

### Q3：`unordered_set` 的 `insert` / `erase` / `find` 复杂度都是多少？为什么用它而不用数组？

`unordered_set<int>` 是基于哈希表实现的集合，三个核心操作：

- `insert(x)`：均摊 O(1)（最坏哈希冲突时 O(n)，但本题 key 是 `-2n ~ 2n` 范围内的小整数，无冲突顾虑）。
- `erase(x)`：均摊 O(1)。
- `find(x)`：均摊 O(1)，返回迭代器；判断存在用 `find(x) != end()` 或 `count(x) != 0`（`count` 对 set 只返回 0 或 1）。

对比 `set<int>`（红黑树，O(log n)）——本题 `n <= 9`，性能差异微乎其微，但 `unordered_set` 概念上更贴「O(1) 查冲突」。

为什么不用「数组下标」记录？其实可以：`row-col` 范围 `-(n-1) ~ n-1`，加个 `n-1` 偏移就能映射到 `0 ~ 2n-2` 的数组下标；`row+col` 范围 `0 ~ 2n-2` 天然就是下标。用 `vector<bool>` 数组代替集合，查询/插入/删除都是严格 O(1)，常数更小。但要多算一个偏移、代码稍繁，**集合写法更直白、不用关心偏移和负数**，作为主解最易理解。数组优化版放「复盘」。

### Q4：`queens[row] = -1` 这一步在「撤销选择」时真的有必要吗？

有必要但作用是「保持语义清晰」，不是「防止 bug」。`queens` 数组是「行→列」映射，`-1` 表示「这行还没放」。放皇后时 `queens[row] = i`，撤销时改回 `-1`，语义对称。

实际中，下一层只读 `queens[0..row-1]`（已经放过皇后的行），不会读 `queens[row]`；而当前行 `row` 在下次循环又会被新的 `i` 覆盖。所以理论上不写 `queens[row] = -1` 也能 AC。但**强烈建议保留**：万一以后改动代码（比如 `generateBoard` 在中途调用、或打印调试），残留的旧值会误导。和 46 全排列里 `used[i] = false` 同理——撤销选择要严格对称，是回溯代码的好习惯。

## 复盘

### 可迁移套路

- **「回溯 + 约束集合」是带约束搜索类问题的通用模板**。本题把 46 全排列的 `used` 标记数组，升级成了「三个集合分别记录列、主对角线、副对角线三类约束」。核心思想是：**把「能不能做这个选择」的判断，预先建模成若干个可 O(1) 查询的集合/标记**，每次做选择时查、做完登记、回溯时撤销。后续遇到「带多维约束的回溯」都往这个方向想：先列清约束有几类、再把每类约束用一个集合或数组表达。
- **「把约束映射成可 O(1) 查询的 key」是通用优化思想**。`row-col`、`row+col` 把「斜线冲突」这种看似连续的几何约束，映射成了离散的整数 key，从而能用哈希集合 O(1) 查。这种「连续/几何问题离散化成 key」的技巧在很多题里出现（如 1 两数之和的 `target - num`、49 字母异位词的排序后字符串作 key）。
- **「做选择 → 递归 → 撤销选择」三件套永远成对**。本题做选择是 `queens[row]=i` + 三个集合 `insert`，撤销是 `queens[row]=-1` + 三个集合 `erase`，和 46/22 题完全同构。回溯组的题到这一道已经是收尾，这套模板应当背得滚瓜烂熟。
- **复杂度基准**：N 皇后是 O(N!)，和 46 全排列同阶但被对角线约束大幅剪枝；空间 O(N)（递归栈 + 约束集合，不计答案数组）。

### 解法二：基于位运算的回溯（官方方法二，常数更优）

当 `n` 很小（`n <= 9`，一个 int 的位就够用）时，可以用「三个整数」代替三个集合——每一位代表一列。这样查冲突、取可用位置、放皇后都靠位运算完成，常数更小、代码更紧凑。思路：

- `columns`、`diagonals1`、`diagonals2` 都是 int，第 `c` 位为 1 表示「该列 / 主对角线 / 副对角线被占用」。
- `(columns | diagonals1 | diagonals2)` 的「0 位」就是当前可放的位置；`((1 << n) - 1) & ~(三者或)` 取出本层「所有可用列」的位掩码 `availablePositions`。
- 用 `position = availablePositions & (-availablePositions)` 取出「最右边的 1」（一个可放位置），用 `__builtin_ctz(position)` 算出它是第几列。
- 递归到下一行时：`columns | position`（占用这一列）；主对角线整体右移 1 位 `(diagonals1 | position) >> 1`（因为下一行同一主对角线的列号要 -1）；副对角线整体左移 1 位 `(diagonals2 | position) << 1`（下一行同一副对角线的列号要 +1）。这个移位正好对应 `row-col` / `row+col` 的「平移」。

```cpp
class Solution {
public:
    vector<vector<string>> solveNQueens(int n) {
        auto solutions = vector<vector<string>>();
        auto queens = vector<int>(n, -1);
        solve(solutions, queens, n, 0, 0, 0, 0);
        return solutions;
    }

    // columns/diagonals1/diagonals2 是三个位掩码：第 c 位为 1 表示第 c 列 / 主对角线 / 副对角线已占用。
    void solve(vector<vector<string>> &solutions, vector<int> &queens, int n, int row,
               int columns, int diagonals1, int diagonals2) {
        if (row == n) {
            auto board = generateBoard(queens, n);
            solutions.push_back(board);
        } else {
            // ((1 << n) - 1)：低 n 位全 1 的掩码（合法列范围）。
            // ~(columns | diagonals1 | diagonals2)：三者都没占用的位为 1。
            // 两者按位与：本行「可放皇后」的所有位置。
            int availablePositions = ((1 << n) - 1) & (~(columns | diagonals1 | diagonals2));
            while (availablePositions != 0) {
                // position = 最右边的那个 1（一个可放位置）。
                int position = availablePositions & (-availablePositions);
                // 清掉这个 1，准备下次循环取下一个可放位置。
                availablePositions = availablePositions & (availablePositions - 1);
                // __builtin_ctz(position)：返回 position 二进制末尾 0 的个数，即「1 在第几位」= 列号。
                int column = __builtin_ctz(position);
                queens[row] = column;
                // 递归：占用该列；主对角线右移 1（下一行同主对角线列号 -1）；副对角线左移 1（列号 +1）。
                solve(solutions, queens, n, row + 1, columns | position,
                      (diagonals1 | position) >> 1, (diagonals2 | position) << 1);
                queens[row] = -1;   // 注意：位掩码是「值传递」，递归回来天然撤销，不用手动清
            }
        }
    }

    vector<string> generateBoard(vector<int> &queens, int n) {
        auto board = vector<string>();
        for (int i = 0; i < n; i++) {
            string row = string(n, '.');
            row[queens[i]] = 'Q';
            board.push_back(row);
        }
        return board;
    }
};
```

- **时间**：O(N!)，与主解相同（决策树形态一致，只是常数更小）。
- **空间**：O(N)，递归栈深度 N；位掩码是 int（O(1)），比集合版常数更优。
- **对比**：位运算是 N 皇后的「终极优化」版，跑得最快、最优雅，但门槛高（要理解 `x & (-x)` 取最右 1、`__builtin_ctz`、移位表示对角线平移等技巧）。**入门和面试首选主解的「集合版」**——思路最直白、最容易写对；位运算版作为思路拓展，理解它有助于体会「同样的约束可以用位来紧凑编码」。

### 其他可选优化：用数组代替集合（折中版）

把三个 `unordered_set<int>` 换成三个 `vector<bool>` 或 `int[]` 数组：`columns` 长度 `n`（下标就是列号）；`diagonals1` 长度 `2n-1`（下标是 `row-col+(n-1)`，把负数偏移到非负）；`diagonals2` 长度 `2n-1`（下标是 `row+col`）。查询/赋值都是严格 O(1)，比 `unordered_set` 均摊 O(1) 常数更小，且不依赖哈希。代码相比集合版要多算 `row-col+(n-1)` 偏移，可读性略降，是集合版和位运算版之间的折中选择。
