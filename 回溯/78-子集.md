# 78 子集

- 难度：中等
- 标签：位运算、数组、**回溯**
- 力扣链接：https://leetcode.cn/problems/subsets/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/subsets/solution/)「子集」（slug：`zi-ji-by-leetcode-solution`）。正文主解是 **回溯法（用 `start` 索引 + `path` 路径，每个节点都收集结果）**，这是和 46 题全排列**同一个回溯框架的变体**——区别在于「子集问题每个节点都收集、用 `start` 保证只往后选避免重复」。官方题解的「选/不选」二叉递归写法本质同构，迭代法和位运算法放在文末「复盘」作对比。

## 题目描述

给你一个整数数组 `nums` ，数组中的元素 **互不相同** 。返回该数组所有可能的子集（幂集）。

解集 **不能** 包含重复的子集。你可以按 **任意顺序** 返回解集。

**示例 1：**

```
输入：nums = [1,2,3]
输出：[[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]
```

**示例 2：**

```
输入：nums = [0]
输出：[[],[0]]
```

**提示：**

- `1 <= nums.length <= 10`
- `-10 <= nums[i] <= 10`
- `nums` 中的所有元素 **互不相同**

## 思路

> 本题主要参考力扣官方题解「方法二：递归法实现子集枚举」的思路。官方描述了两种回溯视角：对每个元素「选/不选」（二叉决策树）、以及在每一步「枚举下一个选谁」（`for` + `start`）。两者等价、都能生成 $2^n$ 个子集；本正文采用后者，因为它和 46 题全排列的回溯模板长得几乎一样，迁移成本最低。

### 什么是「子集（幂集）」？

一个集合的所有子集凑在一起叫**幂集**。`n` 个互不相同的元素，子集个数是 $2^n$（每个元素都有「在/不在」两种状态）。题目要我们**列出全部 $2^n$ 个子集**。

注意示例 1 的输出里：空集 `[]` 算一个子集、单元素 `[1]` 算一个、原集合本身 `[1,2,3]` 也算一个。

### 子集问题和排列问题的区别（这是本题核心）

46 题全排列求的是「**怎么排**」，78 题子集求的是「**选不选**」。同样是回溯，两者的决策树长得不一样：

| | 46 全排列 | 78 子集 |
|---|---|---|
| 顺序重要吗 | **重要**：`[1,2]` 和 `[2,1]` 是两个不同排列 | **不重要**：`[1,2]` 和 `[2,1]` 是同一个子集，只算一个 |
| 每个元素用几次 | 每个用一次 | 每个用一次（同样） |
| 怎么避免重复 | 用 `used[]` 跳过已选元素 | **用 `start` 索引保证「只往后选」**，天然不重复 |
| 收集哪些结果 | **只收集叶子**（`path` 填满才存） | **每个节点都收集**（`path` 不管多长都是合法子集） |
| 结果个数 | $n!$ | $2^n$ |

最关键的两条差异：

1. **用 `start` 索引保证「只往后选」**。子集不管顺序，所以我们可以**人为规定**：往 `path` 里加元素时，下标只能**递增**。这样 `[1,2]` 会被生成（先选下标 0 的 1、再选下标 1 的 2），但 `[2,1]` 永远不会出现（选了 2 后下标只能更大、回不到 1）。这就避免了「同一个子集以不同顺序出现」的重复。

2. **每个节点（不只是叶子）都收集**。全排列要等 `path` 填满 `n` 个才是一个完整排列；子集问题里，`path` 不管有几个元素——空、1 个、2 个……都是合法子集。所以**每进入一次回溯函数，就立刻把当前 `path` 存一份进答案**，而不是等到某个「结束条件」才存。

### 回溯模板（和 46 题同一套骨架）

把 46 题的模板拿过来微调两处，就变成了子集问题的模板：

```
void backtracking(参数, int start) {
    收集结果;           // ← 子集问题特点：每个节点都收集，不写在 if 里
    for (int i = start; i < n; ++i) {   // ← 从 start 开始，不是从 0
        做选择;          // push_back
        backtracking(下一层, i + 1);    // ← 注意传 i+1（往后选），不是 start+1
        撤销选择;        // pop_back
    }
}
```

和 46 题的对比（背模板时重点记这几处差异）：

- 46 题：`if (path.size() == n) { ans.push_back(path); return; }` —— **只有叶子存**；`for` 从 `0` 开始 + `used[]` 跳过 —— **允许往前选（管顺序）**。
- 78 题：**进函数第一行就 `ans.push_back(path)`** —— **每个节点都存**；`for` 从 `start` 开始 —— **只往后选（不管顺序）**；**不需要 `used[]`**（靠 `start` 天然不重复）。

### 手动推导 `nums = [1,2,3]` 的回溯树

每个节点都画出来（**注意：每个节点都是一个要收集的子集，共 $2^3 = 8$ 个**）：

```
                         []                        start=0，空集也是子集，收集 ✓
              /          |           \              for i=0,1,2：下一步「选谁」
            选1         选2          选3
           [1]          [2]          [3]            start=1/2/3，收集 ✓
          /    \         |
        选2    选3      选3                           （[3] 的 start=3，for 不执行 → 叶子）
      [1,2]  [1,3]     [2,3]                         收集 ✓
        |
       选3                                            （[1,3]、[2,3] 的 start=3 → 叶子）
     [1,2,3]                                          收集 ✓（叶子）
```

数一下节点：`[]`、`[1]`、`[2]`、`[3]`、`[1,2]`、`[1,3]`、`[2,3]`、`[1,2,3]`，正好 8 个，和示例输出一致（顺序不同但题目允许任意顺序）。

**关键观察**：`[1,2]` 这条分支里，`for` 从 `start=2` 开始只选了 `3`，**不会回头选 1 或 2**——这就是 `start` 索引的作用，它让决策树只往右下角生长，天然避免 `[2,1]`、`[1,1]` 这种重复或非法子集。

### 另一种等价视角：选/不选（二叉决策树）

官方题解「方法二」用的是这个视角：对 `nums[i]`，分「选它」和「不选它」两个分支，构成一棵**二叉决策树**，$n$ 层共 $2^n$ 个叶子，每个叶子对应一个子集。

```
                   i=0 选1?
                  /        \
                选           不选
              [1]            []
            i=1 选2?        i=1 选2?
           /     \          /     \
         选      不选      选      不选
       [1,2]    [1]       [2]      []
        ...     ...       ...
```

「枚举选谁」（`for`+`start`）和「选/不选」（二叉）是同一棵树的两种遍历方式，结果完全一样。本正文用 `for`+`start`，因为它和 46 题模板同构；官方代码用的是「选/不选」，文末复盘会贴出对照。

## 代码

```cpp
class Solution {
public:
    // ===== 两个成员变量，让所有递归层共用同一份（和 46 题一样的套路）=====
    //   ans：存所有子集的结果。
    //     - vector<vector<int>> 是「二维动态数组」：外层每个元素是一个 vector<int>（一个子集），
    //       共 2^n 个。push_back(某个vector)：末尾追加一个子集，均摊 O(n)（要拷贝整个子集）。
    //     - 这里比 46 题多收集：不是只存叶子，而是每个节点都存一份。
    vector<vector<int>> ans;
    //   path：当前正在拼的子集。vector<int> 动态数组，长度随「做选择/撤销」增减。
    //     - push_back(x)：末尾追加，均摊 O(1)；pop_back()：删末尾元素，O(1)。
    //     - 同一个 path 在所有递归层之间复用，靠「做选择/撤销」在分支间来回切换。
    vector<int> path;

    // 回溯主函数。
    //   - nums：题目给的候选数集合（元素互不相同）。
    //   - start：本层「可以从哪个下标开始选」。
    //     ★ 这是和 46 题最大的区别：46 题用 used[] 跳过已选元素（允许任意顺序），
    //       78 题用 start 保证「只往后选」（不管顺序、天然不重复），所以连 used[] 都不需要。
    void backtracking(const vector<int>& nums, int start) {
        // ★★★ 子集问题的核心：每进入一次回溯函数，就立刻把当前 path 存一份。
        //   - 和 46 题对比：46 题是「if (path.size()==n) { 存; return; }」——只有叶子才存。
        //     78 题是「进函数第一行就存」——空集、1 元素、2 元素……任何长度的 path 都是合法子集。
        //   - 这里没有 return：存完之后还要继续往下 for 循环扩展更长的子集。
        //   - 注意是「拷贝」存进去：ans.push_back(path) 会复制一份当前 path，
        //     后续 pop_back 改的是 path 本身，已存进去的那份不受影响。
        ans.push_back(path);

        // 本层选择列表：从 start 往后枚举「下一个要选的元素」。
        //   - 为什么从 start 而不是 0？因为子集不管顺序，规定「下标递增」就不会重复：
        //     选了 nums[i] 后，下一层只能从 i+1 往后选，永远不会回头选更小下标的元素。
        //     于是 [1,2] 会被生成，[2,1] 不会被生成（同一个子集只出现一次）。
        //   - 和 46 题对比：46 题的 for 是「for i=0..n-1 + if(used[i]) continue」，
        //     允许任意顺序、靠 used 去重；78 题的 for 是「for i=start..n-1」，靠 start 去重，更简洁。
        //   - nums.size() 返回 size_t（无符号），和 int 比较时显式转 int 避免符号警告。
        for (int i = start; i < (int)nums.size(); ++i) {
            // ===== 做选择（回溯三步之 1）=====
            // 把 nums[i] 加进当前子集。
            path.push_back(nums[i]);

            // ===== 递归（回溯三步之 2）=====
            // 进入下一层，去拼更长的子集。
            //   ★ 注意传的是 i+1，不是 start+1！
            //     - 传 i+1：下一层只能从「当前刚选的元素之后」开始选，保证下标严格递增。
            //     - 如果误传 start+1，会允许选回当前层之前的元素，导致重复子集。
            //     - 和 46 题对比：46 题递归不传 start（靠 used 判断），这里靠 start 判断。
            backtracking(nums, i + 1);

            // ===== 撤销选择（回溯三步之 3，回溯的「回」）=====
            // 把刚才加进来的 nums[i] 从 path 末尾拿掉，让同层 for 的下一个 i 能干净地接着选。
            //   - 这一句必须和「做选择」严格对称：push 了什么就 pop 什么。
            //   - 不撤销的话 path 只增不减，后续分支会带上不该有的元素。
            path.pop_back();
        }
    }

    vector<vector<int>> subsets(vector<int>& nums) {
        // 成员变量清空（应对同一个 Solution 对象被多次调用；力扣虽每次新建实例，养成习惯更稳）。
        path.clear();
        ans.clear();

        // 从空 path、start=0 开始回溯。
        //   - 第一次进 backtracking 时 path 是空 → 先收集空集 []，符合题目要求。
        backtracking(nums, 0);
        return ans;
    }
};
```

## 复杂度

- **时间**：O(n × 2ⁿ)
  - 一共 $2^n$ 个子集（决策树节点总数），每个子集存进 `ans` 时要拷贝一份 `path`，耗时 O(n)。
  - 相乘得 O(n × 2ⁿ)。`n ≤ 10` 时最多 10 × 1024 ≈ 10⁴ 次操作，非常快。
- **空间**：O(n)
  - 不计答案数组 `ans` 本身（题目要求返回的空间通常不计入）。
  - 递归调用栈深度等于 `path` 最长长度 n（最深走到 `nums` 全选进去那条路），所以是 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么「每进入一次 `backtracking` 就 `ans.push_back(path)`」，而不是像 46 题那样等 `path` 填满才存？

因为**子集问题里，任何长度的 `path` 都是合法子集**——空集、1 个元素、2 个元素……一直到 n 个元素，全都要收进答案。46 题不同：全排列必须填满 n 个位置才算一个完整排列，没填满的中间状态不是解。

所以子集问题的「收集」不能写在某个「结束条件 if」里（那样只能存叶子、漏掉所有更短的子集），而要写在函数**第一行、无条件执行**——只要进了一次函数，当前 `path` 就是该存的。这也是为什么本解没有 `if (...) return;` 这种提前返回：存完之后还要继续 `for` 往下扩展。

### Q2：为什么用 `start` 索引就能避免重复子集？不需要 `used[]` 吗？

因为**子集不管顺序**。`{1,2}` 和 `{2,1}` 是同一个子集，我们只要生成其中一个就行。规定「往 `path` 里加元素时，下标只能严格递增」就能做到：

- 选了 `nums[0]`（值 1）后，下一层 `start=1`，只能从下标 1 往后选 → 会生成 `[1,2]`。
- 永远不会出现「先选下标 1（值 2）再回头选下标 0（值 1）」的情况，因为 `start` 只增不减。

所以 `[2,1]` 这种顺序在本解里**根本不会被生成**，也就谈不上去重。`used[]` 在全排列里是必要的（因为排列要允许任意顺序、靠 `used` 跳过已选元素），但在子集问题里用 `start` 就够了，而且更简洁。

### Q3：递归时为什么传 `i + 1`，而不是 `start + 1`？

这是个特别容易写错的点。**必须传 `i + 1`**（当前循环变量加一），不是 `start + 1`：

- `i` 是「本层这一轮实际选中的下标」，下一层应该从 `i+1` 往后选（比刚选的更大），保证下标严格递增。
- 如果误传 `start + 1`：假设本层 `start=0`，第一轮 `i=0` 递归传 `start+1=1` 没问题；但第二轮 `i=1` 时还传 `start+1=1`，下一层又从下标 1 开始选 → 会重复选 `nums[1]`，生成重复/错误子集。

一句话：**下一层的起点 = 本层实际选中的下标 + 1**，所以是 `i + 1`。

### Q4：和 46 题全排列到底差在哪？能不能直接套 46 题的代码？

不能直接套，要改三处（背下来）：

| 改动点 | 46 全排列 | 78 子集 |
|---|---|---|
| 收集时机 | `if (path.size()==n) { 存; return; }` 只存叶子 | 进函数第一行 `存`，每个节点都存 |
| 选择列表 | `for i=0..n-1` + `if(used[i]) continue` | `for i=start..n-1`，靠 `start` 去重 |
| 递归参数 | 不传 `start`（靠 `used`） | 传 `i + 1`（靠下标递增） |
| 额外空间 | 需要 `used[]` 标记数组 | **不需要** `used[]` |

本质原因：排列管顺序（要枚举所有顺序、靠 `used` 避免同元素用两次）、子集不管顺序（人为规定下标递增、靠 `start` 避免重复）。两套模板的「回溯三步（做选择→递归→撤销）」完全一样，差别全在上面三处细节。

## 复盘

### 可迁移套路

- **「子集型回溯 = 每个节点都收集 + `start` 避免重复」**。这是和「排列型回溯（只收集叶子 + `used` 去重）」并列的第二大回溯模板。遇到「求所有子集 / 所有组合」类题目，默认套这个模板：
  - **78 子集**：每个元素最多选一次、无目标和约束 → 本题。
  - **39 组合总和**：元素可重复使用 → 递归传 `i` 而不是 `i+1`（同一元素可再选），再加「剩余目标和」做剪枝。
  - **77 组合**：求 `C(n,k)` → 在 78 基础上加一个「`path` 长度 == k 才存」的剪枝（又变回只存部分节点）。
  - **40 组合总和 II**：元素有重复 → 先排序 + 同层去重（`if (i>start && nums[i]==nums[i-1]) continue`）。
  - **131 分割回文串**：`start` 表示「下一个切割点」，本质也是子集型回溯的变体。
- **两种回溯视角的等价性**：「枚举选谁」（`for`+`start`）和「选/不选」（二叉决策树）是同一棵树的两种遍历。前者更贴近 46 题模板、好迁移；后者（官方写法）更直观地体现「$2^n$ 个状态」。做题时哪种顺手用哪种。
- **复杂度基准**：子集型回溯时间 O(n·2ⁿ)、空间 O(n)（不计答案）。`n ≤ 10` 是这类题的典型规模上限（$2^{10}=1024$）。

### 解法二：迭代法（逐步扩展现有子集）

思路：从「只有空集」开始，**每加入一个新元素，就把现有所有子集各复制一份、再追加这个元素，得到一批新子集**。

```
初始     ans = [[]]
加 1     ans = [[], [1]]              ← 复制 [] 追加 1
加 2     ans = [[], [1], [2], [1,2]]  ← 复制 []、[1] 追加 2
加 3     ans = [[], [1], [2], [1,2], [3], [1,3], [2,3], [1,2,3]]
```

每次元素数翻倍，最终正好 $2^n$ 个子集。

```cpp
class Solution {
public:
    vector<vector<int>> subsets(vector<int>& nums) {
        vector<vector<int>> ans;
        ans.push_back({});                 // 初始：只有空集。{} 列表初始化一个空 vector<int>
        for (int num : nums) {             // 逐个元素处理
            int sz = ans.size();           // ★ 先记下「当前已有子集数」
            // 复制现有每个子集、追加 num，得到一批新子集。
            //   - 关键：循环上界用进入循环时的 sz，不能写成 ans.size()：
            //     因为循环体里 ans 还在 push_back 不断变长，用动态 size() 会无限循环。
            //   - ans[i]：取已有子集的引用；push_back(ans[i]) 会拷贝一份追加到末尾。
            //   - ans.back()：取刚追加进去的那个新子集（拷贝），再 push_back(num) 给它追加元素。
            for (int i = 0; i < sz; ++i) {
                ans.push_back(ans[i]);          // 拷贝第 i 个已有子集
                ans.back().push_back(num);      // 在拷贝上追加当前元素
            }
        }
        return ans;
    }
};
```

- **时间**：O(n × 2ⁿ)，每个子集被构造一次、拷贝代价 O(n)。
- **空间**：O(1) 额外空间（不计答案，迭代法没有递归栈）。
- **对比**：不用递归、不写回溯模板，思路最直白；但没有「回溯」的训练价值，面试如果考回溯组题目，期望你写的是主解。

### 解法三：位运算（官方方法一，二进制枚举）

思路：`n` 个元素的子集和长度为 `n` 的 `0/1` 串一一对应——第 `i` 位是 `1` 表示 `nums[i]` 在子集里、`0` 表示不在。`n` 位 `0/1` 串正好覆盖 `0` 到 `2^n - 1` 的所有整数，**枚举这些整数、按位取数即可**。

例如 `nums = [5,2,9]`（下标 0,1,2），`mask = 5`（二进制 `101`）→ 第 0 位和第 2 位是 1 → 子集 `{5,9}`。

```cpp
class Solution {
public:
    vector<int> t;                         // 临时数组，装当前 mask 对应的子集
    vector<vector<int>> ans;

    vector<vector<int>> subsets(vector<int>& nums) {
        int n = nums.size();
        // (1 << n)：1 左移 n 位 = 2^n。mask 从 0 枚举到 2^n - 1，每个 mask 是一个子集的编码。
        for (int mask = 0; mask < (1 << n); ++mask) {
            t.clear();
            for (int i = 0; i < n; ++i) {
                // (1 << i)：只有第 i 位是 1 的掩码。
                // mask & (1 << i)：按位与，非零说明 mask 的第 i 位是 1 → nums[i] 在子集里。
                //   - 位运算优先级低，但这里 mask & (1<<i) 作为 if 条件不用加括号也能判真，
                //     官方写法（判断 != 0）更严谨。n<=10 时 (1<<i) 不会溢出 int。
                if (mask & (1 << i)) {
                    t.push_back(nums[i]);
                }
            }
            ans.push_back(t);              // 把这个 mask 对应的子集存进答案
        }
        return ans;
    }
};
```

- **时间**：O(n × 2ⁿ)，外层 $2^n$ 个 mask、内层每个 mask 扫 n 位。
- **空间**：O(n)，临时数组 `t` 的代价。
- **对比**：和主解（回溯）复杂度完全一样，但**没有递归**、常数更小，是本题最快写法之一。缺点是「位掩码」这个抽象不如回溯模板通用——遇到「组合总和」「分割回文串」这类带约束的变体，位运算就不好加了，还是得回回溯模板。所以学回溯阶段建议以主解为主，位运算当作「子集专用的捷径」记住。
