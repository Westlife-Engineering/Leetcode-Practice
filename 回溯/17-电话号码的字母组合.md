# 17 电话号码的字母组合

- 难度：中等
- 标签：哈希表、字符串、**回溯**
- 力扣链接：https://leetcode.cn/problems/letter-combinations-of-a-phone-number/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/letter-combinations-of-a-phone-number/solutions/388738/dian-hua-hao-ma-de-zi-mu-zu-he-by-leetcode-solutio/)「电话号码的字母组合」（slug：`dian-hua-hao-ma-de-zi-mu-zu-he-by-leetcode-solutio`）。正文主解是 **回溯法**：每个数字对应 3~4 个字母，回溯地枚举「每个位置选哪个字母」。本质上这是一棵**多叉决策树**，套 46 题那套「做选择 → 递归 → 撤销选择」的模板就能直接写出来。另一种「队列迭代法」放在文末「复盘」作对比。

## 题目描述

给定一个仅包含数字 `2-9` 的字符串 `digits`，返回所有它能表示的字母组合。答案可以按 **任意顺序** 返回。

给出数字到字母的映射如下（与电话按键相同）。注意 `1` 不对应任何字母。

```
2 -> abc      3 -> def
4 -> ghi      5 -> jkl     6 -> mno
7 -> pqrs     8 -> tuv     9 -> wxyz
```

**示例 1：**

```
输入：digits = "23"
输出：["ad","ae","af","bd","be","bf","cd","ce","cf"]
```

**示例 2：**

```
输入：digits = "2"
输出：["a","b","c"]
```

**示例 3：**

```
输入：digits = ""
输出：[]
```

**提示：**

- `0 <= digits.length <= 4`
- `digits[i]` 是范围 `['2', '9']` 的一个数字。

## 思路

> 本题主要参考力扣官方题解「方法一：回溯」的思路。

### 题目在做什么？

老式手机九宫格键盘：按一下 `2` 键出 `a`、按两下出 `b`、按三下出 `c`。给一串数字（如 `"23"`），问按这串数字能拼出多少种字母组合。每个数字只能贡献**一个字母**，但可以在它对应的 3~4 个字母里任选一个。

- `"23"` → `2` 选一个 `{a,b,c}`、`3` 选一个 `{d,e,f}`，组合数 = 3 × 4 = 12 种。
- 空串 `""` 对应 0 种（题目要求返回空数组 `[]`）。

注意 `1` 和 `0` 不对应任何字母，本题保证输入只含 `2~9`，不用特殊处理它们。

### 为什么是回溯？——多叉决策树

把每个数字看成决策树的一**层**、把该数字对应的每个字母看成这一层的**分支**：

```
第 1 层：数字 '2'，可选 {a, b, c}        ← 3 个分支
第 2 层：数字 '3'，可选 {d, e, f}        ← 4 个分支
第 3 层：数字 '7'，可选 {p, q, r, s}     ← 4 个分支
...
```

从根到叶的一条路径，就是把每个数字各选一个字母拼起来的一个组合。**所有从根到叶的路径，就是全部答案。** 这正是回溯最典型的应用场景，套 46 题的模板即可。

### 和 46 全排列的区别（关键）

虽然两题代码骨架几乎一样，但「选择列表」的含义不同：

| | 46 全排列 | 17 电话号码的字母组合 |
|---|---|---|
| 每一层选什么 | 从**同一个集合** `nums` 里挑一个 | 从**当前数字对应的那几个字母**里挑一个 |
| 上一层选过的会影响本层吗 | 会（不能再选同一个，要 `used` 标记） | **不会**（不同位置的字母集互不相关） |
| 要不要 `used` 标记 | 要 | **不要** |
| 递归深度 | `n`（排列长度） | `digits.size()`（数字个数） |

核心区别一句话：**46 是「从同一集合选不同元素」，17 是「每个位置从不同字母集各选一个」**。所以 17 题更简单——不需要 `used`，每层的选择列表天然就是「当前数字对应的那几个字母」，不会和别的层冲突。每层只是把「用哪个 `index` / 处理第几个数字」传下去即可。

### 回溯三要素（套 46 题那套）

1. **路径（`combination`）**：当前正在拼的字符串（已经选好的字母）。
2. **选择列表**：当前数字 `digits[index]` 对应的那 3~4 个字母。
3. **结束条件**：`index == digits.size()`，说明每个数字都选过一个字母了，把 `combination` 存进答案。

### 数字到字母的映射表

需要一个「`'2' -> "abc"`、`'3' -> "def"` …」的映射。两种常见写法：

- **`unordered_map<char, string>`**（官方写法）：哈希表，`char` 作 key、`string` 作 value，查找 O(1)。好处是可读性高、直接 `phoneMap[digit]`。
- **`const string mapping[10]`**（数组法）：下标 0~9 直接对应数字 0~9，下标 2 对应 `"abc"`。查找 O(1) 且常数更小，缺点是占用了 0、1 两个无用位置（留空串即可）。

两种都行，本正文跟官方用 `unordered_map`。

### 手动推导 `digits = "23"` 的回溯树

```
                              ""                    combination 起点（空）
              /                |                 \
           选 a                选 b               选 c
          "a"                 "b"                 "c"
        /  |  \             /  |  \            /  |  \
      选d  选e  选f       选d  选e  选f      选d  选e  选f
    "ad" "ae" "af"       "bd" "be" "bf"     "cd" "ce" "cf"
      │    │    │         │    │    │         │    │    │
   index=2 → 存答案   index=2 → 存答案    index=2 → 存答案
```

执行流程（以最左那条分支为例，注意撤销选择是怎么起作用的）：

```
进入 "" (index=0) → digit='2', letters="abc"
  选 letter='a' → combination="a"
    进入 "a" (index=1) → digit='3', letters="def"
      选 letter='d' → combination="ad"
        进入 "ad" (index=2)：index==digits.size() → 存 "ad"，return
      回到 "a"：pop_back → combination="a"
      选 letter='e' → combination="ae" → ... 存 "ae"
      选 letter='f' → combination="af" → ... 存 "af"
    回到 "a"：本层 for 结束，return
  回到 "" (index=0)：pop_back → combination=""
  选 letter='b' → combination="b" → ...（同理得到 bd/be/bf）
  选 letter='c' → combination="c" → ...（同理得到 cd/ce/cf）
```

注意第 5 步「回到 `"a"`：`pop_back`」——正因为把 `'d'` 从 `combination` 拿掉了，后面才能干净地接着选 `'e'`、`'f'`。如果忘了撤销，`combination` 会越拼越长、和答案对不上。这正是回溯「做选择」和「撤销选择」必须成对出现的根本原因。

## 代码

```cpp
class Solution {
public:
    vector<string> letterCombinations(string digits) {
        // vector<string>：动态数组，每个元素是一个 string。
        //   - 存所有合法的字母组合，最终返回它。
        //   - 空字符串输入要返回空数组（不是 [""]），所以先声明为空。
        vector<string> combinations;

        // 空输入特判：digits 为空时没有任何组合，直接返回空数组。
        //   - 不特判的话，回溯会在 index==0==digits.size() 时存一个空串 ""，
        //     返回 [""]，这是错的（题目要求空输入返回 []）。
        if (digits.empty()) {
            return combinations;
        }

        // unordered_map<char, string>：哈希表，key 是 char、value 是 string。
        //   - C++ STL，查找/插入均摊 O(1)（用 std::hash<char> 算哈希、链地址法处理冲突）。
        //   - 这里用「列表初始化」{{'2',"abc"}, ...} 一次性填好 8 个映射。
        //   - 与 map（红黑树 O(log n)）相比，unordered_map 平均更快但无序；本题只做精确查找，用它最合适。
        unordered_map<char, string> phoneMap{
            {'2', "abc"},
            {'3', "def"},
            {'4', "ghi"},
            {'5', "jkl"},
            {'6', "mno"},
            {'7', "pqrs"},
            {'8', "tuv"},
            {'9', "wxyz"}
        };

        // combination：当前正在拼的字符串。先声明为空，靠 push_back/pop_back 增减字符。
        //   - 传引用给回溯函数，所有递归层共用同一份，省去反复拷贝。
        string combination;

        // 从 index=0（第一个数字）开始回溯。
        backtrack(combinations, phoneMap, digits, 0, combination);
        return combinations;
    }

private:
    // 回溯主函数：参数含义——
    //   - combinations：存答案的引用（所有递归层共用）。
    //   - phoneMap：数字→字母映射表的 const 引用（不修改它，只读）。
    //   - digits：输入字符串的 const 引用（只读）。
    //   - index：当前处理到 digits 的第几个数字（即决策树的第几层）。
    //   - combination：当前正在拼的字符串的引用（做选择/撤销选择直接改它）。
    void backtrack(vector<string>& combinations, const unordered_map<char, string>& phoneMap,
                   const string& digits, int index, string& combination) {
        // 结束条件：index 走到 digits 末尾 → 每个数字都贡献了一个字母，收集一个完整组合。
        //   - digits.length() 返回 size_t（无符号），和 int 比较时这里能安全比较，
        //     因为 index 始终 >= 0，不会出现「负数转无符号变大数」的坑。
        //   - combinations.push_back(combination)：把当前字符串拷一份存进答案。
        //     注意是「拷贝」——后续 pop_back 会改 combination，但已存进去的这份不受影响。
        if (index == digits.length()) {
            combinations.push_back(combination);
            return;
        }

        // 取出当前层的数字，并查出它对应的字母串。
        char digit = digits[index];
        // phoneMap.at(digit)：哈希表「带边界检查」的取值。
        //   - 找到 → 返回对应 string 的引用；找不到 → 抛 out_of_range 异常。
        //   - 这里用 at 而非 []：[] 在 key 不存在时会偷偷插入空串（副作用），at 更安全。
        //     （本题保证输入只有 '2'~'9'，map 里都有，所以不会真的抛异常。）
        //   - 返回 const string&：用 const 引用接收，避免拷贝整个字母串。
        const string& letters = phoneMap.at(digit);

        // 本层的选择列表：遍历该数字对应的每个字母，逐个试。
        //   - for (const char& letter : letters)：范围 for 循环遍历 string 的每个字符。
        //     const char& 是「字符的 const 引用」，避免按值拷贝（虽然 char 拷贝很便宜，写成 const char& 更规范）。
        //   - 和 46 题的区别：这里不需要 used 标记——不同位置的字母集互不冲突，每个字母在本层用一次就行。
        for (const char& letter : letters) {
            // ===== 做选择 =====
            // 把 letter 追加到当前组合末尾。
            //   - string::push_back(c)：末尾追加一个字符，均摊 O(1)。
            combination.push_back(letter);

            // ===== 递归 =====
            // 进入下一层：去处理 digits 的下一个数字。
            //   - index + 1 让下一层处理第 index+1 个数字。
            backtrack(combinations, phoneMap, digits, index + 1, combination);

            // ===== 撤销选择（回溯的「回」）=====
            // 把刚才追加的 letter 从末尾拿掉，让本层后续循环能干净地选下一个字母。
            //   - string::pop_back()：删除末尾一个字符，O(1)。
            //   - 这一句必须和 push_back 严格对称，漏掉就全错。
            combination.pop_back();
        }
    }
};
```

## 复杂度

- **时间**：O(3^m × 4^n)
  - 其中 `m` 是 `digits` 中对应 3 个字母的数字个数（`2/3/4/5/6/8`）、`n` 是对应 4 个字母的数字个数（`7/9`），`m + n = digits.size()`。
  - 组合总数就是 `3^m × 4^n`（每条根到叶的路径对应一个组合），每个组合还要花 O(m+n) 拼字符串并存进答案，但组合数本身已经主导了量级，写作 O(3^m × 4^n)。
  - `digits.length() <= 4` 时最多约 4^4 = 256 种，非常快。
- **空间**：O(m+n)
  - 不计答案数组 `combinations`（题目要求返回的空间通常不计入）。
  - 递归调用栈深度等于 `digits.size()` = m+n；`combination` 字符串长度最多也是 m+n。两者相加仍 O(m+n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么用回溯不用多重循环？

因为数字个数 `digits.size()` 是**不固定**的（题目里 `0 <= length <= 4`）。要用多重循环写就得「写 `length` 层嵌套循环」，但 `length` 是变量，你没法提前写出层数。回溯用递归天然解决了「层数动态」的问题——**递归深度就是数字个数**，每一层就是处理一个数字、在它对应的字母里选一个。所以凡是「解的长度随输入变化、要枚举所有组合」的问题，几乎都得用回溯/递归来写。这和 46 全排列「为什么不直接迭代」是同一个理由。

### Q2：映射表用 `unordered_map` 还是数组？

都能 AC，看场景：

| 写法 | 查找 | 优点 | 缺点 |
|---|---|---|---|
| `unordered_map<char,string>` | 均摊 O(1) | 可读性高，key 是字符直观 | 哈希表有常数开销，多占点空间 |
| `const string mapping[10]` | O(1) | 常数最小，下标直接是数字 | 占 0/1 两个无用位置（留空串） |

数组的写法大概长这样：

```cpp
const string mapping[10] = {
    "", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"
};
// 用法：const string& letters = mapping[digit - '0'];
// digit - '0'：把字符 '2' 转成整数 2（字符的 ASCII 差值）。
```

比赛里更常用数组（更快更短），但官方用 `unordered_map`，可读性更好、入门更友好，本正文沿用。

### Q3：空输入为什么要特判？不特判会怎样？

不特判的话，回溯会这样走：`backtracking(... index=0 ...)` → 检查 `index == digits.length()`，即 `0 == 0`，成立 → 把当前的空 `combination` 当成一个合法组合存进答案，返回 `[""]`。

但题目要求空输入返回 `[]`（空数组），不是 `[""]`（含一个空串的数组）。两者语义不同——`[""]` 表示「有一种组合，是空串」；`[]` 表示「没有任何组合」。所以在进入回溯前先 `if (digits.empty()) return {};` 兜底。

### Q4：`index` 参数的作用是什么？能不能像 46 题那样用 `path.size()` 代替？

`index` 表示「当前处理到 `digits` 的第几个数字」，也就是决策树的层数。它的作用有两个：

1. **作为结束条件**：`index == digits.size()` 说明所有数字都处理完了。
2. **取出本层的选择列表**：`digits[index]` 决定本层从哪几个字母里选。

46 题里位置就是 `path.size()`（因为每个位置填一个数，填了几个就到了第几层），所以不传 `index` 也行。但 17 题不同：**`combination` 存的是字母，而层数对应的是数字**——`digits[index]` 是数字、`combination` 里是字母，两者不是一一对应的同一种东西。所以必须显式传 `index` 来定位「现在该处理哪个数字」。这也是回溯模板的一个常见变体：当「层数」和「路径长度」不是同一个语义时，就用单独的 `index` 参数。

## 复盘

### 可迁移套路

- **「多叉决策树回溯」是 46 题那套模板的直接迁移**。本题只是把「选择列表」从 `nums` 换成了「当前数字对应的字母串」，把 `used` 标记去掉了（因为不同位置字母集互不冲突），其余骨架一模一样：`if (结束) { 收集; return; }` + `for (本层选择) { 做选择; 递归; 撤销选择; }`。**回溯三要素（路径、选择列表、结束条件）想清楚，代码就自然出来了。**
- **「解的长度随输入变化」→ 想回溯/递归**。无论是排列、组合、子集、字母组合、括号生成、N 皇后，只要解的长度不固定、要枚举所有可能，几乎都套回溯。
- **「每层从不同集合各选一个」是最简单的回溯**：不需要去重、不需要 `used`、不需要剪枝，每层独立。后续遇到「元素可重复选」「结果不能重复」等约束，才需要加 `start` 参数 / `used` 标记 / 排序去重。
- **复杂度基准**：回溯题时间复杂度通常是「解的个数 × 每个解的构造代价」。本题解个数是 3^m × 4^n；46 全排列是 n!；78 子集是 2^n。

### 解法二：队列迭代法（BFS 思路，对比用）

回溯是 DFS（一条路走到底再回头），也可以用 BFS 思路：用一个队列，每处理一个数字，就把队列里现有的所有组合都「扩展」出若干份、每份追加该数字的一个字母。

以 `digits = "23"` 为例：

```
初始  队列 = [""]                   ← 放一个空串作为起点
处理 '2'：把 "" 扩展成 a/b/c         队列 = ["a","b","c"]
处理 '3'：把每个元素扩展成 +d/+e/+f   队列 = ["ad","ae","af","bd","be","bf","cd","ce","cf"]
```

```cpp
class Solution {
public:
    vector<string> letterCombinations(string digits) {
        if (digits.empty()) return {};
        // 队列初始放一个空串，作为后续扩展的起点。
        vector<string> q;
        q.push_back("");
        // 每个数字对应的字母（数组法，下标 = 数字）。
        //   - 这里用数组比 unordered_map 更紧凑，下标 digit-'0' 直接定位。
        const string mapping[10] = {
            "", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"
        };
        for (char digit : digits) {
            const string& letters = mapping[digit - '0'];   // digit-'0'：字符 '2' 转整数 2
            int sz = q.size();                               // 记下「扩展前」的队列长度，只扩展这一批
            for (int i = 0; i < sz; ++i) {
                string prefix = q[i];                        // 取出队列头部的一个前缀
                for (char letter : letters) {
                    q.push_back(prefix + letter);            // 给前缀追加一个字母，重新塞回队尾
                }
            }
            q.erase(q.begin(), q.begin() + sz);              // 删掉已扩展过的那批旧前缀
        }
        return q;
    }
};
```

- **时间**：O(3^m × 4^n)，与回溯同阶（生成的组合总数一样）。
- **空间**：O(3^m × 4^n)，队列里最多同时存所有组合（回溯只存一条路径 O(m+n)，所以回溯更省空间）。
- **对比**：迭代法思路直白（像「滚雪球」，每轮把已有结果各乘一遍新字母），但空间开销大、要反复 `erase`；回溯法靠递归栈和单个 `combination`，空间只用 O(m+n)，是官方推荐写法。理解了迭代法，更能体会「回溯 = 在决策树上 DFS + 撤销选择」的精妙——用一份路径跑遍所有分支。
