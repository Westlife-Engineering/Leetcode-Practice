# 1143 最长公共子序列

- 难度：中等
- 标签：字符串、**动态规划**
- 力扣链接：https://leetcode.cn/problems/longest-common-subsequence/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[最长公共子序列](https://leetcode.cn/problems/longest-common-subsequence/solution/zui-chang-gong-gong-zi-xu-lie-by-leetcod-y7u0/)」。正文主解是 **方法一：动态规划（二维）**——这是经典的 **LCS（Longest Common Subsequence）问题**，标准的二维 DP 写法：状态 `dp[i][j]` 表示 `text1` 前 i 个字符与 `text2` 前 j 个字符的最长公共子序列长度。和 62 不同路径一样属于「二维表格 + 双层 for 填表」这一类，只是状态来源从「上、左」变成了「左上 / 上 / 左」三选一。官方题解只给了这一种解法，空间优化的滚动数组写法放在「复盘」。

## 题目描述

给定两个字符串 `text1` 和 `text2`，返回这两个字符串的最长 **公共子序列** 的长度。如果不存在公共子序列，返回 `0`。

一个字符串的 **子序列** 是指这样一个新的字符串：它是由原字符串在不改变字符的相对顺序的情况下删除某些字符（也可以不删除任何字符）后组成的新字符串。

- 例如，`"ace"` 是 `"abcde"` 的子序列，但 `"aec"` 不是 `"abcde"` 的子序列。

两个字符串的 **公共子序列** 是这两个字符串所共同拥有的子序列。

**示例 1：**

```
输入：text1 = "abcde", text2 = "ace"
输出：3
解释：最长公共子序列是 "ace" ，它的长度为 3 。
```

**示例 2：**

```
输入：text1 = "abc", text2 = "abc"
输出：3
解释：最长公共子序列是 "abc" ，它的长度为 3 。
```

**示例 3：**

```
输入：text1 = "abc", text2 = "def"
输出：0
解释：两个字符串没有公共子序列，返回 0 。
```

**提示：**

- `1 <= text1.length, text2.length <= 1000`
- `text1` 和 `text2` 仅由小写英文字符组成。

## 思路

> 本题主要参考力扣官方题解「方法一：动态规划」。

要求的是「两个字符串 **公共** 子序列的最长长度」。注意两个关键词：**「公共」**（这个子序列要同时在 `text1` 和 `text2` 里出现）、**「子序列」**（字符可以跳着选，只要求相对顺序不变，不要求连续）。这正是经典的 **LCS 问题**。

如果暴力枚举：把 `text1` 的所有子序列（最多 `2^m` 个）全列出来，再看哪些也是 `text2` 的子序列——指数级爆炸（`m=1000` 时完全不可能）。得找**递推关系**：能不能用「更短的前缀之间的 LCS」推出「更长前缀之间的 LCS」？

### DP 三要素（和 62 不同路径同款思考框架，只是状态来源不同）

#### ① 状态定义：`dp[i][j]` = `text1` 的前 i 个字符、`text2` 的前 j 个字符的最长公共子序列长度

两个下标 `i`、`j` 分别对应两个字符串，所以是**二维**状态。`dp[m][n]`（`m`、`n` 是两串长度）就是答案。

> **为什么是「前 i 个字符」「前 j 个字符」，而不是「以下标 i 结尾」？**
>
> 这和 300 最长递增子序列（一维，按「以 `nums[i]` 结尾」定义）不一样。因为 LCS 的「公共」关系是**两个串对齐看**的——比较 `text1` 的前缀和 `text2` 的前缀，看它们有多少公共字符。定义成「前 i 个 vs 前 j 个」后，「加一个字符」这个动作对应 `i+1` 或 `j+1`，转移自然。
>
> 这里的「前 i 个字符」指 `text1[0..i-1]`（长度为 i 的前缀），官方记作 `text1[0:i]`。

#### ② 状态转移方程（核心！分「匹配 / 不匹配」两种情况）

**盯着「最后两个字符」看**——也就是 `text1` 的第 i 个字符 `text1[i-1]` 和 `text2` 的第 j 个字符 `text2[j-1]`（注意是 `i-1`、`j-1`，下标解释见下方 Q2）。它们只有两种关系：

**情况一：`text1[i-1] == text2[j-1]`（这两个字符相等，匹配上了）**

太好了，这对相同字符可以直接贡献给公共子序列！把它「接在」`text1` 前 i-1 个和 `text2` 前 j-1 个的 LCS 后面即可——长度比 `dp[i-1][j-1]` 多 1：

```
dp[i][j] = dp[i-1][j-1] + 1
```

> 直觉：两个串的「尾巴字符相同」，这个字符肯定要被选进公共子序列（选它不会让结果更差），所以问题归约到「两边都把尾巴砍掉」之后的 LCS，再 +1。
>
> 注意不是从 `dp[i-1][j]` 或 `dp[i][j-1]` 转移，而是从 `dp[i-1][j-1]`——因为这对匹配字符同时消耗了 `text1` 的第 i 个和 `text2` 的第 j 个，两边都得往前挪一格。

**情况二：`text1[i-1] != text2[j-1]`（这两个字符不相等，没法都选）**

既然这对尾巴字符对不上，那它们就**不可能同时**出现在公共子序列的末尾——要么 `text1[i-1]` 不参与（舍弃 `text1` 的最后一个字符），要么 `text2[j-1]` 不参与（舍弃 `text2` 的最后一个字符）。两种「舍弃」各对应一个子问题，取较大者：

```
dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

- `dp[i-1][j]`：`text1` 前 i-1 个 vs `text2` 前 j 个的 LCS（相当于「舍弃 `text1[i-1]`」）；
- `dp[i][j-1]`：`text1` 前 i 个 vs `text2` 前 j-1 个的 LCS（相当于「舍弃 `text2[j-1]`」）。

> 为什么不也减个 `dp[i-1][j-1]`？因为 `dp[i-1][j-1] <= dp[i-1][j]` 且 `dp[i-1][j-1] <= dp[i][j-1]`（前缀越短 LCS 不会更长），`max` 里它一定被压住，写不写都不影响结果，所以只比较前两个就够。

**合起来（官方转移方程）：**

```
            ⎧ dp[i-1][j-1] + 1,                      若 text1[i-1] == text2[j-1]
dp[i][j] =  ⎨
            ⎩ max(dp[i-1][j], dp[i][j-1]),           若 text1[i-1] != text2[j-1]
```

一句话总结：**「字符相等就左上角 +1；不相等就取上方和左方的较大值」**。

#### ③ 初始条件：`dp[0][*] = 0` 且 `dp[*][0] = 0`（第一行、第一列全 0）

`dp[0][j]` 表示「`text1` 取前 0 个字符（空串）和 `text2` 前 j 个字符的 LCS」——空串和任何串都没有公共字符，长度是 0。同理 `dp[i][0] = 0`。

> 这就是为什么 `dp` 数组要**多开一行一列**（下标到 `m+1`、`n+1`）：第一行第一列专门用来表示「空串」这个边界，全部填 0，这样 `i=1`、`j=1` 开始的转移有现成的「空串」值可用，不用特判。这也是 62 不同路径里「第一行第一列单独初始化」的同类操作，只是这里更简单——全填 0 就行。

### 手动推导示例 1：`text1 = "abcde"`、`text2 = "ace"`，答案是 3

`m=5`、`n=3`。`dp` 是 6 行 4 列的表（多一行一列）。行标 `i` 对应 `text1`（纵向），列标 `j` 对应 `text2`（横向）。`text1[i-1]` 取 `text1` 第 i 个字符，`text2[j-1]` 取 `text2` 第 j 个字符。

```
                j=0    j=1        j=2         j=3
                (空)   text2[0]='a'  text2[1]='c'  text2[2]='e'
i=0 (空)         0       0            0            0        ← 第一行全 0（空串 vs 任何）
i=1 text1[0]='a' 0       1            1            1
i=2 text1[1]='b' 0       1            1            1
i=3 text1[2]='c' 0       1            2            2
i=4 text1[3]='d' 0       1            2            2
i=5 text1[4]='e' 0       1            2            3   ← dp[5][3]=3，答案
```

逐格看几个关键格感受转移：

```
dp[1][1]: text1[0]='a' == text2[0]='a'  → 匹配，dp[0][0]+1 = 0+1 = 1
dp[2][1]: text1[1]='b' != text2[0]='a'  → 不匹配，max(dp[1][1], dp[2][0]) = max(1,0) = 1
dp[3][2]: text1[2]='c' == text2[1]='c'  → 匹配，dp[2][1]+1 = 1+1 = 2   ← 对应公共子序列 "ac"
dp[4][2]: text1[3]='d' != text2[1]='c'  → 不匹配，max(dp[3][2], dp[4][1]) = max(2,1) = 2
dp[5][3]: text1[4]='e' == text2[2]='e'  → 匹配，dp[4][2]+1 = 2+1 = 3   ← 公共子序列 "ace"
```

返回 `dp[5][3] = 3` ✓（对应公共子序列 `"ace"`）。

### 用一维数组把空间压到 O(n)

观察转移方程：`dp[i][j]` 只依赖三个格子——**左上 `dp[i-1][j-1]`、正上 `dp[i-1][j]`、左方 `dp[i][j-1]`**，都在「上一行」或「本行上一列」。也就是说，算第 i 行时**只需要第 i-1 行还在**，更早的行可以扔掉。

所以可以用**一个一维数组**滚动（详见「复盘 解法二」）。但有个坑：`dp[i-1][j-1]` 这个「左上」值，在内层 `j` 从小到大更新时会先被覆盖，后面 `j+1` 要用时已经丢了——所以需要**额外一个变量 `prev` 提前保存左上角**。这是 LCS 和 62 不同路径（只需左方和上方）在滚动数组上的关键区别。

## 代码

### 主解：二维动态规划（官方方法一，最直观）

```cpp
class Solution {
public:
    int longestCommonSubsequence(string text1, string text2) {
        // m、n 分别是两串长度。
        //   - string::length() 返回字符串长度（size_t 类型），这里是 5 和 3（示例 1）。
        //   - 注意：官方代码写成 int m = text1.length()，size_t 隐式转 int，长度 ≤ 1000 不会溢出。
        int m = text1.length(), n = text2.length();

        // vector<vector<int>> dp(m + 1, vector<int>(n + 1));
        //   - vector<vector<int>>：二维动态数组（数组的数组），相当于 m+1 行 n+1 列的矩阵。
        //   - 内层 vector<int>(n + 1)：构造长度 n+1、元素全 0 的内层 vector。
        //   - 外层 vector<vector<int>>(m + 1, ...)：把「长度 n+1 的 vector」复制 m+1 份。
        //   - ★ 为什么是 m+1 和 n+1（多一行一列）？
        //     因为 dp[0][*] 和 dp[*][0] 要专门表示「text1 为空串」「text2 为空串」的边界，
        //     它们全部填 0（空串和任何串的 LCS 都是 0）。有了这圈 0 兜底，
        //     i=1、j=1 开始的转移可以直接用 dp[i-1][...]、dp[...][j-1]，不用特判越界。
        //     这是「哨兵行列」技巧——多花一行一列的内存换代码简洁、不特判。
        //   - 这里 dp 全 0 初始化（vector<int>(n+1) 默认全 0），正好等价于「第一行第一列全 0」的初始条件，省了单独的初始化循环。
        vector<vector<int>> dp(m + 1, vector<int>(n + 1));

        // 双层 for 填表：i 从 1 到 m，j 从 1 到 n（跳过第 0 行第 0 列，那是哨兵）。
        //   ★ 计算顺序至关重要：必须「行优先、都从小到大」。
        //     因为 dp[i][j] 依赖 dp[i-1][j-1]、dp[i-1][j]、dp[i][j-1] 三个格子，
        //     它们必须在 dp[i][j] 之前算好：上一行（i-1）在外层循环已算完，
        //     本行上一列（j-1）在内层上一轮刚算好。行优先顺序天然满足。
        for (int i = 1; i <= m; i++) {
            // text1.at(i - 1)：取 text1 的第 i 个字符（下标 i-1）。
            //   - 为什么是 i-1 而不是 i？因为 dp 的下标 i 表示「前 i 个字符」（长度 i），
            //     而字符串下标从 0 开始，「第 i 个字符」在 text1 里是 text1[i-1]。
            //     两者错位：dp 多了一行哨兵（第 0 行表空串），所以 dp[i][*] 对应 text1[i-1]。
            //     这是本题最容易踩的下标坑，详见 Q2。
            //   - at() 和 operator[] 区别：at() 会做越界检查（越界抛 out_of_range 异常），
            //     operator[] 不检查（越界是未定义行为）。这里用哪个都行，at() 更安全。
            char c1 = text1.at(i - 1);
            for (int j = 1; j <= n; j++) {
                char c2 = text2.at(j - 1);   // 同理，第 j 个字符在下标 j-1
                if (c1 == c2) {
                    // 情况一：两字符相等（匹配上了）。
                    //   这对相同字符贡献给公共子序列，接在「两边都砍掉尾巴」的 LCS 后面：
                    //   dp[i][j] = dp[i-1][j-1] + 1（左上角格子 +1）。
                    //   注意来源是 dp[i-1][j-1]（左上），不是 dp[i-1][j]（上）或 dp[i][j-1]（左）——
                    //   因为这对字符同时消耗了 text1 第 i 个和 text2 第 j 个，两边都得往前挪一格。
                    dp[i][j] = dp[i - 1][j - 1] + 1;
                } else {
                    // 情况二：两字符不相等（匹配不上）。
                    //   尾巴字符对不上，不可能同时进公共子序列，分两种「舍弃」取较大：
                    //   dp[i-1][j]：舍弃 text1[i-1]，看 text1 前 i-1 个 vs text2 前 j 个；
                    //   dp[i][j-1]：舍弃 text2[j-1]，看 text1 前 i 个 vs text2 前 j-1 个。
                    //   max 取较大者，即「两种舍弃里更优的那种」。
                    //   - max(a, b)：<algorithm> 里的函数，返回 a、b 中较大者，O(1)。
                    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }

        // 答案是 dp[m][n]：text1 前 m 个字符（整个 text1）和 text2 前 n 个字符（整个 text2）的 LCS 长度。
        //   - 注意 dp 多了一行一列，所以右下角是 dp[m][n]，不是 dp[m-1][n-1]。
        //   - 这和 62 不同路径不一样（62 的 dp 不多开行列，右下角是 dp[m-1][n-1]），
        //     本题因为要表示「空串」，特意多开了一圈。
        return dp[m][n];
    }
};
```

**用示例 1 `text1="abcde"`、`text2="ace"` 走一遍**（填出的表见「思路」手动推导部分）：

```
i=1 c1='a': j=1 c2='a' 相等 → dp[1][1]=dp[0][0]+1=1; j=2 c2='c' 不等 → dp[1][2]=max(dp[0][2],dp[1][1])=1; j=3 c2='e' 不等 → dp[1][3]=1
i=2 c1='b': 全不等        → dp[2][1]=max(1,0)=1; dp[2][2]=max(1,1)=1; dp[2][3]=max(1,1)=1
i=3 c1='c': j=1 不等→1;   j=2 c2='c' 相等 → dp[3][2]=dp[2][1]+1=2; j=3 不等 → dp[3][3]=max(dp[2][3],dp[3][2])=max(1,2)=2
i=4 c1='d': j=1 不等→1;   j=2 不等 → dp[4][2]=max(dp[3][2],dp[4][1])=max(2,1)=2; j=3 不等 → dp[4][3]=max(2,2)=2
i=5 c1='e': j=1 不等→1;   j=2 不等 → dp[5][2]=max(dp[4][2],dp[5][1])=2; j=3 c2='e' 相等 → dp[5][3]=dp[4][2]+1=3
return dp[5][3] = 3 ✓
```

## 复杂度

- **时间**：O(mn)
  - 双层 for 填 `(m+1)×(n+1)` 的表，每格 O(1)，共 O(mn)。
  - 数据范围 `m, n ≤ 1000`，`mn ≤ 10^6`，C++ 轻松通过。
- **空间**：O(mn)（二维写法）/ O(n)（一维优化写法，见复盘）
  - 二维：开了 `(m+1)×(n+1)` 的 `dp` 矩阵。
  - 一维：因为 `dp[i][j]` 只依赖上一行，可压缩成一维数组 `n+1` 长度，外加一个保存「左上角」的临时变量。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么 `dp` 数组要多开一行一列（`m+1`、`n+1`）？

为了**表示「空串」这个边界状态**。`dp[0][j]` 表示「`text1` 取空串、`text2` 取前 j 个」的 LCS，必然是 0（空串和任何串都没有公共字符）；`dp[i][0]` 同理。这圈 0 就是「哨兵行列」。

有了它，从 `i=1`、`j=1` 开始的转移可以直接写 `dp[i-1][j-1]`、`dp[i-1][j]`、`dp[i][j-1]` 而不越界，**不用特判 `i==0` 或 `j==0`**。代价是多花一行一列内存（`O(m+n)` 额外），换来代码简洁。

对比 62 不同路径：62 的 `dp` 不多开行列，第一行第一列单独用循环初始化为 1；本题的多开一圈 + 全填 0，本质都是「把边界条件编码进表里」，只是 LCS 的边界值是 0，写起来更省事（vector 默认全 0）。

### Q2：为什么代码里取字符是 `text1[i-1]`、`text2[j-1]`，下标是 `i-1` 而不是 `i`？

因为 **`dp` 的下标含义和字符串下标错了一格**：

- `dp[i][j]` 的 `i` 表示「`text1` 的前 **i 个** 字符」（长度 i 的前缀），`i` 的范围是 `0..m`（0 表空串，m 表整个串）。
- 但 `text1` 的**字符串下标从 0 开始**，「第 i 个字符」在 `text1` 里的位置是 `text1[i-1]`（第 1 个字符在 `text1[0]`、第 2 个在 `text1[1]`……）。

所以 `dp[i][*]`（前 i 个字符）对应的「尾巴字符」是 `text1[i-1]`，两者下标差 1。这个错位完全是因为 `dp` 多了一行哨兵（第 0 行表空串），相当于把 `text1` 的字符整体「往右下平移了一格」。

记忆口诀：**「dp 的 i 是字符个数，text 的下标是位置，个数比位置多 1」**——所以 `text1[i-1]`。

### Q3：不匹配时 `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`，为什么要取这两种「舍弃」的最大？两者有重叠吗？

因为 `text1[i-1] != text2[j-1]` 时，这对尾巴字符**不可能同时**出现在公共子序列末尾（它俩根本不相等）。于是只剩两种选择：

- **舍弃 `text1[i-1]`**：公共子序列完全在 `text1[0..i-2]` 和 `text2[0..j-1]` 之间，对应 `dp[i-1][j]`；
- **舍弃 `text2[j-1]`**：公共子序列完全在 `text1[0..i-1]` 和 `text2[0..j-2]` 之间，对应 `dp[i][j-1]`。

这两种「舍弃」**覆盖了所有可能**（要么 `text1[i-1]` 不在、要么 `text2[j-1]` 不在、要么都不在，最后那种已被前两种包含），取 `max` 就是「两种里更优的」。两者确实有重叠（都不在的情况被算了两遍），但 `max` 不怕重叠——它只取较大值，重复算不影响结果。

为什么不再加一项 `dp[i-1][j-1]`？因为前缀越短 LCS 越短，`dp[i-1][j-1] ≤ dp[i-1][j]` 且 `≤ dp[i][j-1]`，`max` 里它一定被压住，加了也是白加。

### Q4：子序列和子数组有什么区别？本题和 300 最长递增子序列又是什么关系？

**子序列**（subsequence）：字符可以**跳着选**，只要求相对顺序不变，不要求连续。如 `"ace"` 是 `"abcde"` 的子序列（跳过了 `b`、`d`）。

**子数组 / 子串**（subarray / substring）：元素必须**连续**。如 `"bcd"` 是 `"abcde"` 的子串，但 `"ace"` 不是（中间断了）。

本题是「**两个串的公共子序列**」——和 300 那种「**单个数组的递增子序列**」形态不同：

| | 300 最长递增子序列 | 1143 最长公共子序列 |
|---|---|---|
| 维度 | 一维（单个数组） | 二维（两个串对齐看） |
| 状态 | `dp[i]` = 以 `nums[i]` 结尾的最长递增子序列长 | `dp[i][j]` = `text1` 前 i 个 vs `text2` 前 j 个的 LCS 长 |
| 转移 | `dp[i] = max(dp[j]+1)`，枚举所有 `j<i` 且 `nums[j]<nums[i]`（O(n) 转移） | 字符相等 `dp[i-1][j-1]+1`，否则 `max(dp[i-1][j], dp[i][j-1])`（O(1) 转移） |
| 总复杂度 | O(n²) | O(mn) |

共同点：都是「子序列 + 最值」类 DP，都靠「盯着尾巴」做转移决策。区别是 300 单串靠「枚举前驱」转移，1143 双串靠「字符匹配与否」分两种情况转移。

## 复盘

- **核心套路——「双串 DP：匹配则 +1，不匹配则取两侧 max」**：这是 LCS 及其变体的通用模板。凡是题目给**两个序列**（字符串 / 数组）让你求「公共 / 匹配 / 编辑」类最值，第一步就想：`dp[i][j]` 表示「`A` 前 i 个 vs `B` 前 j 个」的答案，然后看 `A[i-1]` 和 `B[j-1]` 是否「匹配」（相等 / 满足某种条件），匹配就走 `dp[i-1][j-1]+?`、不匹配就走 `max/min(dp[i-1][j], dp[i][j-1])`。这套框架覆盖了一大票题：
  
  | 题目 | 「匹配」条件 | 匹配时 | 不匹配时 |
  |---|---|---|---|
  | 1143 LCS | `A[i-1]==B[j-1]` | `dp[i-1][j-1]+1` | `max(dp[i-1][j], dp[i][j-1])` |
  | 72 编辑距离 | `A[i-1]==B[j-1]` | `dp[i-1][j-1]`（不花钱） | `min(替换/插入/删除)+1` |
  | 718 最长重复子数组 | `A[i-1]==B[j-1]` | `dp[i-1][j-1]+1` | `0`（要求连续，断了就归零） |
  | 583 两字符串的删除操作 | `A[i-1]==B[j-1]` | `dp[i-1][j-1]` | `min(dp[i-1][j], dp[i][j-1])+1` |
  
  其中 72 编辑距离是这一族的「最终 Boss」——把不匹配时的 `max` 换成「三种操作（替换 / 插入 / 删除）取 min」。先吃透 1143，再看 72 会非常顺。
- **「盯着最后两个字符」是双串 DP 的万能起手式**：和一维 DP「盯着最后一步」一脉相承。双串 DP 的「最后一步」就是「`A` 的最后一个字符和 `B` 的最后一个字符是否匹配」，匹配就一起消耗、不匹配就至少舍弃一个。想清楚这一步，转移方程自然就出来了。
- **维度升级不可怕**：300（一维单串）→ 1143（二维双串）→ 72（二维双串 + 三种操作）→ 10 正则匹配（二维带状态机）。每多一维只是多一个下标、多几个转移来源，核心仍是「状态定义 + 转移方程 + 初始条件」三要素。**做会 1143，等于打通了「双串 DP」这一整族**。

### 解法二：一维滚动数组优化（空间 O(n)）

把二维 `dp` 压成一维数组。思路见上方「思路」末尾。**关键坑**：`dp[i][j]` 依赖「左上 `dp[i-1][j-1]`」，在内层 `j` 从小到大更新时，`dp[j-1]`（旧值 = 上一行第 j-1 列）会先被本轮覆盖成新值，后面算 `dp[j]` 时拿到的「左上」就错了。解决办法是**用 `prev` 变量提前保存「上一行第 j-1 列」的旧值**，每轮 `j` 更新前先存、更新后把当前旧值传给下一轮。

```cpp
class Solution {
public:
    int longestCommonSubsequence(string text1, string text2) {
        int m = text1.length(), n = text2.length();
        // vector<int> dp(n + 1, 0)：一维数组，长度 n+1。
        //   - 语义：dp[j] 在每轮外层循环「开始时」存的是「上一行第 j 列」的值（即 dp_2d[i-1][j]）。
        //   - 全 0 初始化等价于「第 0 行（空串）全 0」，省了单独初始化。
        vector<int> dp(n + 1, 0);

        for (int i = 1; i <= m; i++) {
            // prev：保存「左上角」dp_2d[i-1][j-1] 的值。
            //   - 在内层循环开始前（j=1 时），「左上」就是 dp_2d[i-1][0]，即上一行第 0 列，恒为 0。
            int prev = 0;
            for (int j = 1; j <= n; j++) {
                // temp：先把「将要被覆盖的旧 dp[j]」（= 上一行第 j 列 = dp_2d[i-1][j]）存起来。
                //   - 因为下一步 dp[j] 要被更新成新值（本行第 j 列），但下一轮 j+1 的「左上」正是这个旧值。
                int temp = dp[j];
                if (text1[i - 1] == text2[j - 1]) {
                    // 匹配：dp_2d[i][j] = dp_2d[i-1][j-1] + 1 = prev + 1。
                    //   - prev 此时存的正是「上一行第 j-1 列」的旧值（左上角）。
                    dp[j] = prev + 1;
                } else {
                    // 不匹配：dp_2d[i][j] = max(dp_2d[i-1][j], dp_2d[i][j-1])。
                    //   - dp[j]（更新前）= 上一行第 j 列 = dp_2d[i-1][j]（上方）。
                    //   - dp[j-1]（已被本轮更新）= 本行第 j-1 列 = dp_2d[i][j-1]（左方）。
                    dp[j] = max(dp[j], dp[j - 1]);
                }
                // 把「刚被覆盖前的旧 dp[j]」传给下一轮当「左上」。
                //   - 对下一轮 j+1 而言，「左上」= dp_2d[i-1][(j+1)-1] = dp_2d[i-1][j]，正是这个 temp。
                prev = temp;
            }
        }
        // 循环结束时 dp[n] 就是 dp_2d[m][n]。
        return dp[n];
    }
};
```

- **时间**：O(mn)（与二维一致，双层 for 没变）。
- **空间**：O(n)（只留一维数组 + 一个 `prev` 变量）。若 `m < n`，可交换 `text1`/`text2` 让数组沿较短维度开，进一步压到 O(min(m,n))。
- **何时用**：`m`、`n` 都较大、且想省内存时。逻辑等价于二维写法，只是多了 `prev` 保存左上角的细节。初学阶段建议先吃透二维写法（思路清晰、不易出错），再来看这个一维优化版本——尤其要理解「为什么需要 `prev`」（这是 LCS 滚动数组相比 62 不同路径的关键区别）。
