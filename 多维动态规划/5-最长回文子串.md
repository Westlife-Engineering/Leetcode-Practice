# 5 最长回文子串

- 难度：中等
- 标签：**双指针**、字符串、**动态规划**
- 力扣链接：https://leetcode.cn/problems/longest-palindromic-substring/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[最长回文子串](https://leetcode.cn/problems/longest-palindromic-substring/solution/zui-chang-hui-wen-zi-chuan-by-leetcode-solution/)」（slug：`zui-chang-hui-wen-zi-chuan-by-leetcode-solution`）「方法一：动态规划」。正文主解是 **区间 DP**——用一张 `dp[i][j]` 表记录「子串 `s[i..j]` 是不是回文」，按子串长度从小到大递增填表，转移方程 `dp[i][j] = (s[i]==s[j]) && dp[i+1][j-1]`。这和 [131 分割回文串](../回溯/131-分割回文串.md) 里那张回文判断表**完全是同一个转移**——131 是「先把这张表预算好、再拿去剪枝回溯」，本题是「填表的同时顺手记录最长的那一段」。中心扩展法（O(n²) 时间 O(1) 空间）放在「复盘」作对比。

## 题目描述

给你一个字符串 `s`，找到 `s` 中最长的 **回文** 子串。

**示例 1：**

```
输入：s = "babad"
输出："bab"
解释："aba" 同样是符合题意的答案。
```

**示例 2：**

```
输入：s = "cbbd"
输出："bb"
```

**提示：**

- `1 <= s.length <= 1000`
- `s` 仅由数字和英文字母组成

## 思路

> 本题主解参考力扣官方题解「方法一：动态规划」。

题目要的是**子串本身**（不是长度、也不是个数），所以最终要记下「最长回文子串的起点和长度」，用 `s.substr(start, maxLen)` 切出来返回。

### 回文的递推结构：剥掉两端还是回文

回文的关键性质：**如果一个长度 > 2 的子串是回文，那么把它首尾两个字符去掉之后，剩下的中间部分一定也是回文**。

- 反例直觉：`"ababa"` 是回文 → 去掉首尾的 `a` 得到 `"bab"`，也是回文。
- 反过来用（这才是 DP 的发力点）：**如果已知 `"bab"` 是回文，且它两端各加同一个字符 `a`，那 `"ababa"` 必然是回文**。

这就是把「大子串是不是回文」拆成「更小的子串是不是回文」的子问题——典型的动态规划结构。

### 状态定义：`dp[i][j]` = 子串 `s[i..j]` 是否为回文

`dp` 是一张 `n × n` 的 bool 表（`n = s.length()`）。`dp[i][j]` 取 `true` 表示**闭区间**子串 `s[i..j]` 是回文串，`false` 表示不是。

- 主对角线 `dp[i][i]`：单字符子串，当然是回文 → `true`。
- 注意 `i > j`（即 `i+1 > j-1`）的格子表示「空串」，按回文定义也视为 `true`（边界，下面转移会用到）。

### 状态转移方程：`dp[i][j] = (s[i]==s[j]) && dp[i+1][j-1]`（核心！）

子串 `s[i..j]` 是回文，当且仅当**两端字符相等**（`s[i] == s[j]`）**且** 去掉两端后的内部子串 `s[i+1..j-1]` 也是回文（`dp[i+1][j-1]` 为真）。两条同时成立才成立。

把长度 ≤ 2 的边界情况合并进来，得到一行写完的转移：

```
dp[i][j] = (s[i] == s[j]) && (len < 3 || dp[i+1][j-1])
```

- `len < 3`（即子串长度 1 或 2）：只要两端相等就是回文，不用看内部（长度 1 只有一个字符必然相等；长度 2 看两字符是否相同）。此时 `i+1 > j-1`，`dp[i+1][j-1]` 那格对应「空串」，逻辑上也应是 `true`，但用 `len < 3` 短路掉更直观、也不用特意初始化空串那一圈。
- `len >= 3`：两端相等 **且** 内部 `dp[i+1][j-1]` 为真。

### 填表顺序：必须按子串长度递增（区间 DP 的灵魂！）

这是区间 DP 区别于普通二维 DP 的关键。看依赖关系：`dp[i][j]` 依赖 `dp[i+1][j-1]`——而 `s[i+1..j-1]` 的长度 = `(j-1) - (i+1) + 1 = j - i - 1`，比 `s[i..j]` 的长度 `j - i + 1` **恰好短 2**。

也就是说：**要算长度为 L 的子串，得先算完所有长度为 L-2 的子串**。所以外层循环必须是「长度」从小到大递增：

```
for (int len = 1; len <= n; len++) {        // 外层枚举子串长度
    for (int i = 0; i + len - 1 < n; i++) { // 内层枚举起点 i
        int j = i + len - 1;                // 由 len 和 i 定终点 j
        ...                                  // 填 dp[i][j]
    }
}
```

> 为什么不能像 [62 不同路径](./62-不同路径.md) 那样「行优先」填？因为这里 `dp[i][j]` 依赖的是 `dp[i+1][j-1]`——**行号更大、列号更小**，行优先遍历时 `i+1` 那一行还没算。按长度递增才能保证「更短的子串先就绪」。区间 DP 的通则：**外层按区间长度递增，内层枚举区间起点**。

### 边长过程中记录最长：`start` 和 `maxLen`

填表时，每当发现 `dp[i][j] == true` 且当前子串长度 `len > maxLen`，就更新最长回文的起点 `start = i` 和长度 `maxLen = len`。最后 `return s.substr(start, maxLen)`。

> 用严格大于 `>`（不是 `>=`）：长度相同的回文出现多次时，保留**最先发现的那一个**（起点更靠左）。例 1 里 `"bab"` 和 `"aba"` 都是长度 3 的答案，按 `len` 递增 + `>` 会先命中起点更左的 `"bab"`，正好和示例输出一致。

### 手动推导 `s = "babad"` 得 `"bab"`（例 1）

`n = 5`，下标 `0,1,2,3,4` 对应 `b,a,b,a,d`。初始 `maxLen = 0, start = 0`。

**len = 1**（`len < 3` 短路，只看 `s[i]==s[j]` 且 `i==j` 必然相等）：

```
i=0: dp[0][0]=T, 1>0 → start=0, maxLen=1
i=1,2,3,4: dp[i][i]=T, 但 1>1 不成立, 不更新
```

**len = 2**（`j=i+1`，`len<3` 短路，只看两端是否相等）：

```
i=0,j=1: s[0]=b, s[1]=a, b≠a → dp[0][1]=F
i=1,j=2: s[1]=a, s[2]=b, a≠b → dp[1][2]=F
i=2,j=3: s[2]=b, s[3]=a, b≠a → dp[2][3]=F
i=3,j=4: s[3]=a, s[4]=d, a≠d → dp[3][4]=F
（全是 false，无更新）
```

**len = 3**（`j=i+2`，此时 `len<3` 为假，启用 `dp[i+1][j-1]`）：

```
i=0,j=2: s[0]=b, s[2]=b, b==b, 且 dp[1][1]=T → dp[0][2]=T, 3>1 → start=0, maxLen=3  ← "bab"
i=1,j=3: s[1]=a, s[3]=a, a==a, 且 dp[2][2]=T → dp[1][3]=T, 3>3 不成立, 不更新      ← "aba"（同长度，保留先到的）
i=2,j=4: s[2]=b, s[4]=d, b≠d → dp[2][4]=F
```

**len = 4**（`j=i+3`）：`i=0,j=3` 两端 `b≠a`、`i=1,j=4` 两端 `a≠d`，全 false。

**len = 5**（`j=i+4`）：`i=0,j=4` 两端 `b≠d`，false。

最终 `start=0, maxLen=3` → `s.substr(0, 3) = "bab"` ✓ 与示例 1 一致。

`dp` 表（只看 `i <= j` 的上三角）最终长这样：

```
        j=0   j=1   j=2   j=3   j=4
i=0      T     F     T     F     F
i=1            T     F     T     F
i=2                  T     F     F
i=3                        T     F
i=4                              T
```

读法：`dp[0][2]=T` 即 `"bab"` 是回文；`dp[1][3]=T` 即 `"aba"` 也是回文；其余长度 ≥ 2 的格子全 false。

## 代码

```cpp
class Solution {
public:
    string longestPalindrome(string s) {
        int n = s.size();

        // vector<vector<bool>> dp(n, vector<bool>(n));
        //   - vector<vector<bool>>：二维 bool 动态数组（数组的数组）。
        //     外层有 n 个元素，每个元素又是一个 vector<bool>（长度 n）。
        //     整体是一张 n×n 的表，dp[i][j] 访问第 i 行第 j 列，读写均 O(1)。
        //   - vector<bool>(n)：构造一个长度 n、元素全 false 的内层 vector。
        //   - ★ 这里用 bool（官方用 int）是因为只关心「是/否」两种状态，语义更直接；
        //     vector<bool> 还会按位压缩存储（每位 1 bit），比 vector<int> 省 8 倍空间。
        //     代价是 vector<bool> 的 proxy 访问有点特殊（不能用 auto& 取引用），
        //     但本题只做 dp[i][j] = ... 赋值和 if(dp[i][j]) 读判断，不取引用，完全安全。
        //   - dp[i][j]=true 表示闭区间子串 s[i..j] 是回文串。
        vector<vector<bool>> dp(n, vector<bool>(n));

        int start = 0, maxLen = 0;   // 记录最长回文子串的起点和长度，最终用 substr 切出来

        // ★★★ 外层按「子串长度 len」递增——这是区间 DP 的灵魂 ★★★
        //   dp[i][j] 依赖 dp[i+1][j-1]，而 s[i+1..j-1] 比 s[i..j] 恰好短 2，
        //   所以必须先把所有更短的子串算完，才能算当前长度的子串。
        //   对比 62 不同路径的「行优先」行不通：这里依赖的是「行号+1、列号-1」的格子，
        //   行优先遍历时那一行还没算到。唯有「按长度递增」能保证依赖就绪。
        for (int len = 1; len <= n; ++len) {
            // 内层枚举「长度为 len 的子串的起点 i」。
            //   - 约束 i + len - 1 < n：保证终点 j = i+len-1 不越界（j 最大到 n-1）。
            //   - 等价写法：for (int i = 0; i <= n - len; ++i)，意思一样。
            for (int i = 0; i + len - 1 < n; ++i) {
                // 由「起点 i + 长度 len」定出终点 j（闭区间 [i, j]）。
                //   长度 = j - i + 1 = len，所以 j = i + len - 1。
                int j = i + len - 1;

                // ★★★ 状态转移方程（核心）★★★
                //   dp[i][j] = (两端字符相等) && (长度≤2 直接成立 || 否则看内部子串是否回文)
                //   - s[i] == s[j]：两端字符必须相等，否则整个子串肯定不是回文。
                //   - len < 3：长度 1（单字符）或 2（两字符）时，只要两端相等就是回文，
                //     不需要看 dp[i+1][j-1]（长度 2 时 i+1 > j-1，那格是「空串」语义上也是 true，
                //     用 len<3 短路更直观、也省得纠结空串那圈的初值）。
                //   - dp[i+1][j-1]：长度 ≥ 3 时，去掉两端后的内部子串 s[i+1..j-1] 必须也是回文。
                //     这格一定已经算过了——因为它的长度 = len-2 < len，外层按 len 递增时先算完了。
                dp[i][j] = (s[i] == s[j]) && (len < 3 || dp[i + 1][j - 1]);

                // 只要 s[i..j] 是回文，且比当前记录的更长，就更新起点和长度。
                //   - 用严格大于 >（不是 >=）：长度相同时保留最先发现的（起点更靠左），
                //     例 1 的 "bab" 和 "aba" 都是长度 3，先命中起点更左的 "bab"，与示例输出一致。
                if (dp[i][j] && len > maxLen) {
                    maxLen = len;
                    start = i;
                }
            }
        }

        // s.substr(pos, len)：STL 成员函数，返回从下标 pos 开始、长度 len 的新 string。
        //   - ★ 第二个参数是「长度」不是「终点下标」！这里是 start + maxLen - 1 才是终点，
        //     但 substr 要的是长度 maxLen，别写成 substr(start, start+maxLen)。
        //   - 时间空间均 O(len)，即 O(maxLen) ≤ O(n)。
        return s.substr(start, maxLen);
    }
};
```

## 复杂度

- **时间**：O(n²)，其中 `n = s.length()`。
  - 双层 for 填 `n×n` 表的上三角，每格 O(1)（一次字符比较 + 一次 bool 运算），共 O(n²) 个状态。
  - 最后一次 `substr` 是 O(n)，被 O(n²) 主导。
- **空间**：O(n²)。
  - `dp` 表 `n×n`，占 O(n²)。`n ≤ 1000` 时约 10⁶ 个 bool，`vector<bool>` 按位压缩后约 125 KB，可接受。
  - 中心扩展法可把空间压到 O(1)，见「复盘」。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么外层必须「按长度 len 递增」填表，不能像 62 不同路径那样行优先？

因为依赖方向不同。看 `dp[i][j] = ... && dp[i+1][j-1]`：它依赖的格子 `dp[i+1][j-1]` **行号更大（i+1）、列号更小（j-1）**。

- 行优先（外层 i 从小到大、内层 j 从小到大）：算 `dp[i][j]` 时，`dp[i+1][...]`（下一行）**根本还没算到**，会读到未初始化的 false，结果全错。
- 按长度递增：`s[i+1..j-1]` 的长度 = `len - 2`，比当前 `len` 小。外层 `len` 从 1 涨到 n 时，长度 `len-2` 的格子早在几轮前就填好了，依赖一定就绪。

口诀：**区间 DP 外层按区间长度递增，内层枚举起点**。这是所有「`dp[i][j]` 依赖更短的 `dp[i+1][j-1]`」类问题（5、647 回文子串、131 的回文表预处理、718 等）的通用填法。

> 另一种等价写法（[131 分割回文串](../回溯/131-分割回文串.md) 用的）：外层 `i` 从 `n-1` 往下到 0、内层 `j` 从 `i+1` 到 `n-1`。这样算 `dp[i][j]` 时依赖的 `dp[i+1][j-1]`（行 i+1 已算完、列 j-1 也算过）也一定就绪。两种写法等价，按长度递增更直白地体现「先短后长」的区间 DP 思想，所以本题主解用它。

### Q2：`dp[i][j]` 到底依赖谁？`len < 3` 这个特判是干嘛的，能不能去掉？

`dp[i][j]` 依赖 `dp[i+1][j-1]`（内部子串的回文性）。但当 `len` 很小时这个依赖会「退化」：

- `len = 1`（`i == j`）：`dp[i+1][j-1] = dp[i+1][i]`，这里 `i+1 > i`，对应「空串」。空串按定义算回文，所以这格语义上应是 true——但代码里 `dp` 表只开了 `n×n`，`dp[i+1][i]` 这种 `行 > 列` 的格子没初始化过（`vector<bool>` 默认 false），直接用会出错。
- `len = 2`（`j = i+1`）：`dp[i+1][j-1] = dp[i+1][i]`，又是「空串」那一圈，同样没初始化。

所以 `len < 3 || ...` 这个短路有两个作用：(1) 语义上「长度 1 或 2 只要两端相等就是回文」本就成立；(2) 规开 `dp[i+1][i]` 这个未初始化的空串格子，不用专门去初始化「`行 > 列`」那一圈。**不能直接去掉**，否则长度 1、2 的子串会读到 false 导致全错。

> 另一种处理方式（131 的写法）：把整张 `dp` 表初始化为全 true，这样空串那圈自动是 true，转移就能统一写成 `dp[i][j] = (s[i]==s[j]) && dp[i+1][j-1]` 不带特判。两种写法等价，本题用「全 false 初值 + `len<3` 特判」更省一步初始化、也更贴近官方代码。

### Q3：`start` 和 `maxLen` 为什么用「严格大于 `>`」更新？改成 `>=` 会怎样？

改成 `>=` 会让「长度相同的回文」后来者覆盖先到者，即保留**起点更靠右**的那个。例 1 里 `"bab"`（起点 0）和 `"aba"`（起点 1）都是长度 3：

- 用 `>`（本题写法）：先命中 `"bab"`（len=3 那轮 i=0 先算），`"aba"`（i=1）来时 `3 > 3` 不成立，不覆盖 → 返回 `"bab"`，与示例一致。
- 用 `>=`：`"aba"` 会覆盖 → 返回 `"aba"`。

题目说「`"aba"` 同样是符合题意的答案」，所以两种都能 AC。但**习惯上用 `>` 保留最先发现的（更靠左的）**，和示例输出对齐，调试时也更好对照。

### Q4：本题和 [131 分割回文串](../回溯/131-分割回文串.md) 是什么关系？同一张 `dp` 表？

**完全是同一个转移方程**，都是区间 DP 的经典 `dp[i][j] = (s[i]==s[j]) && dp[i+1][j-1]`。区别只在「这张表算出来干嘛用」：

| | 5 最长回文子串 | 131 分割回文串 |
|---|---|---|
| 表的用途 | 填表时**顺手**找最长的 `dp[i][j]==true` 那段 | **预算**好整张表，回溯里 O(1) 查表做剪枝 |
| 主算法 | 纯区间 DP | 回溯（表只是预处理工具） |
| 填表顺序 | 按长度递增（`for len`） | `i` 从 n-1 往下到 0（等价写法） |
| 返回 | 子串本身（一个 string） | 所有分割方案（二维 vector） |

一句话：**5 是「区间 DP 本体」，131 是「区间 DP 当工具」**。把 5 的转移吃透，131 那张回文表就是白送。这也是为什么本题落 `多维动态规划/`——它就是区间 DP 的母题之一。

## 复盘

- **可迁移套路——「区间 DP：按长度递增填表」**。凡是「`dp[i][j]` 描述一段连续区间 `[i, j]` 的某种属性、且转移依赖更短的子区间」的问题，通法都是：
  1. 状态 `dp[i][j]` = 区间 `[i, j]` 上的答案（回文性、最值、方案数……）；
  2. 转移从「更短的子区间」拼出「当前区间」（如 `dp[i][j] = g(s[i], s[j]) && dp[i+1][j-1]`）；
  3. **外层按区间长度递增**（`for len = 1..n`），内层枚举起点 `i`，由 `len` 和 `i` 定终点 `j`。
  
  同族题：647 回文子串（几乎和本题一模一样，只是改成「数有多少个回文子串」）、131 分割回文串的回文表预处理、516 最长回文子序列、312 戳气球、87 扰乱字符串。**5 题练熟，区间 DP 这一类就通了**。
- **回文类问题的统一转移 `dp[i][j] = (s[i]==s[j]) && dp[i+1][j-1]`**。回文判断、最长回文子串、回文子串计数、回文串切割，全是这一个转移，记住即可。边界靠「长度 ≤ 2 特判」或「全 true 初值」两种方式处理，二选一。
- **「记录答案」的两种位置**：本题在「填表时」顺手更新 `start/maxLen`（因为答案就是某个 `dp[i][j]==true` 里最长那段）；也有的题在「填完表后」再扫一遍找最优。前者少一次遍历，但要求答案能在填表过程中唯一确定；后者更稳但多 O(n²)。本题两种都行，主解用前者。

### 解法二：中心扩展法（官方方法二，O(n²) 时间 O(1) 空间）

仔细看主解的状态转移链：`dp[i][j] ← dp[i+1][j-1] ← dp[i+2][j-2] ← ... ← 某个长度 1 或 2 的边界`。**每个状态在转移时来源是唯一的**——也就是说，与其用一张表把所有状态都存下来，不如「从每个回文中心出发，往两边扩展，直到两边字符不等为止」。这就是中心扩展法。

回文中心共 `2n - 1` 个：n 个长度为 1 的中心（奇数长度回文，`s[i]` 为中心）+ `n - 1` 个长度为 2 的中心（偶数长度回文，`s[i]` 和 `s[i+1]` 中间为中心）。每个中心最多向外扩展 O(n) 次。

```cpp
class Solution {
public:
    // 从 (left, right) 出发向两边扩展，返回能扩展出的最长回文子串的 [起, 止] 下标。
    //   - left == right：奇数长度回文，中心是单个字符 s[i]。
    //   - left == right-1：偶数长度回文，中心在 s[i] 和 s[i+1] 之间。
    //   - pair<int,int>：STL 存两个 int 的结构体，.first/.second 取元素。
    pair<int, int> expandAroundCenter(const string& s, int left, int right) {
        // 只要两边都在界内、且两字符相等，就继续往外扩。
        while (left >= 0 && right < s.size() && s[left] == s[right]) {
            --left;
            ++right;
        }
        // 循环跳出时 s[left] != s[right]（或越界），所以真正有效的回文是 (left+1, right-1)。
        return {left + 1, right - 1};
    }

    string longestPalindrome(string s) {
        int start = 0, end = 0;   // 记录最长回文的 [起, 止] 下标
        for (int i = 0; i < s.size(); ++i) {
            // auto [a, b] = ...：C++17 结构化绑定，把 pair 的两个元素直接解到 a、b。
            //   每个 i 都试两种中心：奇数（i,i）和偶数（i,i+1）。
            auto [left1, right1] = expandAroundCenter(s, i, i);
            auto [left2, right2] = expandAroundCenter(s, i, i + 1);
            // 谁扩出来的长就更新谁（用 right-left 即长度-1 比较即可，省得 +1）。
            if (right1 - left1 > end - start) { start = left1; end = right1; }
            if (right2 - left2 > end - start) { start = left2; end = right2; }
        }
        return s.substr(start, end - start + 1);
    }
};
```

- **时间**：O(n²)——`2n-1` 个中心，每个最多扩展 O(n) 次。
- **空间**：O(1)——不用 `dp` 表，只用几个下标变量。这是它相对区间 DP 的最大优势。
- **对比**：和区间 DP 同为 O(n²) 时间，但空间从 O(n²) 降到 O(1)，常数也更小。**面试里通常首选中心扩展法**（更快更省）。区间 DP 的价值在于：(1) 思路更直白地体现「回文 = 两端相等 + 内部回文」的递推结构；(2) `dp` 表能复用到 647、131 等题；(3) 是理解 Manacher 算法的前置。所以本题主解落区间 DP，和目录主题「多维动态规划」对应；做题时两种都该会。
