# 72 编辑距离

- 难度：中等
- 标签：字符串、**动态规划**
- 力扣链接：https://leetcode.cn/problems/edit-distance/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[编辑距离](https://leetcode.cn/problems/edit-distance/solution/bian-ji-ju-chi-by-leetcode-solution/)」。正文主解是 **方法一：动态规划（二维）**——这是 **DP 最经典的难题之一**，状态 `dp[i][j]` 表示 `word1` 前 i 个字符变成 `word2` 前 j 个字符所用的最少操作数。和 1143 最长公共子序列**同框架**（都是双串 DP，盯着「最后两个字符是否相等」分情况），但 1143 不匹配时只有「舍弃一个」两种选择，72 多了「**插入 / 删除 / 替换**」三种操作，转移从 `max` 升级成 `1 + min(三选一)`。可以说 **72 是 1143 的完全体**，也是「多维动态规划」组的收尾题。官方题解只给了这一种解法，空间优化的滚动数组写法放在「复盘」。

## 题目描述

给你两个单词 `word1` 和 `word2`，请返回将 `word1` 转换成 `word2` 所使用的最少操作数。

你可以对一个单词进行如下**三种操作**：

- 插入一个字符
- 删除一个字符
- 替换一个字符

**示例 1：**

```
输入：word1 = "horse", word2 = "ros"
输出：3
解释：
horse -> rorse (将 'h' 替换为 'r')
rorse -> rose  (删除 'r')
rose  -> ros   (删除 'e')
```

**示例 2：**

```
输入：word1 = "intention", word2 = "execution"
输出：5
解释：
intention -> inention  (删除 't')
inention  -> enention  (将 'i' 替换为 'e')
enention  -> exention  (将 'n' 替换为 'x')
exention  -> exection  (将 'n' 替换为 'c')
exection  -> execution (插入 'u')
```

**提示：**

- `0 <= word1.length, word2.length <= 500`
- `word1` 和 `word2` 由小写英文字母组成

## 思路

> 本题主要参考力扣官方题解「方法一：动态规划」。

要求「把 `word1` 变成 `word2` 的**最少操作数**」，每次可以「插入 / 删除 / 替换」一个字符。这是经典的 **编辑距离（Edit Distance）问题**，也叫 Levenshtein 距离。

如果暴力枚举：每种操作都试一遍、把所有可能的编辑序列都走一遍取最短——操作序列是**指数级**的（`word1` 长度稍微一大就爆炸）。得找**递推关系**：能不能用「把 `word1` 更短的前缀变成 `word2` 更短的前缀」的最少操作数，推出「更长前缀之间」的最少操作数？

这正是 1143 LCS 的同款思路：盯着**两个串的「最后两个字符」**看，分「相等 / 不相等」两种情况列转移。

### DP 三要素（和 1143 LCS 同框架，只是不匹配时多出「三种操作」）

#### ① 状态定义：`dp[i][j]` = `word1` 的前 i 个字符变成 `word2` 的前 j 个字符所需的最少操作数

两个下标 `i`、`j` 分别对应两个字符串，所以是**二维**状态。`dp[m][n]`（`m`、`n` 是两串长度）就是答案。

> **为什么是「前 i 个字符」「前 j 个字符」，而不是「以下标 i 结尾」？**
>
> 和 1143 一样：编辑距离关心的是「`word1` 的前缀 变成 `word2` 的前缀」这件事，定义成「前 i 个 vs 前 j 个」后，「在尾部加 / 减一个字符」这个动作对应 `i+1` 或 `j+1`，转移最自然。
>
> 这里的「前 i 个字符」指 `word1[0..i-1]`（长度为 i 的前缀），官方记作 `word1[0:i]`。

#### ② 状态转移方程（核心难点！分「字符相等 / 不相等」两种情况，三种操作逐一对应）

**盯着「最后两个字符」看**——也就是 `word1` 的第 i 个字符 `word1[i-1]` 和 `word2` 的第 j 个字符 `word2[j-1]`（下标 `i-1`、`j-1` 的错位见 Q2）。它们只有两种关系：

**情况一：`word1[i-1] == word2[j-1]`（这两个字符相等）**

太好了，这对相同字符**不需要任何操作**——它已经「免费」对齐了。问题直接归约到「两边都把尾巴砍掉」：`word1` 前 i-1 个变成 `word2` 前 j-1 个的最少操作数：

```
dp[i][j] = dp[i-1][j-1]          （不用操作，直接继承）
```

> 直觉：尾巴字符一样，那就保持原样，剩下的工作全在前面的 i-1 / j-1 个字符身上。

**情况二：`word1[i-1] != word2[j-1]`（这两个字符不相等）**

这时候**必须做一次操作**让它们对齐。题目给了三种操作，**每种操作对应一个子问题**，把三种里取最小、再加 1（这一步操作本身的代价）：

```
dp[i][j] = 1 + min(
    dp[i-1][j],      // 操作 A
    dp[i][j-1],      // 操作 B
    dp[i-1][j-1]     // 操作 C
)
```

**三种操作分别对应哪个 `dp`？这是本题最容易绕晕的地方，必须一个个对清楚**：

| 取的 `dp` | 对应操作 | 直觉解释 |
|---|---|---|
| `dp[i-1][j] + 1` | **删除** `word1[i-1]` | 「先把 `word1` 前 i-1 个变成 `word2` 前 j 个」花 `dp[i-1][j]` 步，再**删掉**多余的 `word1[i-1]`（一步），就得到「`word1` 前 i 个 → `word2` 前 j 个」。`word1` 这边消耗掉了一个字符（i 减 1），`word2` 这边没动。 |
| `dp[i][j-1] + 1` | **插入** 一个字符到 `word1` 末尾 | 「先把 `word1` 前 i 个变成 `word2` 前 j-1 个」花 `dp[i][j-1]` 步，再往 `word1` 末尾**插入**一个字符（= `word2[j-1]`，一步），就匹配上了。`word2` 这边还差一个字符没对上（j 减 1），靠插入补齐。 |
| `dp[i-1][j-1] + 1` | **替换** `word1[i-1]` 为 `word2[j-1]` | 「先把 `word1` 前 i-1 个变成 `word2` 前 j-1 个」花 `dp[i-1][j-1]` 步，再**把** `word1[i-1]` **替换成** `word2[j-1]`（一步），两边同时各消耗一个字符。 |

> **怎么记忆「哪个方向对应哪个操作」？**
>
> 看 `dp` 的下标：**哪个串的「消耗」被减掉了，就说明操作发生在哪个串上**。
> - `dp[i-1][j]`：`word1` 的下标减 1（消耗了 `word1` 的一个字符）、`word2` 没减 → 操作发生在 `word1` 上且让它「变短」 → **删除 `word1[i-1]`**。
> - `dp[i][j-1]`：`word1` 没减、`word2` 的下标减 1 → `word2` 还差一个字符没匹配 → 往 `word1` 里**插入**一个字符去对上它。
> - `dp[i-1][j-1]`：两边都减 1 → 两边同时消耗一个字符 → 用**一次替换**让 `word1[i-1]` 变成 `word2[j-1]`。
>
> 三个子问题里 `min` 取最小者，表示「三种操作里挑最省事的那个」。每种操作都加了 1（这一步操作的代价），所以是 `1 + min(...)`。

**合起来（官方转移方程）：**

```
                ⎧ dp[i-1][j-1],                                                        若 word1[i-1] == word2[j-1]
dp[i][j] =      ⎨
                ⎩ 1 + min( dp[i-1][j],  dp[i][j-1],  dp[i-1][j-1] ),                  若 word1[i-1] != word2[j-1]
                          (删除)         (插入)         (替换)
```

一句话总结：**「字符相等就白嫖左上角；不相等就在三种操作（删 / 插 / 改）里挑最便宜的一种，各加 1」**。

#### ③ 初始条件：`dp[i][0] = i`（全删）、`dp[0][j] = j`（全插）

- `dp[i][0]`：`word1` 前 i 个字符 → `word2` 取前 0 个（空串）。把 `word1` 全删光即可，要删 i 次，所以 `dp[i][0] = i`。
- `dp[0][j]`：`word1` 取空串 → `word2` 前 j 个字符。往空串里插入 j 个字符即可，所以 `dp[0][j] = j`。
- 特别地 `dp[0][0] = 0`（空串到空串，零操作）。

> **为什么是 i 和 j，而不是 0？** 这就是 72 和 1143 的**关键区别**。1143 里空串和任何串的 LCS 长度是 0，所以第一行第一列全填 0。但 72 里「空串 → 非空串」要花 j 次插入、「非空串 → 空串」要花 i 次删除，**操作数随长度线性增长**。所以这里 `dp[i][0]` 必须填 i、`dp[0][j]` 必须填 j，否则后面所有转移都从错的起点推下去。
>
> 这也是为什么 `dp` 数组要**多开一行一列**（下标到 `m+1`、`n+1`）：第一行第一列专门表示「和空串互转」的边界，手动填上 i / j 后，`i=1`、`j=1` 开始的转移就有现成的边界值可用，不用特判越界。这是「哨兵行列」技巧——多花一行一列内存换代码简洁。

### 手动推导示例 1：`word1 = "horse"`、`word2 = "ros"`，答案是 3

`m=5`、`n=3`。`dp` 是 6 行 4 列的表（多一行一列）。行标 `i` 对应 `word1`（纵向），列标 `j` 对应 `word2`（横向）。`word1[i-1]` 取 `word1` 第 i 个字符，`word2[j-1]` 取 `word2` 第 j 个字符。

先填第一行第一列（边界）：第一列 `dp[i][0]=i`（0,1,2,3,4,5），第一行 `dp[0][j]=j`（0,1,2,3）。然后逐格用转移方程推：

```
                j=0     j=1            j=2             j=3
                (空)    word2[0]='r'   word2[1]='o'    word2[2]='s'
i=0 (空)         0       1             2               3          ← 第一行：dp[0][j]=j（空串→word2 前j个，全插）
i=1 word1[0]='h' 1       1             2               3
i=2 word1[1]='o' 2       2             1               2
i=3 word1[2]='r' 3       2             2               2
i=4 word1[3]='s' 4       3             3               2
i=5 word1[4]='e' 5       4             4               3          ← dp[5][3]=3，答案
```

逐格看几个关键格感受转移：

```
dp[1][1]: word1[0]='h' != word2[0]='r'  → 不等，1+min(dp[0][1]=1 删, dp[1][0]=1 插, dp[0][0]=0 改) = 1+0 = 1   ← 替换 h→r 最省
dp[1][2]: word1[0]='h' != word2[1]='o'  → 1+min(dp[0][2]=2, dp[1][1]=1, dp[0][1]=1) = 1+1 = 2
dp[2][2]: word1[1]='o' == word2[1]='o'  → 相等，dp[1][1] = 1                                   ← 'o' 白嫖，不操作
dp[3][1]: word1[2]='r' == word2[0]='r'  → 相等，dp[2][0] = 2                                   ← 'r' 白嫖
dp[5][3]: word1[4]='e' != word2[2]='s'  → 1+min(dp[4][3]=2 删, dp[5][2]=4 插, dp[4][2]=3 改) = 1+2 = 3
```

返回 `dp[5][3] = 3` ✓（对应题目给的方案：替换 `h→r`、删 `r`、删 `e`）。

## 代码

### 主解：二维动态规划（官方方法一，最直观）

```cpp
class Solution {
public:
    int minDistance(string word1, string word2) {
        // m、n 分别是两串长度。
        //   - string::length() 返回字符串长度（size_t 类型）。
        //   - 这里 m=word1 长度、n=word2 长度（与官方代码的 n/m 顺序相反，但本质等价，
        //     用 m/n 与 1143 LCS 笔记保持一致，方便对照）。
        int m = word1.length(), n = word2.length();

        // vector<vector<int>> dp(m + 1, vector<int>(n + 1));
        //   - vector<vector<int>>：二维动态数组（数组的数组），相当于 (m+1) 行 (n+1) 列的矩阵。
        //   - 内层 vector<int>(n + 1)：构造长度 n+1、元素全 0 的内层 vector。
        //   - 外层把内层复制 m+1 份，得到一张 (m+1)×(n+1) 的表。
        //   - ★ 为什么是 m+1 和 n+1（多一行一列）？
        //     因为 dp[0][*] 和 dp[*][0] 要专门表示「word1 为空串」「word2 为空串」的边界。
        //     和 1143 LCS 不同，这里的边界值不是全 0，而是 i 和 j（见下方初始化）。
        //     有了这圈边界兜底，i=1、j=1 开始的转移可以直接用 dp[i-1][...]、dp[...][j-1]，不用特判越界。
        //     这是「哨兵行列」技巧——多花一行一列内存换代码简洁、不特判。
        vector<vector<int>> dp(m + 1, vector<int>(n + 1));

        // ③ 初始条件之一：第一列 dp[i][0] = i。
        //   dp[i][0] = 「word1 前 i 个 → word2 空（前 0 个）」的最少操作数。
        //   把 word1 全删光即可，要删 i 次，所以 dp[i][0] = i。
        //   ★ 注意：这里是 i，不是 0！这是 72 和 1143 的关键区别（1143 空串 LCS 是 0）。
        //     如果误填 0，后面所有转移都会从错的起点推下去，全盘皆错。
        for (int i = 0; i <= m; i++) {
            dp[i][0] = i;
        }

        // ③ 初始条件之二：第一行 dp[0][j] = j。
        //   dp[0][j] = 「word1 空串 → word2 前 j 个」的最少操作数。
        //   往空串里插入 j 个字符即可，所以 dp[0][j] = j。
        for (int j = 0; j <= n; j++) {
            dp[0][j] = j;
        }

        // ② 状态转移：双层 for 填表，i 从 1 到 m，j 从 1 到 n（跳过第 0 行第 0 列哨兵）。
        //   ★ 计算顺序至关重要：必须「行优先、都从小到大」。
        //     因为 dp[i][j] 依赖 dp[i-1][j-1]、dp[i-1][j]、dp[i][j-1] 三个格子，
        //     它们必须在 dp[i][j] 之前算好：上一行（i-1）在外层循环已算完，
        //     本行上一列（j-1）在内层上一轮刚算好。行优先顺序天然满足。
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                // word1[i - 1]：取 word1 的第 i 个字符（下标 i-1）。
                //   ★ 为什么是 i-1 而不是 i？因为 dp 的下标 i 表示「前 i 个字符」（长度 i），
                //     而字符串下标从 0 开始，「第 i 个字符」在 word1 里是 word1[i-1]。
                //     两者错位：dp 多了一行哨兵（第 0 行表空串），所以 dp[i][*] 对应 word1[i-1]。
                //     这是本题最容易踩的下标坑，详见 Q2。
                if (word1[i - 1] == word2[j - 1]) {
                    // 情况一：两字符相等，这对相同字符不花任何操作，白嫖左上角。
                    //   dp[i][j] = dp[i-1][j-1]（直接继承「两边都砍掉尾巴」的子问题答案）。
                    //   注意来源是 dp[i-1][j-1]（左上），不是 dp[i-1][j]（上）或 dp[i][j-1]（左）——
                    //   因为这对匹配字符同时消耗了 word1 第 i 个和 word2 第 j 个，两边都得往前挪一格。
                    dp[i][j] = dp[i - 1][j - 1];
                } else {
                    // 情况二：两字符不相等，必须做一次操作。三种操作各对应一个子问题，取最小再 +1：
                    //
                    //   dp[i-1][j] + 1     ← 删除 word1[i-1]：
                    //     word1 这边消耗一个字符（i-1）、word2 没动，靠「删掉 word1 多余的这个字符」对齐。
                    //   dp[i][j-1] + 1     ← 插入一个字符到 word1 末尾（= word2[j-1]）：
                    //     word2 还差一个字符没对上（j-1），往 word1 里插一个补齐。
                    //   dp[i-1][j-1] + 1   ← 替换 word1[i-1] 为 word2[j-1]：
                    //     两边同时各消耗一个字符，用一次替换让它们对齐。
                    //
                    //   min({a, b, c})：<algorithm> 里的函数，这里用 initializer_list（花括号 { }）写法，
                    //     一次传入三个值，返回最小者。等价于 min(a, min(b, c))，但更直观。
                    //     O(1)。复杂度 O(1)。
                    dp[i][j] = 1 + min({dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]});
                    //              ↑ 删除(上)      ↑ 插入(左)      ↑ 替换(左上)
                }
            }
        }

        // 答案是 dp[m][n]：word1 前 m 个字符（整个 word1）变成 word2 前 n 个字符（整个 word2）的最少操作数。
        //   - 注意 dp 多了一行一列，所以右下角是 dp[m][n]，不是 dp[m-1][n-1]。
        //   - 这和 1143 LCS 一致（都为表示「空串」多开了一圈），但和 62 不同路径不一样（62 不多开，右下角是 dp[m-1][n-1]）。
        return dp[m][n];
    }
};
```

**用示例 1 `word1="horse"`、`word2="ros"` 走一遍**（填出的表见「思路」手动推导部分）：

```

  j=3 's' 不等 → 1+min(dp[0][3]=3, dp[1][2]=2, dp[0][2]=2) = 3

  j=1 'r' 不等 → 1+min(dp[1][1]=1, dp[2][0]=2, dp[1][0]=1) = 2
  j=2 'o' 相等 → dp[1][1] = 1     ← 'o' 白嫖
```

## 复杂度

- **时间**：O(mn)
  - 双层 for 填 `(m+1)×(n+1)` 的表，每格 O(1)（一次比较 + 一次 `min`），共 O(mn)。
  - 数据范围 `m, n ≤ 500`，`mn ≤ 2.5×10^5`，C++ 轻松通过。
- **空间**：O(mn)（二维写法）/ O(n)（一维优化写法，见复盘）
  - 二维：开了 `(m+1)×(n+1)` 的 `dp` 矩阵。
  - 一维：因为 `dp[i][j]` 只依赖上一行，可压缩成一维数组 `n+1` 长度，外加一个保存「左上角」的临时变量。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么三种操作分别对应那三个 `dp`？插入和删除的方向老记混。

记忆口诀：**「哪个串的下标被减掉了，操作就发生在哪个串上」**。

- `dp[i-1][j]`：`word1` 的下标 i 减 1、`word2` 的 j 没减 → `word1` 这边「多消耗」了一个字符 → 操作是**删掉 `word1[i-1]`**。
- `dp[i][j-1]`：`word1` 的 i 没减、`word2` 的 j 减 1 → `word2` 这边「还差一个」字符没对上 → 操作是**往 `word1` 里插入**一个字符（= `word2[j-1]`）。
- `dp[i-1][j-1]`：两边都减 1 → 两边同时各消耗一个字符 → 操作是**一次替换**（`word1[i-1]` → `word2[j-1]`）。

再换个角度想「插入 / 删除其实是对称的」：**在 `word1` 上插入一个字符**，等价于**在 `word2` 上删除一个字符**（因为 `word1 → word2` 的插入，就是 `word2 → word1` 的删除）。所以 `dp[i][j-1]+1`（往 `word1` 插）和「删 `word2[j-1]`」其实是一回事，方向看似乱但操作数完全等价。本题只求「把 `word1` 变成 `word2`」的最少步数，所以一律按「在 `word1` 上动手」来记即可。

### Q2：为什么代码里取字符是 `word1[i-1]`、`word2[j-1]`，下标是 `i-1` 而不是 `i`？

因为 **`dp` 的下标含义和字符串下标错了一格**：

- `dp[i][j]` 的 `i` 表示「`word1` 的前 **i 个** 字符」（长度 i 的前缀），`i` 的范围是 `0..m`（0 表空串，m 表整个串）。
- 但 `word1` 的**字符串下标从 0 开始**，「第 i 个字符」在 `word1` 里的位置是 `word1[i-1]`（第 1 个字符在 `word1[0]`、第 2 个在 `word1[1]`……）。

所以 `dp[i][*]`（前 i 个字符）对应的「尾巴字符」是 `word1[i-1]`，两者下标差 1。这个错位完全是因为 `dp` 多了一行哨兵（第 0 行表空串），相当于把 `word1` 的字符整体「往右下平移了一格」。这条坑和 1143 LCS 完全一样。

记忆口诀：**「dp 的 i 是字符个数，word 的下标是位置，个数比位置多 1」**——所以 `word1[i-1]`。

### Q3：初始条件 `dp[i][0] = i`、`dp[0][j] = j`，为什么不能填 0？（这是和 1143 LCS 最大的区别）

因为编辑距离里「空串 ↔ 非空串」**不是零代价**：

- `dp[i][0]`：`word1` 前 i 个 → `word2` 空串，要把 `word1` 这 i 个字符**全删掉**，操作数就是 i。
- `dp[0][j]`：`word1` 空串 → `word2` 前 j 个，要往空串里**插入** j 个字符，操作数就是 j。

对比 1143 LCS：那里 `dp[i][0]=dp[0][j]=0`，因为空串和任何串的「公共子序列长度」就是 0。**LCS 求的是「公共长度」，空串贡献 0；编辑距离求的是「操作步数」，空串要花满 i / j 步**。两题框架一模一样，但边界值含义不同，这是最容易照搬 1143 时踩的坑——第一行第一列必须填 i / j，不能复制粘贴成全 0。

### Q4：和 1143 LCS 到底是什么关系？

**72 是 1143 的完全体，框架同构，只是不匹配时的转移更「重」**：

| | 1143 最长公共子序列 | 72 编辑距离 |
|---|---|---|
| 求什么 | 两个串的公共子序列的**最长长度**（求最大） | 把 `word1` 变成 `word2` 的**最少操作数**（求最小） |
| 状态 | `dp[i][j]` = `text1` 前 i 个 vs `text2` 前 j 个的 LCS 长 | `dp[i][j]` = `word1` 前 i 个 → `word2` 前 j 个的最少操作数 |
| 字符相等时 | `dp[i-1][j-1] + 1`（匹配，长度 +1） | `dp[i-1][j-1]`（匹配，白嫖，0 操作） |
| 字符不等时 | `max(dp[i-1][j], dp[i][j-1])`（两种「舍弃」取大） | `1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])`（三种操作取小 +1） |
| 初始条件 | `dp[i][0]=dp[0][j]=0`（空串 LCS 是 0） | `dp[i][0]=i, dp[0][j]=j`（空串互转要花满长度） |

**核心套路一样**：双串 DP，盯着「最后两个字符」分「相等 / 不相等」两种情况。1143 的「不等」是「二选一取 max」（求最长，越长约好）；72 的「不等」是「三选一取 min 再 +1」（求最少，越少越好，且多出「替换」这种「两边同时消耗一个字符」的操作）。**吃透 1143，72 就只剩「把 max 换成 1+min、把 0 边界换成 i/j 边界」这两处改动**。

## 复盘

- **核心套路——「双串 DP：字符匹配则继承，不匹配则取操作最小」**：和 1143 LCS 同一族。凡是题目给**两个序列**（字符串 / 数组）让你求「公共 / 匹配 / 编辑」类最值，第一步就想：`dp[i][j]` 表示「`A` 前 i 个 vs `B` 前 j 个」的答案，然后看 `A[i-1]` 和 `B[j-1]` 是否「匹配」，匹配就走 `dp[i-1][j-1]+?`、不匹配就走 `max/min(dp[i-1][j], dp[i][j-1], ...)`。这套框架覆盖了一大票题：

  | 题目 | 「匹配」条件 | 匹配时 | 不匹配时 |
  |---|---|---|---|
  | 1143 LCS | `A[i-1]==B[j-1]` | `dp[i-1][j-1]+1` | `max(dp[i-1][j], dp[i][j-1])` |
  | **72 编辑距离** | `A[i-1]==B[j-1]` | `dp[i-1][j-1]`（不花钱） | `1+min(dp[i-1][j]删, dp[i][j-1]插, dp[i-1][j-1]改)` |
  | 718 最长重复子数组 | `A[i-1]==B[j-1]` | `dp[i-1][j-1]+1` | `0`（要求连续，断了就归零） |
  | 583 两字符串的删除操作 | `A[i-1]==B[j-1]` | `dp[i-1][j-1]` | `min(dp[i-1][j], dp[i][j-1])+1`（只允许删） |

  其中 72 是这一族的「最终 Boss」——把不匹配时的 `max` 换成「三种操作取 `min`」，是 1143 的完全体。

- **「盯着最后两个字符」是双串 DP 的万能起手式**：和一维 DP「盯着最后一步」一脉相承。双串 DP 的「最后一步」就是「`A` 的最后一个字符和 `B` 的最后一个字符是否相等」，相等就一起消耗、不消耗操作；不等就在「删 / 插 / 改」三种让它们对齐的方式里挑最省的。想清楚这一步，转移方程自然就出来了。

- **维度升级不可怕**：62 不同路径（二维网格）→ 1143 LCS（二维双串，匹配取 max）→ 72 编辑距离（二维双串 + 三种操作取 min）→ 10 正则表达式匹配（二维带状态机）。每多一维只是多一个下标、多几个转移来源，核心仍是「状态定义 + 转移方程 + 初始条件」三要素。**做会 72，等于打通了「双串 DP」这一整族的 Boss 关**，多维动态规划组到此收尾。

- **空间优化通用判据**：转移方程只依赖「有限的前驱」（本题只看上一行的三个格子），就能把二维压成一维。但和 1143 一样有坑：`dp[i-1][j-1]` 这个「左上」值，在内层 `j` 从小到大更新时会先被覆盖，需要**额外一个变量 `prev` 提前保存左上角**（见下方解法二）。

### 解法二：一维滚动数组优化（空间 O(n)）

把二维 `dp` 压成一维数组。思路：`dp[i][j]` 只依赖 `dp[i-1][j-1]`（左上）、`dp[i-1][j]`（上）、`dp[i][j-1]`（左）三个格子，都在「上一行」或「本行上一列」，算第 i 行时**只需要第 i-1 行还在**，更早的行可以扔掉。

**关键坑**（和 1143 LCS 滚动数组完全一致）：`dp[i-1][j-1]` 这个「左上」值，在内层 `j` 从小到大更新时会先被覆盖成新值，后面 `j` 要用时已经丢了——所以需要**额外一个变量 `prev` 提前保存左上角**。

```cpp
class Solution {
public:
    int minDistance(string word1, string word2) {
        int m = word1.length(), n = word2.length();
        // vector<int> dp(n + 1, 0)：一维数组，长度 n+1。
        //   - 语义：dp[j] 在每轮外层循环「开始时」存的是「上一行第 j 列」的值（即 dp_2d[i-1][j]）。
        //   - 先不初始化 i/j，下面手动填，便于看清「第一行边界」是怎么来的。
        vector<int> dp(n + 1, 0);

        for (int i = 0; i <= m; i++) {
            // prev：保存「左上角」dp_2d[i-1][j-1] 的值。
            //   - 每行开始前（j=0 时），「左上」就是 dp_2d[i-1][0]，即上一行第 0 列。
            //     外层第一轮（i=0）时它是 0；后续行它是上一行算出的 dp_2d[i-1][0]，正好等于 i-1。
            //   - 但我们还得单独处理「第 0 列」dp_2d[i][0] = i，所以用 prev 暂存「上一行第 0 列」的旧值，
            //     再把 dp[0] 更新成 i（第 0 列新值）。这样下一行的 prev 就能拿到正确的 dp_2d[i][0]=i。
            int prev = dp[0];
            dp[0] = i;        // 第 0 列 = i（「word1 前 i 个 → 空串」要删 i 次）
            for (int j = 1; j <= n; j++) {
                // temp：先把「将要被覆盖的旧 dp[j]」（= 上一行第 j 列 = dp_2d[i-1][j]）存起来。
                //   - 因为下一步 dp[j] 要被更新成新值（本行第 j 列），但下一轮 j+1 的「左上」正是这个旧值。
                int temp = dp[j];
                if (word1[i - 1] == word2[j - 1]) {
                    // 匹配：dp_2d[i][j] = dp_2d[i-1][j-1] = prev。
                    //   - prev 此时存的正是「上一行第 j-1 列」的旧值（左上角）。
                    dp[j] = prev;
                } else {
                    // 不匹配：dp_2d[i][j] = 1 + min(删, 插, 改)。
                    //   - dp[j]（更新前 = temp）= 上一行第 j 列 = dp_2d[i-1][j]（删除方向，上）。
                    //   - dp[j-1]（已被本轮更新）= 本行第 j-1 列 = dp_2d[i][j-1]（插入方向，左）。
                    //   - prev = 上一行第 j-1 列 = dp_2d[i-1][j-1]（替换方向，左上）。
                    dp[j] = 1 + min({temp, dp[j - 1], prev});
                }
                // 把「刚被覆盖前的旧 dp[j]」传给下一轮当「左上」。
                //   - 对下一轮 j+1 而言，「左上」= dp_2d[i-1][(j+1)-1] = dp_2d[i-1][j]，正是这个 temp。
                prev = temp;
            }
        }
        // 循环结束时 dp[n] 就是 dp_2d[m][n]。
        return dp[n];
    }
};
```

- **时间**：O(mn)（与二维一致，双层 for 没变）。
- **空间**：O(n)（只留一维数组 + 一个 `prev` 变量）。若 `m < n`，可交换 `word1`/`word2` 让数组沿较短维度开，进一步压到 O(min(m,n))。
- **何时用**：`m`、`n` 都较大、且想省内存时。逻辑等价于二维写法，只是多了 `prev` 保存左上角的细节。初学阶段建议先吃透二维写法（思路清晰、不易出错），再来看这个一维优化版本——尤其要理解「为什么需要 `prev`」（这条和 1143 LCS 完全一样，两题滚动数组的写法几乎可以互相套用）。
