# 64 最小路径和

- 难度：中等
- 标签：**数组**、**动态规划**、**矩阵**
- 力扣链接：https://leetcode.cn/problems/minimum-path-sum/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[最小路径和](https://leetcode.cn/problems/minimum-path-sum/solution/zui-xiao-lu-jing-he-by-leetcode-solution/)」方法一「动态规划」。正文主解是 **动态规划（二维，原地修改 grid）**——把官方「开一个 `dp` 数组（O(mn) 空间）」的版本直接就地写到 `grid` 上，省到 O(1) 额外空间。它是 **62 题「不同路径」的孪生题**：62 求「有多少条路径」（计数、用加法），64 求「所有路径里数字总和最小的那条」（求最值、用 `min` + 累加格子值）。

## 题目描述

给定一个包含非负整数的 *m* x *n* 网格 `grid`，请找出一条从左上角到右下角的路径，使得路径上的数字总和为最小。

说明：每次只能向下或者向右移动一步。

**示例 1：**

```
输入：grid = [[1,3,1],[1,5,1],[4,2,1]]
输出：7
解释：因为路径 1→3→1→1→1 的总和最小。
```

**示例 2：**

```
输入：grid = [[1,2,3],[4,5,6]]
输出：12
```

**提示：**

- `m == grid.length`
- `n == grid[i].length`
- `1 <= m, n <= 200`
- `0 <= grid[i][j] <= 200`

## 思路

> 本题参考力扣官方题解「方法一：动态规划」，并在其基础上做「原地修改」空间优化。

### DP 三要素（所有 DP 题的通用思考框架）

#### ① 状态定义：`dp[i][j]` = 从左上角 `(0,0)` 走到 `(i,j)` 的最小路径和

把「问题」用一个二维表格描述出来。`dp[m-1][n-1]`（右下角）就是答案。

> 为什么要这么定义？因为「走到 `(i,j)` 的最小路径和」是一个**结构相同的子问题**，原问题「走到右下角的最小路径和」就是 `i=m-1, j=n-1` 的特例。DP 的本质就是把大问题拆成同构的小问题。
>
> 本解直接把 `grid` 本身当 `dp` 用（原地修改）：计算完一个格子后，`grid[i][j]` 里存的就不再是原始数字，而是「走到这里的路径和」。题目只问结果、不要保留原数据，所以可以这么干。

#### ② 状态转移方程：`grid[i][j] = grid[i][j] + min(grid[i-1][j], grid[i][j-1])`（核心！）

**盯着「最后一步」看**：到达 `(i,j)` 的最后一步，只有两种可能——

1. **从上方的 `(i-1,j)` 向下一步**：那走到 `(i,j)` 的最小和 = 走到 `(i-1,j)` 的最小和 + 当前格子值 = `dp[i-1][j] + grid[i][j]`；
2. **从左方的 `(i,j-1)` 向右一步**：那走到 `(i,j)` 的最小和 = 走到 `(i,j-1)` 的最小和 + 当前格子值 = `dp[i][j-1] + grid[i][j]`。

这两种情况**互斥且完备**（题目只允许「向下」或「向右」，没有第三种走法）。**要的是最小和**，所以两者取较小值：

```
dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
```

一句话：**「走到 `(i,j)` 的最小和 = 当前格子值 + min(从上面来的最小和, 从左面来的最小和)」**。每经过一个格子都要付出 `grid[i][j]` 的代价，这是和 62 题「不同路径」最大的区别（见下）。

#### ③ 初始条件：第一行、第一列是「前缀和」（只能从一个方向来）

这是本题最容易写错的地方。转移方程依赖「上方 `dp[i-1][j]`」和「左方 `dp[i][j-1]`」，可第一行（`i=0`）**没有上方**、第一列（`j=0`）**没有左方**，转移方程对它们不适用，必须单独处理：

- **第一行** `grid[0][j]`：只能从左方一路向右走来，路径唯一（一直向右），所以 `grid[0][j] += grid[0][j-1]`——就是「第一行的前缀和」。
- **第一列** `grid[i][0]`：只能从上方一路向下来，路径唯一（一直向下），所以 `grid[i][0] += grid[i-1][0]`——就是「第一列的前缀和」。

处理完首行首列，剩下的格子 `(i,j)`（`i>=1, j>=1`）才套通用转移方程。

> 为什么是前缀和而不是 `min`？因为首行首列的每个格子**只能从一个方向到达**，路径没得选，谈不上「取最小」——走法唯一，路径和就是把沿途格子值一路累加。

### 和 62 题「不同路径」的区别（必看！）

两题几乎一模一样：同一个网格、同样的「只能向下或向右」、同样的 `dp[i][j]` 二维状态、同样的「首行首列特殊处理」。**唯一不同的是转移方程**：

| 题目 | 问什么 | 转移方程 | 初始条件 |
|---|---|---|---|
| 62 不同路径 | 有**多少条**路径（计数） | `dp[i][j] = dp[i-1][j] + dp[i][j-1]`（加法） | 首行首列全 `1`（只有一条路） |
| 64 最小路径和 | 路径和的**最小值**（最值） | `dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])` | 首行首列是 `grid` 的前缀和 |

记忆口诀：**「计数用加法，最值用 `min`/`max`；求最值时别忘了把当前格子的代价 `+ grid[i][j]` 加回去」**。62 题不涉及格子值，64 题每个格子有代价，是核心差异。

### 原地修改为什么能省空间？

朴素 DP 要新开一个 `dp[m][n]` 数组，空间 O(mn)。但观察：`dp[i][j]` 算完后，**原始的 `grid[i][j]` 再也用不到了**（后续格子只用它作为「路径和」而不是「原始值」参与转移），而且题目也不要求保留原 `grid`。所以干脆把 `dp` 直接写回 `grid`：算完 `(i,j)` 后，`grid[i][j]` 的新值就是 `dp[i][j]`，原本的格子值被覆盖也无所谓。这样额外空间省到 O(1)。

### 手动推导 grid = [[1,3,1],[1,5,1],[4,2,1]]

先把网格摆出来，一步步改写 `grid`（每个格子里最终存的是「走到这里的最小路径和」）：

```
原始 grid：           行号/列号：
1  3  1               i\j  0  1  2
1  5  1                0   1  3  1
4  2  1                1   1  5  1
                       2   4  2  1
```

**步骤 1：第一行做前缀和**（`grid[0][j] += grid[0][j-1]`）

```
grid[0][1] += grid[0][0]  →  3 + 1 = 4
grid[0][2] += grid[0][1]  →  1 + 4 = 5

第一行变成：1  4  5
```

**步骤 2：第一列做前缀和**（`grid[i][0] += grid[i-1][0]`）

```
grid[1][0] += grid[0][0]  →  1 + 1 = 2
grid[2][0] += grid[1][0]  →  4 + 2 = 6

第一列变成：1, 2, 6（竖着看）
```

此时网格：

```
1  4  5
2  5  1
6  2  1
```

**步骤 3：内部格子套转移方程** `grid[i][j] += min(grid[i-1][j], grid[i][j-1])`

```
i=1, j=1: grid[1][1] += min(grid[0][1], grid[1][0]) = min(4, 2) = 2  →  5 + 2 = 7
i=1, j=2: grid[1][2] += min(grid[0][2], grid[1][1]) = min(5, 7) = 5  →  1 + 5 = 6
i=2, j=1: grid[2][1] += min(grid[1][1], grid[2][0]) = min(7, 6) = 6  →  2 + 6 = 8
i=2, j=2: grid[2][2] += min(grid[1][2], grid[2][1]) = min(6, 8) = 6  →  1 + 6 = 7
```

最终网格：

```
1  4  5
2  7  6
6  8  7   ← 右下角 grid[2][2] = 7
```

**返回 `grid[2][2] = 7`** ✓（对应路径 1→3→1→1→1，和为 7）。

## 代码

```cpp
class Solution {
public:
    // int 返回：从左上角到右下角的最小路径和。
    // vector<vector<int>>& grid：二维动态数组引用，元素类型 int。
    //   外层 vector 存「每一行」，内层 vector 存「这一行的各列」。
    //   传引用避免拷贝整张网格；本题要「原地修改」，必须直接改调用方那份。
    int minPathSum(vector<vector<int>>& grid) {
        // size()：vector 元素个数；二维矩阵的 size() 就是「行数 m」。
        int m = (int)grid.size();
        // grid[0].size()：第 0 行的列数 n（题目保证每行列数相同）。
        int n = (int)grid[0].size();

        // —— 步骤 1：第一行做前缀和 ——
        // 第一行（i=0）没有「上方」，只能从左方一路向右，路径唯一，
        //   所以 grid[0][j] 的最小路径和 = 把第一行从左到右累加（前缀和）。
        // j 从 1 开始：grid[0][0] 是起点，路径和就是它自己，不用动。
        for (int j = 1; j < n; j++) {
            grid[0][j] += grid[0][j - 1];   // 原地累加：grid[0][j] 变成「走到 (0,j) 的最小和」
        }

        // —— 步骤 2：第一列做前缀和 ——
        // 第一列（j=0）没有「左方」，只能从上方一路向下，路径唯一，
        //   所以 grid[i][0] 的最小路径和 = 把第一列从上到下累加（前缀和）。
        // i 从 1 开始：grid[0][0] 同样不用动。
        for (int i = 1; i < m; i++) {
            grid[i][0] += grid[i - 1][0];   // 原地累加：grid[i][0] 变成「走到 (i,0) 的最小和」
        }

        // —— 步骤 3：内部格子套转移方程 ——
        // 对每个 (i,j)（i>=1, j>=1）：上方和左方都有了，
        //   取两者较小值 + 当前格子值 = 走到这里的最小路径和。
        // 双层 for：外层逐行、内层逐列；顺序无所谓（每个格子只依赖「上」和「左」，
        //   这两个在算到 (i,j) 之前一定已经算完），但通常按「行优先」。
        for (int i = 1; i < m; i++) {
            for (int j = 1; j < n; j++) {
                // min(a, b)：返回 a、b 中较小值（std::min，力扣默认已 include）。
                //   复杂度 O(1)。注意这里是「求最小和」所以用 min，不是 max。
                // 整句 = grid[i][j] + min(从上来 grid[i-1][j], 从左来 grid[i][j-1])
                //   写回 grid[i][j]：原地修改，原始格子值被覆盖也无所谓（用完了）。
                grid[i][j] += min(grid[i - 1][j], grid[i][j - 1]);
            }
        }

        // 右下角格子里现在存的就是「走到右下角的最小路径和」。
        return grid[m - 1][n - 1];
    }
};
```

## 复杂度

- **时间**：O(m×n)
  - 三个循环加起来恰好把每个格子处理一次（首行 n 格 + 首列 m 格 + 内部 (m-1)(n-1) 格），每格 O(1)，共 O(mn)。
- **空间**：O(1)
  - 原地修改 `grid`，没新开数组，只用了 `m`、`n` 两个 int 变量。对比朴素 DP（另开 `dp[m][n]`）的 O(mn)，省了一整个二维数组。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么第一行、第一列要用「前缀和」初始化，不能像内部格子那样套转移方程？

因为转移方程 `dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])` 依赖「上方 `dp[i-1][j]`」和「左方 `dp[i][j-1]`」**两个邻居**。可第一行 `i=0` 根本没有上方（`dp[-1][j]` 越界），第一列 `j=0` 没有左方（`dp[i][-1]` 越界）。

更关键的是：首行首列的格子**只能从一个方向到达**（首行只能从左来、首列只能从上来），路径唯一，谈不上「在两个选择里取最小」——走法就那一条，路径和就是把沿途格子值一路累加，所以是前缀和。如果强行套转移方程并假设不存在的方向贡献为 0，也能凑出前缀和的效果（`min(不存在, 左方)` = 左方），但单独写两行前缀和循环更清晰、不容易越界。

### Q2：能不能不修改原数组 `grid`？题目会介意吗？

力扣判题**不介意**——提交后调用方不再用 `grid`，原地改没问题。但工程上或面试中，如果对方要求「不要破坏输入」，就另开一个 `dp` 数组（即官方原版，空间 O(mn)）或开一个一维 `dp[n]`（滚动数组，空间 O(n)，官方题解末尾提到的优化）：

```cpp
// 滚动数组版：只存「当前行的 dp」，空间 O(n)，不修改原 grid
vector<int> dp(n);
dp[0] = grid[0][0];
for (int j = 1; j < n; j++) dp[j] = dp[j-1] + grid[0][j];   // 首行前缀和
for (int i = 1; i < m; i++) {
    dp[0] += grid[i][0];                                    // 首列：每行第 0 格累加
    for (int j = 1; j < n; j++) {
        dp[j] = min(dp[j], dp[j-1]) + grid[i][j];           // dp[j] 旧值=上一行(上方)，dp[j-1] 新值=本行(左方)
    }
}
return dp[n-1];
```

面试时可以先用最直白的「另开 `dp` 二维数组」讲清思路，再说「能原地优化到 O(1)」作为加分项。

### Q3：和 62 题「不同路径」到底啥关系？怎么区分？

两题是同一套「网格 DP」骨架：同一个二维网格、同样「只能向下或向右」、`dp[i][j]` 同样表示「走到 `(i,j)` 的……」、首行首列同样要特殊处理。**区分看两件事**：

1. **问计数还是最值**：问「有多少条/几种方案」→ 计数 → 转移用**加法**（62 题 `dp[i][j]=dp[i-1][j]+dp[i][j-1]`）；问「最大/最小」→ 最值 → 转移用 `min`/`max`（64 题）。
2. **格子有没有代价**：62 题格子本身没值（只数路径数）；64 题每个格子有 `grid[i][j]` 的代价，转移方程里必须 `+ grid[i][j]`。

记这两点，遇到网格 DP 基本能秒套。类似的还有「最小下降和」「三角形最小路径和」等，都是同一家族。

### Q4：转移方程里用 `min` 还是 `max`？会不会搞反？

本题求「路径和**最小**」，所以取两个邻居里**较小**的那个 → 用 `min`。口诀：**「求最小用 `min`，求最大用 `max`」**，和题目措辞一致，别反着来。如果题目改成「最大路径和」，就把 `min` 换成 `max`（注：本题 `grid[i][j]` 非负，但「向下/向右只能往前走、没有环」，所以就算有负数也能 DP，不存在「绕圈刷分」问题）。

## 复盘

### 可迁移套路

- **「网格 DP：从上和左转移求最值」**：凡是「在网格里走、只能向右/向下（或类似单向移动）、问最值或计数」的题，几乎都是同一个套路——
  1. 状态定义 `dp[i][j]` = 走到 `(i,j)` 时的目标值（最值 / 计数）；
  2. 转移方程 = 「当前格子代价」+「从上、左两个方向转移过来的 `dp` 的 `min`/`max`/`+`」；
  3. 首行首列只能从一个方向来，单独做前缀和或初始化。
  套用家族：62 不同路径、64 最小路径和、120 三角形最小路径和、931 最小下降和、221 最大正方形等。
- **「盯着最后一步」找转移方程**：到达 `(i,j)` 的最后一步要么从上来、要么从左来——把两种情况的最优值算出来再 `min`/`max`/相加。这个思考方式和 70 爬楼梯（「最后一步跨 1 阶还是 2 阶」）一脉相承，是所有 DP 推导转移方程的通用招数。
- **「原地修改省空间」**：当 `dp[i][j]` 算完后原始输入 `grid[i][j]` 再也用不到、且题目不要求保留原数据时，直接把 `dp` 写回 `grid`，额外空间从 O(mn) 压到 O(1)。判断「能不能原地」看两点：原值是否还会被后续格子引用、调用方是否还在意原数据。本题两点都满足，所以可原地。矩阵题里这个套路很常见（如 73 矩阵置零借首行首列当标记，也是「就地存信息」的变体）。
- **首行首列单独处理**：二维 DP 几乎都要为「边界」（首行、首列）写一段初始化循环，因为它们缺一个方向的邻居。养成习惯：写完二维双层 `for`，回头检查 `i=0` 和 `j=0` 这两条边是否被通用转移方程漏掉，漏了就补一段前缀和/单独初始化。

### 与 62 题「不同路径」对照（复习时一起看）

两题代码骨架几乎逐行对应，只是转移符号和初始值不同：

| | 62 不同路径 | 64 最小路径和 |
|---|---|---|
| 状态 `dp[i][j]` | 走到 `(i,j)` 的路径数 | 走到 `(i,j)` 的最小路径和 |
| 首行首列初始化 | 全填 `1`（只有一条路） | 前缀和（沿途累加格子值） |
| 转移方程 | `dp[i][j] = dp[i-1][j] + dp[i][j-1]` | `dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])` |
| 求和/最值 | 加法（计数） | `min`（最值）+ 当前格子代价 |
| 空间 | 可滚动数组 O(n) | 可原地 O(1) |

把两题并排复习，能很直观看出「计数 DP vs 最值 DP」「无代价 DP vs 带代价 DP」的差异，是网格 DP 最经典的对比组。
