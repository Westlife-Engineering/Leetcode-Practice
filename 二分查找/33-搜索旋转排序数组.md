# 33 搜索旋转排序数组

- 难度：中等
- 标签：数组、**二分查找**
- 力扣链接：https://leetcode.cn/problems/search-in-rotated-sorted-array/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[搜索旋转排序数组](https://leetcode.cn/problems/search-in-rotated-sorted-array/solution/sou-suo-xuan-zhuan-pai-xu-shu-zu-by-leetcode-solut/)」方法一。正文主解是 **二分查找（每轮判断哪半边有序 + target 在哪半边，再决定收缩方向）**，O(log n) 时间 O(1) 空间。这是二分查找组的**经典变体**，难点不在二分模板本身，而在「旋转后数组不再全局有序，如何确定 target 该往左找还是往右找」。关键观察一句话：**`mid` 把数组分成两半，至少有一半是有序的**。官方代码用的判据是 `nums[0] <= nums[mid]`，本文改用等价但更贴合「左半有序」语义的 `nums[left] <= nums[mid]`（实测和官方代码完全等价、且天然处理 `n==1`，不用单独特判），两种写法差异见「疑惑 / 卡点」Q4。

## 题目描述

整数数组 `nums` 按升序排列，数组中的值 **互不相同**。

在传递给函数之前，`nums` 在预先未知的某个下标 `k`（`0 <= k < nums.length`）上进行了 **向左旋转**，使数组变为 `[nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]`（下标从 0 开始计数）。例如，`[0,1,2,4,5,6,7]` 在下标 3 上向左旋转后可能变为 `[4,5,6,7,0,1,2]`。

给你旋转后的数组 `nums` 和一个整数 `target`，如果 `nums` 中存在目标值 `target`，则返回它的下标，否则返回 `-1`。

你必须设计一个时间复杂度为 `O(log n)` 的算法解决此问题。

**示例 1:**

```
输入：nums = [4,5,6,7,0,1,2], target = 0
输出：4
```

**示例 2:**

```
输入：nums = [4,5,6,7,0,1,2], target = 3
输出：-1
```

**示例 3:**

```
输入：nums = [1], target = 0
输出：-1
```

**提示：**

- `1 <= nums.length <= 5000`
- `-10^4 <= nums[i] <= 10^4`
- `nums` 中的每个值都 **独一无二**
- 题目数据保证 `nums` 在预先未知的某个下标上进行了旋转
- `-10^4 <= target <= 10^4`

> 题面四个关键前提一定要看清：**原本升序**、**无重复元素**、**旋转过**（但旋转点 `k` 未知，可能 `k=0` 即没真转）、**要求 O(log n)**。前三条是「能套二分变体」的前提，第四条直接排除了线性扫描。

## 思路

> 本题主要参考力扣官方题解「方法一：二分查找」。下面把这道二分变体的核心难点——「判断哪半边有序 + target 在哪半边」——一点点拆开讲。

### 先看旋转后数组长什么样

原数组升序、无重复。旋转一次（把前 `k` 个搬到末尾）之后，数组从「一整段升序」变成了「**两段升序**拼起来」，而且**第二段的最大值 < 第一段的最小值**（因为原本就是升序的，搬走的前 `k` 个是最小的几个）。

例如 `[0,1,2,4,5,6,7]` 在下标 `k=3` 旋转后变成 `[4,5,6,7,0,1,2]`：

```
第一段升序：[4,5,6,7]   （原数组的右半部分被提到了前面）
第二段升序：[0,1,2]     （原数组的左半部分被挤到了后面）
拼接处 "7 → 0" 是唯一一处"逆序"的下降（称为"断点"）。
```

特殊情形：如果 `k = 0`（相当于没转），整个数组还是一整段升序，没有断点——这时这道题就退化成 35 题那种标准二分。我们的算法必须同时覆盖「有断点」和「没断点」两种情况。

### 为什么不能直接套 35 题的标准二分？

35 题能用标准二分，前提是「**整个数组全局有序**」，所以拿 `nums[mid]` 和 `target` 比大小，就能唯一确定 `target` 在左半还是右半。

本题数组只在**局部**有序，`nums[mid] < target` 并不保证 `target` 一定在 `mid` 右边——因为 `mid` 右边那半可能跨越了断点，里面混着小元素。例如 `[4,5,6,7,0,1,2]`，`mid = 3` 时 `nums[mid] = 7`，`target = 0 < 7`，但 `0` 却在 `mid` 右侧的 `[0,1,2]` 段里。所以**只比 `nums[mid]` 和 `target` 不够**，得多问一句：「我现在切出来的这两半，哪一半是真正连续有序的？」

### 关键观察：`mid` 把数组切成两半，至少有一半是有序的

这是整道题的破局点。数组只有**一个**断点（旋转一次只产生一处下降），而 `mid` 又把当前区间 `[left, right]` 切成 `[left, mid]` 和 `[mid, right]` 两半。一个断点不可能同时落在两半里，所以**断点要么在左半、要么在右半、要么都不在**——也就是说，**两半里至少有一半是不含断点的，不含断点的那一半就是连续升序的**。

拿 `[4,5,6,7,0,1,2]` 看：

```
mid 落在 3（值 7），切成 [4,5,6,7] 和 [7,0,1,2]。
  [4,5,6,7] 连续升序（左半有序）；[7,0,1,2] 含断点（7→0 下降），不是整体有序。
```

再看 `mid` 落在 5（值 1）的情况：切成 `[4,5,6,7,0,1]` 和 `[1,2]`：

```
[1,2] 连续升序（右半有序）；[4,5,6,7,0,1] 含断点，不是整体有序。
```

无论 `mid` 在哪，**总有一半是干净的升序段**。这就是我们能继续做二分的依据。

### 怎么判断哪一半有序？—— `nums[left] <= nums[mid]`

既然至少一半有序，那只要判一下**左半** `[left, mid]` 是不是有序即可（左半有序 ⟺ `nums[left] <= nums[mid]`，因为升序段的起点一定 ≤ 终点）：

- **`nums[left] <= nums[mid]`**：左半 `[left, mid]` 没有断点，是连续升序的（注意包含等号：`left == mid` 即区间只剩一两个元素时，单元素/两元素也视作「有序」，用 `<=` 才能正确归类）。
- **否则**（`nums[left] > nums[mid]`）：断点在左半，左半不是整体有序；既然左半含断点，那右半 `[mid, right]` 一定干净、连续升序。

> 直觉记忆：拿区间最左端 `nums[left]` 和中点 `nums[mid]` 比一下。左端值 ≤ 中点值，说明从左端走到中点一路上没掉下去过，左半就是升序；反之左端值 > 中点值，说明中途掉下去了（断点在左半），那右半才是干净的。

### 判断 `target` 在有序那半还是另一半 → 收缩区间

知道哪半有序后，**先看 `target` 在不在那半段有序的范围内**：

- **左半有序时**（`nums[left] <= nums[mid]`）：
  - 若 `nums[left] <= target && target < nums[mid]`：`target` 落在左半这个升序段范围内 → 往左找，`right = mid - 1`。
  - 否则（`target` 比左半段最大值还大，或比左半段最小值还小）：`target` 不可能在左半 → 只能去右半找，`left = mid + 1`。
- **右半有序时**（`nums[left] > nums[mid]`）：
  - 若 `nums[mid] < target && target <= nums[right]`：`target` 落在右半这个升序段范围内 → 往右找，`left = mid + 1`。
  - 否则（`target` 比右半段最大值还大，或比右半段最小值还小）：`target` 不可能在右半 → 只能去左半找，`right = mid - 1`。

注意：**判断 `target` 落在哪半时，只能用「有序那半」的范围来卡**，因为只有有序那半的端点（`nums[left]`/`nums[mid]` 或 `nums[mid]`/`nums[right]`）能保证是这段的真实最小/最大值。另一半含断点，端点不代表范围。

### 模板细节（沿用 35 题那套）

- 区间仍用**闭**区间 `[left, right]`，循环条件 `left <= right`（理由同 35 题 Q1：`left == right` 时还剩一个元素要查）。
- `mid = left + (right - left) / 2`，防 `(left + right)` 溢出（35 题 Q2）。
- 命中 `nums[mid] == target` 直接 `return mid`；循环结束仍未命中，`return -1`。

### 手动推导：`nums = [4,5,6,7,0,1,2]`，`target = 0`

下标：`0:4, 1:5, 2:6, 3:7, 4:0, 5:1, 6:2`。`left = 0, right = 6`。断点在 `7→0`（下标 3→4 之间）。

```
第 1 轮  left=0 right=6  mid=0+(6-0)/2=3   nums[mid]=7   nums[0]=4 <= 7 → 左半 [4,5,6,7] 有序
         target=0 在左半范围 [4,7) 吗？ 4<=0<7 → 否 → target 只能在右半 → left=mid+1=4
第 2 轮  left=4 right=6  mid=4+(6-4)/2=5   nums[mid]=1   nums[4]=0 <= 1 → 左半 [0,1] 有序
         target=0 在左半范围 [0,1) 吗？ 0<=0<1 → 是 → 往左找 → right=mid-1=4
第 3 轮  left=4 right=4  mid=4+(4-4)/2=4   nums[mid]=0   nums[mid]==target → 命中，return 4 ✓
```

返回 `4`，正是 `0` 在原数组里的下标。

再补一个找不到的例子：`nums = [4,5,6,7,0,1,2]`，`target = 3`。

```
第 1 轮  left=0 right=6  mid=3  nums[mid]=7  nums[0]=4<=7 → 左半有序
         target=3 在 [4,7) 吗？ 否（3<4）→ target 在右半 → left=mid+1=4
第 2 轮  left=4 right=6  mid=5  nums[mid]=1  nums[4]=0<=1 → 左半 [0,1] 有序
         target=3 在 [0,1) 吗？ 否（3>=1）→ target 在右半 → left=mid+1=6
第 3 轮  left=6 right=6  mid=6  nums[mid]=2  nums[6]=2<=2 → 左半 [2] 有序（单元素）
         target=3 在 [2,2) 吗？ 2<=3<2 → 否（空区间）→ target 在右半 → left=mid+1=7
第 4 轮  left=7 right=6  left>right → 循环结束，未命中
return -1 ✓
```

## 代码

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        // vector<int>& nums：按引用传入的可变长 int 数组（力扣 C++ 默认包含 <vector>）。
        //   - 用引用 & 避免拷贝整个数组；本题只读不写，但标准二分写法不要求 const。
        //   - 题目保证 nums.length >= 1，所以下面不单独判空。

        // 闭区间二分：[left, right] 是「还没排查过的范围」，含两端。
        int left = 0, right = (int)nums.size() - 1;
        //   - (int) 强转：nums.size() 是 size_t（无符号），减 1 后赋给 int 前显式转换，
        //     既消除「有符号/无符号比较」的编译警告，也防止空数组时 0-1 回绕成巨大正数
        //     （本题保证非空，这里其实安全，养成习惯不亏）。

        // while (left <= right)：带等号是闭区间标配（和 35 题一致）。
        //   - left == right 时区间里还剩 1 个元素没查，必须再进一轮检查它。
        //   - 改成 left < right 会漏查最后一个元素。
        while (left <= right) {
            // mid 取中点：写成 left + (right - left) / 2 防整数溢出（35 题讲过，这里不重复）。
            int mid = left + (right - left) / 2;

            // 命中：直接返回下标。题目保证无重复元素，找到即可返回，无需找第一个/最后一个。
            if (nums[mid] == target) {
                return mid;
            }

            // ★ 本题核心：先判断 [left, mid] 这半是不是有序的（即左半不含旋转断点）。
            //   - 升序段的左端值一定 <= 右端值；nums[left] <= nums[mid] 说明从 left 走到 mid
            //     一路上没下降过，左半 [left, mid] 连续升序，断点不在左半里。
            //   - 注意必须用 <= 而不是 <：当 left == mid（区间只剩一两个元素）时，
            //     nums[left] == nums[mid]，单元素段也视为「有序」，归到左半有序分支处理。
            //     用 < 会在两元素区间里判错（见 Q&A Q1）。
            //   - 反之 nums[left] > nums[mid]：断点在左半（中途有下降），那右半 [mid, right]
            //     一定连续升序。我们这里用「左半有序」做主分支，else 自然落到「右半有序」。
            if (nums[left] <= nums[mid]) {
                // 左半 [left, mid] 有序。再用 target 和左半的范围 [nums[left], nums[mid]) 比较，
                // 判断 target 是不是落在这个有序段内。
                //   - 必须用「有序那半的端点」当上下界：只有有序段才能保证 nums[left] 是这段
                //     的最小值、nums[mid] 是最大值。另一半含断点，端点不代表范围，不能用。
                //   - 左闭右开 [nums[left], nums[mid])：左端可命中（= 时在左半），右端不含
                //     （nums[mid] 已经在上面判过 != target，不必再含）。
                if (nums[left] <= target && target < nums[mid]) {
                    // target 落在有序的左半范围内 → 往左找。
                    //   - right = mid - 1：mid 已查过且不是答案，跳过它，否则可能死循环。
                    right = mid - 1;
                } else {
                    // target 不在有序的左半（比 nums[left] 小，或比 nums[mid] 大）
                    // → 即使右半含断点也只能去右半找 → left = mid + 1。
                    left = mid + 1;
                }
            } else {
                // ★ 否则：nums[left] > nums[mid]，左半含断点，右半 [mid, right] 有序。
                //   对称地用 target 和右半的范围 (nums[mid], nums[right]] 比较。
                //   - 左开右闭 (nums[mid], nums[right]]：左端不含（nums[mid] 已判过 != target），
                //     右端可命中（= 时在右半）。
                if (nums[mid] < target && target <= nums[right]) {
                    // target 落在有序的右半范围内 → 往右找。
                    left = mid + 1;
                } else {
                    // target 不在有序的右半 → 只能去左半找（即便左半含断点）。
                    right = mid - 1;
                }
            }
        }
        // 循环走到这里说明整个区间都查完没命中（没触发上面的 return mid），返回 -1。
        return -1;
    }
};
```

## 复杂度

- **时间**：O(log n)，其中 n 为数组长度。
  - 每轮循环区间缩一半，最多迭代 ⌈log₂(n+1)⌉ 次，n = 5000 时约 13 次，远优于线性扫描的 O(n)。
  - 每轮除了比较和赋值没有别的开销，整体就是一次二分。
- **空间**：O(1)。
  - 只用了 `left` / `right` / `mid` 三个下标变量，常数额外空间。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：判断「左半有序」时为什么必须用 `nums[left] <= nums[mid]`（带等号）？

因为 `left` 和 `mid` 可能相等。当区间收缩到只剩一两个元素时，`mid = left + (right - left) / 2` 会落到 `left` 上（`/2` 向下取整），此时 `nums[left] == nums[mid]`。

- 用 `<=`：`left == mid` 时判为「左半有序」，归到左半分支处理。单元素段 `[x]` 视作有序完全合理，target 要么等于它（前面 `nums[mid] == target` 已经 return 了）、要么不在它里面，走 `else` 把 `left = mid + 1` 收缩掉，逻辑自洽。
- 如果误写成 `<`：`left == mid` 时 `nums[left] < nums[mid]` 为假，会落到 `else`（右半有序）分支。但右半 `[mid, right]` 此刻可能根本不有序（断点在右半时），再用 `nums[mid] < target && target <= nums[right]` 去卡就会判错，丢掉正确方向。

**口诀：判有序用 `<=`，和二分循环条件用 `<=` 是同一个道理——边界处要包含等号，单元素段也算有序。**

### Q2：为什么判断 `target` 落在哪半时，只能拿「有序那半」的范围来卡？

因为只有有序那半的两个端点，才是这段的**真实**最小/最大值。另一半含旋转断点，端点不代表范围。

举例：`nums = [4,5,6,7,0,1,2]`，`mid = 3`（值 7），此时**右半** `[7,0,1,2]` 含断点。右半的「左端」是 `nums[mid] = 7`、「右端」是 `nums[right] = 2`，但 7 根本不是右半的最小值（0 才是），2 也不是最大值（7 才是）。如果拿 `nums[mid] <= target <= nums[right]`（即 `7 <= target <= 2`）去判断，永远为假，完全失效。

所以代码里的策略是：**先确定哪一半真的有序，再用那一半的端点做上下界**。左半有序时拿 `nums[left]`、`nums[mid]` 卡；右半有序时拿 `nums[mid]`、`nums[right]` 卡。这一步用错端点是最容易写错的地方。

### Q3：如果数组其实没旋转（`k = 0`），这个算法还成立吗？

成立，而且会自动退化成标准二分。`k = 0` 意味着整个数组还是一整段升序、没有断点。此时对任意 `mid`，`nums[left] <= nums[mid]` 永远成立（左半永远有序），代码一直走左半有序分支：

- `nums[left] <= target < nums[mid]` → `right = mid - 1`（往左找）；
- 否则 → `left = mid + 1`（往右找）。

这和 35 题的标准二分完全等价（只是把 `nums[mid] < target` / `nums[mid] > target` 的判断，包装成了「target 在不在左半范围内」的形式）。所以本题算法是**标准二分的真扩充**：没旋转时退化成标准二分，旋转了也能处理。题目「保证旋转过」其实可以无视——`k=0` 也算合法的旋转（自己转一圈回到原位），算法照样 AC。

### Q4：本文用 `nums[left] <= nums[mid]`，官方代码用 `nums[0] <= nums[mid]`，有区别吗？

功能上**等价**，都 AC，但语义和实现细节有差别：

- **官方版**（`nums[0] <= nums[mid]`）：判断「`mid` 是不是落在旋转后的**第一段升序**里」（第一段从下标 0 开始）。所以判断 target 时，官方也用 `nums[0] <= target && target < nums[mid]`（拿第一段的范围卡）。这种写法需要单独处理 `n == 0` 和 `n == 1`（因为 `nums[0]`、`nums[n-1]` 在退化情形下边界较绕），官方代码开头那几行 `if (!n)` / `if (n == 1)` 就是为此加的特判。
- **本文版**（`nums[left] <= nums[mid]`）：判断「当前区间 `[left, right]` 的**左半** `[left, mid]` 是不是有序」。随着 `left` 每轮更新，参考点也跟着移动，语义更贴近「收缩中的子区间」。这种写法**不需要** `n == 0` / `n == 1` 特判：`n == 1` 时第一次进循环 `mid == left == right == 0`，要么 `nums[0] == target` 直接 return 0、要么 `left = mid + 1 = 1` 退出循环 return -1，自然正确。

两种写法背一种、能看懂另一种即可。本文选 `nums[left]` 版是因为它和 35 题「闭区间 `[left, right]`」的语境一致，也更容易推广到 81 题（含重复元素的旋转数组）。

## 复盘

- **可迁移套路**：**「旋转数组的二分 = 每轮先判哪半有序，再判 target 在不在有序那半」** 是一个可以直接背的模板。核心就两步：
  1. 用 `nums[left] <= nums[mid]` 判左半是否有序（否则右半有序）。
  2. 用有序那半的端点当上下界，判 target 在不在里面，决定收缩方向。
  这个模板是 33/81/153/154 这一组「旋转数组二分」题的通用骨架。
- **和同组题的关系**：
  - **153 寻找旋转排序数组中的最小值**：同样的「判哪半有序」套路，只是不找 target、找最小值（最小值一定在含断点那半的端点处）。判完有序方向后直接收缩到含断点那半即可。
  - **81 搜索旋转排序数组 II**：把「无重复元素」放开成「可有重复」。难点是 `nums[left] == nums[mid]` 时无法判断哪半有序（比如 `[1,0,1,1,1]`），这时只能 `left++` 跳过这个无法归类的元素（最坏退化成 O(n)）。
  - **154 寻找旋转排序数组中的最小值 II**：153 + 允许重复，同样 `nums[left] == nums[mid]` 时 `left++`。
- **易错点速查（本题专属）**：
  - 判有序用 `<=` 不是 `<`（边界 `left == mid` 时单元素段也算有序，见 Q1）。
  - 判 target 在哪半时，**只能用有序那半的端点**当上下界，不能用含断点那半的端点（见 Q2）。
  - 左半有序用左闭右开 `[nums[left], nums[mid])`、右半有序用左开右闭 `(nums[mid], nums[right]]`（`nums[mid]` 已判过 ≠ target，两端不必同时含）。
  - 找不到返回 `-1`（不是 35 题的「返回插入位置」，两题返回值语义不同）。
- **二分通用易错点**（沿用 35 题复盘）：循环条件 `<=` 配闭区间；`mid = left + (right - left) / 2` 防溢出；收缩 `left = mid + 1` / `right = mid - 1` 必带 `±1` 防死循环。
