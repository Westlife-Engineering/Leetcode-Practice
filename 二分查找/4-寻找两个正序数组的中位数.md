# 4 寻找两个正序数组的中位数

- 难度：困难
- 标签：数组、**二分查找**、分治
- 力扣链接：https://leetcode.cn/problems/median-of-two-sorted-arrays/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[寻找两个有序数组的中位数](https://leetcode.cn/problems/median-of-two-sorted-arrays/solution/xun-zhao-liang-ge-you-xu-shu-zu-de-zhong-wei-s-114/)」方法二。正文主解是 **二分查找（在较短数组上二分划分点）**，O(log min(m,n)) 时间 O(1) 空间。这是**二分查找组的收尾题**，也是整个 Hot 100 里公认最难的几道之一——难点不在二分模板本身，而在「把找中位数转化成找划分点」这一步抽象。本题务必把「为什么是二分划分点」「i 和 j 的关系」「四种边界处理（`nums1[i-1]` 和 `nums2[j]` 比较）」三件事讲透。官方另一解「二分找第 k 小」(getKthElement，时间 O(log(m+n))) 以及暴力合并法都放在「复盘」对比。

## 题目描述

给定两个大小分别为 `m` 和 `n` 的正序（从小到大）数组 `nums1` 和 `nums2`。请你找出并返回这两个正序数组的中位数。

算法的时间复杂度应该为 `O(log (m+n))`。

**示例 1:**

```
输入：nums1 = [1,3], nums2 = [2]
输出：2.00000
解释：合并数组 = [1,2,3] ，中位数 2
```

**示例 2:**

```
输入：nums1 = [1,2], nums2 = [3,4]
输出：2.50000
解释：合并数组 = [1,2,3,4] ，中位数 (2 + 3) / 2 = 2.5
```

**提示：**

- `nums1.length == m`
- `nums2.length == n`
- `0 <= m <= 1000`
- `0 <= n <= 1000`
- `1 <= m + n <= 2000`
- `-10^6 <= nums1[i], nums2[i] <= 10^6`

**进阶：** 你能设计一个时间复杂度为 `O(log (m+n))` 的算法解决此问题吗？

> 题面三个关键前提一定要看清：**两个数组都正序**（升序）、**找中位数**（不是找第 k 小，但可以互相转化）、**要求 O(log(m+n))**（直接排除了合并数组 O(m+n) 的朴素做法）。注意允许某个数组为空（`m` 或 `n` 可为 0），但总长度至少为 1。

## 思路

> 本题主要参考力扣官方题解「方法二：划分数组」。下面把这道题的核心难点一点点拆开讲。如果第一遍觉得难懂很正常——这题是 Hot 100 里公认最烧脑的二分，多读几遍、拿纸笔跟着下面手动推一遍就能理解。

### 第一步：先想清楚「中位数」到底意味着什么

直觉里中位数就是「合并后大数组排在最中间的那个数」。但这只是表象。换一个角度，中位数的真正作用是 **把一个集合划分成两半**：

> 把集合划分成两个子集，**左半的元素个数等于（或恰好多一个）右半**，且 **左半的最大值 ≤ 右半的最小值**。

满足这个划分条件的「切口」就是中位数所在：

- 如果总长度是**奇数**，中位数就是「左半的最大值」（左半多放一个）。
- 如果总长度是**偶数**，中位数就是「左半最大值与右半最小值的平均」。

这个观察是整道题的钥匙：**找中位数 ⟺ 找一个满足上面两个条件的划分**。一旦接受这个等价，问题就从「合并数组找中间值」变成了「找一个划分位置」。

### 第二步：把「划分」具体化——两个数组各切一刀

在两个数组 `A = nums1`、`B = nums2` 上各切一刀，分别记切的位置为 `i` 和 `j`：

```
        左半 (left_part)         |        右半 (right_part)
   A[0], A[1], ..., A[i-1]       |   A[i], A[i+1], ..., A[m-1]
   B[0], B[1], ..., B[j-1]       |   B[j], B[j+1], ..., B[n-1]
```

`i` 表示 `A` 前 `i` 个元素进左半（`A[0..i-1]`），剩下的 `A[i..m-1]` 进右半；`j` 同理。注意 `i ∈ [0, m]`（`i=0` 表示 `A` 全进右半、`i=m` 表示 `A` 全进左半），`j ∈ [0, n]`。

要把这个划分叫做「中位数划分」，得同时满足：

1. **个数条件**：左半元素个数 = 右半元素个数（偶数），或左半比右半多 1（奇数）。
2. **大小条件**：左半最大值 ≤ 右半最小值。

### 第三步：i 和 j 的关系——为什么 j 由 i 唯一确定

先看个数条件。左半元素个数是 `i + j`，右半是 `(m - i) + (n - j)`。官方一个小技巧把奇偶两种情况**统一**成同一个式子：

```
左半元素个数 i + j = ⌈(m + n) / 2⌉ = (m + n + 1) / 2   （整数除法）
```

为什么是 `(m + n + 1) / 2`？

- 总长偶数时（比如 `m+n=4`）：`(4+1)/2=2`，左半 2 个、右半 2 个，相等。
- 总长奇数时（比如 `m+n=5`）：`(5+1)/2=3`，左半 3 个、右半 2 个，左半多 1。

这个「`+1`」就是为了在奇数情况下让**左半多放一个**，这样奇数时中位数 = 左半最大值（`median1`）单独就是答案，处理统一了。

于是给定 `i`，`j` 就被**唯一决定**：

```
j = (m + n + 1) / 2 - i
```

四个未知数 `i, j` 退化成一个未知数 `i`——这是本题能二分的前提。**记牢这个等式，它是全篇的命脉。**

### 第四步：大小条件——两种比较决定 i 偏大还是偏小

个数条件已经用 `j = (m+n+1)/2 - i` 搞定。还剩大小条件要满足。由于 `A` 和 `B` 各自升序，左半内部最大值只可能来自 `A[i-1]` 或 `B[j-1]`（它们是各自左半的最后一个、也就是最大的）；右半内部最小值只可能来自 `A[i]` 或 `B[j]`（各自右半的第一个、也就是最小的）。

所以「左半最大 ≤ 右半最小」等价于下面**两个不等式同时成立**：

```
A[i-1] <= B[j]     （A 的左半最大值，不能超过 B 的右半最小值）
B[j-1] <= A[i]     （B 的左半最大值，不能超过 A 的右半最小值）
```

注意 `A[i-1]` 和 `A[i]` 在 `A` 内部本来就有序（`A[i-1] <= A[i]`），`B` 同理；所以这两条交叉比较是真正有约束力的，是判定 `i` 取得「对不对」的核心。

按这两条把情况分类（暂且假设 `A[i-1], B[j-1], A[i], B[j]` 都存在，边界情况下一步处理）：

| 情况 | 判据 | 含义 | 怎么调整 `i` |
|---|---|---|---|
| `i` 取得正好 | `A[i-1] <= B[j]` **且** `B[j-1] <= A[i]` | 大小条件满足，找到划分 | 停，记录中位数 |
| `i` 太大 | `A[i-1] > B[j]` | `A` 切多了（左半装的 `A` 太多），导致 `A[i-1]` 太大 | `i` 往**左**挪：`right = i - 1` |
| `i` 太小 | `B[j-1] > A[i]` | `A` 切少了（左半装的 `A` 不够），导致 `A[i]` 太小 | `i` 往**右**挪：`left = i + 1` |

为什么 `A[i-1] > B[j]` 就说明 `i` 太大？因为 `A` **升序**，`i` 越大，`A[i-1]`（A 左半最大值）越大；同时 `j = (m+n+1)/2 - i` 越小，`B[j]`（B 右半最小值）越小。所以这是「切多了」的症状：左半塞进了一个不该在左边的大数。要让 `A[i-1]` 变小，切口 `i` 必须往**左**挪——当前这个太大的 `A[i-1]` 会被踢到右半，新的 `A[i-1]` 变成更靠前、更小的元素。同时 `j` 自动增大，B 多贡献几个给左半来补个数。`B[j-1] > A[i]`（`i` 太小）同理反向：`A` 切少了，右半最小值 `A[i]` 太小，要把切口往右挪，让更多 A 进左半。

> 这里有个关键事实：因为 `i` 增大时 `A[i-1]` 单调增、`j` 减小时 `B[j]` 单调减，所以「`A[i-1] <= B[j]`」这个条件随 `i` 增大**从成立变到不成立**，存在唯一的临界点。这正是能二分搜索的根本原因——**判定函数对 `i` 单调**。

### 第五步：为什么一定要在「较短数组」上二分

前面四步的前提是：随着 `i` 在 `[0, m]` 上变化，`j = (m+n+1)/2 - i` 始终落在 `[0, n]` 内（合法），否则 `j` 会越界、`B[j]` 或 `B[j-1]` 取不到。

如果我们规定 `A` 是**较短**的那个数组（`m <= n`），就能保证这一点：

- 当 `i ∈ [0, m]` 时，`j` 的最大值（在 `i=0` 时取到）是 `(m+n+1)/2`，因为 `m <= n`，所以 `(m+n+1)/2 <= n`（不会超出 `B` 范围）；
- `j` 的最小值（在 `i=m` 时取到）是 `(m+n+1)/2 - m`，因为 `m <= n`，所以这个值 `>= 0`（不会变负）。

反过来如果让 `A` 是较长的数组（`m > n`），`i` 取到较大值时 `j` 可能算成负数，直接越界崩溃。所以代码开头第一件事就是：**判断哪个数组短，把短的当作 `A`（要二分的那个）**。如果 `nums1` 比 `nums2` 长，就交换两者再递归调用自己。这是把二分范围压到 `min(m,n)` 的关键，也是「O(log min(m,n))」复杂度的来源。

### 第六步：边界处理——用 INT_MIN / INT_MAX 哨兵

到目前为止我们假设了 `A[i-1], B[j-1], A[i], B[j]` 四个数都存在，但实际：

- `i = 0` 时 `A[i-1]` 不存在（`A` 全进了右半）；
- `i = m` 时 `A[i]` 不存在（`A` 全进了左半）；
- `j = 0` 时 `B[j-1]` 不存在；`j = n` 时 `B[j]` 不存在。

官方用一个优雅的约定处理：**不存在的「左半端」视为负无穷 `INT_MIN`，不存在的「右半端」视为正无穷 `INT_MAX`**。直觉是：

- 如果某个数组完全没贡献元素给左半，那它就不可能影响「左半最大值」，设成 `-∞` 让 `max` 自然忽略它；
- 如果某个数组完全没贡献元素给右半，那它就不可能影响「右半最小值」，设成 `+∞` 让 `min` 自然忽略它。

代码里这四行就是干这个的：

```cpp
int nums_im1 = (i == 0 ? INT_MIN : nums1[i - 1]);   // A 左半最大值，A 没贡献左半时设 -∞
int nums_i   = (i == m ? INT_MAX : nums1[i]);       // A 右半最小值，A 没贡献右半时设 +∞
int nums_jm1 = (j == 0 ? INT_MIN : nums2[j - 1]);   // B 左半最大值
int nums_j   = (j == n ? INT_MAX : nums2[j]);       // B 右半最小值
```

这样后续比较 `nums_im1 <= nums_j` 等等就不需要单独判空，逻辑统一干净。

### 第七步：循环里做什么 + 怎么收尾

二分范围是 `i ∈ [0, m]`（注意 `i` 可以取到 `m`，所以是**闭区间** `left=0, right=m`，循环条件 `left <= right`）。每轮：

1. 取中点 `i = (left + right) / 2`，算出 `j = (m+n+1)/2 - i`。
2. 读出四个边界值 `nums_im1, nums_i, nums_jm1, nums_j`（带哨兵）。
3. 判定（和第四步表格一致：`A[i-1] > B[j]` 说明 `i` 太大）：
   - 若 `nums_im1 <= nums_j`：当前 `i` **合法**（可能还不是最大的那个）。这一步**顺便把答案候选记下来**——当前划分对应的「左半最大 `median1 = max(nums_im1, nums_jm1)`」和「右半最小 `median2 = min(nums_i, nums_j)`」先存着。然后 `left = i + 1`，继续往右看能不能让 `i` 更大（我们其实是在找「最大的满足 `A[i-1] <= B[j]` 的 `i`」）。
   - 否则（`nums_im1 > nums_j`）：`i` 太大了，`A` 切多了，左半最大值冲过了 `B[j]`。`right = i - 1` 往左压。

   对着「单调性」想一遍：`i` 越大 → `A[i-1]` 越大 → `B[j]` 越小（因为 `j = (m+n+1)/2 - i` 减小）。所以 `A[i-1] <= B[j]` 在 `i` 较小时成立、在 `i` 较大时不成立。我们想找**最大的让 `A[i-1] <= B[j]` 成立的 `i`**。循环结束（`left > right`）时，`median1 / median2` 里存的正是那个最大合法 `i` 对应的左右半最值。

> 关于「找最大的 `i` 满足 `A[i-1] <= B[j]`」为什么等价于「同时满足 `A[i-1] <= B[j]` 且 `B[j-1] <= A[i]`」：官方证明是——若 `i` 是最大的满足 `A[i-1] <= B[j]` 的下标，那么 `i+1` 不满足，即 `A[i] > B[j-1]`，于是 `B[j-1] < A[i]` 自然成立。所以只要找到那个临界 `i`，两个不等式就都满足了。这一步不用强记，记「单调性 → 能二分 → 找临界 `i`」即可。

### 第八步：奇偶收尾——返回 median1 还是 (median1+median2)/2

二分结束后：

- 总长 `(m+n)` 为**奇数**：左半多放了一个，中位数就是左半最大值 `median1`，返回 `median1`。
- 总长为**偶数**：中位数是左半最大与右半最小的平均，返回 `(median1 + median2) / 2.0`。

注意 `/ 2.0` 不能写成 `/ 2`（整数除法会截断小数）。`(median1 + median2) / 2.0` 因为 `2.0` 是 `double`，整个表达式会被提升为 `double` 运算，得到正确的小数结果。

### 手动推导 1：`nums1 = [1,3]`, `nums2 = [2]`，期望 `2.0`

`m=2, n=1`，`m > n`，所以**先交换**：实际 `A = nums2 = [2]`（`m=1`），`B = nums1 = [1,3]`（`n=2`）。`(m+n+1)/2 = (1+2+1)/2 = 2`，所以 `j = 2 - i`。`left=0, right=m=1`。

```
第 1 轮  left=0 right=1  i=(0+1)/2=0   j=2-0=2
         A[0..-1] 全进右半，A[-1]=哨兵 INT_MIN；A[0]=2
         B[0..1] 全进左半，B[1]=3；B[2] 越界→哨兵 INT_MAX
         nums_im1 = INT_MIN  (i==0)
         nums_i   = A[0] = 2  (i=0 < m=1)
         nums_jm1 = B[1] = 3  (j=2 > 0)
         nums_j   = INT_MAX  (j==n==2)
         判定 nums_im1(INT_MIN) <= nums_j(INT_MAX) → 成立
              median1 = max(INT_MIN, 3) = 3
              median2 = min(2, INT_MAX) = 2
              left = i+1 = 1
第 2 轮  left=1 right=1  i=(1+1)/2=1   j=2-1=1
         A 全进左半：A[0]=1-1=0 处的值=A[0]=2；A[1] 越界→哨兵 INT_MAX
         B[0] 进左半：B[0]=1；B[1]=3 进右半
         nums_im1 = A[0] = 2  (i=1 > 0)
         nums_i   = INT_MAX  (i==m==1)
         nums_jm1 = B[0] = 1  (j=1 > 0)
         nums_j   = B[1] = 3  (j=1 < n=2)
         判定 nums_im1(2) <= nums_j(3) → 成立
              median1 = max(2, 1) = 2
              median2 = min(INT_MAX, 3) = 3
              left = i+1 = 2
第 3 轮  left=2 right=1  left>right → 循环结束
总长 m+n=3 奇数 → 返回 median1 = 2 → 2.0 ✓
```

注意第 1 轮里虽然 `nums_im1 <= nums_j` 成立，但它**不是最大的合法 `i`**（`i=1` 也合法且更大），所以继续往右。最终 `median1 = 2`，正是合并后 `[1,2,3]` 的中位数。

### 手动推导 2：`nums1 = [1,2]`, `nums2 = [3,4]`，期望 `2.5`

`m=2, n=2`，`m <= n` 不用交换：`A = nums1 = [1,2]`（`m=2`），`B = nums2 = [3,4]`（`n=2`）。`(m+n+1)/2 = (2+2+1)/2 = 2`，`j = 2 - i`。`left=0, right=m=2`。

```
第 1 轮  left=0 right=2  i=(0+2)/2=1   j=2-1=1
         nums_im1 = A[0] = 1
         nums_i   = A[1] = 2
         nums_jm1 = B[0] = 3
         nums_j   = B[1] = 4
         判定 nums_im1(1) <= nums_j(4) → 成立
              median1 = max(1, 3) = 3
              median2 = min(2, 4) = 2
              left = i+1 = 2
第 2 轮  left=2 right=2  i=(2+2)/2=2   j=2-2=0
         nums_im1 = A[1] = 2
         nums_i   = INT_MAX  (i==m==2)
         nums_jm1 = INT_MIN  (j==0)
         nums_j   = B[0] = 3
         判定 nums_im1(2) <= nums_j(3) → 成立
              median1 = max(2, INT_MIN) = 2
              median2 = min(INT_MAX, 3) = 3
              left = i+1 = 3
第 3 轮  left=3 right=2  left>right → 循环结束
总长 m+n=4 偶数 → 返回 (median1 + median2) / 2.0 = (2+3)/2.0 = 2.5 ✓
```

最终 `median1 = 2`（左半最大）、`median2 = 3`（右半最小），`(2+3)/2.0 = 2.5`，正是合并后 `[1,2,3,4]` 的中位数 `(2+3)/2`。

## 代码

```cpp
class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1, vector<int>& nums2) {
        // vector<int>& nums1, nums2：两个升序 int 数组，按引用传入（力扣默认含 <vector>）。
        //   - 返回 double：因为偶数长度中位数可能是小数（如 2.5）。

        // ★ 第 1 步：保证 nums1 是较短的那个数组。
        //   - 后续二分是在 nums1 上做（范围 [0,m]），m 越小二分越快，复杂度 O(log min(m,n))。
        //   - 更重要的原因：若 m > n，则 j = (m+n+1)/2 - i 在 i 取大值时可能算成负数，
        //     导致 nums2[j-1] 越界。保证 m <= n 就能让 j 始终落在 [0, n] 合法区间。
        //   - 交换做法：直接调自己（递归一次，参数顺序反过来）。递归只发生一次，无性能问题。
        if (nums1.size() > nums2.size()) {
            return findMedianSortedArrays(nums2, nums1);
        }

        // 把较短数组记作 A（要二分的），较长数组记作 B。
        //   - m = A.size()、n = B.size()，此时保证 m <= n。
        int m = nums1.size();
        int n = nums2.size();

        // 二分划分点 i：A 中前 i 个元素进左半，范围是闭区间 [0, m]（注意 i 能取到 m，表示 A 全进左半）。
        //   - 和 35/33 题的闭区间二分一致：left=0、right=m，循环条件 left <= right。
        int left = 0, right = m;
        // median1：合法划分时「左半部分的最大值」；median2：「右半部分的最小值」。
        //   - 奇数总长返回 median1；偶数总长返回 (median1+median2)/2.0。
        //   - 这两个变量在循环里每轮都可能被覆盖更新，最终留下的是「最大合法 i」对应的那一组值。
        int median1 = 0, median2 = 0;

        while (left <= right) {
            // i：A 的划分位置（A 前 i 个进左半）。
            //   - (left+right)/2 在本题 m<=1000，绝不可能溢出，不必写防溢出形式；
            //     但写 left+(right-left)/2 也完全可以（35 题讲过的防溢出写法），效果一致。
            int i = (left + right) / 2;
            // ★ i 和 j 的关系（全篇命脉）：左半元素总数固定为 (m+n+1)/2，
            //   A 贡献 i 个，B 就得贡献 j = (m+n+1)/2 - i 个。
            //   - 这个 (m+n+1)/2 的 +1 是为了奇数总长时让左半多放一个，
            //     这样奇数时中位数 = median1 单独就是答案，奇偶处理统一。
            int j = (m + n + 1) / 2 - i;

            // 读出四个边界值，带哨兵处理越界情况：
            //   nums_im1 = A[i-1]（A 左半最大值）；nums_i = A[i]（A 右半最小值）；
            //   nums_jm1 = B[j-1]（B 左半最大值）；nums_j = B[j]（B 右半最小值）。
            // - i==0 时 A 没贡献左半 → A[i-1] 不存在 → 设 INT_MIN（负无穷），
            //   让它绝对不可能成为左半 max，对后续比较无害。
            // - i==m 时 A 没贡献右半 → A[i] 不存在 → 设 INT_MAX（正无穷），不会成为右半 min。
            // - j==0 / j==n 同理对 B 处理。
            //   ★ 这是本题最优雅的一步：用 ±∞ 哨兵把所有边界情况统一成同一套比较逻辑，
            //     不用单独判 i==0、i==m、j==0、j==n，代码干净很多。
            int nums_im1 = (i == 0 ? INT_MIN : nums1[i - 1]);
            int nums_i   = (i == m ? INT_MAX : nums1[i]);
            int nums_jm1 = (j == 0 ? INT_MIN : nums2[j - 1]);
            int nums_j   = (j == n ? INT_MAX : nums2[j]);

            // 判定当前 i 是否合法（找「最大的满足 nums_im1 <= nums_j 的 i」）。
            if (nums_im1 <= nums_j) {
                // nums_im1 <= nums_j 成立：当前 i 合法（或偏小）。
                //   顺便把答案候选记下来——这组划分对应的左半最大、右半最小：
                //   - median1 = max(A 左半最大, B 左半最大) = 左半整体最大值
                //   - median2 = min(A 右半最小, B 右半最小) = 右半整体最小值
                //   - 哨兵 INT_MIN/INT_MAX 在这里发挥作用：如果 A 没贡献左半(nums_im1=INT_MIN)，
                //     max(INT_MIN, nums_jm1) 自然取 nums_jm1，不会污染结果。
                median1 = max(nums_im1, nums_jm1);
                median2 = min(nums_i, nums_j);
                // 继续往右找更大的 i（我们要找最大的合法 i）。
                //   - 不会有「漏掉」：哪怕后面全都不合法，median1/median2 已记下当前这组合法值。
                left = i + 1;
            } else {
                // nums_im1 > nums_j：i 取太大了（A 切多了），A[i-1] 跑到 B[j] 前面去还留在左半，
                //   违反大小条件。需要 i 往左挪。
                right = i - 1;
            }
        }

        // 循环结束时，median1/median2 存的是「最大合法 i」对应的那组值。
        //   - 总长奇数：左半多放一个，中位数 = 左半最大值 median1。
        //   - 总长偶数：中位数 = (左半最大 + 右半最小) / 2.0。
        //   ★ 注意除以 2.0 而不是 2：2.0 是 double，整个表达式提升为 double 运算得到小数；
        //     写 / 2（整数除法）会丢掉小数部分（如 (2+3)/2 得 2 而不是 2.5）。
        return (m + n) % 2 == 0 ? (median1 + median2) / 2.0 : median1;
    }
};
```

## 复杂度

- **时间**：O(log min(m,n))，其中 `m`、`n` 分别是两数组长度。
  - 二分范围是 `[0, m]`（`m` 是较短数组长度），每轮区间缩一半，最多迭代 ⌈log₂(m+1)⌉ 次。`m <= 1000` 时最多约 10 次。
  - 由于开头保证 `m <= n`，二分长度只取决于较短数组，所以是 `O(log min(m,n))` 而非 `O(log(m+n))`。这比方法一「二分找第 k 小」(O(log(m+n))) 还要略优，也是本题能达到的最优时间。
- **空间**：O(1)。
  - 只用了 `left` / `right` / `i` / `j` / 四个边界值 / `median1` / `median2` 等常数个变量。开头那次递归交换最多多一层调用栈，整体仍算 O(1)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么一定要在「较短数组」上二分？换成长数组会怎样？

为了保证 `j = (m+n+1)/2 - i` 始终落在 `[0, n]` 合法区间。

设 `A` 是被二分的数组（长度 `m`）、`B` 是另一个（长度 `n`）。`i ∈ [0, m]` 时 `j` 的范围是 `[(m+n+1)/2 - m, (m+n+1)/2]`。

- 若 `m <= n`（`A` 较短）：`j` 最小值 `(m+n+1)/2 - m >= 0`（因为 `n >= m`），最大值 `(m+n+1)/2 <= n`（因为 `m <= n`）。`j` 始终合法。
- 若 `m > n`（`A` 较长）：`i` 取到较大值（接近 `m`）时，`(m+n+1)/2 - i` 可能算成**负数**（比如 `m=10, n=2, i=7` 时 `j = (13)/2 - 7 = 6 - 7 = -1`），`B[j-1]` 直接越界崩溃。

所以代码开头必须判断、必要时交换两数组，把短的换到 `A` 的位置。这也是「O(log min(m,n))」复杂度的来源——二分范围被压到了较短数组长度。

### Q2：`j = (m+n+1)/2 - i` 这个式子怎么来的？为什么是 `+1`？

来自「个数条件」。左半要放「总长一半」的元素：

- 偶数总长（如 `m+n=4`）：左半右半各一半，左半 2 个。
- 奇数总长（如 `m+n=5`）：左半比右半多 1，左半 3 个。

把两种情况**统一**成一个式子就是 `左半个数 = (m+n+1)/2`（整数除法）：

- `(4+1)/2 = 2`，偶数对。
- `(5+1)/2 = 3`，奇数对。

那个 `+1` 就是为了奇数时让左半多放一个，这样**奇数时中位数直接等于左半最大值 `median1`**（左半已经包含了正中间那个数），不用再特判。`j = (m+n+1)/2 - i` 就是「左半总数减去 `A` 贡献的 `i` 个，剩下由 `B` 贡献」。

### Q3：边界处理为什么用 `INT_MIN` / `INT_MAX` 当哨兵？

为了避免单独判 `i==0`、`i==m`、`j==0`、`j==n` 这四种「某数组没贡献左半/右半」的情况。

- `i == 0`（`A` 全进右半，没贡献左半）：`A[i-1]` 不存在。但「左半最大值」这时只能来自 `B`，`A` 不该参与比较。设 `nums_im1 = INT_MIN`，让它**绝对不可能**成为 `max(nums_im1, nums_jm1)` 的赢家，等价于「`A` 没贡献左半」。
- `i == m`（`A` 全进左半，没贡献右半）：`A[i]` 不存在，同理设 `INT_MAX`，让它在 `min(nums_i, nums_j)` 里永远输掉。
- `j == 0` / `j == n` 对 `B` 同理。

用哨兵的好处是后续比较代码完全统一，不用为四种边界各写一套分支；坏处是要记得 `INT_MIN` / `INT_MAX` 的语义（「不存在」=「不影响」）。注意题目数据范围 `nums[i] ∈ [-10^6, 10^6]`，远小于 `INT_MIN ≈ -21亿` / `INT_MAX ≈ 21亿`，哨兵不会和真实数据混淆。

### Q4：循环里 `nums_im1 <= nums_j` 成立时为什么要 `left = i + 1` 往右找？不是已经合法了吗？

因为我们要找的是**最大**的合法 `i`，不是任意一个合法 `i`。

为什么必须是最大的？因为「`nums_im1 <= nums_j`」只保证了**一条**大小条件（`A[i-1] <= B[j]`），另一条 `B[j-1] <= A[i]` 还没保证。但官方证明：随着 `i` 递增，`A[i-1]` 单调增、`B[j]` 单调减（`j` 随 `i` 增而减），所以 `A[i-1] <= B[j]` 这个条件**从成立单调地变到不成立**，存在唯一的临界点（最大的合法 `i`）。而这个临界 `i` 会自动让另一条 `B[j-1] <= A[i]` 也成立（反证：若 `i+1` 不满足 `A[i] <= B[j'-1]`，则 `A[i] > B[j'-1]`，正好补上）。

所以策略是：只要当前 `i` 合法（`nums_im1 <= nums_j`），就 **记下答案候选** 然后 **`left = i + 1` 继续往右**，直到往右再也找不到合法 `i` 为止。循环结束时 `median1/median2` 里留的就是那个最大合法 `i` 对应的值。这个「边找边记、往右逼近」的写法比「找到精确临界再 return」更不容易写错边界。

### Q5：`A[i-1]` 太大时，为什么 `i` 要往左挪？数组不是升序的吗？

对，正因为升序，`i` 往右时 `A[i-1]` 只会更大。要让 `A[i-1]` 变小，切口必须往左。

`i` 是切口：左半是 `A[0..i-1]`，所以 `A[i-1]` 是 A 左半里最大的那个。`i` 往右 = 左半多塞一个更大的数。出现 `A[i-1] > B[j]` 时，问题是一个太大的数还停在左半，要把它踢到右半，切口往左：

```
A:  1  5  [8]  9          i=3，8 是 A[i-1]，还在左半
            ↑切口

A:  1  5  |  8  9          i 减到 2，8 被挪到右半，新的 A[i-1]=5
          ↑切口往左
```

同时 `j = (m+n+1)/2 - i` 会变大，B 多贡献几个给左半，`B[j]` 也会变大，更容易满足 `A[i-1] <= B[j]`。第四步表格、第七步判定、代码 `else { right = i - 1; }` 说的都是这件事。

## 复盘

- **可迁移套路**：**「二分找划分点」** 是本题最重要的抽象。一旦把题意翻译成「在单调变化的某个量上找一个临界点」，就能套二分。本题翻译成「在较短数组上二分划分位置 `i`，使得 `A[i-1] <= B[j]` 恰好成立」。这个「把中位数抽象成划分」的视角还可以推广到：
  - **295 数据流的中位数**：用两个堆（大顶堆放左半、小顶堆放右半）动态维护这个划分，本质是同一思想（左半最大 ≤ 右半最小）的流式版本。
  - 求两个有序数组第 `k` 小：方法一的 `getKthElement` 思路（每次砍掉 `k/2` 个），也是「在有序结构上二分砍」。
- **本题难点回顾**：三件事一定要吃透——
  1. **中位数的划分本质**：左半个数 = 右半个数（或多 1）+ 左半最大 ≤ 右半最小。
  2. **i 和 j 的绑定关系**：`j = (m+n+1)/2 - i`，四个未知数退化成一个，才能二分。
  3. **较短数组上二分 + 哨兵边界**：前者保证 `j` 合法，后者把四种边界统一掉。
- **和方法一（getKthElement）对比**：
  - **思路**：方法一把中位数转化成「找第 `k` 小」（奇数 `k = (m+n+1)/2`，偶数 `k = m/2` 和 `m/2+1` 两个的平均），每轮比较 `A[k/2-1]` 和 `B[k/2-1]`，砍掉较小的前 `k/2` 个，`k` 减半。更贴近「二分砍」的直觉，但调用两次（偶数）。
  - **复杂度**：方法一 O(log(m+n))，方法二 O(log min(m,n))，方法二略优。Hot 100 收录的是方法二的思路（划分数组），它更「巧」也更难。两种都属于官方推荐解，背方法二（主解）即可，方法一能在「复盘」看懂。
- **易错点速查（本题专属）**：
  - 漏了「保证 A 是较短数组」的交换 → `j` 可能负数越界（见 Q1）。
  - `j = (m+n+1)/2 - i` 写成 `j = (m+n)/2 - i` → 奇数总长时左半少放一个，中位数错位（见 Q2）。
  - 边界不用哨兵、硬判 `i==0` 等 → 代码冗长且容易漏分支（见 Q3）。
  - 返回偶数中位数时写 `/ 2` 而非 `/ 2.0` → 整数除法丢小数（`(2+3)/2 = 2` 而非 `2.5`）。
- **二分通用易错点**（沿用 35/33 题复盘）：闭区间 `[0, m]` 配 `left <= right`；`mid` 防溢出写 `left+(right-left)/2`（本题 `m<=1000` 实际不溢，但养成习惯）；收缩 `left = mid+1` / `right = mid-1` 必带 `±1` 防死循环。
