# 34 在排序数组中查找元素的第一个和最后一个位置

- 难度：中等
- 标签：数组、**二分查找**
- 力扣链接：https://leetcode.cn/problems/find-first-and-last-position-of-element-in-sorted-array/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[在排序数组中查找元素的第一个和最后一个位置](https://leetcode.cn/problems/find-first-and-last-position-of-element-in-sorted-array/solution/zai-pai-xu-shu-zu-zhong-cha-zhao-yuan-su-de-di-3-4/)」方法一：二分查找。正文主解是 **两次二分分别找左、右边界**（写两个对称的辅助函数 `leftBound` / `rightBound`），O(log n) 时间 O(1) 空间。本题是 **35 题「搜索插入位置」的进阶**——35 题找精确值或「第一个 `>= target`」的位置，这里数组**有重复元素**，要找的是**一段连续 target 的两个端点**。官方那种「用一个 `lower` 开关把两次二分合并成一个函数」的复用写法放在「复盘」对比。

## 题目描述

给你一个按照**非递减顺序**排列的整数数组 `nums`，和一个目标值 `target`。请你找出给定目标值在数组中的**开始位置和结束位置**。

如果数组中不存在目标值 `target`，返回 `[-1, -1]`。

你必须设计并实现时间复杂度为 `O(log n)` 的算法解决此问题。

**示例 1：**

```
输入：nums = [5,7,7,8,8,10], target = 8
输出：[3,4]
```

**示例 2：**

```
输入：nums = [5,7,7,8,8,10], target = 6
输出：[-1,-1]
```

**示例 3：**

```
输入：nums = [], target = 0
输出：[-1,-1]
```

**提示：**

- `0 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`
- `nums` 是一个**非递减**数组
- `-10^9 <= target <= 10^9`

> 题面四个关键前提一定要看清：**非递减（即升序但允许相邻相等）**、**可能有重复元素**、**找不到返回 `[-1,-1]`**、**强制 O(log n) 必须二分**。`nums.length` 可以是 `0`（空数组），要单独处理或让二分自然返回 `[-1,-1]`。

## 思路

> 本题主要参考力扣官方题解「方法一：二分查找」。下面重点讲清「**用二分找左右边界**」这个技巧——它和 35 题「找精确值/插入位置」是同一个模板的两种用法。

### 问题转化：题目其实在问什么？

数组是非递减的，`target` 可能**连续出现多次**。我们要返回这一段的**起点下标**和**终点下标**。

把题意翻译成二分能处理的「找某个位置」的语言：

- 起点下标 = **第一个等于 `target` 的位置**，也就是「第一个 `>= target` 的位置」（因为数组有序，第一个 `>= target` 的要么就是 `target`、要么就比 `target` 大，两种情况区分就是没找到的处理）。
- 终点下标 = **最后一个等于 `target` 的位置**，也就是「最后一个 `<= target` 的位置」。

这样一翻译，问题就拆成了**两个标准的「二分找边界」子问题**：一个找下界（第一个 `>= target`）、一个找上界（最后一个 `<= target`）。各跑一次二分，O(log n) × 2 = O(log n)，满足题目强制要求。

> 和 35 题的区别：35 题找的是「第一个 `>= target` 的位置」**一个**位置（且数组无重复，找到精确值可直接 `return mid`）；本题找的是**两个**端点（且数组有重复，必须老老实实把整段二分跑完、用 `ans` 记下最左/最右，不能中途 `return`）。所以官方题解的 `ans` 写法（见 35 题复盘）正是这里的主武器。

### 暴力为什么不行（先想最朴素的）

最直白的做法：从前往后扫一遍，记下第一次遇到 `target` 的下标（起点）和最后一次遇到 `target` 的下标（终点）。一次遍历 O(n)，能做对，但**没利用到「数组已排序」这个条件**，复杂度 O(n) 达不到题目强制要求的 O(log n)。题目就是逼你用二分。

### 二分找边界：左、右两个辅助函数各怎么写

我们**写两个对称的函数**，把「找第一个 `>= target`」和「找最后一个 `<= target`」分开，逻辑最清晰、差异最容易对比（官方是把两者合并成一个带 `lower` 开关的函数，放在复盘对比）。两个函数的骨架都是 35 题那套「`left` / `right` / `mid` + 闭区间 `while(left<=right)`」，区别只在**收缩条件和 `ans` 记录**。

**① `leftBound`：找「第一个 `>= target` 的位置」（左边界/下界）**

```text
int ans = n;              // 初始值给 n：兜底「target 比所有元素都大」
while (left <= right) {
    int mid = left + (right - left) / 2;   // 防溢出（见 35 题 Q2）
    if (nums[mid] >= target) {             // ★ 关键：用 >= 判
        ans = mid;                         //   mid 是个候选「第一个 >= target」，记下来
        right = mid - 1;                   //   但左边可能还有更靠左的 >= target，往左压
    } else {                               // nums[mid] < target
        left = mid + 1;                    //   mid 及左侧全 < target，往右抬
    }
}
return ans;                // ans 就是第一个 >= target 的下标（找不到时是 n）
```

为什么 `>=` 能找到「第一个」？因为每次遇到 `nums[mid] >= target`，我们**先把它记进 `ans`**，然后**继续往左看**有没有更靠左的 `>= target`——只要右边一直收缩 `right = mid - 1`，最终 `ans` 会被推到**最左**那个满足 `>= target` 的下标。`>=` 而不是 `==`，是为了把「等于 target」和「大于 target」都归到「候选」分支里，这样即使 target 不在数组里，也能返回「第一个比 target 大的位置」（这是没找到的标志）。

**② `rightBound`：找「最后一个 `<= target` 的位置」（右边界/上界）**

```text
int ans = -1;              // 初始值给 -1：兜底「target 比所有元素都小」
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] <= target) {             // ★ 关键：用 <= 判（和 leftBound 完全对称）
        ans = mid;                         //   mid 是个候选「最后一个 <= target」，记下来
        left = mid + 1;                    //   但右边可能还有更靠右的 <= target，往右抬
    } else {                               // nums[mid] > target
        right = mid - 1;                   //   mid 及右侧全 > target，往左压
    }
}
return ans;                // ans 就是最后一个 <= target 的下标（找不到时是 -1）
```

为什么 `<=` 能找到「最后一个」？和上面**完全对称**：每次遇到 `nums[mid] <= target`，记进 `ans` 后**继续往右看**有没有更靠右的 `<= target`——只要 `left = mid + 1` 一直抬，`ans` 会被推到**最右**那个满足 `<= target` 的下标。

**两个二分的差异对照表（重点）**：

| | `leftBound`（找左/下界） | `rightBound`（找右/上界） |
|---|---|---|
| 要找的位置 | 第一个 `>= target` | 最后一个 `<= target` |
| 判断条件 | `nums[mid] >= target` | `nums[mid] <= target` |
| 命中后怎么走 | 往**左**压：`right = mid - 1` | 往**右**抬：`left = mid + 1` |
| 命中后更新 `ans` | `ans = mid` | `ans = mid` |
| 不命中怎么走 | 往**右**抬：`left = mid + 1` | 往**左**压：`right = mid - 1` |
| `ans` 初始值 | `n`（兜底「都比 target 大」） | `-1`（兜底「都比 target 小」） |

**口诀**：`>=` 往左压找第一个、`<=` 往右抬找最后一个。两边完全对称，记一个推另一个。

### 怎么判断「找到了」还是「target 根本不在数组里」

`leftBound` 返回的可能是 `n`（target 比所有都大），`rightBound` 返回的可能是 `-1`（target 比所有都小）——这两种都是「没找到」。还有一种：target 落在数组范围内但不等于任何元素（如 `nums=[5,7,7,8,8,10], target=6`），此时 `leftBound` 会返回第一个 `>= 6` 的下标 `1`（`nums[1]=7`），`rightBound` 会返回最后一个 `<= 6` 的下标 `0`（`nums[0]=5`），出现 `leftBound(1) > rightBound(0)` 这种「左 > 右」的怪情况，也是没找到。

所以统一用一个校验条件判断「是否真的找到了」：

```text
if (lb <= rb && lb < n && nums[lb] == target && nums[rb] == target)
    return {lb, rb};      // 真正找到一段
else
    return {-1, -1};      // 否则没找到
```

关键是 `lb <= rb`：左边界不可能大于右边界，一旦大于就说明这一段不存在。再加 `nums[lb] == target && nums[rb] == target` 双保险（确认两端确实等于 target 而不是「第一个比 target 大 / 最后一个比 target 小」），就万无一失了。注意校验前要先判 `lb < n`、`rb >= 0`，否则 `nums[lb]` / `nums[rb]` 会越界（`lb` 可能等于 `n`、`rb` 可能等于 `-1`）。

### 手动推导：`nums = [5,7,7,8,8,10]`，`target = 8`，得 `[3,4]`

下标：`0:5, 1:7, 2:7, 3:8, 4:8, 5:10`。先跑 `leftBound(nums, 8)`：

```
初始  left=0 right=5  ans=6(n)
第1轮  mid=0+(5-0)/2=2  nums[2]=7  7 >= 8? 否 → left=mid+1=3
第2轮  left=3 right=5  mid=3+(5-3)/2=4  nums[4]=8  8 >= 8? 是 → ans=4, right=mid-1=3
第3轮  left=3 right=3  mid=3+(3-3)/2=3  nums[3]=8  8 >= 8? 是 → ans=3, right=mid-1=2
第4轮  left=3 right=2  left>right → 循环结束
返回 ans=3   ✓ 这是第一个 >= 8 的下标（nums[3]=8）
```

再跑 `rightBound(nums, 8)`：

```
初始  left=0 right=5  ans=-1
第1轮  mid=0+(5-0)/2=2  nums[2]=7  7 <= 8? 是 → ans=2, left=mid+1=3
第2轮  left=3 right=5  mid=3+(5-3)/2=4  nums[4]=8  8 <= 8? 是 → ans=4, left=mid+1=5
第3轮  left=5 right=5  mid=5+(5-5)/2=5  nums[5]=10  10 <= 8? 否 → right=mid-1=4
第4轮  left=5 right=4  left>right → 循环结束
返回 ans=4   ✓ 这是最后一个 <= 8 的下标（nums[4]=8）
```

校验：`lb=3 <= rb=4`、`nums[3]==8`、`nums[4]==8` 全成立，返回 `[3,4]`。✓

注意 `leftBound` 在第 2 轮先把 `ans` 记成了 `4`（下标 4 也是 `>=8`），但第 3 轮又继续往左压，把它**修正**成更靠左的 `3`——这正是「`ans` + 往左压」能找到「第一个」的原因。`rightBound` 同理，第 2 轮把 `ans` 从 `2` 抬到 `4`，最终停在 `4`。

## 代码

```cpp
class Solution {
public:
    // leftBound：在 [0, n-1] 中找「第一个 >= target 的下标」。
    //   - 找不到（target 比所有元素都大）时返回 n（ans 的初始值），后续校验会兜住。
    //   - 这是「二分找下界」的标准写法，和 35 题复盘里官方 ans 版完全一致。
    int leftBound(vector<int>& nums, int target) {
        int left = 0, right = (int)nums.size() - 1;
        //   - (int) 强转 nums.size()：size() 返回 size_t（无符号），减 1 后赋给 int 前显式转换，
        //     消除「有符号/无符号比较」警告，也避免空数组时 0-1 回绕成巨大正数。
        int ans = (int)nums.size();
        //   - ans 初值设为 n（数组长度），意义是「候选的最右边界」。
        //     如果整个循环里没有任何 nums[mid] >= target（即 target 比所有元素都大），
        //     ans 保持 n 不变，表示「第一个 >= target 的位置是数组末尾之外」，等价于没找到。
        while (left <= right) {
            //   - while(left<=right)：闭区间 [left,right] 的标配，带等号才能查到最后一个元素。
            int mid = left + (right - left) / 2;
            //   - mid 防溢出写法：先算 (right-left) 差值再 /2，最后加回 left，绝不溢出。
            //     不要写成 (left+right)/2，大下标时会溢出变负数（见 35 题 Q2）。
            if (nums[mid] >= target) {
                //   - ★ 左边界的关键判断：用 >=，把「等于 target」和「大于 target」都当作候选。
                //     只要 nums[mid] >= target，mid 就是「第一个 >= target」的候选之一，记进 ans；
                //     但左边可能还有更靠左的满足条件，所以继续往左压。
                ans = mid;
                right = mid - 1;
                //   - 命中后往左收缩：right=mid-1，下一轮去 [left, mid-1] 找有没有更靠左的 >= target。
            } else {
                //   - nums[mid] < target：mid 及其左侧全部 < target，不可能含答案，往右抬。
                left = mid + 1;
            }
        }
        return ans;
        //   - 循环结束时 ans 就是最左那个「nums[i] >= target」的 i（或 n 表示没找到）。
    }

    // rightBound：在 [0, n-1] 中找「最后一个 <= target 的下标」。
    //   - 找不到（target 比所有元素都小）时返回 -1（ans 的初始值）。
    //   - 逻辑和 leftBound 完全对称：判断换成 <=，命中后往右抬而不是往左压。
    int rightBound(vector<int>& nums, int target) {
        int left = 0, right = (int)nums.size() - 1;
        int ans = -1;
        //   - ans 初值设为 -1，意义是「候选的最左边界之外」。
        //     如果整个循环里没有任何 nums[mid] <= target（即 target 比所有元素都小），
        //     ans 保持 -1 不变，表示没找到。
        while (left <= right) {
            int mid = left + (right - left) / 2;   // 防溢出，同上
            if (nums[mid] <= target) {
                //   - ★ 右边界的关键判断：用 <=，和左边的 >= 完全对称。
                //     只要 nums[mid] <= target，mid 就是「最后一个 <= target」的候选，记进 ans；
                //     但右边可能还有更靠右的满足条件，所以继续往右抬。
                ans = mid;
                left = mid + 1;
                //   - 命中后往右收缩：left=mid+1，下一轮去 [mid+1, right] 找有没有更靠右的 <= target。
                //     注意这里和 leftBound 反着：那边命中后动 right=mid-1，这里动 left=mid+1。
            } else {
                //   - nums[mid] > target：mid 及其右侧全部 > target，不可能含答案，往左压。
                right = mid - 1;
            }
        }
        return ans;
    }

    vector<int> searchRange(vector<int>& nums, int target) {
        //   - vector<int>& nums：按引用传入的可变长 int 数组（力扣 C++ 默认含 <vector>）。
        //   - 返回类型 vector<int>：长度固定为 2 的下标数组。
        int n = (int)nums.size();
        int lb = leftBound(nums, target);    // 左边界：第一个 >= target
        int rb = rightBound(nums, target);   // 右边界：最后一个 <= target

        // 校验「是否真的找到一段 target」：
        //   - lb <= rb：左边界不能超过右边界（超过说明 target 不在数组里，如 target=6 时 lb=1,rb=0）。
        //   - lb < n：防止下面 nums[lb] 越界（lb 可能等于 n）。
        //   - rb >= 0：防止下面 nums[rb] 越界（rb 可能等于 -1）。
        //   - nums[lb]==target && nums[rb]==target：双保险，确认两端确实等于 target，
        //     而不是「第一个比 target 大 / 最后一个比 target 小」那种没找到的情况。
        if (lb <= rb && lb < n && rb >= 0 && nums[lb] == target && nums[rb] == target) {
            //   - vector<int>{a, b}：C++11 列表初始化，直接构造返回的 vector。
            return vector<int>{lb, rb};
        }
        return vector<int>{-1, -1};
        //   - 走到这里说明 target 不在数组里，返回 [-1,-1]。
    }
};
```

## 复杂度

- **时间**：O(log n)，其中 n 为数组长度。
  - `leftBound` 和 `rightBound` 各跑一次二分，每次区间缩一半最多迭代 ⌈log₂(n+1)⌉ 轮，合计 2·O(log n) = O(log n)。
  - n = 10^5 时每次约 17 轮，两次共约 34 轮，远优于线性扫描的 O(n)，也正是题目强制要求 O(log n) 所指向的算法。
- **空间**：O(1)。
  - 只用了 `left` / `right` / `mid` / `ans` 等常数个下标变量，不随输入规模增长。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么找左边界用 `>=` 收缩、找右边界用 `<=`？

这是「二分找边界」最核心的判断点，看你要找「第一个」还是「最后一个」：

- **找左边界（第一个 `>= target`）**：每当 `nums[mid] >= target`，`mid` 就是个候选，但**左边可能还有更靠左的也满足 `>= target`**，所以记下 `ans = mid` 后要继续往左压（`right = mid - 1`），直到把 `ans` 推到最左。判断必须用 `>=` 而不是 `==`，因为 `==` 会在第一次碰到 `target` 时就停（且不知道是不是最左那个），还会漏掉「target 不存在但要返回第一个比它大的位置」的情况。
- **找右边界（最后一个 `<= target`）**：每当 `nums[mid] <= target`，`mid` 是候选，但**右边可能还有更靠右的也满足 `<= target`**，所以记下 `ans = mid` 后要继续往右抬（`left = mid + 1`），把 `ans` 推到最右。判断用 `<=` 而不是 `==`，道理同上。

两边**完全对称**，判断符号反一下、收缩方向反一下就行。**口诀：`>=` 往左压找第一个、`<=` 往右抬找最后一个**。

### Q2：怎么判断「没找到」？为什么不能直接 `return {lb, rb}`？

因为 `leftBound` 和 `rightBound` 返回的不一定是「等于 target 的位置」：

- target 比所有元素都大：`leftBound` 返回 `n`（越界）。
- target 比所有元素都小：`rightBound` 返回 `-1`（越界）。
- target 在范围内但不等于任何元素（如 `nums=[5,7,7,8,8,10], target=6`）：`leftBound` 返回 `1`（`nums[1]=7`，是第一个 `>=6` 但不等于 6 的），`rightBound` 返回 `0`（`nums[0]=5`，最后一个 `<=6` 但不等于 6 的），出现 `lb(1) > rb(0)` 的怪情况。

所以必须校验。最稳的校验是同时满足三个条件：`lb <= rb`（排除「左 > 右」的怪情况）、两端不越界、且 `nums[lb] == target && nums[rb] == target`（确认两端确实等于 target）。任一不满足都返回 `[-1,-1]`。只看 `lb <= rb` 不够（target 落在范围内但不等于任何元素时也可能 `lb <= rb` 但实际没找到，所以还要 `nums[lb]==target` 双保险）。

### Q3：和 35 题「搜索插入位置」的区别在哪？

两者用的是**同一套二分模板**（闭区间 + `while(left<=right)` + `mid` 防溢出 + `ans` 记录），但目标不同：

| | 35 题（搜索插入位置） | 34 题（本题） |
|---|---|---|
| 数组有无重复 | **无重复** | **有重复**（非递减） |
| 要找的位置 | 1 个（插入位置） | 2 个（起点 + 终点） |
| 二分跑几次 | 1 次 | 2 次（左边界 + 右边界） |
| 能否中途 `return mid` | 能（找到精确值直接返回） | 不能（必须跑完整段找端点，用 `ans` 记录） |
| 找的是什么 | 第一个 `>= target` | 第一个 `>= target` 和最后一个 `<= target` |

35 题复盘里那种「用 `ans` 记录、`target <= nums[mid]` 时更新 `ans` 并往左压」的写法，就是**本题 `leftBound` 的原型**——把「找精确值」和「找边界」统一成「找下界」。所以 35 题吃透了，本题就是再套一次对称的「找上界」。

### Q4：`leftBound` 的 `ans` 初始值为什么是 `n`、`rightBound` 的是 `-1`？

`ans` 的初始值要设成「找不到时的合法返回值」，让循环体不用特判：

- `leftBound` 找「第一个 `>= target`」。如果 target 比所有元素都大，整个循环里 `nums[mid] >= target` 一次都不成立（全是 `<`，走 `left=mid+1`），`ans` 一次都没被赋过。这时返回 `ans` 初值 `n` 表示「比所有都大、插到末尾之外」，后续校验 `lb < n` 会失败、返回 `[-1,-1]`，正确。
- `rightBound` 找「最后一个 `<= target`」。如果 target 比所有元素都小，循环里 `nums[mid] <= target` 一次都不成立，`ans` 保持初值 `-1`，表示「比所有都小、左边没有 <= target 的」，校验 `rb >= 0` 会失败、返回 `[-1,-1]`，正确。

反过来也成立：`leftBound` 初值设 `-1` 也行但语义混乱（`-1` 是「左边界之外」，和「找下界」不对应），所以约定 `leftBound` 初值 `n`、`rightBound` 初值 `-1`，分别对应各自的「越界方向」。

## 复盘

- **可迁移套路：「二分找边界」是模板**。把题意翻译成「找第一个满足某条件的位置」或「找最后一个满足某条件的位置」后，直接套：
  - 找**第一个**满足 `nums[mid] >= target` 的位置 → 判断用 `>=`、命中后往左压 `right = mid - 1`、`ans` 初值设 `n`。
  - 找**最后一个**满足 `nums[mid] <= target` 的位置 → 判断用 `<=`、命中后往右抬 `left = mid + 1`、`ans` 初值设 `-1`。
  - 这是所有「**有序数组找区间**」题的通用武器：本题（找 target 区间）、35 题（找插入位置）、在有序数组里找「第一个 >= x」「最后一个 <= x」等。
- **和 35 题形成二分组的核心进阶**：35 题是「找精确值/插入位置」的入门、只跑一次二分；本题是「找区间两端」、跑两次对称的二分。两题共享同一套模板（闭区间 + `while(left<=right)` + `mid = left+(right-left)/2` 防溢出 + `ans` 记录），本题只是把「找下界」的 `ans` 写法用到底、再补一个对称的「找上界」。后续 33 题（搜索旋转排序数组）、74 题（搜索二维矩阵）都会在这套骨架上做变体。
- **易错点速查（二分找边界通用）**：
  - 判断符号别写错：找左/下界用 `>=`、找右/上界用 `<=`，别无脑写 `==`。
  - 命中后的收缩方向：找第一个就往**左**压（`right = mid - 1`）、找最后一个就往**右**抬（`left = mid + 1`）。
  - `ans` 初值：找第一个用 `n`（兜底「都比 target 大」）、找最后一个用 `-1`（兜底「都比 target 小」）。
  - 别忘了「没找到」的校验：返回前查 `lb <= rb` 且两端不越界且 `nums[lb]==target && nums[rb]==target`，不然会返回错的区间。
  - `mid` 永远写 `left + (right - left) / 2` 防溢出。

### 解法二：官方「`lower` 开关合并成一个函数」写法（对比用）

官方题解把 `leftBound` / `rightBound` 合并成一个带布尔参数 `lower` 的 `binarySearch` 函数：`lower=true` 时找「第一个 `>= target`」（对应左边界），`lower=false` 时找「第一个 `> target`」（注意是严格大于），返回值减 1 就是右边界。两套写法**逻辑等价**，只是官方用「找第一个 > target 再减 1」来表达右边界，省一个辅助函数。

```cpp
class Solution {
public:
    // lower=true  → 找第一个 >= target 的下标（左边界）
    // lower=false → 找第一个 >  target 的下标（右边界+1，用时要减 1）
    int binarySearch(vector<int>& nums, int target, bool lower) {
        int left = 0, right = (int)nums.size() - 1, ans = (int)nums.size();
        while (left <= right) {
            int mid = (left + right) / 2;
            // 这一行是关键：lower 时把 == 也当候选（>=），非 lower 时严格 > 。
            //   - lower=true：nums[mid] > target || nums[mid] >= target，化简就是 nums[mid] >= target。
            //   - lower=false：nums[mid] > target || (false && ...)，化简就是 nums[mid] > target。
            if (nums[mid] > target || (lower && nums[mid] >= target)) {
                right = mid - 1;
                ans = mid;
            } else {
                left = mid + 1;
            }
        }
        return ans;
    }

    vector<int> searchRange(vector<int>& nums, int target) {
        int leftIdx = binarySearch(nums, target, true);              // 第一个 >= target
        int rightIdx = binarySearch(nums, target, false) - 1;        // 第一个 > target 再减 1 = 最后一个 <= target
        // 校验同主解：leftIdx <= rightIdx 且不越界且两端等于 target
        if (leftIdx <= rightIdx && rightIdx < nums.size() && nums[leftIdx] == target && nums[rightIdx] == target) {
            return vector<int>{leftIdx, rightIdx};
        }
        return vector<int>{-1, -1};
    }
};
```

- **时间**：O(log n)；**空间**：O(1)。与主解完全一致。
- **对比**：官方那版只写一个函数、用一个 `lower` 开关区分两种语义，代码更短但判断条件 `nums[mid] > target || (lower && nums[mid] >= target)` 要绕一下脑子才能读懂「`lower=false` 时其实只剩 `nums[mid] > target`」。主解把左右边界拆成两个对称的函数（`leftBound` 用 `>=` 往左压、`rightBound` 用 `<=` 往右抬），**差异一目了然**，适合刚学二分边界、需要反复对比两种写法时用。两套等价，背一套、能读懂另一套即可。
- **注意一个细节差异**：官方那版的右边界是「找第一个 `> target` 再减 1」，主解是「直接找最后一个 `<= target`」，两者结果相同（因为有序数组里「最后一个 `<= target`」的下标 = 「第一个 `> target` 的下标 - 1」），但表达方式不同，思考时挑自己顺手的那个。
