# 153 寻找旋转排序数组中的最小值

- 难度：中等
- 标签：数组、**二分查找**
- 力扣链接：https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「方法一：二分查找」。正文主解是 **二分查找（用 `mid` 和 `nums[right]` 比较）**，O(log n) 时间 O(1) 空间。这是 **33 题「搜索旋转排序数组」的姊妹题**：33 题在旋转数组里找一个具体 target，153 题只找最小值，思路完全相通，但 153 因为只问最小值，所以只拿中点和右端点比就能定方向，写法比 33 更短更干净。

## 题目描述

已知一个长度为 `n` 的数组，预先按照升序排列，经由 `1` 到 `n` 次 **旋转** 后，得到输入数组。例如，原数组 `nums = [0,1,2,4,5,6,7]` 在变化后可能得到：

- 若旋转 `4` 次，则可以得到 `[4,5,6,7,0,1,2]`
- 若旋转 `7` 次，则可以得到 `[0,1,2,4,5,6,7]`

注意，数组 `[a[0], a[1], a[2], ..., a[n-1]]` **旋转一次** 的结果为数组 `[a[n-1], a[0], a[1], a[2], ..., a[n-2]]`。

给你一个元素值 **互不相同** 的数组 `nums`，它原来是一个升序排列的数组，并按上述情形进行了多次旋转。请你找出并返回数组中的 **最小元素**。

你必须设计一个时间复杂度为 `O(log n)` 的算法解决此问题。

**示例 1：**

```
输入：nums = [3,4,5,1,2]
输出：1
解释：原数组为 [1,2,3,4,5] ，旋转 3 次得到输入数组。
```

**示例 2：**

```
输入：nums = [4,5,6,7,0,1,2]
输出：0
解释：原数组为 [0,1,2,4,5,6,7] ，旋转 4 次得到输入数组。
```

**示例 3：**

```
输入：nums = [11,13,15,17]
输出：11
解释：原数组为 [11,13,15,17] ，旋转 4 次得到输入数组。
```

**提示：**

- `n == nums.length`
- `1 <= n <= 5000`
- `-5000 <= nums[i] <= 5000`
- `nums` 中的所有整数 **互不相同**
- `nums` 原来是一个升序排序的数组，并进行了 `1` 至 `n` 次旋转

> 题面三个关键前提一定要看清：**元素互不相同**（这是能用「和右端点比」这一招的根本保证，否则要进 154 题那种去重版）、**旋转过但仍局部有序**（两段升序拼起来）、**必须 O(log n)**（直接指向二分）。

## 思路

> 本题主要参考力扣官方题解「方法一：二分查找」，核心是「拿 `mid` 和 `nums[right]` 比较来定方向」。

### 先看清楚「旋转」到底干了什么

旋转一次就是把最后一个元素搬到开头。原数组升序，旋转 `k` 次后，数组变成「两段升序」拼起来的样子。以 `nums = [3,4,5,1,2]` 为例（原数组 `[1,2,3,4,5]` 旋转 3 次）：

```
下标: 0 1 2 3 4
值:   3 4 5 1 2
        ^
        断点（从 5 到 1 是下降，唯一一处「左边比右边大」）
```

旋转后的数组有个关键性质：**整个数组里只有一处「断点」**——最小值 `1` 把数组切成 `[3,4,5]` 和 `[1,2]` 两段，每段内部都是升序，但第一段的最小值 `3` 比第二段的最大值 `2` 还大。**最小值就是断点的起点**，找到它就找到了答案。题目要求 O(log n)，所以不能线性扫——得上二分。

### 为什么二分有效：旋转数组依然「半有序」

虽然整个数组不是全局升序，但**任意一个 `mid` 位置，要么 `[left, mid]` 是升序段，要么 `[mid, right]` 是升序段**，至少一半是有序的。这正是能二分的基础。剩下的问题是：**拿什么作为「标尺」来判断最小值在左半还是右半？**

### 关键决策：为什么和 `nums[right]` 比较，不和 `nums[left]` 比较？

这是本题最核心的观察。我们先拿 `nums[mid]` 和 `nums[left]` 比会怎样——**会失败**，原因是 `nums[left]` 在两种情况下行为不一致：

- 数组没真正旋转（如 `[11,13,15,17]`），`nums[mid] > nums[left]` 时最小值**可能是 `nums[left]` 本身**，也可能在右半，二分判断不了。
- 数组旋转过了（如 `[3,4,5,1,2]`），`nums[mid] > nums[left]` 时最小值在右半。

同一个比较结果对应两种不同结论，所以 `nums[left]` 不是好标尺。

**改成和 `nums[right]` 比就清晰了**。官方思路是：考虑数组最后一个元素 `x = nums[right]`，**在最小值右侧的元素，它们的值一定都严格小于 `x`；而在最小值左侧（含最小值）的元素，它们的值一定都严格大于 `x`**。于是拿 `nums[mid]` 和 `nums[right]` 比，就能一刀切：

- **`nums[mid] < nums[right]`**：说明 `mid` 落在「最小值右侧的升序段」里，`mid` 到 `right` 这段是升序的。最小值要么就是 `nums[mid]`，要么在 `mid` 左边，**绝不在 `mid` 右边**。所以把 `right = mid`（注意不是 `mid - 1`，因为 `mid` 本身可能是最小值，不能丢掉）。
- **`nums[mid] > nums[right]`**：说明 `mid` 落在「最小值左侧的升序段」里，而 `right` 落在右侧段，**`mid` 到 `right` 之间一定跨过了断点**，最小值就在 `mid` 右边。又因为 `nums[mid]` 已经大于 `nums[right]`，`mid` 不可能是最小值，可以放心 `left = mid + 1`。
- **不会出现 `nums[mid] == nums[right]`**：因为元素互不相同，且只要区间长度 > 1，`mid` 就不会等于 `right`，所以等号情况不存在（这是「互不相同」前提的功劳；如果有重复元素就要进 154 题）。

循环结束时 `left == right`，这个位置就是最小值所在，`return nums[left]`。

### 手动推导：`nums = [3,4,5,1,2]`，找最小值

下标：`0:3, 1:4, 2:5, 3:1, 4:2`。`left = 0, right = 4`。

```
第 1 轮  left=0 right=4  mid=0+(4-0)/2=2   nums[2]=5   5 > nums[4]=2 → 最小值在 mid 右边
                                                        left = mid+1 = 3
第 2 轮  left=3 right=4  mid=3+(4-3)/2=3   nums[3]=1   1 < nums[4]=2 → 右半升序，mid 可能就是最小值
                                                        right = mid = 3
第 3 轮  left=3 right=3  left == right → 循环结束（while 条件用 <，不进循环）
返回 nums[left] = nums[3] = 1 ✓
```

再验两个示例确认普适性：

- `nums = [4,5,6,7,0,1,2]`：`l=0 r=6 mid=3 nums[3]=7 > nums[6]=2 → l=4`；`l=4 r=6 mid=5 nums[5]=1 < nums[6]=2 → r=5`；`l=4 r=5 mid=4 nums[4]=0 < nums[5]=1 → r=4`；`l=4 r=4` 退出，`nums[4]=0` ✓。
- `nums = [11,13,15,17]`（没真正旋转过的情形）：`l=0 r=3 mid=1 nums[1]=13 < nums[3]=17 → r=1`；`l=0 r=1 mid=0 nums[0]=11 < nums[1]=13 → r=0`；`l=0 r=0` 退出，`nums[0]=11` ✓——这种「全程右半有序」的情况，`right` 会一路往左压到 0，最终停在最小值。

## 代码

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        // vector<int>& nums：按引用传入的可变长 int 数组（力扣 C++ 默认包含 <vector>）。
        //   - 用引用 & 避免拷贝整个数组；本题只读不写，但标准二分写法不强求 const。

        // 二分区间：[left, right]，两端都含，最小值一定在这个区间里。
        int left = 0, right = (int)nums.size() - 1;
        //   - (int) 强转：nums.size() 是 size_t（无符号），减 1 赋给 int 前显式转换，
        //     既消除「有符号/无符号比较」的编译警告，也避免空数组时 0-1 回绕成巨大正数
        //     （本题保证 n >= 1，这里其实安全，但养成强转习惯不亏）。

        // ⚠️ 循环条件用 < 不用 <=，这是本题和「35 题」最大的区别，必须想清楚：
        //   - 本题在「区间里只剩一个元素」(left == right) 时，它就是最小值，直接出去 return。
        //     没必要再进一轮循环。
        //   - 如果写 <=：当 left == right 时还进循环，mid = left + (right-left)/2 = left = right，
        //     nums[mid] < nums[right] 永远为假（自己和自己比），走 else 分支 left = mid + 1，
        //     把 left 抬过了 right，再退出就错了。所以必须 <。
        //   - 口诀：这种「用 mid 和某端点比、收缩到 left==right 才停」的二分，循环一律用 <。
        //     它的语义是「只要区间里还有 >= 2 个元素就继续二分」，剩 1 个时直接给答案。
        while (left < right) {
            // mid 取中点：写成 left + (right - left) / 2 而非 (left + right) / 2，防整数溢出。
            //   - left + right 在两者都接近 INT_MAX(≈21亿) 时会溢出变负数，导致 mid 为负、下标越界。
            //   - 先算 (right - left) 差值（远小于 INT_MAX，安全），再除以 2，最后加回 left。
            //   - / 2 对非负 int 是向下取整（如 3/2=1），所以 mid 偏左。
            //     「偏左」很重要：配合下面的「right = mid」（不减 1），mid 偏左能保证区间
            //     每轮都严格缩小，不会死循环（若 mid 偏右，left=mid+1 可能跳不出去）。
            int mid = left + (right - left) / 2;

            // 核心：拿中点和右端点 nums[right] 比，定最小值方向。
            if (nums[mid] < nums[right]) {
                // nums[mid] < nums[right]：mid 到 right 这段是升序的（右半有序），
                //   最小值要么就是 nums[mid]，要么在 mid 左边，绝不在 mid 右边。
                // ⚠️ 用 right = mid，不是 right = mid - 1：
                //   - 因为 mid 本身可能就是最小值（如上面推导里第 2 轮 nums[3]=1），
                //     如果写 mid - 1 就把最小值跳过去了，再也找不回来。
                //   - 这和「找到精确值」的二分不同（那种可以 mid±1 跳过查过的位置），
                //     这里 mid 还没排除，必须把它留在区间里。
                right = mid;
            } else {
                // 走到 else 说明 nums[mid] > nums[right]（元素互不相同，不会有 == ）：
                //   mid 到 right 之间一定跨过了断点，最小值在 mid 右边。
                //   又因为 nums[mid] > nums[right]，mid 本身不可能是最小值，可以放心跳过。
                // 这里可以 left = mid + 1（注意是 +1，把 mid 排除掉，防死循环）。
                left = mid + 1;
            }
        }
        // 循环结束时 left == right，区间收缩到一个点，这个点就是最小值位置。
        return nums[left];
    }
};
```

## 复杂度

- **时间**：O(log n)，其中 n 为数组长度。
  - 每轮循环区间缩一半（要么 `right = mid`、要么 `left = mid + 1`，都在砍掉至少一半），最多迭代 ⌈log₂ n⌉ 次。n = 5000 时约 13 次，远优于线性扫描的 O(n)。
  - 这也正是题目「必须 O(log n)」硬性要求所指向的算法。
- **空间**：O(1)。
  - 只用了 `left` / `right` / `mid` 三个下标变量，常数额外空间。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么是和 `nums[right]` 比，不和 `nums[left]` 比？

这是本题最容易卡住的地方。直觉上「和左端点比」似乎也行，但实际会出错。原因是 `nums[left]` 在两种情况下行为不一致：

- **数组没真正旋转**（旋转了 n 次回到原状，如 `[11,13,15,17]`）：此时 `nums[mid] > nums[left]` 时，最小值**就是 `nums[left]` 本身**（在最左边）。
- **数组旋转过了**（如 `[3,4,5,1,2]`）：此时 `nums[mid] > nums[left]` 时，最小值在**右半**。

同一个比较结果（`nums[mid] > nums[left]`）对应两种完全相反的结论，二分没法决策。

而 `nums[right]` 不存在这个问题。官方原理：**最小值右侧的元素都严格小于 `nums[right]`，最小值左侧（含最小值）的元素都严格大于 `nums[right]`**（因为右侧段是从最小值到 `nums[right]` 的升序段，右侧段的任意值都 <= `nums[right]`；左侧段每个值都 >= 第一段最小值 > 第二段最大值 = nums[right]... 等等，这里其实只需记住右侧段值都 < nums[right]，因为互不相同）。所以 `nums[mid]` 和 `nums[right]` 一比，`mid` 落在哪个段就清楚了，方向唯一确定。

一句话记忆：**旋转数组二分，要定方向就和「远离断点的那个端点」比。最小值一定在断点处，和右端点比能确定 `mid` 在最小值左还是右，所以选右端点。**

### Q2：为什么 `nums[mid] < nums[right]` 时写 `right = mid` 而不是 `right = mid - 1`？

因为 **`mid` 本身可能就是最小值**，不能丢掉。看推导里 `nums = [3,4,5,1,2]` 的第 2 轮：`mid = 3, nums[3] = 1`，它正是最小值。如果写 `right = mid - 1 = 2`，最小值就被排除在区间外了，再也找不回来，会错返回 `nums[2] = 5`。

区分两种二分场景：

| 场景 | 比较 | 收缩 | 原因 |
|---|---|---|---|
| 找精确值（35 题标准二分） | `nums[mid]` vs `target` | `right = mid - 1` | `mid` 已查过不是答案，可跳过 |
| 找边界/最小值（本题） | `nums[mid]` vs `nums[right]` | `right = mid` | `mid` 可能就是答案，必须留在区间里 |

记忆：**「`mid` 可能是答案」时用 `= mid`；「`mid` 已经排除」时才用 `= mid ± 1`。**

### Q3：为什么循环条件用 `<` 不用 `<=`？

因为本题的语义是「区间里只剩一个元素时，它就是答案，直接出去 return」，没必要再进循环。

- 用 `<`：`left == right` 时退出，`return nums[left]` 给出这个唯一元素，对。
- 用 `<=`：`left == right` 时还进循环，此时 `mid = left = right`，`nums[mid] < nums[right]`（自己比自己）永远为假，走 else 分支 `left = mid + 1`，把 `left` 抬过了 `right`，再退出循环时 `left != right`，`return nums[left]` 越界或取错值，错。

这和 35 题「闭区间配 `<=`」并不矛盾——35 题在 `left == right` 时还要再查一次那个元素（看是不是 target），所以用 `<=`；本题在 `left == right` 时那个元素已经是答案了，不用查，所以用 `<`。

**口诀：本题这种「循环体里没有提前 return、靠收缩到单点拿答案」的二分，循环条件一律 `<`。**

### Q4：和 33 题「搜索旋转排序数组」有什么区别？

两题都是旋转数组 + 二分，但目标和写法差异明显：

| 维度 | 33 搜索旋转排序数组 | 153 寻找最小值 |
|---|---|---|
| 目标 | 找一个具体值 `target` 的下标，找不到返回 -1 | 找最小值，一定能找到 |
| 比较对象 | `nums[mid]` vs `target`，外加判断「哪半有序」 | `nums[mid]` vs `nums[right]`，只看方向 |
| 循环条件 | 通常用 `<=`（要查每个元素是不是 target） | 用 `<`（剩单点就是答案） |
| 写法复杂度 | 较长：要判 `mid` 落在左段还是右段，再分情况 | 较短：只需和右端点比一次 |

**关键差异**：33 题因为要找具体值，所以得先判断「`mid` 在左段还是右段」（用 `nums[mid]` 和 `nums[left]` 比），再分情况看 `target` 在有序半段还是无序半段，分支多。153 题只问最小值，**最小值一定是断点起点**，和右端点比就能直接定位，所以只需两个分支，写法干净得多。

33 题的二分思路更通用（能找任意值），153 题是 33 题的特例（只找最小值，所以能简化）。复习时先吃透 33 题，再回看 153 会觉得「砍掉了一半分支」。

## 复盘

- **可迁移套路：旋转（半有序）数组二分，拿 `mid` 和某个端点比较来定方向。** 这是这类题的统一思维模型：
  - 先想清楚「最小值 / target」相对于「断点」的位置关系。
  - 再选一个能唯一确定方向的端点做标尺（本题选 `nums[right]`）。
  - 最后按方向收缩区间，注意「`mid` 可能是答案」时用 `= mid`，「`mid` 已排除」时用 `= mid ± 1`。
- **和 33 题的对比记忆**：33 找任意 target 要判断「`mid` 在左段还是右段」（和 `nums[left]` 比）再分情况，分支多；153 只找最小值，最小值就是断点，和 `nums[right]` 比一次就够，分支少。两者共享「半有序可二分」的大前提。
- **「互不相同」前提的分量**：本题敢直接用 `<` / `>`（不处理 `==`），全靠「元素互不相同」保证了 `nums[mid] != nums[right]`。一旦允许重复（154 题），就要面对 `nums[mid] == nums[right]` 时无法判断方向的尴尬，处理办法是 `right--`（只能退而求其次，最坏退化到 O(n)）。所以 153 是 154 的简化版。
- **易错点速查（旋转数组二分通用）**：
  - 循环条件 `<` 而非 `<=`（剩单点即答案，不用再查）。
  - `mid` 防溢出：永远写 `left + (right - left) / 2`。
  - `nums[mid] < nums[right]` 时 `right = mid`（不减 1，mid 可能是答案）。
  - `nums[mid] > nums[right]` 时 `left = mid + 1`（mid 排除，跳过）。
  - 别用 `nums[left]` 当标尺（见 Q1）。
