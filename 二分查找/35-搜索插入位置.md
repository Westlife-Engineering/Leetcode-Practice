# 35 搜索插入位置

- 难度：简单
- 标签：数组、**二分查找**
- 力扣链接：https://leetcode.cn/problems/search-insert-position/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[搜索插入位置](https://leetcode.cn/problems/search-insert-position/solution/sou-suo-cha-ru-wei-zhi-by-leetcode-soluti-xiao/)」。正文主解是 **二分查找**（标准三段式写法，找到返回下标、没找到 `left` 落在插入位置），O(log n) 时间 O(1) 空间。这是**二分查找组的入门题**，本文会把二分模板的每个细节都讲透。官方另一种「用 `ans` 变量找第一个 >= target」的等价写法放在「复盘」对比。

## 题目描述

给定一个排序数组和一个目标值，在数组中找到目标值，并返回其索引。如果目标值不存在于数组中，返回它将会被按顺序插入的位置。

请必须使用时间复杂度为 `O(log n)` 的算法。

**示例 1:**

```
输入: nums = [1,3,5,6], target = 5
输出: 2
```

**示例 2:**

```
输入: nums = [1,3,5,6], target = 2
输出: 1
```

**示例 3:**

```
输入: nums = [1,3,5,6], target = 7
输出: 4
```

**提示：**

- `1 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- `nums` 为**无重复元素**的**升序**排列数组
- `-10^4 <= target <= 10^4`

> 题面三个关键前提一定要看清：**已排序（升序）**、**无重复元素**、**返回下标或「按顺序插入的位置」**。这三条是能用二分、且能直接 `return left` 的根本原因。

## 思路

> 本题主要参考力扣官方题解「方法一：二分查找」。这是二分查找的入门题，下面把二分模板的每个细节都拆开讲。

### 问题转化：题目其实在问什么？

数组是**升序**的，要找 `target`。如果 `target` 在数组里，返回它的下标；如果不在，返回「它该插在哪个位置，插完之后数组还是升序」。

官方题解把这个条件写得很清楚：插入位置 `pos` 成立的条件是

```
nums[pos-1] < target <= nums[pos]
```

也就是说 `pos` 是**第一个满足 `nums[pos] >= target` 的下标**。如果 `target` 本身就在数组里，那 `nums[pos] == target`，下标 `pos` 也正好是它；如果 `target` 比所有元素都大，`pos` 就是数组长度 `n`（插到末尾）。两种情况被这一句话统一了：**在有序数组里找第一个 `>= target` 的下标**。

### 二分模板：三指针 + 一个循环

「有序 + 找位置」正是二分查找的招牌场景。维护三个下标：

- `left`：当前查找区间的**左边界**（含）。
- `right`：当前查找区间的**右边界**（含）。所以 `[left, right]` 是闭区间。
- `mid`：区间中点，每次拿 `nums[mid]` 和 `target` 比大小，决定丢掉哪一半。

每轮循环做三件事：

1. 算中点：`mid = left + (right - left) / 2`。
2. 比较 `nums[mid]` 和 `target`：
   - `nums[mid] == target`：找到了，直接 `return mid`。
   - `nums[mid] < target`：`target` 只可能在右半边，把 `left` 抬到 `mid + 1`。
   - `nums[mid] > target`：`target` 只可能在左半边，把 `right` 压到 `mid - 1`。
3. 区间不断缩一半，直到 `left > right`（区间空了），说明 `target` 不在数组里。

### 模板的四个关键细节（逐一讲清）

**① 循环条件为什么是 `left <= right`（带等号）？**

因为区间是**闭**的 `[left, right]`，当 `left == right` 时区间里还**剩一个元素没查过**，必须再进一轮循环去检查它。如果写成 `left < right`，就会漏掉这最后一个元素，比如 `nums = [1]`、`target = 1` 时直接不进循环、错返回插入位置而不是 0。**口诀：闭区间配 `<=`，左闭右开区间配 `<`**。两套写法都行，但必须自洽，本文统一用闭区间 + `<=`。

**② `mid` 为什么写成 `left + (right - left) / 2` 而不是 `(left + right) / 2`？**

为了**防整数溢出**。`left + right` 在 `left`、`right` 都接近 `INT_MAX`（约 21 亿）时会溢出，变成负数，再除以 2 得到负的下标，直接越界崩溃。改写成 `left + (right - left) / 2`，先算差值（不会溢出，因为 `right - left` 远小于 `INT_MAX`），再加回 `left`，数学上和 `(left + right) / 2` 完全等价，但永远不会溢出。**这是二分题的标准防坑写法，背下来**。官方代码用 `((right - left) >> 1) + left`，`>> 1` 就是除以 2，等价的位运算写法。

**③ 没找到时为什么 `return left` 就是插入位置？**

这是本题最巧的地方。循环结束时一定有 `left == right + 1`（`left` 刚刚越过 `right`）。我们追一下 `left` 这个指针的语义：它**始终指向「第一个可能 >= target 的位置」**。

- 如果某一轮 `nums[mid] < target`，说明 `mid` 以及它左边**全都小于 target**，`target` 的插入位置至少在 `mid + 1`，于是 `left = mid + 1` 往右抬。注意这一步把所有 `< target` 的位置都「甩」到了 `left` 左边。
- 如果 `nums[mid] > target`（且没找到等号的情况），说明 `mid` 这个位置**可能就是**插入点（第一个 `> target` 的也算 `>= target`），但我们还不确定左边有没有更小的，于是只动 `right = mid - 1`，`left` 不动——`left` 仍可能是答案。

循环结束（`left > right`）时：所有 `< target` 的元素都被 `left = mid + 1` 甩到了 `left` 左边，而所有 `> target` 的元素都在 `left` 右边（被 `right = mid - 1` 挤过去了）。于是 `left` 这个位置**左边全是 `< target` 的、右边全是 `> target` 的**，正好就是 `target` 该插入的缝——也就是「第一个 `>= target` 的下标」。所以 `return left` 直接得到答案。

**④ `left <= right` 和 `left < right` 这两套写法的区别？**

| 写法 | 区间含义 | 循环结束时 | 适合场景 |
|---|---|---|---|
| `left <= right` | 闭区间 `[left, right]` | `left = right + 1`，`left` 就是插入位置 | **找精确值**（本题标准写法），找到能直接 `return mid` |
| `left < right` | 左闭右开 `[left, right)` | `left == right`，落在答案处 | **找边界**（如第一个 >= target），循环里只剩一个元素时不再进入 |

两种都能 AC 本题。本文主解用闭区间 + `<=`，因为它最贴合「标准二分查找」的直觉（找到就 return）；官方题解用 `ans` 变量配合 `<=` 也是一种写法（见复盘）。「左闭右开 + `<`」的写法在 34 / 35 这类「找边界」题里更常见，本文先掌握闭区间写法。

### 手动推导：`nums = [1,3,5,6]`，`target = 2`

下标：`0:1, 1:3, 2:5, 3:6`。`left = 0, right = 3`。

```
第 1 轮  left=0 right=3  mid=0+(3-0)/2=1   nums[1]=3   3 > 2 → right=mid-1=0
         （3 太大，target 若存在只能在 mid 左侧含 mid，但 mid 已查过不是，所以 right 压到 0）
第 2 轮  left=0 right=0  mid=0+(0-0)/2=0   nums[0]=1   1 < 2 → left=mid+1=1
         （1 太小，target 不可能在 0 及其左侧，left 抬到 1）
第 3 轮  left=1 right=0  left > right → 循环结束，target 不在数组里
返回 left=1 ✓
```

`left` 停在 `1`，正是 `2` 该插入的位置（插完后数组是 `[1,2,3,5,6]`，`2` 在下标 1）。

再验两个例子，确认 `return left` 的普适性：

- `target = 5`（在数组里）：第 1 轮 `mid=1, nums[1]=3 < 5 → left=2`；第 2 轮 `mid=2+(3-2)/2=2, nums[2]=5 == 5 → return 2`。命中，返回下标 2。
- `target = 7`（比所有都大）：`mid=1 nums[1]=3<7→left=2`；`mid=2 nums[2]=5<7→left=3`；`mid=3 nums[3]=6<7→left=4`；`left=4 right=3` 退出，返回 `left=4`，正是插到末尾的位置。

## 代码

```cpp
class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        // vector<int>& nums：按引用传入的可变长 int 数组（力扣 C++ 默认包含 <vector>）。
        //   - 用引用 & 避免拷贝整个数组；不加 const 是因为这里虽然不修改，但标准二分不要求 const。
        //   - nums.size()：返回元素个数，类型 size_t（无符号），范围可达 10^4，本题无溢出风险。

        // 闭区间二分：[left, right] 是「还没排查过的范围」，含两端。
        int left = 0, right = (int)nums.size() - 1;
        //   - (int) 强转：nums.size() 是 size_t（无符号），减 1 后赋给 int 前显式转换，
        //     既消除「有符号/无符号比较」的编译警告，也避免空数组时 size_t 的 0-1 回绕成巨大正数
        //     （本题保证 nums.length >= 1，这里其实安全，但养成强转习惯不亏）。

        // while (left <= right)：带等号是闭区间的标配。
        //   - 当 left == right 时，区间里还剩 1 个元素没查，必须再进一轮检查它。
        //   - 若改成 left < right，会漏查最后一个元素（如 nums=[1], target=1 会直接返回 1 而非 0）。
        while (left <= right) {
            // mid 取中点：写成 left + (right - left) / 2 而非 (left + right) / 2，防整数溢出。
            //   - left + right 在两者都接近 INT_MAX(≈21亿) 时会溢出变负数，导致 mid 为负、下标越界。
            //   - 先算 (right - left) 差值（远小于 INT_MAX，安全），再除以 2，最后加回 left，
            //     数学上与 (left+right)/2 完全等价。这是二分题的标准防坑写法。
            //   - / 2 在 C++ 里对非负 int 是向下取整（如 3/2=1），所以 mid 偏左。
            int mid = left + (right - left) / 2;

            // 三段式比较：根据 nums[mid] 与 target 的大小收缩区间。
            if (nums[mid] < target) {
                // mid 及其左侧全部 < target，target 只可能在右半边 → left 跳到 mid+1。
                //   - 必须 mid+1 而不是 mid：mid 已经查过且确定不是答案，跳过它，否则可能死循环。
                left = mid + 1;
            } else if (nums[mid] > target) {
                // mid 及其右侧全部 > target，target 只可能在左半边 → right 压到 mid-1。
                right = mid - 1;
            } else {
                // nums[mid] == target：命中，直接返回下标。题目保证无重复元素，无需找第一个/最后一个。
                return mid;
            }
        }
        // 循环走到这里说明 target 不在数组里（没触发上面的 return mid）。
        // 此时 left == right + 1：left 左边全是 < target 的，右边全是 > target 的，
        // left 正好指向「第一个 >= target 的位置」，也就是 target 该插入的地方。
        //   - target 比所有元素都大时，left 会一路被抬到 n（数组长度），正好是插到末尾的位置。
        //   - target 比所有元素都小时，right 一路被压到 -1，left 仍为 0，插到开头，也对。
        return left;
    }
};
```

## 复杂度

- **时间**：O(log n)，其中 n 为数组长度。
  - 每轮循环区间缩一半，最多迭代 ⌈log₂(n+1)⌉ 次，n = 10^4 时约 14 次，远优于线性扫描的 O(n)。
  - 这也正是题目「必须 O(log n)」硬性要求所指向的算法。
- **空间**：O(1)。
  - 只用了 `left` / `right` / `mid` 三个下标变量，常数额外空间。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：循环条件为什么是 `left <= right` 而不是 `left < right`？

因为本文用的是**闭区间** `[left, right]`，两端都含。当 `left == right` 时，区间里还剩最后一个元素没排查，必须再进一轮循环检查它。如果写成 `left < right`，这最后一个元素会被漏查。

反例：`nums = [1], target = 1`。用 `left < right` 时，初始 `left = 0, right = 0`，条件 `0 < 0` 为假，根本不进循环，直接 `return left = 0`——这题恰好对，但换个 `nums = [1], target = 0`（要插到位置 0）也一样不进循环返回 0，看似对，其实是因为 `left` 初值就是 0 碰巧蒙对。一旦数组稍复杂，`<` 就会漏查。

**口诀：闭区间 `[l,r]` 配 `<=`，左闭右开 `[l,r)` 配 `<`。** 两套写法各自自洽就行，别混着用（比如区间是闭的却写 `<`，或区间是左闭右开却写 `<=` 导致 `mid` 越界）。

### Q2：`mid` 为什么必须写成 `left + (right - left) / 2`？

防 `(left + right)` 整数溢出。`int` 在 C++ 里通常是 32 位，最大约 21.4 亿（`INT_MAX`）。如果 `left` 和 `right` 都接近 21 亿（比如在一个超长数组或下标被放大后），`left + right` 会超过 `INT_MAX` 溢出成负数，`/ 2` 后得到负的 `mid`，访问 `nums[mid]` 直接越界崩溃。

`left + (right - left) / 2` 先算 `right - left`（差值，远小于 `INT_MAX`），再除以 2，最后加回 `left`，数学上完全等价于 `(left + right) / 2`，但永远不会溢出。**这是所有二分题的标配写法**，力扣官方代码也这么写（它用 `((right - left) >> 1) + left`，`>> 1` 是除以 2 的位运算写法，等价）。

本题 `n <= 10^4` 实际不会溢出，但养成习惯，写二分永远用这个形式。

### Q3：没找到 target 时，为什么 `return left` 恰好就是插入位置？

这是本题最核心的理解点。循环结束时 `left == right + 1`（`left` 刚越过 `right`）。追 `left` 的语义：它始终是「下一个还没被排除的、可能 `>= target` 的位置」。

- 每次走 `left = mid + 1`，是因为 `nums[mid] < target`——这把 `mid` 及其左侧**所有 `< target` 的元素**都甩到了 `left` 左边。
- 走 `right = mid - 1` 是因为 `nums[mid] > target`——这些 `> target` 的元素被挤到 `right` 右边，而 `left` 没动。

所以循环结束时，`left` 的**左边全是 `< target`**、**右边（含原 right+1 起）全是 `> target`**，`left` 这个缝就是 `target` 该插入的位置，也就是「第一个 `>= target` 的下标」。两种边界也对：`target` 比所有大都大时 `left` 抬到 `n`（插末尾），比所有都小时 `right` 压到 `-1` 而 `left` 仍为 0（插开头）。

换句话说，**整个二分过程可以等价看成是在找「第一个 `>= target` 的位置」**，找到精确值时提前 `return mid` 只是优化。

### Q4：官方题解为什么多用了个 `ans` 变量？和我这版有啥区别？

官方代码长这样（思路完全一致，写法不同）：

```cpp
int left = 0, right = n - 1, ans = n;          // ans 初值设为 n，兜底「target 比所有都大」
while (left <= right) {
    int mid = ((right - left) >> 1) + left;
    if (target <= nums[mid]) {                 // 注意是 <=，把 == 也归到这里
        ans = mid;                             // mid 是个候选答案，记下来
        right = mid - 1;                       // 继续往左看有没有更小的 >= target
    } else {
        left = mid + 1;
    }
}
return ans;
```

它把「找精确值」和「找插入位置」**统一成「找第一个 `>= target` 的下标」**：只要 `nums[mid] >= target`，就把 `mid` 记进 `ans` 再往左压；最后 `ans` 就是答案。`ans` 初值设为 `n` 是为了兜底「`target` 比所有元素都大、循环里从来没赋过 `ans`」的情况。

本文主解的 `return left` 是**等价**的——循环结束 `left` 恰好落在「第一个 `>= target`」处，省掉了 `ans` 变量。两种写法都对，本文那版更贴近「标准二分找精确值、找不到再说」的直觉，适合入门；官方那版是「二分找下界」的通用模板，在 34 题（找第一个和最后一个位置）里会大量用到。

## 复盘

- **二分模板是所有二分题的基础**。本题就是二分查找组的第 1 题、入门题，把这套「`left`/`right`/`mid` 三指针 + 闭区间 `while(left<=right)` + `mid=left+(right-left)/2` 防溢出 + 按比较收缩 + 找不到返回 `left`」的模板吃透，后续二分题都是在这个骨架上做变体：
  - **34 在排序数组中查找元素的第一个和最后一个位置**：数组有重复元素了，要找 `>= target` 的第一个和 `> target` 的第一个，正是「二分找下界/上界」的标准应用（官方题解里 `ans` 那套写法的直接延伸）。
  - **33 搜索旋转排序数组**：数组不再全局有序而是两段有序，二分时要多判一次「`mid` 落在左段还是右段」。
  - **74 搜索二维矩阵**：把二维下标压成一维再做标准二分，模板不变。
- **「找第一个 `>= target` 的位置」这个二分视角**是本题最重要、最可迁移的抽象。一旦把题意翻译成「找第一个满足某条件的位置」，就能直接套二分。本题翻译成「找第一个 `>= target`」之后，主解代码（哪怕不 `return mid` 提前退出）也天然给出答案。
- **易错点速查（二分通用）**：
  - 循环条件 `<=` 还是 `<`：看区间是闭 `[l,r]` 还是左闭右开 `[l,r)`，两者要配套。
  - `mid` 防溢出：永远写 `left + (right - left) / 2`，不要写 `(left + right) / 2`。
  - 收缩时 `left = mid + 1` / `right = mid - 1`：必须 `±1`，否则剩两个元素时会死循环。
  - 找不到时返回 `left`（闭区间写法）：它就是「第一个 `>= target`」的位置，别误写成返回 `right` 或 `mid`。

### 解法二：官方 `ans` 变量写法（找第一个 `>= target`，对比用）

和主解思路完全等价，只是把「找精确值」和「找插入位置」统一成「找第一个 `>= target` 的下标」，用 `ans` 记录候选答案、`ans` 初值设为 `n` 兜底「`target` 比所有都大」。

```cpp
class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        int n = nums.size();
        int left = 0, right = n - 1, ans = n;   // ans 初值 n：兜底 target 大于所有元素时插到末尾
        while (left <= right) {
            int mid = ((right - left) >> 1) + left;   // >> 1 等价于 / 2，位运算写法
            if (target <= nums[mid]) {         // 注意 <=：把 == 也归到「候选」分支
                ans = mid;                     // mid 是一个可能的插入位置，记下来
                right = mid - 1;               // 往左继续找有没有更小的 >= target
            } else {
                left = mid + 1;                // nums[mid] < target，mid 及左侧全部排除
            }
        }
        return ans;
    }
};
```

- **时间**：O(log n)；**空间**：O(1)。与主解完全一致。
- **对比**：主解找到精确值就 `return mid` 提前退出，更贴近「标准二分查找」直觉；这版永远跑完整程、用 `ans` 收集「第一个 `>= target`」，是「二分找下界」的通用模板，在 34 题里会直接复用。两种写法背一种、理解另一种即可。
