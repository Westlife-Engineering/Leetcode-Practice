# 128 最长连续序列

- 难度：中等
- 标签：并查集、数组、哈希表、**哈希表**
- 力扣链接：https://leetcode.cn/problems/longest-consecutive-sequence/?envType=study-plan-v2&envId=top-100-liked

## 题目描述

给定一个未排序的整数数组 `nums`，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。

请你设计并实现时间复杂度为 **O(n)** 的算法解决此问题。

**示例 1：**

```
输入：nums = [100,4,200,1,3,2]
输出：4
解释：最长数字连续序列是 [1, 2, 3, 4]。它的长度为 4。
```

**示例 2：**

```
输入：nums = [0,3,7,2,5,8,4,6,0,1]
输出：9
```

**示例 3：**

```
输入：nums = [1,0,1,2]
输出：3
```

**数据范围：**

- `0 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

## 思路

> 本题参考力扣官方题解的「哈希表」做法。
> 注：题解正文为动态渲染，初稿代码是这道题标准的哈希表解法，与官方题解思路一致；如需严格对齐原文代码再替换。

**核心要求**：O(n) 时间。直接排序是 O(n log n)，不满足，所以必须用哈希表。

**关键观察**：

1. 想知道一个数 `x` 的后面有没有 `x+1`、`x+2`……，需要**快速判断"某个数在不在数组里"** → 哈希表（`unordered_set`），O(1) 查找。
2. 但如果对每个数都往后数一遍，会重复计算。比如 `[1,2,3,4]`，从 1 数到 4 算了一次，从 2 又会数到 4——总复杂度退化成 O(n²)。
3. **优化 trick**：**只从每段连续序列的"起点"开始数**。怎么判断 `x` 是起点？**`x-1` 不在集合里**。
   - 比如 `[1,2,3,4]`：`1` 是起点（因为 `0` 不在），从 1 往后数；`2` 不是起点（因为 `1` 在），直接跳过。
   - 这样每个元素最多被访问 2 次（一次判断是不是起点，一次被某个起点往后数时碰到），总体仍是 O(n)。

**算法步骤**：

1. 把所有数塞进 `unordered_set`（顺便去重）。
2. 遍历集合里每个数 `num`：
   - 如果 `num-1` **不在**集合里 → `num` 是某段序列的起点，从 `num` 开始一直数 `num+1, num+2, ...`，记录这段长度。
   - 如果 `num-1` **在**集合里 → 跳过（不是起点，会被别的起点算到）。
3. 返回所有段长度的最大值。

## 代码

```cpp
class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        // unordered_set<int>：C++ STL 无序集合容器。
        //   - 底层是哈希表（和 unordered_map 同一套机制）。
        //   - 只存 key 不存 value；元素不重复（重复插入会自动忽略，相当于自带去重）。
        //   - 元素无序（不会按大小排，遍历顺序不固定）。
        //   - 查找/插入/删除均摊 O(1)。
        //   - 本题用它来做两件事：① 把 nums 去重；② O(1) 判断某个数在不在。
        unordered_set<int> num_set;

        // 把 nums 所有元素塞进集合。insert(x)：插入元素 x，已存在                                                                                                                                                                                                                                      则无操作。
        // 写 const int& 同样是为了避免拷贝（虽然 int 拷贝很便宜，写法上保持习惯）。
        for (const int& num : nums) {
            num_set.insert(num);
        }

        int longestStreak = 0;  // 记录全局最长连续序列长度

        // 遍历集合（不是原数组，避免重复元素被多次处理）。
        for (const int& num : num_set) {
            // count(x)：返回集合中 x 的个数（对 set 而言只会是 0 或 1）。
            //   - O(1) 判断 x 在不在集合里。
            //   - 这里判断 num-1 在不在：如果不在，说明 num 是某段连续序列的起点。
            //     只有起点才需要往后数，避免重复计算，保证总复杂度 O(n)。
            if (!num_set.count(num - 1)) {
                int currentNum = num;      // 从 num 开始往后数
                int currentStreak = 1;     // 当前段长度，至少包含 num 自己

                // 不断检查"下一个数"在不在集合里，在就继续延长。
                while (num_set.count(currentNum + 1)) {
                    currentNum += 1;
                    currentStreak += 1;
                }

                // max(a, b)：返回较大值。<algorithm> 里的函数，力扣环境默认包含。
                longestStreak = max(longestStreak, currentStreak);
            }
        }
        return longestStreak;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 把元素塞进集合 O(n)；遍历集合时，每个元素最多被"起点判断"和"被数到"各一次，合计 O(n)。
- **空间**：O(n)
  - 哈希集合存放所有元素。

## 疑惑 / 卡点

> 这块随做题过程中的提问持续更新。

### Q1：`unordered_set` 是什么？

C++ STL 的**无序集合**容器，可以理解成"只存 key、不存 value 的 `unordered_map`"。

| 特性 | 说明 |
|---|---|
| 底层 | 哈希表（和 `unordered_map` 一套机制） |
| 元素 | 只存 key，**不重复**（重复插入会自动忽略） |
| 顺序 | **无序**（遍历顺序不固定） |
| 查找/插入/删除 | 均摊 **O(1)** |
| 典型用途 | 去重 + O(1) 查找"某元素在不在" |

和其他容器的对比：

| 容器 | 存什么 | 是否去重 | 是否有序 | 查找复杂度 |
|---|---|---|---|---|
| `vector<int>` | 序列 | 否 | 保持插入顺序 | O(n) |
| `set<int>` | 集合 | 是 | **从小到大** | O(log n)（红黑树） |
| `unordered_set<int>` | 集合 | 是 | **无序** | **O(1)**（哈希表） |

> 本题选 `unordered_set` 而不是 `set` 的关键：要 O(n) 总复杂度，查找必须 O(1)；如果用 `set`，每次查找 O(log n)，总复杂度退化成 O(n log n)。

### Q2：内层 while 要查找若干次，整个查找过程真的是 O(n) 吗？

这是本题最反直觉的复杂度点。表面看：

- 外层遍历 n 个元素；
- 每个起点进入内层 while 后可能要查很多次（比如 `[1,2,3,...,n]` 从 1 出发要查 n-1 次）；
- 朴素相乘会以为是 O(n²)。

**但实际是 O(n)**，关键在于**均摊分析（amortized analysis）**。

**核心观察：内层 while 的每一次"成功查找"，都唯一消耗掉一个集合里的元素；而每个元素最多被这样消耗一次。** 所以所有"成功查找"加起来 ≤ n 次，不会爆炸。

拆开看每次 while 查 `currentNum+1` 的两种结果：

| 查找结果 | 含义 | 发生次数上限 |
|---|---|---|
| 成功（在集合里） | `currentNum+1` 被**这段序列占用** | 所有成功查找加起来 **≤ n**（每个元素最多被占用一次） |
| 失败（不在集合里） | 这段序列结束，跳出 while | 每个起点最多 1 次失败，起点数 ≤ n |

**为什么一个元素不可能被两个起点"成功查到"？**

假设 `y` 被某段从起点 `x` 开始的序列成功查到，则 `y = x + k`（k ≥ 1）。
→ `y - 1 = x + (k-1)` 也在集合里
→ `y` **不可能是起点**（起点的判定是 `y-1` 不在集合里）
→ 外层遍历到 `y` 时，`count(y-1)` 返回 true，**直接跳过**，不会启动新的内层 while
→ 所以 `y` 只会被那一个起点 `x` 的 while "成功查到"一次

**综合总查找次数**：外层 `count(num-1)` 共 n 次 ＋ 内层成功查找总和 ≤ n 次 ＋ 内层失败查找 ≤ n 次 = **O(n)**。

**用例子验证**（`nums = [1,2,3,4,5]`，n=5）：

| 外层 num | count(num-1) | 进入 while? | while 内查找 | 这次迭代查找次数 |
|---|---|---|---|---|
| 1 | count(0)=false | ✅ 起点 | count(2)✅ count(3)✅ count(4)✅ count(5)✅ count(6)❌ | 1+5=6 |
| 2 | count(1)=true | ❌ 跳过 | — | 1 |
| 3 | count(2)=true | ❌ 跳过 | — | 1 |
| 4 | count(3)=true | ❌ 跳过 | — | 1 |
| 5 | count(4)=true | ❌ 跳过 | — | 1 |

总查找 = 6+1+1+1+1 = **10 次**，n=5，O(n) 量级。`2,3,4,5` 虽在 `num=1` 的 while 里被成功查过，但外层遇到时只做一次 `count(num-1)` 就跳过，**没有再启动新的 while**——这就是不重复计算的关键。

> 一句话总结：**每次查找的"成功"都唯一占用一个元素，每个元素只能被占用一次，所以总成功查找 ≤ n。这就是 O(n) 的根本来源。**

### Q3：if 是 false 的那轮循环是"默认不耗时"吗？

**不是**，这是一个常见误解。"跳过 while" ≠ "这一轮不耗时"。

注意代码每一轮都会执行 `if (!num_set.count(num - 1))`。这个 `count(num-1)` **本身是一次哈希表查找**——它会算 `num-1` 的哈希值、定位桶、看元素在不在。所以不管 if 是 true 还是 false，这一轮**至少做了一次 O(1) 的哈希查找**，并不是"白嫖"。

正确的拆分方式——把 for 循环的总开销拆成两部分：

| 部分 | 干什么 | 单次复杂度 | 总次数 | 小计 |
|---|---|---|---|---|
| **A. if 的 count 检查** | `count(num-1)` 判断是不是起点 | O(1) | 每轮都做，共 n 次 | O(n) |
| **B. while 内部的查找** | 从起点往后数 | O(1) | 所有轮加起来 ≤ n 次（见 Q2） | O(n) |

**合计 = A + B = O(n) + O(n) = O(n)**。

正确说法：
- ❌ 「if 是 false 的那轮不耗时」
- ✅ 「每一轮都耗时（至少一次 `count` 查找，O(1)）；n 轮 × O(1) 已经是 O(n) 了，加上 while 内的总查找（也 ≤ n），整体仍是 O(n)」

## 复盘

- **核心套路**：题目要求 O(n) 又涉及"快速判断元素在不在" → 想到哈希表。
- **关键 trick**：**只从序列起点开始数**（判断条件 `num-1` 不在集合里），把潜在的 O(n²) 优化到 O(n)。
- **STL 要点**：
  - `unordered_set`：去重 + O(1) 查找，本题的核心数据结构。
  - `count(x)` 返回 0/1，常用来做"在不在"的判断。
  - `insert(x)` 对重复元素无操作，自带去重效果。

## 拓展：返回最长连续序列本身，而不是长度

原题只问「最长有多长」，函数返回 `int`。机试更常改成：**把那段连续数字完整交出来**。哈希还是那个哈希（集合去重 + 只从起点往后数），变的是两件事：

1. 函数的 **返回类型**：从 `int` 变成 `vector<int>`（一段递增的连续值）；
2. 找到一段之后 **不要只拿 `max(长度)`**，要把起点和长度记下来，必要时把序列填进答案数组。

下面默认题意钉死：

- 返回的是 **数值上连续** 的那一段，例如 `[100,4,200,1,3,2]` → `[1,2,3,4]`。不是原数组里按下标抽出来的子序列，也不是下标。
- 数组里有重复值时，序列里每个数只出现一次（集合已经去重了）。
- 空数组返回空序列。
- **多段一样长时只交一段**：取起点更小的那一段。例如 `[1,2,3,10,11,12]` 两段都是长度 3，交 `[1,2,3]`。如果某次机试要「所有最长段都交出来」，那是另一道题，返回类型要改成 `vector<vector<int>>`，不要和下面这份混。

### 思路

原题在 `while` 里只做 `currentStreak++`，最后 `return longestStreak`。拓展里这段连续序列其实已经被算出来了：起点是 `num`，长度是 `currentStreak`，整段就是

```text
num, num+1, num+2, ..., num+currentStreak-1
```

所以 **不必边数边往 vector 里 push**。仍然先数长度；只有这段比当前最优更长（或一样长但起点更小）时，才按上面的公式把答案数组填一遍。

手算一遍 `[100, 4, 200, 1, 3, 2]`：

| 起点判断 | 这段序列 | 长度 | 是否更新答案 |
|---|---|---|---|
| `100`：99 不在 → 起点 | `[100]` | 1 | 空 → `[100]` |
| `4`：3 在 → 跳过 | — | — | — |
| `200`：199 不在 → 起点 | `[200]` | 1 | 长度没超过，起点 200 > 100，不换 |
| `1`：0 不在 → 起点 | `[1,2,3,4]` | 4 | 更长 → `[1,2,3,4]` |
| `3`、`2`：前一个都在 → 跳过 | — | — | — |

`unordered_set` 遍历顺序不固定，上面只是按「碰巧这个顺序」演示。因为更新规则是「更长，或同长取更小起点」，最终答案和遍历顺序无关。

### 返回类型怎么选（机试必看）

C++ 函数只能 `return` 一个对象。长度和序列要一起带出去时，常见三种：

| 写法 | 类型 | 什么时候用 |
|---|---|---|
| 只返回序列 | `vector<int>` | 长度就是 `ans.size()`，**最干净，优先用这个** |
| `pair` 打包两个值 | `pair<int, vector<int>>` | 题目函数签名明确要求「返回长度和序列」 |
| 引用传出 | `void f(..., vector<int>& seq)` | 机试自己写 `main` 时也很常见 |

下面主代码只返回 `vector<int>`。`pair` 的 `first` 其实就是 `second.size()`，没有新信息，不必硬写。

机试和力扣还有两个差别，练习时不要混：

- 力扣给你 `class Solution` 和 `int longestConsecutive(...)`；机试要自己写 `#include`、`main`、读入、输出。不要拿这份去交 128 题。
- 输出格式先看题：有的要先打长度再打序列，有的只要空格分隔的一串数。空数组通常打 `0` 或打空行，别自己猜。

### 代码

可以整段贴进 `练习/playground.cpp` 编译跑。

```cpp
#include <iostream>
#include <vector>
#include <unordered_set>
using namespace std;

// 返回最长连续序列本身。长度用 (int)ans.size() 就能拿到。
vector<int> longestConsecutiveSeq(const vector<int>& nums) {
    // unordered_set<int>：和原题一样，无序集合，去重 + O(1) 判断某个数在不在。
    // 构造：unordered_set<int> s(a, b);
    //   a、b 是一对迭代器，表示半开区间 [a, b)。
    //   nums.begin() 指向第一个元素，nums.end() 指向末尾之后。
    //   这行等价于先声明空集合再 for 一遍 insert，写起来更短。
    unordered_set<int> num_set(nums.begin(), nums.end());

    // vector<int> best：当前已知的最长连续序列。
    //   空数组时它保持默认空 {}，size() 为 0，后面比较长度时自然当「还没找到任何段」。
    vector<int> best;

    for (const int& num : num_set) {
        // 仍然只从起点开始数：num-1 不在集合里，才说明 num 是某段的头。
        if (!num_set.count(num - 1)) {
            int currentNum = num;
            int currentStreak = 1;

            while (num_set.count(currentNum + 1)) {
                currentNum += 1;
                currentStreak += 1;
            }

            // 更新条件：这段更长；或一样长，但起点更小（best 非空时才能看 best[0]）。
            //   空数组时 best.empty() 为 true，currentStreak >= 1 一定走「更长」这一支，不会去读 best[0]。
            bool longer = currentStreak > (int)best.size();
            bool sameLenSmallerStart =
                currentStreak == (int)best.size() && !best.empty() && num < best[0];

            if (longer || sameLenSmallerStart) {
                // resize(n)：把 vector 调成恰好 n 个元素。
                //   变长时多出来的 int 默认是 0；变短时尾部丢掉。
                //   这里 n = currentStreak，接下来会立刻全部覆写，默认 0 无所谓。
                //   先 resize 再按下标写，比 clear + 反复 push_back 干净：容量一次到位，不会边推边扩容。
                best.resize(currentStreak);
                for (int i = 0; i < currentStreak; ++i) {
                    best[i] = num + i;   // 第 i 个数一定是起点 + i
                }
            }
        }
    }
    return best;
}

int main() {
    vector<int> nums{100, 4, 200, 1, 3, 2};

    vector<int> ans = longestConsecutiveSeq(nums);
    // 也可以 auto ans = longestConsecutiveSeq(nums);

    cout << ans.size() << "\n";          // 先打长度（原题要的那个数）
    for (int x : ans) {                  // 范围 for：依次取出序列里每个 int
        cout << x << " ";
    }
    cout << "\n";
    // 期望输出：
    // 4
    // 1 2 3 4
    return 0;
}
```

### 复杂度

- **时间**：仍是 O(n)。找最长段的过程和原题完全一样；额外工作只是把最长那一段（长度 L ≤ n）写进 `best`。最坏每次更新都写一遍，更新次数很少（长度严格递增时最多写 1+2+... 但实际每次覆盖，总写入仍 ≤ 若干次 L，L ≤ n），量级还是 O(n)。
- **空间**：O(n)。集合仍要存全部去重后的数；答案数组再占 O(L)，L ≤ n。

原题看起来「只返回一个 int」，空间口头上还是 O(n)，因为集合就在。拓展之后不要以为改成返回序列就突然多了一阶——多的只是把最长那段抄出来。

### 和原题对比时最容易写错的地方

1. **返回类型还写成 `int`，或函数末尾 `return longestStreak`。** 机试要的是序列。长度用 `ans.size()`。
2. **按原数组下标去「抽子序列」。** 本题的「连续」是数值连续，`[100,4,200,1,3,2]` 的答案是 `[1,2,3,4]`，不是从原数组里挑出一段保持原相对顺序的子序列。
3. **边 `while` 边 `current.push_back`，每段都建一个 vector。** 能对，但短段也在分配内存。先数长度，只有要更新 `best` 时再 `resize` + 填值。
4. **用 `unordered_set` 的遍历顺序当序列顺序。** 集合无序，不能 `for (x : num_set)` 指望从小到大。必须从起点 `num` 用 `num, num+1, ...` 自己填。
5. **`best[0]` 在 `best` 为空时去读。** 空数组第一段更新之前 `best` 是空的，直接 `num < best[0]` 是未定义行为。先判断 `!best.empty()`，或先判断「更长」。
6. **`currentStreak > best.size()` 直接比。** `size()` 的类型是 `size_t`（无符号）。`currentStreak` 是 `int`。两边都转成同一种再比更稳：`(int)best.size()`。
7. **多段一样长时依赖哈希表遍历顺序。** `unordered_set` 每次跑顺序可能不同。题目如果要确定答案，必须加并列规则（这里用「起点更小」）；题目如果写「任意一段即可」，并列时不更新也行。
8. **把重复值写进答案。** `[1,0,1,2]` 最长是 `[0,1,2]`，不要输出两个 `1`。集合已经去重，按起点填值就不会重复。

再补几组自测，建议在 `main` 里轮流换数据：

```text
nums = [100,4,200,1,3,2]
→ 长度 4，序列 [1,2,3,4]

nums = [0,3,7,2,5,8,4,6,0,1]
→ 长度 9，序列 [0,1,2,3,4,5,6,7,8]

nums = [1,0,1,2]
→ 长度 3，序列 [0,1,2]   （重复的 1 只算一次）

nums = []
→ 长度 0，序列空

nums = [5]
→ 长度 1，序列 [5]

nums = [1,2,3,10,11,12]
→ 两段都是 3，按「起点更小」交 [1,2,3]
```
