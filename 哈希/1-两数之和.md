# 1 两数之和

- 难度：简单
- 标签：**数组**、**哈希表**
- 力扣链接：https://leetcode.cn/problems/two-sum/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解。正文主解是 **哈希表（一次遍历）**，时间 O(n)；暴力枚举 O(n²) 放在「复盘」作为对比。

## 题目描述

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出 **和为目标值 `target`** 的那 **两个** 整数，并返回它们的数组下标。

你可以假设每种输入只会对应一个答案，并且你**不能使用两次相同的元素**。你可以按任意顺序返回答案。

**示例 1：**

```
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：因为 nums[0] + nums[1] == 9 ，返回 [0, 1] 。
```

**示例 2：**

```
输入：nums = [3,2,4], target = 6
输出：[1,2]
```

**示例 3：**

```
输入：nums = [3,3], target = 6
输出：[0,1]
```

**数据范围：**

- `2 <= nums.length <= 10^4`
- `-10^9 <= nums[i] <= 10^9`
- `-10^9 <= target <= 10^9`
- **只会存在一个有效答案**

**进阶：** 你可以想出一个时间复杂度小于 `O(n²)` 的算法吗？

## 思路

> 本题主要参考力扣官方题解的「哈希表」做法。

先想最直接的暴力做法：两层循环枚举所有数对 `(i, j)`，看 `nums[i] + nums[j] == target` 是否成立。这样要枚举 O(n²) 个数对，数据范围 n ≤ 10^4 时会到 10^8 量级，偏慢。

**关键观察**：当我们固定一个数 `x = nums[i]` 时，要找的就是它的「互补数」`target - x`。问题从「找一对数」变成了「对每个元素，快速查另一个值在不在」——**这正是哈希表最擅长的 O(1) 查找**。

进一步优化成**一次遍历**：

- 边遍历边把已经见过的 `nums[i] → i` 存进哈希表；
- 对当前元素 `nums[i]`，先查 `target - nums[i]` 是不是已经在表里：
  - 在 → 直接返回 `[表里的下标, i]`；
  - 不在 → 把 `nums[i] → i` 存进表，继续往后。

为什么「先查再存」是对的、而且不会用重复元素？

> 因为查的时候，表里只放了 `i` 之前的元素，绝不会包含 `nums[i]` 自己。比如 `nums = [3,3], target = 6`：第一个 `3` 查 `3` 不在表里、存入；第二个 `3` 查 `3` 命中第一个，返回 `[0,1]`，正确。

## 代码

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        // unordered_map<int,int>：C++ STL 哈希表，查找/插入均摊 O(1)。
        //   - key 类型：int（数组里出现过的数值）
        //   - value 类型：int（这个数值对应的下标）
        //   - int 是标准库默认支持哈希的类型，无需自己写哈希函数/冲突处理：
        //     标准库用 std::hash<int> 算哈希、链地址法处理冲突、std::equal_to<int> 判等。
        //   - 与 map（红黑树，O(log n)）相比，unordered_map 平均更快但无序。
        unordered_map<int, int> hashtable;

        // 单层循环：i 既是当前元素下标，也保证表里只放过 i 之前的元素。
        for (int i = 0; i < (int)nums.size(); ++i) {
            // 先算出「互补数」：要让两数之和等于 target，另一个数应该是 target - nums[i]。
            auto it = hashtable.find(target - nums[i]);
            // find：哈希表查找，返回迭代器。
            //   - 找到 → 指向那个键值对，it->second 就是互补数的下标。
            //   - 找不到 → 等于 hashtable.end()（尾后迭代器，表示「不存在的位置」）。
            //   - 不能用 hashtable[key] 来「查找」！因为下标访问在 key 不存在时会
            //     自动插入一个默认值（int 默认 0），会污染哈希表、还会让多次调用出错。

            if (it != hashtable.end()) {
                // 找到了互补数：返回 [互补数下标, 当前下标]。
                // it->second：迭代器指向键值对的 value（即之前存进去的下标）。
                return {it->second, i};
                // {a, b}：C++11 列表初始化，这里用于初始化返回类型 vector<int>，
                //   等价于 vector<int>{it->second, i}，编译器会自动推导返回类型。
            }
            // 没找到：把当前数 nums[i] -> i 存进哈希表，留给后面的元素去匹配。
            //   - 写在 find 之后，保证不会拿 nums[i] 自己和自己配对。
            hashtable[nums[i]] = i;
            //   - 下标访问 hashtable[k]=v：若 key k 不存在会自动插入，并把 value 设为 v；
            //     若已存在则覆盖原来的 value。这里 i 是第一次遇到，直接插入。
        }
        return {};  // 题目保证有唯一解，这行实际不会执行，写上只是满足「所有路径都返回」。
    }
};
```

## 复杂度

- **时间**：O(n)
  - 只遍历一次数组，每次对哈希表做一次 `find` 和一次插入，都是均摊 O(1)。
  - 对比暴力枚举的 O(n²)，n = 10^4 时快约 10^4 倍。
- **空间**：O(n)
  - 最坏情况下哈希表里存了几乎所有元素（解出现在最后两个数时）。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么用 `find` 而不是直接 `hashtable[target - nums[i]]` 来判断在不在？

**因为下标访问 `mp[key]` 有「副作用」**：当 `key` 不存在时，它会**自动插入一个默认值**（`int` 默认为 `0`）再返回引用。

后果：

1. 污染哈希表：本来不存在的 key 被插进去了，值是 `0`（下标 0），这是错的；
2. `Solution` 对象如果被复用调用，上一次的脏数据会残留（不过力扣每次新建实例，这点在力扣上看不出来，但在本地测试或工程里会踩坑）。

`find` 才是纯粹的「查找」：找到返回迭代器，找不到返回 `end()`，**不改哈希表**。判断存在性永远用 `find`/`count`，只有「我想取值并且允许插入」时才用 `[]`。

### Q2：「先查再存」和「先存再查」有什么区别？

- **先查再存**（本解法）：查的时候表里只有 `i` 之前的元素，所以 `nums[i]` 绝不会匹配到自己。`nums = [3,3], target=6` 这种重复值也能正确返回 `[0,1]`。
- **先存再查**：如果先 `hashtable[nums[i]] = i` 再查 `target - nums[i]`，当 `target - nums[i] == nums[i]`（如 `target=6, nums[i]=3`）时，会直接命中刚存进去的自己，错误地返回 `[i, i]`。需要额外加判断 `it->second != i` 才能修正。

所以「先查再存」更简洁，是推荐写法。

### Q3：`unordered_map` 和 `map` 这里该用哪个？

都能 AC，但场景不同：

| 容器 | 底层 | 查找/插入 | 是否有序 |
|---|---|---|---|
| `unordered_map` | 哈希表 | **均摊 O(1)** | 无序 |
| `map` | 红黑树 | O(log n) | 按 key 升序 |

本题**只做精确查找**，不需要按 key 排序，用 `unordered_map` 平均最快，是标准选择。只有当你需要「按 key 顺序遍历」或「找大于某值的第一个 key」这类操作时，才用 `map`。

## 复盘

- **核心套路**：「对每个元素，要快速找另一个特定值」→ 想到**哈希表 O(1) 查找**，把「两层循环 O(n²)」降成「一层循环 + 哈希 O(n)」。这是两数之和、三数之和、四数之和这一系列题的共同起点。
- **易错点**：
  - 判断「在不在」用 `find`/`count`，不要用 `mp[key]`（会偷偷插入）。
  - 「先查再存」可以天然避免元素和自己配对，比「先存再查 + 判断下标」更干净。
- **可迁移**：`target - x` 这种「互补数」思路后续会反复出现（如 15 三数之和、18 四数之和、560 和为 K 的子数组）。只是多维度的题需要在哈希表之外再套双指针 / 前缀和。

### 解法二：暴力枚举（对比用，非主解）

官方题解给出的最朴素做法：两层循环枚举数对。思路直观但 O(n²)，n = 10^4 时约 5×10^7 次比较，能勉强 AC 但不推荐。

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        int n = nums.size();
        for (int i = 0; i < n; ++i) {
            for (int j = i + 1; j < n; ++j) {  // j 从 i+1 开始：每个元素只用一次，且避免重复枚举
                if (nums[i] + nums[j] == target) {
                    return {i, j};
                }
            }
        }
        return {};
    }
};
```

- **时间**：O(n²)
- **空间**：O(1)

> 这就是题目「进阶」里希望你超越的那个 O(n²) 算法。

## 拓展：多组答案，返回所有下标对 + 组数

原题写死了「只有一组解」，所以函数只返回 `vector<int>`，里面塞两个下标就结束。机试里更常见的改法是：**所有满足 `nums[j] + nums[i] == target` 的下标对都要报出来，并且还要报一共有几组。**

哈希还是那个哈希（扫一遍，查互补数），变的是三件事：

1. 哈希表的 **value 类型**：从「一个下标」变成「一串下标」；
2. 函数的 **返回类型**：从「两个数」变成「组数 + 所有对」；
3. 找到一对之后 **不能 `return`**，要记下来继续扫。

下面默认题意是：**按组合枚举所有下标对**。同一对里两个下标必须不同；不同对之间可以共用下标。例如 `[3,3,3], target=6` 要给出 `[0,1]、[0,2]、[1,2]` 三组，不是只配一次就扔掉。如果某次机试写成「每个数最多用一次」，那是另一道匹配题，算法就不是这个了。

### 思路

原题用 `unordered_map<int, int>`：一个数值只记**最后一次**出现的下标。因为保证只有一组解，丢掉旧下标没事。

现在要枚举全部组合，同一个数值可能已经出现过很多次，每一个旧下标都能和当前 `i` 配一对。所以表必须改成：

```text
unordered_map<int, vector<int>>
  key   = 数值
  value = 这个数值目前已经出现过的全部下标（一个动态数组）
```

扫描顺序仍然是「先查再存」，每扫到 `i`：

1. 算互补数 `need = target - nums[i]`；
2. 如果表里已经有 `need`，它的 `vector` 里每个旧下标 `j` 都满足 `j < i`，把 `[j, i]` 推进答案；
3. 再把当前下标 `i` 挂到 `nums[i]` 对应的那个 `vector` 后面。

「先查再存」还是为了同一下标不和自己配对。和原题的差别只是：命中之后要 **for 一遍整个 vector**，不能只取一个下标。

手算一遍 `[1, 5, 1, 5], target = 6`：

| i | nums[i] | 表里已有 | 命中的旧下标 | 新加入的对 |
|---|---|---|---|---|
| 0 | 1 | 空 | 无 | — ，然后 `1 → [0]` |
| 1 | 5 | `1 → [0]` | 0 | `[0,1]` ，然后 `5 → [1]` |
| 2 | 1 | `1 → [0]，5 → [1]` | 1 | `[1,2]` ，然后 `1 → [0,2]` |
| 3 | 5 | `1 → [0,2]，5 → [1]` | 0、2 | `[0,3]、[2,3]` ，然后 `5 → [1,3]` |

四组：`[0,1] [1,2] [0,3] [2,3]`。

### 返回类型怎么选（机试必看）

C++ 函数只能 `return` 一个对象。组数是 `int`，所有对是 `vector<vector<int>>`（外层数组 = 所有组，内层两个元素 = 一对下标），要一起带出去，常见三种写法：

| 写法 | 类型 | 什么时候用 |
|---|---|---|
| 只返回所有对 | `vector<vector<int>>` | 组数就是 `ans.size()`，**最干净，优先用这个** |
| `pair` 打包两个值 | `pair<int, vector<vector<int>>>` | 题目函数签名明确要求「返回组数和所有对」 |
| 引用传出 | `void f(..., vector<vector<int>>& ans)` | 机试自己写 `main` 时也很常见，组数用 `ans.size()` 打印 |

下面主代码用 `pair`，就是为了把「返回类型怎么变」写清楚。`first` 是组数，`second` 是所有下标对。真正上机时，如果输出格式是「先打组数再打每一对」，只返回二维数组、再用 `.size()` 打印，往往更省事。

机试和力扣还有两个差别，练习时不要混：

- 力扣给你 `class Solution` 和函数签名；机试要自己写 `#include`、`main`、读入、输出。
- 力扣下标从 **0** 开始；有的机试要求输出 **1-based**（打印时 `j+1`、`i+1`）。先看题目，不要默认。

### 代码

可以整段贴进 `练习/playground.cpp` 编译跑。力扣原题签名对不上，这是拓展题，不要拿去交 1 题。

```cpp
#include <iostream>
#include <vector>
#include <unordered_map>
#include <utility>   // pair<T1,T2> 的声明在这里；有的实现里 <iostream> 会间接带进来，机试里自己写上更稳
using namespace std;

// pair<int, vector<vector<int>>>：把两个不同类型捆成一个返回值。
//   first  : int，组合个数（组数）
//   second : vector<vector<int>>，二维数组；ans[k] 是第 k 组，形如 {j, i}，保证 j < i
// 访问：ans.first、ans.second；C++17 也可以 auto [cnt, pairs] = twoSumAll(...); 结构化绑定拆开。
pair<int, vector<vector<int>>> twoSumAll(const vector<int>& nums, int target) {
    // unordered_map<int, vector<int>>：key 是数值，value 是「这个数值已经出现过的全部下标」。
    //   原题是 unordered_map<int, int>，一个 key 只存一个下标，后出现的会覆盖前面的。
    //   现在不能覆盖：同一个值的每个旧下标都还要用，所以 value 改成 vector<int>。
    //   查找仍是均摊 O(1)；真正费时间的是命中后要把这个 vector 扫一遍。
    unordered_map<int, vector<int>> hashtable;

    // vector<vector<int>>：动态的「数组的数组」。
    //   外层会随着找到的组数增长；内层我们每次只 push 两个下标。
    //   不要写成 vector<int> pairs，那样没法区分「第 1 组的两个下标」和「第 2 组的两个下标」。
    vector<vector<int>> pairs;

    for (int i = 0; i < (int)nums.size(); ++i) {
        // find 仍然只查、不插入。返回迭代器：
        //   找到 → it->first 是 key（互补值），it->second 是 vector<int>（所有旧下标）
        //   找不到 → it == hashtable.end()
        auto it = hashtable.find(target - nums[i]);

        if (it != hashtable.end()) {
            // 范围 for：for (int j : it->second)
            //   依次取出 vector 里每个旧下标 j，类型按元素类型写。
            //   这里 j 是拷贝出来的 int，改 j 不会改表；我们只读，没问题。
            //   如果元素是大型对象、且要改原容器，才写成 for (auto& x : vec)。
            for (int j : it->second) {
                // push_back({j, i})：在外层数组末尾追加一个「长度为 2 的 vector」。
                //   {j, i} 是列表初始化，编译器据此构造 vector<int>{j, i}。
                //   不要写成 pairs.push_back(j) —— 类型对不上，j 是 int 不是 vector<int>。
                pairs.push_back({j, i});
            }
        }

        // 先查再存：当前 i 还没进表，不会和自己配。
        // hashtable[nums[i]]：
        //   key 不存在时，[] 会插入一个默认值——对 vector<int> 来说就是空数组 {}，再返回引用；
        //   key 已存在时，返回已经在表里的那个 vector 的引用。
        // 然后 .push_back(i)：vector 在尾部追加一个 int。
        //   均摊 O(1)。容量不够时会扩容（大约翻倍），旧元素搬到新空间；均摊下来仍是 O(1)。
        // 原题这里是 hashtable[nums[i]] = i; 赋值会覆盖。拓展题必须 push_back，不能赋值。
        hashtable[nums[i]].push_back(i);
    }

    // {(int)pairs.size(), pairs}：列表初始化一个 pair。
    //   pairs.size() 的类型是 size_t（无符号），转成 int 再塞进 first，避免和题目里的 int 组数打架。
    //   组数不必另设一个 cnt++：每 push 一组，size 自己就是组数。
    return {(int)pairs.size(), pairs};
}

int main() {
    // 机试里这两行通常改成 cin >> n >> target; 再 for 读 n 个数。
    // 练习阶段先写死示例，确认函数对了再换成读入。
    vector<int> nums{1, 5, 1, 5};
    int target = 6;

    pair<int, vector<vector<int>>> ans = twoSumAll(nums, target);
    // 上面也可以写成：auto ans = twoSumAll(nums, target);
    // auto 让编译器自己推类型，机试里能少写一长串，但自己要清楚推出来的是 pair。

    cout << ans.first << "\n";           // 先打组数
    for (const auto& p : ans.second) {   // const auto&：只读、不拷贝每一行
        cout << p[0] << " " << p[1] << "\n";
    }
    // 期望输出：
    // 4
    // 0 1
    // 1 2
    // 0 3
    // 2 3
    return 0;
}
```

只返回二维数组、组数用 `.size()` 的写法（更短，机试输出常用）：

```cpp
vector<vector<int>> twoSumAll(const vector<int>& nums, int target) {
    unordered_map<int, vector<int>> hashtable;
    vector<vector<int>> pairs;
    for (int i = 0; i < (int)nums.size(); ++i) {
        auto it = hashtable.find(target - nums[i]);
        if (it != hashtable.end()) {
            for (int j : it->second) {
                pairs.push_back({j, i});
            }
        }
        hashtable[nums[i]].push_back(i);
    }
    return pairs;   // 组数：调用方写 (int)pairs.size() 或 (int)ans.size()
}
```

### 复杂度

- **时间**：O(n + k)。n 是数组长度，k 是答案组数。每个下标进表一次；每找到一组就写一次答案。最坏 k 能到 O(n²)，比如全是 `3`、`target = 6`，这时时间和输出本身一样大，再快也快不到哪去。
- **空间**：O(n + k)。表里最多挂 n 个下标；答案数组再存 k 对。

原题保证 k = 1，所以看起来是 O(n)。拓展之后不要再口头说「还是 O(n)」——组数上去了，时间和空间都跟着走。

### 和原题对比时最容易写错的地方

1. **表还写成 `unordered_map<int, int>`，或继续 `hashtable[x] = i`。** 后出现的同值会把旧下标盖掉，漏组合。必须是 `vector<int>` + `push_back`。
2. **命中后只取 `it->second[0]` 或 `it->second.back()`。** 互补值有多个下标时会漏。必须把 `it->second` 整个扫完。
3. **找到第一对就 `return`。** 原题可以停，拓展题必须记下来继续走。
4. **用 `hashtable[need]` 判断在不在。** 和原题同一个坑：`[]` 在 key 不存在时会插入空 `vector`，表被污染。判断仍然只用 `find` / `count`。
5. **返回类型写成 `vector<int>`。** 多个 `{j,i}` 拼成一维数组后，调用方分不清哪两个是一组。组与组之间必须隔开，所以是 `vector<vector<int>>`。
6. **`pair` 和 `.size()` 重复计数。** `first` 就是 `second.size()`，不要一边 `push_back` 一边再手写一个可能忘加的 `cnt`。
7. **先看清「所有组合」还是「每个数只用一次」。** 前者是本题拓展；后者要换算法（例如排序后双指针配完就删掉），不能只改返回类型。
8. **先看清下标从 0 还是从 1 开始、输出要不要排序。** 算法对了，格式错一样 0 分。需要按第一下标排序时，对 `pairs` 做 `sort(pairs.begin(), pairs.end())`：`vector<int>` 默认按字典序比，`{0,3}` 会排在 `{1,2}` 前面。

再补两组自测，建议在 `main` 里轮流换数据：

```text
nums = [2,7,11,15], target = 9
→ 1 组：[0,1]

nums = [3,3,3], target = 6
→ 3 组：[0,1] [0,2] [1,2]

nums = [1,2,3,4,5], target = 6
→ 2 组：[0,4] [1,3]
```
