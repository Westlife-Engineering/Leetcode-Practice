# 49 字母异位词分组

- 难度：中等
- 标签：数组、哈希表、字符串、排序
- 力扣链接：https://leetcode.cn/problems/group-anagrams/?envType=study-plan-v2&envId=top-100-liked

## 题目描述

给你一个字符串数组，请你将 **字母异位词** 组合在一起。可以按任意顺序返回结果列表。

字母异位词 是由重新排列源单词的所有字母得到的一个新单词。

**示例 1：**

```
输入: strs = ["eat", "tea", "tan", "ate", "nat", "bat"]
输出: [["bat"],["nat","tan"],["ate","eat","tea"]]
```

**示例 2：**

```
输入: strs = [""]
输出: [[""]]
```

**示例 3：**

```
输入: strs = ["a"]
输出: [["a"]]
```

**数据范围：**

- `1 <= strs.length <= 10^4`
- `0 <= strs[i].length <= 100`
- `strs[i]` 仅包含小写字母

## 思路

> 本题主要参考力扣官方题解的「排序 + 哈希表」做法。

核心观察：**互为字母异位词的两个字符串，把字符排序后一定相同。**

- `"eat"` → 排序 → `"aet"`
- `"tea"` → 排序 → `"aet"`
- `"ate"` → 排序 → `"aet"`

所以可以这样做：

1. 遍历每个字符串，把它排序后的结果当作 **key**。
2. 用一个哈希表 `unordered_map<string, vector<string>>`，把原始字符串塞进对应 key 的 vector 里。
3. 最后把哈希表里所有的 value 收集起来，就是答案。

为什么想到哈希？因为本质上是**「按某个特征把元素归类」**——这是哈希表最典型的应用场景。

## 代码

```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        // unordered_map：C++ STL 哈希表，查找/插入均摊 O(1)。
        //   - key 类型：string（排序后的字符串，作为分组依据）
        //   - value 类型：vector<string>（这一组里所有的原始字符串）
        //   - 不需要自己写哈希函数/冲突处理：string 是标准库默认支持哈希的类型，
        //     标准库会自动用 std::hash<string> 算哈希值、用链地址法处理冲突、
        //     用 std::equal_to<string> 判断两个 key 是否相等。
        unordered_map<string, vector<string>> mp;

        // range-based for：C++11 语法，遍历容器元素。
        //   - 写 string&（引用）是为了避免拷贝，直接引用 strs 里的每个元素。
        //   - 如果写 string str 会每次拷贝一份，浪费。
        for (string& str : strs) {
            string key = str;                 // 拷贝一份用来排序，不动原字符串
            sort(key.begin(), key.end());     // STL 排序算法，就地排序（in-place），
                                              //   会修改 key 自身，时间 O(k log k)，
                                              //   k 是字符串长度。这就是为什么要先拷贝。
            // mp[key]：哈希表的下标访问。
            //   - 如果 key 不存在，会自动插入一个默认值（这里是空 vector）。
            //   - 返回的是 value 的引用，可以直接调用方法。
            // emplace_back(str)：在 vector 末尾就地构造一个元素（这里就是拷贝 str 进去）。
            //   - 比 push_back 少一次拷贝/移动；对 string 这种简单类型差别不大，
            //     但对复杂对象更高效，是现代 C++ 推荐写法。
            mp[key].emplace_back(str);
        }

        // 准备返回值：外层每个元素是一个 vector<string>（即一个分组）。
        vector<vector<string>> ans;

        // 用迭代器遍历哈希表。
        //   - mp.begin() 指向第一个键值对的迭代器，mp.end() 是尾后迭代器。
        //   - auto 让编译器自动推导类型，这里推导为
        //     unordered_map<string, vector<string>>::iterator。
        //   - it->first 是 key（排序后的字符串），it->second 是 value（那组原始字符串）。
        for (auto it = mp.begin(); it != mp.end(); ++it) {
            // emplace_back(it->second)：把 it->second（一个完整的 vector<string>）
            //   作为一个整体元素加入 ans。因为是左值，这里会拷贝整个 vector。
            //   - 这就是"一次写入一整个分组"的关键。
            //   - 如果想避免拷贝，可以写 std::move(it->second)，但本题 mp 之后不再使用，
            //     拷贝也能 AC，写不写 move 都行。
            ans.emplace_back(it->second);
        }
        return ans;
    }
};
```

## 复杂度

- **时间**：O(n · k log k)
  - n 是字符串个数，k 是最长字符串长度。
  - 每个字符串排序 O(k log k)，哈希表插入均摊 O(k)（算 key 哈希 + 比较），合计 O(n · k log k)。
- **空间**：O(n · k)
  - 哈希表要存所有字符串。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。

### Q1：这个哈希不需要自己定义映射函数、冲突处理吗？

**不需要**，因为 key 用的是 `std::string`，标准库已经全覆盖：

| 组件 | 作用 | 谁提供 |
|---|---|---|
| 哈希函数 | 把 `string` 映射成 `size_t` | `std::hash<string>`（标准库） |
| 冲突处理 | 不同 key 落到同一个桶时怎么办 | `unordered_map` 内部用**链地址法**自动处理 |
| 键相等判断 | 在桶内找到真正匹配的 key | `std::equal_to<string>`（标准库） |

> 只有当 key 是**自定义类型**（比如 `array<int, 26>`）时，才需要自己手写 `std::hash` 特化和 `operator==`。本题用排序后的 `string` 作 key，刚好绕开了这个麻烦。

### Q2：`emplace_back` 是什么？

C++11 引入的 STL 容器方法，在容器末尾**就地构造**一个新元素。

和 `push_back` 的区别：

- `push_back(x)`：先有对象 x，再把它拷贝/移动进容器（构造 → 拷贝/移动 → 析构临时对象）。
- `emplace_back(参数...)`：直接把参数传给元素类型的构造函数，**在容器的内存里就地构造**（只构造一次）。

对 `string` 这种简单类型差别不大；对复杂对象（多成员变量的结构体）`emplace_back` 明显更高效。现代 C++ 默认推荐 `emplace_back`。

### Q3：`ans.emplace_back(it->second)` 是做什么的？一次写入整个分组吗？

**是的**。`it->second` 的类型是 `vector<string>`，也就是**一整个分组**。这行把它作为一个整体元素塞进 `ans`。

举例，遍历到 `"aet"` 分组时：

```
it->second = ["eat", "tea", "ate"]
ans.emplace_back(it->second)
→ ans 变成 [ ["eat", "tea", "ate"] ]
```

一次操作，整个分组全部进入答案。

### Q4：为什么迭代多次，结果是二维分组而不是一维平铺？

因为 **`ans` 的类型决定了结构**。

`vector<vector<string>>` 的含义：

- 外层 vector 的每个元素**本身就是一个 `vector<string>`**。
- 每次 `emplace_back(it->second)` 添加的是整个内层 vector，作为一个独立元素。

如果 `ans` 写成一维的 `vector<string>`，那就需要用 `insert` 逐个塞字符串进去，结果就是 `["eat", "tea", "ate", "tan", "nat", "bat"]`——**丢失了分组信息**。

> 一句话：**数据结构决定结果形态**。`vector<vector<string>>` 天然就是分组的二维结构。

## 复盘

- **核心套路**：「按某个特征把元素归类」→ 想到哈希表，特征当 key，归到同一个容器里。
- **小技巧**：用排序后的 `string` 当 key，可以避开手写哈希函数的麻烦（如果用 `array<int, 26>` 计数当 key，就得自己定义 hash）。
- **STL 要点**：
  - `unordered_map` 对内置类型/`string` 开箱即用；自定义类型当 key 才需要额外配置。
  - `sort` 是**就地排序**，会改原对象——要先拷贝。
  - `emplace_back` 比 `push_back` 更现代、更高效。
  - 容器的「维度」由类型决定，写代码前先想清楚答案的结构。
- **可选优化**：`ans.emplace_back(std::move(it->second));` 可以省掉最后一次拷贝，但本题不影响 AC。

### 思路

分组那几行原封不动：拷贝 → `sort` → `mp[key].emplace_back(str)` → 把每个 `vector<string>` 收进答案。

机试多出来的只是两头：

1. `main` 里先把 `n` 个字符串读进 `vector<string>`；
2. 调用函数拿到 `vector<vector<string>>`，按题目格式打出来。

手算一遍输入 `eat tea tan ate nat bat`：

| 原串 | 排序后的 key | 此时表里 |
|---|---|---|
| eat | aet | `aet → [eat]` |
| tea | aet | `aet → [eat, tea]` |
| tan | ant | `aet → [eat, tea]，ant → [tan]` |
| ate | aet | `aet → [eat, tea, ate]，ant → [tan]` |
| nat | ant | `aet → [eat, tea, ate]，ant → [tan, nat]` |
| bat | abt | 再加上 `abt → [bat]` |

三组：`[eat, tea, ate]`、`[tan, nat]`、`[bat]`。`unordered_map` 遍历无序，打印出来三组谁先谁后都算对。

### 返回类型怎么选（机试必看）

原题已经是 `vector<vector<string>>`：外层一个元素 = 一组，内层一个元素 = 一个字符串。组数就是 `ans.size()`，不必再包一层 `pair`。

| 写法 | 类型 | 什么时候用 |
|---|---|---|
| 只返回所有组 | `vector<vector<string>>` | 组数用 `.size()` 打印，**优先用这个** |
| `pair` 打包 | `pair<int, vector<vector<string>>>` | 函数签名硬性要求「返回组数和所有组」 |
| 引用传出 | `void f(..., vector<vector<string>>& ans)` | 自己写 `main` 时也可以，组数仍用 `ans.size()` |

下面主代码只返回二维数组。`main` 负责读、调、打。

### 代码

可以整段贴进 `练习/playground.cpp` 编译跑。力扣原题签名对不上，这是机试写法，不要拿去交 49 题。

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <unordered_map>
#include <algorithm>   // sort 声明在这里；只写 <iostream> 不够，MSVC 上会报找不到 sort
using namespace std;

// vector<vector<string>>：外层 = 所有分组，内层 = 这一组里的原始字符串。
// 组数不要另设 cnt：调用方写 (int)ans.size() 就是组数。
vector<vector<string>> groupAnagrams(vector<string>& strs) {
    // unordered_map<string, vector<string>>：
    //   key   = 排序后的字符串（分组依据）
    //   value = 这一组里所有原始字符串
    // 查找/插入均摊 O(1)；string 是标准库默认支持哈希的类型，不用自己写哈希函数。
    unordered_map<string, vector<string>> mp;

    for (string& str : strs) {            // 引用遍历，避免每次拷贝整个 string
        string key = str;                 // 必须拷贝：sort 会改对象本身
        sort(key.begin(), key.end());     // 就地排序，O(k log k)，k 是字符串长度
        mp[key].emplace_back(str);        // key 不存在时 [] 会插入空 vector，再在末尾就地放入 str
    }

    vector<vector<string>> ans;
    for (auto it = mp.begin(); it != mp.end(); ++it) {
        // it->second 类型是 vector<string>，一次塞进一整组，不要逐个字符串 push
        ans.emplace_back(it->second);
    }
    return ans;
}

int main() {
    // ---------- 练习：先写死示例，确认函数对了再换成 cin ----------
    vector<string> strs{"eat", "tea", "tan", "ate", "nat", "bat"};

    vector<vector<string>> ans = groupAnagrams(strs);
    // 上面也可以写成：auto ans = groupAnagrams(strs);
    // auto 让编译器自己推类型，推出来的是 vector<vector<string>>。

    cout << ans.size() << "\n";           // 先打组数；size() 是 size_t，cout 可以直接打
    for (const auto& group : ans) {       // const auto&：只读、不拷贝每一组
        cout << group.size();             // 该组有几个单词
        for (const auto& s : group) {
            cout << " " << s;             // 先空格再单词，避免行首多一个空格
        }
        cout << "\n";
    }
    // 期望：组数是 3；三组分别是 {eat,tea,ate}、{tan,nat}、{bat}（组序任意）
    return 0;
}
```

### 和原题对比时最容易写错的地方

1. **忘了头文件。** 力扣环境预置了；本地 / 机试必须自己写。`sort` 在 `<algorithm>`，`string` 在 `<string>`，MSVC 没有 `<bits/stdc++.h>`。
2. **还带着 `class Solution`。** 机试入口是 `main`。函数可以是自由函数，也可以在 `main` 里直接写逻辑，但必须有 `main`。
3. **`cin >> strs[i]` 去读空串。** `>>` 跳过空白，读不到 `""`。力扣示例 2 是 `[""]`，机试若允许空串必须换 `getline`。
4. **`cin >> strs`。** `vector` 没有这个重载。先 `vector<string> strs(n);` 再按下标读。
5. **输出打成一维。** 只 `cout << s` 不打组的边界，评测分不清谁和谁一组。必须按「一组一行」或「先打 k 再打 k 个词」。
6. **对 `unordered_map` 的遍历顺序做断言。** 组序不稳定。自测时看「每一组里的词对不对」，不要死对某一行必须先打 `bat`。
7. **`sort` 没拷贝就排原串。** 和原题同一个坑：排完原串被改掉，答案里就不是题目给的单词了。
8. **`>>` 和 `getline` 混用却不吃换行。** 第一行读完 `n` 后，缓冲区里还留着 `'\n'`，下一个 `getline` 会读到空行，后面所有串错位。
