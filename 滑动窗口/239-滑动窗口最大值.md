# 239 滑动窗口最大值

- 难度：困难

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/sliding-window-maximum/solution/hua-dong-chuang-kou-zui-da-zhi-by-leetco-ki6m/)（slug：`hua-dong-chuang-kou-zui-da-zhi-by-leetco-ki6m`，官方篇）。正文主解是 **单调队列（双端队列 deque）**，时间 O(n)，与「滑动窗口」目录主题最对应；优先队列（堆）解法、分块+预处理解法放在「复盘」。

## 题目描述

给你一个整数数组 `nums`，有一个大小为 `k` 的滑动窗口从数组的最左侧移动到数组的最右侧。你只可以看到在滑动窗口内的 `k` 个数字。滑动窗口每次只向右移动一位。

返回 滑动窗口中的最大值。

**示例 1：**

```
输入：nums = [1,3,-1,-3,5,3,6,7], k = 3
输出：[3,3,5,5,6,7]
解释：
滑动窗口的位置                最大值
---------------               -----
[1  3  -1] -3  5  3  6  7       3
 1 [3  -1  -3] 5  3  6  7       3
 1  3 [-1  -3  5] 3  6  7       5
 1  3  -1 [-3  5  3] 6  7       5
 1  3  -1  -3 [5  3  6] 7       6
 1  3  -1  -3  5 [3  6  7]      7
```

**示例 2：**

```
输入：nums = [1], k = 1
输出：[1]
```

**提示：**

- `1 <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`
- `1 <= k <= nums.length`

## 思路

> 本题参考力扣官方题解的「方法二：单调队列」。

### 暴力想法（O(nk)，会超时）

最直白的做法：每个窗口都从头扫一遍找最大值。一共有 `n - k + 1` 个窗口，每个窗口扫 `k` 个元素，总复杂度 O((n-k+1)·k) = O(nk)。n = 10^5、k 取中间值时约 10^9 量级，会超出时间限制。

### 关键观察：相邻窗口只差 1 个元素

相邻两个滑动窗口共用 `k - 1` 个元素，只有左右两端各 1 个元素发生变化（右边进一个、左边出一个）。暴力的问题是**没有复用上一个窗口的任何信息**——左边的旧元素被划出窗口时，如果它正好不是最大值，其实根本不影响答案；而右边新进来的元素，可能直接「杀死」一批比它小的候选。

### 核心观察（单调队列的精髓）

> 如果窗口里有两个下标 `i` 和 `j`，`i < j`（`i` 在 `j` 左侧），且 `nums[i] <= nums[j]`，那么 **只要 `i` 还在窗口里，`j` 就一定也在窗口里**（因为 `j` 比 `i` 晚出去）。既然 `nums[j]` 不比 `nums[i]` 小，`nums[i]` 就**永远不可能成为窗口最大值**，可以把它彻底扔掉。

按这个规则维护后，留下的候选下标在数组中对应的值是**严格单调递减**的——这就是「单调队列」名字的由来。队首（最左、最老）总是当前窗口的最大值候选。

### 为什么要双端队列（deque）

维护这个候选队列需要在**两端**操作：

- **从队尾弹出**：新元素 `nums[i]` 进来时，把队尾所有 `<= nums[i]` 的下标一个个踢掉（它们再没机会当最大值），再把 `i` 从队尾入队。
- **从队首弹出**：窗口每右移一位，如果队首下标已经落在窗口左边界外（`<= i - k`），它就过期了，从队首踢掉。

「同时操作队首和队尾」决定了必须用双端队列 `deque`，普通队列/栈都做不到。

### 算法（单调队列，存下标而不是存值）

**为什么存下标？** 因为我们需要判断「队首是否过期」（要和窗口边界 `i - k` 比大小），只有存下标才能做这个判断；只存值的话没法知道它什么时候划出窗口。

1. 先处理前 `k` 个元素建初始窗口：对 `i = 0..k-1`，把队尾所有 `nums[back] <= nums[i]` 的弹出，再把 `i` 入队尾。
2. 此时队首就是第一个窗口的最大值，记下 `nums[q.front()]`。
3. 对 `i = k..n-1`，每步：
   - 维护队尾：弹出所有 `nums[back] <= nums[i]` 的下标，再 `push_back(i)`。
   - 维护队首：若 `q.front() <= i - k`（已划出窗口左侧），`pop_front()`。
   - 记录答案：`nums[q.front()]` 就是当前窗口最大值。

示意（`nums = [1,3,-1,-3,5,3,6,7], k = 3`，队列里存的是下标）：

```
i=0: q=[0(1)]                      窗口未满
i=1: 3>=1 踢掉0, q=[1(3)]
i=2: -1<3, q=[1(3),2(-1)]          窗口满 → ans=[3]
i=3: -3<-1, q=[1(3),2(-1),3(-3)]   队首1在窗口内 → ans=[3,3]
i=4: 5 踢掉3,2,1, q=[4(5)]         → ans=[3,3,5]
i=5: 3<5, q=[4(5),5(3)]            → ans=[3,3,5,5]
i=6: 6 踢掉5,4, q=[6(6)]           → ans=[3,3,5,5,6]
i=7: 7 踢掉6, q=[7(7)]             → ans=[3,3,5,5,6,7]
```

**为什么对？** 每个下标至多入队一次、出队一次，所以整体是线性的；队首始终是当前窗口内的最大值（被它「压死」的小值都已从队尾清掉了）。

## 代码

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        int n = nums.size();

        // deque<int> q：双端队列，元素是「数组下标」（不是值！），均摊 O(1) 操作两端。
        //   - 头文件 <deque>，力扣 C++ 模板默认已包含。
        //   - 存下标而非存值：因为要判断队首是否滑出窗口（和 i-k 比下标大小），只有存下标能做到。
        //   - 不变式：q 里的下标对应的 nums 值是「严格单调递减」的（队首最大，队尾最小）。
        //   - 与 queue（只能队尾进、队首出）相比，deque 还能从队尾弹出，这是本题必需的。
        //   - 底层是一段段连续内存（分段数组），随机访问 q[i] 也是 O(1)，比 list 快很多。
        deque<int> q;

        // 先把前 k 个元素压入，建立第一个窗口的单调队列。
        for (int i = 0; i < k; ++i) {
            // 队尾清理：把所有「值 <= 当前元素」的队尾下标弹出。
            //   - q.back()：返回队尾元素的引用（这里是个下标），O(1)。
            //   - 必须先判 !q.empty()，空队列调 back()/front() 是未定义行为（会崩）。
            //   - 注意是 >= 的逻辑：nums[i] >= nums[q.back()] 时弹出，
            //     所以若有相等的值，靠右的（新的）会留下来——它待得更久，更划算。
            while (!q.empty() && nums[i] >= nums[q.back()]) {
                // q.pop_back()：删除队尾元素，O(1)。这是 deque 相对 queue 的关键能力。
                q.pop_back();
            }
            // q.push_back(i)：把当前下标从队尾入队，O(1)。
            q.push_back(i);
        }

        // 第一个窗口的最大值就是队首下标对应的值。
        //   - 用列表初始化 {..} 直接构造返回的 vector<int>，只放一个元素。
        //   - q.front()：返回队首（最老、值最大）下标的引用，O(1)。
        vector<int> ans = {nums[q.front()]};

        // 从第 k 个元素开始，每次窗口右移一位。
        for (int i = k; i < n; ++i) {
            // 1) 新元素 nums[i] 进窗口：同样从队尾弹出所有 <= 它的候选。
            while (!q.empty() && nums[i] >= nums[q.back()]) {
                q.pop_back();
            }
            q.push_back(i);

            // 2) 队首清理：如果队首下标已落在窗口左边界外（<= i-k），它就过期了。
            //   - 窗口是 [i-k+1, i]，所以「还在窗口内」要求下标 >= i-k+1，即 > i-k；
            //     反过来 下标 <= i-k 就是「已划出」，必须弹出。
            //   - 注意这里用 while 还是 if 都行：因为队首是下标最小的，一次最多过期一个，
            //     用 if 即可；为了和官方代码一致这里写成 while，语义更稳妥。
            while (q.front() <= i - k) {
                // q.pop_front()：删除队首元素，O(1)。这是 deque 相对普通 queue 的另一面。
                q.pop_front();
            }

            // 3) 当前队首就是窗口最大值。
            ans.push_back(nums[q.front()]);
        }
        return ans;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 每个下标至多入队一次、出队一次（无论从队首还是队尾），均摊到每次循环就是 O(1)，总共 O(n)。这是单调队列相对优先队列（O(n log n)）的优势所在。
- **空间**：O(k)
  - 队列里同时存在的下标不超过 `k + 1` 个（因为队首过期会被及时弹出）。官方分析：双向结构 + 「不断从队首弹出」保证了队列长度上界是 O(k)。
  - 返回的答案数组 O(n - k + 1)，按惯例不计入额外空间。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么队列里存「下标」而不是直接存「值」？

因为需要判断**队首什么时候过期**。窗口是 `[i - k + 1, i]`，要判断队首是否还在窗口里，得拿它的下标和 `i - k` 比大小——只存值的话，根本不知道这个值是哪个位置进来的，也就不知道它什么时候该划出窗口。

附带好处：通过下标 `q.front()` 仍然能拿到值 `nums[q.front()]`，两者都不丢。

### Q2：`pop_back` 为什么是「>=」而不是「>」？相等的值怎么处理？

弹出条件写成 `nums[i] >= nums[q.back()]`，意思是「新来的元素只要不比队尾小，就把队尾踢掉」。对于相等的值（如 `nums = [5, 5]`），后进来的那个 `5` 会把前一个踢掉、自己留在队里。这样更划算：两个 `5` 中右边那个在窗口里待得更久，留它一个就够了；左边那个反正不可能当最大值（被右边那个压住），早点清掉无妨。

如果改成严格 `>`，相等的值会都留下，队列里可能堆积一串相同值——结果也正确，但队列会偏长，没有好处。

### Q3：队首过期判断用 `if` 还是 `while`？

理论上用 `if` 就够了：下标是按升序入队的，队首一定是最小的下标；窗口每次只右移一位，最多让一个下标过期。但写成 `while` 也对（循环体最多执行一次），而且更「防呆」——万一以后改成跳着移动窗口也能正常工作。官方题解用的就是 `while`。

### Q4：`deque` 和 `queue`、`vector` 有什么区别？什么时候用 `deque`？

| 容器 | 两端操作 | 头文件 | 典型用途 |
|---|---|---|---|
| `queue` | 只能队尾进、队首出（FIFO） | `<queue>` | BFS、普通先进先出 |
| `deque` | **两端都能进能出**，还能下标随机访问 | `<deque>` | 单调队列、两端都要操作的场景 |
| `vector` | 尾部 O(1) 增删；**头部增删 O(n)** | `<vector>` | 动态数组，只在尾部增删 |

本题必须从**队尾**弹出小值、又必须从**队首**弹出过期值——两端都要删，所以只能用 `deque`。`queue` 没有 `pop_back`，`vector` 的头部删除太慢，都不行。

`deque` 底层是「分段连续数组」（map 指向多段 buffer），所以两端 O(1)、中间 O(n)、随机访问 O(1) 但常数略大于 `vector`。

### Q5：`deque` 常用方法速查

| 方法 | 含义 | 复杂度 | 踩坑 |
|---|---|---|---|
| `q.push_back(x)` | 队尾入队 | O(1) | — |
| `q.push_front(x)` | 队首入队 | O(1) | vector 没有这个方法 |
| `q.pop_back()` | 删除队尾 | O(1) | 空队列调用是未定义行为 |
| `q.pop_front()` | 删除队首 | O(1) | vector 没有这个方法 |
| `q.front()` | 返回队首引用 | O(1) | 空队列调用是未定义行为 |
| `q.back()` | 返回队尾引用 | O(1) | 空队列调用是未定义行为 |
| `q.empty()` | 是否为空 | O(1) | 用 front/back 前必判 |
| `q.size()` | 元素个数 | O(1) | — |

## 复盘

- **核心套路（单调队列）**：遇到「滑动窗口的最值」一类问题，第一反应应是单调队列。关键是那句**「左边的较小值永远没机会当最大值，可以彻底扔掉」**——这种「丢弃无用候选」的思想是单调队列/单调栈共有的精髓。
- **单调队列 vs 单调栈**：
  - 单调栈：只在一端（栈顶）操作，典型场景是「找下一个更大/更小元素」（如 739 每日温度、84 柱状图最大矩形）。
  - 单调队列：两端都操作（队尾维护单调性 + 队首清理过期），典型场景就是**带窗口的最值**（本题）。多出来的「队首过期」对应窗口的滑动。
- **存下标而非存值**：凡是涉及「元素何时过期/位置关系」的题，存下标几乎总是更方便——下标既能还原值，又能判断边界。
- **可迁移**：单调队列是「窗口最值」的标配，后续遇到「带窗口限制的最大/最小」问题（如 862 和至少为 K 的最短子数组）都可以套这个模板。

### 解法二：优先队列 / 大根堆（官方方法一，O(n log n)）

思路：用大根堆实时维护窗口内元素的最大值。堆里存 `(值, 下标)` 二元组，堆顶就是最大值；当堆顶下标已划出窗口（`<= i - k`）时，就反复 `pop` 直到堆顶重新落在窗口内。由于堆**不能任意删除中间元素**，过期的旧元素只能等它浮到堆顶时才被「懒删除」。

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        int n = nums.size();
        // priority_queue<pair<int,int>>：默认是大根堆（最大元素在堆顶）。
        //   - 头文件 <queue>，和 queue 共用一个头文件。
        //   - 默认排序：pair 先比 first 再比 second，都默认大者在前 → 大根堆。
        //   - 存二元组 (值, 下标)：first=元素值用于排序找最大；second=下标用于判断是否过期。
        //   - 没法 O(1) 删除堆中任意元素，所以旧元素只能「懒删除」（等它浮到堆顶再 pop）。
        priority_queue<pair<int, int>> q;

        // 建立第一个窗口的堆。
        for (int i = 0; i < k; ++i) {
            // q.emplace(a, b)：在原地构造一个 pair{a, b} 放进堆，比 push 少一次移动。
            //   - 等价于 q.push(make_pair(nums[i], i))，但少一次临时对象的构造/移动。
            q.emplace(nums[i], i);
        }

        // 堆顶就是第一个窗口的最大值。q.top() 返回堆顶的 const 引用，O(1)；
        //   - .first 是元素值，.second 是下标。
        vector<int> ans = {q.top().first};

        for (int i = k; i < n; ++i) {
            q.emplace(nums[i], i);
            // 懒删除：堆顶若已划出窗口（下标 <= i-k），就一直 pop。
            //   - q.top().second <= i - k 判断过期；
            //   - q.pop()：删除堆顶，O(log n)（需要重新下沉调整堆）。
            while (q.top().second <= i - k) {
                q.pop();
            }
            ans.push_back(q.top().first);
        }
        return ans;
    }
};
```

- **时间**：O(n log n)。最坏情况数组单调递增，过期元素都堆在堆里不被弹出，堆最大可达 n 个元素，每次 push/pop 是 O(log n)。
- **空间**：O(n)（堆最大可能存 n 个元素，懒删除带来的冗余）。
- **对比单调队列**：单调队列利用「左边小值无用」把冗余候选即时清掉，做到了 O(n)；堆做不到这一点，只能等过期元素浮到堆顶才清。这是单调队列在本题胜出的根本原因。

### 解法三：分块 + 预处理（官方方法三，O(n)，了解即可）

把数组按 `k` 个一组分块，预处理出每组的前缀最大值 `prefixMax` 和后缀最大值 `suffixMax`。任意窗口 `[i, i+k-1]` 若跨越两个相邻分块，则其最大值 = `max(suffixMax[i], prefixMax[i+k-1])`（左段在该组的后缀最大、右段在下组的前缀最大）。这是稀疏表（Sparse Table）思想的简化版，能 O(n) 预处理 + O(1) 查询，但思路较绕，作为扩展了解。详细见官方题解。
