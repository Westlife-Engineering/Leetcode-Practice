# 76 最小覆盖子串

- 难度：困难
- 标签：哈希表、字符串、**滑动窗口**
- 力扣链接：https://leetcode.cn/problems/minimum-window-substring/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/minimum-window-substring/solutions/2876637/zui-xiao-fu-gai-zi-chuan-by-leetcode-solution/)的滑动窗口做法。正文主解是 **滑动窗口（双指针 + 哈希表计数）**——即官方「方法一」；官方文中提到的「过滤后滑动窗口」优化见文末「复盘」。

## 题目描述

给你一个字符串 `s` 、一个字符串 `t`。返回 `s` 中涵盖 `t` 所有字符的子串。如果不存在这样的子串，则返回空字符串 `""`。

**示例 1：**

```
输入：s = "ADOBECODEBANC", t = "ABC"
输出："BANC"
解释：最小覆盖子串 "BANC" 包含来自字符串 t 的 'A'、'B' 和 'C'。
```

**示例 2：**

```
输入：s = "a", t = "a"
输出："a"
解释：整个字符串 s 就是最小覆盖子串。
```

**示例 3：**

```
输入：s = "a", t = "aa"
输出：""
解释：t 中两个字符 'a' 均应包含在 s 的子串中，
因此没有符合条件的子字符串，返回空字符串。
```

**提示：**

- `m == s.length`
- `n == t.length`
- `1 <= m, n <= 10^5`
- `s` 和 `t` 由英文字母组成

**进阶：** 你能设计一个在 `O(m + n)` 时间内解决此问题的算法吗？

## 思路

> 本题参考力扣官方「方法一：滑动窗口」。

### 暴力想法（O(n³ · 字符集)，必超时）

枚举 `s` 的所有子串 `[l, r]`，对每个子串统计字符频次，再和 `t` 的频次逐字符比较。子串有 O(m²) 个，每次比较 O(字符集)，m ≤ 10⁵ 完全不可行。

### 关键观察：滑动窗口

和 [3 无重复字符的最长子串](./3-无重复字符的最长子串.md)、[438 找到字符串中所有字母异位词](./438-找到字符串中所有字母异位词.md) 是同一族问题：**在 `s` 上维护一个区间窗口，用两个同向移动的指针控制窗口大小**。

不同点：
- 第 3 题要找「最长」无重复子串 → 窗口「尽量扩」；
- 第 438 题窗口「定长」；
- **本题要找「最短」覆盖子串 → 窗口「先扩后缩」**：右指针扩张到刚覆盖 `t`，左指针再尽量收缩到不能再缩。这一扩一缩就锁定了一个「以当前 `l` 为起点」的最短覆盖。

### 如何判断「窗口覆盖 t」

`t` 中字符可能重复（如 `t = "aa"`），所以不能只看「字符种类齐全」，要看**每个字符的频次都不低于 `t` 中的需求**。官方做法：

- 用哈希表 `ori` 记录 `t` 中每个字符的需求量（`ori[c]` = `c` 在 `t` 中出现几次）。
- 用哈希表 `cnt` 动态维护当前窗口 `[l, r]` 里每个字符的出现次数（只统计 `t` 中出现的字符）。
- 判断「覆盖」：对 `ori` 里每个字符 `c`，都有 `cnt[c] >= ori[c]`。官方封装成一个 `check()` 函数。

### 算法

1. 预处理：遍历 `t`，填好 `ori`。
2. 双指针 `l = 0`、`r = -1`（`r = -1` 表示窗口还空着，下标在左边界左侧）。
3. 主循环 `while (r < s.size())`：
   - **扩张**：`++r` 把 `s[r]` 纳入窗口；若它是 `t` 中字符，`++cnt[s[r]]`。
   - **收缩**：只要 `check()` 为真（当前窗口已覆盖 `t`）且 `l <= r`：
     - 用 `r - l + 1` 更新最短答案（记下起点 `ansL` 和长度 `len`）；
     - 把 `s[l]` 移出窗口（若是 `t` 中字符则 `--cnt[s[l]]`），`++l` 继续尝试更短的覆盖。
4. 返回 `s.substr(ansL, len)`；若无解（`ansL == -1`）返回 `""`。

**为什么对？** 两个指针都只向右走、不回退。`r` 每走一步最多触发一次「收缩内层 while」，而 `l` 在整个算法里总共最多前进 `m` 步。所以总操作量是线性的。

示意（`s = "ADOBECODEBANC"`, `t = "ABC"`）：

```
r 一路扩到 "ADOBEC" → 覆盖 {A,B,C}，记下长度 6
  l 收缩 → 丢 A 后不再覆盖，停；最短 [0,5]="ADOBEC"
r 继续扩到 "ADOBECODEBA" → 覆盖
  l 收缩到 "ODEBA" → 不覆盖；最短仍是 6
r 扩到 "ADOBECODEBANC" → 覆盖
  l 收缩到 "BANC" → 仍覆盖，长度 4，更新答案
最终答案 "BANC"
```

## 代码

> 官方原版代码的循环条件 `while (r < int(s.size()))` 配合循环体内先 `++r`，会让 `r` 取到 `s.size()`——此时访问 `s[s.size()]` 对 `std::string` 是合法的（`operator[]` 在 `pos == size()` 时返回只读的末尾空字符 `\0` 的引用），不会越界。这是个易踩的细节，下面有注释。

```cpp
class Solution {
public:
    // unordered_map<char, int> ori, cnt; 作为成员变量（官方写法）。
    //   - ori：t 中每个字符的需求量（target），构造好后只读。
    //   - cnt：当前滑动窗口 [l, r] 中各字符的出现次数，动态维护。
    //   - unordered_map：基于哈希表的字典，key→value 映射；查找/插入/修改均摊 O(1)。
    //     和 map（红黑树，O(log n)）相比，本题只做 key 精确查找、不需要排序，用 unordered_map 更快。
    unordered_map<char, int> ori, cnt;

    // check()：判断当前窗口 cnt 是否「覆盖」ori（即覆盖 t）。
    //   - 遍历 ori 的每个键值对 p：p.first 是字符，p.second 是需求量；
    //     只要 cnt[p.first] < p.second（窗口里该字符不够）就返回 false。
    //   - 注意 cnt 里某 key 不存在时，cnt[key] 读出来是 0（下面会详述 [] 行为）。
    //   - 复杂度 O(|ori|) = O(字符集) = O(C)，C 最多 52（大小写字母）。
    bool check() {
        for (const auto &p : ori) {
            if (cnt[p.first] < p.second) {
                return false;
            }
        }
        return true;
    }

    string minWindow(string s, string t) {
        // 预处理：统计 t 中每个字符的需求量。
        //   - ++ori[c]：unordered_map 的 operator[] 在 key 不存在时会先插入默认值（int 为 0），
        //     再返回引用，所以 ++ 能直接对「新 key」工作，不需要先 count 判断。
        //   - const auto &c：只读引用遍历，避免拷贝每个字符。
        for (const auto &c : t) {
            ++ori[c];
        }

        int l = 0, r = -1;          // 窗口 [l, r]，r=-1 表示空窗口
        // INT_MAX：limits.h / climits 里的整型最大值（2147483647）。
        //   - 这里作 len 的「哨兵」初值：任何合法窗口长度都 < INT_MAX，第一次比较必被更新。
        //   - 比手写 0x3f3f3f3f 更直观；力扣 C++ 环境默认可用。
        int len = INT_MAX, ansL = -1;

        // 主循环：r < s.size() 时继续。
        //   - 下一行先 ++r，所以 r 实际取值范围是 [0, s.size()]。
        //   - 当 r == s.size() 时：进入循环体，++r 后 r 不再 < size()，但本轮仍会执行 check()/收缩，
        //     这是为了让「最后一次扩张后」还能收缩一次拿到最短答案。
        while (r < int(s.size())) {
            // 扩张：把 s[r] 纳入窗口。
            //   - ori.find(s[r])：在 ori 中查找；返回迭代器，找不到返回 ori.end()。
            //     这里用 find != end() 而不是 count()，效果一致（count 返回 0/1）。
            //   - 只有 t 中出现的字符才计入 cnt，其它字符直接跳过（窗口长度仍含它）。
            if (ori.find(s[++r]) != ori.end()) {
                ++cnt[s[r]];
            }

            // 收缩：只要当前窗口覆盖 t，就尝试把左边界往右挤，挤到「再挤就不覆盖」为止。
            //   - check() 每次都遍历整个 ori，代价 O(C)。
            //   - 条件 l <= r：保证窗口非空（收缩不能让 l 跑到 r 右边）。
            while (check() && l <= r) {
                // 发现一个合法覆盖窗口，用它更新最短答案。
                if (r - l + 1 < len) {
                    len = r - l + 1;
                    ansL = l;          // 记下起点；长度 len 已记，返回时 substr(ansL, len)
                }
                // 把 s[l] 移出窗口，准备继续收缩。
                if (ori.find(s[l]) != ori.end()) {
                    --cnt[s[l]];
                }
                ++l;
            }
        }

        // ansL == -1 表示从未更新过答案（即 s 无法覆盖 t）。
        //   - string()：默认构造的空字符串（等价于 ""）。
        //   - s.substr(pos, len)：从 pos 起取长度 len 的子串，返回新 string，O(len)。
        return ansL == -1 ? string() : s.substr(ansL, len);
    }
};
```

## 复杂度

- **时间**：O(C·m + n)
  - `l`、`r` 对 `s` 各至多遍历一遍，共 O(m) 次指针移动；
  - 每次指针移动后调用一次 `check()`，单次 O(C)（C 为字符集大小，本题 ≤ 52）；
  - 预处理 `t` 是 O(n)。整体 O(C·m + n)。由于 C 是常数（英文字母），可写成 **O(m + n)**。
  - 下方「复盘」的过滤优化能把每次比较降到 O(1)，进一步省掉 C 这个因子。
- **空间**：O(C)
  - 两张哈希表 `ori` / `cnt`，键数不超过字符集大小 C。

## 复盘

- **核心套路**：**「先扩张到合法，再收缩到最短」** 是「最小覆盖 / 最短合法子串」类问题的通用滑动窗口模板。和「最长无重复」正好相反（那个是「扩张到非法就收缩」）。判断条件写成一个谓词（本题 `check()`），主循环结构 `for/while r { 扩; while 合法 { 更新答案; 缩 } }` 可以套到很多题。
- **`unordered_map` 的三个易混点**（STL 踩坑）：
  - `m[key]`：**读/写都会**在 key 不存在时插入默认值。所以「只想读、不想污染表」时**不要用 `[]`**，应该用 `m.find(key)` 或 `m.count(key)` 先判存在。本题 `check()` 里 `cnt[p.first]` 用 `[]` 是安全的，因为 `p.first` 来自 `ori`，遍历过它一定会触发写入；但若 `cnt` 中该 key 还没建过，会多插一个 0 项——结果正确但表会膨胀。
  - `m.count(key)`：返回 0 或 1（multimap 才可能 >1），用于「判断是否存在」最直观。
  - `m.find(key)`：返回迭代器，找不到等于 `m.end()`；需要「既判存在又拿值」时比 `[]` 更安全（不污染表）。
- **`INT_MAX` 作哨兵**：找最小值时把答案初值设成 `INT_MAX`（`<climits>`），任何合法值都会更小，避免单独写「第一次赋值」的特判。注意 `INT_MAX + 1` 会溢出，本题只做 `<` 比较不参与运算，安全。
- **收缩内层 `while` 的终止条件**：除了 `check()` 为假，还必须有 `l <= r`（或 `l <= r + 1` 之类）防越界。本题窗口 `[l, r]` 收缩到 `l > r` 时就空了，`check()` 自然返回假，所以 `l <= r` 看似多余但官方保留它是稳妥写法。

### 解法二：过滤后的滑动窗口（官方优化思路）

官方「方法一」正文末尾留了一个开放问题：如果 `s` 里很多字符根本不在 `t` 中（如 `s = "XXXXABCXXXX"`, `t = "ABC"`），扩张时把无用的 `X` 逐个进窗、收缩时又逐个扔掉，做了无用功。**优化思路**：先扫一遍 `s`，**只保留在 `t` 中出现的字符及其原始下标**，存成 `filtered_s`；然后在 `filtered_s` 上跑滑动窗口——窗口的左右端点在 `filtered_s` 上移动，但实际子串长度用「原始下标之差 + 1」算。

进一步可以引入一个 `valid` 计数器（窗口里「需求已满足的字符种类数」），当 `valid == ori.size()` 即覆盖，省掉每次 O(C) 的整表 `check()`，把单步比较降到 O(1)。

```cpp
class Solution {
public:
    string minWindow(string s, string t) {
        // ori：t 中每个字符的需求量
        unordered_map<char, int> ori;
        for (const char &c : t) ++ori[c];

        // filtered_s：只保留 s 中在 t 出现过的字符，配对存 (字符, 原下标)。
        //   - vector<pair<char,int>>：存「字符 + 下标」的动态数组。
        //   - pair 的两个成员用 .first / .second 访问。
        //   - 这样滑动窗口只在这些「有用字符」之间推进，跳过了大量无关字符。
        vector<pair<char, int>> filtered_s;
        for (int i = 0; i < (int)s.size(); ++i) {
            if (ori.find(s[i]) != ori.end()) {
                // emplace_back：在末尾就地构造元素；比 push_back({s[i], i}) 少一次临时对象拷贝。
                filtered_s.emplace_back(s[i], i);
            }
        }

        unordered_map<char, int> window;   // 当前窗口里各字符计数
        int left = 0, right = 0;            // 双指针，作用在 filtered_s 上
        int valid = 0;                      // 窗口里「需求已满足」的字符种类数
        int start = 0, minLen = INT_MAX;

        while (right < (int)filtered_s.size()) {
            char c = filtered_s[right].first;
            ++window[c];
            // window[c] == ori[c]：该字符的计数刚好达到需求（多的不算，避免 valid 重复加）
            if (window[c] == ori[c]) ++valid;

            // 所有种类都满足即覆盖，开始收缩左端
            while (valid == (int)ori.size()) {
                // 用「原始下标之差 + 1」算真实子串长度
                int curLen = filtered_s[right].second - filtered_s[left].second + 1;
                if (curLen < minLen) {
                    minLen = curLen;
                    start = filtered_s[left].second;   // 真实起点
                }
                // 把左端字符移出窗口
                char d = filtered_s[left].first;
                if (window[d] == ori[d]) --valid;      // 从「刚好满足」跌出，valid 减 1
                --window[d];
                ++left;
            }
            ++right;
        }
        return minLen == INT_MAX ? "" : s.substr(start, minLen);
    }
};
```

- **时间**：O(m + n)。预处理 `ori` 是 O(n)；过滤 `s` 是 O(m)；之后在 `filtered_s` 上左右指针各走一遍，每步 O(1)（用 `valid` 替代 `check()`，不再扫整个 `ori`）。当 `s` 里多数字符都不在 `t` 中时，比方法一明显更快；最坏情况（`s`、`t` 字符高度重叠）和方法一同阶。
- **空间**：O(m + n)。`filtered_s` 最坏 O(m)，两张哈希表 O(字符集)。
- **小细节**：`valid` 用「`window[c] == ori[c]`」判断该字符「刚好达标」，**只有刚达标那一刻 `++valid`，超过不再加**；收缩时若 `window[d] == ori[d]`（即移出前刚好达标，移出后就不够了）才 `--valid`。这是「计数器代替整表比较」的标准写法，可迁移到所有「覆盖 / 匹配频次」类滑动窗口题。
