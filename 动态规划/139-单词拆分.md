# 139 单词拆分

- 难度：中等
- 标签：字典树、记忆化、数组、哈希表、字符串、**动态规划**
- 力扣链接：https://leetcode.cn/problems/word-break/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[单词拆分](https://leetcode.cn/problems/word-break/solution/dan-ci-chai-fen-by-leetcode-solution/)」。正文主解是 **动态规划**——`dp[i]` 表示 `s` 的前 `i` 个字符能否被字典拆分，O(n²) 状态、每个状态枚举切点；用 `unordered_set` 存字典做 O(1) 查找。官方的**记忆化搜索**（自顶向下 DP）放在「复盘」作对照。这是**字符串 DP 的经典题**：「能否由若干部分拼成」一类的套路起点。

## 题目描述

给你一个字符串 `s` 和一个字符串列表 `wordDict` 作为字典。如果可以利用字典中出现的一个或多个单词拼接出 `s` 则返回 `true`。

**注意：** 不要求字典中出现的单词全部都使用，并且字典中的单词可以**重复使用**。

**示例 1：**

```
输入: s = "leetcode", wordDict = ["leet", "code"]
输出: true
解释: 返回 true 因为 "leetcode" 可以由 "leet" 和 "code" 拼接成。
```

**示例 2：**

```
输入: s = "applepenapple", wordDict = ["apple", "pen"]
输出: true
解释: 返回 true 因为 "applepenapple" 可以由 "apple" "pen" "apple" 拼接成。
     注意，你可以重复使用字典中的单词。
```

**示例 3：**

```
输入: s = "catsandog", wordDict = ["cats", "dog", "sand", "and", "cat"]
输出: false
```

**提示：**

- `1 <= s.length <= 300`
- `1 <= wordDict.length <= 1000`
- `1 <= wordDict[i].length <= 20`
- `s` 和 `wordDict[i]` 仅由小写英文字母组成
- `wordDict` 中的所有字符串 **互不相同**

## 思路

> 本题主要参考力扣官方题解「方法一：动态规划」。

题目三要素：①字典里的单词**可以重复用**（不是每词用一次，类似「无限硬币」）；②问的是「**能否**拼成」（布尔判定，不是方案数、不是最少词数）；③允许**只用字典里的一部分单词**（不必全用上）。

这本质就是「**用一些可重复的字符串，问能否拼出目标字符串**」——和 322 零钱兑换「用可重复的硬币凑金额」结构很像，只是把「硬币面额 + 求和」换成了「单词串 + 拼接」。所以照搬 DP 套路：**定义「前 i 个字符能否被拼出」为状态，盯着最后一段单词找转移**。

### DP 三要素（所有 DP 题的通用思考框架）

#### ① 状态定义：`dp[i]` = 字符串 `s` 的前 `i` 个字符 `s[0..i-1]` 能否被字典拆分（`bool`）

把「前 `i` 个字符能否拼出来」这个子问题用一个 `bool` 数组描述。`dp[n]`（`n = s.size()`）就是答案。

> 为什么这么定义？因为「前 `i` 个字符能否拼成」是一个**结构相同的子问题**，原问题就是 `i = n` 的特例。下标用「前 i 个字符」而不是「第 i 个字符」，是为了把「空串」这个边界天然对应到 `dp[0]`。

#### ② 状态转移方程：`dp[i] = dp[j] && s[j..i-1] 在字典中`（核心！）

**盯着「最后一段单词」看**：假设 `s[0..i-1]` 能被拆成若干单词，那么**最后一个单词**一定占据了 `s[j..i-1]` 这一段（某个切点 `j`，`0 <= j < i`）。于是 `s[0..i-1]` 被切成两段：

- 前半段 `s[0..j-1]`（前 `j` 个字符）——它能不能被拆分，**正是 `dp[j]`**（已经算好了）；
- 后半段 `s[j..i-1]`——它必须是字典里的**某一个单词**。

只有这两段**同时合法**，`dp[i]` 才为 `true`。但「最后一个单词从哪里切」我们事先不知道，所以**枚举所有切点 `j`**：只要存在一个 `j` 使 `dp[j]` 为真 **且** `s[j..i-1]` 在字典里，`dp[i]` 就是真。

```
dp[i] = OR { dp[j] && s.substr(j, i-j) 在 wordSet 中 }    对所有 0 <= j < i
```

一句话总结：**「前 i 个字符能拆分 ⇔ 存在切点 j，使前 j 个字符能拆分、且剩下的 s[j..i-1] 是字典里的单词」**。这是字符串「能否由部分组成」类 DP 的标准转移。

#### ③ 初始条件：`dp[0] = true`，其余默认 `false`

- `dp[0] = true`：**空串可以被拆分**（「什么都不拼」也是一种合法状态）。这个边界**必须手动给**：当切点 `j = 0` 时，转移退化为「`dp[0] && s[0..i-1] 整段在字典里`」——即整个前缀就是一个单词的情况。如果 `dp[0]` 是 `false`，单单词的情况（示例 2 里第一个 `apple`）就永远判不出来。
- `dp[1..n]` 初始为 `false`（`vector<bool>` 默认就是 `false`）：一开始「悲观地认为拆不出来」，后面只要找到一个合法切点就翻成 `true`。

### 为什么用 `unordered_set` 存字典？

转移里要**反复判断「某个子串在不在字典里」**。如果每次都扫一遍 `wordDict` 数组，是 O(字典大小) 每次，太慢。把字典预先塞进 `unordered_set<string>`（哈希集合），查找**均摊 O(1)**，外层 O(n²) 次查找总开销可控。

> `unordered_set` vs `set`：前者基于哈希表，查找/插入均摊 O(1)；后者基于红黑树，O(log m)。本题只需判存在、不要求顺序，用哈希集合最快。注意**字符串哈希的代价和串长成正比**（算哈希要扫一遍字符），所以严格说是「查找 O(len)」，但 `len <= 20` 很小，可视为常数。

### 手动推导 `s = "leetcode", wordDict = ["leet", "code"]`

`n = 8`，`wordSet = {"leet", "code"}`，`dp[0..8]` 初始 `dp[0]=true`，其余 `false`。

逐个算 `dp[i]`，内层枚举切点 `j`（这里只列「`dp[j]` 为真」的 `j`，因为 `dp[j]` 假直接跳过）：

```
i=1: 可枚举 j=0(dp[0]=T): substr(0,1)="l"    不在 wordSet → dp[1]=false
i=2: j=0: "le"   不在 → false
i=3: j=0: "lee"  不在 → false
i=4: j=0: substr(0,4)="leet" 在 wordSet! → dp[4]=true, break  ★ 找到了
i=5: j=0("leetc" 不在); j=4(dp[4]=T): substr(4,1)="t" 不在 → dp[5]=false
i=6: j=4: substr(4,2)="co" 不在 → false
i=7: j=4: substr(4,3)="cod" 不在 → false
i=8: j=4: substr(4,4)="code" 在 wordSet! → dp[8]=true, break  ★ 找到了
```

最终 `dp[8] = true` ✓。对应拆分 `leet | code`（切点 `j=4` 处把前缀 `s[0..3]="leet"` 和后缀 `s[4..7]="code"` 拼起来）。

**反例** `s = "catsandog", wordDict = ["cats","dog","sand","and","cat"]`：`dp[3]=true`（`cat`）、`dp[4]=true`（`cats`）、`dp[7]=true`（`cats+and` 或 `cat+sand`），但算 `dp[9]` 时枚举 `j=7` 剩 `substr(7,2)="og"` 不在字典、`j=4` 剩 `"sandog"` 不在、其他 `dp[j]` 都假……没有任何切点能让最后一段落在字典里，`dp[9]` 保持 `false`，返回 `false` ✓。

## 代码

```cpp
class Solution {
public:
    bool wordBreak(string s, vector<string>& wordDict) {
        // ★ unordered_set<string> wordSet：基于哈希的字符串集合，存「字典里出现过的所有单词」。
        //   - 签名 unordered_set<Key>，Key 是 string。底层哈希表，插入/查找均摊 O(1)（严格说是 O(串长)，因为要算哈希）。
        //   - 作用：把 wordDict 从 vector 搬进 set，后面判「某子串在不在字典」就能 O(1) 查，而不是每次扫一遍 vector。
        //   - unordered_set vs set：前者哈希 O(1)、无序；后者红黑树 O(log m)、有序。本题只要判存在，用哈希最快。
        //   - 构造方式：用 wordDict 的 [begin, end) 区间初始化，一行搞定（区间构造，省去手写循环 insert）。
        unordered_set<string> wordSet(wordDict.begin(), wordDict.end());

        int n = s.size();

        // ★ vector<bool> dp(n + 1)：长度 n+1 的 bool 数组，dp[i] 表示 s 前 i 个字符 s[0..i-1] 能否被字典拆分。
        //   - 下标范围 0..n（含两端），dp[n] 就是答案。
        //   - vector<bool> 默认全 false：一开始「悲观地认为都拆不出来」，后面找到一个合法切点再翻 true。
        //   - 注意 vector<bool> 是特化版本，内部按位压缩存储（不是普通 bool 数组），用它做 dp 没问题；
        //     若要取地址 &dp[i] 会出问题（返回的是代理对象），但本题只读写值、不取地址，安全。
        vector<bool> dp(n + 1);

        // ★ dp[0] = true：空串可以被拆分（「什么都不拼」是合法状态）。
        //   - 这是转移方程能启动的起点：当切点 j=0 时，转移是 dp[i] = dp[0] && s[0..i-1] 在字典里，
        //     即「整个前缀就是一个单词」的情况（如示例 2 第一个 apple）。dp[0] 为 false 的话这类情况全判不出来。
        dp[0] = true;

        // 外层循环：枚举「前 i 个字符」这个子问题，从小到大递推。
        //   - i 从 1 到 n（含 n），共 n 个状态；每个状态依赖比它小的 dp[j]，所以自底向上先算小再算大。
        //   - i=0 已经初始化，不用算。
        for (int i = 1; i <= n; ++i) {

            // 内层循环：枚举切点 j，把 s[0..i-1] 切成「前缀 s[0..j-1] + 后缀 s[j..i-1]」。
            //   - j 从 0 到 i-1：j=0 表示「整个前缀当最后一个单词」，j=i-1 表示「最后一个单词只有 s[i-1] 一个字符」。
            //   - 思路对应转移：dp[i] = dp[j] && s[j..i-1] 在字典里。
            for (int j = 0; j < i; ++j) {

                // ★ 双条件判断：dp[j] 为真，且子串 s[j..i-j] 在字典里。
                //   - dp[j]：前 j 个字符已经被拆分过了（短路条件，假就直接跳过，省得算 substr）。
                //   - wordSet.count(key)：返回 key 在集合里的个数（0 或 1）。
                //     · count 这里等价于「key 是否存在」，比 find(key)!=end() 写起来短。
                //     · unordered_set 元素互异，count 只会是 0/1；不像 multiset 能 >1。
                //   - s.substr(pos, len)：string 成员函数，返回从下标 pos 开始、长度 len 的子串**副本**（新 string）。
                //     · 参数：pos 起始下标，len 子串长度。这里要 s[j..i-1] 共 (i-j) 个字符，所以传 (j, i-j)。
                //     · 注意第二参数是「长度」不是「结束下标」，容易记混；写成 substr(j, i-j) 最稳。
                //     · 复杂度 O(len)：会拷贝字符。所以严格说本题每次转移是 O(n)（substr）+ O(n)（哈希算 key），总 O(n³)。
                //     · 若要 O(n²) 得改成「在哈希表上跑字符串匹配」或用 Trie，官方按「哈希查找视为 O(1)」记作 O(n²)。
                if (dp[j] && wordSet.count(s.substr(j, i - j))) {

                    // 找到一个合法切点就够，dp[i] 置 true。
                    dp[i] = true;

                    // ★ break：找到一种拆法即真，不必再试后面的切点。
                    //   - 本题问「能否」拆分（OR 语义），不是求方案数/最少词数，没必要穷举所有 j。
                    //   - 提前跳出省时间，是「能否型 DP」的常用剪枝。
                    break;
                }
            }
        }

        // dp[n] 即「整个 s 能否被拆分」。
        return dp[n];
    }
};
```

## 复杂度

- **时间**：O(n²)（按官方，把哈希查找视为 O(1)），`n = s.length()`
  - 外层 `i` 共 O(n) 个状态，每个状态内层枚举 O(n) 个切点 `j`，每次 `dp[j] && wordSet.count(...)` 是 O(1)。
  - **注意 C++ 里的实际开销**：`s.substr(j, i-j)` 会**拷贝子串**，是 O(len)，加上字符串哈希也要扫子串算哈希值，严格说每次转移是 O(n)，**总复杂度 O(n³)**。由于数据范围 `n <= 300`，`n³ ≈ 2.7×10⁷`，仍能 AC。若要真正 O(n²)，可以把「在字典里查子串」换成在 Trie 上跑匹配，或倒序枚举 `j` 并限制子串长度不超过字典里最长单词（≤ 20），剪枝后常数极小。
- **空间**：O(n)
  - `dp` 数组 O(n)；`wordSet` 存字典所有单词，单词总长度上限是 `1000 × 20`，但官方按「与 n 同阶」记 O(n)。两者相加 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么 `dp[0] = true`？空串也算「能拆分」吗？

算。`dp[0] = true` 的物理意义是「**空串可以由零个单词拼成**」——它不是数学上的「空串等于某个单词」，而是 DP 的**边界约定**：为转移方程提供一个合法的起点。

看转移 `dp[i] = dp[j] && s[j..i-1] 在字典里`。当 `j = 0` 时，前缀 `s[0..-1]` 就是空串，对应「整个 `s[0..i-1]` 就是一个单词、前面没有别的东西」的情况。这种情况要让 `dp[i]` 能变 `true`，就必须有 `dp[0] = true`。否则像示例 2 第一个 `apple`（`i=5, j=0`，整段 `"apple"` 在字典里）就判不出来，后面全崩。

> 类比：322 零钱兑换里 `dp[0] = 0`（凑金额 0 用 0 枚硬币），70 爬楼梯里 `dp[0] = 1`（站地面算 1 种不动）。**「空/零/不动」这种退化状态往往要初始化成「合法」**，否则转移启动不了。

### Q2：内层循环的 `j` 到底在枚举什么？为什么范围是 `[0, i)`？

`j` 是**切点**（分割位置），把前缀 `s[0..i-1]` 切成两段：

- 前段 `s[0..j-1]`（前 `j` 个字符）——能否拆分由 `dp[j]` 表达；
- 后段 `s[j..i-1]`（`i-j` 个字符）——必须正好是字典里某个单词。

`j` 范围 `[0, i)`：

- `j = 0`：前段为空（`dp[0]=true`），后段是整个 `s[0..i-1]`，即「整段前缀就是一个单词」。
- `j = i-1`：前段是前 `i-1` 个字符，后段只有最后一个字符 `s[i-1]`。
- `j` 不能等于 `i`：那样后段长度为 0，空串不是字典里的单词（题目说 `wordDict[i].length >= 1`），无意义。

枚举 `j` 就是**枚举「最后一个单词的起点」**，这是字符串「拆分/切分」类 DP 的通用视角。

### Q3：`s.substr(j, i-j)` 的两个参数是什么意思？为什么经常记混？

`string::substr(pos, len)`：

- **第一个参数 `pos`**：子串**起始下标**（从 0 开始）。
- **第二个参数 `len`**：子串的**长度**（不是结束下标！）。

这里要取 `s[j..i-1]`，起点是 `j`，长度是 `i - j`（从 `j` 数到 `i-1` 共 `i-j` 个字符），所以写 `s.substr(j, i - j)`。

容易记混是因为别的语言/库不一样：Java 的 `s.substring(j, i)` 第二参是**结束下标**（不含）；Python 的 `s[j:i]` 也是切片右端。C++ 的 `substr` 第二参是**长度**——要换算成 `i - j`。记不住就记住口诀：**「C++ substr 是 起点加长度」**。

> 另外 `substr` 会**拷贝**出新 string（不修改原串），所以调用一次 O(len)。这也是本题严格复杂度是 O(n³) 的原因。

### Q4：为什么找到 `true` 就 `break`？不 break 会怎样？

本题问的是「**能否**拆分」（OR 语义）：只要存在**一种**拆法，`dp[i]` 就是 `true`。所以一旦某个切点 `j` 让 `dp[j] && 子串在字典` 成立，就立刻翻 `true` 并 `break`，没必要继续试后面的 `j`。

不 `break` 也不会错（最多多算几次无用的 `substr` + 查表），但会**浪费时间**：最坏情况（拆不出来的 `i`）仍要枚举完所有 `j`，而能拆出来的 `i` 本可以提前退出。`break` 是「能否型 DP」的标准剪枝。

> 对比：如果题目改成「**有多少种**拆法」（方案数），就不能 `break` 了——要穷举所有切点把方案数累加。本题是判定题，OR 语义，所以 `break` 合法。

## 复盘

- **核心套路：「字符串 DP——能否由若干部分拼成」**。当题目是「给一个目标串/目标值，问能否用一组可重复的『零件』（单词、平方数、硬币）拼出来」时，套这个模板：
  1. **状态** `dp[i]` = 前 `i` 个单位（字符/金额）能否被拼出（`bool`）；
  2. **转移** `dp[i] = OR/Min { dp[j] && 第 j+1..i 段是合法零件 }`，枚举切点 `j`；
  3. **初始** `dp[0] = true`（空/零是合法起点）；
  4. 用哈希集合存「零件集合」做 O(1) 判定。
  本题和 322 零钱兑换、279 完全平方数是**同一族**——只是「零件」从数字换成了字符串、运算是拼接而非相加。
- **「盯着最后一段」找转移**：和 322「盯最后一枚硬币」、70「盯最后一步跨几阶」一脉相承——**分析最后一段是什么 → 前面剩下的是子问题 → 合成转移方程**。这是推导所有「拼接/划分」类 DP 的通用招数。本题盯「最后一个单词从哪切」，自然得到 `dp[i] = dp[j] && s[j..i-1] 在字典里`。
- **哈希集合加速「判存在」**：凡是要频繁判断「某元素在不在给定集合里」，第一反应就是 `unordered_set`（O(1) 查找），而不是每次线性扫 vector。本题把 `wordDict` 预处理进 `wordSet` 是把 O(n²·m) 降到 O(n²)（或 O(n³)，算上 substr）的关键。
- **「能否型 DP 用 OR + break 剪枝」**：求方案数要累加、不能提前退出；求「能否」只要一个切点成立就 `true` 并 `break`。分清题目的语义（OR / 求和 / 最值），决定要不要 break、要不要哨兵值。
- **边界 `dp[0] = true` 的物理意义**：「空/零/不动」这种退化状态在拼接/拆分类 DP 里通常要初始化成「合法」，否则转移在 `j=0`（整段就是一个零件）这种边界处启动不了。和 322 的 `dp[0]=0`、70 的 `dp[0]=1` 是同一思路。

### 解法二：记忆化搜索（官方思路，自顶向下 DP）

迭代 DP 是「自底向上」（从 `dp[0]` 推到 `dp[n]`）；也可以写成「自顶向下」的递归 + 记忆化：函数 `dfs(pos)` 表示「从下标 `pos` 到末尾这段后缀能否被拆分」，每步枚举「下一个单词的终点 `end`」。

```cpp
class Solution {
public:
    // memo[pos]：缓存 dfs(pos) 的结果。-1 表示没算过，0 表示 false，1 表示 true。
    //   - 用 vector<int> 而非 vector<bool>，是为了用 -1 区分「未计算」和「算出来是 false」。
    vector<int> memo;
    unordered_set<string> wordSet;

    bool dfs(const string& s, int pos) {
        if (pos == s.size()) return true;          // 扫到末尾：前面都拆成功了
        if (memo[pos] != -1) return memo[pos];     // 算过了直接查表（记忆化核心）

        // 枚举「下一个单词」的终点 end（含 pos+1 到 s.size()）。
        //   - s.substr(pos, end-pos)：下一个候选单词。
        //   - 在字典里 && 后缀 dfs(end) 也能拆成 → 整段能拆。
        for (int end = pos + 1; end <= (int)s.size(); ++end) {
            if (wordSet.count(s.substr(pos, end - pos)) && dfs(s, end)) {
                memo[pos] = 1;                       // 记忆化：true
                return true;
            }
        }
        memo[pos] = 0;                               // 所有切法都试过了，不行 → false
        return false;
    }

    bool wordBreak(string s, vector<string>& wordDict) {
        wordSet = unordered_set<string>(wordDict.begin(), wordDict.end());
        memo.assign(s.size(), -1);                   // 初始化成「全部未计算」
        return dfs(s, 0);
    }
};
```

- **时间**：O(n²)（同迭代 DP，每个子问题只算一次，共 O(n) 个子问题，每个枚举 O(n) 个终点；严格含 substr 是 O(n³)）。
- **空间**：O(n)（记忆化数组 + 递归栈深度最深 n）。
- **和迭代 DP 的关系**：记忆化搜索是「自顶向下」（从 `dfs(0)` 往下递归到 `pos == n`），迭代是「自底向上」（从 `dp[0]` 往上推到 `dp[n]`）。**两者本质等价**，只是思考方向相反：迭代通常常数更小、无递归栈溢出风险，是首选；记忆化更贴近自然语言的递归思路，适合「先想清楚递归再改迭代」的学习路径。本题 `n <= 300`，两种写法都轻松 AC。
- **注意点**：记忆化这里用 `vector<int>` 配 `-1` 标记「未计算」，是因为 `vector<bool>` 没法区分「未算」和「算出来是 false」两种状态（都是 false）。这是记忆化搜索里常见的容器选型坑。
