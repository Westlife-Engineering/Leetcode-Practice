# 416 分割等和子集

- 难度：中等
- 标签：数组、**动态规划**
- 力扣链接：https://leetcode.cn/problems/partition-equal-subset-sum/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[分割等和子集](https://leetcode.cn/problems/partition-equal-subset-sum/solution/fen-ge-deng-he-zi-ji-by-leetcode-solution/)」。正文主解是 **动态规划（0-1 背包，一维空间优化版）**，O(n×target) 时间 O(target) 空间——把「能否等和分割」转化成「能否从数组选若干数使和 = sum/2」，就是经典的 0-1 背包问题。官方同一篇文章先用**二维 dp**讲清转移方程（更直观），再把空间压到一维（内层 `j` 必须**倒序**遍历，这是 0-1 背包的命门）；二维版本放「复盘」对照。

## 题目描述

给你一个 **只包含正整数** 的 **非空** 数组 `nums` 。请你判断是否可以将这个数组分割成两个子集，使得两个子集的元素和相等。

**示例 1：**

```
输入：nums = [1,5,11,5]
输出：true
解释：数组可以分割成 [1, 5, 5] 和 [11] 。
```

**示例 2：**

```
输入：nums = [1,2,3,5]
输出：false
解释：数组不能分割成两个元素和相等的子集。
```

**提示：**

- `1 <= nums.length <= 200`
- `1 <= nums[i] <= 100`

## 思路

> 本题主要参考力扣官方题解「方法一：动态规划」。

### 第一步：把「等和分割」翻译成「选子集凑一半」

题目要求把数组分成**两个子集**、使它们的元素和**相等**。设数组总和是 `sum`，如果真能等分，那每一份的和必然都是 `sum / 2`。换句话说——

> 原问题 ⟺ 「能否从 `nums` 里选出**若干个数**（每个数**只用一次**），使它们的和恰好等于 `sum / 2`」。

这就是整道题最关键的转化。一旦想通这一步，后面全是套背包模板。转化过程中要先做三个前置判断（任何一个不满足就直接返回 `false`，省得白跑 DP）：

1. **`n < 2`**：数组不到 2 个元素，没法分成两个非空子集，直接 `false`。
2. **`sum` 是奇数**：奇数没法对半平分（`sum/2` 不是整数），直接 `false`。代码里用 `sum & 1` 或 `sum % 2` 判奇偶。
3. **`maxNum > target`**：如果数组里最大的那个数已经超过 `target = sum/2`，那它单独一个就爆了，剩下的数加起来又不够 `target`（因为总和才 `2×target`），所以也 `false`。

通过这三关后，记 `target = sum / 2`，问题就**纯粹**变成：「能否选若干数凑出 `target`」。

### 第二步：为什么这是 0-1 背包？

对比一下「传统 0-1 背包」和本题：

| 维度 | 传统 0-1 背包 | 本题 |
|---|---|---|
| 物品 | n 个，各有重量和价值 | n 个数，每个数既是「重量」又是「价值」（值 = 重量） |
| 每个物品 | 选 / 不选，**至多选一次** | 选 / 不选，**每个数只能用一次** |
| 背包容量 | W | `target = sum/2` |
| 目标 | 重量 ≤ W 时价值最大 | 选出的数之和**恰好等于** `target`（问能否，是 bool） |

唯一的区别是：传统背包要求「**不超过**容量」，本题要求「**恰好等于** `target`」。但骨架完全一样——每个数只有「选 / 不选」两种决策，且不可重复用。这就是典型的 **0-1 背包**（「0-1」就是「每个物品选 0 个或 1 个」的意思）。

> 顺带一提：和 **322 零钱兑换** 对比，322 的硬币**可以无限用**（完全背包），本题的数**只能用一次**（0-1 背包）。两者内层循环的方向正好相反——这是背包家族最容易混的地方，下文会专门讲。

### 第三步：DP 三要素

#### ① 状态定义：`dp[j]` = 能否从数组里选若干数、使和**恰好**为 `j`

`dp` 是个长度 `target + 1` 的 bool 数组（一维优化版）。`dp[target]` 就是答案。

> 二维版本是 `dp[i][j]` = 「从下标 `[0, i]` 范围内选若干数、能否凑出和 `j`」。观察到「第 i 行的 `dp` 只依赖第 `i-1` 行」，所以能把「物品维度」i 压掉，只剩「容量维度」j。这正是 198 打家劫舍「滚动变量」思想在背包里的推广。

#### ② 状态转移方程：`dp[j] = dp[j] | dp[j - num]`（核心！）

**盯着「当前的数 `num` 选不选」看**——两种决策取「或」（只要有一种能凑出就行）：

- **不选 `num`**：能否凑出 `j` 取决于之前的数，即原来的 `dp[j]`；
- **选 `num`**：那剩下要凑的和是 `j - num`，能否凑出看 `dp[j - num]`。

两者有一个为真就为真：

```
dp[j] = dp[j] | dp[j - num]      对所有 j >= num
```

一句话总结：**「能否凑和 j = 不选 num 时凑得出 j（dp[j]）或者 选 num 时凑得出 j-num（dp[j-num]）」**。

#### ③ 初始条件：`dp[0] = true`，其余 `false`

- `dp[0] = true`：和为 0 意思是「什么都不选」，永远可行（这是转移方程的起点：当选 `num` 恰好等于 `j` 时，要查 `dp[0]`，代表「只选这一个 num 就凑齐 j」）。
- `dp[1..target] = false`：一开始还没选任何数，非 0 的和都凑不出，慢慢更新。

### ★ 第四步：为什么一维版内层 `j` 必须**倒序**遍历？（全题命门）

这是 0-1 背包和完全背包最核心的区别，务必想清楚。

二维版转移是 `dp[i][j] = dp[i-1][j] | dp[i-1][j-num]`——注意等号右边**两处都是第 `i-1` 行**（上一层、还没考虑 `num` 之前的状态）。压成一维后，`dp[j]` 在被更新前，存的正好就是「上一层」的值。问题是：**更新顺序会决定 `dp[j-num]` 到底是「上一层」还是「本层」的值**。

- **倒序（`j` 从 `target` 到 `num`）**：算 `dp[j]` 时，`dp[j-num]` 因为下标更小、**还没被本轮更新过**，所以它仍是「上一层」的旧值——正好对应二维版 `dp[i-1][j-num]`。✅ 这正是 0-1 背包要的语义（每个数只用一次）。
- **正序（`j` 从 `num` 到 `target`）**：算 `dp[j]` 时，`dp[j-num]` 下标更小、**已经被本轮更新过了**，里面已经「掺进了当前 `num`」。于是 `dp[j] = dp[j] | dp[j-num]` 会把 `num` **用第二次**——这就退化成了**完全背包**（每个数可重复用），违背了「每个数只用一次」的题意。❌

> 反例：`nums = [2]`、`target = 4`，正确答案应是 `false`（一个 2 没法凑出 4）。但若误用正序：`dp[2] = dp[2] | dp[0] = true`，接着 `dp[4] = dp[4] | dp[2] = true`——把同一个 2 用了两次，错成 `true`。倒序就不会犯这个错：`dp[4]` 先算、此时 `dp[2]` 还是 `false`，所以 `dp[4]` 保持 `false`。

**口诀**：**0-1 背包内层倒序（保证每个物品只用一次）；完全背包内层正序（允许物品重复用）**。322 零钱兑换是完全背包、正序；本题是 0-1 背包、倒序。两道题对照着记，一辈子忘不掉。

### 手动推导 `nums = [1,5,11,5]`

`sum = 1+5+11+5 = 22`（偶数 ✓），`target = 11`，`maxNum = 11 ≤ 11` ✓。初始 `dp = [T, F, F, F, F, F, F, F, F, F, F, F]`（下标 0~11，T=true，F=false）。

外层依次处理每个数 `num`，内层 `j` **从 11 倒序到 num**，执行 `dp[j] |= dp[j-num]`：

```
num=1:  j=11→1，dp[j] |= dp[j-1]
        dp[1]=T, dp[2]=T, ..., dp[11]=T   （全是 dp[0]=T 连锁推上来）
        dp = [T,T,T,T,T,T,T,T,T,T,T,T]    （和 1~11 都能凑出，用若干个 1）

num=5:  j=11→5，dp[j] |= dp[j-5]
        j=11: dp[11] |= dp[6]=T  → T
        j=10: dp[10] |= dp[5]=T  → T
        j=9:  dp[9]  |= dp[4]=T  → T
        j=8:  dp[8]  |= dp[3]=T  → T
        j=7:  dp[7]  |= dp[2]=T  → T
        j=6:  dp[6]  |= dp[1]=T  → T
        j=5:  dp[5]  |= dp[0]=T  → T
        dp 不变（本来就全是 T）

num=11: j=11→11，dp[11] |= dp[0]=T → T

num=5:  j=11→5，dp[j] |= dp[j-5]，仍全是 T

返回 dp[11] = true ✓   （对应 [1,5,5] 凑出 11，剩下 [11] 自然也是 11）
```

再看示例 2 `nums = [1,2,3,5]`：`sum = 11` 是**奇数** → 第二关就 `return false`，根本不用跑 DP。这正说明前置判断的价值。

## 代码

```cpp
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int n = nums.size();

        // ★ 前置判断 1：n < 2 没法分成两个非空子集，直接 false。
        //   —— 官方代码照搬，防御性编程。
        if (n < 2) {
            return false;
        }

        // 一次性累加总和、找最大值。
        //   - accumulate(b, e, init)：STL 数值算法 <numeric>，从 init 起累加 [b,e) 所有元素。
        //     · init 给 0（int 字面量）→ 累加按 int 进行；若元素是 long long 要写 0LL 防溢出。
        //     · 复杂度 O(n)，遍历一次。
        //   - max_element(b, e)：STL 算法 <algorithm>，返回 [b,e) 中「最大元素的迭代器」。
        //     · 注意返回的是迭代器不是值，取值要解引用 *max_element(...)。
        //     · 多个并列最大时返回第一个；复杂度 O(n)。
        int sum = accumulate(nums.begin(), nums.end(), 0);
        int maxNum = *max_element(nums.begin(), nums.end());

        // ★ 前置判断 2：sum 是奇数没法对半平分（target 不是整数），直接 false。
        //   - sum & 1：按位与取最低位，等价于 sum % 2，但更快（位运算）。
        //     · 奇数 & 1 == 1（真），偶数 & 1 == 0（假）。
        //     · 正整数才适用这种判奇偶的写法；负数 % 2 在 C++11 后保证截断到 0，但位运算判负数要小心符号位。
        if (sum & 1) {
            return false;
        }

        int target = sum / 2;        // 每一份的目标和（sum 必为偶数才能走到这）

        // ★ 前置判断 3：最大元素已超过 target，剩下的数加起来必 < target，没法凑，直接 false。
        //   - 这是个剪枝，不加也对，但能提前 return 省时间。
        if (maxNum > target) {
            return false;
        }

        // vector<int> dp(target + 1, 0)：开 target+1 个 int，全初始化为 0（即 false）。
        //   - 这里用 vector<int> 而非 vector<bool>：vector<bool> 是 STL 的特化版（按位压缩存储），
        //     · 优点省内存（1 bit / 元素），缺点对元素取地址、位运算语义有坑，调试不直观；
        //     · 官方代码用 vector<int> 当 bool 数组（0/1），语义清晰、避免 vector<bool> 的 Proxy 陷阱。
        //   - dp[j] = 「能否选若干数凑出和恰好为 j」，下标范围 0..target。
        vector<int> dp(target + 1, 0);

        // ★ 初始条件：dp[0] = true。
        //   - 和为 0 = 什么都不选，永远可行；也是转移方程的起点
        //     （当选 num 恰好等于 j 时，dp[j] |= dp[0]，代表「只选这一个 num 就凑齐 j」）。
        dp[0] = true;

        // ★ 外层循环：遍历每个数 num（= 0-1 背包的「物品」）。
        //   - 每个 num 只处理一轮，对应「每个数只用一次」。
        //   - range-based for：for (int num : nums) 等价于按下标遍历，只读不改 nums。
        for (int num : nums) {

            // ★★ 内层循环：j 从 target 「倒序」到 num。这是 0-1 背包的命门！
            //   - 为什么必须倒序？因为转移 dp[j] |= dp[j-num] 右边要的是「还没考虑当前 num」的旧 dp[j-num]。
            //     · 倒序时 j-num < j，dp[j-num] 还没被本轮更新过 → 仍是上一层的旧值 → 正确（num 只用一次）。
            //     · 若误写成正序（j 从 num 到 target），dp[j-num] 已被本轮改过，会把 num 「用第二遍」，
            //       退化成完全背包（如 nums=[2], target=4 会错算成 true）。❌
            //   - 口诀：0-1 背包内层倒序（物品只用一次）；完全背包内层正序（物品可重复用）。
            //     322 零钱兑换是完全背包、正序；本题是 0-1 背包、倒序。
            //   - j >= num：j - num 必须 >= 0 才不越界，所以循环下界是 num（含）。
            //   - --j：前置自减，比后置 j-- 略快（后置要存旧值）；对 int 其实没差，是习惯写法。
            for (int j = target; j >= num; --j) {

                // ★ 核心转移：dp[j] = dp[j] | dp[j - num]
                //   - dp[j]      ：不选 num 时，能否凑出 j（沿用旧值）。
                //   - dp[j - num]：选 num 时，能否凑出 j-num（剩下交给之前的数）。
                //   - |= ：按位或赋值（dp[j] = dp[j] | dp[j-num]）。只要有一边为真 dp[j] 就为真。
                //     · 比 dp[j] = dp[j] || dp[j-num] 更简洁；对 0/1 的 int，| 和 || 结果一致（但 | 不短路）。
                //   - 注意：因为 j 是倒序，这里的 dp[j-num] 是「本轮还没动过的旧值」，等价于二维版的 dp[i-1][j-num]。
                dp[j] |= dp[j - num];
            }
        }

        // dp[target] = 能否凑出恰好 target。能 → 可等和分割 → true。
        return dp[target];
    }
};
```

## 复杂度

- **时间**：O(n × target)，其中 `n = nums.length`，`target = sum/2`
  - 外层遍历 n 个数，内层每个数最多扫 target 次，每次 O(1) 的位或。
  - 注意：`target` 取决于数组元素值（上限 `200×100/2 = 10000`），所以最坏约 `200 × 10000 = 2×10^6` 次操作，轻松过。
  - 官方在「前言」里特别提到：这是 **NP 完全问题**（如果存在多项式时间解法就证明了 P=NP）。这里的 O(n×target) 是**伪多项式时间**（因为 target 是数值大小而非输入长度），对力扣的数据规模足够。
- **空间**：O(target)
  - 开了一个长度 `target + 1` 的 `dp` 数组，压成了一维（朴素二维版是 O(n×target)）。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么这是 0-1 背包？怎么看出「每个数只能用一次」的？

题目说「分割成**两个子集**」，子集的定义本身就要求**每个元素要么在 A 子集、要么在 B 子集**，不能既在 A 又在 B，也不能把同一个数用两遍。所以「选出凑 `target` 的那若干个数」里，每个数**至多用一次**——这正是 0-1 背包的字面定义（「0-1」= 每个物品选 0 个或 1 个）。

对比 **322 零钱兑换**：硬币是「面额」，每种面额**有无限枚**（完全背包），所以 322 同一个硬币可以重复用。本题的「数」是数组里的具体元素，每个元素就一份、用完即止，所以是 0-1 背包。**能不能重复用，是区分 0-1 背包和完全背包的唯一标准**。

### Q2：为什么内层 `j` 要倒序？正序会怎样？（最关键的疑问）

倒序是为了**保证每个数只用一次**。转移方程 `dp[j] |= dp[j-num]` 右边的 `dp[j-num]`，必须是「**还没考虑当前 num**」的旧值（对应二维版的「上一层」）。

- 倒序（j 从大到小）：算 `dp[j]` 时，下标更小的 `dp[j-num]` **还没被本轮更新**，仍是旧值 ✅。
- 正序（j 从小到大）：算 `dp[j]` 时，`dp[j-num]` 已经被本轮改过了，里面已经「掺了 num」，于是 `dp[j] |= dp[j-num]` 会把 num **再用一次**，退化成完全背包 ❌。

**反例**：`nums = [2], target = 4`。正确答案 `false`（一个 2 凑不出 4）。但正序会算出 `dp[2]=true`，再 `dp[4] |= dp[2] = true`，错成 `true`（相当于把同一个 2 用了两次）。倒序时 `dp[4]` 先算、`dp[2]` 还是 `false`，结果正确 `false`。

**口诀**：**0-1 背包倒序（每个物品一次）；完全背包正序（物品可重复）**。322 是完全背包正序，416 是 0-1 背包倒序。

### Q3：`dp[0] = true` 为什么？和为 0 也算「凑出来了」？

算。`dp[0] = true` 的物理意义是「**不选任何数，和就是 0**」，这永远可行。它是转移方程的起点：当选某个 `num` 恰好等于 `j` 时，`dp[j] |= dp[0]` 就代表「只选这一个 num 正好凑齐 j」。

如果不设 `dp[0] = true`，那 `dp[num] |= dp[0]` 永远是 `false | false = false`，第一个数都放不进去，整张表全是 `false`，答案必错。这和 322 零钱兑换的 `dp[0] = 0`（凑金额 0 要 0 枚硬币）是同一类边界。

### Q4：`sum` 是奇数怎么办？为什么要单独判？

奇数 `sum` **根本没法对半平分**——因为 `sum/2` 不是整数，两个整数子集的和不可能等于一个非整数。所以 `sum & 1`（奇数）时直接 `return false`，不用进 DP。示例 2 `nums = [1,2,3,5]` 的 `sum = 11` 就是奇数，第二关就被拦下了。

这个前置判断既是正确性需要（避免 `target = sum/2` 向下取整后错算），也是性能优化（直接剪枝，不跑 DP）。

### Q5：为什么用 `vector<int>` 而不是 `vector<bool>`？不是 bool 数组吗？

`dp` 语义上确实是 bool（真/假），但官方代码用了 `vector<int>`（存 0/1）。原因：

- `vector<bool>` 是 STL 的**特化版本**，内部按位压缩存储（8 个元素挤 1 字节）。优点是省内存，缺点是：对元素取地址（`&dp[i]`）返回的是 proxy 代理对象而非真正的 `bool*`，和很多 STL 算法、位运算配合时会有语义陷阱，调试也不直观。
- `vector<int>` 每个元素占一个 int（4 字节），语义清晰、无坑，对 `target ≤ 10000` 的规模内存完全够用（约 40KB）。

所以「存 0/1 的 int 数组」是竞赛/刷题里更稳妥的写法。如果追求极致省内存（比如 target 上百万），才考虑 `vector<bool>` 或 `bitset`。

## 复盘

- **核心套路：「0-1 背包——每个数选 / 不选，内层倒序避免重复用」**。当题目要「从一组**不可重复**的物品里选若干个、凑满某个容量、问能否 / 最值 / 方案数」时，套 0-1 背包模板：`dp[j]` 描述容量 j 的子问题，外层遍历物品、内层 `j` **倒序**（保证每物只用一次），转移 `dp[j] = dp[j] ⊕ dp[j-w]`（⊕ 视问的是能否/最值/方案数，分别用 `|`、`max/min`、`+`）。416 是这个套路求「能否」的样板题。
- **转化思维：「等和分割 ⟺ 凑 sum/2」**。看到「分成和相等的两部分」要立刻条件反射到「选子集凑 sum/2」。这是 416、1049 最后一块石头重量、2035 等一系列「分割/配对」题的通用入口。三个前置判断（`n<2`、`sum` 奇、`maxNum>target`）是这类题的标准剪枝。
- **0-1 背包 vs 完全背包——内层方向是唯一分水岭**：物品**不可重复**用 → 0-1 背包 → 内层**倒序**（`j` 从大到小）；物品**可重复**用 → 完全背包 → 内层**正序**（`j` 从小到大）。对照记忆：**416 倒序、322 正序**。想错方向就会把 0-1 算成完全（或反之），结果错乱。
- **一维压缩的本质**：当二维 `dp[i][j]` 只依赖「上一行 `dp[i-1][...]`」时，可以把行维度 i 压掉，只留容量维度 j。倒序遍历就是为了在「原地更新」时不破坏「上一层旧值」——这和 198 打家劫舍的「滚动变量」、322 零钱兑换的「一维 dp」是同一类空间压缩思想。

### 解法二：二维 dp（官方写法一，对照用）

思路完全一样，区别是不压缩空间——直接开 `dp[n][target+1]` 把每行存下来，转移方程一目了然，**理解 / 调试时更直观**。生产代码里一维版更省内存（O(target) vs O(n×target)），是首选。

```cpp
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int n = nums.size();
        if (n < 2) return false;
        int sum = accumulate(nums.begin(), nums.end(), 0);
        int maxNum = *max_element(nums.begin(), nums.end());
        if (sum & 1) return false;             // 奇数没法等分
        int target = sum / 2;
        if (maxNum > target) return false;     // 最大元素爆掉

        // dp[i][j] = 从下标 [0,i] 范围选若干数、能否凑出和恰好为 j。
        vector<vector<int>> dp(n, vector<int>(target + 1, 0));
        for (int i = 0; i < n; i++) {
            dp[i][0] = true;                   // 不选任何数 → 和为 0
        }
        dp[0][nums[0]] = true;                 // 只有 nums[0] 可选时，只能凑它本身

        for (int i = 1; i < n; i++) {
            int num = nums[i];
            for (int j = 1; j <= target; j++) {
                // 二维版 j 可以正序！因为 dp[i-1][...] 是独立的一整行，不会被本行覆盖。
                //   - j >= num：可选 num → dp[i][j] = 不选 num (dp[i-1][j]) | 选 num (dp[i-1][j-num])
                //   - j <  num：放不下 num → 只能沿用 dp[i-1][j]
                if (j >= num) {
                    dp[i][j] = dp[i - 1][j] | dp[i - 1][j - num];
                } else {
                    dp[i][j] = dp[i - 1][j];
                }
            }
        }
        return dp[n - 1][target];
    }
};
```

- **时间**：O(n × target)
- **空间**：O(n × target)——比一维版多开一个 `n × (target+1)` 的二维数组。
- **和一维版的关系**：二维版是「原始版本」，转移方程里 `dp[i-1][...]` 是独立的一整行，**不会被本行更新覆盖**，所以 `j` 可以正序遍历、不用倒序。一维版把行维度压掉后，`dp[j-num]` 和 `dp[j]` 共用同一行，必须倒序才能保住「上一行的旧值」。**先看懂二维版（倒序不倒序无所谓），再理解一维版为什么必须倒序**，是掌握 0-1 背包的最顺路径。
- **何时用**：理解转移过程、调试时用二维版更清晰；正式提交用一维版省内存。
