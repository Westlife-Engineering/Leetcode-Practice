# 70 爬楼梯

- 难度：简单
- 标签：记忆化、数学、**动态规划**

> 说明：本题参考力扣官方题解「[爬楼梯](https://leetcode.cn/problems/climbing-stairs/solution/pa-lou-ti-by-leetcode-solution/)」。正文主解是 **动态规划（滚动变量）**，O(n) 时间 O(1) 空间——这是 **DP 入门经典**，把「状态定义 + 转移方程 + 初始条件」三件套讲透；官方的**矩阵快速幂**（O(log n)）和**通项公式**放在「复盘」作拓展。

## 题目描述

假设你正在爬楼梯。需要 `n` 阶你才能到达楼顶。

每次你可以爬 `1` 或 `2` 个台阶。你有多少种不同的方法可以爬到楼顶呢？

**示例 1：**

```
输入：n = 2
输出：2
解释：有两种方法可以爬到楼顶。
1. 1 阶 + 1 阶
2. 2 阶
```

**示例 2：**

```
输入：n = 3
输出：3
解释：有三种方法可以爬到楼顶。
1. 1 阶 + 1 阶 + 1 阶
2. 1 阶 + 2 阶
3. 2 阶 + 1 阶
```

**提示：**

- `1 <= n <= 45`

## 思路

> 本题主要参考力扣官方题解「方法一：动态规划」。

要求的是「爬到楼顶的**方法总数**」。n 很大时方法数爆炸增长，没法枚举每一种走法，得找一个**递推关系**：知道小规模的方法数，能不能推出大规模的？

### DP 三要素（所有 DP 题的通用思考框架）

做任何动态规划题，先把这三件事想清楚，代码自然就出来了。

#### ① 状态定义：`dp[i]` = 爬到第 `i` 阶的方法数

把「问题」用一个数组（或变量）描述出来。这里「第 `i` 阶的方法数」就是最自然的状态——`dp[n]` 就是答案。

> 为什么要这么定义？因为「爬到第 `i` 阶」是一个**子问题**，且原问题「爬到第 `n` 阶」就是子问题 `i=n` 的特例。DP 的本质就是把大问题拆成结构相同的子问题。

#### ② 状态转移方程：`dp[i] = dp[i-1] + dp[i-2]`（核心！）

这是全题最关键的观察。**盯着「最后一步」看**：到达第 `i` 阶的最后一步，只有两种可能——

1. **最后一步跨 1 阶**：那上一步一定站在第 `i-1` 阶，从第 `i-1` 阶到第 `i` 阶的方式只有「跨 1 阶」这 1 种，所以这部分方法数 = `dp[i-1]`；
2. **最后一步跨 2 阶**：那上一步一定站在第 `i-2` 阶，从第 `i-2` 阶到第 `i` 阶的方式也只有「跨 2 阶」这 1 种，所以这部分方法数 = `dp[i-2]`。

这两种情况**互斥**（最后一步要么跨 1 阶要么跨 2 阶，不能既是 1 又是 2）、且**完备**（题目只允许跨 1 或 2 阶，没有第三种）。所以把两部分相加就是总数：

```
dp[i] = dp[i-1] + dp[i-2]
```

一句话总结：**「爬到第 i 阶的方法数 = 爬到第 i-1 阶的方法数 + 爬到第 i-2 阶的方法数」**，因为最后一步要么从 `i-1` 跨过来，要么从 `i-2` 跨过来。

#### ③ 初始条件：`dp[1] = 1`，`dp[2] = 2`

转移方程依赖「前两项」，所以最小的两项必须**手动给定**（否则没法启动递推）：

- `dp[1] = 1`：爬到第 1 阶只有 1 种方法（跨 1 阶）。
- `dp[2] = 2`：爬到第 2 阶有 2 种方法（1+1，或直接跨 2 阶）。

> 为什么不从 `dp[0]` 开始？可以！如果把「站在地面（第 0 阶）」看成 1 种状态（不动也是一种「方法」），令 `dp[0] = 1, dp[1] = 1`，则 `dp[2] = dp[1] + dp[0] = 2`，同样递得出来。两种初始写法等价，看哪种更顺眼。本文按官方从 `dp[1]` 起算。

### 为什么就是斐波那契数列？

把转移方程 `dp[i] = dp[i-1] + dp[i-2]` 和初始值摆在一起看：

```
dp[1]=1, dp[2]=2, dp[3]=3, dp[4]=5, dp[5]=8, dp[6]=13 ...
```

这正是**斐波那契数列**（每一项 = 前两项之和）。和教科书上 `F[1]=1, F[2]=1, F[3]=2 ...` 的标准斐波那契相比，本题的 `dp[n]` 相当于 `F[n+1]`（整体错开一位）。所以这道题的本质就是「换了个马甲的斐波那契」。

### 手动推导 n = 1~5 的方法数

```
n=1: dp[1] = 1                              → 1 种   (1)
n=2: dp[2] = 2                              → 2 种   (1+1, 2)
n=3: dp[3] = dp[2]+dp[1] = 2+1     = 3      → 3 种   (1+1+1, 1+2, 2+1)
n=4: dp[4] = dp[3]+dp[2] = 3+2     = 5      → 5 种
n=5: dp[5] = dp[4]+dp[3] = 5+3     = 8      → 8 种
```

数列 `1, 2, 3, 5, 8` 就是斐波那契。

### 用滚动变量把空间压到 O(1)

朴素 DP 要开一个长度 n 的 `dp` 数组，空间 O(n)。但观察转移方程：**`dp[i]` 只依赖它前面的两项 `dp[i-1]` 和 `dp[i-2]`**，再往前的 `dp[i-3]`、`dp[i-4]`……一旦用完就再也没用了。

所以不用存整个数组，**只用 3 个变量轮流滚动**就够了——这就是「滚动变量」（也叫滚动数组思想的一维退化版）。官方代码用 `p, q, r` 三个变量，含义见下方代码注释。

## 代码

```cpp
class Solution {
public:
    int climbStairs(int n) {
        // p, q, r 是三个「滚动变量」，含义（在每轮循环「开始时」）：
        //   r = dp[i-1]  （上一轮刚算出的方法数）
        //   q = dp[i-2]
        //   p = dp[i-3]
        // 这一轮要算 dp[i] = dp[i-1] + dp[i-2] = r + q，算完后三个变量整体「往前滚动一位」。
        //
        // 初始化 p=0, q=0, r=1：
        //   - 让 r=1 相当于预设 dp[0]=1（站在地面算 1 种），这样第 1 轮就能递出 dp[1]=1。
        //   - p、q 给 0 是因为 i=1 时根本用不到 dp[-2]/dp[-1]，凑个数即可，不影响结果
        //     （第 1 轮 r = p + q = 0 + 1 = 1，正是 dp[1]）。
        int p = 0, q = 0, r = 1;

        // i 从 1 到 n：第 i 轮算出 dp[i]。
        //   - 注意是 <= n（含 n），共循环 n 次；循环结束时 r 里就是 dp[n]。
        for (int i = 1; i <= n; ++i) {
            p = q;      // 新 p = 旧 q：把 dp[i-2] 的值存进 p（为下一轮的 dp[i-3] 做准备）
            q = r;      // 新 q = 旧 r：把 dp[i-1] 的值存进 q（为下一轮的 dp[i-2] 做准备）
            r = p + q;  // 新 r = 新 p + 新 q = dp[i-2] + dp[i-1] = dp[i]   ← 本轮真正的计算
            // ★ 滚动的精髓：三句赋值的「顺序」不能乱！
            //   必须先用旧 q 覆盖 p、再用旧 r 覆盖 q，最后才能算新 r。
            //   如果先写 r = p + q，就会把旧的 r（=dp[i-1]）覆盖掉，
            //   后面 q = r 取到的就是错的值，整个递推就崩了。
            //   （这里的 p、q、r 在 C++ 里就是普通 int，赋值即覆盖，没有副本。）
        }
        return r;       // 循环结束时 r = dp[n]，即爬到楼顶的方法数
    }
};
```

**用 n=5 走一遍**（每轮循环**结束后**的 p, q, r）：

```
初始:           p=0, q=0, r=1
i=1: p=q=0, q=r=1, r=p+q=0+1=1   →  r=1   (=dp[1])
i=2: p=q=1, q=r=1, r=p+q=1+1=2   →  r=2   (=dp[2])
i=3: p=q=1, q=r=2, r=p+q=1+2=3   →  r=3   (=dp[3])
i=4: p=q=2, q=r=3, r=p+q=2+3=5   →  r=5   (=dp[4])
i=5: p=q=3, q=r=5, r=p+q=3+5=8   →  r=8   (=dp[5])
返回 8 ✓
```

## 复杂度

- **时间**：O(n)
  - 循环跑 n 次，每次做 3 次赋值 + 1 次加法，都是 O(1)，共 O(n)。
- **空间**：O(1)
  - 只用了 `p`、`q`、`r` 三个 int 变量，没有开数组。对比朴素 DP 数组的 O(n)，省了一大块。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么是斐波那契数列？两者初始值不一样啊？

「斐波那契数列」这个名字指的是**满足 `F(n) = F(n-1) + F(n-2)` 的数列**——核心是**递推关系**，初始值换一下还是同一族数列。

标准斐波那契：`F[1]=1, F[2]=1, F[3]=2, F[4]=3, F[5]=5, F[6]=8 ...`
本题爬楼梯：`dp[1]=1, dp[2]=2, dp[3]=3, dp[4]=5, dp[5]=8 ...`

对比发现 `dp[n] = F[n+1]`，只是**整体错开一位**。所以本质完全一样，凡是斐波那契的优化手段（通项公式、矩阵快速幂）都能直接套用。

### Q2：`dp[1]` 和 `dp[2]` 凭什么是 1 和 2？怎么定初始条件？

初始条件就是「**最小那几个没法用转移方程推、必须靠物理意义直接给出的子问题**」。

- `dp[1]=1`：只有 1 阶，唯一走法是「跨 1 阶」，所以 1 种。
- `dp[2]=2`：2 阶可以「1+1」或「直接跨 2」，所以 2 种。

定初始条件的通用思路：**问自己「最小的输入是什么，答案显然是多少」**，把这些边界值填进去，让转移方程能从它们出发一路推到 n。本题如果非要让转移方程从 `i=2` 开始用（`dp[2]=dp[1]+dp[0]`），就得额外定义 `dp[0]=1`（站在地面算 1 种「不动」的方式），效果一样。

### Q3：三个滚动变量 `p, q, r` 到底怎么工作？绕晕了。

记住一句话：**每轮循环把 `(p, q, r)` 整体往右「挪」一格，腾出来的最右格填新算的值**。

循环开始时三者的角色（对第 `i` 轮）：

```
p = dp[i-3]   q = dp[i-2]   r = dp[i-1]     ← 这是「旧的」三连
```

本轮目标是算 `dp[i] = dp[i-1] + dp[i-2] = r + q`，并让下一轮（`i+1`）开始时三者变成 `dp[i-2], dp[i-1], dp[i]`。所以：

```
p = q;      // p  ← 旧 q      (新 p 表示 dp[i-2]，给下轮当 dp[i-3] 用)
q = r;      // q  ← 旧 r      (新 q 表示 dp[i-1]，给下轮当 dp[i-2] 用)
r = p + q;  // r  ← 新 p + 新 q = dp[i-2] + dp[i-1] = dp[i]
```

**赋值顺序是命门**：`r = p + q` 必须放在最后。因为算新 `r` 要用到「新 p」和「新 q」（也就是更新后的 p、q），如果先动 `r` 就会把旧 `r`（dp[i-1]）冲掉，后面 `q = r` 就取到错值了。

如果觉得三变量绕，可以改写成更直观的两变量版本（见复盘 Q3 扩展），逻辑等价。

### Q4：能不能用递归做？

能，但**朴素递归会超时**。直接照着 `f(n) = f(n-1) + f(n-2)` 写递归：

```cpp
int climbStairs(int n) {
    if (n <= 2) return n;
    return climbStairs(n - 1) + climbStairs(n - 2);
}
```

这棵递归树会**重复计算**同一个 `f(k)` 很多次（比如 `f(5)` 会算 `f(4)+f(3)`，`f(4)` 又算 `f(3)+f(2)`，`f(3)` 被算了两次……），时间复杂度 O(2^n)，n=45 时约 3.5×10^13 次调用，**直接 TLE**。

两种救法：

1. **记忆化搜索**：开个 `memo` 数组，算过的 `f(k)` 存起来，下次直接查。时间降到 O(n)，本质和 DP 等价（「自顶向下」的 DP）。
2. **改成递推（本题主解）**：从 `dp[1]` 往上循环推到 `dp[n]`，天然不重复（「自底向上」的 DP）。

两种都是 O(n) 时间。递推通常常数更小、不用递归栈，是首选。

## 复盘

- **核心套路**：「**DP 三要素——状态定义 + 转移方程 + 初始条件**」是所有动态规划题的基础模板。看到「方法数 / 方案数 / 最值」且能拆成**结构相同的子问题**时，第一步就是问自己：状态怎么定义？转移怎么从子问题合成？最小的几个边界是多少？把这三件事写下来，代码就完成了一大半。
- **「盯着最后一步」找转移方程**：爬楼梯是「最后一步跨 1 阶还是跨 2 阶」；这个思考方式可迁移到一大类 DP——比如「最后一步选不选、选哪个、从哪来」。**分析最后一步→归类子问题→相加/取最值**，是推导转移方程的通用招数。
- **滚动变量压缩**：当 `dp[i]` 只依赖**有限的前几项**（本题只依赖前 2 项）时，不用数组、用几个变量滚动即可，空间从 O(n) 降到 O(1)。判断「能不能压」就看转移方程回头看几步——只看前 1 步用 2 个变量，前 2 步用 3 个变量，以此类推。
- **斐波那契家族**：本题、509 斐波那契数、1137 第 N 个泰波那契数等本质相同，都是线性递推，可互相套用解法。

### 解法二：矩阵快速幂（官方方法二，O(log n) 时间）

DP 是 O(n)，但线性递推可以用**矩阵快速幂**加速到 O(log n)。思路是把递推 `dp[i]=dp[i-1]+dp[i-2]` 写成矩阵形式：

```
[ dp[i]   ]   [ 1 1 ] [ dp[i-1] ]
[ dp[i-1] ] = [ 1 0 ] [ dp[i-2] ]
```

即 `状态向量(i) = M × 状态向量(i-1)`，其中 `M = [[1,1],[1,0]]`。于是 `状态向量(n) = M^(n-1) × 状态向量(1)`。用**快速幂**（每次把指数折半、矩阵平方）算 `M^(n-1)` 只要 O(log n) 次矩阵乘法。n=45 时差别不大，但当 n 极大（如 10^9）且递推固定的场景，这是唯一不超时的解法。

```cpp
class Solution {
public:
    // 2x2 矩阵乘法：c = a × b。二维 vector 嵌套，元素为 long long 防溢出。
    vector<vector<long long>> multiply(vector<vector<long long>> &a, vector<vector<long long>> &b) {
        vector<vector<long long>> c(2, vector<long long>(2));
        for (int i = 0; i < 2; i++) {
            for (int j = 0; j < 2; j++) {
                c[i][j] = a[i][0] * b[0][j] + a[i][1] * b[1][j];
            }
        }
        return c;
    }

    // 矩阵快速幂：算 a^n。和整数快速幂同构，只是把「数相乘」换成「矩阵相乘」。
    vector<vector<long long>> matrixPow(vector<vector<long long>> a, int n) {
        vector<vector<long long>> ret = {{1, 0}, {0, 1}};  // 单位矩阵（矩阵乘法的「1」）
        while (n > 0) {
            if ((n & 1) == 1) {   // n 的当前二进制位是 1 → 把当前 a 累乘进结果
                ret = multiply(ret, a);
            }
            n >>= 1;              // 指数折半
            a = multiply(a, a);   // 底数平方
        }
        return ret;
    }

    int climbStairs(int n) {
        vector<vector<long long>> ret = {{1, 1}, {1, 0}};
        vector<vector<long long>> res = matrixPow(ret, n);
        return res[0][0];        // M^n 的左上角元素即 dp[n]
    }
};
```

- **时间**：O(log n)——快速幂的矩阵乘法次数。
- **空间**：O(1)——只用几个 2×2 矩阵。
- **何时用**：n 极大（≥10^9）或题目明确要求亚线性时间；本题 n ≤ 45 用 DP 足够。

### 解法三：通项公式（官方方法三，O(log n) 取决于 pow 实现）

既然是斐波那契，可以直接套**通项公式**（Binet 公式）：

```
dp[n] = (1/√5) × [ ((1+√5)/2)^(n+1) - ((1-√5)/2)^(n+1) ]
```

```cpp
class Solution {
public:
    int climbStairs(int n) {
        double sqrt5 = sqrt(5);
        double fibn = pow((1 + sqrt5) / 2, n + 1) - pow((1 - sqrt5) / 2, n + 1);
        return (int)round(fibn / sqrt5);   // round 四舍五入抵消浮点误差
    }
};
```

- **时间**：O(log n)（`pow` 内部用快速幂）或 O(1)（视实现）。
- **空间**：O(1)。
- **缺点**：浮点运算有精度损失，n 很大时可能丢精度（本题 n ≤ 45 在 double 精度内安全）。工程上不如矩阵快速幂稳。
