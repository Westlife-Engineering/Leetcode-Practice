# 322 零钱兑换

- 难度：中等
- 标签：广度优先搜索、数组、**动态规划**
- 力扣链接：https://leetcode.cn/problems/coin-change/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[零钱兑换](https://leetcode.cn/problems/coin-change/solution/322-ling-qian-dui-huan-by-leetcode-solution/)」。正文主解是 **动态规划（完全背包求最少个数）**，O(amount×n) 时间 O(amount) 空间——和 **279 完全平方数** 是同一套模板的「双胞胎题」（279 的"硬币面额"就是平方数 1、4、9、16…）。官方的**记忆化搜索**（自顶向下 DP）放在「复盘」作对照。

## 题目描述

给你一个整数数组 `coins` ，表示不同面额的硬币；以及一个整数 `amount` ，表示总金额。

计算并返回可以凑成总金额所需的 **最少的硬币个数** 。如果没有任何一种硬币组合能组成总金额，返回 `-1` 。

你可以认为每种硬币的数量是无限的。

**示例 1：**

```
输入：coins = [1, 2, 5], amount = 11
输出：3
解释：11 = 5 + 5 + 1
```

**示例 2：**

```
输入：coins = [2], amount = 3
输出：-1
```

**示例 3：**

```
输入：coins = [1], amount = 0
输出：0
```

**提示：**

- `1 <= coins.length <= 12`
- `1 <= coins[i] <= 2^31 - 1`
- `0 <= amount <= 10^4`

## 思路

> 本题主要参考力扣官方题解「方法二：动态规划」。

题目三要素：①硬币**无限**用（不是 0-1 背包，是完全背包）；②求凑成 amount 的**最少个数**（不是方案数）；③凑不出要返回 `-1`（**带无解判定的最优化**，这是和 279 不同的地方）。

### DP 三要素（所有 DP 题的通用思考框架）

#### ① 状态定义：`dp[i]` = 凑成金额 `i` 所需的**最少硬币数**

把「凑金额 `i` 至少要几枚」这个子问题用一个数组描述出来。`dp[amount]` 就是答案。

> 为什么这么定义？因为「凑金额 `i`」是一个**结构相同的子问题**，原问题就是 `i = amount` 的特例。DP 的本质就是把大问题拆成同形的子问题。

#### ② 状态转移方程：`dp[i] = min(dp[i], dp[i - coin] + 1)`（核心！）

**盯着「最后一步」看**：凑出金额 `i` 的最后一枚硬币，**必然**是 `coins` 里的某一种。假设最后一枚是 `coin`，那么——

- 这枚 `coin` 之前的硬币，凑出的总金额是 `i - coin`；
- 这些之前的硬币，用的最少个数就是 `dp[i - coin]`；
- 再加最后这 1 枚 `coin`，总共 `dp[i - coin] + 1` 枚。

但「最后一枚」到底是哪一种硬币我们不知道，所以**枚举所有硬币**，取使总数最少的那个：

```
dp[i] = min { dp[i - coin] + 1 }    对所有满足 coin <= i 的硬币 coin
```

一句话总结：**「凑金额 i 的最少硬币数 = 凑金额 i-coin 的最少硬币数 + 1」**，对所有能放的硬币取最小。这是完全背包求最少的个数的标准套路。

#### ③ 初始条件：`dp[0] = 0`，其余填 `amount + 1`

- `dp[0] = 0`：金额为 0 不需要任何硬币（这个边界**必须手动给**，因为转移方程依赖 `dp[i-coin]`，当 `i == coin` 时就要查 `dp[0]`）。
- `dp[1..amount]` 初始化成什么？这是本题**最容易翻车的地方**，下面单独讲。

### 为什么初始化成 `amount + 1`，而不是 `INT_MAX`？

转移方程是 `dp[i] = min(dp[i], dp[i - coin] + 1)`。注意末尾那个 **`+ 1`**——

- 如果把 `dp[i-coin]` 初始化成 `INT_MAX`，再 `+ 1`，就会**整型溢出**（`INT_MAX + 1` 变成负数 `INT_MIN`），`min` 会取到这个错误的负值，结果完全错乱。
- 所以用一个**比任何合法解都大、但又不至于溢出**的"哨兵值"。`amount + 1` 正好满足：凑 `amount` 元最多也只可能用 `amount` 枚（全是 1 元硬币），所以**任何合法解都 `<= amount`**。把哨兵设成 `amount + 1` 就能保证：
  1. 比任何真正的答案都大，不会干扰 `min`；
  2. `+ 1` 后变成 `amount + 2`，远远到不了 `INT_MAX`，不会溢出。

> 这是 DP 求最值的常用技巧：**哨兵值 = 答案的理论上界 + 1**。本题答案上界是 `amount`（全用 1 元），所以哨兵 = `amount + 1`。类似的，279 完全平方数哨兵也是 `amount + 1`（用 n 个 1 凑 n，上界 n）。

### 怎么判无解返回 `-1`？

转移结束后，**如果 `dp[amount]` 还是哨兵值 `amount + 1`（即 `dp[amount] > amount`）**，说明从 `dp[0]` 出发、用所有硬币的组合都凑不到 `amount`，无解，返回 `-1`；否则 `dp[amount]` 就是答案。

> 示例 2 `coins = [2], amount = 3` 就是这种情况：`dp[1]`、`dp[3]` 都没法从 `dp[0]` 递到（因为 `coin=2 > 1`、`coin=2` 凑不出奇数 3），它们保留哨兵值 `4`，最后 `dp[3] = 4 > 3`，返回 `-1`。

### 手动推导 `coins = [1, 2, 5], amount = 11`

哨兵 `Max = amount + 1 = 12`，初始 `dp = [0, 12, 12, 12, 12, 12, 12, 12, 12, 12, 12, 12]`（下标 0~11）。

从 `i = 1` 开始递推，每个 `i` 枚举三种硬币 `1, 2, 5`，凡 `coin <= i` 就更新 `dp[i] = min(dp[i], dp[i-coin]+1)`：

```
i=1:  coin=1 → dp[1]=min(12, dp[0]+1=1)=1                 → dp=[0,1,12,12,...]
i=2:  coin=1 → dp[2]=min(12, dp[1]+1=2)=2
      coin=2 → dp[2]=min(2,  dp[0]+1=1)=1                 → dp=[0,1,1,12,...]
i=3:  coin=1 → dp[3]=min(12, dp[2]+1=2)=2
      coin=2 → dp[3]=min(2,  dp[1]+1=2)=2                 → dp=[0,1,1,2,12,...]
i=4:  coin=1 → 3; coin=2 → dp[2]+1=2                      → dp[4]=2
i=5:  coin=1 → 3; coin=2 → dp[3]+1=3; coin=5 → dp[0]+1=1  → dp[5]=1
i=6:  coin=1 → 2; coin=2 → dp[4]+1=3; coin=5 → dp[1]+1=2  → dp[6]=2
i=7:  coin=5 → dp[2]+1=2; coin=2 → dp[5]+1=2; coin=1 → 3  → dp[7]=2
i=8:  coin=5 → dp[3]+1=3; coin=2 → dp[6]+1=3; coin=1 → 3  → dp[8]=3
i=9:  coin=5 → dp[4]+1=3; coin=2 → dp[7]+1=3              → dp[9]=3
i=10: coin=5 → dp[5]+1=2; coin=2 → dp[8]+1=4              → dp[10]=2
i=11: coin=5 → dp[6]+1=3; coin=2 → dp[9]+1=4; coin=1 → 4  → dp[11]=3
```

最终 `dp[11] = 3`（`3 <= 11`，有效），返回 `3` ✓。对应组合 `5 + 5 + 1`（先拿一枚 5 凑到 `dp[6]`，再拿一枚 5 凑到 `dp[1]`，最后拿一枚 1 凑到 `dp[0]`）。

### 和 279 完全平方数的关系（**核心可迁移点**）

279 题面是「凑成 `n` 的最少平方数个数」，平方数就是 `1, 4, 9, 16, ...`。如果把它们看成**硬币面额**，279 就是 `coins = {1,4,9,16,...}, amount = n` 的零钱兑换——**同一个完全背包求最少个数问题**。两道题的转移方程一字不差：

```
279:  dp[i] = min(dp[i], dp[i - j*j] + 1)     枚举每个平方数 j*j
322:  dp[i] = min(dp[i], dp[i - coin] + 1)    枚举每个硬币 coin
```

会做其中一道，另一道就是改个枚举范围的事。

## 代码

```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        // ★ 哨兵值 Max = amount + 1：比任何合法解都大（凑 amount 最多用 amount 枚 1 元），
        //   既不干扰 min，又能在 +1 后远不到 INT_MAX，避免溢出。
        //   - 用 INT_MAX 当初始值的话，dp[i-coin]+1 会溢出成负数，min 取到错值，结果错乱。
        //   - 这是"答案上界 + 1"的通用哨兵技巧，279 完全平方数也是这么初始化的。
        int Max = amount + 1;

        // vector<int> dp(amount + 1, Max)：开 (amount+1) 个 int，每个都初始化为 Max。
        //   - vector 构造签名：vector(size_type count, const T& value)，把 count 个元素全填 value。
        //   - 下标范围 0..amount（含两端），dp[i] 表示凑金额 i 的最少硬币数。
        //   - 一开始全都填哨兵 Max = "暂时认为凑不出来"，后面用 min 慢慢往下更新。
        vector<int> dp(amount + 1, Max);

        // dp[0] = 0：金额为 0 不需要硬币。这个边界必须单独给定，
        //   因为转移方程 dp[i] = dp[i-coin] + 1 在 i == coin 时要查 dp[0]。
        dp[0] = 0;

        // 外层循环枚举金额 i：从 1 到 amount（含 amount）。
        //   - i=0 已经初始化为 0，不用算。
        //   - 这是"自底向上"的递推：先算小金额，再算大金额；大金额依赖小金额已算好。
        for (int i = 1; i <= amount; ++i) {

            // 内层循环枚举每一种硬币。
            //   - coins.size() 返回 size_t（无符号），和 int 比较前强制转 int 防符号警告。
            //   - 每种硬币都要试一遍，取让 dp[i] 最小的那个（完全背包：同一硬币可重复用）。
            for (int j = 0; j < (int)coins.size(); ++j) {

                // coins[j] <= i：硬币面额不能超过当前要凑的金额 i。
                //   - 若 coin > i，dp[i - coin] 会越界（下标为负），必须先判住。
                if (coins[j] <= i) {

                    // ★ 核心转移方程：dp[i] = min(dp[i], dp[i - coins[j]] + 1)
                    //   - dp[i - coins[j]]：先凑出金额 (i - coin) 所需的最少硬币数（已算好）。
                    //   - + 1：再加上当前这枚硬币 coins[j] 本身。
                    //   - min：在所有可选硬币里取最小值。
                    //   - min 是 STL 算法 <algorithm>，原型 min(const T& a, const T& b)，返回较小者，O(1)。
                    dp[i] = min(dp[i], dp[i - coins[j]] + 1);
                }
            }
        }

        // ★ 判无解：若 dp[amount] 仍是哨兵值（> amount），说明没法凑出 amount，返回 -1；
        //   否则 dp[amount] 就是答案。
        //   - 为什么用 > amount 判？因为哨兵 Max = amount + 1 > amount；而任何合法解都 <= amount。
        //   - 这样就把"哨兵值未被更新"等价于"无解"，统一在一次遍历里处理了。
        return dp[amount] > amount ? -1 : dp[amount];
    }
};
```

## 复杂度

- **时间**：O(amount × n)，其中 `n = coins.length`
  - 外层循环 amount 次，内层枚举 n 种硬币，每次 O(1) 的 `min` 比较。
- **空间**：O(amount)
  - 开了一个长度 `amount + 1` 的 `dp` 数组。注意它**压成了一维**（朴素完全背包是二维 `dp[i][j]`，这里只保留金额维度，硬币维度靠"内层枚举"隐式合并）。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么初始化成 `amount + 1`？用 `INT_MAX` 不是更"干净"吗？

`INT_MAX` 看着像"正无穷"，但本题转移是 `dp[i] = min(dp[i], dp[i-coin] + 1)`，末尾有 `+ 1`。如果 `dp[i-coin]` 是 `INT_MAX`，那 `INT_MAX + 1` 直接**溢出**成 `INT_MIN`（负数），`min` 会取到这个负数，整个 `dp` 表全乱套。

所以需要一个"比答案大、但 `+1` 不溢出"的值。凑 `amount` 元最多用 `amount` 枚（全是 1 元硬币），所以任何合法答案 `<= amount`，`amount + 1` 就是天然的哨兵：比答案大、且 `+1` 后 `amount + 2` 离 `INT_MAX` 远得很。

> 通用技巧：DP 求最小值时，哨兵值 = **答案理论上界 + 1**。本题上界 = amount（全用 1 元）；279 完全平方数上界 = n（全用 1）；0-1 背包求价值最大时则相反，哨兵初始化成 `-1` 或 `-∞`。

### Q2：为什么 `dp[0] = 0`？金额 0 也算"凑出来了"吗？

算。`dp[0] = 0` 的物理意义是：**凑金额 0 不需要任何硬币**（0 枚）。这既是转移方程的起点（当 `i == coin` 时 `dp[i-coin] = dp[0]`，代表"放一枚 coin 正好凑齐 i"），也对应示例 3 `amount = 0` 直接返回 0。

另外注意题目说 `amount >= 0`，所以代码里 `dp` 数组长度是 `amount + 1`（下标 0 到 amount），不会因为 `amount = 0` 而越界。

### Q3：怎么判无解返回 `-1`？为什么最后用 `dp[amount] > amount` 判？

判无解的精髓在**哨兵值是否被更新过**。初始化时所有 `dp[i]`（i>0）都是哨兵 `Max = amount + 1`。如果某个金额 `i` 凑不出来，那它在整个递推过程中**永远不会被 `min` 更新**（因为没有任何 `dp[i-coin]` 是可达的），最终保留哨兵值 `amount + 1`。

所以最后判断 `dp[amount] > amount`（等价于 `dp[amount] == amount + 1`）：
- 成立 → 说明 `dp[amount]` 没被更新过 → 凑不出 → 返回 `-1`；
- 不成立 → `dp[amount]` 是真答案 → 返回它。

用 `> amount` 而不是 `== amount + 1` 是更稳健的写法（即使哨兵值定义以后改了，只要保证比 amount 大，这个判断都对）。

### Q4：和 279 完全平方数到底有什么区别？

**几乎没区别，就是同一道题换了马甲**：

| 维度 | 322 零钱兑换 | 279 完全平方数 |
|---|---|---|
| "硬币"集合 | 题目给的 `coins` 数组 | 固定的平方数 `{1,4,9,16,...}`（上限 `⌊√n⌋²`） |
| amount | 参数 `amount` | 参数 `n` |
| 转移方程 | `dp[i] = min(dp[i], dp[i-coin]+1)` | `dp[i] = min(dp[i], dp[i-j*j]+1)` |
| 哨兵初始化 | `amount + 1` | `n + 1` |
| 无解情况 | 有（如 `coins=[2], amount=3`，返回 -1） | 几乎没有（1 永远是平方数，任何 n 都能用 n 个 1 凑出来） |

**唯一实质区别**：279 的"硬币集"里一定包含 1（`1=1²`），所以 279 永远有解、不需要判 `-1`；322 的硬币集是任意的，可能凑不出，所以要加无解判定。这就是为什么 322 用 `amount + 1` 当哨兵、最后还要 `return dp[amount] > amount ? -1 : dp[amount]`。

### Q5：外层循环和内层循环能不能换？（完全背包的"先物后容"vs"先容后物"）

能换。完全背包求**最少个数**时，两种循环顺序都对：

- **本题写法（先金额 i、后硬币 coin）**：外层 `for i`、内层 `for coin`——按金额从小到大填表。
- **另一种（先硬币 coin、后金额 i）**：外层 `for coin`、内层 `for i`——按硬币逐个"加入"。

两者结果相同，因为完全背包求最值**不关心组合方案数、不关心顺序**（不像"组合总和 IV"那种排列数题，排列/组合顺序敏感才要严格区分）。本题两种写法都 AC，官方采用的是第一种。

## 复盘

- **核心套路：「完全背包求最少个数」**。当题目要"用**可重复**的若干物品凑满某个容量、求**最少/最多**用了几个/价值多少"时，套这个模板：定义 `dp[i]` = 凑容量 `i` 的最优值，转移 `dp[i] = min/max(dp[i], dp[i - w] + v)`，枚举每个物品（可重复 → 内层正序扫）。322 和 279 是这个套路的**双胞胎样板题**，记住一个等于记住两个。
- **"答案上界 + 1" 当哨兵**：DP 求最值、且转移里有 `+1`/`+w` 这类运算时，**千万不要用 `INT_MAX`/`INT_MIN` 当初始值**（会溢出）。先用题目条件估算答案上界，取"上界 + 1"当哨兵，既不会干扰 `min/max`，又能安全做加减。本题上界 = `amount`（全用 1 元），哨兵 = `amount + 1`。
- **无解判定 = 哨兵是否被更新**：把"凑不出"编码成一个比任何合法解都大的哨兵值，最后用 `dp[amount] > amount` 一句话判定。这种"用哨兵兼并无解状态"的写法比"另开一个 `-1` 标记数组"简洁得多，是 DP 求最值处理无解的标准姿势。
- **"盯着最后一步"找转移**：和 70 爬楼梯（最后一步跨 1 还是跨 2 阶）一样，本题盯着"最后一枚硬币是哪种"，就能把大问题 `dp[i]` 拆成小问题 `dp[i-coin]`。**分析最后一步 → 归类子问题 → 取最值/求和**，是推导所有背包/DP 转移方程的通用招数。

### 解法二：记忆化搜索（官方方法一，自顶向下 DP）

迭代 DP 是"自底向上"（从 `dp[0]` 推到 `dp[amount]`）；也可以写成"自顶向下"的递归 + 记忆化：函数 `dp(rem)` 表示凑金额 `rem` 所需的最少硬币数，递归时枚举"最后一枚硬币"。

```cpp
class Solution {
    vector<int> count;   // 记忆化数组：count[rem-1] 缓存 dp(rem) 的结果，避免重复递归
    int dp(vector<int>& coins, int rem) {
        if (rem < 0) return -1;        // 金额变负 → 这条路凑不出
        if (rem == 0) return 0;        // 凑齐了 → 0 枚
        if (count[rem - 1] != 0) return count[rem - 1];  // 算过了直接查表（0 表示未算）
        int Min = INT_MAX;
        for (int coin : coins) {       // 枚举"最后一枚硬币"
            int res = dp(coins, rem - coin);
            if (res >= 0 && res < Min) {  // res>=0 表示这条路能凑成
                Min = res + 1;
            }
        }
        count[rem - 1] = Min == INT_MAX ? -1 : Min;  // 没凑出过 → 记 -1；否则记最小值
        return count[rem - 1];
    }
public:
    int coinChange(vector<int>& coins, int amount) {
        if (amount < 1) return 0;      // amount=0 直接返回 0（对应示例 3）
        count.resize(amount);          // 开 amount 个槽，下标 0..amount-1 对应 rem=1..amount
        return dp(coins, amount);
    }
};
```

- **时间**：O(amount × n)——每个子问题只算一次，共 amount 个子问题，每个枚举 n 种硬币。
- **空间**：O(amount)——记忆化数组 + 递归栈深度最深 amount。
- **和迭代 DP 的关系**：记忆化搜索是"自顶向下"的 DP（从 `amount` 往下递归到 0），迭代是"自底向上"（从 0 往上推到 `amount`）。**两者本质完全等价**，只是思考方向相反：迭代通常常数更小、没有递归栈溢出风险，是首选；记忆化搜索更接近自然语言的递归思路，适合"先想清楚递归关系再优化成迭代"的学习路径。
- **注意点**：记忆化这里用 `count[rem-1] != 0` 判"是否算过"，前提是合法解永远不会是 0（`rem > 0` 时至少 1 枚），所以用 0 当"未计算"标记是安全的；如果要缓存 `dp(0)` 就不能用 0 当标记了，得换成单独的 `vector<char> visited` 或填一个不可能的值。
