# 152 乘积最大子数组

- 难度：中等
- 标签：数组、**动态规划**
- 力扣链接：https://leetcode.cn/problems/maximum-product-subarray/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[乘积最大子数组](https://leetcode.cn/problems/maximum-product-subarray/solution/cheng-ji-zui-da-zi-shu-zu-by-leetcode-solution/)」（官方文章 slug：`cheng-ji-zui-da-zi-shu-zu-by-leetcode-solution`）。正文主解是 **动态规划（同时维护「以 nums[i] 结尾的最大积 maxF」和「最小积 minF」，滚动变量）**，O(n) 时间 O(1) 空间。本题正是 **53 最大子数组和的「积」版本**——但乘积比求和麻烦一个量级，核心难点是「**负负得正会让最小积翻成最大积**」，所以必须同时维护两个值，不能像 53 题只维护一个。

## 题目描述

给你一个整数数组 `nums` ，请你找出数组中乘积最大的非空连续 **子数组**（该子数组中至少包含一个数字），并返回该子数组所对应的乘积。

测试用例的答案是一个 **32 位** 整数。

**请注意**，一个只包含一个元素的数组的乘积是这个元素的值。

**示例 1：**

```
输入: nums = [2,3,-2,4]
输出: 6
解释: 子数组 [2,3] 有最大乘积 6。
```

**示例 2：**

```
输入: nums = [-2,0,-1]
输出: 0
解释: 结果不能为 2, 因为 [-2,-1] 不是子数组。
```

**提示：**

- `1 <= nums.length <= 2 * 10^4`
- `-10 <= nums[i] <= 10`
- `nums` 的任何子数组的乘积都 **保证** 是一个 32 位整数

> 两个关键约束：①「**子数组**」必须**连续**（示例 2 里 `[-2,-1]` 中间隔了 0，不算）；②「**非空**」，至少含一个元素，所以全负数时答案也得选一个元素、不能是空积 1。

## 思路

> 本题主要参考力扣官方题解「方法一：动态规划」，并结合力扣「编辑精选」题解里**遇负数交换 maxF/minF**的等价写法（代码更短、转移方程更接近 53 题的形态，便于对比记忆）。

### 和 53 题放在一起想：为什么「积」比「和」难

53 题「最大子数组和」的状态是 `f(i) = max(f(i-1)+nums[i], nums[i])`——「前面的累积和是正贡献就接上，否则从自己重开」。一个非常自然的想法是：把 `+` 换成 `×`，写出 `f_max(i) = max(f_max(i-1) × nums[i], nums[i])`，是不是就完事了？

**不行。** 问题出在「负数」上：

- **求和**的世界里，负数只会让和变小。`f(i-1)` 是负的 → 加上 `nums[i]` 一定小于 `nums[i]` → 直接丢掉前面那段。所以维护「最大和」一个值就够。
- **乘积**的世界里，负数会把局面**翻转**——一个很小的负数（比如 `-30`），再乘一个负数（比如 `-4`），会变成 `+120`，瞬间变成最大值！

官方给的反例 `nums = [5, 6, -3, 4, -3]`：如果只维护 `f_max`，得到 `{5, 30, -3, 4, -3}`，最大值是 `30`（前两个数）；但**真正的答案是把整个数组乘起来** `5×6×(-3)×4×(-3) = 1080`。原因就是最后那个 `-3` 本该接在 `5×6×(-3)×4 = -360`（一个很大的负数）后面翻成 `1080`，可 `-360` 被「只维护最大值」的转移方程丢掉了，永远找不回来。

**结论：当前位置的最优解未必从前一个位置的最优解转移而来，它可能来自「前一个位置的最差解（最负的积）」。所以必须同时维护最大积和最小积两个值。**

### 核心定义：maxF 和 minF 各代表什么

- `maxF`：**以当前元素结尾**的「乘积最大子数组」的乘积；
- `minF`：**以当前元素结尾**的「乘积最小子数组」的乘积（也就是**最负**的那个积）。

为什么要带着 `minF` 一起走？因为它随时可能**反杀**——下一轮如果遇到负数，`minF × nums[i]` 就会变成正数、冲上来当最大值。`minF` 就是埋在身边的「潜力股」，丢不得。

### 转移方程：三个候选取最值

对 `nums[i]` 来说，`maxF` 的新值有三个候选：

1. **`nums[i]` 自己单开一段**：之前的积太差（比如负的、或 0），不如从自己重开；
2. **`maxF × nums[i]`**：接在前面的最大积后面（`nums[i]` 为正时通常走这条）；
3. **`minF × nums[i]`**：接在前面的**最小积**后面（`nums[i]` 为负、`minF` 也为负时，负负得正翻成最大）。

```
new_maxF = max( nums[i], maxF × nums[i], minF × nums[i] )
new_minF = min( nums[i], maxF × nums[i], minF × nums[i] )   ← 对称地维护最小
```

`minF` 同理，把 `max` 换成 `min`、三候选相同。**注意必须先用临时变量算出 `new_maxF`、`new_minF` 再同时赋值**——否则先更新 `maxF` 就会把 `minF` 算错（它要用到旧的 `maxF`）。

### 等价技巧：遇到负数先 swap(maxF, minF)

上面「三候选取最值」等价于一个更短的写法——**遇到负数时，先把 maxF 和 minF 交换，再做和 53 题一模样的两候选转移**：

```
若 nums[i] < 0:  swap(maxF, minF)        // 负数会让大变小、小变大，先交换等价于「预判翻转」
maxF = max(nums[i], maxF × nums[i])      // 和 53 题 f(i)=max(f(i-1)+x, x) 形式完全一致
minF = min(nums[i], minF × nums[i])
ans  = max(ans, maxF)
```

为什么 swap 等价？因为 `nums[i] < 0` 时，`maxF × nums[i]` 反而比 `minF × nums[i]` 小。先交换 maxF 和 minF，就让「乘完会变大的那个」坐到了 maxF 的位置上，于是两候选 `max(nums[i], maxF × nums[i])` 自动取到了正确的较大值。**这版的代码最短、也最像 53 题，推荐记这版。**（官方代码用的是不交换的「三候选」版，复盘里贴出对照。）

### 手动推导两个关键用例

**用例 1：`nums = [2,3,-2,4]`，答案 6**（swap 版，每行是「处理完 nums[i] 后」的 maxF/minF/ans）：

```
i=0  nums[0]= 2  初始: maxF= 2, minF= 2, ans= 2
i=1  nums[1]= 3  正数不交换
                   maxF = max(3, 2×3)  = 6
                   minF = min(3, 2×3)  = 3
                   ans  = max(2, 6) = 6
i=2  nums[2]=-2  负数！先 swap(maxF,minF) → maxF=3, minF=6
                   maxF = max(-2, 3×-2) = -2
                   minF = min(-2, 6×-2) = -12   ← 埋下潜力股 -12
                   ans  = max(6, -2)= 6
i=3  nums[3]= 4  正数不交换
                   maxF = max(4, -2×4) = 4
                   minF = min(4, -12×4)= -48
                   ans  = max(6, 4) = 6
返回 6 ✓   （子数组 [2,3]）
```

**用例 2（验证「负负得正」）：`nums = [-2,3,-4]`，答案 24**

如果只维护一个 maxF（像 53 题那样），会算出：

```
朴素(错误): f_max(0)=-2 → f_max(1)=max(3, -2×3)=3 → f_max(2)=max(-4, 3×-4)=-4 → 返回 3 ❌
```

同时维护 minF 才对：

```
i=0  -2   maxF=-2,  minF=-2,  ans=-2
i=1   3   maxF=max(3,-2×3)=3,     minF=min(3,-2×3)=-6,   ans=3
i=2  -4   负数！swap → maxF=-6, minF=3
            maxF=max(-4,-6×-4)=24   ← minF=-6 翻成 24！
            minF=min(-4, 3×-4)=-12
            ans=max(3,24)=24
返回 24 ✓   （整个数组 [-2,3,-4]）
```

这就是「为什么必须同时维护 minF」的最直观例子。

## 代码

```cpp
class Solution {
public:
    int maxProduct(vector<int>& nums) {
        // 同时维护「以 nums[i] 结尾」的最大积 maxF 和最小积 minF。
        //   - maxF：以当前元素结尾的、乘积最大的连续子数组的积；
        //   - minF：以当前元素结尾的、乘积最小的连续子数组的积（最负的那个，潜力股）。
        //   - 为什么维护两个值？乘积和求和不同：负负得正会让「最小的负积」乘个负数后翻成「最大的正积」，
        //     所以光记 maxF 不够，minF 随时可能反杀成答案，必须一起带在身边。
        //   - 三者都初始化成 nums[0]：因为「子数组至少含一个元素」，i=0 时 maxF=minF=ans=nums[0]
        //     （不能给 0 或 1，全负数组会算错；也不能给 INT_MIN，否则后续 max/min 比较出错）。
        int maxF = nums[0], minF = nums[0], ans = nums[0];
        int n = nums.size();

        // i 从 1 开始（i=0 已作为初值），逐个元素向右推进。
        for (int i = 1; i < n; i++) {
            // ★ 遇到负数先交换 maxF 和 minF——这是本解法最关键的一行。
            //   原理：nums[i] < 0 时，乘法会让「大变小、小变大」。
            //   原本 maxF > minF，乘完负数后 maxF×nums[i] < minF×nums[i]，大小关系翻转。
            //   于是干脆先把两者交换，让「乘完会变大的」坐到 maxF 的位置上、
            //   「乘完会变小的」坐到 minF 的位置上，之后就能用和 53 题「最大子数组和」一模一样的
            //   两候选转移（max(nums[i], maxF×nums[i])）直接出结果，无需写「三候选取最值」。
            //   对正数和 0 不做交换（正数不改变大小关系，0 的积恒为 0 交换也无妨）。
            if (nums[i] < 0) {
                swap(maxF, minF);   // swap：C++ STL，交换两个同类型变量值，int 是 O(1) 三次赋值
            }

            // 转移：和 53 题 f(i)=max(f(i-1)+x, x) 形式完全一致，只是 + 换成 ×。
            //   max(a, b)：<algorithm> 函数，返回较大者，O(1)。
            //   决策含义：nums[i] 要么接在「以 nums[i-1] 结尾的最大积」后面（maxF × nums[i]），
            //             要么自己另起一段（nums[i]），取大者。
            maxF = max(nums[i], maxF * nums[i]);

            // 对称地维护最小积 minF（取小）。和上面用同一个（已 swap 过的）maxF/minF，
            //   所以 maxF 和 minF 的更新顺序无所谓——它们彼此不再互相依赖（swap 已完成）。
            minF = min(nums[i], minF * nums[i]);

            // 用当前 maxF 更新全局答案。
            ans = max(ans, maxF);
        }
        return ans;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 只遍历一遍数组，每个元素做常数次 `max` / `min` / `swap`（都是 O(1)），共 O(n)。
- **空间**：O(1)
  - 只用了 `maxF`、`minF`、`ans`、`n`、`i` 几个变量，没有开额外数组。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么不能像 53 题那样只维护一个最大值？

因为「**乘积里负数会让最小变最大**」，破坏了「最优子结构」。

53 题求和时，负数只会拖后腿（让和变小），所以「前一个位置的最大和」始终是往后接的唯一最优候选，维护一个 `f_max` 就够。

乘积不同：一个很大的负数（比如 `-360`）再乘一个负数（比如 `-3`）会变成 `+1080`——也就是说，**当前位置的最大值，可能要从「前一个位置的最小值（最负的积）」转移过来**。如果只记 `f_max`，那个关键的负积就被丢掉了，永远找不回 `1080`。

所以必须同时维护 `maxF`（最大积，候选答案）和 `minF`（最小积，埋伏的潜力股），两者一起滚动。这是乘积版 DP 和求和版 DP 的本质差异。

### Q2：遇到负数时为什么 swap(maxF, minF) 就够了？

因为 `nums[i] < 0` 时，**乘法会把大小关系翻转**：原本 `maxF > minF`，乘完负数后变成 `maxF × nums[i] < minF × nums[i]`。

「三候选取最值」的原始转移是：

```
new_maxF = max( nums[i], maxF × nums[i], minF × nums[i] )
```

当 `nums[i] < 0` 时，`minF × nums[i] > maxF × nums[i]`，所以上面那个 `max` 里真正能赢的是 `minF × nums[i]`（而不是 `maxF × nums[i]`）。那干脆**先把 maxF 和 minF 交换**，让新的 `maxF` 指向「乘完会变大的」那个，于是两候选 `max(nums[i], maxF × nums[i])` 就自动取到了正确的较大值。

等价性可严格证明：swap 版和不 swap 的「三候选版」在每一步产出的 `maxF`、`minF` 完全相同。swap 版的好处是代码短、转移方程和 53 题长得一样（只把 `+` 换 `×`），好记。

### Q3：maxF 和 minF 各自到底代表什么？minF 是答案吗？

不是。**只有 `maxF` 用来更新答案 `ans`**，`minF` 不直接进答案，它是个「辅助状态」：

- `maxF`：以 `nums[i]` 结尾的、**乘积最大**的连续子数组的积——这是 `ans` 的候选来源。
- `minF`：以 `nums[i]` 结尾的、**乘积最小**的连续子数组的积（通常是最负的那个值，比如 `-12`、`-48`）——它存在的唯一目的是：**万一下一个元素是负数，`minF × 负数` 会翻成正数冲上来**，所以得一直带着它。

可以理解为：`maxF` 是「台面上的最优」，`minF` 是「台面下的潜力股」，遇到负数时两者互换角色。

### Q4：能不能用滑动窗口做？

不能，和 53 题一样的道理。滑动窗口依赖「窗口扩大 / 收缩时目标值单调变化」的性质，而乘积既会因乘正数变大、也会因乘负数反向，**完全没有单调性**，无法用双指针左右伸缩。

更麻烦的是数组里可能有 `0`：一旦乘到 0，积直接归零，窗口该怎么缩都不对。所以本题的正解是 DP（同时维护 max/min），不是滑动窗口。

### Q5：为什么更新 maxF 和 minF 时不用临时变量备份？

注意代码里**先 `if (nums[i] < 0) swap(maxF, minF);`**，swap 之后再分别写 `maxF = max(...)` 和 `minF = min(...)`。这两行的右值里 `maxF * nums[i]` 和 `minF * nums[i]` 用的都是 **swap 之后**的值，而且 `maxF` 的更新只读 `maxF` 自己、`minF` 的更新只读 `minF` 自己——两者不再互相依赖。所以写顺序无所谓，也不需要 `mx = maxF, mn = minF` 这种备份。

对比官方代码（复盘里贴出）用的是「三候选」版，那种写法**同一行里既要用旧 maxF 又要用旧 minF**，所以必须先备份成 `mx`、`mn` 再同时赋值。swap 版把这个依赖提前消掉了，更简洁。

## 复盘

- **核心套路**：「**乘积最值的连续子段**」→ 想到 **同时维护 maxF 和 minF 的 DP**。和 53 题「最大子数组和」是姊妹题，状态都定义为「以 `i` 结尾」，转移都是「接前面 / 自己重开」两候选取最值；唯一的、致命的差异是乘积要**多带一个 minF**。
- **可迁移大套路——「DP 遇到可能翻转符号的运算（×、异或）时要同时维护最大和最小」**：只要运算结果会因某个因素（负数、位运算）让「最优」和「最差」互换角色，就不能只记一个最值。**记 max 也要记 min** 是这类题的总诀。类似可迁移到「带符号的最大子数组积」「区间乘积」等变形。
- **swap 技巧**：遇到负数先 `swap(maxF, minF)`，等价于「三候选取最值」但代码更短、转移方程和求和版长得一样。这种「**通过交换把分类讨论藏进对称性**」的写法在 DP 里很常见（比如某些博弈 DP、min-max DP）。
- **初始化陷阱**（和 53 题一致）：`maxF / minF / ans` 都必须用 `nums[0]` 初始化，**不能给 0 或 1**。因为「子数组至少含一个元素」，全负数组（如 `[-2]`）的答案就是那个负数本身；若初值给 0，会被错误地当成更大值返回。

### 53 题 vs 152 题：和与积的对比表

| 维度 | 53 最大子数组和 | 152 乘积最大子数组 |
|---|---|---|
| 状态定义 | `f(i)` = 以 `i` 结尾的最大和 | `maxF / minF` = 以 `i` 结尾的最大积 / 最小积 |
| 维护几个值 | **1 个**（`f_max`） | **2 个**（`maxF` 和 `minF`） |
| 转移方程 | `f(i) = max(f(i-1)+nums[i], nums[i])` | swap 后 `maxF=max(nums[i], maxF×nums[i])`，minF 对称 |
| 负数的作用 | 让和变小，可丢掉 | 负负得正，让最小变最大，**不能丢** |
| 是否满足最优子结构 | 满足 | 不满足（需带 minF 才补全） |
| 时间 / 空间 | O(n) / O(1) | O(n) / O(1) |
| 能否滑动窗口 | 不能（有负数不单调） | 不能（同上，且 0 会断链） |

### 解法二：官方「三候选」版（对照用）

官方正文给的是不交换的写法——直接把「`nums[i]`、`maxF × nums[i]`、`minF × nums[i]`」三个候选塞进 `max()` / `min()`。因为同一轮里 `maxF` 和 `minF` 互相依赖，所以必须先用 `mx`、`mn` 备份旧值，再同时赋值。两种写法**完全等价**，swap 版是它的简化。

```cpp
class Solution {
public:
    int maxProduct(vector<int>& nums) {
        // 官方「三候选」版：不 swap，而是把 maxF×nums[i]、minF×nums[i]、nums[i] 三者一起比。
        // 注意：maxF 和 minF 的更新都用到「旧」的对方值，所以必须先备份成 mx、mn。
        long maxF = nums[0], minF = nums[0], ans = nums[0];
        for (int i = 1; i < nums.size(); ++i) {
            long mx = maxF, mn = minF;                 // 备份上一轮的 maxF / minF
            maxF = max(mx * nums[i], max((long)nums[i], mn * nums[i]));  // 三候选取大
            minF = min(mn * nums[i], min((long)nums[i], mx * nums[i]));  // 三候选取小
            ans = max(maxF, ans);
        }
        return ans;
    }
};
```

- **时间**：O(n)，**空间**：O(1)，与 swap 版一致。
- **用 `long` 的原因**：官方代码用 `long` 防「中间乘积」在极端用例下溢出 32 位（题目只保证**最终子数组乘积**是 32 位整数，不保证中间 `maxF × nums[i]` 这种过渡值不溢出）。swap 版里若担心同样问题，也可把 `maxF / minF` 声明成 `long`，最后返回前再转回 `int`（本题力扣数据下 `int` 版能过，但 `long` 更稳）。
- **何时用哪个**：理解原理看「三候选版」更直接（一眼看到 minF 在 max 里发挥作用）；日常手写记 swap 版更快、更不容易写错。
