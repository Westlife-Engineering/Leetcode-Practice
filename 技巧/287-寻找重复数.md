# 287 寻找重复数

- 难度：中等
- 标签：位运算、数组、**双指针**、二分查找
- 力扣链接：https://leetcode.cn/problems/find-the-duplicate-number/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「寻找重复数」（slug：`xun-zhao-zhong-fu-shu-by-leetcode-solution`，方法三）。正文主解是 **快慢指针把数组看成链表找环**，和 **142 环形链表 II** 完全同一套思路（本题链表的 `next` 指针就是隐式的 `nums[i]`）——O(n) 时间 O(1) 空间，且**不修改原数组**，正好满足题目三大约束。官方另两种解法（二分查找、按位统计）放在「复盘」对比。

## 题目描述

给定一个包含 `n + 1` 个整数的数组 `nums` ，其数字都在 `[1, n]` 范围内（包括 `1` 和 `n`），可知至少存在一个重复的整数。

假设 `nums` 只有 **一个重复的整数** ，返回 这个重复的数 。

你设计的解决方案必须 **不修改** 数组 `nums` 且只用 **常量级 O(1) 的额外空间**。

**示例 1：**

```
输入：nums = [1,3,4,2,2]
输出：2
```

**示例 2：**

```
输入：nums = [3,1,3,4,2]
输出：3
```

**示例 3 :**

```
输入：nums = [3,3,3,3,3]
输出：3
```

**提示：**

- `1 <= n <= 10^5`
- `nums.length == n + 1`
- `1 <= nums[i] <= n`
- `nums` 中 **只有一个整数** 出现 **两次或多次** ，其余整数均只出现 **一次**

**进阶：**

- 如何证明 `nums` 中至少存在一个重复的数字?
- 你可以设计一个线性级时间复杂度 `O(n)` 的解决方案吗？

## 思路

> 本题主要参考力扣官方题解的「方法三：快慢指针」。

题面看着像「找重复数」，但卡得很死：**不修改数组、只用 O(1) 额外空间、O(n) 时间**。三条加在一起，把哈希表（要 O(n) 空间）、排序（要修改数组）两条最朴素的路全堵死了。正解的关键是**把数组「换个视角」看成链表**，于是问题瞬间变成 142 题环形链表 II。

### 核心技巧：为什么能把数组看成链表？

这是整道题最巧妙的一步。观察题目的两个条件：

1. **下标范围** `0 ~ n`（数组长度 `n+1`）；
2. **值的范围** `1 ~ n`（每个 `nums[i]` 都在 `1 ~ n` 内）。

把每个下标 `i` 看成一个**节点**，把 `nums[i]` 看成 `i` 的**后继指针**（`next`），也就是「从节点 `i` 走一步会到节点 `nums[i]`」。这样整个数组就成了一张有向图，每个节点**出度恰好为 1**（有且只有一个后继）。

> 注意 `nums[i]` 的值域是 `1 ~ n`，所以 `nums[i]` 永远**不可能是 0**。这意味着下标 `0` 这个节点**入度必定为 0**（没有任何 `nums[j]` 等于 0 来指向它），它就是这条隐式链表的**起点**。这也是为什么后面代码里快慢指针都从 `0` 出发。

### 为什么重复数对应「环的入口」？

这是整道题的灵魂。设重复的数是 `target`。

- **如果没有重复**：`n+1` 个位置装 `1 ~ n` 这 `n` 个互不相同的值，由鸽巢原理这不可能——所以**一定有重复**（这也顺带回答了进阶第一问）。
- **如果有重复**：`target` 这个值在数组里至少出现**两次**，也就是说**至少有两个不同的下标 `i`、`j` 满足 `nums[i] = nums[j] = target`**。在「下标即节点、`nums[i]` 即后继」的映射下，这意味着**节点 `target` 有至少两条入边**（分别来自 `i` 和 `j`），换句话说，从 `i` 和 `j` 出发都会**走到同一个节点 `target`**。
- 由于「每个节点出度恰好为 1」，这张图一定是「**一棵树 + 把树根接到树里某个节点上形成的环**」（俗称「基环树」，functional graph）。两个入边的那个节点 `target`，就是**从起点 0 出发走进环时碰到的第一个环上节点**——即**环的入口**。

一句话：**重复的数 = 链表中环的入口节点**。

### 为什么用 142 题的方法能找到环入口？

这正是本题和 **142 环形链表 II** 完全同构的地方：一旦建立了「数组 = 隐式链表」「重复数 = 环入口」的对应，剩下的就是 142 题原封不动的那套——**快慢指针两阶段找环入口**：

- **阶段一（找相遇点）**：`slow` 每次走 1 步（`slow = nums[slow]`），`fast` 每次走 2 步（`fast = nums[nums[fast]]`），在环内某点相遇；
- **阶段二（找入口）**：把 `slow` 挪回起点 `0`，然后 `slow`、`fast` **同速**（都走 1 步）前进，**再次相遇的位置就是环入口**，即重复数。

阶段二的数学推导（为什么同速走就一定在入口相遇）在 142 笔记里已详细写过，结论是 `a = c + (n−1)·环长`（`a` 是起点到入口距离、`c` 是相遇点到入口距离），此处不再重复。**本题只是把 142 的 `slow->next` 换成了 `nums[slow]`**，链表是「隐式」的，没有显式的 `ListNode`。

### 手动推导 `nums = [1,3,4,2,2]`

先把数组映射成链表（下标 `i` → 节点 `nums[i]`）：

```
下标:  0  1  2  3  4
nums: [1, 3, 4, 2, 2]

i → nums[i] 的映射：
0 → 1
1 → 3
2 → 4
3 → 2
4 → 2   ← 注意：下标 3 和下标 4 都指向 2，所以 2 是入环点（有两个入边）

从起点 0 出发的链表：
0 → 1 → 3 → 2 → 4 → 2 → 4 → 2 → ...   （到 2 之后在 2↔4 之间转圈）
            ↑___________|
                 环：2 → 4 → 2（环入口 = 节点 2 = 重复数）
```

走快慢指针：

```
slow = 0, fast = 0

阶段一（找相遇点）：
  第1轮  slow = nums[0] = 1;        fast = nums[nums[0]] = nums[1] = 3
  第2轮  slow = nums[1] = 3;        fast = nums[nums[3]] = nums[2] = 4
  第3轮  slow = nums[3] = 2;        fast = nums[nums[4]] = nums[2] = 4
  第4轮  slow = nums[2] = 4;        fast = nums[nums[4]] = nums[2] = 4
  slow == fast == 4，相遇！相遇点 = 节点 4

阶段二（找入口）：
  slow = 0（挪回起点）; fast 仍 = 4（留在相遇点）
  第1轮  slow = nums[0] = 1;  fast = nums[4] = 2
  第2轮  slow = nums[1] = 3;  fast = nums[2] = 4
  第3轮  slow = nums[3] = 2;  fast = nums[4] = 2
  slow == fast == 2，再次相遇，返回 2 ✓
```

返回 `2`，正是重复数。

## 代码

```cpp
class Solution {
public:
    int findDuplicate(vector<int>& nums) {
        // ============ 隐式链表说明 ============
        // 本题最巧妙的视角转换：把 nums 看成一张「下标 i 指向 nums[i]」的有向图。
        //   - 每个下标 i 当作一个节点，nums[i] 当作 i 的「后继」（相当于链表的 next 指针）。
        //   - 因为题目保证 1 <= nums[i] <= n（n = nums.size() - 1），nums[i] 永远不为 0，
        //     所以下标 0 没有任何节点指向它 → 入度为 0 → 它就是这条隐式链表的「起点」。
        //   - 重复数 target 在数组里出现 ≥2 次，意味着有 ≥2 个下标都指向 target，
        //     也就是节点 target 有 ≥2 条入边 → 它就是链表环的入口。
        //   - 于是「找重复数」转化为「142 环形链表 II 找入环点」，下面这套路子完全照搬 142。

        // slow / fast：快慢两个「游标」，存的是【下标】，不是值。
        //   - 都从 0 出发（0 是隐式链表的唯一起点，入度为 0）。
        //   - 「走一步」= nums[x]，即从下标 x 跳到下标 nums[x]。
        //   - 注意这里的写法和 142 不同：142 里是 slow = slow->next（显式指针），
        //     这里是 slow = nums[slow]（用数组下标模拟指针跳转），但本质完全一样。
        int slow = nums[0], fast = nums[0];

        // ============ 阶段一：快慢指针找相遇点（和 142 阶段一一致）============
        // 慢指针每次走 1 步，快指针每次走 2 步；若有环，必在环内某点相遇。
        //   - do...while：保证至少跑一轮（初始 slow == fast 时也要先进循环）。
        //   - slow = nums[slow]：慢指针走 1 步（从下标 slow 跳到 nums[slow]）。
        //   - fast = nums[nums[fast]]：快指针走 2 步。
        //       先 nums[fast] 走第 1 步得到一个新下标，再 nums[...] 走第 2 步。
        //       两层嵌套很自然地表达了「连续走两步」。
        //   - 安全性：题目保证 nums[i] ∈ [1,n]，永远不会越界；并且由于一定有重复、一定有环，
        //     循环一定会在相遇时终止，不存在无限循环或走到 nullptr 的情形（不存在「无环」case）。
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);
        // 跳出时 slow == fast，这个点就是「相遇点」（环内某处，未必是入口）。

        // ============ 阶段二：一个回起点，两同速走找入口（142 阶段二一致）============
        // 数学结论：起点到入口的距离 a = 相遇点到入口的距离 c + (n-1)·环长（n 为快指针多绕的圈数）。
        //   - 于是把一个游标放回起点 0、另一个留在相遇点，两个都「每次走 1 步」同速前进，
        //     它们一定会在【环的入口】首次相遇（相遇点那个游标可能多绕了几整圈，但绕整圈不改变落点）。
        //   - 「放回起点」这一步把 slow 重置为 0（隐式链表的起点），fast 保持在相遇点。
        slow = nums[0];
        // while (slow != fast)：两个游标都走 1 步，直到相遇。
        //   - slow = nums[slow]：从起点方向往前 1 步。
        //   - fast = nums[fast]：从相遇点方向往前 1 步（可能在环里绕圈，但最终落在入口）。
        //   - 跳出循环时 slow == fast，落在【环入口】= 重复数。
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }
        return slow;
    }
};
```

## 复杂度

- **时间**：O(n)，其中 `n = nums.size() - 1`。
  - 阶段一找相遇点：`slow` 一旦进环，到被 `fast` 追上走过的环内距离不超过 2 圈（相对速度 1 格/轮），整体步数 O(n)。
  - 阶段二找入口：`slow` 从起点 0 出发，最多走到入口，距离 ≤ n。
  - 两阶段合计 O(n)，满足进阶「线性时间」要求。
- **空间**：O(1)
  - 只用了 `slow` / `fast` 两个下标变量，没有哈希表、没有新数组、也没修改 `nums`。**同时满足题目「不修改数组」「O(1) 额外空间」两条硬约束**。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么「把数组看成链表」这种视角转换成立？依据是什么？

依据是题目两个**互相耦合**的约束：

1. 下标范围是 `0 ~ n`（共 `n+1` 个位置）；
2. 每个值 `nums[i]` 落在 `1 ~ n` 内。

第 2 条保证了「`nums[i]` 当作下一个下标」**永远合法、不会越界**（值域和下标域几乎重合，只差一个 0）。于是「下标 i 跳到 nums[i]」可以无限进行下去，这就是一个隐式链表。同时由于 `nums[i]` 不可能等于 0，**没有任何节点会指向下标 0**，所以 0 是确定的起点（入度为 0）。

换句话说，**「值域 = 下标域」是把数组当链表用的总开关**。同类题（41 缺失的第一个正数、442 数组中重复的数据）也都是利用这一性质，把「数组」当「原地哈希 / 隐式链表」用——这是数组题里非常核心的一条套路（见复盘）。

### Q2：为什么重复数一定是「环的入口」，而不是环上别的点？

这是本题最容易绕晕的地方。关键在于**入度**。

- 每个节点的**出度恰好是 1**（每个下标 `i` 都有唯一的 `nums[i]` 作为后继）。
- **不重复的值** `v` 在数组里只出现一次，意味着只有一个下标 `i` 满足 `nums[i] = v` → 节点 `v` 的**入度 = 1**。
- **重复的值** `target` 在数组里出现 ≥2 次，意味着 ≥2 个下标都满足 `nums[?] = target` → 节点 `target` 的**入度 ≥ 2**。

在「每个节点出度为 1」的图里，整张图必然是「**基环树**」（一棵或多棵树，每棵树的根接到自己内部的某个节点上形成环）。从起点 0（入度为 0）出发往前走，**第一次「撞进环」的那个节点，正是入度 ≥ 2 的那个节点**——因为它除了「树干」上那条入边之外，还有「环回边」这条额外的入边。而整张图里入度 ≥ 2 的节点**只有一个**（就是 `target`，题目说只有一个重复整数），所以**环的入口 = 重复数**，一一对应。

> 补充：如果有多个不同的重复数（本题不会出现），就会有多个入度 ≥2 的节点、多个环，情况会复杂；但本题保证「只有一个整数重复」，所以环入口唯一对应重复数。

### Q3：快慢指针为什么一定会相遇？会不会永远在环里错开？

一定会相遇，而且「快指针走 2 步、慢指针走 1 步」这个配比是关键。

- 慢指针进环后，快指针也一定在环里。
- 每走一轮，快指针前进 2 格、慢指针前进 1 格 → **快指针相对慢指针每轮多走 1 格**（相对速度恒为 1 格/轮）。
- 环上两点最大距离是「环长」一圈，所以快指针以相对速度 1 去追，最多再追 `环长` 格就一定能追上，不会永远错开。

这里**相对速度必须是 1**（也就是 gcd(快步数, 慢步数) = 1，2 和 1 互质）。如果改成快指针走 3 步、慢指针走 1 步（相对速度 2），在某些**偶数环长**的情况下可能永远错开（这是 141 环形链表里的经典坑）。所以「2 步 vs 1 步」不是随便选的，是为了保证一定相遇。

### Q4：这题和 142 环形链表 II 到底什么关系？几乎一模一样吗？

**本质一模一样，只是「链表」从显式变成了隐式。** 对应关系：

| 142 环形链表 II | 287 寻找重复数 |
|---|---|
| 显式 `ListNode`，`head` 是链表头 | 隐式链表，下标 `0` 是起点（`head`） |
| `slow = slow->next` | `slow = nums[slow]` |
| `fast = fast->next->next` | `fast = nums[nums[fast]]` |
| 入环点 = 第一个重复访问的节点 | 环入口 = 重复数 |
| 可能无环（返回 `nullptr`） | **一定有环**（鸽巢原理保证一定有重复） |

两段代码骨架完全一致：阶段一 `do/while` 找相遇点、阶段二 `slow` 回起点后两同速走找入口。区别只有两点：① 287 用 `nums[x]` 代替 `x->next`；② 287 不需要判「无环」（题目保证有重复），所以 142 里那套 `fast->next == nullptr` 的越界检查可以省掉，代码更短。**复习时强烈建议把 142 和 287 对照着看**，两题互相印证，对「快慢指针找环入口」这一套的理解会很扎实。

## 复盘

- **核心可迁移套路：把数组下标 + 值看成「隐式链表 / 图」**。当题目同时满足「下标域」和「值域」高度重合（值都在 `[0, n]` 或 `[1, n]` 内、且能当下标用）时，就要立刻想到这条思路——**别再死磕「扫数组 + 哈希」**。常见变体：
  - **287 寻找重复数**：`i → nums[i]` 当链表，重复数 = 环入口（Floyd 快慢指针）。
  - **442 数组中重复的数据**：值域 `[1,n]` → 把 `nums[i]` 当下标去给对应位置打标记（原地哈希，负号标记法）。
  - **41 缺失的第一个正数**：值域理想是 `[1,n]` → 把每个值「归位」到下标 `v-1`（原地哈希，标号归位法）。
  - 这三道是「数组 + 值域当下标」一组的姊妹题，**强推对照复习**。核心心智模型就一句：**值 = 下标 = 指针**。
- **「快慢指针找环入口」是 141 / 142 / 287 三连**：141 判环（只要阶段一）、142 找入环点（阶段一+二，显式链表）、287 找重复数（阶段一+二，隐式链表）。三题同一套模板，会一个就会三个。
- **为什么不能用排序 / 哈希？** 题面三条硬约束堵死了朴素解：① **不修改数组** → 不能 `sort`（排序是就地修改）；② **O(1) 额外空间** → 不能开哈希表（要 O(n) 空间）、也不能复制数组；③ **O(n) 时间** → 排除排序的 O(n log n)。Floyd 快慢指针是**唯一同时满足三条**的解法，这也是为什么它被列为「官方主解」——不是炫技，而是约束下的必然。

### 解法二：二分查找（官方方法一，对比用，非主解）

如果**去掉「不修改数组」「O(1) 空间」**中任意一条都不行，但又想不到快慢指针，还有一条退路：**对「答案的值域」做二分**，而不是对数组下标二分。理由是答案一定在 `[1, n]` 内。

定义 `cnt(i)` = `nums` 中 ≤ `i` 的元素个数。设重复数为 `target`，则：

- 当 `i < target`：`[1, i]` 这些数每个最多出现一次 → `cnt(i) <= i`；
- 当 `i >= target`：`target` 多算了一次 → `cnt(i) > i`。

这就是单调性：`cnt(i) <= i` 在左侧成立、`cnt(i) > i` 在右侧成立，**分界点就是 `target`**。于是二分 `[1, n]`，每次 `O(n)` 数一遍 `cnt(mid)`，总 O(n log n)。

```cpp
class Solution {
public:
    int findDuplicate(vector<int>& nums) {
        int n = nums.size();
        // l / r：答案值域 [1, n-1] 的左右端点（值域，不是下标）。
        int l = 1, r = n - 1, ans = -1;
        while (l <= r) {
            int mid = (l + r) >> 1;
            // cnt：统计 nums 里 <= mid 的元素个数。
            //   - nums[i] <= mid 是 bool，转 int 后 0/1，直接累加。
            int cnt = 0;
            for (int i = 0; i < n; ++i) {
                cnt += nums[i] <= mid;
            }
            if (cnt <= mid) {
                // 左半区间「正常」，target 必在右侧
                l = mid + 1;
            } else {
                // cnt > mid：mid 已经 >= target，记下来并继续往左收紧
                r = mid - 1;
                ans = mid;
            }
        }
        return ans;
    }
};
```

- **时间**：O(n log n)——每次二分扫一遍 O(n)，共 log n 轮。
- **空间**：O(1)，且不修改 `nums`。
- **对比**：二分法**思路更直白**（对值域二分 + 抽屉原理），约束上只差一个「O(n) 时间」（它是 O(n log n)），所以**不是主解**。但它在想不到「数组当链表」时是个好用的保底解。官方方法二「按位统计」也是 O(n log n)，思路类似（每一位统计 1 的个数是否超标），同样放复盘即可，不再贴代码。
