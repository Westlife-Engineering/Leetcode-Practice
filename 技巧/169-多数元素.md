# 169 多数元素

- 难度：简单
- 标签：**数组**、哈希表、分治、计数、排序
- 力扣链接：https://leetcode.cn/problems/majority-element/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「方法五：Boyer-Moore 投票算法」。正文主解是 **Boyer-Moore 投票算法**（官方推荐，O(n) 时间 O(1) 空间）；哈希表统计、排序取中位数等做法放在「复盘」作对比。

## 题目描述

给定一个大小为 `n` 的数组 `nums`，返回其中的多数元素。多数元素是指在数组中出现次数 **大于** `⌊ n/2 ⌋` 的元素。

你可以假设数组是非空的，并且给定的数组总是存在多数元素。

**示例 1：**

```
输入：nums = [3,2,3]
输出：3
```

**示例 2：**

```
输入：nums = [2,2,1,1,1,2,2]
输出：2
```

**提示：**

- `n == nums.length`
- `1 <= n <= 5 * 10^4`
- `-10^9 <= nums[i] <= 10^9`
- 输入保证数组中一定有一个多数元素。

**进阶：** 尝试设计时间复杂度为 O(n)、空间复杂度为 O(1) 的算法解决此问题。

## 思路

> 本题主要参考力扣官方题解的「Boyer-Moore 投票算法」做法。题目「进阶」明确要求 O(n) 时间 O(1) 空间，而投票算法正是为此设计的。

**先注意两个题设前提**，它们是投票算法成立的基础：

1. 多数元素出现次数 **严格大于** `⌊ n/2 ⌋`（不是「大于等于一半」，是「超过一半」）；
2. 题目**保证一定存在**多数元素（不用判空、不用二次验证）。

最直观的暴力做法是哈希表统计：扫一遍 `nums`，把每个数出现次数记进 `unordered_map<int,int>`，再找次数最大的那个键。O(n) 时间能过，但空间 O(n)，不满足进阶的 O(1)。

**Boyer-Moore 投票算法的核心思想**：把不同元素看成「两两对抗抵消」。

想象一场「打擂台」：候选人在台上，每来一个和他一样的人就 +1 票（声援），每来一个和他不一样的人就 −1 票（踢下台一个）。当台上票数被抵消成 0 时（擂台空了），下一个出场的人直接成为新候选人。一直打到最后，留在台上的那个人就是多数元素。

**为什么这样能找到多数元素？** 关键在于「多数元素的数量比其他所有元素加起来还多」。

- 设多数元素出现了 `m` 次，其余所有元素合计 `n - m` 次。因为 `m > n/2`，所以 `m > n - m`，即「多数元素比所有非多数元素加起来还多」。
- 投票过程本质上是把一个多数元素和一个非多数元素「配对抵消」。即使把多数元素和非多数元素尽量两两对消，非多数元素全部用光了，多数元素仍然有剩余。
- 所以无论中途候选人怎么换，**最后撑到台上的必然是多数元素**（它的人数优势是无法被抵消光的）。

**算法步骤**（维护一个候选人 `candidate` 和计数器 `count`）：

1. 初始 `candidate` 任意、`count = 0`；
2. 遍历每个元素 `num`：
   - 若 `count == 0`：当前擂台空了，**把 `num` 立为新候选人**（`candidate = num`）；
   - 若 `num == candidate`：来者是同伙，`count++`；
   - 若 `num != candidate`：来者是敌人，`count--`；
3. 遍历结束，`candidate` 即为多数元素。

**手动推导示例 1** `nums = [3,2,3]`（多数元素是 3）：

```
num=3  count=0 → 换候选人 candidate=3，再 num==candidate → count=1
num=2  count!=0 且 num!=3 → count=0（敌人 2 把台上唯一的 3 抵消光了，擂台空了）
num=3  count=0 → 换候选人 candidate=3，再 num==candidate → count=1
结束，返回 candidate=3 ✓
```

**手动推导示例 2** `nums = [2,2,1,1,1,2,2]`（多数元素是 2）：

```
num=2  count=0 → candidate=2，num==candidate → count=1
num=2  num==2 → count=2
num=1  num!=2 → count=1
num=1  num!=2 → count=0（连续两个 1 把台上两个 2 抵消光）
num=1  count=0 → candidate=1，num==candidate → count=1
num=2  num!=1 → count=0
num=2  count=0 → candidate=2，num==candidate → count=1
结束，返回 candidate=2 ✓
```

可以看到中途候选人从 2 换成了 1、又换回 2，但最终留下的是出现次数更多的 2。

## 代码

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        // candidate：当前「候选人」（擂台上的人），多数元素的候选者。
        //   - 初始化为任意值都行，因为 count=0 时第一步就会把它覆盖掉。
        //   - int 类型直接存数值本身（不是下标、不是计数）。
        // count：当前候选人相对其他元素的「净票数」。
        //   - 含义：到目前为止，candidate 比「非 candidate」多出现了几次。
        //   - count==0 表示擂台空了（候选人被抵消光），下一步该换人。
        int candidate = 0;
        int count = 0;

        // 范围 for 循环：依次取出 nums 里的每个元素，只读不改。
        //   - 等价于 for (int i = 0; i < (int)nums.size(); ++i) { int num = nums[i]; ... }
        //   - 对 int 这种小类型，直接拷贝比引用更快，所以写 int num 而非 const int& num。
        for (int num : nums) {
            // 第一步：判断是否需要「换候选人」。
            //   - 必须放在判断 num==candidate 之前：count==0 说明擂台空了，
            //     当前 num 无论是什么，都要先成为新候选人。
            //   - 注意官方 C++ 写法用的是 else if (--count < 0) 的紧凑形式，
            //     这里拆成「先判 count==0 换人、再判同异加减」更直观，逻辑等价。
            if (count == 0) {
                candidate = num;   // 立为新候选人
            }

            // 第二步：根据 num 与 candidate 是否相同，更新计数。
            //   - 相同 → +1（同伙声援）
            //   - 不同 → -1（敌人抵消）
            //   - 三目运算符 (cond ? a : b)：cond 为真取 a、为假取 b，
            //     这里把 +1 / -1 一次写完，等价于 if/else。
            if (num == candidate) {
                ++count;
            } else {
                --count;
            }
        }

        // 题目保证存在多数元素，遍历结束后 candidate 一定是它。
        //   - 若不保证存在（如变体题），还需再扫一遍统计 candidate 实际出现次数验证。
        return candidate;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 只对数组做了一次遍历，每步都是常数操作（比较、赋值、自增自减）。
  - 满足「进阶」要求的 O(n) 时间。
- **空间**：O(1)
  - 只用了 `candidate` 和 `count` 两个额外变量，与数组规模无关。
  - 满足「进阶」要求的 O(1) 空间，这也是投票算法相比哈希表法的核心优势。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么是 `count == 0` 时才换候选人？换个时机行不行？

必须用 `count == 0` 作为换人信号，因为 **`count == 0` 的语义是「当前候选人已被完全抵消，擂台空了」**。此时下一个出场的元素是「无主之地」上的第一个，自然成为新候选人。

如果改成「每来一个不同的元素就换候选人」，那就退化成「最后一个元素」，完全错了（比如 `[2,2,1,1,1,2,2]` 最后一个是 2 碰巧对，但 `[1,2,2]` 最后一个是 2 也对、`[2,1,1]` 最后是 1 也对……其实那只是巧合）。关键在于 **count 的累积**：只有当净票数归零、抵消干净了才换，才能保证换的「时机」正确。

代码里 `if (count == 0)` 必须写在 `if (num == candidate)` 之前，否则当 `count=0` 且 `num != candidate` 时，会先走 `else` 分支把 count 减成 -1，逻辑就乱了。

### Q2：为什么最后 `candidate` 一定是多数元素？万一中途换成错的怎么办？

这是投票算法最常被质疑的点。直觉上「中途换人」让人担心候选人走偏，但**最终结果由数量优势决定，与中途换人无关**。

证明思路（官方题解的版本）：把多数元素记为 `maj`，定义 `value` = 「到当前位置为止，`maj` 比非 `maj` 多出现了几次」。可以证明 **在每一步，`count` 和 `value` 要么相等、要么互为相反数**（当候选人是 `maj` 时相等，候选人是别的数时互为相反数）。

- 遍历过程中 `count` 始终非负（因为 count 归零时会立刻被新候选人 +1 拉回正数）；
- 遍历结束时 `value` 为正数（多数元素比非多数加起来还多，所以净值为正）；
- 「非负」与「正数」不可能互为相反数，所以结尾处必然 `count == value`（同号），也就是此时候选人就是 `maj`。

简单记：**多数元素数量超过一半，再怎么抵消也抵消不光，最后留在台上的只能是它**。

### Q3：题目如果不保证「一定存在多数元素」会怎样？

那就不能直接 `return candidate` 了——投票算法在「不存在多数元素」时仍会返回某个 `candidate`，但它**可能是错的**（只是个数最多的之一，未必超过 n/2）。

处理办法：投票结束后**再扫一遍数组，统计 `candidate` 的真实出现次数**，确认 `> n/2` 才返回，否则返回 -1（或表示不存在）。这样仍是 O(n) 时间 O(1) 空间。本题力扣保证存在，所以省了这一步验证。

### Q4：Boyer-Moore 投票法和「排序后取中位数」是什么关系？

两者都能解决本题，但思路完全不同：

- **排序取中位数**：因为多数元素超过 n/2 个，排完序后**下标 `n/2` 的位置必然被多数元素占据**（无论它分布在哪，跨过中点的那段一定是它）。`sort` 后 `return nums[n/2]` 即可，代码极短但 O(n log n) 时间、且**修改了原数组**。
- **投票法**：不排序、不改数组、O(n) 时间 O(1) 空间，是「进阶」要求下的最优解。

排序法胜在代码短、好记；投票法胜在效率和原地性。面试或刷题里，看到「超过 n/2」+「O(1) 空间」就上投票法。

## 复盘

- **核心套路**：**「Boyer-Moore 投票：找出现次数超过 n/k 的元素」**。本题是 k=2（超过 n/2）的最经典场景。套路是「候选人 + 净计数 + count 归零换人」，本质是利用「目标元素数量碾压其他元素之和」做两两抵消。
- **可迁移性**：推广到「找出所有出现超过 `⌊n/k⌋` 次的元素」（如 229 多数元素 II，k=3）时，用「k-1 个候选人 + 各自计数」的通用投票法即可——每个候选人遇到非自己阵营就各自 -1，全归零时换人。思路完全一致，只是候选人从 1 个扩到 k-1 个。
- **前提条件要记牢**：投票法**要求目标元素占比严格超过 1/k**（本题是 > n/2）。占比不超过一半时投票法不保证正确，必须二次验证。
- **不要混淆**：「投票法找众数」和「求众数（mode）」是两回事。一般意义的众数不一定超过半数，得用哈希表统计；投票法专治「超过 n/2」这种「绝对多数」。

### 解法二：哈希表统计（对比用，非主解）

官方题解「方法一」。扫一遍用 `unordered_map<int,int>` 统计每个数出现次数，顺便记录出现次数最大的那个键。O(n) 时间但 O(n) 空间，不满足进阶。

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        // unordered_map<int,int>：key=数值，value=出现次数。查找/插入均摊 O(1)。
        unordered_map<int, int> counts;
        int majority = 0, cnt = 0;   // majority 记当前已知次数最多的数，cnt 记它的次数
        for (int num : nums) {
            ++counts[num];           // counts[num]：num 不存在时会自动插入并置 0，再 ++ 变 1
            if (counts[num] > cnt) { // 边统计边更新最大值，省去再扫一遍 map
                majority = num;
                cnt = counts[num];
            }
        }
        return majority;
    }
};
```

- **时间**：O(n)（一次遍历，每步均摊 O(1)）
- **空间**：O(n)（最坏 map 存近 n 个不同键）

### 解法三：排序取中位数（对比用，非主解）

官方题解「方法二」。一句代码：排完序后下标 `n/2` 必是多数元素。

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        // sort：STL 内省排序（introsort），平均/最坏 O(n log n)，就地排序（会修改 nums）。
        //   - 注意：题目若要求「不能修改输入」，这个解法就不能用（投票法才是原地只读的）。
        sort(nums.begin(), nums.end());
        return nums[nums.size() / 2];  // 多数元素超过 n/2 个，必占据排序后的中点位置
    }
};
```

- **时间**：O(n log n)
- **空间**：O(log n)（`sort` 内部递归栈）
- **优点**：代码极短；**缺点**：改了原数组、时间不如投票法。面试里可作为「最短写法」答出，再优化到投票法。
