# 75 颜色分类

- 难度：中等
- 标签：数组、**双指针**、排序
- 力扣链接：https://leetcode.cn/problems/sort-colors/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[颜色分类](https://leetcode.cn/problems/sort-colors/solution/yan-se-fen-lei-by-leetcode-solution/)」。正文主解是 **三指针（荷兰国旗问题）**，一次遍历 O(n)、O(1) 空间，是官方「方法三」也是最经典的写法；单指针两趟扫描、双指针（p0/p1）两种解法放在「复盘」对比。这是 [283 移动零](../双指针/283-移动零.md) 那种「双指针交换划分」思路的进阶——把「非零 / 零」两段升级成「0 / 1 / 2」三段。

## 题目描述

给定一个包含红色、白色和蓝色、共 `n` 个元素的数组 `nums`，**原地**对它们进行排序，使得相同颜色的元素相邻，并按照红色、白色、蓝色顺序排列。

我们使用整数 `0`、`1` 和 `2` 分别表示红色、白色和蓝色。

必须**在不使用库内置的 sort 函数**的情况下解决这个问题。

**示例 1：**

```
输入：nums = [2,0,2,1,1,0]
输出：[0,0,1,1,2,2]
```

**示例 2：**

```
输入：nums = [2,0,1]
输出：[0,1,2]
```

**提示：**

- `n == nums.length`
- `1 <= n <= 300`
- `nums[i]` 为 `0`、`1` 或 `2`

**进阶：**

- 你能想出一个仅使用**常数空间**的**一趟扫描**算法吗？

## 思路

> 本题主要参考力扣官方题解「方法三：双指针（三指针交换法）」。

本题是经典的 **荷兰国旗问题（Dutch National Flag problem）**，由计算机科学家 Dijkstra 提出。要求把只含 0/1/2 三种值的数组**原地**排成 `[0,0,...,1,1,...,2,2,...]`，且**进阶要求一趟扫描 + 常数空间**。

**朴素做法（两趟，不满足进阶）**：先数 0、1、2 各有多少个（一趟 O(n)），再按数量把数组覆写回去（又一趟）。简单但写两遍、且**不是「交换式」的」原地操作**（覆写会丢失原信息）。官方「方法一」的「单指针」也是两趟：第一趟把所有 0 交换到最前面、第二趟把所有 1 交换到中间。能满足 O(n) 时间 O(1) 空间，但**要扫两遍**，进阶的「一趟」做不到。

**官方主解（三指针，一趟）**：用三个指针把数组**同时**切成四段。这是荷兰国旗问题的标准三向划分（three-way partition）技巧，和 283 移动零的「双指针交换划分」是同一类思路，只是从「两段」升级到「三段」。

### 三个指针各代表什么

设数组下标 `0..n-1`，维护三个指针 `p0`、`curr`、`p2`，把数组在**任意时刻**切成四段：

```
[ 0 .. p0-1 ]    全是 0    （已就位的红色区）
[ p0 .. curr-1 ] 全是 1    （已就位的白色区）
[ curr .. p2 ]   待扫描    （还没看，里面啥都有）
[ p2+1 .. n-1 ]  全是 2    （已就位的蓝色区）
```

- `p0`：**下一个 0 应该放的位置**（也是「0 区的右边界 + 1」）。初始 `0`。
- `curr`：**当前扫描指针**，从左往右走。初始 `0`。
- `p2`：**下一个 2 应该放的位置**（也是「2 区的左边界 - 1」）。初始 `n-1`。

`curr` 是唯一往前走的「读」指针；`p0` 在遇到 0 时往前推、`p2` 在遇到 2 时往回缩。四段的含义在循环里始终不变（不变式），只要维护住它，循环结束时 `[0,p0)` 是 0、`[p0,curr)` 是 1、`(p2,n)` 是 2，数组就排好了。

### 三种情况怎么处理（核心）

每一步看 `nums[curr]` 是什么：

1. **`nums[curr] == 0`**：它是个 0，应该放进红色区。**交换 `nums[curr]` 和 `nums[p0]`**，把这个 0 换到 `p0` 位置；然后 `p0++`（0 区右扩一位）、`curr++`（这个位置处理完了）。
   - 换过来的 `nums[curr]` 是什么？由不变式，`p0` 原本指向的位置要么就是 `curr`（还没遇到 1，0 区和待扫描区相邻），要么是个 1（中间隔了一段 1 区）。所以换过来的一定是 1 或 0 自己——**都已经就位**，`curr` 可以放心 `++`。
2. **`nums[curr] == 1`**：1 就该待在白色区，而 `curr` 当前位置正好在 `[p0, p2]` 内（白色区/待扫描区），它已经在正确的「1 区」里了。**直接 `curr++`**，啥都不换。
3. **`nums[curr] == 2`**：它是个 2，应该放进蓝色区。**交换 `nums[curr]` 和 `nums[p2]`**，把这个 2 甩到末尾；然后 `p2--`（2 区左缩一位）。
   - **关键：此时 `curr` 不动！** 因为从 `p2` 位置换过来的元素**还不知道是啥**（待扫描区里啥都有），可能是 0、可能是 1、可能是 2。必须**在下一轮重新判断 `nums[curr]`**，不能贸然 `curr++` 跳过它。
   - 举个例子：`curr` 指向 2，`p2` 指向 0，交换后 `curr` 位置变成 0——如果这里直接 `curr++`，这个 0 就被错误地留在了 1 区里，排序就错了。所以遇到 2 必须停在原地再判一次。

**一句话区分**：遇到 0 和 1 都能让 `curr++`（换来的元素已经确定是 0/1 自己、或本来就该是 1）；唯独遇到 2 换来的元素未知，必须原地再判。这就是为什么官方代码用 `while` 把「遇到 2」包起来连续换，直到 `nums[curr] != 2` 才放行。

### 为什么循环条件是 `curr <= p2` 而不是 `curr < p2`

`curr == p2` 时，`curr` 和 `p2` 指向同一个位置，它仍在待扫描区 `[curr, p2]` 里，**还没被判断过**。如果用 `<` 跳过它，最后这个位置的值（可能是 0/1/2 任意一个）就没被处理，排序可能错。所以条件必须是 `curr <= p2`（含等号），让 `curr` 把 `p2` 位置也判一下；判完之后 `p2--` 或 `curr++`，循环才结束。

### 和 283 移动零的关系

283 是「把 0 挪到末尾」，相当于只分「非零 / 零」**两段**，用 `left`（边界）+ `right`（扫描）两个指针交换即可。本题是「分 0 / 1 / 2」**三段**，相当于多了一个「右边界 `p2`」从右往左缩——思路完全同构，只是指针从 2 个变 3 个、从「单向划分」变「双向划分（三向切分）」。**把 283 的交换套路想清楚，再往右加一个 `p2` 边界，就得到本题解法。**

### 手动推导 `nums = [2,0,2,1,1,0]`

`p0=0, curr=0, p2=5`，箭头标出当前 `curr` 指向的值：

```
下标: 0 1 2 3 4 5
初始 [2,0,2,1,1,0]   p0=0 curr=0 p2=5
      ^
curr=0: nums[0]=2 → swap(nums[0],nums[5]) → [0,0,2,1,1,2]  p2=4, curr 不动（换来的0要再判）
curr=0: nums[0]=0 → swap(nums[0],nums[0]) → [0,0,2,1,1,2]  p0=1, curr=1（自换，p0/curr都++）
curr=1: nums[1]=0 → swap(nums[1],nums[1]) → [0,0,2,1,1,2]  p0=2, curr=2
curr=2: nums[2]=2 → swap(nums[2],nums[4]) → [0,0,1,1,2,2]  p2=3, curr 不动（换来的1要再判）
curr=2: nums[2]=1 → curr=3（1本该在中间，直接放过）
curr=3: nums[3]=1 → curr=4（同上）
curr=4 > p2=3，循环结束。
结果 [0,0,1,1,2,2] ✓
```

注意第 1 步把末尾的 0 换到开头后，`curr` 停在原地（指向刚换来的 0），第 2 步才处理它——这正是「遇到 2 不 `curr++`」的典型场景。

## 代码

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        // vector<int>& nums：力扣传入的数组引用，原址修改、无返回值（void）。
        //   - 题目要求「原地排序 + 不能用库 sort」，所以直接在 nums 上动手脚。

        int n = nums.size();          // size()：返回元素个数，O(1)

        // 三个指针（本题全部精髓）：
        //   p0   = 下一个 0 该放的位置（0 区右边界 +1），从左往右推。
        //   p2   = 下一个 2 该放的位置（2 区左边界 -1），从右往左缩。
        //   curr = 当前扫描指针，从左往右逐个判断 nums[curr]。
        // 不变式：[0,p0)=全0  [p0,curr)=全1  [curr,p2]=待扫描  (p2,n)=全2
        int p0 = 0, p2 = n - 1, curr = 0;

        // 循环条件必须是 <= 不是 <：
        //   curr==p2 时那一个元素仍在待扫描区里，还没判过，必须处理。
        //   判完之后（curr++ 或 p2--）curr 就会超过 p2，循环自然退出。
        while (curr <= p2) {
            if (nums[curr] == 0) {
                // 遇到 0：换到 p0 位置（红色区末尾），p0 和 curr 都 ++。
                //   swap(a,b)：C++ STL（<utility>），交换两个同类型对象，对 int 是 O(1)。
                //   换来的 nums[curr] 只会是 1（中间隔的 1 区）或 0 自己（p0==curr 时），
                //   都已就位，所以 curr 可以放心 ++。
                swap(nums[p0], nums[curr]);
                ++p0;
                ++curr;
            } else if (nums[curr] == 2) {
                // 遇到 2：甩到 p2 位置（蓝色区开头），p2--。
                //   ★★ 关键：curr 不 ++！因为从 p2 换过来的元素还不知道是 0/1/2，
                //   必须停在原地、下一轮重新判断 nums[curr]。
                //   （如果这里也 curr++，换来的 0 可能被错误留在 1 区，排序就错了。）
                //   写成 while 的等价：这里用 if 也能工作，因为外层 while 会再判一次 curr，
                //   只要 nums[curr] 仍是 2 就再甩一次，直到换来的不是 2 才 curr++（走 0 或 1 分支）。
                swap(nums[p2], nums[curr]);
                --p2;
                // 注意：没有 ++curr！
            } else {
                // nums[curr] == 1：1 本该待在中间，curr 当前位置就在 [p0, p2] 内，
                //   已经在正确的 1 区里，直接 curr++ 放过。
                ++curr;
            }
        }
    }
};
```

## 复杂度

- **时间**：O(n)
  - `curr` 从左到右、`p2` 从右到左，每个元素最多被 `curr` 扫到一次、或被 `p2` 交换一次。总体元素访问次数是 O(n) 量级。
  - 严格说：遇到 0 或 1 时 `curr++`，遇到 2 时 `p2--`（`curr` 不动）。每次循环要么 `curr` 右移、要么 `p2` 左移，总共最多 `n`（curr 走的步）+ `n`（p2 走的步）次操作，是 O(n)。一趟扫描搞定，满足进阶。
- **空间**：O(1)
  - 只用了 `p0`、`p2`、`curr` 三个下标变量，原地修改 `nums`，满足「常数空间」。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么遇到 2 时 `curr` 不 `++`，遇到 0 和 1 时却可以？

核心区别在于**「从指针位置换过来的元素是否已知」**：

- 遇到 **2**：和 `p2` 交换。`p2` 指向的是**待扫描区**里的元素，里面 0/1/2 都可能有，所以换到 `curr` 位置的值**未知**，必须原地重新判断，不能 `curr++` 跳过。
- 遇到 **0**：和 `p0` 交换。`p0` 指向的位置由不变式保证要么是 `curr` 自己（0 区和待扫描区相邻），要么是 1（中间隔了 1 区），换过来的是 **0 或 1**，都已经就位，`curr++` 安全。
- 遇到 **1**：不交换，1 本就在中间区，`curr++` 安全。

一句话：**「换来的东西不确定」就不动 curr，「换来的东西确定」就可以动**。这是三向划分最容易写错的地方，务必记住。

### Q2：为什么循环条件是 `curr <= p2` 而不是 `curr < p2`？

`curr == p2` 时，下标 `curr`（= `p2`）这个元素还在待扫描区 `[curr, p2]` 内，**还没被判断过**，可能是个 0/1/2 任意值。用 `<` 跳过它，这个值就漏判了，排序结果可能错。

含等号 `<=` 让 `curr` 把 `p2` 位置也处理一下；处理完要么 `curr++`（成了 0 或 1）要么 `p2--`（成了 2 被甩走），两种都会让 `curr > p2`，循环随即退出，不会死循环。

### Q3：`p0` 和 `p2` 到底代表什么？为什么一个左推一个右缩？

- `p0`：**0 区的右边界（不含）**，即「下一个 0 该放的位置」。遇到 0 时把 0 换到 `p0`，再 `p0++`，红色区 `[0, p0)` 就多了一位。
- `p2`：**2 区的左边界（含）**，即「下一个 2 该放的位置」。遇到 2 时把 2 换到 `p2`，再 `p2--`，蓝色区 `(p2, n)` 就多了一位。

之所以 `p0` 从左往右、`p2` 从右往左，是因为 **0 要放最左、2 要放最右**——0 的边界自然从左端扩张，2 的边界自然从右端收缩，1 留在中间不动。两个边界相向逼近，中间夹的就是待处理区，`curr` 在里面逐个判。

### Q4：本题和 283 移动零的区别 / 联系？

- **283 移动零**：分「非零 / 零」**两段**，一个左边界 `left` + 一个扫描 `right`，两个指针，单向划分（0 只往右堆）。
- **75 颜色分类**：分「0 / 1 / 2」**三段**，左边界 `p0` + 右边界 `p2` + 扫描 `curr`，三个指针，双向划分（0 往左堆、2 往右堆、1 留中间）。

思路完全同构：**用边界指针圈定「已就位区」，扫描指针把元素按值交换到对应边界**。75 就是 283 多加了一个右边界、多处理一种值。理解了 283，把它的「左边界」思路复制一份到右边（处理 2），就是 75 的三指针解法。这种「双向夹逼 + 三向划分」也正是**快速排序三向切分**的核心。

### Q5：交换时 `curr == p0`（自己和自己换）会不会出问题？

不会。遇到 0 且 `curr == p0` 时，`swap(nums[p0], nums[curr])` 是自交换，值不变，只是多一次赋值，无害。这通常发生在数组开头还没遇到 1、0 区和待扫描区相邻的时候（见手推第 2、3 步）。可以加 `if (p0 != curr) swap(...)` 优化，但可读性下降，力扣上没必要。遇到 2 时 `curr` 和 `p2` 一般不相等（除非 `curr == p2`，但那种情况下若 `nums[curr]==2` 也是自交换后 `p2--`，`curr` 随即越界退出，依然正确）。

## 复盘

- **核心套路**：**「三指针 / 三向划分 = 荷兰国旗问题」**。要把数组按若干个值（这里是 0/1/2）原地分段，用「左边界 + 右边界 + 扫描指针」三个指针：扫描指针逐个判，碰到左段值就和左边界交换 + 左边界右推，碰到右段值就和右边界交换 + 右边界左缩（**扫描指针不动**，因为换来的未知），碰到中段值就直接放过。一趟扫描 O(n)、O(1) 空间。
- **和 283 移动零的关系**：283 是「两段划分」（退化版，没有右边界），75 是「三段划分」（完整版）。会 283 就该想到 75——多加一个右边界处理 2 即可。两个题是同一条「交换式原址划分」套路的姊妹篇。
- **可迁移到快速排序的三向切分**：当待排序数组里有大量重复元素时，普通快排（两向 `<` / `>=`）会把相等的元素反复搬，退化。用荷兰国旗的三向切分（`<pivot` / `==pivot` / `>pivot` 三段）可以一次性把所有等于 pivot 的元素就位，后续只递归 `<` 和 `>` 两段，对重复元素多的输入显著更快。Java 的 `Arrays.sort` 对原始类型用的双轴快排、对重复 key 的处理就借鉴了这种思路。
- **「换来的元素是否已知」决定扫描指针动不动**：这是三向划分的灵魂。遇到左段值（0）换来的已知是 0/1，扫描指针 `++`；遇到右段值（2）换来的未知，扫描指针**不动**。记住这个判据，写三指针划分就不会乱。
- **不变式思维**：动笔写三指针前，先画清楚 `[0,p0) / [p0,curr) / [curr,p2] / (p2,n)` 四段各是什么，循环体只管维护这个不变式。这是所有「原址划分」类题（移动零、颜色分类、快排分区、奇偶分隔）通用的思考方式。

### 解法二：单指针两趟扫描（官方「方法一」，对比用）

更直白的写法：第一趟只管把所有 0 交换到最前面（用一个指针 `ptr` 标记「下一个 0 该放的位置」），第二趟再把所有 1 交换到 0 后面。两趟各扫一遍，O(n) 时间 O(1) 空间，但**不满足进阶的「一趟扫描」**。

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int n = nums.size();
        int ptr = 0;                 // ptr：下一个 0（或第二趟的 1）该放的位置
        // 第一趟：把所有 0 交换到最前面
        for (int i = 0; i < n; ++i) {
            if (nums[i] == 0) {
                swap(nums[i], nums[ptr]);
                ++ptr;               // 0 区右扩一位
            }
        }
        // 第二趟：从 ptr 开始，把所有 1 交换到 0 后面
        for (int i = ptr; i < n; ++i) {
            if (nums[i] == 1) {
                swap(nums[i], nums[ptr]);
                ++ptr;
            }
        }
    }
};
```

- **时间**：O(n)（两趟）；**空间**：O(1)。
- **对比**：写法比三指针简单（一个指针、不用考虑「换来的未知」），但要扫两遍；三指针一趟搞定，是进阶的正解。初学可先写这个，再优化到三指针。

### 解法三：计数排序（两趟覆写，最朴素）

题目提示里点过的方法：先数 0/1/2 各几个，再按数量把数组覆写一遍。两趟、O(n) 时间 O(1) 空间，但**不是原地交换、不满足进阶的「一趟」**，且**覆写会丢失原数组信息**（不过本题只关心最终值，无所谓）。

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int cnt[3] = {0, 0, 0};      // cnt[v] = 值 v 出现的次数
        for (int x : nums) ++cnt[x]; // 第一趟：计数
        int k = 0;
        for (int v = 0; v < 3; ++v)  // 第二趟：按 0、1、2 的数量覆写
            for (int i = 0; i < cnt[v]; ++i)
                nums[k++] = v;
    }
};
```

- **时间**：O(n)；**空间**：O(1)（`cnt` 大小固定 3）。
- **对比**：思路最简单、对「值域很小」的排序问题通用（这就是**计数排序**的雏形）。缺点是**覆写不是交换**、要两趟，且只在「值的种类很少」时高效（值域大就退化成普通计数排序，空间爆炸）。三指针交换法是「值种类少 + 要求原地一趟」时的最优解。
