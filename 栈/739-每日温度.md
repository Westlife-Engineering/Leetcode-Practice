# 739 每日温度

- 难度：中等
- 标签：**栈**、数组、**单调栈**
- 力扣链接：https://leetcode.cn/problems/daily-temperatures/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/daily-temperatures/solution/mei-ri-wen-du-by-leetcode-solution/)「每日温度」（slug：`mei-ri-wen-du-by-leetcode-solution`）。正文主解是 **单调栈（单调递减栈）**——遍历温度数组，用一个存下标的栈维护「还没找到更高温度的那些天」，当前温度比栈顶高时就弹栈记录答案，O(n) 时间。这是**单调栈的经典入门题**，和 84 柱状图中最大的矩形（同批）并称单调栈双壁，把它吃透，后续「找下一个更大/更小元素」一串题都是同一套模板。

## 题目描述

给定一个整数数组 `temperatures`，表示每天的温度，返回一个数组 `answer`，其中 `answer[i]` 是指对于第 `i` 天，下一个更高温度出现在几天后。如果气温在这之后都不会升高，请在该位置用 `0` 来代替。

**示例 1：**

```
输入: temperatures = [73,74,75,71,69,72,76,73]
输出: [1,1,4,2,1,1,0,0]
```

**示例 2：**

```
输入: temperatures = [30,40,50,60]
输出: [1,1,1,0]
```

**示例 3：**

```
输入: temperatures = [30,60,90]
输出: [1,1,0]
```

**提示：**

- `1 <= temperatures.length <= 10^5`
- `30 <= temperatures[i] <= 100`

## 思路

> 本题参考力扣官方题解「方法二：单调栈」。

### 这题到底在求什么

把题意翻译一下：对每个位置 `i`，要找它**右边第一个比它大的元素**，并算出两者的距离 `j - i`；如果右边没有更大的，答案就是 `0`。

「右边第一个更大」是单调栈最标准的应用场景。看到这种句式，第一反应就该是单调栈。

### 单调栈的本质：用「等待队列」来理解

想象一队人从左到右排好（就是温度数组），每个人都在等「**一个比我高的人出现**」来告诉自己答案。我们维护一个栈，里面存的是**「还在等待的人的下标」**：

- 栈里这些人，**之所以还在等，是因为到目前为止，他们后面还没出现过比他们更高的**。
- 那么栈里这些下标对应的温度，从栈底到栈顶一定是**单调递减**的——因为如果后入栈的某个人比先入栈的矮，没关系，他叠在上面；但如果后入栈的反而更高，那他一进来就会立刻把栈顶那个比他矮的「解救」掉（找到答案弹出去），不可能让矮的压在高的下面。

所以叫**单调递减栈**：栈底温度最高，栈顶温度最低，**小的压在大的上面**，一直等到一个更大的来，才从栈顶开始往外弹。

### 为什么栈内存「下标」而不是存「温度值」

这是单调栈最常见的初学疑问。答案是：**因为最终要算「距离」（差几天）**。

- 存下标后，`ans[stk.top()] = i - stk.top()` 一行就能算出「栈顶那天到今天相差几天」。
- 需要比较温度时，用 `temperatures[stk.top()]` 也能随时还原出值。
- 如果只存值，就丢了「是第几天」这个信息，没法算距离。

记住一句话：**凡是答案和「位置 / 距离」有关的，栈里就存下标**。本题、84 柱状图最大矩形、42 接雨水的单调栈解法都是存下标。

### 算法步骤（从左到右一次遍历）

1. 准备答案数组 `ans`，长度 `n`，**全部初始化为 0**——这样留在栈里没被弹出的下标，答案天然就是 0（后面没有更高温度），不用最后再处理。
2. 维护一个存下标的栈 `stk`，初始为空。
3. 从左到右遍历 `i = 0..n-1`，对每个当前温度 `T[i]`：
   - **弹栈循环**：只要栈不空且 `T[i] > T[stk.top()]`（当前温度比栈顶那天高），说明栈顶那天的「下一个更高温度」就是今天！弹出栈顶 `prev = stk.top()`，记 `ans[prev] = i - prev`。重复这个动作，直到栈空或栈顶温度不再比当前小。
   - **入栈**：把当前下标 `i` 压入栈，让它也开始等待它的「下一个更高」。
4. 遍历结束，`ans` 就是答案。栈里剩下的下标答案保持 0。

> 关键不变式：**栈里下标对应的温度从栈底到栈顶单调递减**。弹栈循环就是在维护这个不变式——当前更大的来了，就把栈顶所有比它小的统统「解救」出去。

### 手动推导 `temperatures = [73,74,75,71,69,72,76,73]`（答案 `[1,1,4,2,1,1,0,0]`）

栈底在左、栈顶在右，括号里是对应温度。`ans` 初始全 0。

```
i=0  T=73  栈空 → push(0)                  stk=[0(73)]
i=1  T=74  74>73 弹0, ans[0]=1-0=1          stk=[]
           栈空 → push(1)                   stk=[1(74)]
i=2  T=75  75>74 弹1, ans[1]=2-1=1          stk=[]
           栈空 → push(2)                   stk=[2(75)]
i=3  T=71  71<75 不弹 → push(3)             stk=[2(75),3(71)]
i=4  T=69  69<71 不弹 → push(4)             stk=[2(75),3(71),4(69)]
i=5  T=72  72>69 弹4, ans[4]=5-4=1          stk=[2(75),3(71)]
           72>71 弹3, ans[3]=5-3=2          stk=[2(75)]
           72<75 停 → push(5)               stk=[2(75),5(72)]
i=6  T=76  76>72 弹5, ans[5]=6-5=1          stk=[2(75)]
           76>75 弹2, ans[2]=6-2=4          stk=[]
           栈空 → push(6)                   stk=[6(76)]
i=7  T=73  73<76 不弹 → push(7)             stk=[6(76),7(73)]

遍历结束。栈里剩 6、7（76 和 73 后面没有更高），ans[6]=ans[7]=0（初始值）。
ans = [1,1,4,2,1,1,0,0] ✓
```

观察栈的变化：每次遇到更高温度，就连续弹出一串比它矮的（i=5 连弹 2 个、i=6 连弹 2 个），这正是「单调递减」被维护的过程——栈里始终保持从底到顶温度递减。

## 代码

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();

        // vector<int> ans(n)：长度 n 的答案数组，元素类型 int。
        //   - vector<int>(n) 不写初值时，int 会被「值初始化」为 0（这是关键！）。
        //   - 所以 ans 一开始全是 0：留在栈里没被弹出的下标（即后面没有更高温度的那几天），
        //     答案天然保持 0，不需要遍历结束后再单独处理，省一段收尾代码。
        //   - 返回类型就是 vector<int>，直接 return ans 即可。
        vector<int> ans(n);

        // stack<int> stk：C++ STL 栈，这里元素是 int（存的是「数组下标」，不是温度值！）。
        //   - 头文件 <stack>，力扣 C++ 模板默认已包含。
        //   - 只能在栈顶操作：push 压入、pop 弹出（无返回值！）、top 看栈顶、empty 判空、size 个数。
        //   - push / pop / top 都是 O(1)。
        //   - 语义：保存「到目前为止还没找到更高温度的那些天的下标」。
        //     栈顶永远是「最近一个、尚未被解救的待处理天」。
        //   - 不变式（核心）：从栈底到栈顶，下标对应的温度 temperatures[stk[k]] 单调递减。
        //   - 为什么存下标不存值：因为要算「差几天」(i - stk.top())，丢了下标就算不出距离；
        //     而比较温度时用 temperatures[stk.top()] 随时能还原出值，两不耽误。
        stack<int> stk;

        // for (int i = 0; i < n; ++i)：从左到右遍历每一天，i 是「当前天」的下标。
        //   - 每个 i 至多入栈一次、出栈一次，所以总循环（含 while 体）均摊 O(n)。
        for (int i = 0; i < n; ++i) {
            // 弹栈循环（单调栈的精髓）：当前温度比栈顶那一天高，就反复弹出栈顶并记录答案。
            //   - stk.empty()：先判空！空栈调 top() 是未定义行为（会崩）。
            //   - temperatures[i] > temperatures[stk.top()]：当前温度严格大于栈顶那天的温度。
            //     * 注意是严格 > 不是 >=：相等不算「更高温度」（题目要「升高」），所以等号的留在栈里继续等。
            //     * 栈顶下标 stk.top() 对应的那天，它的「下一个更高温度」就是今天 i！
            //   - 用 while 不是 if：因为当前温度可能连续比多个栈顶都高（如 i=5 的 72 连弹 69、71），
            //     要一直弹到栈空或栈顶温度不再比当前小为止——这一串弹出正是在恢复「单调递减」不变式。
            while (!stk.empty() && temperatures[i] > temperatures[stk.top()]) {
                int prev = stk.top();   // 取出栈顶下标：它就是「刚找到答案」的那一天。
                                        //   - 必须先 top() 取值，因为 pop() 不返回任何东西。
                ans[prev] = i - prev;   // 记录答案：栈顶那天到今天相差 i - prev 天。
                                        //   - 这就是为什么要存下标——距离 = 两个下标之差。
                stk.pop();              // 弹出 prev：它已经找到答案，退出「等待队列」。
                                        //   - 弹出后，新的栈顶是更早入栈、温度更高的那一天，
                                        //     下一轮 while 会继续判断它是否也比当前温度小。
            }
            // 当前下标 i 入栈，开始等待它自己的「下一个更高温度」。
            //   - 无论刚才弹了多少个，i 一定会入栈（它自己还没找到答案）。
            //   - 入栈后单调递减不变式依然成立：刚才比它小的都被弹光了，栈顶（若有）一定比它大。
            stk.push(i);
        }

        // 遍历结束：栈里剩下的下标（如示例中的 6、7）后面没有更高温度，
        //   ans 对应位置保持初始值 0，符合题目要求，无需额外处理。
        return ans;
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 是数组长度。
  - 看起来有双重循环（for 套 while），容易误以为 O(n²)。关键在于**每个下标至多入栈一次、出栈一次**：内层 while 每次弹出会永久删掉一个元素，n 次入栈对应至多 n 次出栈。把所有 while 体的执行次数加起来，总共不超过 n 次。所以整体是均摊 O(n)，不是 O(n²)。
- **空间**：O(n)。
  - 栈最坏要存 n 个下标（如温度单调递减 `100,99,98,...` 时，每个都入栈没人弹），占 O(n)。
  - 答案数组 O(n) 按惯例是返回值、不计入额外空间；即便计入也是 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：栈里为什么存「下标」而不是直接存「温度值」？

因为**答案要的是「相差几天」这个距离，不是温度本身**。距离 = 两个下标之差 `i - prev`，丢了下标就算不出来。

存下标并不丢温度信息：要比较时用 `temperatures[stk.top()]` 随时能取回值。所以「存下标」是同时拿到「位置」和「值」两份信息的做法，最划算。

一句话：**凡答案依赖位置/距离/边界的单调栈题，栈里一律存下标**。本题、84 柱状图最大矩形、42 接雨水的单调栈写法都是如此。

### Q2：栈为什么是「单调递减」而不是「单调递增」？

由「弹栈条件」和「入栈时机」共同决定。本题弹栈条件是 `T[i] > T[stk.top()]`（**更大的来了才弹**），所以：

- 如果一个矮的（栈顶）压在一个高的（栈底）上面，相安无事——高的在底下等，矮的在上面也等，谁都没遇到比自己高的；
- 但如果一个**高的**想压在**矮的**上面（即新来的温度比栈顶大），弹栈条件立刻触发，矮的会被弹走，不会让矮的盖在高的上面。

于是栈里从底到顶只能是「高 → … → 矮」，即**单调递减**。

反过来，如果你要找的是「右边第一个更小元素」，弹栈条件就该是 `T[i] < T[stk.top()]`（更小的来了才弹），那栈就会是单调递增的。**弹栈条件决定栈的单调方向**——要找「更大」就用递减栈，要找「更小」就用递增栈。

### Q3：那些「后面没有更高温度」的天，代码怎么处理？为什么不用单独写？

靠 `ans` 初始化为 0 和「不弹栈就留在栈里」两点配合，自动处理掉：

- `vector<int> ans(n)` 把答案数组初始化全 0；
- 遍历过程中，如果某天一直没有遇到比它更高的温度，它就**永远不会被弹出**，自然也永远不会被赋值，对应位置的 `ans` 保持初始的 0；
- 遍历结束后栈里剩的那些下标（如示例中的第 6、7 天），答案就是 0，正是题目要求的「不会升高用 0 代替」。

所以**不需要**在最后再遍历一遍栈把剩余元素清零——初始化为 0 这个细节帮我们省了一段收尾代码。这也是为什么 `ans(n)` 不写初值（值初始化为 0）在这里特别合适。

### Q4：明明有 for 套 while 两层循环，为什么是 O(n) 而不是 O(n²)？

这是单调栈/单调队列类问题最经典的复杂度分析，叫**均摊分析（amortized）**。

关键观察：**每个下标在整个算法中至多入栈一次、出栈一次**。内层 while 每执行一次循环体，就 `pop` 掉一个元素——而一个元素被 pop 之前必须先被 push 过。n 次 push 对应至多 n 次 pop，所以 while 循环体总共最多执行 n 次（不是每个 i 都执行 n 次）。

把外层 for 的 n 次和内层 while 累计的 n 次加起来，总操作数不超过 2n，所以是 O(n)。看起来像 O(n²) 是因为只盯着「最坏单次 while 跑很多轮」，但那些轮是用之前攒下的「没弹的元素」换来的，均摊下来每个元素只贡献常数次操作。

### Q5：弹栈条件为什么是严格 `>` 不是 `>=`？温度相等要不要弹？

用严格 `>`。温度相等的两天，**后一天不算比前一天「更高」**（题目要「升高」，相等不算升高），所以相等时不能弹栈——前一天还要继续等一个严格比它高的。

如果误写成 `>=`，相等的会被弹走并记成「找到了更高温度」，但实际温度没升高，答案就错了。比如 `[70,70,50]`，正确答案是 `[0,0,0]`（没有人后面温度升高）；写成 `>=` 会把第一个 70 在第二个 70 处弹掉记成距离 1，得到 `[1,0,0]`，错。

## 复盘

### 可迁移套路：单调栈找「下一个更大/更小元素」

本题是这一套路的**标准模板**，背下来能直接套一大片题：

```
// 找每个元素右边第一个更大元素（单调递减栈，存下标）
stack<int> stk;
for (int i = 0; i < n; ++i) {
    while (!stk.empty() && a[i] > a[stk.top()]) {   // 更大的来了才弹
        int prev = stk.top();
        ans[prev] = i - prev;   // 或 a[i]，看题目要距离还是要值
        stk.pop();
    }
    stk.push(i);
}
```

变形记口诀：
- 找「下一个更大」→ 弹栈条件 `a[i] > a[stk.top()]`，栈**单调递减**；
- 找「下一个更小」→ 弹栈条件 `a[i] < a[stk.top()]`，栈**单调递增**；
- 找「上一个更大/更小」→ 从右往左遍历，或反向记录。

同类题（都是这个模板）：496 下一个更大元素 I、503 下一个更大元素 II（循环数组）、901 股票价格跨度、907 子数组的最小值之和、42 接雨水（单调栈解法）、**84 柱状图中最大的矩形**（同批姊妹题，以栈里下标为高度、弹栈时算面积）。

### 和 84 柱状图最大矩形的关系（单调栈双壁）

84 和 739 是单调栈的两道里程碑题，思路同源但用法不同：

| | 739 每日温度 | 84 柱状图最大矩形 |
|---|---|---|
| 栈内存 | 下标 | 下标 |
| 单调方向 | 从底到顶**递减**（值） | 从底到顶**递增**（高度） |
| 弹栈触发 | 当前元素**更大**时弹栈顶 | 当前高度**更小**时弹栈顶（较小者是右边界） |
| 弹栈时算什么 | 距离 `i - prev` | 面积 `高 × 宽`（宽 = 当前下标 - 新栈顶 - 1） |

共同精髓：**栈维护一个「待处理」序列，靠弹栈时机把每个元素恰好处理一次，从而把看似 O(n²) 的两两比较降到 O(n)**。把 739 的弹栈 + 记答案逻辑吃透，84 只是在「弹栈时多算一步面积」而已。

### 解法对比：从后往前（官方方法一，O(n)）

官方方法一给的是「**从后往前**遍历 + 跳跃式查找」的写法，也很有启发。思路：从右往左扫，对每个 `i`，利用已经算出的 `ans` 快速跳过不可能的位置——`j = i + ans[j]` 直接跳到「下一个比 `temperatures[j]` 更高的位置」继续比，而不是一位一位挪。因为温度范围只有 `[30,100]`，官方还给了个用 `next[101]` 数组记录每个温度下次出现位置的暴力变体。

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> ans(n), next(101, INT_MAX);
        // 从后往前：处理 i 时，i+1..n-1 的答案都已就绪，可跳跃查找。
        for (int i = n - 1; i >= 0; --i) {
            int warmerIndex = INT_MAX;
            // 温度范围 [30,100]，枚举所有比当前高的温度，取最早出现的下标。
            for (int t = temperatures[i] + 1; t <= 100; ++t) {
                warmerIndex = min(warmerIndex, next[t]);
            }
            if (warmerIndex != INT_MAX) {
                ans[i] = warmerIndex - i;
            }
            next[temperatures[i]] = i;   // 记录该温度最左侧（最新）出现位置。
        }
        return ans;
    }
};
```

这个解法巧妙利用了「温度范围只有 71 种」这个条件，内层最多枚举 71 次，整体 O(71n) = O(n)。但**只适用于温度范围小**的场景，没有单调栈通用。两相对比更能体会到单调栈的普适性——不依赖值域，纯靠结构维护，是更值得掌握的模板。

### STL 小结（本题顺带练熟）

- `vector<int>(n)`：不写初值时 int 被**值初始化为 0**，本题正需要这个默认 0，省一段收尾。
- `stack<int>`：只有 `push / pop / top / empty / size` 五个接口；`pop()` 不返回值，要先 `top()` 取值再 `pop()`；空栈调 `top()` 是未定义行为，调用前必须先判 `empty()`。这些和 20-有效的括号里用过的栈是完全同一套接口。
