# 20 有效的括号

- 难度：简单
- 标签：**栈**、字符串
- 力扣链接：https://leetcode.cn/problems/valid-parentheses/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/valid-parentheses/solutions/38080/you-xiao-de-gua-hao-by-leetcode-solution/)「有效的括号」（slug：`you-xiao-de-gua-hao-by-leetcode-solution`）。正文主解是 **栈**——遍历字符串，遇左括号入栈、遇右括号弹栈匹配，这正是**栈的经典入门题**，也是理解「栈 LIFO（后进先出）」特性最好的第一题。

## 题目描述

给定一个只包括 `'('`，`')'`，`'{'`，`'}'`，`'['`，`']'` 的字符串 `s` ，判断字符串是否有效。

有效字符串需满足：

1. 左括号必须用**相同类型**的右括号闭合。
2. 左括号必须以**正确的顺序**闭合。
3. 每个右括号都有一个对应的相同类型的左括号。

**示例 1：**

```
输入：s = "()"
输出：true
```

**示例 2：**

```
输入：s = "()[]{}"
输出：true
```

**示例 3：**

```
输入：s = "(]"
输出：false
```

**示例 4：**

```
输入：s = "([])"
输出：true
```

**示例 5：**

```
输入：s = "([)]"
输出：false
```

**提示：**

- `1 <= s.length <= 10^4`
- `s` 仅由括号 `'()[]{}'` 组成

## 思路

> 本题主要参考力扣官方题解「方法一：栈」。

### 为什么这题要用栈？

括号匹配有一个天然规律：**「后遇到的左括号，要先被闭合」**。

举个例子，看到 `(`，过一会儿又看到 `[`，那么必须**先闭合 `[`**（出现 `]`），**再闭合 `(`**（出现 `)`）——也就是 `([])` 合法、`([)]` 不合法。这种「**后进先出**」的顺序，正好就是**栈（Stack）**这种数据结构的本质特性（LIFO，Last In First Out）。

> 栈你可以想象成一摞盘子：只能从最上面放（push）、从最上面拿（pop），最底下那个永远最后才能拿到。本题里「最后放进去的左括号」就是「最上面那个盘子」，它必须最先被对应右括号拿掉。

所以套路是：

- **遇到左括号**：先存起来（压入栈顶），等它对应的右括号出现。
- **遇到右括号**：它必须匹配**栈顶那个最近、还没闭合的左括号**。匹配上就把栈顶弹掉（这一对闭合了），匹配不上（类型不符，或栈已经空了没有左括号可配）整个字符串就无效。

### 判定有效的两个条件（缺一不可）

遍历结束后，要同时满足：

1. **过程中所有右括号都成功匹配**：每次遇到右括号，栈都不空且栈顶是同类型的左括号（否则中途直接 `return false`）。
2. **栈最终为空**：所有左括号都被配对掉了。如果栈里还剩左括号，说明「左括号多了」、没等来它的右括号，也是无效的。

注意第 2 点：像 `()(` 这种，遍历过程中右括号都匹配了，但最后栈里还剩一个 `(`，所以无效。

### 哈希表存「右括号 → 左括号」的映射

为了快速判断「栈顶的左括号和当前右括号是不是同一类型」，用一张哈希表把配对关系存起来。**关键是 key 存右括号、value 存对应左括号**：

```
')' -> '('
']' -> '['
'}' -> '{'
```

为什么这么做？因为遇到右括号时，我们要拿它去「反查」期望的左括号，再去和栈顶比对。把右括号当 key，一行 `pairs[ch]` 就能拿到它应该匹配的左括号，写起来最顺。而且用 `pairs.count(ch)` 是否为真就能**判断当前字符是右括号还是左括号**——左括号根本不在 map 的 key 里，省去单独的判断逻辑。

### 一个小优化：奇数长度直接判无效

有效字符串的括号一定成对出现，所以长度必然是偶数。如果 `s.size()` 是奇数，可以直接 `return false`，省去后续遍历。

### 手动推导 `s = "()[]{}"`（应为 `true`）

栈底在左、栈顶在右。映射表 `pairs = {')':'(', ']':'[', '}':'{'}`。

```
初始  stk=[]                      （空）

ch='('  左括号 → 入栈                stk=[(]
ch=')'  右括号 → 查 pairs[')']='('  栈顶='(' 匹配！pop    stk=[]
ch='['  左括号 → 入栈                stk=[[]
ch=']'  右括号 → 查 pairs[']']='['  栈顶='[' 匹配！pop    stk=[]
ch='{'  左括号 → 入栈                stk=[{]
ch='}'  右括号 → 查 pairs['}']='{'  栈顶='{' 匹配！pop    stk=[]

遍历结束，stk 为空 → return true ✓
```

### 手动推导 `s = "([)]"`（应为 `false`）

```
初始  stk=[]

ch='('  左括号 → 入栈                stk=[(]
ch='['  左括号 → 入栈                stk=[(,[]   栈顶是 '['
ch=')'  右括号 → 查 pairs[')']='('  栈顶='[' ≠ '(' → 类型不符！return false ✓
```

可以看到，`)` 想闭合最外层的 `(`，但栈顶却是后入的 `[`——因为 `[` 还没被闭合，它挡在 `(` 前面。这就生动体现了「后进先出」：你只能先处理离你最近的那个左括号。

## 代码

```cpp
class Solution {
public:
    bool isValid(string s) {
        int n = s.size();
        // 有效字符串的括号成对出现，长度必为偶数。
        //   - 奇数长度直接判无效，省去后续无意义的遍历，是个常数级小优化。
        if (n % 2 == 1) {
            return false;
        }

        // unordered_map<char, char>：C++ STL 哈希表，key/value 都是 char。
        //   - 查找/插入均摊 O(1)（哈希表特性，对比 map 的 O(log n)）。
        //   - 这里存「右括号 -> 对应的左括号」映射，目的是：
        //     (1) 遇右括号时用 pairs[ch] 一步查出它期望匹配的左括号；
        //     (2) 用 pairs.count(ch) 是否非零，判断当前字符是不是右括号
        //         （左括号不在 key 里，count 返回 0）。
        //   - 列表初始化 {{')','('}, {']','['}, {'}','{'}} 一次性填好三对。
        unordered_map<char, char> pairs = {
            {')', '('},
            {']', '['},
            {'}', '{'}
        };

        // stack<char>：C++ STL 栈，元素是 char（一个个括号字符）。
        //   - 只能在栈顶操作：push 压入、pop 弹出（无返回值！）、top 看栈顶、empty 判空。
        //   - push / pop / top 都是 O(1)。
        //   - 语义：保存「已经遇到、但还没被闭合」的左括号；栈顶永远是最近一个未闭合的左括号。
        //   - 栈底 <-> 栈顶的方向：第一个 push 的在最底，最后 push 的在最顶（最先被 pop）。
        //   - 为什么用栈不用数组？因为本题恰恰需要「后进先出」——最后那个左括号最先闭合。
        stack<char> stk;

        // for (char ch : s)：范围 for 循环，逐个取出字符串 s 里的字符。
        //   - ch 是 s 中每个字符的拷贝（不改 s 本身），从左到右依次处理。
        for (char ch : s) {
            // pairs.count(ch)：返回 key 为 ch 的元素个数（哈希表里要么 0 要么 1）。
            //   - count != 0 说明 ch 是右括号（')' ']' '}'），进入匹配分支。
            //   - count == 0 说明 ch 是左括号（不在 pairs 的 key 里），走 else 入栈。
            if (pairs.count(ch)) {
                // 到这里 ch 是右括号。它要能闭合，必须满足两个条件，任一不满足即无效：
                //   1) stk.empty()：栈空 = 根本没有左括号可配（右括号比左括号先出现/多了），
                //      例如 s=")" 或 s="()]",遇到这个右括号时栈是空的 -> 无效。
                //   2) stk.top() != pairs[ch]：栈顶左括号类型不对，例如 s="(]"，
                //      ch=']' 期望 '['，但栈顶是 '(' -> 无效。
                //   - 注意：top() 之前必须先判 empty()！空栈调 top() 是未定义行为（可能崩）。
                //   - 用「或」连接：只要其中一条成立就 return false。
                if (stk.empty() || stk.top() != pairs[ch]) {
                    return false;
                }
                // 匹配成功：把栈顶那个已闭合的左括号弹出。
                //   - pop() 只弹出、不返回值，所以上面用 top() 先取过值了。
                stk.pop();
            } else {
                // ch 是左括号 -> 入栈，等它对应的右括号出现。
                //   - 这里不用区分 '(' '[' '{'，反正后面靠 pairs 反查匹配。
                stk.push(ch);
            }
        }

        // 遍历结束：所有右括号都成功匹配过了。
        //   - 若栈空：所有左括号也被配对掉了 -> 有效，返回 true。
        //   - 若栈非空：还有左括号没等来右括号（左括号多了），如 s="((" -> 返回 false。
        //   - 所以最终结论正好等于「栈是否为空」，一行搞定。
        return stk.empty();
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 是字符串 `s` 的长度。
  - 只遍历一次字符串，每个字符要么入栈一次、要么弹栈一次，每次都是 O(1)，共 O(n)。
- **空间**：O(n + |Σ|)，其中 |Σ| 是字符集大小。
  - 栈最坏要存 n 个左括号（如 `s = "((((..."` 全是左括号），占 O(n)。
  - 哈希表 `pairs` 固定存 3 对映射，|Σ| = 6（六种括号），占 O(|Σ|) = O(1)。
  - 总体 O(n)。官方题解写的是 O(n + |Σ|)，常数部分可忽略。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么用栈，不能用数组或别的数据结构吗？

能做（数组模拟栈也行），但**栈是和「括号匹配」语义最贴合的数据结构**，用 `stack<char>` 写出来最清晰。

原因是括号匹配要求「最后遇到的左括号最先被闭合」，也就是**后进先出（LIFO）**——这正是栈的定义。如果用数组，你也要手动维护一个「从尾部增删」的指针，本质还是在模拟一个栈，不如直接用 `stack`。换用队列（FIFO，先进先出）反而完全错——它会让你去匹配最早遇到的左括号，和题目要求的「最近的左括号先闭合」正好相反。

**一句话记住：看到「匹配 / 嵌套 / 最近相关性」这类需求，第一反应就是栈。**

### Q2：如果右括号比左括号先出现（比如 `s = ")("`），代码会怎么处理？

不会出错，会被 `stk.empty()` 这一关正确拦下。

拿 `s = ")("` 走一遍：第一个字符 `)` 是右括号，进 `if (pairs.count(ch))` 分支，此时栈是空的，`stk.empty()` 为真，条件 `stk.empty() || ...` 直接成立，`return false`。这正是「右括号先于左括号」的无效情况。

所以这一句 `if (stk.empty() || stk.top() != pairs[ch])` 同时防住了两种错：栈空（没左括号可配）和类型不匹配。

### Q3：哈希表的映射为什么要存「右括号 → 左括号」，反过来存行不行？

反过来存（`'(' -> ')'`）也能做，但代码会绕一点。

存「右括号 → 左括号」的好处是：**遇到右括号时，能一步反查到「期望的左括号」并和栈顶对比**，而判断「当前字符是不是右括号」只要看 `pairs.count(ch)` 是否非零——左括号不在 key 里，自动归到 else 分支去入栈。一个 map 同时承担「配对表」和「左右括号判别器」两个职责，逻辑最干净。

如果存「左括号 → 右括号」，遇到右括号时你没法直接用它做 key，还得额外维护一个「右括号集合」来判方向，多一层判断，没必要。

### Q4：遍历结束后为什么要 `return stk.empty()`，不直接 `return true` 吗？

不行。遍历过程只检查了「每个右括号是否匹配」，没有保证「所有左括号都被闭合」。

反例：`s = "()"` 没问题，但 `s = "(()"` 这种——遍历中没遇到任何「栈空却来右括号」或「类型不符」的情况（两个 `(` 入栈、一个 `)` 匹配掉栈顶一个 `(`），中途不会 return false。可最后栈里还剩一个 `(` 没闭合，这是无效的。所以必须用 `stk.empty()` 收尾：栈空 = 左括号全配对完 = 有效；栈非空 = 还有左括号剩 = 无效。

## 复盘

### 可迁移套路

- **「栈处理匹配 / 嵌套结构」是通用模板**。凡是有「后进先出、最近优先」这种关系的需求，第一反应就是栈。括号匹配是这类问题的鼻祖，把它吃透，后续一串题都是同一套：删除最外层括号、删除相邻重复项、字符串解码（394）、计算器（224/227）、逆波兰表达式求值（150）、最长有效括号（32）等。
- **「映射表 + 单次遍历 + 栈」这个三件套**：用哈希表存配对关系让匹配判断 O(1)，单次遍历保证 O(n) 时间，栈负责维护「待匹配」状态。这是括号类题的标准骨架。
- **边界意识**：奇数长度直接判无效；右括号先出现（栈空）要拦；遍历完栈非空（左括号多）也要拦。这三类「无效」分别由「开头判奇偶」「中途判空栈/类型」「结尾判栈空」三个位置处理，缺一不可。
- **栈的 STL 基本功**（本题顺带练熟）：`stack<T>` 只有 `push / pop / top / empty / size` 五个接口；`pop()` 不返回值，要先 `top()` 取值再 `pop()`；空栈调 `top()` 是未定义行为，调用前必须先判 `empty()`。
