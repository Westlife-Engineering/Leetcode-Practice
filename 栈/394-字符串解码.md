# 394 字符串解码

- 难度：中等
- 标签：**栈**、递归、字符串
- 力扣链接：https://leetcode.cn/problems/decode-string/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/decode-string/solutions/548405/zi-fu-chuan-jie-ma-by-leetcode-solution/)「字符串解码」（slug：`zi-fu-chuan-jie-ma-by-leetcode-solution`）。正文主解是 **栈处理嵌套**（官方方法一「栈操作」的核心思想）：从左到右扫描，遇到 `[` 把「当前数字 + 当前字符串」压栈保存现场，遇到 `]` 弹栈拼接——这是和括号嵌套结构最贴合的写法。官方原文用的是「token 入栈（`vector<string>`）」实现，这里换成更易读的「双栈 + 当前结果」写法（思路完全一致），官方原版和递归法放在「复盘」。

## 题目描述

给定一个经过编码的字符串，返回它解码后的字符串。

编码规则为：`k[encoded_string]`，表示其中方括号内部的 `encoded_string` 正好重复 `k` 次。注意 `k` 保证为正整数。

你可以认为输入字符串总是有效的；输入字符串中没有额外的空格，且输入的方括号总是符合格式要求的。

此外，你可以认为原始数据不包含数字，所有的数字只表示重复的次数 `k`，例如不会出现像 `3a` 或 `2[4]` 的输入。

测试用例保证输出的长度不会超过 `10^5`。

**示例 1：**

```
输入：s = "3[a]2[bc]"
输出："aaabcbc"
```

**示例 2：**

```
输入：s = "3[a2[c]]"
输出："accaccacc"
```

**示例 3：**

```
输入：s = "2[abc]3[cd]ef"
输出："abcabccdcdcdef"
```

**示例 4：**

```
输入：s = "abc3[cd]xyz"
输出："abccdcdcdxyz"
```

**提示：**

- `1 <= s.length <= 30`
- `s` 由小写英文字母、数字和方括号 `'[]'` 组成
- `s` 保证是一个有效的输入。
- `s` 中所有整数的取值范围为 `[1, 300]`

> 关于规则：核心是 `k[encoded_string]` 表示把方括号里的内容重复 `k` 次，并且**可以嵌套**（如示例 2 的 `3[a2[c]]`：先解内层 `2[c]` 得 `cc`，外层变成 `3[acc]`，再解得 `accaccacc`）。嵌套正是本题的难点——它要求我们处理完内层、再回头处理外层，这种「后遇到的外层括号、却要先在脑子里记着」的关系，就是典型的**栈结构**能解决的事。

## 思路

> 本题主要参考力扣官方题解「方法一：栈操作」。

### 为什么这题要用栈？嵌套是关键

如果没有嵌套（比如 `3[a]2[bc]`），问题很简单：扫一遍，遇到数字 `k` 就读完整数字、读 `[` 后面的字母串、重复 `k` 次、跳过 `]`。难就难在**嵌套**——`3[a2[c]]` 里，外层的 `3[...]` 还没结束时，内部又冒出一个 `2[c]`，你必须先算完内层 `2[c]` = `cc`，才能继续外层 `3[a` + `cc` + `]` = `3[acc]` = `accaccacc`。

这就像括号匹配：**后遇到的左括号要先闭合**。处理外层括号时，得把外层的「现场」（重复几次、前面拼了什么）**先存起来**，专心处理内层；内层处理完、把结果拼回去时，再**取回**之前存的现场继续外层。这种「**存现场 → 处理内层 → 取现场 → 拼接**」的进出，正是**栈的后进先出（LIFO）**——最后存的现场（最内层的外层）最先被取回。

### 两个栈分别存什么？为什么要两个？

一个括号层的「现场」包含两样东西：

1. **重复次数 `k`**（`[` 前面那个数字）；
2. **进入这个括号层之前、已经拼出来的字符串**（外层的前缀）。

所以用**两个栈**把它们成对存起来：

- `numStk`（重复次数栈，`stack<int>`）：存每个 `[` 之前刚解析出来的数字 `k`；
- `strStk`（字符串栈，`stack<string>`）：存进入这个 `[` 之前、`res` 当时的内容（外层已拼好的前缀）。

再维护两个**当前量**（不在栈里，是「正在处理的这一层」的状态）：

- `res`（`string`）：当前这一层正在拼的字符串；
- `num`（`int`）：当前正在解析的、还没遇到 `[` 的数字（可能是多位，边读边累加）。

> 为什么要两个栈而不是一个？因为一层的现场本来就是**两部分信息**（次数 + 前缀）。也可以用一个 `stack<pair<int,string>>` 把两者打包进一个栈，效果一样（复盘里会提），但拆成两个栈语义更清楚——「次数栈」专门存次数、「字符串栈」专门存前缀，压栈弹栈时两栈同步进退。

### 三类字符怎么处理？

从左到右扫描 `s`，每个字符 `c` 分三种情况（注意题目保证 `s` 合法，所以不用做错误处理）：

| 字符 `c` | 操作 |
|---|---|
| **数字**（`isdigit`） | 解析进 `num`：`num = num * 10 + (c - '0')`。数字可能多位（如 `12[ab]`），所以要**连续读到非数字为止**，用 `num*10 + 当前位` 累加。 |
| **`[`** | **压栈保存现场**：把当前的 `num`（这个括号的重复次数）和 `res`（外层前缀）分别压进两个栈，然后把 `res` 清空、`num` 归零——准备开始拼这个括号**内部**的内容。 |
| **字母**（`isalpha`） | 直接追加到 `res`：`res += c`。不管它在外层还是内层，字母都是「当前层」要拼的内容。 |
| **`]`** | **弹栈拼接**：从 `numStk` 弹出这一层的重复次数 `k`、从 `strStk` 弹出外层前缀 `prev`，然后 `res = prev + res 重复 k 次`。也就是「把当前这一层的内容重复 k 次，拼回到外层前缀的尾巴上」。 |

### 拼接顺序：`prev + res*k`，方向别搞反

`]` 处的拼接是最容易写错的一步。要算的是：**外层前缀 `prev` + （当前层内容 `res` 重复 `k` 次）**。

- `prev` 在前：因为 `prev` 是进入这个括号**之前**就已经有的外层内容，它自然在最前面；
- `res` 重复 `k` 次在后：括号里的内容解码后就是要重复 `k` 次接在 `prev` 后面。

写成代码就是 `res = prev + repeat(res, k)`，其中 `repeat` 是把 `res` 自身追加 `k-1` 次（或用一个临时串 `t` 循环拼 `k` 次）。**不要写成 `res = res*k + prev`**，方向反了。

### 手动推导 `s = "3[a2[c]]"`（应为 `accaccacc`）

跟踪过程中，两个栈底在左、栈顶在右；`res` 是当前层字符串，`num` 是当前在解析的数字。

```
初始  res=""  num=0  numStk=[]  strStk=[]

c='3'  数字 → num = 0*10 + 3 = 3
c='['  压栈保存现场：
        strStk.push(res) → strStk=[""]
        numStk.push(num) → numStk=[3]
        重置 res=""  num=0
c='a'  字母 → res += 'a'   → res="a"
c='2'  数字 → num = 0*10 + 2 = 2
c='['  压栈保存现场：
        strStk.push(res) → strStk=["", "a"]
        numStk.push(num) → numStk=[3, 2]
        重置 res=""  num=0
c='c'  字母 → res += 'c'   → res="c"
c=']'  弹栈拼接：
        k = numStk.top() = 2 ; numStk.pop() → numStk=[3]
        prev = strStk.top() = "a" ; strStk.pop() → strStk=[""]
        res = prev + res*2 = "a" + "cc" = "acc"
c=']'  弹栈拼接：
        k = numStk.top() = 3 ; numStk.pop() → numStk=[]
        prev = strStk.top() = "" ; strStk.pop() → strStk=[]
        res = prev + res*3 = "" + "accaccacc" = "accaccacc"

扫描结束，返回 res = "accaccacc" ✓
```

重点体会两次 `]` 的处理：**第一次 `]` 闭合最内层 `2[c]`**，把 `"c"` 重复 2 次拼回外层前缀 `"a"` 得到 `"acc"`；**第二次 `]` 闭合最外层 `3[...]`**，把 `"acc"` 重复 3 次拼回空串前缀得到最终结果。弹栈的顺序恰好是「内层先、外层后」——这就是 LIFO 在嵌套解码里的直接体现。

## 代码

```cpp
// 主解：栈处理嵌套（官方「方法一：栈操作」的双栈版）。
//   - 用两个栈分别存「重复次数」和「外层前缀字符串」，外加当前层 res、当前数字 num。
//   - 遇 [ 压栈保存现场；遇 ] 弹栈拼接；数字累加解析；字母直接追加。

class Solution {
public:
    string decodeString(string s) {
        // ============ ① 声明两个栈 + 两个当前量 ============
        // stack<int> numStk：C++ STL 栈（<stack>），元素是 int。
        //   - 只能在栈顶操作：push 压入、pop 弹出（无返回值！）、top 看栈顶、empty 判空。均 O(1)。
        //   - 语义：存每个 [ 之前刚解析出来的重复次数 k。栈顶 = 最近一次压入（最内层）的次数。
        stack<int> numStk;

        // stack<string> strStk：元素是 string。
        //   - 语义：存进入每个 [ 之前、res 当时的内容（外层已拼好的前缀）。栈顶 = 最近一次压入（最内层）的前缀。
        //   - 注意 stack 存 string 是「按值」存——push 时会拷贝一份 string 进栈，pop 时销毁。
        //     本题字符串总长 ≤ 1e5，拷贝开销可接受；若追求极致可用引用计数，但没必要。
        stack<string> strStk;

        // string res：当前这一层正在拼的字符串（解码到目前的中间结果）。
        //   - 遇字母追加进 res；遇 ] 把 res 重复 k 次拼回外层前缀得到新 res。
        string res;

        // int num：当前正在解析的数字（可能多位），遇到 [ 时会用到，之后归零。
        int num = 0;

        // ============ ② 逐字符扫描 ============
        // for (char c : s)：范围 for，c 是 s 中每个字符的拷贝（不修改 s）。
        for (char c : s) {
            if (isdigit(c)) {
                // ---- 情况 1：数字。可能是多位，用 num*10 + 当前位 累加 ----
                // isdigit(c)：C 库函数（<cctype>），c 是 '0'~'9' 时返回非零（真）。
                //   - 注意：这里逐个字符判断，'12' 会拆成两次进入，靠 num*10 累加还原成 12。
                //   - c - '0'：把字符数字转成对应整数值（如 '3'-'0' = 3）。这是 char→int 的标准写法。
                num = num * 10 + (c - '0');

            } else if (c == '[') {
                // ---- 情况 2：左括号。压栈保存现场，然后重置当前层 ----
                // 先把「外层前缀 res」和「本括号的重复次数 num」分别压进两个栈。
                //   - 两栈同步 push，保证「同一层」的次数和前缀在两栈里的位置一一对应。
                //   - strStk.push(res)：拷贝一份当前 res 进栈（外层前缀留个底）。
                //   - numStk.push(num)：把刚解析完的数字压栈（它是这个 [ 的重复次数）。
                strStk.push(res);
                numStk.push(num);
                // 重置当前层：准备开始拼这个括号内部的内容。
                //   - res 清空（新的一层从空串开始拼）。
                //   - num 归零（这个数字已经存好了，下一轮要重新解析下一个数字）。
                res.clear();
                num = 0;

            } else if (c == ']') {
                // ---- 情况 3：右括号。弹栈拼接：外层前缀 + 当前层内容重复 k 次 ----
                // 取出本层的重复次数 k（最近压入的，所以是栈顶）。
                //   - numStk.top()：读栈顶（int），O(1)。
                //   - numStk.pop()：弹出栈顶（返回 void！必须先 top() 拿到值再 pop）。
                //   - 踩坑：空栈调 top() 是未定义行为。本题 s 合法，] 一定有匹配的 [，所以这里栈非空。
                int k = numStk.top();
                numStk.pop();

                // 取出外层前缀 prev（进入本括号之前的 res）。
                //   - strStk 也在同步进退，栈顶就是本层对应的外层前缀。
                string prev = strStk.top();
                strStk.pop();

                // 构造「prev + res 重复 k 次」：
                //   - 先用一个临时串 t 把 res 自身重复 k 次（循环 k 次，每次 t += res）。
                //   - 再 res = prev + t：外层前缀在前、重复串在后，顺序别反。
                //   - 为什么不直接 res = prev + res; 再重复？因为 prev 要先拼上一次，重复的是「拼接结果」，
                //     而我们要的是「res 本身重复 k 次后接在 prev 后」。用临时串 t 最不容易错。
                string t;
                while (k--) {       // k 次：先判断 k 是否非零、再自减；k=0 时循环不进
                    t += res;
                }
                res = prev + t;     // 外层前缀 + 本层内容重复 k 次，得到新的（上一层）res

            } else {
                // ---- 情况 4：字母。直接追加到当前层 res ----
                //   - isalpha(c) 时进这里（题目说只有小写字母/数字/方括号，所以 else 分支一定是字母）。
                //   - 不管字母在外层还是内层，都是「当前层」要拼的内容，直接 res += c。
                res += c;
            }
        }

        // 扫描结束，res 就是最终解码结果。
        //   - 最外层不会有 [ ] 包裹（题目保证合法），所以最终的 res 直接是答案。
        return res;
    }
};
```

## 复杂度

- **时间**：**O(S)**，其中 `S` 是**解码后字符串的长度**（不是输入 `s` 的长度）。
  - 每个字母字符被追加到某个中间 `res` 一次、又被拷贝拼接（`t += res` 或 `res = prev + t`）若干次，总工作量和输出长度同阶。
  - 官方分析：设解码后长度为 `S`，则时间复杂度为 O(S)；输入 `s` 长度最多 30，输出不超过 `10^5`。
- **空间**：**O(S)**。
  - 两个栈存的是「各层前缀 + 次数」，前缀串的总长度不超过解码后串长 `S`，所以栈空间 O(S)。
  - 中间临时串 `t`、`prev`、`res` 的总长度也不超过 `S`。
  - 综上 O(S)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么要用两个栈？能不能合并成一个，或者干脆不用栈？

一层的「现场」天然包含两部分——**重复次数 `k`** 和 **外层前缀字符串**。两个栈就是把这两部分**分开存**：`numStk` 只管次数、`strStk` 只管前缀，压栈弹栈时两栈同步，语义清楚。

完全可以合并成一个 `stack<pair<int,string>>`，每次压 `{num, res}`、弹出来用 `.first` 取次数、`.second` 取前缀，逻辑等价，少一个栈。这里拆成两个是为了可读性——读代码时一眼能看出「这个栈存的是次数、那个栈存的是字符串」。

至于「不用栈」：括号嵌套要求「后遇到的外层括号、现场要先存起来、内层处理完先取回」，这是**后进先出**结构。不用栈，你也得用数组模拟一个「从尾部增删」的结构，本质上还是栈。递归法（复盘里讲）其实就是**借函数调用栈**来当这个栈——把现场存在「上一层函数的局部变量」里，遇到 `[` 就递归进下一层。

### Q2：多位数字怎么处理？比如 `12[ab]`。

用 `num = num * 10 + (c - '0')` 边读边累加，关键是**不立刻用 num，而是等到遇到 `[` 才用它**。

`12[ab]` 扫描过程：`c='1'` → `num = 0*10+1 = 1`；`c='2'` → `num = 1*10+2 = 12`；`c='['` → 此时 `num=12` 正是这个括号的重复次数，压栈保存，再归零。如果用「读到一位数字就当重复次数」，遇到 `12` 会错误地重复 1 次再重复 2 次，全乱套。所以**数字必须连续解析到非数字为止**，这也是为什么要维护一个 `num` 变量在 `[` 之前持续累加。

> 官方原文用的是 `getDigits` 函数把一整段数字一次性读出来（返回 `string` 再 `stoi`），逻辑和这里等价，只是写法不同——一个是「分散累加、遇 `[` 用」，一个是「集中读完、直接用」。

### Q3：嵌套是怎么工作的？内层的 `res` 不会污染外层吗？

不会，因为**每次遇到 `[` 都把外层 `res` 压栈保存了，然后清空 `res` 重新开始**。内层从头拼，绝不会动到外层的内容。

看 `3[a2[c]]` 的过程：外层 `res="a"`（已经拼了 `a`）时遇到内层 `2[c]` 的 `[`，立刻把 `"a"` 压进 `strStk`、`res` 清空——内层开始拼自己的 `"c"`，根本看不到外层的 `"a"`。内层 `]` 时，再把 `"a"` 从 `strStk` 弹出来和内层结果拼接。**外层前缀被「冻结」在栈里，内层独立工作**，这就是栈能处理嵌套的根本原因。

### Q4：`]` 处拼接顺序为什么是 `prev + res*k`，不是 `res*k + prev`？

因为 `prev` 是「进入这个括号**之前**就有的外层内容」，它在时间上和位置上都**在前**。括号里的内容解码后是「**接在 prev 后面**」的，不是「**插在 prev 前面**」。

举个最直观的例子：`ab3[c]` 应该解成 `abccc`（`ab` 在前、`ccc` 在后）。扫描时：`res="ab"`（外层前缀），遇到 `3[c]`，处理 `]` 时 `prev="ab"`、`res="c"`、`k=3`，要的结果是 `ab + ccc`，所以是 `prev + res*k`。如果写成 `res*k + prev` 会得到 `cccab`，错了。

口诀：**前缀（外层）在前、重复（内层）在后**。

### Q5：`while (k--)` 这种写法到底循环几次？`k--` 和 `--k` 有什么区别？

`while (k--)` 会循环 **k 次**（当 `k=3` 时进 3 次循环体，分别是 `k` 为 3/2/1 时判断为真、`k` 退到 2/1/0，第 4 次 `k=0` 判断为假退出）。它的语义是「先判断 `k` 是否非零、再自减」，所以循环体执行 `k` 次。

`--k` 是「先自减、再判断」，当 `k=3` 时循环体只会执行 2 次（`k` 先变成 2 再判断为真、再变成 1 判断为真、再变成 0 判断为假退出），会少重复一次。这里要重复 `k` 次，所以用 `k--`。

更稳妥的写法是 `for (int i = 0; i < k; ++i) t += res;`，没歧义。这里用 `while (k--)` 是力扣 C++ 题解里的常见简写，知道它的语义即可。

## 复盘

### 可迁移套路：「栈处理嵌套结构——遇 `[` 压现场、遇 `]` 弹拼接」

这是**括号嵌套类问题**的通用骨架，和 20 有效的括号（匹配）、224/227 计算器（带括号的表达式求值）、32 最长有效括号是一脉相承的家族。核心模式：

1. **遇到「进入嵌套」的标记**（本题的 `[`、计算器的 `(`）→ 把当前现场（已拼的内容 + 当前次数/运算状态）**压栈保存**，重置状态准备处理内层；
2. **遇到「退出嵌套」的标记**（本题的 `]`、计算器的 `)`）→ 弹栈取回现场，把内层结果和外层状态**按规则合并**（本题是 `prev + res*k`，计算器是「继续外层运算」）；
3. 遇到普通元素（字母、数字）→ 按「当前层」的规则处理。

记住这条：**凡是「括号/嵌套」结构，第一反应就是栈；遇开括号压栈、遇闭括号弹栈**。本题和 20 有效的括号共用这个直觉，区别只在「弹栈时做什么」——20 是匹配并丢弃，394 是拼接出新字符串。

### 多位数字解析：`num*10 + 当前位`

凡是题面里数字可能多位、且数字夹在其它字符中间（地址、表达式、解码串），都用这个套路：**维护一个 `num` 变量，遇数字字符就 `num = num*10 + (c-'0')` 累加，遇非数字字符（或特定分隔符）时才把 `num` 用掉并归零**。计算器（224/227）、字符串转整数（8）都是这套。

### 「当前量 + 栈存历史」的分工

本题的代码结构值得记住：**当前正在处理的一层状态（`res`、`num`）放在外面当变量，历史各层的现场（次数、前缀）压进栈**。这样「当前层」永远直接可用，不用每次 `top()`，只有进入/退出括号时才动栈。这种「当前 + 栈」的分工，比官方原文的「所有 token 都入栈、最后再合并」更直观、也更快（少了一次 `reverse` 和反复拼 token）。两者思路同源，写法不同。

### 解法二：官方原版的 token 栈（`vector<string>` 模拟）

官方原文用的是「把每个 token（数字串、字母串、`[`）都压进一个 `vector<string>`，遇到 `]` 时从尾部一直弹到 `[`，把弹出的字母 token 拼起来、重复次数取自 `[` 前面那个数字 token」。本质和主解完全一样（都是栈），只是它**把次数也当 token 一起进栈**（所以只需要一个栈），代价是 `]` 处要 `reverse`（因为弹出的顺序和原顺序相反）。代码如下，作对比：

```cpp
// 官方「方法一」原版：用 vector<string> 当栈，数字/字母/括号都当 token 入栈。
class Solution {
public:
    string getDigits(string &s, size_t &ptr) {
        string ret = "";                       // 连续读一整段数字，返回数字串（如 "12"）
        while (isdigit(s[ptr])) {
            ret.push_back(s[ptr++]);
        }
        return ret;
    }

    string getString(vector<string> &v) {      // 把 v 里所有 string 顺序拼成一个串
        string ret;
        for (const auto &s : v) ret += s;
        return ret;
    }

    string decodeString(string s) {
        vector<string> stk;                    // 用 vector 当栈（push_back/pop_back/back）
        size_t ptr = 0;
        while (ptr < s.size()) {
            char cur = s[ptr];
            if (isdigit(cur)) {
                stk.push_back(getDigits(s, ptr));           // 数字串作为一个 token 入栈
            } else if (isalpha(cur) || cur == '[') {
                stk.push_back(string(1, s[ptr++]));         // 字母或 '[' 作为一个 token 入栈
            } else {
                ++ptr;                                       // cur == ']'，跳过
                vector<string> sub;
                while (stk.back() != "[") {                  // 弹到最近的 '[' 为止
                    sub.push_back(stk.back());
                    stk.pop_back();
                }
                reverse(sub.begin(), sub.end());             // 弹出顺序和原顺序相反，要翻转
                stk.pop_back();                              // 弹掉 '['
                int repTime = stoi(stk.back()); stk.pop_back(); // '[' 前那个 token 是次数
                string t, o = getString(sub);
                while (repTime--) t += o;                    // 重复 repTime 次
                stk.push_back(t);                            // 构造好的串作为一个 token 回填
            }
        }
        return getString(stk);
    }
};
```

### 解法三：递归（官方方法二）

递归法用**函数调用栈**代替手写栈：遇到数字 + `[` 就递归处理括号内的子串，返回内层结果后在外层重复。本质和栈法等价，只是「现场」存在函数的局部变量里、嵌套靠函数调用实现。

```cpp
// 官方「方法二」：递归下降解析。把 src/ptr 作为成员变量，简化递归参数传递。
class Solution {
public:
    string src;
    size_t ptr;

    int getDigits() {                            // 解析一段数字，返回整数值
        int ret = 0;
        while (ptr < src.size() && isdigit(src[ptr])) {
            ret = ret * 10 + src[ptr++] - '0';
        }
        return ret;
    }

    string getString() {
        if (ptr == src.size() || src[ptr] == ']') return "";   // 边界：空串或遇到右括号

        char cur = src[ptr];
        int repTime = 1;
        string ret;

        if (isdigit(cur)) {
            // 形如 k[encoded_string]：解析 k、跳过 '['、递归解析内部、跳过 ']'、重复
            repTime = getDigits();
            ++ptr;                               // 跳过 '['
            string str = getString();            // 递归解析括号内部
            ++ptr;                               // 跳过 ']'
            while (repTime--) ret += str;        // 内部结果重复 k 次
        } else if (isalpha(cur)) {
            // 形如 普通字母串：取当前字母，再递归处理后面的部分
            ret = string(1, src[ptr++]);
        }
        return ret + getString();                // 当前结果 + 后续递归结果
    }

    string decodeString(string s) {
        src = s;
        ptr = 0;
        return getString();
    }
};
```

- **时间 / 空间**：和栈法同阶，都是 O(S)。递归深度等于最大嵌套层数。
- **对比**：递归法代码更短、思路更接近「按语法规则自然展开」，但依赖**函数调用栈**，极端嵌套下可能爆栈（本题 `s.length <= 30`，嵌套层数有限，不会爆）。栈法是手写模拟，可控性更强、也没爆栈风险，工程上更稳。理解了任一种，另一种就是「换了个写法」。
