# 155 最小栈

- 难度：中等
- 标签：**栈**、**设计**
- 力扣链接：https://leetcode.cn/problems/min-stack/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「最小栈」（slug：`zui-xiao-zhan-by-leetcode-solution`）。正文主解是 **辅助栈（同步记录最小值）**（官方方法一）：用一个主栈存数据、一个辅助栈存「当前栈内最小值」，两个栈完全同步 push/pop，`getMin` 直接返回辅助栈栈顶。所有操作 O(1)。这是最小栈这类设计题最经典直观的写法。单栈存差值的优化法放在「复盘」作对比。

## 题目描述

设计一个支持 `push`，`pop`，`top` 操作，并能在**常数时间**内检索到最小元素的栈。

实现 `MinStack` 类：

- `MinStack()` 初始化堆栈对象。
- `void push(int val)` 将元素 `val` 推入堆栈。
- `void pop()` 删除堆栈顶部的元素。
- `int top()` 获取堆栈顶部的元素。
- `int getMin()` 获取堆栈中的最小元素。

**示例 1：**

```
输入：
["MinStack","push","push","push","getMin","pop","top","getMin"]
[[],[-2],[0],[-3],[],[],[],[]]

输出：
[null,null,null,null,-3,null,0,-2]

解释：
MinStack minStack = new MinStack();
minStack.push(-2);
minStack.push(0);
minStack.push(-3);
minStack.getMin();   --> 返回 -3.
minStack.pop();
minStack.top();      --> 返回 0.
minStack.getMin();   --> 返回 -2.
```

**提示：**

- `-2^31 <= val <= 2^31 - 1`
- `pop`、`top` 和 `getMin` 操作总是在**非空栈**上调用。
- `push`、`pop`、`top` 和 `getMin` 最多被调用 `3 * 10^4` 次。

> 关于接口：本题要实现的是一个 `MinStack` 类（不是普通的 `Solution` 类），包含构造函数 `MinStack()` 和 `push` / `pop` / `top` / `getMin` 四个方法。注意 `getMin` 要求 **O(1)** 返回当前栈内最小值——这正是难点：普通做法是 `getMin` 时遍历整个栈找最小，O(n)，但题目要常数时间，所以必须**在 push/pop 的同时就把最小值维护好**，不能等到查询时才算。

## 思路

> 本题主要参考力扣官方题解的「方法一：辅助栈」。

### 难点在哪？为什么不能只用一个栈？

普通栈（`stack<int>`）只支持 `push` / `pop` / `top`，都是 O(1)。但 `getMin`（取栈内最小）没有现成操作，朴素做法是遍历整个栈求最小，O(n)。题目偏偏要求 `getMin` 也是 O(1)，调用次数最高 `3 * 10^4`，O(n) 会超时。

那么能不能只维护**一个变量 `min_val`** 记录最小值？不行。设想栈里有 `[-3, 0, -2]`（栈顶 -3），`min_val = -3`。这时 `pop` 掉栈顶 -3，新的最小值应该是 `min(0, -2) = -2`——但**你早就忘了** `-2` 这个信息，单凭一个 `min_val` 变量没法回退到「次小值」。也就是说，最小值是**会随着 pop 变化的**，而一个标量变量只能记住当前的一个最小，记不住历史。

### 核心观察：每个元素入栈时的最小值，只取决于它和它下面的元素

这是官方题解的关键一句话，理解了它就理解了整道题。

栈是「先进后出」的。如果一个元素 `a` 入栈时，它下面已经压着 `b, c, d`，那么**只要 `a` 还在栈里，`b, c, d` 就一定都还在栈里**（要弹出 `b` 得先弹出 `a` 和它上面的元素）。所以「`a` 在栈顶的那一刻，栈里的元素集合是唯一确定的」——就是 `a` 加上它入栈那一刻下面所有的元素。

这意味着：**`a` 入栈时整个栈的最小值，就等于「`a` 入栈前栈的最小值」和「`a` 自己」取 min**。而且这个最小值**只要 `a` 还在栈里就始终有效**，因为 `a` 下面的元素不会被单独弹掉。

### 用辅助栈同步记录「到当前为止的最小值」

既然每个元素 `a` 入栈时都能算出「此时整个栈的最小值 `m`」，那就把 `(a, m)` 一一对应地存下来。最自然的做法是**再开一个辅助栈 `min_stack`**，和主栈 `x_stack` 完全同步 push / pop：

| 操作 | 主栈 `x_stack` | 辅助栈 `min_stack` |
|---|---|---|
| `push(x)` | 压入 `x` | 压入 `min(x, min_stack.top())`（当前最小值与 x 的较小者） |
| `pop()` | 弹出栈顶 | **同步**弹出栈顶 |
| `top()` | 返回 `x_stack.top()` | — |
| `getMin()` | — | 返回 `min_stack.top()`（栈顶永远存着「当前全栈最小值」） |

辅助栈栈顶的语义：**「主栈从底到当前栈顶这部分元素的最小值」**。因为主栈和辅助栈同步进退，辅助栈第 `i` 个元素恰好记录「主栈前 `i` 个元素的最小值」，栈顶就是整个主栈的最小值。

- `push` 时辅助栈压入 `min(新值, 辅助栈顶)`——要么新值更小、刷新记录，要么维持原最小；
- `pop` 时两个栈都弹一个——保持两层一一对应，辅助栈顶自动回退到「次小值」（这正是单变量做不到的）；
- `getMin` 直接读辅助栈顶，O(1)。

### 边界：辅助栈初始要压一个哨兵

构造函数里辅助栈先 `push(INT_MAX)`（一个极大值）作为「空栈时的最小值」。这样第一次 `push(x)` 时 `min(INT_MAX, x) = x`，逻辑统一，不用对「辅助栈为空」做特判。主栈不需要哨兵，因为主栈一开始就是空的、语义正确。

### 手动推导示例

跟踪官方示例，用 `(主栈 / 辅助栈)` 表示，都从左到右是底→顶：

```
构造 MinStack()：
  x_stack   = []
  min_stack = [INT_MAX]            ← 哨兵

push(-2)：
  x_stack.push(-2)                 → x_stack   = [-2]
  min_stack.push(min(INT_MAX,-2))  → min_stack = [INT_MAX, -2]
  （辅助栈顶 -2 表示「当前全栈最小是 -2」）

push(0)：
  x_stack.push(0)                  → x_stack   = [-2, 0]
  min_stack.push(min(-2, 0))       → min_stack = [INT_MAX, -2, -2]
  （0 比 -2 大，最小值仍是 -2，辅助栈再压一份 -2）

push(-3)：
  x_stack.push(-3)                 → x_stack   = [-2, 0, -3]
  min_stack.push(min(-2, -3))      → min_stack = [INT_MAX, -2, -2, -3]
  （-3 比 -2 小，刷新最小值为 -3）

getMin() → min_stack.top() = -3   ✓

pop()：
  x_stack.pop()   → x_stack   = [-2, 0]
  min_stack.pop() → min_stack = [INT_MAX, -2, -2]
  （两个栈同步弹一个；辅助栈顶回到 -2，正好是「剩下元素 -2, 0 的最小值」）

top() → x_stack.top() = 0         ✓

getMin() → min_stack.top() = -2   ✓
```

可以看到辅助栈的精妙之处：**它不是「去重后的最小值序列」，而是和主栈完全同长、每个位置都记录到该位置为止的最小值**。这样 pop 同步弹一个，辅助栈顶自动变成新栈的最小值，完全不用重新计算。

## 代码

```cpp
// 本题要实现的是 MinStack 类（不是 Solution 类），含构造函数 + push/pop/top/getMin 五个接口。
// 用两个 std::stack：主栈存数据，辅助栈同步存「到当前为止的最小值」。

class MinStack {
private:
    // ============ ① 两个栈的声明 ============
    // stack<int>：C++ STL 的栈容器适配器（默认基于 deque 实现）。
    //   - 只能访问栈顶（top），支持 push（入栈）、pop（出栈）、top（读栈顶）、empty（判空）。
    //   - 这些操作都是 O(1)。
    //   - 注意：stack 没有 begin()/end()，不能遍历，也没有 []。题目就只需要栈顶操作，正好。
    //   - 头文件 <stack> 力扣环境已默认包含，不用手写 #include。
    stack<int> x_stack;     // 主栈：正常存每个被 push 进来的元素
    stack<int> min_stack;   // 辅助栈：栈顶永远存「当前 x_stack 全栈的最小值」

public:
    // ============ ② 构造函数 ============
    // 初始化时往辅助栈压一个 INT_MAX 当哨兵：
    //   - INT_MAX 是 <climits> 里 int 的最大值（约 2.1e9），力扣默认环境已包含。
    //   - 作用：让第一次 push 时 min(INT_MAX, x) == x，逻辑统一，不用特判「辅助栈为空」。
    //   - 注意主栈 x_stack 不用压哨兵——它本来就该从空栈开始。
    MinStack() {
        min_stack.push(INT_MAX);
    }

    // ============ ③ push：两个栈同步压入 ============
    void push(int x) {
        x_stack.push(x);    // 主栈正常压入新元素
        // 辅助栈压入「当前辅助栈顶 与 x 的较小者」：
        //   - min(a, b)：C++ STL 算法（<algorithm>），返回 a、b 中较小者，O(1)。
        //   - min_stack.top()：读辅助栈栈顶，即「x 入栈之前整栈的最小值」。
        //   - 含义：若 x 更小，则刷新最小值为 x；否则最小值保持不变。
        //   - 踩坑：调用 top() 前栈必须非空。构造函数已压了 INT_MAX，这里辅助栈永远非空，安全。
        min_stack.push(min(min_stack.top(), x));
    }

    // ============ ④ pop：两个栈同步弹出 ============
    void pop() {
        x_stack.pop();      // 主栈弹出栈顶
        min_stack.pop();    // 辅助栈也弹一个，保持两层一一对应
        // 关键：辅助栈和主栈「同长」。主栈弹一个，辅助栈跟着弹一个，
        //   辅助栈顶就自动回到「弹掉那个元素入栈之前的最小值」，
        //   也就是新栈的最小值——这正是只用一个 min 变量做不到的（单变量记不住次小值）。
        //   注意 stack::pop() 返回 void，不返回栈顶元素！要先 top() 再 pop() 才能拿到值。
    }

    // ============ ⑤ top：只看主栈栈顶 ============
    int top() {
        return x_stack.top();   // top() 返回栈顶元素的引用（这里隐式拷贝成 int 返回值），O(1)。
        // 注意 top() 不会删除元素，要删除得再调 pop()。
    }

    // ============ ⑥ getMin：直接读辅助栈栈顶 ============
    int getMin() {
        return min_stack.top();
        // 辅助栈顶永远存「当前 x_stack 全栈的最小值」，O(1) 直接拿到，不用遍历。
        // 因为 push/pop 时辅助栈一直在同步维护，这里只是「读」，不修改。
    }
};
```

## 复杂度

- **时间**：所有操作（`push` / `pop` / `top` / `getMin`）都是 **O(1)**。
  - `stack` 的 `push` / `pop` / `top` 本身都是 O(1)；
  - 本题每个接口最多调用 2 次栈操作（`push` 调 2 次、`pop` 调 2 次，其余 1 次），再加一次 `min` 比较也是 O(1)，所以整体 O(1)。
  - 这正是题目「在常数时间内检索到最小元素」的硬性要求。
- **空间**：**O(n)**，其中 n 是总操作数。
  - 最坏情况下连续 `push` n 个元素，主栈和辅助栈各存 n 个元素（辅助栈还有构造时那 1 个哨兵 `INT_MAX`，可忽略）。
  - 两个栈都是 O(n)，合计 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么辅助栈要和主栈同步 push/pop？能不能辅助栈只在最小值变化时才动？

辅助栈「同步」是最省脑子的写法：主栈动一下、辅助栈跟着动一下，一一对应，不用想边界。它的代价是辅助栈会重复存一些「没用的最小值」（比如示例里连续两个 `-2`）。

另一种「不同步」写法是：辅助栈只在「新元素 ≤ 当前最小」时才压入，`pop` 时只有「弹出的元素 == 辅助栈顶」才弹辅助栈。这样辅助栈更短（去重了），但有两个坑：① 判等要用 `<=` 而不是 `<`，否则连续相同的最小值会漏存；② `pop` 时要先记下主栈弹出的值，再和辅助栈顶比较，逻辑更绕。两种写法时间和空间复杂度都是 O(1)/O(n)，官方推荐同步法，因为简单不易错。

### Q2：能不能只用一个栈，不要辅助栈？

可以，这就是「单栈存差值」法（见复盘）。核心思路是栈里不直接存 `x`，而是存 `x - 当前最小值`，另外用一个变量 `min_val` 记最小值。这样能用一个栈 + 一个变量同时表达「值」和「最小值」。代价是：① 用 `long long` 存差值以防 int 溢出（`x - min` 可能溢出 int 范围）；② push/pop 逻辑变绕，读代码的人要想半天才懂。

辅助栈法用「多一个栈」换「逻辑直观」，是典型的**以空间换可读性**，面试和工程都更推荐它。

### Q3：辅助栈里存的到底是什么？为什么 pop 同步弹一个就能拿到正确的新最小值？

辅助栈第 `i` 个元素 = 「主栈前 `i` 个元素的最小值」（从底数到顶）。因为栈是先进后出，主栈前 `i` 个元素永远不可能在「第 i+1 个元素还在栈里」的时候被单独弹掉，所以这个「前缀最小值」在 `a` 出栈前始终有效。

`pop` 时主栈和辅助栈同时弹一个，辅助栈顶就从「前 n 个元素的最小值」变成「前 n-1 个元素的最小值」——而主栈弹掉栈顶后剩下的恰好就是前 n-1 个元素，二者再次对齐。所以「同步弹」天然维护了正确性，根本不用重新算。

### Q4：构造函数里辅助栈为什么要先 push 一个 INT_MAX？不压会怎样？

不压的话，第一次 `push(x)` 执行 `min(min_stack.top(), x)` 时辅助栈是空的，`top()` 在空栈上调用是**未定义行为**（可能崩、可能返回垃圾值）。

压了 `INT_MAX` 当哨兵后，第一次 `push(x)` 时 `min(INT_MAX, x) == x`，辅助栈栈顶正确变成 `x`（第一个元素本身就是最小），后续逻辑全部统一，代码里再不用写 `if (min_stack.empty())`。这是「用哨兵简化边界」的通用技巧（和 146 LRU 缓存里的伪头/伪尾节点是同一思路）。

注意：`getMin` 按题意只在非空栈上调用，所以不会把那个 `INT_MAX` 哨兵直接返回出去（至少 push 过一次后辅助栈顶才是真实最小值）。

## 复盘

- **核心套路：「辅助栈 / 辅助数据结构同步维护额外信息」** 是一类通用思路。当题目要求在一个数据结构上 O(1) 查询某个**会随增删变化**的统计量（最小值、最大值、和、某种状态）时，不要想着在查询时现算（那是 O(n)），而是**在每次增删时就把这个量同步维护好**。多开一个「辅助栈 / 辅助数组 / 伴随变量」记录它，让辅助结构和主结构同生共死。本题（辅助栈存前缀最小值）、739 每日温度（单调栈）、84 柱状图最大矩形（单调栈存下标）都是这个家族的。
- **关键记忆点**：
  1. **两个栈同长、同 push、同 pop**——这是「同步辅助栈」法的全部要义。
  2. **辅助栈顶 = 当前主栈的最小值**，`getMin` 直接读栈顶。
  3. **push 辅助栈压 `min(新值, 辅助栈顶)`**；构造时压一个 `INT_MAX` 当哨兵，免特判。
  4. STL 的 `stack::pop()` 返回 `void`，要先 `top()` 再 `pop()` 才能拿到值（本题 `pop` 接口不用返回值，但自己写代码时要留心）。
- **易错点**：
  - 只用单个 `min_val` 变量，`pop` 掉最小值后无法回退到次小值——必须用栈把每个时刻的最小值都存下来。
  - 「不同步」写法里用 `<` 而不是 `<=` 判定是否压辅助栈，会漏掉连续相同最小值（如连续两个 `-3`）。
  - 忘了构造函数压哨兵，第一次 `push` 时 `top()` 空栈未定义行为。

### 解法二：单栈存差值（不用辅助栈，对比用）

思路：栈里不存 `x` 本身，而是存 `x - min_val`（`min_val` 是「这次 push 之前的最小值」，单独用一个变量维护）。这样栈里每个元素都隐含编码了「它和当时最小值的关系」，配合 `min_val` 就能反推出原始值和新最小值。

```cpp
class MinStack {
    // 栈里存「当前值 - 当前最小值」的差值；min_val 单独维护当前最小值。
    // 注意要用 long long，因为 x - min_val 可能超出 int 范围（如 x=INT_MAX, min_val=INT_MIN）。
    stack<long long> diff;
    long long min_val;

public:
    MinStack() : min_val(0) {}

    void push(int x) {
        if (diff.empty()) {
            // 第一个元素：差值记 0，最小值就是它本身
            diff.push(0);
            min_val = x;
        } else {
            // 差值 = x - min_val；若为负说明 x 更小，要更新 min_val
            long long d = (long long)x - min_val;
            diff.push(d);
            if (d < 0) min_val = x;   // x 是新最小值
        }
    }

    void pop() {
        long long d = diff.top();
        diff.pop();
        // 若弹出的差值为负，说明栈顶当时是「新最小值」，pop 后要把它加回去恢复上次最小值
        if (d < 0) {
            min_val = min_val - d;    // 等价于 min_val = 上次的 min_val
        }
    }

    int top() {
        long long d = diff.top();
        // 若差值 >= 0，原始值 = min_val + d；若 < 0，栈顶本身就是 min_val
        return d < 0 ? (int)min_val : (int)(min_val + d);
    }

    int getMin() {
        return (int)min_val;
    }
};
```

- **时间**：所有操作 O(1)。**空间**：O(n)（一个栈 + 一个变量，比辅助栈法少一个栈的常数）。
- **对比**：省了一个栈的内存（常数意义），但**代码明显更绕**——push/pop/top 三处都要分「差值正负」讨论，还要用 `long long` 防溢出。可读性远不如辅助栈法。面试和工程场景都更推荐辅助栈法，这个写法当作「哦还能这么玩」了解即可。
