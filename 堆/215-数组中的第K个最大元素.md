# 215 数组中的第K个最大元素

- 难度：中等
- 标签：数组、分治、快速选择、排序、**堆（优先队列）**
- 力扣链接：https://leetcode.cn/problems/kth-largest-element-in-an-array/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/kth-largest-element-in-an-array/solution/shu-zu-zhong-de-di-kge-zui-da-yuan-su-by-leetcode-2/)（slug：`shu-zu-zhong-de-di-kge-zui-da-yuan-su-by-leetcod-2`，官方篇）。正文主解是 **小根堆（维护大小为 K）**，O(n log k) 时间 O(k) 空间，与「堆」目录主题最对应；官方的**快速选择**（平均 O(n)）解法放在「复盘」作对比——快选更快但堆法更直观稳定。

## 题目描述

给定整数数组 `nums` 和整数 `k`，请返回数组中第 `k` 个最大的元素。

请注意，你需要找的是数组排序后的第 `k` 个最大的元素，而不是第 `k` 个**不同**的元素。

你必须设计并实现时间复杂度为 `O(n)` 的算法解决此问题。

**示例 1：**

```
输入: [3,2,1,5,6,4], k = 2
输出: 5
```

**示例 2：**

```
输入: [3,2,3,1,2,4,5,5,6], k = 4
输出: 4
```

**提示：**

- `1 <= k <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

> 读题注意：「第 k 个最大的元素」指的是**升序排序后倒数第 k 个**（也就是降序排序后正数第 k 个），**不去重**。例如 `[3,2,3,1,2,4,5,5,6]` 升序是 `[1,2,2,3,3,4,5,5,6]`，倒数第 4 个是 `4`（不是去重后再数）。

## 思路

> 正文主解是「维护大小为 K 的小根堆」，这是 Top-K 问题的经典模板。官方题解里堆排（手写大根堆）和快速选择都讲了，这里用 STL `priority_queue` 的小根堆写法，更简洁直观。

### 暴力想法：整体排序 O(n log n)

最直接的做法：把 `nums` 整个排序（升序），然后返回 `nums[n - k]`（倒数第 k 个）。`sort` 是 O(n log n)，能过，但题目要求 O(n)，严格说不达标。而且我们**其实不需要整个数组都有序**——只要知道「最大的 k 个里最小的那一个」就够了，剩下的元素具体顺序根本不关心。

### 关键观察：只关心「最大的 k 个」，不需要全排序

第 k 大 = 「最大的 k 个元素里，最小的那一个」。

那么只要想办法**把最大的 k 个留住**，再从这 k 个里挑最小值即可。用一个**容量为 k 的容器**始终保存「目前见过的、较大的 k 个数」，遍历一遍数组后，这个容器里的最小值就是答案。

### 为什么是小根堆

要让这个「容量 k 的容器」能高效地「丢掉最小的、留住较大的」，**小根堆**天然合适：

- 小根堆的**堆顶总是最小值**，所以我们能 O(1) 知道「当前 k 个里最小的是谁」；
- 新来一个元素时，如果它比堆顶大，就说明它有资格挤进「最大的 k 个」，把堆顶（最小的）踢出去；如果它比堆顶还小，那它连前 k 大都进不去，直接不要。

**为什么不用大根堆？** 大根堆堆顶是最大值，能 O(1) 知道「最大的那个是谁」，但本题要的是「第 k 大」（即最大的 k 个里的最小值），用大根堆的话你得把所有 n 个元素都塞进去（O(n) 空间）再 pop k 次，或者干脆堆排。而**小根堆只放 k 个**，空间 O(k)、每次调整 O(log k)，更省。一句话：**求第 k 大 / Top-K，固定大小的容器要随时能「丢掉最小」，所以用小根堆。**

### 算法（小根堆维护大小 K）

1. 建一个**空的小根堆**。
2. 遍历 `nums`，每个元素都 `push` 进堆：
   - 一旦堆大小超过 `k`，就 `pop` 堆顶（小根堆的堆顶是当前最小值，踢掉它 = 扔掉一个「不够大」的）。
3. 遍历结束后，堆里恰好留下「最大的 k 个元素」，**堆顶就是其中最小的，即第 k 大**。

### 手动推导 `nums = [3,2,1,5,6,4], k = 2`

小根堆堆顶永远是最小值；当 size 超过 2 时把最小的踢掉。追踪堆的内容：

```
num=3 : push → {3}              size=1
num=2 : push → {2,3}(顶是2)     size=2
num=1 : push → {1,3,2}(顶是1)   size=3>2 → pop掉1 → {2,3}(顶是2)
num=5 : push → {2,3,5}(顶是2)   size=3>2 → pop掉2 → {3,5}(顶是3)
num=6 : push → {3,5,6}(顶是3)   size=3>2 → pop掉3 → {5,6}(顶是5)
num=4 : push → {4,6,5}(顶是4)   size=3>2 → pop掉4 → {5,6}(顶是5)
遍历完，堆顶 = 5 ✓（第 2 大确实是 5）
```

最终堆里 `{5, 6}` 就是最大的 2 个，堆顶 `5` 是其中最小的，即第 2 大。

## 代码

```cpp
class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        // priority_queue<int, vector<int>, greater<int>>：小根堆（最小元素在堆顶）。
        //   - 头文件 <queue>，和 queue 共用一个头文件，力扣 C++ 模板默认已包含。
        //   - 三个模板参数的含义：
        //       1) int               —— 存的元素类型（本题存数值）。
        //       2) vector<int>       —— 底层容器，priority_queue 是「容器适配器」，
        //                               必须基于支持随机访问的容器，默认就是 vector。
        //       3) greater<int>      —— 比较器。greater 表示「较大的更「小」」，
        //                               实际效果是「最小元素浮到堆顶」→ 小根堆。
        //   - ⚠️ 踩坑：priority_queue<int> （只写一个参数）默认是大根堆（最大元素在堆顶），
        //     因为默认比较器是 less<int>。要变**小根堆**必须显式写全三个参数
        //     priority_queue<int, vector<int>, greater<int>>——这是本题 STL 的核心！
        //   - 常用方法（都是 O(log n) 调整，top() 是 O(1)）：
        //       push(x)：插入元素并向上调整；
        //       pop()：删除堆顶（不是任意元素！），向下调整；
        //       top()：返回堆顶 const 引用（小根堆里就是当前最小值）；
        //       size()：元素个数；empty()：是否为空。
        //   - priority_queue 没有 clear()、没有 erase()，也**不能遍历**（底层容器受保护），
        //     只能通过 top()/pop() 一个一个取出。
        priority_queue<int, vector<int>, greater<int>> q;

        // 范围 for 循环：逐个把 nums 的元素（按值拷贝，int 无所谓）送进堆。
        for (int num : nums) {
            q.push(num);            // 先把当前元素入堆，再判断是否超容。
            // 维护「堆大小恰好为 k」：一旦超过 k，就把堆顶（小根堆里最小的）弹掉。
            //   - 弹最小 = 扔掉一个「不够大」的，只留下较大的 k 个。
            //   - q.size() 返回 size_t（无符号），和 k（int）比较时会自动转；
            //     这里 size 最多 k+1，不会发生负数转无符号的坑，写 > k 即可。
            if ((int)q.size() > k) {
                q.pop();            // 删除堆顶，O(log k)
            }
        }

        // 遍历结束后，堆里恰是「最大的 k 个」，堆顶是其中最小值 = 第 k 大。
        //   - top() 返回堆顶 const 引用，O(1)，不删除元素。
        return q.top();
    }
};
```

## 复杂度

- **时间**：O(n log k)
  - 遍历 n 个元素，每个元素一次 `push`（O(log k)）和至多一次 `pop`（O(log k)），共 n 次堆操作，每次 O(log k)，总计 O(n log k)。当 k 远小于 n 时（如 k=常数），接近线性。
  - 说明：题目描述里写了「请实现 O(n) 的算法」，严格说堆法是 O(n log k) 不是 O(n)。但 log k 通常很小（k ≤ 10^5 时 log k ≈ 17），力扣的实际时间限制并不拒绝这个解法，能 AC。若要严格 O(n)，用「复盘」里的快速选择（平均 O(n)，最坏 O(n²)，随机化后期望 O(n)）。
- **空间**：O(k)
  - 堆里最多同时存 `k + 1` 个元素（push 完还没 pop 的瞬间），即 O(k)。原地修改输入数组则不计。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么用**小根堆**而不是大根堆？

因为题目要的是「第 k 大」=「最大的 k 个里的最小值」。我们维护一个**容量 k 的窗口**，要随时能把「窗口里最小的」踢出去、给更大的腾位置——**小根堆的堆顶恰好就是这个「最小值」**，O(1) 就能拿到并 O(log k) 弹掉。

如果用大根堆，堆顶是最大值，没法直接知道「这 k 个里最小的是谁」，也就没法决定该踢谁。用大根堆只能把**全部 n 个**元素都塞进去再 pop k-1 次（空间 O(n)），或者干脆做完整堆排序，都不如小根堆只放 k 个来得省。

一句话记忆：**「求 Top-K 大 → 容量 k 的小根堆」；反过来「求 Bottom-K 小 → 容量 k 的大根堆」。** 比较器和「要的方向」相反，这样堆顶才正好是要丢的边界。

### Q2：`greater<int>` 是怎么让堆变成小根堆的？

`priority_queue` 默认比较器是 `less<int>`，语义是「a < b 时 a 优先级低」，结果**大的浮到顶**→ 大根堆。换成 `greater<int>` 后，语义变成「a > b 时 a 优先级低」，结果**小的浮到顶**→ 小根堆。

可以这样记：**比较器的名字和堆顶性质「相反」**——`less` 出大根堆，`greater` 出小根堆。要小根堆就写 `greater`。

注意模板参数必须**写全三个**：`priority_queue<int, vector<int>, greater<int>>`。只写 `priority_queue<int>` 会用默认的 `less`（大根堆）；只写 `priority_queue<int, greater<int>>` 编译不过，因为第二个参数（底层容器）不能省。

### Q3：为什么 `pop` 掉的是「最小的」？被弹掉的元素会不会其实是答案？

`pop` 弹的是小根堆堆顶，也就是当前堆里最小的那个。我们只在 **size > k** 时才弹，弹之前堆里已经有 k+1 个元素了。这 k+1 个里**最小的那一个**连「前 k 大」都进不去（后面就算再来更大的，它只会更靠后），所以它**绝对不可能是第 k 大**，放心扔掉。

换句话说：弹掉的全是「确定进不了前 k 大」的元素，不会误删答案。遍历结束时，所有比堆顶小的元素都已经被挡在堆外或弹走了，剩下的 k 个就是最大的 k 个。

### Q4：堆大小为什么始终保持 `k`？

因为 `push` 后紧跟一个 `if (size > k) pop()`。每轮循环结束时堆大小最多是 k（前 k 个元素时堆从 0 长到 k，之后每 push 一个就 pop 一个，恒为 k）。这个「容量 k」是本题空间 O(k) 和每次操作 O(log k) 的来源。也可以写成「先判 size==k 且 num>堆顶 再 push」，但「先 push 再 pop」写法更简洁、不用特判，是常见模板。

## 复盘

- **核心套路（Top-K 模板）**：「求第 k 大 / 最大的 k 个」→ **维护一个大小为 k 的小根堆**，遍历一遍数组，每轮 `push` 后若超容就 `pop` 堆顶，结束时堆顶即答案。时间 O(n log k)、空间 O(k)。这是一道**模板题**，套路可迁移：
  - **347 前 K 个高频元素**：先用哈希表统计频率，再对「频率」套这个「大小 k 的小根堆」模板（堆里放 `{频率, 元素}`，按频率比大小）。
  - **295 数据流的中位数**：用**一个大根堆 + 一个小根堆**对半分，是 Top-K 模板的进阶（动态维护中位数）。
  - 凡是「只要前 K 个、不关心其余」的题，先想「大小 K 的堆」。
- **求 Top-K 用「容量 k 的堆」比整体排序省在哪**：排序要把所有 n 个元素都排好（O(n log n)），而容量 k 的堆只关心 k 个，每次调整只 O(log k)。当 n 很大、k 很小时优势明显（典型如海量数据求 Top-K）。
- **方向记忆**：「第 k 大」用小根堆（容量 k）、「第 k 小」用大根堆（容量 k）。比较器名字和堆顶性质相反：`greater` → 小根堆、`less` → 大根堆。
- **题目里「O(n)」的要求**：堆法 O(n log k) 严格说不满足，但能 AC。若面试官追问严格 O(n)，转快速选择。

### 解法二：快速选择（官方方法一，平均 O(n)）

> 本题正文主解是 STL 小根堆；这里放官方题解的快速选择法，平均时间 O(n) 更快，但最坏 O(n²)、思路比堆复杂。

**思路**：借用快速排序的「分割（partition）」——每次随机选一个基准 `pivot`，把数组分成「小于 pivot」和「大于等于 pivot」两段，pivot 落在它的最终位置 `j`。要找「升序第 `n - k` 位」（即第 k 大），只需判断目标位落在哪半边，然后**只递归那一半**（另一半直接丢掉，所以平均每次把规模折半，总工作量 O(n)）。这就是「快速选择」比快排快的原因——快排两边都要递归，快选只递归一边。

```cpp
class Solution {
public:
    // quickselect：在 nums[l..r] 范围内找「升序第 k 位（下标 k）」的元素。
    int quickselect(vector<int> &nums, int l, int r, int k) {
        if (l == r)                  // 只剩一个元素，就是它
            return nums[k];
        // 以 nums[l] 为基准做一次 partition（双向扫描）。
        int partition = nums[l], i = l - 1, j = r + 1;
        while (i < j) {
            do i++; while (nums[i] < partition);   // i 右移到第一个 >= pivot 的
            do j--; while (nums[j] > partition);   // j 左移到第一个 <= pivot 的
            if (i < j)
                swap(nums[i], nums[j]);            // 交换使左小右大
        }
        // 此时 j 是 pivot 划分点；[l..j] 都 <= pivot，[j+1..r] 都 >= pivot。
        if (k <= j) return quickselect(nums, l, j, k);       // 目标在左半，只递归左半
        else        return quickselect(nums, j + 1, r, k);   // 目标在右半，只递归右半
    }

    int findKthLargest(vector<int> &nums, int k) {
        int n = nums.size();
        // 第 k 大 = 升序第 (n-k) 位（从 0 开始的下标）。
        return quickselect(nums, 0, n - 1, n - k);
    }
};
```

- **时间**：平均 O(n)（每次只递归一半，等比数列求和 n + n/2 + n/4 + ... = O(n)）；最坏 O(n²)（每次都选到最差基准，可随机化 pivot 规避，期望 O(n)）。
- **空间**：平均 O(log n) 递归栈，最坏 O(n)。
- **对比堆法**：快选平均更快（O(n) vs O(n log k)），但**会修改原数组**（原地 partition）、最坏情况不稳、思路更绕。堆法胜在**稳定、直观、不依赖基准运气**，且是 Top-K 万能模板，因此正文主解选堆法。两种都应掌握。
