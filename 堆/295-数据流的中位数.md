# 295 数据流的中位数

- 难度：困难
- 标签：设计、双指针、数据流、排序、**堆（优先队列）**
- 力扣链接：https://leetcode.cn/problems/find-median-from-data-stream/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「数据流的中位数」（slug：`shu-ju-liu-de-zhong-wei-shu-by-leetcode-ktkst`）。正文主解是 **双堆（大根堆存较小半 + 小根堆存较大半）**（官方方法一「优先队列」），addNum O(log n)、findMedian O(1)。这是 **堆组的收尾题**，也是「双堆维护动态中位数」套路的教科书示范。难点不在堆本身，而在「为什么两个堆摞起来就能 O(1) 取中位数」这一步抽象，以及 addNum 时怎么维持两个不变量。官方方法二「有序集合 + 双指针」（`multiset` + 迭代器，addNum O(log n)、findMedian O(1)）放在「复盘」对比。

## 题目描述

中位数是有序整数列表中的中间值。如果列表的大小是偶数，则没有中间值，中位数是两个中间值的平均值。

- 例如 `arr = [2,3,4]` 的中位数是 `3`。
- 例如 `arr = [2,3]` 的中位数是 `(2 + 3) / 2 = 2.5`。

实现 `MedianFinder` 类:

- `MedianFinder()` 初始化 `MedianFinder` 对象。
- `void addNum(int num)` 将数据流中的整数 `num` 添加到数据结构中。
- `double findMedian()` 返回到目前为止所有元素的中位数。与实际答案相差 `10^-5` 以内的答案将被接受。

**示例 1：**

```
输入
["MedianFinder", "addNum", "addNum", "findMedian", "addNum", "findMedian"]
[[], [1], [2], [], [3], []]
输出
[null, null, null, 1.5, null, 2.0]

解释
MedianFinder medianFinder = new MedianFinder();
medianFinder.addNum(1);    // arr = [1]
medianFinder.addNum(2);    // arr = [1, 2]
medianFinder.findMedian(); // 返回 1.5 ((1 + 2) / 2)
medianFinder.addNum(3);    // arr = [1, 2, 3]
medianFinder.findMedian(); // 返回 2.0
```

**提示：**

- `-10^5 <= num <= 10^5`
- 在调用 `findMedian` 之前，数据结构中至少有一个元素
- 最多 `5 * 10^4` 次调用 `addNum` 和 `findMedian`

> 关于接口：本题要实现的是一个 `MedianFinder` 类（不是普通的 `Solution` 类），含构造、`addNum(int)`、`findMedian()` 三个方法。和静态数组求中位数（如第 4 题）不同，这里数据是**流式不断进来**的——每塞一个数都可能立刻被问中位数，所以必须**动态维护**一个能随时 O(1) 报中位数的状态，不能每次 findMedian 都重新排序。`addNum`+`findMedian` 总调用次数最多 `5*10^4`，每次都排序 O(n log n) 会超时，必须让 findMedian 退化为 O(1)。

## 思路

> 本题主要参考力扣官方题解「方法一：优先队列」。下面把「为什么用两个堆」「怎么平衡」这两个核心问题一点点拆开讲。

### 第一步：中位数到底意味着什么——它是一个「分界点」

和第 4 题（两个正序数组的中位数）一样，本题的关键也是先想清楚中位数的**本质**：中位数不是「排序后中间那个数」这个表象，而是把全体数**切成两半**的那个分界点。

> 把已知的所有数分成两半，使 **左半（较小的一半）所有数 ≤ 右半（较大的一半）所有数**，且两半大小差不超过 1。这个分界就是中位数：
> - 总个数**奇数**：中位数 = 多出来的那半的边界值（左半多一个就取左半最大，右半多一个就取右半最小）。
> - 总个数**偶数**：中位数 = 左半最大值 与 右半最小值 的平均。

所以「随时报中位数」等价于「随时知道这两个值：**左半的最大值** 和 **右半的最小值**」。一旦接受这个等价，问题就从「找中间那个数」变成「动态维护左半最大 / 右半最小」。

### 第二步：为什么一个堆不够、需要两个堆

如果只用一个堆存所有数，堆顶要么是最大值（大根堆）要么是最小值（小根堆），但**不可能同时**给出「左半最大」和「右半最小」——中位数要的是两个。

那就用**两个堆**，把它们「对口」摞起来：

```
         左半（较小的一半）           |        右半（较大的一半）
   小 ←────────────────── 大         |    小 ──────────────────→ 大
                          ↑                    ↑
                     左半的最大              右半的最小
                     （大根堆堆顶）        （小根堆堆顶）
                     = 中位数左侧候选       = 中位数右侧候选
```

- **大根堆 `queMax`** 存「较小的一半」。大根堆的堆顶是这半里的**最大值**，正好就是「左半的最大值」= 中位数左侧候选。
- **小根堆 `queMin`** 存「较大的一半」。小根堆的堆顶是这半里的**最小值**，正好就是「右半的最小值」= 中位数右侧候选。

两个堆顶摞在一起，正好夹住了中位数所在的位置。findMedian 只要看两个堆顶（和两堆大小）就够了，**O(1)**。这就是「两个堆摞起来就能 O(1) 取中位数」的全部秘密。

> 注意「大根堆存较小半」听起来别扭：明明是较大的数为什么放进大根堆？关键在于「较小半」是相对**全体**而言的——这一半装的虽然都是「排在前面的较小数」，但堆关心的是**这半内部的相对顺序**，我们要的是这半里最大的那个（作为左半边界），所以用大根堆。另一边同理。

### 第三步：两个必须时刻维持的不变量

光两个堆还不够，要让它们始终能正确报中位数，每次 addNum 后都必须保持两条「不变量（invariant）」：

1. **大小关系**：`queMax.top() <= queMin.top()`（大根堆顶 ≤ 小根堆顶）。即左半任意数 ≤ 右半任意数，保证「分界」是对的。
2. **个数关系**：`queMax.size()` 与 `queMin.size()` 最多差 1。约定奇数个时让 `queMax`（较小半）多放一个，于是奇数时中位数就是 `queMax.top()`，偶数时是两堆顶平均。

只要这两条始终成立，findMedian 的逻辑就是死的（看大小谁多 → 取堆顶 / 取平均）。所有「聪明」都集中在 addNum 怎么维持这两条。

### 第四步：addNum 的平衡逻辑——先放进对应堆，再修正

官方 addNum 写法很简洁，分两步走：

**第 1 步：判断 num 属于哪半，先塞进去。**

- 若 `queMax` 为空 或 `num <= queMax.top()`：num 属于**较小半**，先 push 进 `queMax`（大根堆）。
- 否则（`num > queMax.top()`）：num 属于**较大半**，push 进 `queMin`（小根堆）。

> 为什么拿 `queMax.top()`（左半最大值）当判据？因为左半最大值就是两半的分界线——比它小或相等的数自然归左半，比它大的归右半。这一步先保证了「num 进对了那一堆」，但**可能破坏个数平衡**（见第 2 步）。

**第 2 步：检查个数差，超了就把堆顶「搬」到另一堆。**

塞完后只可能有两种失衡：

- `queMax` 比 `queMin` 多了 **2 个或更多**（`queMax.size() > queMin.size() + 1`）：把 `queMax` 堆顶（左半最大值）搬给 `queMin`。搬完后左半最大值变成了右半最小值，两半个数差回到 ≤ 1，大小关系也仍然成立（搬到右半的这个数本来就 ≤ 右半原本的最小值……不对，等等）。

  让我理一下「搬过去大小关系为什么仍成立」：搬之前 `queMax.top() <= queMin.top()`。搬的是 `queMax.top()`（设为 `x`），而 `x <= queMin.top()`，所以 `x` 放进 `queMin` 后成为新的 `queMin.top()`（因为 `x` 比原最小值还小），新 `queMin.top() = x`。新 `queMax.top()` 是搬走 `x` 后左半剩下的最大值，必然 ≤ `x`（因为 `x` 原来是左半最大）。所以新 `queMax.top() <= x = 新 queMin.top()`，大小关系保持。✓

- `queMin` 比 `queMax` **多**（`queMin.size() > queMax.size()`）：把 `queMin` 堆顶（右半最小值）搬给 `queMax`。同理可证搬完后两条不变量都成立。注意这里用的判据是「>」（而不是「> +1」），因为我们约定**奇数时让 `queMax` 多一个**，所以 `queMin` 一旦追平就必须让它搬过去给 `queMax`，绝不允许 `queMin` 比 `queMax` 多。

这两次「搬」都是一次 push + 一次 pop，**O(log n)**，就是 addNum 的全部成本。

> 为什么这样搬能同时维持两条不变量？因为搬的是**堆顶**——堆顶本来就是这一半的极值（左半最大 / 右半最小），搬到对面后天然落在边界上，新的极值也由堆自动维护。这就是用堆的最大好处：**「找半个内部的最值」免费（O(1) 拿堆顶），「调整半个内部的最值」也便宜（O(log n) push/pop 后堆自洽）**。换成数组，光维护半个的最值就要 O(n)。

### 第五步：findMedian 的收尾——奇偶看大小

维持好两条不变量后，findMedian 直接按两堆大小判：

- `queMax.size() > queMin.size()`：总个数奇数，左半多一个，中位数 = `queMax.top()`。
- 否则（两堆相等）：总个数偶数，中位数 = `(queMax.top() + queMin.top()) / 2.0`。

（按上面的约定，`queMin` 永远不可能比 `queMax` 多，所以不用处理那种情况。）

注意 `/ 2.0` 不能写成 `/ 2`：`2.0` 是 `double`，整个表达式被提升为浮点运算得到小数；写 `/ 2`（整数除法）会截断小数，`(1+2)/2` 得 1 而不是 1.5。

### 手动推导：`addNum(1), addNum(2), findMedian, addNum(3), findMedian`，期望 `1.5` 然后 `2.0`

用 `[左半 queMax 大根堆 | 右半 queMin 小根堆]` 表示，堆顶标 `*`。初始两堆都空。

```
addNum(1)：queMax 空 → 先塞 queMax
  queMax = [1*]      queMin = []
  检查：queMax.size()(1) > queMin.size()+1(1)? 否，不搬
  状态：[1* | ]              （queMax 多 1，符合奇数约定）

addNum(2)：2 > queMax.top()(1) → 塞 queMin
  queMax = [1*]      queMin = [2*]
  检查：queMin.size()(1) > queMax.size()(1)? 否，不搬
  状态：[1* | 2*]             （两堆相等，1<=2 ✓）

findMedian()：queMax.size()==queMin.size() → (1+2)/2.0 = 1.5 ✓

addNum(3)：3 > queMax.top()(1) → 塞 queMin
  queMax = [1*]      queMin = [2,3]，堆顶 2*
  检查：queMin.size()(2) > queMax.size()(1)? 是！搬 queMin 堆顶(2) 给 queMax
  queMin pop 2；queMax push 2
  queMax = [1,2] 堆顶 2*    queMin = [3*]
  状态：[2* | 3*]            （queMax 多 1，2<=3 ✓）

findMedian()：queMax.size()(2) > queMin.size()(1) → 返回 queMax.top() = 2.0 ✓
```

最终左半 `[1,2]` 右半 `[3]`，中位数 = 左半最大 = 2，和「排序后 `[1,2,3]` 的中位数 2」一致。

## 代码

```cpp
class MedianFinder {
private:
    // ============ ① 两个堆的声明（本题核心，务必看懂） ============
    //
    // priority_queue<int>：C++ STL 的「优先队列」，本质是堆（默认大根堆）。
    //   - 签名 priority_queue<元素类型, 底层容器, 比较器>。后两个模板参数可省略，
    //     省略时 = priority_queue<int, vector<int>, less<int>>，即大根堆。
    //   - 堆顶通过 .top() 访问，O(1)；.push(x) 插入 O(log n)；.pop() 删堆顶 O(log n)。
    //   - 踩坑：priority_queue 没有 .begin()/.end()，不能遍历；也不支持按值删，只能删堆顶。
    //     （想按值删要用 multiset，见复盘方法二。）
    //
    // queMax：大根堆，存「较小的一半」。
    //   - 堆顶 queMax.top() = 这半的最大值 = 左半边界 = 中位数左侧候选。
    //   - 命名由来：它是「记录 max 的那半」——虽存的是较小的数，但关心的是这半的 max。
    //
    priority_queue<int> queMax;

    // queMin：小根堆，存「较大的一半」。
    //   - 比较器 greater<int> 让小的优先（堆顶最小），即小根堆。
    //   - 必须显式写出第二个模板参数 vector<int>（greater 要求底层容器，省略会编译报错）。
    //   - 堆顶 queMin.top() = 这半的最小值 = 右半边界 = 中位数右侧候选。
    //   - 命名由来：它是「记录 min 的那半」——虽存的是较大的数，但关心的是这半的 min。
    //
    priority_queue<int, vector<int>, greater<int>> queMin;
    // 不变量（每次 addNum 后都要维持）：
    //   1) queMax.top() <= queMin.top()（左半任意数 ≤ 右半任意数）
    //   2) queMax.size() - queMin.size() ∈ {0, 1}（约定奇数时 queMax 多放一个）

public:
    // 构造函数：STL 堆自带默认构造，两个空堆，无需手动初始化。
    MedianFinder() {}

    // ============ ② addNum：O(log n) ============
    void addNum(int num) {
        if (queMax.empty() || num <= queMax.top()) {
            // num 属于「较小半」（queMax 空时第一数也先放这）：先塞进 queMax。
            queMax.push(num);                       // 大根堆插入，O(log n)
            // 检查 queMax 是否比 queMin 多超过 1：若是，把 queMax 堆顶（左半最大）搬给 queMin。
            if (queMax.size() > queMin.size() + 1) {
                queMin.push(queMax.top());          // 左半最大值进入右半，成为右半最小值候选
                queMax.pop();                       // 删掉原堆顶，O(log n)，堆自动调整
            }
        } else {
            // num 属于「较大半」：先塞进 queMin。
            queMin.push(num);                       // 小根堆插入，O(log n)
            // 检查 queMin 是否反超 queMax：若是，把 queMin 堆顶（右半最小）搬给 queMax。
            //   注意判据是「>」而非「>+1」：约定奇数时让 queMax 多一个，
            //   所以 queMin 一旦追平（size 相等）就立刻搬走，绝不让 queMin 更大。
            if (queMin.size() > queMax.size()) {
                queMax.push(queMin.top());          // 右半最小值进入左半，成为左半最大值候选
                queMin.pop();
            }
        }
    }

    // ============ ③ findMedian：O(1) ============
    double findMedian() {
        // 按约定，queMin.size() 永远 <= queMax.size()，所以只需分两种情况：
        if (queMax.size() > queMin.size()) {
            // 总个数奇数：queMax（较小半）多放了一个，中位数就是左半最大值。
            return queMax.top();                    // O(1) 读堆顶
        }
        // 总个数偶数：两堆相等，中位数 = (左半最大 + 右半最小) / 2.0。
        //   ★ 除以 2.0（double）而非 2（int）：2.0 让表达式提升为浮点运算，保留小数部分。
        //     写 / 2 会整数除法截断，(1+2)/2 得 1 而非 1.5。
        return (queMax.top() + queMin.top()) / 2.0;
    }
};
```

> 命名说明：官方题解原文里的变量名 `queMin`/`queMax` 与本题解**相反**（官方 `queMin` 是大根堆、`queMax` 是小根堆，容易看晕）。本笔记按「关心哪个极值就取什么名」的直觉重命名：`queMax` = 关心 max 的大根堆（存较小半），`queMin` = 关心 min 的小根堆（存较大半）。两份代码算法完全等价，只是变量名对调。

## 复杂度

- **时间**：
  - `addNum` **O(log n)**，其中 `n` 是当前已添加的元素总数。每次最多做 1 次 push + 1 次 pop 的「搬迁」，priority_queue 的 push/pop 都是 O(log n)。
  - `findMedian` **O(1)**。只读两个堆顶和 size，都是常数操作。这正是双堆设计的回报——把代价全摊到 addNum，让查询白嫖。
- **空间**：**O(n)**。两个堆合计存全部 `n` 个元素。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么用两个堆？一个堆不行吗？

因为中位数要同时知道**两个**值——左半的最大值和右半的最小值。一个堆的堆顶只能给出一个极值（大根堆给最大、小根堆给最小），不可能同时给出两个。

两个堆「对口」摞起来就解决了：大根堆管左半（堆顶=左半最大=中位数左侧候选），小根堆管右半（堆顶=右半最小=中位数右侧候选）。两个堆顶夹住中位数位置，findMedian 直接 O(1) 读堆顶即可。

这是「双堆（对顶堆）」套路的精髓：**用两个极性相反的堆对口，分别维护一个序列的「前一半」和「后一半」**，从而把「中间的统计量（中位数、第 k 大等）」变成 O(1) 可查。

### Q2：两堆大小怎么平衡？为什么约定 queMax 多一个？

约定 `queMax.size() - queMin.size() ∈ {0, 1}`，即奇数时让左半（`queMax`）多放一个。这样规定有两个好处：

1. findMedian 逻辑统一：奇数时直接返回 `queMax.top()`（左半最大），不用纠结「多出来的那个到底在左还是右」。
2. addNum 搬运判据对称好记：`queMax` 多过 2 才搬给 `queMin`（`size > other + 1`），`queMin` 一旦追平就搬给 `queMax`（`size > other`）——单向收敛到「queMax 永不少于 queMin」。

为什么不让右半多一个？纯粹是约定，选哪边都行，官方选了左半（`queMax`/较小半）。只要代码里 addNum 的搬运判据和 findMedian 的奇偶判据**配套一致**就行，不能一边让左半多、另一边去读右半堆顶。

### Q3：为什么「搬堆顶」这一步能同时保证大小关系和个数关系都不崩？

关键在于搬的是**堆顶（本半的极值）**。以「`queMax` 太大、搬它的堆顶 `x` 给 `queMin`」为例：

- 搬之前：`x = queMax.top()` 是左半最大值，且 `x <= queMin.top()`（不变量 1）。
- 搬之后：`x` 进入 `queMin`。因为 `x <= 原 queMin.top()`，`x` 成为新的 `queMin.top()`（右半最小值）。新 `queMax.top()` 是搬走 `x` 后左半剩下的最大值，必然 `<= x`。所以新 `queMax.top() <= x = 新 queMin.top()`，不变量 1 保持。✓
- 个数上，`queMax` 减 1、`queMin` 加 1，差值缩 2，原本差 2 现在差 0（在合法范围内）。✓

反过来「`queMin` 追平、搬它的堆顶给 `queMax`」同理。所以无论怎么失衡，**搬一次堆顶**就能同时修好两条不变量。这是堆「自动维护极值」的特性带来的福利——换成无序数组，光找半个的最值就 O(n)，更别说搬完还要重新找。

### Q4：`priority_queue<int, vector<int>, greater<int>>` 为什么必须写出 `vector<int>`？

因为 STL 的 priority_queue 模板签名是 `priority_queue<T, Container, Compare>`，三个参数。`Compare`（比较器）依赖 `Container`（底层容器）的类型，所以**指定 `Compare` 时必须同时指定 `Container`**，不能跳过。

- 省略后两个：`priority_queue<int>` → 等价 `priority_queue<int, vector<int>, less<int>>`，大根堆。
- 想要小根堆：必须写全 `priority_queue<int, vector<int>, greater<int>>`，少了 `vector<int>` 编译报错。

底层容器一般就用 `vector<int>`（默认），它只是堆的物理存储，不影响堆顶是谁（堆顶由 `Compare` 决定）。另外 priority_queue 没有 `.begin()/.end()`，**不能遍历**、**不能按值删除**，只能 push/pop/top——如果需要这些操作，得用 `multiset`（见复盘方法二）。

## 复盘

- **可迁移套路：「双堆（对顶堆）维护动态中位数」是经典设计**。一旦遇到「数据流 / 滑动窗口里随时问中位数 / 第 k 大」这类问题，第一反应就应该是两个堆对口：大根堆管前半、小根堆管后半，靠堆顶夹住目标统计量。这个套路可迁移到：
  - **滑动窗口中位数（LC 480）**：在 295 的双堆基础上，窗口滑出时要按值删旧元素，而 priority_queue 不支持按值删，所以要么用「延迟删除」（标记 + 惰性清理），要么改用 `multiset` + 迭代器（即下面的方法二）。把 295 的双堆骨架吃透，480 就只剩「怎么删」这一层新东西。
  - **数据流第 K 大（LC 703）**：只用一个小根堆存「当前最大的 K 个」，堆顶就是第 K 大，是双堆的退化版（只取后半那一个堆）。
  - **求 TopK / 频率最高 / 流式分位数**：都是「用一个或两个堆维护某个统计量」的变体。
- **关键记忆点**：
  1. **大根堆存较小半（堆顶=左半最大），小根堆存较大半（堆顶=右半最小）**——命名容易绕，记住「关心哪个极值就取什么名」。
  2. **两条不变量**：`queMax.top() <= queMin.top()`，且 `queMax.size() - queMin.size() ∈ {0, 1}`。
  3. **addNum 两步走**：先按 `num <= queMax.top()` 判属于哪半并塞进去；再检查个数差、超了就搬堆顶到对面（搬一次同时修好两条不变量）。
  4. **findMedian**：奇数（queMax 多）返回 `queMax.top()`，偶数返回两堆顶平均（`/ 2.0` 别写 `/ 2`）。
- **方法二（有序集合 + 双指针，官方同篇题解）对比**：用 `multiset<int>` 存所有数，并维护两个迭代器 `left`/`right` 始终指向中位数位置（偶数时分别指向中间两个）。addNum 插入后按 `num` 落点和当前奇偶微调迭代器，findMedian 直接 `(*left + *right) / 2.0`。
  - **优点**：`multiset` 支持按值删除、支持遍历，所以能直接扩展成「滑动窗口中位数」（480）这种需要删指定元素的场景，而 priority_queue 不支持。
  - **缺点**：迭代器调整逻辑比双堆绕（要分 num 落在 left 左边 / right 右边 / 两者之间三种情况讨论），代码长一些。
  - **复杂度**：addNum O(log n)（`multiset::insert`），findMedian O(1)。和双堆同级，但常数略大。
  - Hot 100 收录的核心解是双堆（方法一），背双堆即可；方法二能在「需要删元素」时作为升级方案。
- **易错点速查（本题专属）**：
  - 小根堆声明漏写 `vector<int>` → 编译报错（见 Q4）。
  - 搬运判据写反（比如让 `queMin` 允许比 `queMax` 多）→ findMedian 奇偶判断失效，中位数取错。
  - 偶数中位数 `/ 2` 而非 `/ 2.0` → 整数除法丢小数（`(1+2)/2 = 1` 而非 `1.5`）。
  - 忘了判 `queMax.empty()` 就读 `queMax.top()` → 空堆 top 是未定义行为（首元素必须先无脑塞 queMax）。
