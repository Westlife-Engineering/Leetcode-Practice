# 347 前 K 个高频元素

- 难度：中等
- 标签：数组、哈希表、分治、桶排序、计数、快速选择、排序、**堆（优先队列）**
- 力扣链接：https://leetcode.cn/problems/top-k-frequent-elements/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「方法一：堆」。正文主解是 **哈希表计数 + 大小为 k 的小根堆**（官方推荐，O(n log k)）；它是 [215. 数组中的第K个最大元素](../堆/215-数组中的第K个最大元素.md) 的变体——215 题按「值」找第 K 大，本题按「出现频率」找前 K 高。基于快速选择的方法二（平均 O(n)）和桶排序法放在「复盘」。

## 题目描述

给你一个整数数组 `nums` 和一个整数 `k` ，请你返回其中出现频率前 `k` 高的元素。你可以按 **任意顺序** 返回答案。

**示例 1：**

```
输入: nums = [1,1,1,2,2,3], k = 2
输出: [1,2]
```

**示例 2：**

```
输入: nums = [1], k = 1
输出: [1]
```

**示例 3：**

```
输入: nums = [1,2,1,2,1,2,3,1,3,2], k = 2
输出: [1,2]
```

**提示：**

- `1 <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`
- `k` 的取值范围是 `[1, 数组中不相同的元素的个数]`
- 题目数据保证答案唯一，换句话说，数组中前 `k` 个高频元素的集合是唯一的

**进阶：** 你所设计算法的时间复杂度 **必须** 优于 `O(n log n)` ，其中 `n` 是数组大小。

## 思路

> 本题主要参考力扣官方题解的「方法一：堆」。

### 两步走

要求「频率前 k 高」，先把「频率」算出来，再在这些频率里选前 k 大：

1. **第一步：哈希表统计频率。** 遍历一遍 `nums`，用 `unordered_map<int,int> freq` 记录每个元素出现了多少次（key=元素值，value=次数）。一次遍历 O(n)。
2. **第二步：小根堆（大小 k）维护前 k 高频元素。** 遍历 `freq` 里每个 `(元素, 频率)`，往一个**大小不超过 k 的小根堆**里塞：
   - 先 `push` 进堆；
   - 若 `堆大小 > k`，就把堆顶 `pop` 掉。

   小根堆的堆顶永远是堆里**频率最小**的那个元素。每次塞完如果超了 k 个，就淘汰掉堆里频率最小的——也就是「当前这 k+1 个里最不配进前 k 的那一个」。遍历结束时，堆里剩下的恰好是频率前 k 高的元素。

### 和 215 题的区别

| | 215 第 K 个最大元素 | 347 前 K 个高频元素 |
|---|---|---|
| 比较依据 | 元素的**值** | 元素的**出现频率** |
| 堆里存的是 | 元素值本身 | 元素值，但**比较的是频率** |
| 哈希表 | 不需要 | 需要先统计频率 |

关键区别一句话：**本题堆里存的是「元素」，但排序依据是「频率」**。这就引出一个问题——堆怎么知道按频率排？答案是**把频率塞进 pair**，让堆比较 pair（见下文「代码」和 Q&A）。

### pair 怎么存：`(频率, 元素)`

我们让堆里每个节点是一个 `pair<int,int>`：

- `pair.first` = **频率**（count）
- `pair.second` = **元素值**（num）

为什么频率放 first？因为 `priority_queue` 默认（以及 `greater`/`less`）比较 `pair` 时，是**字典序**：先比 `first`，`first` 相同再比 `second`。把频率放 first，堆就**自动按频率比较**，不用自己写比较器。

### 手动推导 nums = [1,1,1,2,2,3], k = 2

第一步统计频率：

```
freq = { 1:3, 2:2, 3:1 }      // 1 出现 3 次，2 出现 2 次，3 出现 1 次
```

第二步遍历 `freq`，往大小为 2 的小根堆里塞（`unordered_map` 遍历顺序不确定，但结果一致，这里以一种顺序演示）：

```
处理 (1, 频率3)：push {3, 1}          堆 = [{3,1}]            size=1 ≤ k，保留
处理 (2, 频率2)：push {2, 2}          堆 = [{2,2},{3,1}]      size=2 ≤ k，保留
                                        （小根堆顶是 {2,2}，因为频率 2 < 3）
处理 (3, 频率1)：push {1, 3}          堆 = [{1,3},{3,1},{2,2}] size=3 > k
                  → pop 堆顶 {1,3}     堆 = [{2,2},{3,1}]      size=2，保留
                                        （被淘汰的是频率最小的元素 3）
```

遍历结束，堆里剩 `{2,2}` 和 `{3,1}`，对应元素 **2 和 1**，即 `[1,2]`（顺序无所谓）✓

可以看到：**不管哈希表以什么顺序吐出元素，最终堆里保留的永远是频率最高的 k 个**——因为每次都只淘汰「当前最不配的那个」。

## 代码

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        // ===== 第一步：哈希表统计每个元素的出现频率 =====
        // unordered_map<int,int>：C++ STL 哈希表，查找/插入均摊 O(1)。
        //   - key   = 元素值（int，nums[i]）
        //   - value = 该元素出现次数（int）
        //   - 对 int 这种内置类型，标准库自带 std::hash<int>，开箱即用，
        //     不需要自己写哈希函数 / 冲突处理（内部用链地址法）。
        unordered_map<int, int> freq;
        for (int v : nums) {
            // freq[v]：下标访问。若 v 不存在会自动插入并初始化为 0，
            //   然后 ++ 让它变 1；已存在则直接 +1。这是「计数」最省事的写法。
            freq[v]++;
        }

        // ===== 第二步：大小为 k 的小根堆，维护前 k 高频元素 =====
        // priority_queue：C++ STL 「优先队列」，本质是一个堆（默认大根堆）。
        //   - 模板参数：<元素类型, 底层容器, 比较器>
        //   - 元素类型：pair<int,int>。
        //       * 约定 pair.first  = 频率（count），用来比较大小
        //       * 约定 pair.second = 元素值（num），只是「搭便车」存着，最后要取它
        //       * 为什么频率放 first？因为 priority_queue 比较 pair 时按「字典序」：
        //         先比 first、first 相同再比 second。频率放 first，堆就自动按频率排，
        //         不用自定义比较器。这是本题最关键的技巧。
        //   - 底层容器：vector<pair<int,int>>（priority_queue 默认用 vector 做底层堆数组）。
        //   - 比较器：greater<pair<int,int>>。
        //       * greater 表示「a>b 时 a 优先级低」，效果是「小的在堆顶」→ 小根堆。
        //       * 不写比较器（默认 less）是大根堆，堆顶是最大的；这里要小根堆故用 greater。
        //       * 复杂度：push/pop 都是 O(log size)，size≤k 所以是 O(log k)。
        //   - 堆顶（频率最小的元素）用 q.top() 取；入堆 q.push(...)；出堆 q.pop()。
        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> q;

        // 结构化绑定（C++17）：auto& [num, count] 一次性把 map 里每个键值对
        //   解构成 num=key(元素值)、count=value(频率)，比 it->first/it->second 直观。
        //   写 auto& 是引用，避免拷贝 pair。
        //   注意：unordered_map 遍历顺序不确定，但本题答案唯一，顺序不影响最终结果。
        for (auto& [num, count] : freq) {
            // push({count, num})：把 {频率, 元素值} 作为一个 pair 入堆。
            //   - 顺序很关键：count 在前（first），num 在后（second），
            //     这样 greater 才能按频率比较。
            //   - {count, num} 是 C++11 列表初始化，会隐式构造 pair<int,int>。
            //     也可写成 q.emplace(count, num) 或 q.push(make_pair(count,num))。
            q.push({count, num});
            // 维持堆大小不超过 k：一旦超了，弹掉堆顶。
            //   - 堆顶是小根堆里频率最小的（q.top()），也就是「当前 k+1 个里最该被淘汰的」。
            //   - q.pop() 只删除堆顶元素、不返回值（取值要先 q.top()）；这里不需要取值，直接删。
            if (q.size() > k) {
                q.pop();
            }
        }

        // ===== 收集结果：把堆里剩下的 k 个元素值取出来 =====
        vector<int> ret;
        // 堆里恰好剩 k 个（题目保证 k ≤ 不同元素个数，所以一定能填满）。
        while (!q.empty()) {
            // q.top() 返回堆顶 pair 的 const 引用；.second 取「元素值」（num）。
            //   - 我们只要 num，频率 count 已经完成使命，丢弃即可。
            //   - 取完必须 q.pop() 把堆顶移除，才能露出下一个；否则死循环。
            ret.push_back(q.top().second);
            q.pop();
        }
        return ret;   // 顺序无所谓，题目允许任意顺序返回
    }
};
```

## 复杂度

- **时间**：O(n log k)
  - 第一步统计频率：遍历 `nums` 一次，哈希表插入均摊 O(1)，共 O(n)。
  - 第二步维护堆：哈希表里至多 n 个不同元素，每个 `push`/`pop` 是 O(log k)（堆大小 ≤ k），共 O(n log k)。
  - 合计 O(n) + O(n log k) = **O(n log k)**，优于进阶要求的 O(n log n)。当 k 远小于 n 时尤其高效。
- **空间**：O(n)
  - 哈希表存所有不同元素：O(n)。
  - 堆最多 k 个元素：O(k)。
  - 合计 O(n + k) = **O(n)**（k ≤ n）。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：堆里为什么存的是 pair，而不是直接存元素值？

因为**堆排序的依据（频率）和最终要取的东西（元素值）不是同一个**。

- 如果堆里只存元素值 `int`，堆怎么知道谁频率高？它只能按「值」比大小，那就跑题了。
- 所以得把「频率」和「元素值」**绑在一起**塞进堆，让堆按频率排、同时还能记住这个频率属于哪个元素。`pair<int,int>` 就是干这个的——一个 int 存频率、一个 int 存元素值。

更一般地：**当「比较依据」和「要保留的数据」不是同一个字段时，用 pair/struct 把它们绑一起，比较依据放前面**。这是 STL 里非常常用的套路。

### Q2：pair 怎么按频率比较？为什么频率要放 first？

`priority_queue` 和 `sort` 这些 STL 组件比较 `pair` 时，默认走**字典序**：

```
比较 {a1, a2} 和 {b1, b2}：
  先比 first：a1 vs b1
  若 first 相等，再比 second：a2 vs b2
```

所以：

- **频率放 first** → 堆先按频率比，正中下怀。
- 元素值放 second → 只有当两个频率相等时才用上（本题保证答案唯一，频率一般不会撞，撞了也不影响「前 k 高」的集合）。

如果反过来把元素值放 first，堆就会先按元素值比大小，那就完全错了。**结论：把「要比较的那个量」放在 pair 的 first**。

### Q3：为什么用「小根堆」而不是大根堆？

因为我们要**保留前 k 个最大的**，得快速知道「当前堆里最小的是谁」好把它踢掉。小根堆的堆顶就是最小值，O(1) 能拿到、O(log k) 能删掉，正好。

对比两种做法（设不同元素共 N 个）：

| 做法 | 堆大小 | 每次 push/pop | 总时间 |
|---|---|---|---|
| 小根堆，大小 k | k | O(log k) | **O(N log k)** ✓ |
| 大根堆，大小 N | N | O(log N) | O(N log N) ✗（不满足进阶） |

小根堆把堆控制在大小 k，每次操作只花 O(log k)，这是本题优于 O(n log n) 的关键。**求「前 K 大/高」用小根堆（限制大小 k）；求「前 K 小/低」用大根堆（限制大小 k）**——这是 TopK 问题的通用口诀。

### Q4：和 215 题「数组中的第K个最大元素」是什么关系？

两题是**同一套「堆求 TopK」模板**，只是输入不同：

- **215 题**：直接给你一个数组，要找第 K 大的**值**。堆里存元素值，按值比。
- **347 题（本题）**：给你数组，要找**按出现频率排**的前 K 高。多了「统计频率」这一步，堆里存的是元素值但按频率比。

所以解题链路是：**215 的堆模板 + 前面套一层哈希计数** = 347。会做 215 就会做 347；反过来练完 347 也巩固了 215。官方题解在文末「引申」一节也明确指出了这道题和 215 的关联。

### Q5：`q.pop()` 为什么不返回值？取堆顶元素为什么要先 `top()` 再 `pop()`？

这是 C++ STL `priority_queue`（和 `queue`/`stack`）的设计：**`pop()` 只负责删除，不返回被删的元素**。原因是为了**异常安全**——如果 pop 返回元素、而拷贝构造抛异常，元素就既不在堆里也没成功交给你，丢了。

所以取堆顶要两步走：

```cpp
auto val = q.top();   // 先拷贝走堆顶
q.pop();              // 再删除
```

本题收集结果时 `ret.push_back(q.top().second); q.pop();` 就是这个套路。Python 的 `heapq.heappop` 直接返回值，和 C++ 不一样，别混淆。

## 复盘

- **核心可迁移套路：「哈希计数 + 堆求 TopK」是高频模板。** 任何「在一堆数据里找出现次数/频率前 K 的」类问题，第一步无脑哈希计数，第二步套大小为 K 的小根堆（要前 K 大）或大根堆（要前 K 小）。本题、[215](../堆/215-数组中的第K个最大元素.md)、[692 前K个高频单词]、[451 根据字符出现频率排序] 都是同一套，值得作为「母题」记牢。
- **pair 存比较依据 + 数据的技巧**：当比较依据和要保留的数据不同字段时，用 pair 把它们绑一起，比较依据放 first。这样能直接用 `greater`/`less` 走默认字典序，省掉自定义比较器。
- **priority_queue 三件套要记**：`top()` 取堆顶（不删除）、`push()` 入堆、`pop()` 删堆顶（不返回值）。`greater` 对应小根堆，`less`（默认）对应大根堆。
- **TopK 口诀**：求前 K **大**用**小根堆**（堆大小 k，踢最小）；求前 K **小**用**大根堆**（堆大小 k，踢最大）。堆大小控制在 k，才能把 O(N log N) 压到 O(N log k)。

### 解法对比：桶排序（O(n) 线性解，复盘向）

如果追求比 O(n log k) 更快的线性时间，可以用**桶排序**：

1. 哈希表统计频率（同主解第一步）。
2. 建 `n+1` 个桶，下标 `i` 表示「出现次数为 i」，桶里装频率恰为 i 的那些元素。
3. 从最大下标（最高频）往低频方向扫桶，每碰到非空桶就把里面的元素收进答案，直到收够 k 个。

因为元素频率最多是 n，桶数组大小 n+1；倒序扫一遍桶即可，**无需堆的 log 因子**，总时间 O(n)。

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        unordered_map<int, int> freq;
        for (int v : nums) freq[v]++;
        // 桶：下标 = 频率，值 = 该频率对应的元素列表。最大频率不超过 n。
        int n = nums.size();
        vector<vector<int>> bucket(n + 1);
        for (auto& [num, count] : freq) {
            bucket[count].push_back(num);
        }
        // 从高频往低频扫，收够 k 个就停。
        vector<int> ret;
        for (int i = n; i >= 0 && (int)ret.size() < k; --i) {
            for (int x : bucket[i]) {
                ret.push_back(x);
                if ((int)ret.size() == k) break;
            }
        }
        return ret;
    }
};
```

- **时间**：O(n)（计数 O(n) + 桶分配 O(n) + 倒序扫桶总计 O(n)，因为所有桶里元素总数 ≤ n）。
- **空间**：O(n)（哈希表 + 桶数组）。
- **对比**：桶排序**时间更优** O(n) < O(n log k)，但要**多开一个大小 n 的桶数组**，空间常数更大；且依赖「频率取值范围有限（≤ n）」这一前提。堆解法更通用、不依赖频率上界，是官方主推解法；桶排序适合**频率分布集中、n 很大但 k 也很大**时榨取那一点 log k。日常面试**写堆解法即可**（模板通用、好记），桶排序作为加分项提一句。
