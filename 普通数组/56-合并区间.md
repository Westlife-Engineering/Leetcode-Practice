# 56 合并区间

- 难度：中等
- 标签：**数组**、**排序**
- 力扣链接：https://leetcode.cn/problems/merge-intervals/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[合并区间](https://leetcode.cn/problems/merge-intervals/solution/he-bing-qu-jian-by-leetcode-solution/)」。正文主解是 **排序 + 一次遍历合并**（按左端点排序，扫一遍合并重叠区间），O(n log n) 时间 O(log n) 额外空间。这是官方唯一推荐解法，无其他并列主解。

## 题目描述

以数组 `intervals` 表示若干个区间的集合，其中单个区间为 `intervals[i] = [starti, endi]`。请你合并所有重叠的区间，并返回一个不重叠的区间数组，该数组需恰好覆盖输入中的所有区间。

**示例 1：**

```
输入：intervals = [[1,3],[2,6],[8,10],[15,18]]
输出：[[1,6],[8,10],[15,18]]
解释：区间 [1,3] 和 [2,6] 重叠, 将它们合并为 [1,6].
```

**示例 2：**

```
输入：intervals = [[1,4],[4,5]]
输出：[[1,5]]
解释：区间 [1,4] 和 [4,5] 可被视为重叠区间。
```

**示例 3：**

```
输入：intervals = [[4,7],[1,4]]
输出：[[1,7]]
解释：区间 [1,4] 和 [4,7] 可被视为重叠区间。
```

**提示：**

- `1 <= intervals.length <= 10^4`
- `intervals[i].length == 2`
- `0 <= starti <= endi <= 10^4`

## 思路

> 本题主要参考力扣官方题解「方法一：排序」。

要合并「所有重叠的区间」。难点在于：输入区间是乱序的，可能 `[1,3]` 后面跟着 `[8,10]`，再后面又冒出个 `[2,6]`——直接顺序扫根本看不出谁和谁重叠。

### 为什么要先排序？

**关键观察**：如果把区间按**左端点升序**排好，那么「能合并的区间在数组里一定是连续挨着的」。

为什么？排序后左端点单调不降（`a[i].start ≤ a[i+1].start ≤ ...`）。假设 `a[i]` 和后面某个 `a[k]` 能合并（即 `a[k].start ≤ a[i].end`），那么夹在中间的任何 `a[j]`（`i < j < k`）也一定满足 `a[j].start ≤ a[k].start ≤ a[i].end`，即 `a[j]` 也和 `a[i]` 重叠。换句话说，**排序把「能合并的一组区间」聚成了一段连续的区间块**，不会出现「跳过一个不合并的、再合并后面的」这种交错情况。

官方给了个反证（见题解）：若排好序后存在 `i < j < k`，`(a[i],a[k])` 能合并而 `(a[i],a[j])`、`(a[j],a[k])` 都不能，会推出 `a[i].end < a[j].start ≤ a[j].end < a[k].start ≤ a[i].end` 的矛盾。所以「能合并则必连续」成立。

这一步是全题的钥匙：**排序把无序的合并问题，变成「一段连续区间的贪心合并」**。

### 排序后怎么合并？一次遍历即可

开一个结果数组 `merged`，按顺序处理每个区间：

1. 先把第一个区间放进 `merged`（它左端点最小，必然是新的一组的开头）。
2. 对后续每个区间 `cur = [L, R]`，看它和 `merged` 里**最后一个区间** `last` 的关系：
   - 若 `L > last.right`：`cur` 的左端点在 `last` 的右端点**之后**，两者不重叠，`cur` 自己开一组，直接 `push` 进 `merged`。
   - 否则（`L ≤ last.right`）：`cur` 和 `last` 重叠，合并它们——把 `last.right` 更新成 `max(last.right, R)`。注意左端点不用动，因为排过序，`L ≥ last.left` 必然成立。

**为什么只看「最后一个」就够了？** 因为「能合并则连续」，一旦 `cur` 和 `last` 不重叠，`cur` 和 `merged` 里更早的区间（左端点更小、右端点也更小）更不可能重叠，所以只需和尾部比一次。

**合并条件用 `≤` 还是 `<`？** 题目里 `[1,4]` 和 `[4,5]` 算重叠（端点挨着就算），所以条件是 `L <= last.right` 即「`cur` 左端点不超过 `last` 右端点」。代码里写成「`last.right < L` 时不重叠」，等价于「`L <= last.right` 时重叠」，含等号。

### 用示例 1 走一遍

`intervals = [[1,3],[2,6],[8,10],[15,18]]`（已按左端点排好）：

```
cur=[1,3]  merged=[]               → 不重叠(空) → push → merged=[[1,3]]
cur=[2,6]  last=[1,3], 2<=3 重叠   → 右端点取 max(3,6)=6 → merged=[[1,6]]
cur=[8,10] last=[1,6], 8>6 不重叠  → push → merged=[[1,6],[8,10]]
cur=[15,18] last=[8,10], 15>10 不重叠 → push → merged=[[1,6],[8,10],[15,18]]
返回 [[1,6],[8,10],[15,18]] ✓
```

示例 3 的输入是乱的（`[[4,7],[1,4]]`），排序后变 `[[1,4],[4,7]]`，再按上面流程合并成 `[[1,7]]`——这也体现了「排序」的必要性。

## 代码

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {
        // vector<vector<int>>：二维 vector，元素是 vector<int>。
        //   - 这里每个内层 vector<int> 长度为 2，表示一个区间 [start, end]。
        //   - 函数返回值就是这个二维数组（合并后的所有不重叠区间）。
        // intervals 是输入引用（不加 const 因为 sort 要就地修改它）。

        if (intervals.empty()) {     // empty()：判空，比 size()==0 更直观，O(1)
            return {};                // {}：返回一个空的 vector<vector<int>>
        }

        // sort(begin, end)：C++ STL 就地排序算法（<algorithm>），默认升序，O(n log n)。
        //   - 对 vector<vector<int>> 排序时，默认按「字典序」比较：
        //     先比第 0 个元素（区间左端点），左端点相同再比第 1 个元素（右端点）。
        //   - 我们要的就是「按左端点升序」，所以默认 sort 恰好满足，无需自定义比较！
        //   - 注意 sort 是「就地」的，会直接修改 intervals 本身的顺序（题目不要求保留原序）。
        //   - 底层是内省排序（introsort）：快排+堆排+插排的混合，最坏也是 O(n log n)。
        sort(intervals.begin(), intervals.end());

        // merged：存放合并结果的二维数组。
        vector<vector<int>> merged;

        // 遍历每个区间 cur = [L, R]。
        //   - 用 size_t / int 下标都行；这里 i < intervals.size()，注意有符号/无符号比较。
        for (int i = 0; i < (int)intervals.size(); ++i) {
            int L = intervals[i][0], R = intervals[i][1];   // 当前区间的左右端点

            // merged.empty()：结果数组为空（第一个区间），或
            // merged.back()[1] < L：结果数组「最后一个区间的右端点」< 当前左端点 → 不重叠。
            //   - back()：返回 vector 最后一个元素的引用（不检查越界，空 vector 调用是未定义行为，
            //     所以前半句 merged.empty() 的短路判断必不可少！）。
            //   - back()[1]：取最后一个区间（vector<int>）的第 2 个元素（右端点）。
            //   - 用「<」不含等号：端点相等（如 [1,4] 和 [4,5]）算重叠，走 else 分支合并。
            if (merged.empty() || merged.back()[1] < L) {
                // emplace_back(L, R)：在末尾「原地构造」一个 vector<int>{L, R}。
                //   - 比 push_back({L,R}) 少一次临时对象的拷贝/移动，效率略高，写法也更简洁。
                //   - 这里传入两个 int，emplace_back 会用它们构造 vector<int>（via initializer_list）。
                merged.emplace_back(vector<int>{L, R});
            } else {
                // 重叠：把最后一个区间的右端点更新为「两者右端点的较大值」。
                //   - 左端点不用改：排序保证 L >= merged.back()[0]。
                //   - max(a,b)：<algorithm>，返回较大者，O(1)。
                merged.back()[1] = max(merged.back()[1], R);
            }
        }
        return merged;
    }
};
```

## 复杂度

- **时间**：O(n log n)，其中 n 为区间数量。
  - 排序 O(n log n) 是主开销；后面只是一次线性扫描 O(n)，每个区间做 O(1) 的比较和更新。
- **空间**：O(log n)（不计返回值本身）。
  - 排序（内省排序）的递归栈占用 O(log n) 额外空间。
  - `merged` 是要返回的答案，按题意不计入额外空间复杂度；若计入则是 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么必须按「左端点」排序？按右端点排序行不行？

按左端点排序是**最自然且正确**的选择，因为它保证了「排序后能合并的区间一定连续」（见思路里的反证）。遍历时只要维护一个「当前合并组的右端点最大值」就能一路贪心合并下去。

按右端点排序理论上也能做（同样能保证「能合并的连续」——把数组翻转着看即可），但写起来别扭：得反向看左端点。力扣官方和绝大多数题解都用左端点，记忆成本最低。**结论：默认按左端点升序**。

如果想自定义比较（比如题目改成按右端点排），用 lambda：

```cpp
sort(intervals.begin(), intervals.end(),
     [](const auto& a, const auto& b) { return a[0] < b[0]; });
```

但本题默认字典序就已经是「按左端点升序」，不需要写 lambda。

### Q2：合并条件到底是 `<` 还是 `<=`？端点相等算重叠吗？

**算**。题目示例 2 明确：`[1,4]` 和 `[4,5]` 重叠，合并成 `[1,5]`。也就是说「`cur` 的左端点等于 `last` 的右端点」时也要合并。

代码里写成 `if (merged.back()[1] < L)`（不重叠才进 if），等价于「`L <= merged.back()[1]` 时重叠、走 else 合并」。**这里的 `<` 不能写成 `<=`**——写成 `<=` 会让端点相等的两个区间被错误地判为「不重叠」、各自独立，输出多出一个 `[4,5]`，错。

记忆：**「不重叠」用严格 `<`，「重叠」自然含等号**。两个区间 `[a,b]`、`[c,d]`（已排序 a≤c）不重叠的充要条件是 `b < c`（严格小于），`b == c` 时它们共享端点 b=c、算重叠。

### Q3：lambda 捕获 `[]`、`[&]`、`[=]` 有什么区别？本题需要捕获吗？

lambda 表达式 `[](params){ body }` 方括号里写的是**捕获子句**，决定 lambda 内部如何访问外部变量：

- `[]`：不捕获任何外部变量。lambda 内只能用自己的参数和全局量。
- `[&]`：按引用捕获所有用到的外部变量。
- `[=]`：按值捕获所有用到的外部变量（拷贝一份）。
- `[&intervals]`：只按引用捕获 `intervals` 一个。

本题如果写自定义比较 lambda `[](const auto& a, const auto& b){ return a[0] < b[0]; }`，**用 `[]` 即可**——比较只用到参数 `a`、`b`（由 sort 传入），不需要访问任何外部变量。初学者常见误区是「无脑写 `[&]`」，其实大多数 sort 比较器都不需要捕获。

### Q4：`back()` 调用前为什么必须先判 `empty()`？

`vector::back()` 返回最后一个元素的引用，但**不检查容器是否为空**——对空 vector 调 `back()` 是**未定义行为（UB）**，可能崩溃、可能返回垃圾值。

代码里 `if (merged.empty() || merged.back()[1] < L)` 用了短路求值：前半句 `merged.empty()` 为 `true` 时，整个 `||` 表达式已经为 `true`，**后半句 `merged.back()` 根本不会被执行**，从而避免了在空容器上调 `back()` 的 UB。这是 C++ 里「先判空再访问末尾」的标准写法。

## 复盘

- **核心套路**：「**区间合并 / 区间调度类问题**」第一步几乎总是**排序**——要么按左端点，要么按右端点。排序后区间有序了，无序的「谁和谁重叠」就退化成「连续段内的贪心合并」。记这套流程：**排序 → 扫描 → 和结果末尾比较 → 合并或新增**。
- **维护「结果数组最后一个元素」的技巧**：合并类问题里，答案数组 `merged` 的尾部就是「当前正在处理的那一组」。只需 `back()` 拿到它、判断能否扩展，不必单独维护「当前组的左右端点」变量——`merged.back()` 本身就是当前组。注意 `back()` 前要判 `empty()`。
- **STL 默认排序对二维 vector 的行为**：`sort` 对 `vector<vector<int>>` 默认按字典序（先比第 0 维、再比第 1 维），所以「按左端点排序」不用写比较器，直接 `sort(v.begin(), v.end())` 就对。需要按其他键排序时再写 lambda。
- **端点边界**：区间题最易错的点是「端点相等算不算重叠」。本题算（`<` 还是 `<=` 要分清），写代码时把「不重叠用严格 `<`」作为口诀。这类边界条件建议用题目示例（如 `[1,4],[4,5]`）专门验一遍。
