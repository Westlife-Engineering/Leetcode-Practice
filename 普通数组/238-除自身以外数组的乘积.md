# 238 除自身以外数组的乘积

- 难度：中等
- 标签：**数组**、前缀和
- 力扣链接：https://leetcode.cn/problems/product-of-array-except-self/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[除自身以外数组的乘积](https://leetcode.cn/problems/product-of-array-except-self/solution/chu-zi-shen-yi-wai-shu-zu-de-cheng-ji-by-leetcode-/)」。正文主解是 **方法二：空间复杂度 O(1) 的左右乘积法**——用结果数组本身存「前缀积」，再从右往左用滚动变量 `R` 乘上「后缀积」，一趟一趟地复用同一块内存；官方的**方法一（左右两个数组 L/R，O(n) 空间）**放在「复盘」作对比，便于理解思路是怎么来的。

## 题目描述

给你一个整数数组 `nums`，返回数组 `answer`，其中 `answer[i]` 等于 `nums` 中除了 `nums[i]` 之外其余各元素的乘积。

题目数据 **保证** 数组 `nums` 之中任意元素的全部前缀元素和后缀的乘积都在 **32 位** 整数范围内。

请 **不要使用除法**，且在 `O(n)` 时间复杂度内完成此题。

**示例 1：**

```
输入: nums = [1,2,3,4]
输出: [24,12,8,6]
```

**示例 2：**

```
输入: nums = [-1,1,0,-3,3]
输出: [0,0,9,0,0]
```

**提示：**

- `2 <= nums.length <= 10^5`
- `-30 <= nums[i] <= 30`
- 输入 **保证** 数组 `answer[i]` 在 **32 位** 整数范围内

**进阶：** 你可以在 `O(1)` 的额外空间复杂度内完成这个题目吗？（出于对空间复杂度分析的目的，输出数组 **不被视为** 额外空间。）

## 思路

> 本题主要参考力扣官方题解「方法二：空间复杂度 O(1) 的方法」。

题目给了三个硬约束，逐条拆：

- **O(n) 时间**：数据范围 n ≤ 10^5，O(n²) 必超时，只能常数趟线性扫描。
- **不能用除法**：最直观的「先求总乘积，再除以 `nums[i]`」直接被禁。
- **进阶：O(1) 额外空间**（输出数组不算）。

### 为什么不能用除法？除了禁用，还有个坑

哪怕题目不禁除法，除法在这题也**行不通**：一旦 `nums` 里有 `0`（如示例 2 `[-1,1,0,-3,3]`），总乘积就是 `0`，用 `0` 去除任何元素都得 `0`——可正确答案是 `[0,0,9,0,0]`（位置 2 应是 `(-1)*1*(-3)*3 = 9`）。除法在这里**结构性失效**，所以官方题解一开头就特别强调「含 0 时除法方法失效」。这就逼出另一条路：**不绕总乘积，直接对每个位置分别算「左半边乘积 × 右半边乘积」**。

### 关键观察：`answer[i] = 左半边乘积 × 右半边乘积`

对每个下标 `i`，`nums[i]` 之外其余各元素的乘积，恰好等于：

```
answer[i] = (nums[0] × nums[1] × … × nums[i-1])   ← 左半边（不含 i）
          × (nums[i+1] × … × nums[n-1])            ← 右半边（不含 i）
```

`i` 左边那些数和 `i` 右边那些数，正好把「除自己以外」全覆盖了。把这两块分别记作 **前缀积 `L[i]`** 和 **后缀积 `R[i]`**（这里借用「前缀和」的术语，只是把「和」换成「积」，所以题目也打了「前缀和」标签）。

`L[i]` 和 `R[i]` 都可以**一趟线性扫描递推出来**：

```
L[0] = 1                          （左边没有元素，乘积定义为 1，乘法单位元）
L[i] = L[i-1] × nums[i-1]         （左边再多塞一个 nums[i-1]）

R[n-1] = 1                        （右边没有元素）
R[i] = R[i+1] × nums[i+1]         （右边再多塞一个 nums[i+1]）
```

递推只看「相邻一项」，所以 `L` 从左往右扫一遍、`R` 从右往左扫一遍即可，每趟都是 O(n)。这就解决了「O(n) 时间、不用除法」的要求，剩下的是「O(1) 额外空间」。

### 把 O(n) 空间压到 O(1)：结果数组复用 + 滚动变量 `R`

方法一会开两个长度 n 的数组 `L[]`、`R[]`，加起来 O(n) 额外空间。但仔细看：`L[i]` 算完只为后续一步 `answer[i] = L[i] × R[i]` 服务，**根本不用整块存下来**。方法二分两步：

1. **从左往右扫一遍，把 `answer` 当 `L` 用**。`answer[i]` 先存「`i` 左侧所有元素的乘积」（即方法一里的 `L[i]`），用一个滚动变量 `L`（其实就是上一步的 `answer[i-1]`）递推。
2. **再从右往左扫一遍，用一个滚动变量 `R` 把「`i` 右侧所有元素的乘积」乘上去**。`R` 在这一趟里**实时维护**「当前下标右侧所有元素的累乘」，从 `R = 1` 起步，每处理完一个 `i` 就让 `R *= nums[i]`，传给下一个（更靠左的）下标。

这样 `L[]`、`R[]` 两个数组都不用开了，只剩 `answer`（输出，不计入额外空间）和一个 `int R`，额外空间 O(1)。**这正是「滚动变量压缩」在「前缀积」上的应用**——和 53 题 Kadane 用 `pre` 滚动保存 `f(i-1)` 是一回事。

### 用示例走一遍：`nums = [1,2,3,4]`

第一趟（从左往右，`answer[i]` ← `i` 左侧乘积）：

```
i=0  answer[0]=1                         （左边没有，置 1）
i=1  answer[1]=nums[0]*answer[0]=1*1=1
i=2  answer[2]=nums[1]*answer[1]=2*1=2
i=3  answer[3]=nums[2]*answer[2]=3*2=6
现在 answer = [1,1,2,6]   ← 这就是「左半边乘积」L
```

第二趟（从右往左，`R` 维护右侧累乘，初值 1）：

```
i=3  answer[3]=answer[3]*R=6*1=6   R*=nums[3]=1*4=4
i=2  answer[2]=answer[2]*R=2*4=8   R*=nums[2]=4*3=12
i=1  answer[1]=answer[1]*R=1*12=12 R*=nums[1]=12*2=24
i=0  answer[0]=answer[0]*R=1*24=24 R*=nums[0]=24*1=24
现在 answer = [24,12,8,6] ✓
```

手算验证：`answer[2]` 应等于 `nums[0]*nums[1]*nums[3] = 1*2*4 = 8`，对上了。

## 代码

```cpp
class Solution {
public:
    vector<int> productExceptSelf(vector<int>& nums) {
        int length = nums.size();

        // vector<int> answer(length)：构造一个长度为 length 的 int 数组（元素默认 0）。
        //   - 这是题目要返回的「输出数组」，按题目约定不计入额外空间复杂度。
        //   - 它在本解法里身兼两职：第一趟当「前缀积 L」用，第二趟再乘上后缀积。
        //   - 注意：下面用 answer[0]=1 覆盖了第 0 个元素，其它元素在循环里逐一赋值，
        //     所以这里默认初始化成什么都不影响，写 vector<int>(length) 或 vector<int>(length,1) 都行。
        vector<int> answer(length);

        // ===== 第一趟：从左往右扫，answer[i] 暂存「i 左侧所有元素的乘积」（前缀积）=====
        // answer[0]=1：下标 0 左边没有任何元素，「空乘积」按乘法单位元定义为 1。
        //   - 这是初值必须填 1 而不是 0 的关键原因：乘法里 0 会把后续所有乘积都污染成 0，
        //     而 1 是乘法单位元（x*1=x），不会改变任何乘积。
        //   - 对比 53 题 Kadane 里 pre 初值填 0，那是因为那是「加法」、加法单位元是 0；
        //     本题是「乘积」、乘法单位元是 1，别套错。
        answer[0] = 1;
        for (int i = 1; i < length; i++) {
            // answer[i] = nums[i-1] × answer[i-1]
            //   - answer[i-1] 已经是「i-1 左侧所有元素的乘积」，
            //     再乘上紧挨着 i 左边那个 nums[i-1]，就得到「i 左侧所有元素的乘积」。
            //   - 这就是「前缀积」递推：只用相邻前一项，故无需开 L[] 数组，原地存到 answer 里。
            answer[i] = nums[i - 1] * answer[i - 1];
        }

        // ===== 第二趟：从右往左扫，用滚动变量 R 把「i 右侧所有元素的乘积」乘上去 =====
        // R：滚动变量，含义是「当前下标 i 右侧所有元素的累乘」（后缀积）。
        //   - 初值 R=1：因为最右边下标 length-1 右侧没有任何元素，后缀积为 1（乘法单位元）。
        //   - 每处理完一个 i，执行 R *= nums[i]，让 R 把 nums[i]「收编」进去，
        //     这样走到下一个（更靠左的）下标时，R 正好等于「它右侧所有元素的乘积」。
        //   - 一个变量够用，因为递推 R[i] 只依赖 R[i+1]（相邻一项），不需要整块 R[] 数组。
        int R = 1;
        // 扫描方向：i 从 length-1 递减到 0，即「从右往左」。
        //   - 注意方向必须和第一趟相反：第一趟从左往右算前缀积，第二趟从右往左算后缀积，
        //     才能保证「i 右侧所有元素」随着 R 的滚动被正确累乘进来。
        for (int i = length - 1; i >= 0; i--) {
            // answer[i] 现在是「左侧乘积」，R 是「右侧乘积」，两者一乘就是题目要的「除自身以外」的乘积。
            answer[i] = answer[i] * R;
            // 把 nums[i] 收编进 R，为下一个（更左的）下标准备好「右侧乘积」。
            //   - 注意这句必须在算完 answer[i] 之后才执行：因为对当前 i 来说，
            //     nums[i] 是「自身」，不能进入右侧乘积；只有处理完 i 后，nums[i] 才成为「下一个 i 的右侧元素」。
            R *= nums[i];
        }
        return answer;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 两次线性扫描：第一趟从左往右 n 步，第二趟从右往左 n 步，每步常数次乘法，共 O(2n) = O(n)。
- **空间**：O(1) **额外空间**
  - 只用了滚动变量 `R`（和循环变量 `i`）这两个额外变量。
  - `answer` 是题目要求的输出数组，按题目进阶的约定**不计入额外空间**；如果把它也算上则是 O(n)。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么不能用除法？除了题目禁止，还有别的原因吗？

就算题目不禁除法，**含 0 的数组也会让除法直接失效**。比如 `nums = [-1,1,0,-3,3]`（示例 2），总乘积是 `0`，对任何位置 `0 / nums[i]` 都得 0，但正确答案是 `[0,0,9,0,0]`（位置 2 应得 9）。0 不能做除数、总乘积为 0 时也无法区分「本来该是 0」和「因为除了 0 才是 0」。所以「先求总乘积再除」这条路本身就有 bug，题目的「禁用除法」其实是顺水推舟。正确思路绕开总乘积，分别算每个位置的「左半 × 右半」。

### Q2：`answer` 数组的初值为什么填 1（或者说，递推里为什么用 1 当起点）？

因为这是「**乘积**」问题，乘法的单位元是 **1**（`x * 1 = x`），不是 0。`answer[0]` 表示「下标 0 左侧所有元素的乘积」，而它左边啥也没有，「空集的乘积」约定为 1 才能让递推 `answer[i] = nums[i-1] * answer[i-1]` 自洽（不然一旦填 0，后续所有 `answer[i]` 都会被乘成 0，全盘作废）。

对比一下 53 题 Kadane：那是「**和**」问题，加法单位元是 0，所以 `pre` 初值填 0。**「乘积」用 1、「和」用 0，对应各自的单位元**，别记混了。

### Q3：输出数组算不算额外空间？题目为什么这么说？

不算。题目进阶明确写「输出数组 **不被视为** 额外空间」。这是力扣/算法题里的通行约定：**题目要求你返回的那个数组，无论多大，都不计入空间复杂度**（因为它本身就是答案的载体，不是你为了计算而额外申请的辅助空间）。所以本解法里 `answer` 长度 n，但额外空间只算 `R` 这一个变量，是 O(1)。这种「把结果数组当工作数组反复复用」是压空间常见套路。

### Q4：第二趟为什么必须从右往左？`R` 这个滚动变量到底在维护什么？

`R` 在第二趟里的语义始终是「**当前下标 `i` 右侧所有元素的累乘**」。它从 `R=1` 起步（最右元素右侧为空），每处理完一个 `i` 就 `R *= nums[i]`，把 `nums[i]` 「收编」进右侧累乘——这样走到下一个（更靠左的）下标时，`R` 正好等于那个下标右侧所有元素的乘积。

**方向必须从右往左**，是因为 `R` 要按「从右到左」的顺序把右侧元素一个个累乘进来。如果反过来从左往右扫，`R` 维护的就会是「左侧累乘」，和第一趟重复了，右侧乘积就永远进不来。一句话记：**第一趟左→右算前缀积，第二趟右→左算后缀积，两趟方向必须相反**。

## 复盘

- **核心套路**：「除自身以外的乘积 / 和」这类问题，标准做法是 **前缀 × 后缀**。把每个位置拆成「左半部分」和「右半部分」两段，分别用一趟线性扫描递推出前缀积和后缀积，再合并。这是「**前缀和/前缀积**」思想（同一个套路，把「求和」换成「求积」）的经典应用——题目打的「前缀和」标签正是这个意思。
- **滚动变量压缩**：当 `L[i]` 只依赖 `L[i-1]`、`R[i]` 只依赖 `R[i+1]` 时，不需要开整块数组，一个变量滚动即可。本题更进一步——**直接把结果数组当工作数组复用**，第一趟当 `L` 存，第二趟乘上滚动 `R`，把额外空间从 O(n) 压到 O(1)。这种「输出数组身兼两职」的写法在「输出本身就是 O(n) 数组」的题里很常见，是省空间的通用招。
- **单位元意识**：乘法题用 1、加法题用 0 当「空集」的初值，别混。「空集的乘积 = 1，空集的和 = 0」是前缀类递推的基石。
- **初始化陷阱**：本题还好（数据保证 32 位内），但记住「求和/求积的累加变量」要初始化成单位元，不要无脑给 0。

### 解法二：左右两个数组 L/R（官方方法一，O(n) 时间 O(n) 空间）

这是方法二的原型，思路更直观：开两个数组 `L[]`、`R[]` 分别存「`i` 左侧乘积」和「`i` 右侧乘积」，再让 `answer[i] = L[i] * R[i]`。代价是多用了两个长度 n 的数组，额外空间 O(n)。理解了它，方法二只是把 `L[]` 拍扁进 `answer`、把 `R[]` 拍扁成单个变量 `R` 而已。

```cpp
class Solution {
public:
    vector<int> productExceptSelf(vector<int>& nums) {
        int length = nums.size();

        // L 和 R 分别表示左右两侧的乘积列表
        // vector<int> L(length, 0)：构造长度为 length、初值全 0 的 int 数组。
        //   - 这里初值填 0 无所谓，因为下面 L[0]、R[length-1] 和循环里都会逐一赋值覆盖。
        //   - 这就是方法一「额外 O(n) 空间」的来源：多开了 L、R 两个长度 n 的数组。
        vector<int> L(length, 0), R(length, 0);

        vector<int> answer(length);

        // L[i] 为索引 i 左侧所有元素的乘积
        // 对于索引为 '0' 的元素，因为左侧没有元素，所以 L[0] = 1
        L[0] = 1;
        for (int i = 1; i < length; i++) {
            L[i] = nums[i - 1] * L[i - 1];
        }

        // R[i] 为索引 i 右侧所有元素的乘积
        // 对于索引为 'length-1' 的元素，因为右侧没有元素，所以 R[length-1] = 1
        R[length - 1] = 1;
        for (int i = length - 2; i >= 0; i--) {
            R[i] = nums[i + 1] * R[i + 1];
        }

        // 对于索引 i，除 nums[i] 之外其余各元素的乘积就是左侧所有元素的乘积乘以右侧所有元素的乘积
        for (int i = 0; i < length; i++) {
            answer[i] = L[i] * R[i];
        }

        return answer;
    }
};
```

- **时间**：O(n)（三趟线性扫描）。
- **空间**：O(n) 额外（`L`、`R` 各占 n）。
- **与方法二对比**：方法二把 `L` 拍扁进 `answer`、`R` 拍扁成滚动变量 `R`，省下两个数组；代价是 `answer` 语义在两趟里不同（第一趟是 `L`、第二趟才是最终答案），可读性略差。做题首选方法二（满足进阶要求），讲思路时先用方法一铺路更顺。
