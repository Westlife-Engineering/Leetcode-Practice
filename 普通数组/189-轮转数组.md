# 189 轮转数组

- 难度：中等
- 标签：**数组**、数学、双指针

> 说明：本题参考力扣官方题解「[旋转数组](https://leetcode.cn/problems/rotate-array/solution/xuan-zhuan-shu-zu-by-leetcode-solution-nipk/)」。正文主解是 **数组翻转法**（官方方法三，三次翻转实现 O(1) 原地轮转，最优雅）；官方另外两种解法「使用额外数组」（方法一）和「环状替换」（方法二）放在「复盘」章节作对比。

## 题目描述

给定一个整数数组 `nums`，将数组中的元素向右轮转 `k` 个位置，其中 `k` 是非负数。

**示例 1：**

```
输入: nums = [1,2,3,4,5,6,7], k = 3
输出: [5,6,7,1,2,3,4]
解释:
向右轮转 1 步: [7,1,2,3,4,5,6]
向右轮转 2 步: [6,7,1,2,3,4,5]
向右轮转 3 步: [5,6,7,1,2,3,4]
```

**示例 2：**

```
输入：nums = [-1,-100,3,99], k = 2
输出：[3,99,-1,-100]
解释:
向右轮转 1 步: [99,-1,-100,3]
向右轮转 2 步: [3,99,-1,-100]
```

**提示：**

- `1 <= nums.length <= 10^5`
- `-2^31 <= nums[i] <= 2^31 - 1`
- `0 <= k <= 10^5`

**进阶：**

- 尽可能想出更多的解决方案，至少有 **三种** 不同的方法可以解决这个问题。
- 你可以使用空间复杂度为 `O(1)` 的 **原地** 算法解决这个问题吗？

## 思路

> 本题主要参考力扣官方题解「方法三：数组翻转」。

「向右轮转 `k` 位」的含义：每个元素的下标都加 `k`，超出末尾的就从数组开头「绕回来」。直观结果就是**末尾的 `k` 个元素被搬到了数组开头**，其余元素整体右移 `k` 位。比如 `[1,2,3,4,5,6,7], k=3` → `[5,6,7,1,2,3,4]`，末尾的 `5,6,7` 跑到了最前面。

### 第一步：必须先 `k %= n`（最容易忘的坑）

题目给的 `k` 可能比数组长度 `n` 大（如 `n=7, k=10`）。由于「轮转一圈」会回到原位，**轮转 `k` 次等价于轮转 `k mod n` 次**：`k=10, n=7` 时 `10 mod 7 = 3`，和 `k=3` 效果完全一样。

所以开头第一件事永远是：

```
k %= nums.size();
```

- 特例 `k == 0`（包括 `k` 本来就是 0、以及 `k` 是 `n` 的整数倍被取模归零的情况）：数组**原地不动**，三次翻转虽然也对（翻转-翻转-翻转抵消），但理解上等价于「直接返回」。

### 官方主解：三次翻转（O(1) 原地，最优雅）

**核心观察**：结果数组其实是「末尾 `k` 个元素」+「前 `n-k` 个元素」拼起来的。只要能把这两段各自挪到正确位置、再保证段内顺序不变即可。

**翻转的妙处在于：一次翻转同时完成「搬段」和「打乱段内顺序」，而打乱的部分刚好被第二次翻转还原。** 三步如下：

1. **整体翻转** `nums[0..n-1]`：把末尾 `k` 个元素挪到数组开头（但段内顺序是反的），前 `n-k` 个挪到末尾（也是反的）。
2. **翻前 `k` 个** `nums[0..k-1]`：把上一步开头那段的顺序「正回来」。
3. **翻后 `n-k` 个** `nums[k..n-1]`：把末尾那段的顺序也「正回来」。

三次翻转后，每段位置对了、段内顺序也对了，就是答案。

### 用示例走一遍（`n=7, k=3`，先 `k%=n` → `k=3`）

```
原始数组                         1 2 3 4 5 6 7
① 翻转所有 [0, 6]               7 6 5 4 3 2 1   ← 末尾 5,6,7 搬到了开头（但反序 7,6,5）
② 翻转 [0, 2]（前 k=3 个）       5 6 7 4 3 2 1   ← 开头那段顺序正回来：7,6,5 → 5,6,7 ✓
③ 翻转 [3, 6]（后 n-k=4 个）     5 6 7 1 2 3 4   ← 末尾那段顺序正回来：3,2,1 → 1,2,3,4 ✓
返回 [5,6,7,1,2,3,4] ✓
```

**为什么翻转三次一定对？** 直觉上：整体翻转 = 「交换前后两段」+「两段各自反序」。后两次翻转刚好抵消了「各自反序」的部分，留下「交换前后两段」的效果——这正是轮转 `k` 位要干的事。数学上可以验证：对任意 `i`，三次翻转后 `nums[i]` 最终落在 `(i + k) mod n` 位置（即「向右移 k 位」）。

## 代码

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        // n 是数组长度。注意 k 的类型用 int 即可（题目 k <= 10^5），
        // 但 STL 下标运算常和 size()（类型为 size_t，无符号）混用，下面取模前先存好 n。
        int n = nums.size();

        // 关键预处理：k %= n。题目 k 可能 > n（如 n=7,k=10），轮转一圈回到原位，
        //   所以「轮转 k 次」等价于「轮转 k mod n 次」。
        //   - 必须放在翻转之前，否则后续「前 k 个 / 后 n-k 个」的区间会越界或算错。
        //   - 取模后若 k == 0（k 本身是 0，或 k 是 n 的整数倍），相当于「原地不动」，
        //     三次翻转会自然抵消（整体翻转→再翻转→再翻转），结果不变，无需特判返回。
        k %= n;

        // ① 整体翻转 nums[0..n-1]。
        //   std::reverse(first, last) 是 <algorithm> 里的算法：
        //   - 参数是两个「迭代器」，规定一个左闭右开区间 [first, last)。
        //   - nums.begin() 指向首元素，nums.end() 指向「最后一个元素的下一个位置」
        //     （past-the-end，不指向任何有效元素），合起来正好覆盖整个数组。
        //   - 它是「就地」操作：直接在 nums 上反转，不开新数组，返回 void。
        //   - 复杂度 O(last - first)，对整个数组即 O(n)；交换次数为 n/2。
        //   - 注意区间是 [first, last) 左闭右开，所以 reverse(begin, end) 翻的是
        //     下标 [0, n-1] 全部元素，不会漏掉末尾也不会越界。
        reverse(nums.begin(), nums.end());

        // ② 翻转前 k 个 nums[0..k-1]，把它们由「整体翻转造成的反序」正回来。
        //   - nums.begin() + k 得到「第 k 个元素的迭代器」，作为右开端点，
        //     所以 [begin, begin+k) 覆盖下标 [0, k-1]，正好 k 个元素。
        //   - 例：k=3 时翻下标 0,1,2。
        reverse(nums.begin(), nums.begin() + k);

        // ③ 翻转后 n-k 个 nums[k..n-1]。
        //   - [begin+k, end) 覆盖下标 [k, n-1]，即剩下那一段，把它也正回来。
        //   - 例：n=7,k=3 时翻下标 3,4,5,6。
        //   - 因为 STL 区间左闭右开，begin()+k 到 end() 正好到末尾，不会越界。
        reverse(nums.begin() + k, nums.end());
    }
};
```

## 复杂度

- **时间**：O(n)
  - 三次 `reverse` 分别翻转 `n`、`k`、`n-k` 个元素，总交换次数 `n/2 + k/2 + (n-k)/2 = n`，整体线性。
- **空间**：O(1)
  - `std::reverse` 原地操作，只用了 `n`、`k` 两个辅助变量，没有开额外数组。满足「进阶」的 O(1) 原地要求。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：`k > n` 怎么办？为什么必须先取模？

轮转 `n` 次等于没转（每个元素都绕了一圈回到原位），所以轮转 `k` 次等价于轮转 `k mod n` 次。比如 `n=7, k=10`，真正有效的是 `10 mod 7 = 3` 步。

**必须先取模**有两个原因：

1. **正确性**：后续翻转用 `begin() + k` 定位区间，若 `k > n`，下标会越界（迭代器加过头）。
2. **逻辑**：`k=10` 和 `k=3` 的轮转结果完全相同，不取模就是白算。

取模后 `k` 落在 `[0, n-1]`。当 `k == 0`（包括 `k` 本来就是 0、或 `k` 是 `n` 的整数倍被取模归零）时，三次翻转依次是「整体翻 → 翻前 0 个（空操作）→ 翻后 n 个（又翻回去）」，净效果为零，数组不变，符合「轮转 0 步」的预期，无需特殊处理。

### Q2：为什么「翻转三次」一定能得到正确结果？

可以从「等价变换」角度理解。设最终每个元素要从下标 `i` 移到 `(i+k) mod n`。把数组看作「前 `n-k` 个」和「后 `k` 个」两段：

```
原始：     [ A 段 (n-k 个) | B 段 (k 个) ]
目标：     [ B 段          | A 段          ]   ← 等价于把 B 搬到前面，A 顺序不变
```

三次翻转恰好完成这件事：

1. **整体翻转**：得到 `[Bᵣ | Aᵣ]`（B、A 各自反序，且位置交换）。
2. **翻前 k 个**：把 `Bᵣ` 反序回 `B`，开头变成正确的 B 段。
3. **翻后 n-k 个**：把 `Aᵣ` 反序回 `A`，末尾变成正确的 A 段。

最终 `[B | A]`，且 B、A 内部顺序都和原始一致，正是轮转 `k` 位的结果。关键在于「整体翻转」一步同时做了「换段」和「反序」两件事，而后两次翻转只把「反序」抵消，留下「换段」——这是该解法的精髓。

### Q3：`std::reverse` 的 `[first, last)` 区间到底是什么意思？为什么是左闭右开？

C++ STL 的迭代器区间**一律是左闭右开** `[first, last)`：包含 `first` 指向的元素，**不包含** `last` 指向的元素。

- `reverse(nums.begin(), nums.end())`：`begin` 是首元素，`end` 是「尾后位置」（past-the-end，不指向有效元素），合起来覆盖 `[0, n-1]` 全部 `n` 个元素。
- `reverse(nums.begin(), nums.begin() + k)`：覆盖 `[0, k-1]`，即前 `k` 个。`begin()+k` 指向第 `k+1` 个元素（下标 `k`），但它**不被包含**。
- `reverse(nums.begin() + k, nums.end())`：覆盖 `[k, n-1]`，即后 `n-k` 个。

左闭右开的好处是：`end - begin` 直接等于元素个数，两个相邻区间 `[a, b)` 和 `[b, c)` 不重不漏（`b` 既是前一个的右端、又是后一个的左端）。本题第二段从 `begin()+k` 开始，正好接在第一段之后，不重叠也不漏元素。

### Q4：为什么不用手写 `while (start < end) swap(...)` 的翻转函数？

官方代码里方法三确实手写了一个 `reverse` 辅助函数。但 STL 已经提供了 `std::reverse`（在 `<algorithm>`，力扣环境默认包含），**直接调用更简洁、更不易写错边界**（手写循环容易在 `start < end` 还是 `start <= end`、以及下标增减顺序上出错）。两者复杂度完全一致（都 O(n) 原地），STL 版本还能从编译器优化中受益。养成「能用 STL 就不手写」的习惯，是 C++ 的惯用风格。

## 复盘

- **核心套路**：**「数组整体平移 / 轮转」类问题** → 优先想到 **翻转法**。三次翻转（整体翻 + 两段分别翻）能在 O(n) 时间、O(1) 空间内原地完成，是这类题的最优解模板。类似的还有「旋转字符串」「翻转单词顺序」等，都是「先整体翻、再分段翻」的思路。
- **先取模的习惯**：凡是涉及「周期性移动」（轮转、跳跃、约瑟夫环）的题，第一步永远是 `k %= n`（或 `i %= n`），把 `k` 规约到 `[0, n-1]`，能避开绝大多数边界 bug。
- **STL 左闭右开**：所有 STL 算法的区间都是 `[first, last)`。记住 `end()` 是「尾后」、`begin()+k` 指向下标 `k`（且不含于区间），写区间时心里默念「右开」就不会越界。

### 解法二：使用额外数组（官方方法一，O(n) 时间 O(n) 空间）

最朴素的思路：开一个新数组 `newArr`，把每个 `nums[i]` 直接放到 `newArr[(i + k) % n]`，最后拷回 `nums`。正确性直观（下标映射直接写出来），但需要 O(n) 额外空间，不满足「进阶」的 O(1) 原地要求。

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> newArr(n);                    // 开一个长度 n 的新数组，默认值 0
        for (int i = 0; i < n; ++i) {
            newArr[(i + k) % n] = nums[i];        // nums[i] 轮转后落到 (i+k)%n 位置
        }
        // assign(first, last)：把 [first,last) 区间的元素赋值给 nums，替换原内容。
        nums.assign(newArr.begin(), newArr.end());
    }
};
```

- **时间**：O(n)（一次遍历 + 一次拷贝）
- **空间**：O(n)（新数组）
- **何时用**：面试时如果一时想不到翻转法，这是最稳的「保底」解法，正确性最容易讲清。

### 解法三：环状替换（官方方法二，O(n) 时间 O(1) 空间）

也是 O(1) 原地解法，思路更「巧妙」：从下标 `0` 出发，沿 `(i + k) % n` 这条链不断把元素「踢」到下一个位置，直到绕回起点形成一个环；若一圈没走完所有元素（即 `gcd(k, n) > 1` 时有多个独立环），就换下一个未访问的起点继续。被访问的元素总数恰为 `gcd(k, n)` 个起点 × 每个环的长度，合计 `n`，所以 O(n)。

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        k = k % n;
        int count = gcd(k, n);                    // __gcd / std::gcd：最大公约数，环的个数
        for (int start = 0; start < count; ++start) {
            int current = start;
            int prev = nums[start];
            do {
                int next = (current + k) % n;     // current 这个元素要去的位置
                swap(nums[next], prev);           // 把 prev 放到 next，同时取出原 next 存进 prev
                current = next;
            } while (start != current);           // 绕回起点 → 这个环结束
        }
    }
};
```

- **时间**：O(n)（每个元素恰好被访问一次）
- **空间**：O(1)
- **对比**：和翻转法同为 O(1) 空间最优解，但需要理解「环 + gcd」的数学，常数也略大、代码更绕；面试里翻转法通常更受青睐（思路短、好讲、好写）。环状替换的价值在于展示「下标映射 + 置换环」这一通用技巧（在「寻找重复数」「数组原地哈希」等题里也会用到）。
