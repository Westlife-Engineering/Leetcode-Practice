# 41 缺失的第一个正数

- 难度：困难
- 标签：**数组**、哈希表
- 力扣链接：https://leetcode.cn/problems/first-missing-positive/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「[缺失的第一个正数](https://leetcode.cn/problems/first-missing-positive/solution/que-shi-de-di-yi-ge-zheng-shu-by-leetcode-solution/)」。正文主解是 **方法二：置换（原地哈希 / 数字归位法）**——把每个 `1~n` 范围内的数 `x` 交换到下标 `x-1` 的位置，再扫一遍找第一个没归位的。O(n) 时间 O(1) 空间，正好满足进阶要求。官方「方法一：哈希表（打标记法）」放在「复盘」作对比。

## 题目描述

给你一个未排序的整数数组 `nums` ，请你找出其中没有出现的最小的正整数。

请你实现时间复杂度为 `O(n)` 并且只使用常数级别额外空间的解决方案。

**示例 1：**

```
输入：nums = [1,2,0]
输出：3
解释：范围 [1,2] 中的数字都在数组中。
```

**示例 2：**

```
输入：nums = [3,4,-1,1]
输出：2
解释：1 在数组中，但 2 没有。
```

**示例 3：**

```
输入：nums = [7,8,9,11,12]
输出：1
解释：最小的正数 1 没有出现。
```

**提示：**

- `1 <= nums.length <= 10^5`
- `-2^31 <= nums[i] <= 2^31 - 1`

**进阶：** 时间 O(n)、额外空间 O(1)。

## 思路

> 本题主要参考力扣官方题解「方法二：置换」。

题目的两个硬约束是关键：**时间 O(n)**（不能排序，排序至少 O(n log n)）+ **空间 O(1)**（不能开哈希表、不能开新数组）。这两条一起卡掉了很多「直观」做法，逼出真正的考点——**原地哈希**。

### 暴力 / 哈希集：为什么不行？

如果没有空间限制，最直观的做法是：把所有数塞进一个 `unordered_set`，然后从 `1` 开始依次问「`1` 在不在集合里？`2` 呢？……」第一个不在的就是答案。时间 O(n)、空间 O(n)。

但这违反「**常数额外空间**」。`n ≤ 10^5`，开哈希集要几 MB，空间 O(n) 不达标。所以必须想办法「**借用数组本身当哈希表**」。

### 关键观察一：只关心 `1~n` 范围内的数

设数组长度为 `n`。答案（缺失的最小正整数）**一定落在 `[1, n+1]` 之间**：

- 最好的情况是数组恰好包含 `1, 2, ..., n`（全部就位），此时答案是 `n+1`；
- 否则 `[1, n]` 里一定有某个数缺失，那个最小的缺失数就是答案，范围 `[1, n]`。

也就是说，`≤ 0` 的数和 `> n` 的数**对答案毫无贡献**——它们不可能是答案（答案 ≤ n+1），也占着位置「挡道」。我们只需要把注意力放在 `1~n` 这 `n` 个候选值上。

这一步把「无限大的正整数域」收缩成「`n` 个候选数 + `n` 个数组槽位」——候选数和槽位数量正好相等，这是后面能用「**值 x 放到下标 x-1**」的前提。

### 关键观察二：数字 `x` 应该放到下标 `x-1`（原地哈希）

既然只看 `1~n`，而数组下标正好是 `0~n-1`，那么最自然的映射就是：

```
值 x（1 ≤ x ≤ n）  →  应该放在下标 x-1 处
```

这样「**位置 i 上放的应该是值 i+1**」。把每个符合条件的数都归位后，再从头扫一遍：第一个满足 `nums[i] != i+1` 的位置 `i`，答案就是 `i+1`；如果全都对得上，答案就是 `n+1`。

这就是「**原地哈希 / 把值当索引**」——数组本身充当哈希表，键（值）通过 `x-1` 直接映射到槽位（下标），不需要额外空间。

### 归位算法：用 `while` 循环 + `swap`

对每个位置 `i`，只要 `nums[i]` 是个 `1~n` 范围内的数、且它还没归位（`nums[nums[i]-1] != nums[i]`，即它该去的那个槽位上不是它自己），就把它**换到它该去的位置** `nums[i]-1`。

```
while (nums[i] 在 [1, n] 范围内 且 nums[nums[i]-1] != nums[i]) {
    swap(nums[nums[i]-1], nums[i]);
}
```

**为什么是 `while` 不是 `if`？** 因为换过来的新值可能也是个 `1~n` 内的数，需要继续往它的目标位置送——直到当前位置 `i` 上的值「不在范围内」或「已经归位（目标位置上就是它自己）」为止。用 `if` 只交换一次，换来的新数就没机会继续归位了。

**为什么是 `swap` 而不是直接赋值？** `nums[nums[i]-1] = nums[i]` 会把目标位置上**原来的值覆盖丢失**——那个被覆盖的数本来也该归位的，现在没了。`swap` 把它换到当前位置 `i` 来，下一轮 `while` 判断时正好处理它，信息不丢失。

### 用示例 2 手动推导 `[3,4,-1,1]`（n=4）

```
i=0: nums[0]=3, 在[1,4]内, nums[3-1]=nums[2]=-1 != 3 → swap(nums[2],nums[0])
     数组变 [-1,4,3,1]   ← 3 归位到下标2
     再判 nums[0]=-1, 不在[1,4]内 → while结束, i++

i=1: nums[1]=4, 在[1,4]内, nums[4-1]=nums[3]=1 != 4 → swap(nums[3],nums[1])
     数组变 [-1,1,3,4]   ← 4 归位到下标3
     再判 nums[1]=1, 在[1,4]内, nums[1-1]=nums[0]=-1 != 1 → swap(nums[0],nums[1])
     数组变 [1,-1,3,4]   ← 1 归位到下标0
     再判 nums[1]=-1, 不在[1,4]内 → while结束, i++

i=2: nums[2]=3, nums[3-1]=nums[2]=3 == 3, 已归位 → while不进, i++
i=3: nums[3]=4, nums[4-1]=nums[3]=4 == 4, 已归位 → while不进, i++
```

归位后数组 `[1,-1,3,4]`。扫一遍找第一个 `nums[i] != i+1`：

```
i=0: nums[0]=1 == 1 ✓
i=1: nums[1]=-1 != 2 ✗ → 答案是 2 ✓
```

与示例输出一致。

## 代码

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        // vector<int>& nums：输入数组的引用，直接在原数组上改动（满足 O(1) 额外空间）。
        int n = nums.size();   // size()：返回元素个数，O(1)。

        // 第一阶段：把每个 1~n 范围内的数 x 归位到下标 x-1 处。
        for (int i = 0; i < n; ++i) {
            // while 循环条件三段（缺一不可，且顺序靠短路求值保护下标不越界）：
            //   1) nums[i] > 0        —— 只处理正数（负数和 0 不可能是答案，跳过）；
            //   2) nums[i] <= n       —— 只处理 1~n 范围内的数（超过 n 的数无对应槽位，
            //                            且不影响答案，跳过；这一条也保证 nums[i]-1 ∈ [0,n-1]，
            //                            用作下标不会越界）；
            //   3) nums[nums[i]-1] != nums[i] —— 目标位置上还不是 nums[i]（即还没归位），
            //                            才需要换；若目标位置上已经是自己，再换就是死循环/无意义。
            //
            // 为什么用 while 而不是 if：
            //   swap 之后，位置 i 上换来了「原本在 nums[i]-1 处的那个值」，它可能也属于 1~n
            //   且尚未归位，必须继续尝试把它也送走。用 if 只交换一次就会漏掉这种「连锁归位」。
            //   while 会一直换到当前位置 i 上的值「不在范围 / 已归位」为止。
            //
            // 为什么用 swap 而不是 nums[nums[i]-1] = nums[i]：
            //   直接赋值会覆盖丢失目标位置上的旧值；swap 把旧值换到位置 i，下一轮 while
            //   正好处理它，信息不丢。每个元素至多被 swap 一次（见复杂度分析）。
            while (nums[i] > 0 && nums[i] <= n && nums[nums[i] - 1] != nums[i]) {
                // swap(a, b)：<utility>/<algorithm> 里的函数，交换两个同类型对象的值。
                //   - 对 int 是三次移动（tmp=a; a=b; b=tmp），O(1)。
                //   - 注意：swap 的两个参数必须是左值引用，这里 nums[nums[i]-1] 和 nums[i]
                //     都是 vector 的元素（左值），合法。
                //   - 细节坑：swap(nums[nums[i]-1], nums[i]) 的执行顺序里，
                //     先求值 nums[i]-1 这个下标、锁定目标位置，再交换两处值，安全。
                swap(nums[nums[i] - 1], nums[i]);
            }
        }

        // 第二阶段：找第一个没归位的位置。
        //   归位后理想状态是 nums[i] == i+1（位置 i 放值 i+1）。
        for (int i = 0; i < n; ++i) {
            if (nums[i] != i + 1) {
                return i + 1;   // 位置 i 缺了 i+1，它就是最小缺失正整数
            }
        }

        // 1~n 全部就位（数组恰好含 1,2,...,n），答案是 n+1。
        //   这也是答案的上界：n 个槽位最多放下 1~n 这 n 个数，
        //   若全放下了，缺失的最小正整数必然是 n+1。
        return n + 1;
    }
};
```

## 复杂度

- **时间**：O(n)
  - 粗看是「`for` 套 `while`」，像 O(n²)，其实不是。关键不变式：**每次 `swap` 都至少让一个数归位**（被换到 `nums[i]-1` 的那个值从此待在正确位置不再移动）。数组一共 `n` 个位置，所以整个算法至多发生 `n` 次 `swap`。`for` 循环本身 `n` 步，每步要么进 `while` 做若干次 `swap`（总摊到 n 次），要么直接跳过。把所有 `swap` 加起来 ≤ n 次，总操作 O(n)。
- **空间**：O(1)
  - 只用了下标 `i` 和 `n` 两个变量，原地修改 `nums`，没有开任何额外容器。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么内层用 `while` 而不是 `if`？

因为**一次 `swap` 不一定能让当前位置 `i` 变成「不用再处理」的状态**。

举例 `[3,4,-1,1]` 的 `i=1`：`nums[1]=4` 先被换到下标 3，但下标 3 上的旧值 `1` 被换到了位置 1。这个 `1` 也属于 `1~n`、且没归位，**必须继续处理**——把它换到下标 0。如果用 `if`，换一次就 `i++` 走人了，位置 1 上的 `1` 就被漏掉，最终归位不完整，答案出错。

`while` 的本质：**只要当前位置 `i` 上的值还「应该且能够」被送走，就继续送**。换来的新值正好接受下一轮判断。直到位置 `i` 上的值变成「不在 `1~n` 范围」（如负数、0、超过 n）或「目标位置上已经是自己」（重复元素/已归位），才停下来 `i++`。

### Q2：重复元素会不会让 `while` 死循环？

不会，**第三个条件 `nums[nums[i]-1] != nums[i]` 就是防这个的**。

假设 `nums = [1,1]`（n=2）：

- `i=0`：`nums[0]=1`，`nums[1-1]=nums[0]=1`，`1 != 1` 为 `false`，`while` 不进，`i++`。
- `i=1`：`nums[1]=1`，`nums[1-1]=nums[0]=1`，`1 != 1` 为 `false`，`while` 不进，`i++`。

两个相同的 `1` 不会互相交换——目标位置上已经是同样的值，再换毫无意义且会死循环，所以条件里加 `!=` 直接挡掉。归位后 `[1,1]`，扫描时 `nums[1]=1 != 2`，返回 `2`，正确。

### Q3：为什么答案是 `n+1`？数组里如果有超过 n 的大数怎么办？

**答案上界就是 `n+1`**：数组长度 `n`，能放下 `1~n` 这 `n` 个不同的正整数已是极限。如果全放下了（归位后 `nums[i]==i+1` 对所有 `i` 成立），那 `[1,n]` 一个不缺，缺失的最小正整数只能是 `n+1`。如果有任何一个位置没对上，答案就出现在 `[1,n]` 里，更小。

至于数组里那些 `> n` 的数（或 `≤ 0` 的数），它们**不可能是答案**（答案 ≤ n+1 < 那些 `> n` 的数），而且它们**占着的槽位正好对应「某个该出现却没出现的数」**。归位时第二个条件 `nums[i] <= n` 会跳过它们，最终它们会被「挤」到那些缺失数的位置上，扫描时被 `nums[i] != i+1` 抓出来。

例如 `[7,8,9,11,12]`（n=5），全是 `> n` 的数，`while` 全程不进，归位后数组不变。扫描 `i=0`：`nums[0]=7 != 1`，返回 `1`，正确。

### Q4：`while` 条件里三个判断的顺序能换吗？

**不能随便换**，特别是把 `nums[nums[i]-1]` 那段放最前面会很危险。

现在的顺序是 `nums[i] > 0` → `nums[i] <= n` → 才敢用 `nums[i]-1` 作下标。C++ 的 `&&` 是**短路求值**：只有前两个成立（即 `nums[i] ∈ [1,n]`），才会去算 `nums[nums[i]-1]`。如果 `nums[i]` 是个 `≤ 0` 或 `> n` 的值，`nums[i]-1` 就是个非法下标（负数或超过数组长度），用它去索引 `nums[]` 是**越界 / 未定义行为**，可能崩溃。所以「**范围判断必须在用 `nums[i]-1` 作下标之前**」，这个顺序是安全底线。

## 复盘

- **核心套路**：「**原地哈希 / 把值当索引**」。当题目要求 O(1) 空间、且数据范围天然与下标范围对应（值 `x` 对应下标 `x-1` 或 `x`）时，不要开哈希表，**让数组本身充当哈希表**：值通过简单运算直接映射到槽位。同类题目：287 寻找重复数（Floyd 或下标标记）、442 数组中重复的数据、448 找到所有数组中消失的数字，都是这一套。
- **「归位」思想**：把每个元素换到它「该在」的位置，是「原地哈希」最直观的实现方式。配合 `while`（连锁归位）+ `swap`（不丢信息）+ 三段条件（范围、去重、防越界），几乎是一个固定模板。
- **复杂度分析的陷阱**：看到 `for` 套 `while` 别本能地说 O(n²)。本题的关键不变式是「**每次 `swap` 至少归位一个元素**」，而元素总数 `n` 有限，所以 `swap` 总次数 ≤ n，均摊后整体 O(n)。这种「**用『操作带来多少永久进展』来给均摊复杂度兜底**」的论证，在 283 移动零、并查集路径压缩里也都见过。
- **答案上界 `n+1` 的来源**：这类「最小缺失正整数 / 最小没出现的数」题，答案总在 `[1, n+1]`。脑子里先锁死这个范围，能把「无限正整数域」收缩成「n 个候选」，整个原地哈希的思路才成立。

### 解法二：官方方法一·哈希表打标记（O(n) 时间 O(1) 空间，对比用）

官方还给了另一种也满足 O(n)/O(1) 的做法，思路更「技巧向」，不如置换法直观，但思路巧妙值得一看。

**核心**：复用「正负号」当标记位。

1. **预处理**：把所有 `≤ 0` 的数改成 `n+1`（这样数组里只剩正数，且 `1~n` 范围内的数原样保留）；
2. **打标记**：扫一遍，对每个 `nums[i]`，取 `num = abs(nums[i])`；若 `num ≤ n`，就把下标 `num-1` 处的数变成**负的**（`nums[num-1] = -abs(nums[num-1])`）。这一步的含义是「值 `num` 存在，于是在下标 `num-1` 处打个负号标记」；
3. **找答案**：再扫一遍，第一个 `nums[i] > 0` 的位置 `i`，说明「值 `i+1` 没被打过标记」，即 `i+1` 没出现过，返回 `i+1`；全为负则返回 `n+1`。

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        int n = nums.size();
        for (int& num : nums) {       // 第1步：非正数改成 n+1，清掉干扰
            if (num <= 0) num = n + 1;
        }
        for (int i = 0; i < n; ++i) { // 第2步：用正负号当「存在性」标记
            int num = abs(nums[i]);   // abs：<cmath>，取绝对值。读取时要去绝对值，
                                      //   因为前面的标记可能已把 nums[i] 改成负数。
            if (num <= n) {
                nums[num - 1] = -abs(nums[num - 1]); // 把目标位置改成负的，但不改变其绝对值
            }
        }
        for (int i = 0; i < n; ++i) { // 第3步：第一个仍为正的位置 → 缺 i+1
            if (nums[i] > 0) return i + 1;
        }
        return n + 1;
    }
};
```

- **时间**：O(n)，三次线性扫描。
- **空间**：O(1)，原地修改。
- **对比**：打标记法巧妙地「**用符号位当 1 bit 的额外存储**」，避免了 `swap` 的连锁归位；但引入了 `abs` 和「把 ≤0 改成 n+1」的预处理，可读性略差，且如果数组元素本来就有特殊含义就不通用。置换法（正文主解）更接近「自然语言描述的归位」，便于记忆和推导，推荐以置换法为主。
