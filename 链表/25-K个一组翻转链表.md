# 25 K 个一组翻转链表

- 难度：困难
- 标签：**递归**、**链表**
- 力扣链接：https://leetcode.cn/problems/reverse-nodes-in-k-group/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「K 个一组翻转链表」（slug：`k-ge-yi-zu-fan-zhuan-lian-biao-by-leetcode-solutio`）。正文主解是 **迭代法（哑节点 hair + 每组先探查 k 个、够数才翻转并接回主链）**，时间 O(n)、空间 O(1)，是 206 反转链表的进阶版——翻转的不再是整条链，而是「一段段」地翻并接回前后；递归法放在「复盘」章节作对比。

## 题目描述

给你链表的头节点 `head` ，每 `k` 个节点一组进行翻转，请你返回修改后的链表。

`k` 是一个正整数，它的值小于或等于链表的长度。如果节点总数不是 `k` 的整数倍，那么请将最后剩余的节点保持原有顺序。

你不能只是单纯的改变节点内部的值，而是需要实际进行节点交换。

**示例 1：**

```
输入：head = [1,2,3,4,5], k = 2
输出：[2,1,4,3,5]
```

**示例 2：**

```
输入：head = [1,2,3,4,5], k = 3
输出：[3,2,1,4,5]
```

**提示：**

- 链表中的节点数目为 `n`
- `1 <= k <= n <= 5000`
- `0 <= Node.val <= 1000`

**进阶：** 你可以设计一个只用 `O(1)` 额外内存空间的算法解决此问题吗？

> 题目两个关键约束要记住：① **不足 k 个的最后一组保持原样不动**（不是翻一部分）；② **只能改指针、不能改 val**（和 24 题一样的禁令，规避偷懒做法）。进阶要求 O(1) 空间，正是迭代法相对递归法的核心优势。

## 思路

> 本题主要参考力扣官方题解的「方法一：模拟」（即迭代法）。

### 本题 = 206 反转链表 + 「分段」+ 「接回主链」

如果做过 206 反转链表，本题的「翻转」动作你已经会了——三指针 `prev/curr/next` 把每个节点的 `next` 掉头。新东西只有两点：

1. **翻转的不是整条链，而是「一段 k 个节点」**：所以要界定「从哪翻到哪」。
2. **翻转完要接回主链**：一段翻转后头尾颠倒，必须把它重新焊到前驱和后继之间，否则链表断成几截。

这两件事就是本题的全部难点。把它拆成「分段 + 翻转一段 + 接回」三步，就和 206 题对上了。

### 和 24 题「两两交换」的区别：24 交换 2 个，25 要翻转整段 k 个

很多人会本能地把 24 题的写法往这里套，但两者有本质差别：

- **24 题每组只有 2 个节点**，交换两个节点只需要固定的「三步指针赋值」(`temp->next = node2; node1->next = node2->next; node2->next = node1`)，是「一次性」的局部重排。
- **25 题每组有 k 个节点**（k 是参数，可能 3、5、甚至 5000），不可能写出固定几步的指针赋值——必须用一个**循环**把这一段翻转过来，也就是把 206 题的翻转循环原封不动搬进来，只是边界从「翻到链表尾」改成「翻到本组尾」。

所以 24 题是 25 题在 k=2 时的「特例简化版」；25 题更通用，更接近 206。把 206 的 `reverseList` 看作「翻转从 a 到链表尾」的工具，本题就是「循环调用一个翻转从 a 到 b 的工具」。

### 为什么要「先探查够不够 k 个」再决定翻不翻？

题目要求「不足 k 个的最后一组保持原样」。这意味着翻转前**必须先数一数这一组有没有 k 个**：

- 够 k 个：翻转这一段，接回主链，指针推进到下一组开头。
- 不够 k 个：**这一段原样不动，直接返回结果**（后面也不会再有完整的 k 个了，因为链表只越往后越短）。

如果不探查就硬翻，最后一组不足 k 个时也会被翻过来，结果就错了。所以「探查 → 够才翻」是题意强制的逻辑，不是优化。

### 翻转「一段」的技巧：把翻转的右边界当作 prev 的初值

206 题翻转整条链时，`prev` 从 `nullptr` 起（因为原头翻完后是尾，尾的 `next` 必须是空）。本题翻转「从 head 到 tail 这一段」时，**`tail` 的下一个节点 `tail->next`（也就是下一组的开头）才是这段翻转后该接上的位置**。所以这里 `prev` 的初值不是 `nullptr`，而是 `tail->next`：

```
翻转前：pre -> head -> ... -> tail -> nex(tail->next) -> ...
                        （要翻转 head..tail 这一段，nex 是后继）
翻转后：pre -> tail -> ... -> head -> nex -> ...
        （head 变成本段尾，接 nex；tail 变成本段头，接 pre）
```

循环条件也从 206 的 `while (curr)` 改成 `while (prev != tail)`——`prev` 一路推进，追上 `tail` 时说明这一段全翻完了。翻完返回 `{tail, head}`（新的头尾）。

### 翻转后怎么「接回主链」？

翻转函数只负责把 `head..tail` 这一段内部掉头，返回新的头 `tail` 和新的尾 `head`。但这一段还悬空着，必须手动焊回主链：

```
pre->next = head;     // 注意：这里的 head 是翻转后函数返回的新头（原 tail）
tail->next = nex;     // 翻转后的尾（原 head）接到后继 nex
```

`pre` 是上一段翻转后的尾（也是这一段的前驱），`nex` 是下一段的开头。这两句把翻转后的一段「缝」回链表中间。

### 为什么需要哑节点 `hair`？

和 24、21 题一个道理：**第一组的头节点翻转后会被换掉**（原头 `head` 翻完变成本组尾，本组新头是原第 k 个节点）。如果不开哑节点，第一组的处理就得特判「前驱是谁、返回值怎么挑」。开了哑节点 `hair`（令 `hair->next = head`），让前驱指针 `pre` 从 `hair` 起步，**第一组也有统一的前驱**；而且最后不管链表翻没翻、头节点有没有变，`hair->next` 永远指向正确的新头，直接 `return hair->next` 即可——不用纠结「该返回原头还是第 k 个节点」。

> 口诀：**只要头节点可能被换掉，就开哑节点**。206/21/24/25 全用这一招。

### 手动推导 `1->2->3->4->5`，k=2，翻成 `2->1->4->3->5`

```
初始  hair -> 1 -> 2 -> 3 -> 4 -> 5 -> nullptr
      pre=hair, head=1

第1组  head=1, k=2
  探查：tail 从 pre 出发走 2 步 → tail=2（没遇到空，够 k 个）
  nex = tail->next = 3
  翻转 head..tail = 1..2：
      prev=tail->next=3, p=1
      第1轮：nex2=p->next=2; 1->next=prev=3; prev=1; p=2   （prev != tail=2，继续）
      第2轮：nex2=p->next=3; 2->next=prev=1; prev=2; p=3   （prev == tail=2，停）
      返回 {新头=tail=2, 新尾=head=1}
      此时这段内部：2 -> 1 -> 3（1 接上了后继 3）
  接回主链：pre->next = 新头 2  →  hair -> 2 -> 1 -> 3 -> 4 -> 5
            tail(=新尾 1)->next = nex=3  （已由翻转函数保证，这里等价）
  推进：pre = tail = 1（新尾当下一组前驱），head = tail->next = 3
  状态：hair -> 2 -> 1 -> 3 -> 4 -> 5，pre=1, head=3

第2组  head=3, k=2
  探查：tail 从 pre=1 走 2 步 → tail=4（够 k 个）
  nex = tail->next = 5
  翻转 head..tail = 3..4：
      prev=tail->next=5, p=3
      第1轮：3->next=5; prev=3; p=4
      第2轮：4->next=3; prev=4; p=5（停）
      返回 {新头=4, 新尾=3}
  接回：pre(=1)->next = 4  →  hair -> 2 -> 1 -> 4 -> 3 -> 5
  推进：pre = 3，head = tail->next = 5
  状态：hair -> 2 -> 1 -> 4 -> 3 -> 5，pre=3, head=5

第3组  head=5, k=2
  探查：tail 从 pre=3 走 1 步 → tail=5；再走第 2 步 → tail = nullptr
  tail 为空，不足 k 个 → return hair->next，原样不动！

最终返回 hair->next：2 -> 1 -> 4 -> 3 -> 5  ✓
```

注意**最后一组只剩 1 个节点（5）不足 k=2，保持原样不动**——这正是探查逻辑的功劳。如果硬翻，5 会孤零零地「翻」成自己，虽然本题单节点翻转结果一样，但 k=3、剩 2 个节点时就会翻错。所以「够才翻」是通用且必要的。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;             // 节点存的值
 *     ListNode *next;      // 指向下一个节点的指针；最后一个节点的 next == nullptr
 *     ListNode() : val(0), next(nullptr) {}                       // 默认构造
 *     ListNode(int x) : val(x), next(nullptr) {}                  // 只给值的构造
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}     // 全参数构造
 * };
 */
class Solution {
public:
    // 翻转一个子链表 [head, tail]（闭区间），返回翻转后的 {新头, 新尾}。
    //   - 和 206 反转链表是同一个套路：三指针 prev/p/nex 逐个掉头。
    //   - 关键区别 1：prev 的初值不是 nullptr，而是 tail->next（即这一段的后继）。
    //     因为翻转后 head 变成本段尾，它的 next 应该接上后继，而不是 nullptr。
    //   - 关键区别 2：循环条件不是 while(p)，而是 while(prev != tail)——
    //     prev 一路推进，追上 tail 时说明 head..tail 这一段已全部掉头完毕。
    //   - 返回 pair<ListNode*, ListNode*>：翻转后头尾互换，新头是原 tail，新尾是原 head。
    //     pair 是 STL 的「双值容器」，first/second 取两个成员；这里用 C++17 的
    //     花括号初始化 {tail, head} 直接构造，比 make_pair(tail, head) 更简洁。
    pair<ListNode*, ListNode*> myReverse(ListNode* head, ListNode* tail) {
        // prev：已翻转段的头（也就是下一个要被掉头节点指向的目标）。
        //   - 初值取 tail->next：翻转完这一段后，原 head 的 next 要指向 tail->next，
        //     也就是「无缝」接上后继。这等价于 206 里 prev 从 nullptr 起的作用，
        //     只是把「nullptr」换成了「本段的后继」。
        ListNode* prev = tail->next;
        // p：当前正在翻转的节点，从本段头 head 开始。
        ListNode* p = head;
        // 只要 prev 还没追上 tail，说明这一段还没翻完。
        while (prev != tail) {
            // nex：临时存 p 原来的下一个节点。和 206 一样，必须先存再改 next，
            //   否则 p->next 被覆盖后就找不到原来的下一个了，链表断裂。
            ListNode* nex = p->next;
            // 翻转核心：让 p 掉头指向 prev。
            p->next = prev;
            // prev 前进：吃进刚翻好的 p，变成已翻转段的新头。
            prev = p;
            // p 前进：去处理刚才存好的 nex。注意不能用 p = p->next（已被改）。
            p = nex;
        }
        // 翻完返回 {新头=tail, 新尾=head}。head/tail 是函数参数（值传递的副本），
        //   返回时它们分别指向「原尾」「原头」，正好对应翻转后的新头、新尾。
        return {tail, head};
    }

    ListNode* reverseKGroup(ListNode* head, int k) {
        // 哑节点 hair：在真正结果链表前面「虚构」一个假头，令它的 next 指向 head。
        //   - 作用 1：第一组翻转后头节点会变（原头变本组尾，本组新头是原第 k 个），
        //     没有哑节点时第一组没有「前驱」、返回值也不好挑；有了 hair，
        //     每一组都有统一的前驱，最后直接 return hair->next 就是对的新头。
        //   - 作用 2：不管链表翻没翻、头变没变，hair->next 永远指向正确答案，
        //     省掉「该返回原头还是第 k 个节点」的纠结。
        //   - 值填 0 占位，代码里从不读 hair->val，填什么都不影响。
        //   - 必须 new 在堆上：栈对象函数返回即销毁，会变野指针。
        ListNode* hair = new ListNode(0);
        hair->next = head;

        // pre：当前这一组的「前驱」，即上一组翻转后的尾（也是待翻组的头的前一个）。
        //   - 初始指向 hair：第一组的前驱就是哑节点，统一处理。
        //   - 每翻完一组，pre 推进到本组翻转后的尾（= 原 head），成为下一组的前驱。
        ListNode* pre = hair;

        // 外层循环：head 依次指向每组开头。只要 head 非空就还有节点可能要翻。
        while (head) {
            // 探查：tail 从 pre 出发走 k 步，看本组够不够 k 个节点。
            //   - tail 初值设成 pre 而不是 head，是因为「从 pre 走 k 步」恰好落到本组最后一个节点；
            //     若设成 head 再走 k-1 步也等价，官方这里用 k 步、初值 pre，逻辑一致。
            ListNode* tail = pre;
            for (int i = 0; i < k; ++i) {
                tail = tail->next;
                // 任意一步走到空，说明剩余不足 k 个 → 直接返回 hair->next，保持原样。
                //   - 这里 return 而不是 break：因为一旦不足 k 个，后面所有组也都不足
                //     （链表只越往后越短），整条链就此定型，直接给答案即可。
                //   - 也覆盖了「链表一开始就空 / k > 链表长度」的边界：tail 会很快变空。
                if (!tail) {
                    return hair->next;
                }
            }
            // 走到这里说明本组恰好够 k 个：head..tail 是待翻段。
            // nex：本组的后继（下一组的开头），翻完后要由本组新尾接上它。
            //   - 必须在调用 myReverse 之前先存住：翻转会改 head..tail 内部的 next，
            //     虽然 tail->next 本身没被改，但提前存能让「接回」逻辑更清晰。
            ListNode* nex = tail->next;
            // 翻转本段。tie(head, tail) = myReverse(...) 是 C++17 结构化绑定的写法，
            //   把返回的 pair 解开：head ← 新头（原 tail），tail ← 新尾（原 head）。
            //   - 等价于 pair<ListNode*, ListNode*> res = myReverse(head, tail);
            //             head = res.first; tail = res.second;
            //   - 注意翻转后 head/tail 变量的含义「互换」了：现在 head 是新头，tail 是新尾。
            tie(head, tail) = myReverse(head, tail);
            // 接回主链：两根指针缝补翻转段和前后。
            //   - pre->next = head：前驱接上翻转后的新头（原 tail）。
            //   - tail->next = nex：翻转后的新尾（原 head）接上后继 nex。
            //   - 这两句是「区间连接」的关键，缺一句链表就断。
            pre->next = head;
            tail->next = nex;
            // 推进到下一组：
            //   - pre = tail：本组新尾当下一组的前驱。
            //   - head = tail->next：下一组的开头就是本组新尾的下一个（= nex）。
            //   - 注意 head 这里等于 nex，写 head = nex 也对，官方用 tail->next 强调「跟着链走」。
            pre = tail;
            head = tail->next;
        }

        // 全部翻完（head 走到空）返回哑节点的下一个，即最终结果链表的头。
        //   - 若链表长度恰好是 k 的整数倍，所有组都翻了，hair->next 是第一组的新头。
        //   - 若中途某组不足 k 个，已经在循环内 return 了，走不到这里。
        return hair->next;
    }
};
```

## 复杂度

- **时间**：O(n)，n 为链表长度。
  - 外层 `head` 指针在每组开头停一次，共停 ⌊n/k⌋ 次；每次探查走 k 步、翻转走 k 步，合计每组 O(k)。总计 O(⌊n/k⌋ · k) = O(n)。
  - 关键观察：**每个节点最多被「探查」和「翻转」各访问常数次**，不存在嵌套遍历，所以是线性而非平方。
- **空间**：O(1)。
  - 只用了 `hair / pre / head / tail / nex` 这几个指针变量，外加 `myReverse` 内部的 `prev / p / nex`（也是常数个）。没有新建链表、没有递归栈。**这正是进阶问题「只用 O(1) 额外内存」的要求所在**，也是迭代法相比递归法的核心优势。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么 `myReverse` 里 `prev` 的初值是 `tail->next`，而不是像 206 那样用 `nullptr`？

因为本题翻转的是「链表中间的一段」，不是「整条链」。

- 206 翻整条链：翻完后**原头变成整条链的尾，尾的 `next` 必须是 `nullptr`**，所以 `prev` 从 `nullptr` 起，第一轮 `curr->next = nullptr` 正好把原头变成尾。
- 25 翻一段 `head..tail`：翻完后**原 head（变成本段新尾）的 `next` 必须接上本段的后继 `tail->next`**（否则本段尾部和下一段断开），所以 `prev` 从 `tail->next` 起，第一轮 `p->next = tail->next` 正好把原头接到后继上。

一句话：**`prev` 的初值 = 翻转后这段尾节点该指向的那个「终点」**。整条链的终点是空，一段的终点是它的后继。理解这一点，「翻转一段」就是「翻转整条」的小改。

### Q2：翻转完之后那两句 `pre->next = head; tail->next = nex;` 为什么不能省？

因为 `myReverse` 只翻了 `head..tail` 这一段**内部**的指针，让 `head` 变新尾、`tail` 变新头，但这一段是**悬空**的——它和前驱 `pre`、后继 `nex` 的连接还没建立。这两句就是「焊接」：

- `pre->next = head`（这里的 `head` 是函数返回的新头）：让前驱指向翻转后的新头，前半段连上。
- `tail->next = nex`（这里的 `tail` 是函数返回的新尾）：让翻转后的新尾指向后继，后半段连上。

少任一句，链表都会从翻转段断成两截。这是「分段翻转」相比「整链翻转」多出来的连接工作，也是本题最容易写漏的一步。口诀：**翻一段 = 内部翻转 + 两端焊接**。

### Q3：探查时为什么一发现 `!tail` 就直接 `return hair->next`，而不是 `break` 出循环？

因为「一旦有一组不足 k 个，后面所有组也都不足 k 个」。链表是从左到右越来越短的：本组已经数到尾巴了，下一组、再下一组只会更短，绝不可能再凑齐 k 个。所以整条链在这一刻**彻底定型**——前面翻好的该啥样啥样，最后这段保持原样，直接 `return hair->next` 给出最终答案即可，没必要再 `break` 出循环多走一圈。

这也顺带覆盖了边界：**k 比链表总长还大**时，第一组探查就会走到 `nullptr`，直接返回原链（`hair->next = head`，原样），完全正确，无需特判。

### Q4：和 24 题「两两交换链表中的节点」到底什么区别？能直接套 24 的写法吗？

不能直接套，虽然两题长得很像。核心区别：

- **24 题每组固定 2 个节点**，交换两个节点可以用固定的「三步指针赋值」一次完成（`temp->next = node2; node1->next = node2->next; node2->next = node1`），不需要循环。
- **25 题每组 k 个节点**，k 是参数（可能 3、5、5000），不可能写出「固定几步」的交换——必须用 `while` 循环把这一段逐个掉头翻转，也就是把 206 题的翻转循环搬过来，只是边界改成 `prev != tail`。

可以这么理解：**24 题是 25 题在 k=2 时的「特例简化版」**。25 题更通用、更接近 206。把 206 的 `reverseList` 看成「翻转从 a 到链表尾」的工具，25 题就是「循环调用翻转从 a 到 b 的工具」，24 题是「每组只调用一个固定的两节点交换」。所以做 25 题前先把 206 彻底搞懂，这里就只剩「分段 + 接回」要处理。

## 复盘

- **核心套路**：**「分组翻转 = 反转链表（206）+ 区间连接」**。这是一类非常通用的模式：凡是题目要求「按某种长度/规则分段翻转链表」时，套路都是 ① 哑节点统一头部；② 用探查指针数够不够 k 个（够才翻）；③ 调用「翻转一段」的工具函数（边界由 `tail->next` 当 prev 初值、`prev != tail` 当循环条件）；④ 翻完用两根指针把这段焊接回前驱和后继；⑤ 指针推进到下一组。后续的「反转链表 II」(92) 是「只翻指定一段」，本质是本题的「单组」特例——把本题外层循环去掉、只调用一次 `myReverse` 就是 92 题的核心。
- **可迁移的细节**：
  1. **哑节点 `hair` 统一头部**（206/21/24/25 全用）——只要头节点可能被换掉就开。
  2. **「翻转一段」= 整链翻转的改版**——`prev` 初值从 `nullptr` 换成 `tail->next`，循环条件从 `while(curr)` 换成 `while(prev != tail)`。
  3. **翻完两端焊接**（`pre->next = 新头; 新尾->next = nex`）——这是分段翻转比分整链翻转多出来的步骤。
  4. **探查优先于翻转**——题目要求「不足 k 保持原样」时，必须先数够再翻；一旦不足直接 return。
- **不变式思维**：循环每一步，`pre` 始终指向「已处理段的尾」+「下一组的前驱」，`head` 始终指向「未处理段的开头」。维护好这个不变式，循环结束时整条链就按 k 个一组翻好了。
- **指针图示**：做链表题强烈建议在纸上画方框箭头（`pre -> head -> ... -> tail -> nex`），每改一根指针就重画一次状态。本题指针多（`hair/pre/head/tail/nex` 外加翻转函数里的 `prev/p/nex`），光看代码很容易搞混谁是谁。

### 解法二：递归法（对比用，非主解）

官方题解只给了迭代法（方法一）。递归法是另一种经典思路，放在这里作对比。思路是**把「K 个一组翻转」递归定义**：

- 递归函数 `reverseKGroup(head, k)` 假设「从 head 开始数 k 个，翻好并接上后面递归翻好的结果」。
- **先探查**：从 head 走 k-1 步，看够不够 k 个。不够（走到空）→ 原样返回 `head`（递归基）。
- 够 k 个 → 记下这组的尾 `tail` 和下一组的开头 `nex = tail->next`。
- **翻转 head..tail 这一段**（用 206 的三指针，初值 `prev = nex`，循环到 `prev == tail`）。
- **关键接回**：翻转后 head 变成本段尾，让它指向「后面递归翻好的结果」：`head->next = reverseKGroup(nex, k)`。
- 返回翻转后的新头 `tail`。

```cpp
class Solution {
public:
    ListNode* reverseKGroup(ListNode* head, int k) {
        // 递归基 / 探查：从 head 走 k-1 步，看够不够 k 个节点。
        //   - 用 tail 从 head 出发走 k-1 步，如果中途 tail 变空，说明不足 k 个。
        //   - 不足 k 个：保持原样，直接返回 head（题目要求）。
        ListNode* tail = head;
        for (int i = 1; i < k; ++i) {  // i 从 1 起，走 k-1 步后 tail 落在第 k 个
            tail = tail->next;
            if (!tail) {
                return head;  // 不足 k 个，原样返回
            }
        }
        // nex：本组的后继（下一组开头）。翻转前先存住，递归调用要用。
        ListNode* nex = tail->next;
        // 翻转 head..tail 这一段，和迭代法里 myReverse 一模一样：
        //   - prev 初值取 nex（= tail->next）：翻完后 head 变本段尾，要接后继。
        //   - 循环条件 prev != tail：追上 tail 时本段全翻完。
        ListNode* prev = nex;
        ListNode* p = head;
        while (prev != tail) {
            ListNode* nxt = p->next;
            p->next = prev;
            prev = p;
            p = nxt;
        }
        // 翻完后 head 变成本段新尾。让它指向「后面递归翻好的结果」。
        //   - reverseKGroup(nex, k) 把下一组及以后全翻好并返回下一组新头。
        //   - 本段新尾 head 接上那个新头，整条链就连起来了。
        head->next = reverseKGroup(nex, k);
        // 返回本段翻转后的新头（原 tail）。一路递归回去就是最终链表头。
        return tail;
    }
};
```

- **时间**：O(n)，每个节点被探查和翻转各常数次。
- **空间**：O(n)，递归深度等于分组数 ⌊n/k⌋，最坏（k=1 退化时）O(n) 栈空间。**这是递归法相比迭代法的主要劣势**——不满足进阶「O(1) 额外空间」的要求；链表很长（本题最多 5000 节点，k 很小时递归层数很深）还有栈溢出风险。
- **对比**：递归法代码更短、思路更优雅（「先翻本段，再让本段新尾接上后面递归翻好的结果」），不用写哑节点和外层循环；但空间开销大、不满足 O(1) 空间的进阶要求。面试/工程里优先迭代法，递归法作为「另一种理解角度」掌握即可。
