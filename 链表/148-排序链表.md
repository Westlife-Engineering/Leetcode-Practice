# 148 排序链表

- 难度：中等
- 标签：**链表**、双指针、分治、排序、**归并排序**
- 力扣链接：https://leetcode.cn/problems/sort-list/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「排序链表」（slug：`pai-xu-lian-biao-by-leetcode-solution`）。正文主解是 **自底向上的归并排序（迭代法）**，满足进阶要求的 O(n log n) 时间 + O(1) 空间；合并两条有序子链表时复用 **21 题的 `mergeTwoLists`** 套路。官方「方法一：自顶向下归并（递归）」空间是 O(log n)，放在「复盘」章节作对比。

## 题目描述

给你链表的头结点 `head` ，请将其按 **升序** 排列并返回 **排序后的链表** 。

**示例 1：**

```
输入：head = [4,2,1,3]
输出：[1,2,3,4]
```

**示例 2：**

```
输入：head = [-1,5,3,4,0]
输出：[-1,0,3,4,5]
```

**示例 3：**

```
输入：head = []
输出：[]
```

**提示：**

- 链表中节点的数目在范围 `[0, 5 * 10^4]` 内
- `-10^5 <= Node.val <= 10^5`

**进阶：** 你可以在 `O(n log n)` 时间复杂度和常数级空间复杂度下，对链表进行排序吗？

## 思路

> 本题主要参考力扣官方题解的「方法二：自底向上归并排序」。

### 为什么链表排序要选归并，而不是快排？

排序能稳到 O(n log n) 的常见算法有：归并排序、堆排序、快速排序（快排最坏 O(n^2)）。这三者里**最适合链表的是归并排序**，原因有两点：

1. **链表不支持随机访问**。快排和堆排都依赖「按下标取元素」（`a[i]`、`a[(i+j)/2]` 这种），单链表想拿第 k 个节点得从头走 k 步，代价爆炸。归并排序只需要「顺序往后扫」和「把链表从中间断成两段」，这些操作链表都能高效做（顺序遍历 O(n)、找中点用快慢指针 O(n)）。
2. **归并排序能稳定排序**。链表里值相等的节点不会乱跳相对顺序，这对一些场景很重要。快排不稳定，堆排也不稳定。

插入排序（147 题）倒是天生适合链表，但它是 O(n^2)，本题节点数最多 5 万，平方级会超时。所以归并排序是唯一的选择。

### 归并排序的分治思想

归并排序的套路就两步，反复套用：

1. **分**：把链表从中间切成两段。
2. **合**：把两段**已经各自排好序**的子链表合并成一条（这步就是 21 题「合并两个有序链表」的 `merge`）。

只要子问题足够小（长度 ≤ 1 的链表天然有序），递归/迭代地「分→合」就能把整条链表排好。

### 自顶向下（递归）的空间问题

最容易想到的实现是「自顶向下递归」：先找中点切成两半，递归排序两半，再 merge。但是**递归有调用栈**，链表长 5 万时递归深度约 log n ≈ 17，空间是 O(log n)，**不满足进阶的 O(1) 空间**。

### 自底向上（迭代）：从长度 1 开始两两合并

要省掉递归栈，就把「分→合」倒过来想——**不从大问题往下切，而是从小段往上拼**：

- 初始时，把链表看作一连串**长度 1** 的小段（每段天然有序，单个节点嘛）。
- 把相邻两段长度 1 的合并，得到若干长度 **2** 的有序段。
- 再把相邻两段长度 2 的合并，得到若干长度 **4** 的有序段。
- 段长 1 → 2 → 4 → 8 → 16 → … 一直翻倍，直到段长 ≥ 总长度，整条链表就有序了。

这就是「自底向上」。整个过程只有循环、没有递归调用，**空间 O(1)**。

### 关键辅助函数：`split(head, n)` —— 切出长度 n 的子链

每轮要「切两条长度为 `subLength` 的子链」出来合并。这个动作抽象成 `split(head, n)`：

- 从 `head` 往后走 `n-1` 步（加上 `head` 自己共 n 个节点），把这一段**从原链表中切下来**（把这段尾节点的 `next` 置空），然后**返回剩下那条链表的头节点**（下一段的起点）。

```
切之前：head -> a -> b -> c -> d -> e -> ...   （要从 head 切 2 个）
切之后：[head -> a]   （这段返回给调用者）
        c -> d -> e -> ...   （split 返回 c，作为下一轮的 head）
```

- 切的时候要小心两条边界：链表可能**不足 n 个**（最后一段短一些），那 `split` 走到 `nullptr` 就停，返回 `nullptr`；切完第二段后，剩下的部分（`next`）也要单独记下来，作为下一组的起点。

### `merge` 函数：直接复用 21 题

合并两条有序链表，就是 21 题的 `mergeTwoLists`：开个**哑节点**，两个指针分别扫两条链，每次把值小的接到结果末尾，一条走空了就把另一条整段接上。官方代码里把 `merge` 复制了一份进来，逻辑和 21 题完全一样（只是用了 `<=` 相等时取 `head1`，不影响正确性）。把 21 题的笔记看熟，这里就是抄一遍。

### 手动推导 `4 -> 2 -> 1 -> 3` 的排序过程

总长度 4，所以 `subLength` 会取 1、2 两轮（`subLength < length` 即 1<4、2<4；`subLength=4` 时 `4 < 4` 不成立，循环结束，但实际上 `subLength=2` 那一轮已经把全链合完了）。

```
原始链表：4 -> 2 -> 1 -> 3
总长度 length = 4

=== subLength = 1（每段 1 个节点，两两合并成有序的长度 2 段）===
  dummyHead -> (空)，prev=dummyHead，curr=4

  第 1 组：
    head1 = 4              （从 curr 切 subLength=1 个：就是 4 这一个）
    切完断开：4 -> nullptr
    head2 = 2              （上一段切完后返回的 next，即 2）
    切完断开：2 -> nullptr
    next  = 1              （head2 这段切完后剩下的链表头）
    merge(4, 2) = 2 -> 4   （合并两条长度 1 的有序链表）
    prev->next = 2 -> 4
    prev 走到 4
    curr = next = 1

  第 2 组：
    head1 = 1              （从 curr 切 1 个）
    切完断开：1 -> nullptr
    head2 = 3
    切完断开：3 -> nullptr
    next  = nullptr        （链表用完了）
    merge(1, 3) = 1 -> 3
    prev->next = 1 -> 3
    prev 走到 3
    curr = next = nullptr → 内层 while 结束

  subLength=1 这一轮后链表：dummyHead -> 2 -> 4 -> 1 -> 3
  （得到了两条长度 2 的有序段：[2,4] 和 [1,3]）

=== subLength = 2（每段 2 个节点，两两合并成有序的长度 4 段）===
  prev=dummyHead，curr=2

  第 1 组：
    head1 = 2 -> 4        （从 curr 切 subLength=2 个）
    切完断开：2 -> 4 -> nullptr，返回 head2 = 1
    head2 = 1 -> 3        （从 head2 切 2 个）
    切完断开：1 -> 3 -> nullptr，返回 next = nullptr
    merge([2,4], [1,3])：
        2 vs 1 取 1； 2 vs 3 取 2； 4 vs 3 取 3； 剩下 4 接上
        = 1 -> 2 -> 3 -> 4
    prev->next = 1 -> 2 -> 3 -> 4
    prev 走到 4
    curr = nullptr → 内层 while 结束

  subLength=2 这一轮后链表：dummyHead -> 1 -> 2 -> 3 -> 4

=== subLength = 4：4 < length=4 不成立，外层循环结束 ===

返回 dummyHead->next = 1 -> 2 -> 3 -> 4  ✓
```

可以看到**每一轮 `subLength` 都把「长度 `subLength` 的相邻两段合并成一条长度 `2*subLength` 的有序段」**，段长翻倍，轮次共 log n 次，每轮扫整条链表 O(n)，所以总时间是 O(n log n)。全程只用了常数个指针变量（dummyHead、prev、curr、head1、head2、next、merged 等），**空间 O(1)**。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 * *     int val;             // 节点存的值
 * *     ListNode *next;      // 指向下一个节点的指针；最后一个节点的 next == nullptr
 * * *   ListNode() : val(0), next(nullptr) {}                       // 默认构造
 * * *   ListNode(int x) : val(x), next(nullptr) {}                  // 只给值的构造
 * * *   ListNode(int x, ListNode *next) : val(x), next(next) {}     // 全参数构造
 * * };
 */
class Solution {
public:
    ListNode* sortList(ListNode* head) {
        // 空链表或单节点直接返回，无需排序（虽然下面的循环也能处理，但这里先快速返回更省事）。
        if (head == nullptr) {
            return head;
        }

        // 第 1 步：先遍历一次，统计链表总长度 length。
        //   - 后面外层循环要用 length 判断「段长 subLength 是否还小于总长」。
        //   - 这一次 O(n) 扫描不改变整体复杂度。
        int length = 0;
        ListNode* node = head;
        while (node != nullptr) {
            length++;
            node = node->next;
        }

        // dummyHead：哑节点（哨兵节点），在真正结果链表前面虚构一个假头。
        //   - 作用和 21 题一模一样：消除「每一轮合并后，结果该接在哪」的头部特判。
        //     外层每一组把 merge 结果接在 prev->next 上，第一组时 prev=dummyHead，
        //     后续组接着 prev 往后走，统一处理，不用单独写头部逻辑。
        //   - 用 new ListNode(0, head) 一步到位：值 0 占位，next 直接指向原链表头。
        //   - 注意必须堆上 new（不能栈对象），否则函数返回后指针失效。力扣环境不在乎这点泄漏。
        ListNode* dummyHead = new ListNode(0, head);

        // 外层循环：subLength 表示「本轮每个子链表的目标长度」，从 1 开始每轮翻倍（1→2→4→8…）。
        //   - subLength <<= 1 是「左移 1 位 = 乘 2」的简写，比 subLength *= 2 更快也更地道。
        //   - 循环条件 subLength < length：段长一旦 ≥ 总长度，说明整条链已经是一条大有序段，结束。
        //     （严格说 subLength=length 时不再需要合并，所以用 < 而不是 <=。）
        for (int subLength = 1; subLength < length; subLength <<= 1) {
            // prev：始终指向「上一组合并结果链表的末尾」，下一组 merge 完就接在 prev->next 上。
            //   - 每轮外层循环开始时 prev 重置回 dummyHead（重新从头开始接新一组的结果）。
            // curr：扫描指针，指向「还没处理的链表段的开头」，从这里切下一段段长为 subLength 的子链。
            ListNode* prev = dummyHead, *curr = dummyHead->next;

            // 内层循环：只要还有节点没处理，就继续「切两条 subLength 长的段、合并、接回去」。
            while (curr != nullptr) {
                // ---- 切第 1 条子链 head1 ----
                ListNode* head1 = curr;
                // 往后走 subLength-1 步（加 head1 自己共 subLength 个节点）。
                //   - 循环条件 i < subLength：从 i=1 开始走，走 subLength-1 次。
                //   - 加上 curr->next != nullptr 保护：链表末尾不足 subLength 个时走到尽头就停，
                //     不会越界解引用空指针。最后这一段会短一些，但仍然是有序的（归纳法保证）。
                for (int i = 1; i < subLength && curr->next != nullptr; i++) {
                    curr = curr->next;
                }
                // head2：第 1 条子链切完后，下一段的开头。此时 curr 是第 1 段的尾节点，
                //   curr->next 就是第 2 段的头。
                ListNode* head2 = curr->next;
                // 断开第 1 段和第 2 段：把第 1 段尾节点的 next 置空，让 head1 成为独立的子链表。
                //   - 这一步必须做！否则 merge 时 head1 会一直连着 head2，无法当成「独立有序链表」处理。
                curr->next = nullptr;
                // curr 跳到第 2 段的开头，准备去切第 2 段。
                curr = head2;

                // ---- 切第 2 条子链 head2 ----
                // 同样往后走 subLength-1 步。注意这里多加了 curr != nullptr 的保护：
                //   第 2 段可能比第 1 段还短甚至为空（比如链表总长是奇数，最后一段孤立），
                //   curr 可能在循环中途就变空，必须判空。
                for (int i = 1; i < subLength && curr != nullptr && curr->next != nullptr; i++) {
                    curr = curr->next;
                }
                // next：第 2 段切完后，剩下链表的开头（也就是下一组的起点）。
                //   - 先初始化成 nullptr，防止「第 2 段刚好是最后一段」时 next 是野值。
                ListNode* next = nullptr;
                if (curr != nullptr) {
                    next = curr->next;   // 记下下一组的起点
                    curr->next = nullptr;// 断开第 2 段，让 head2 成为独立子链表
                }

                // ---- 合并两条有序子链表 ----
                // merge(head1, head2)：就是 21 题「合并两个有序链表」的迭代版，
                //   开哑节点、双指针比大小、取小者接上、剩段整条接尾。返回合并后的新头。
                ListNode* merged = merge(head1, head2);

                // 把合并结果接到 prev 后面。
                //   - 第 1 组时 prev=dummyHead，prev->next=merged 把整条新链的头挂到哑节点上。
                //   - 后续组 prev 是上一组结果链的尾，prev->next=merged 把新合并段拼上去。
                prev->next = merged;
                // prev 走到「刚合并好的这段」的末尾，准备接下一组。
                //   - 只能顺着 merged 一个个往后走，因为不知道这段有多长。
                //   - 走到 prev->next == nullptr 表示到了这段的尾巴。
                while (prev->next != nullptr) {
                    prev = prev->next;
                }
                // curr 跳到下一组的起点，继续内层循环。
                curr = next;
            }
        }

        // 返回真正的结果头：跳过哑节点。
        //   - 注意返回 dummyHead->next，不是 head！head 在排序过程中可能已经被挪到中间去了。
        return dummyHead->next;
    }

    // merge：合并两条有序链表，返回合并后的新头。
    //   - 和 21 题「合并两个有序链表」的迭代法完全一样，直接照搬。
    //   - 用 <= 而不是 <：相等时取 head1，稳定性更好（原来在前面的还留在前面）。
    ListNode* merge(ListNode* head1, ListNode* head2) {
        // dummyHead：哑节点，消除「合并后头是谁」的特判。和 21 题一脉相承。
        ListNode* dummyHead = new ListNode(0);
        // temp：指向结果链表的当前末尾；temp1/temp2 分别扫两条输入链表。
        ListNode* temp = dummyHead, *temp1 = head1, *temp2 = head2;
        // 两条都没走空时，比大小取小者接到 temp 后面。
        while (temp1 != nullptr && temp2 != nullptr) {
            if (temp1->val <= temp2->val) {
                temp->next = temp1;       // 接 temp1 当前节点
                temp1 = temp1->next;      // temp1 往后走（注意先接再走，否则丢节点）
            } else {
                temp->next = temp2;       // 接 temp2 当前节点
                temp2 = temp2->next;      // temp2 往后走
            }
            temp = temp->next;            // temp 往后走，始终指向结果链表的末尾
        }
        // 一条走空了，剩下那条整段接上（升序性质保证剩下段都更大）。
        //   - 注意这里写成了 if/else if（而不是三目），等价于 21 题那句 temp->next = (temp1 ? temp1 : temp2)。
        if (temp1 != nullptr) {
            temp->next = temp1;
        } else if (temp2 != nullptr) {
            temp->next = temp2;
        }
        // 跳过哑节点返回真正的合并头。
        return dummyHead->next;
    }
};
```

## 复杂度

- **时间**：O(n log n)
  - 外层 `subLength` 从 1 翻倍到 ≥ length，共 O(log n) 轮。
  - 每轮内层循环把整条链表（n 个节点）扫一遍（切 + merge + 接回去），每轮 O(n)。
  - 开头统计长度那一遍 O(n) 不改变整体量级。总时间 O(n log n)。
- **空间**：O(1)
  - 全程只有循环，**没有递归调用栈**（这是自底向上相比自顶向下的关键优势）。
  - 只用了 `dummyHead` / `prev` / `curr` / `head1` / `head2` / `next` / `merged` / `length` 等常数个指针/变量；哑节点本身也只占常数空间。
  - 满足进阶要求的「常数级空间复杂度」。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么对链表用归并排序，而不用快排/堆排？

核心原因是**链表不支持随机访问**。快排和堆排都依赖「按下标 O(1) 取元素」（快排要取 `a[(lo+hi)/2]` 当 pivot、堆排要按下标算父子关系 `a[2i+1]`），而单链表想拿第 k 个节点必须从头走 k 步，代价 O(k)，排序直接退化。

归并排序只需要「顺序往后扫」和「把链表从中间一刀两断」，这两种操作链表都能高效做：

- 顺序扫：天然支持，O(n)。
- 找中点：快慢指针，`fast` 走 2 步、`slow` 走 1 步，`fast` 到尾时 `slow` 在中点，O(n)。
- 合并两条有序链表：21 题的双指针，O(n)。

另外归并排序**稳定**（相等元素相对顺序不变），快排不稳定。所以链表排序几乎都是归并。

### Q2：自底向上是怎么控制每段长度的？怎么保证最后整条链都有序？

靠外层 `subLength` 从 1 开始每轮 `<<= 1`（翻倍）。**数学归纳法**保证每轮结束后段都是有序的：

- 初始 `subLength = 1`：每个长度 1 的段（单个节点）天然有序。
- 假设 `subLength = k` 这一轮开始前，链表由若干长度 ≤ k 的**有序段**组成。这一轮把相邻两段长度 ≤ k 的合并，得到长度 ≤ 2k 的段——**两个有序段 merge 出来的一定还是有序段**（21 题保证了）。
- 所以 `subLength` 翻倍后，新链表由若干长度 ≤ 2k 的有序段组成，归纳成立。

当 `subLength ≥ length` 时，整条链表就是一条长度 ≤ `subLength` 的大有序段，即答案。段长 1→2→4→… 翻倍 log n 次就够了。

### Q3：`split` 切完两段后，剩下的链表（`next`）怎么处理？为什么不会丢？

切完两段后，链表在逻辑上被分成了三截：`[head1 段]` + `[head2 段]` + `[剩下没处理的 next 段]`。前两段被 `merge` 合并后挂回 `prev->next`，而**第三段必须单独记下来**，否则一旦 `curr` 跳进 `head2` 段，原来的 `next` 就找不回来了。

代码里这两句就是干这个的：

```cpp
ListNode* next = nullptr;
if (curr != nullptr) {
    next = curr->next;       // 记下第 2 段之后的下一段头
    curr->next = nullptr;    // 断开第 2 段
}
// ... merge、接回去 ...
curr = next;                 // 跳到下一段继续内层循环
```

- `next` 先初始化成 `nullptr`：防御「第 2 段恰好是链表末尾」的情况（此时没有「剩下段」，`curr` 本来就是 `nullptr`，`next` 保持 `nullptr`，内层 `while(curr)` 下一轮自然退出）。
- 「先记 next 再断开」的顺序不能反：如果先把 `curr->next = nullptr` 断开，就再也找不到原本的下一组起点了。这和 21 题「先接再走」、206 题「先存 `next` 再改指针」是同一类**指针操作顺序坑**。

### Q4：为什么自底向上（迭代）比自顶向下（递归）省空间？

递归实现里，每层递归调用都会在系统调用栈上压一帧（保存返回地址、局部变量等）。自顶向下归并的递归深度是 O(log n)（每次把链表对半分），链表长 5 万时大约压 17 层栈帧，所以空间是 **O(log n)**，**不满足进阶要求的 O(1)**。

自底向上完全是循环，**没有任何递归调用**，所有状态都靠几个指针变量维护，所以空间是 O(1)。代价是代码比递归版绕一些（要手动控制段长、切两段、接回去），但换来的是常数空间，满足进阶。

记忆口诀：**「递归 = 用系统栈，迭代 = 用自己管的几个指针」**。凡是题目对空间有严格要求（要 O(1)）的递归解法，想想能不能改成迭代。

## 复盘

- **可迁移套路**：**「链表归并排序 + 快慢指针找中点 + 合并有序链表」** 是链表排序题的标准组合技，三个零件都来自前面做过的题：
  - **合并有序链表** = 21 题（哑节点 + 双指针比大小取小者）。
  - **快慢指针找中点** = 876 题「链表的中间结点」（`fast` 走 2 步、`slow` 走 1 步）。递归归并那版（见下方解法二）里会显式用到。
  - **归并排序框架** = 分治思想，把「链表切成两半、各自排序、再合并」。
  这套组合后面在「合并 K 个升序链表」(23) 里还会用到（K 条链表两两用 `merge` 合并，本质也是归并）。把本题和 21 题写熟，是链表排序类题的基本功。
- **链表题常见技巧再强化**：
  1. **哑节点统一头部**：本题 `dummyHead` 让「每一组 merge 结果接到哪」不用特判第一组。21、206 都用过。
  2. **先存再改的指针顺序**：`split` 里「记下 next 再断开」、`merge` 里「接上节点再走指针」，顺序反了就丢节点。206 题「先存 `next` 再改 `curr->next`」同款坑。
  3. **快慢指针**：找中点、判环（141/142）、找倒数第 N 个（19）都是这套「一快一慢两个指针」的变体。
- **进阶思考**：题目要求 O(1) 空间，正是逼你从「会做」（递归归并，O(n log n) 时间 O(log n) 空间）升级到「做精」（迭代归并，O(n log n) 时间 O(1) 空间）。这种「把递归改成迭代省栈空间」的思路，在「合并 K 个升序链表」(23，用堆代替递归分治)、树的Morris遍历等场合也会出现。

### 解法二：自顶向下归并（递归，对比用，非主解）

官方「方法一」。思路更直观：先找中点把链表切成两半（`[head, mid)` 和 `[mid, tail)`），分别递归排序，再 merge。

注意官方这份代码用了「双参 `sortList(head, tail)`」的写法——`tail` 是**开区间右端**（不参与），这样可以**不真正断开链表也能递归**（靠 `tail` 标记每段到哪为止）。递归基是 `head == nullptr`（空段）和 `head->next == tail`（只剩一个节点），后者要把 `head->next` 置空让它独立。

```cpp
class Solution {
public:
    ListNode* sortList(ListNode* head) {
        // 对外接口：对 [head, nullptr) 这条完整链表排序。
        return sortList(head, nullptr);
    }

    // 对 [head, tail) 这段（tail 不参与，开区间）排序，返回排好序的新头。
    //   - 用「双参 + 开区间」的写法，递归时不用真正把链表断开，靠 tail 标记边界。
    ListNode* sortList(ListNode* head, ListNode* tail) {
        // 递归基 1：空段，直接返回 nullptr。
        if (head == nullptr) {
            return head;
        }
        // 递归基 2：只剩 1 个节点（head->next == tail）。
        //   - 必须把 head->next 置空，让它成为独立的单节点链表，否则后面 merge 会越界。
        if (head->next == tail) {
            head->next = nullptr;
            return head;
        }
        // 快慢指针找中点：
        //   - slow 每次走 1 步，fast 每次走 2 步，fast 到 tail 时 slow 在中点。
        //   - 注意 fast 走每一步都要判 != tail，防止越过开区间右端。
        ListNode* slow = head, *fast = head;
        while (fast != tail) {
            slow = slow->next;
            fast = fast->next;
            if (fast != tail) {
                fast = fast->next;
            }
        }
        ListNode* mid = slow;
        // 分别递归排序 [head, mid) 和 [mid, tail)，再合并。
        //   - 注意两边共享同一个 mid 作为分界：左段开区间到 mid，右段从 mid 开始。
        return merge(sortList(head, mid), sortList(mid, tail));
    }

    // merge：合并两条有序链表，和上面方法二的 merge 完全一样。
    ListNode* merge(ListNode* head1, ListNode* head2) {
        ListNode* dummyHead = new ListNode(0);
        ListNode* temp = dummyHead, *temp1 = head1, *temp2 = head2;
        while (temp1 != nullptr && temp2 != nullptr) {
            if (temp1->val <= temp2->val) {
                temp->next = temp1;
                temp1 = temp1->next;
            } else {
                temp->next = temp2;
                temp2 = temp2->next;
            }
            temp = temp->next;
        }
        if (temp1 != nullptr) {
            temp->next = temp1;
        } else if (temp2 != nullptr) {
            temp->next = temp2;
        }
        return dummyHead->next;
    }
};
```

- **时间**：O(n log n)，递归 log n 层，每层合并总工作量 O(n)。
- **空间**：**O(log n)**，递归调用栈的深度。**这是递归法相比迭代法的主要劣势**——不满足进阶的 O(1) 空间要求。
- **对比**：递归法思路直观（直接把分治翻译成代码）、代码较短；迭代法（主解）更难写但满足 O(1) 空间。面试里如果没明确卡空间，递归法更容易写对；要求 O(1) 空间时上迭代法。
