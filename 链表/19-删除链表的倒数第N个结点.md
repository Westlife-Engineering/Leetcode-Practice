# 19 删除链表的倒数第 N 个结点

- 难度：中等
- 标签：**链表**、**双指针**
- 力扣链接：https://leetcode.cn/problems/remove-nth-node-from-end-of-list/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「删除链表的倒数第N个节点」（slug：`shan-chu-lian-biao-de-dao-shu-di-nge-jie-dian-b-61`，官方「方法三：双指针」）。正文主解是 **双指针（快慢指针）一次遍历**，O(n) 时间、O(1) 空间，是「进阶：一趟扫描」的正解；两次遍历法（先求长度再找）放在「复盘」章节作对比。

## 题目描述

给你一个链表，删除链表的倒数第 `n` 个结点，并且返回链表的头结点。

**示例 1：**

```
输入：head = [1,2,3,4,5], n = 2
输出：[1,2,3,5]
```

**示例 2：**

```
输入：head = [1], n = 1
输出：[]
```

**示例 3：**

```
输入：head = [1,2], n = 1
输出：[1]
```

**提示：**

- 链表中结点的数目为 `sz`
- `1 <= sz <= 30`
- `0 <= Node.val <= 100`
- `1 <= n <= sz`

**进阶：** 你能尝试使用一趟扫描实现吗？

## 思路

> 本题主要参考力扣官方题解的「方法三：双指针」。

### 先想最朴素的做法：两次遍历

链表不像数组能按下标随机访问，单链表只能从 `head` 一路 `next` 往后走。所以「删倒数第 `n` 个」最直白的想法是：

1. 第一趟：把整条链走一遍，数出链表总长 `sz`。于是「倒数第 `n` 个」就等于「正数第 `sz - n + 1` 个」（下标从 1 开始）。
2. 第二趟：从头再走 `sz - n` 步，停在「待删节点的前驱」上，然后 `prev->next = prev->next->next` 跳掉待删节点。

这就是官方「方法一：计算链表长度」，能 AC，但要**两次遍历**。「进阶」要求一趟扫描，所以它不是最优解，放在「复盘」里对比。

### 为什么双指针能做到一次遍历？

核心观察：**倒数第 `n` 个节点的前驱，距离链表末尾恰好是 `n`**（前驱到末尾之间有 `n` 个节点，包括待删节点本身和它后面的 `n-1` 个）。

如果我们能弄出两个相距 `n` 的指针，让它们**同步往后走**，当前面的指针正好走到链表末尾（最后一个节点的 `next` 即 `nullptr`）时，后面那个指针自然就停在「倒数第 `n+1` 个」节点——也就是**待删节点的前驱**。这样一趟遍历就能定位前驱，不用事先知道链表总长。

### 三步拆解

**第一步：快指针 `first` 先走 `n` 步，制造出 `n` 的间距。**

- 快指针 `first` 从 `head` 出发，慢指针 `second` 暂时停在「哑节点 dummy」（dummy 的 next 指向 head）。
- `first` 连续走 `n` 步。走完后，`second` 到 `first` 之间恰好隔着 `n` 个节点（`first` 当前所在位置就是正数第 `n+1` 个节点，`second` 在 dummy 即第 0 个位置）。

**第二步：`first` 和 `second` 同步往后走，直到 `first` 走到 `nullptr`。**

- 现在 `first` 和 `second` 的间距固定是 `n`。让两者每轮各走 1 步，间距始终保持 `n` 不变。
- 当 `first` 变成 `nullptr`（已经越过最后一个真实节点）时，`second` 也跟着前移了若干步。由于间距始终是 `n`，此时 `second` 正好停在「倒数第 `n+1` 个」节点——也就是**待删节点的前驱**。

**第三步：跳过待删节点。**

- `second->next = second->next->next`：让前驱的 `next` 直接跨过待删节点，指向待删节点的下一个，完成删除。
- 返回 `dummy->next`（不是 `head`，因为 `head` 本身可能被删掉）。

### 为什么一定要用「哑节点（dummy node）」？

这是本题最容易卡的点。删除一个节点 `y`，必须知道它的**前驱** `x`，执行 `x->next = x->next->next`。可是：

- 如果要删的恰好是**第一个节点**（`head` 本身），它**没有前驱**——没有任何节点的 `next` 指向它。此时无从下手：既不能写 `前驱->next = ...`，也不能让 `head` 自己指向下一个然后还能被外部引用。
- 双指针法的 `second` 最终要停在前驱上。如果链表只有 `n` 个节点且要删的就是第 1 个，`second` 必须停在「第 0 个」位置——而第 0 个位置根本不存在。

**哑节点就是人为造出来的「第 0 个节点」**：`dummy = new ListNode(0)`，让 `dummy->next = head`。于是：

- 原来的 `head` 也有前驱了，前驱就是 `dummy`。
- `second` 从 `dummy` 出发，最坏情况能停在 `dummy` 上（删第 1 个节点时），此时 `second->next` 正好是 `head`，`second->next = second->next->next` 就把 `head` 删掉了。
- 最后返回 `dummy->next`，不管 `head` 有没有被删，`dummy->next` 都指向新的头节点。

口诀：**链表题凡是要动头节点（删除/插入/翻转），优先上哑节点**，能省掉一堆 `head == nullptr` / 删头节点的特判。

### 手动推导 `1 -> 2 -> 3 -> 4 -> 5`，`n = 2`（删倒数第 2 个 = 节点 4）

```
初始链表：dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> nullptr
                                   ↑ 待删（倒数第2个）

step1: first 从 head 出发走 n=2 步
       dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> nullptr
       second(在dummy)        first(在3)        ← first 走了2步：head->3->4... 
       （注意：first 从 head 开始，走 2 步到节点 3）

step2: first/second 同步走，直到 first == nullptr
       第1轮：first=4,  second=1
       第2轮：first=5,  second=2
       第3轮：first=nullptr, second=3        ← first 越过末尾
       
       dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> nullptr
                          second  ↑待删

step3: second->next = second->next->next  （让节点3的next跨过节点4，直接指向5）

       dummy -> 1 -> 2 -> 3 ------> 5 -> nullptr   （节点4被跳过，删除完成）

返回 dummy->next = 节点1，即 1 -> 2 -> 3 -> 5 ✓
```

可以看到 `second` 最后停在节点 3，正好是待删节点 4 的前驱。若没有 dummy，删第 1 个节点时 `second` 就没地方站——dummy 给它提供了「第 0 个」落脚点。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;             // 节点存的值
 *     ListNode *next;      // 指向下一个节点的指针；末节点 next == nullptr
 *     ListNode() : val(0), next(nullptr) {}                       // 默认构造
 *     ListNode(int x) : val(x), next(nullptr) {}                  // 只给值
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}     // 值 + next
 * };
 */
class Solution {
public:
    ListNode* removeNthFromEnd(ListNode* head, int n) {
        // 哑节点（dummy node / sentinel，哨兵节点）：
        //   - new ListNode(0, head)：调用 ListNode 的「值+next」构造函数，
        //     造一个 val=0、next=head 的新节点。它站在 head 前面，是人为的「第 0 个节点」。
        //   - 为什么用哑节点？删除链表节点必须知道「前驱」，但若要删的就是第一个节点 head，
        //     它没有前驱。dummy 给 head 提供了一个统一的前驱，于是「删头节点」不再特殊。
        //   - 删除后返回 dummy->next 即新头；无论 head 有没有被删，dummy->next 都对。
        //   - 注意 new 出来的 dummy 是堆内存，函数末尾要 delete 掉，否则内存泄漏
        //     （力扣后台会回收，但写规范点更稳妥；下面用 ans 存好返回值后再 delete）。
        ListNode* dummy = new ListNode(0, head);

        // 快指针 first：从 head 出发，先走 n 步制造间距。
        //   - 不从 dummy 出发而从 head 出发：这样 first 走 n 步后，
        //     second（在 dummy）到 first 之间恰好隔着 n 个节点，间距正好是 n。
        //     对照「两次遍历法」逻辑：倒数第 n 个的前驱距离末尾 n，所以快指针要制造 n 的差距。
        ListNode* first = head;

        // 慢指针 second：从 dummy 出发，待会儿和 first 同步走，最后停在「待删节点的前驱」。
        //   - 一定要从 dummy 出发，不能从 head 出发！否则删第 1 个节点时 second 无前驱可站。
        ListNode* second = dummy;

        // 快指针先独自走 n 步，制造出 n 的间距。
        //   - 题目保证 1 <= n <= sz，所以 first 一定能走满 n 步，不会中途变 nullptr。
        //   - 走完后：second 在 dummy（第 0 个），first 在第 n+1 个位置，两者间隔 n 个节点。
        for (int i = 0; i < n; ++i) {
            first = first->next;
        }

        // 快慢指针同步往后走，直到 first 越过最后一个节点（变成 nullptr）。
        //   - 循环条件 while (first)：first 还没越过末尾就继续走。
        //     注意是判 first 不是 first->next！判 first 才能让 second 最终停在「前驱」而非「待删」节点：
        //       * 若判 while (first->next)：first 停在最后一个节点，second 停在「待删节点」本身，
        //         此时 second->next->next 会越界或删错位置。
        //       * 判 while (first)：first 越过最后一个节点变 nullptr，second 多走一步停在前驱上。
        //   - 两者每轮各走 1 步，间距 n 全程保持不变（这是双指针制造「固定间距」的核心）。
        while (first) {
            first = first->next;
            second = second->next;
        }

        // 删除操作：让 second（待删节点的前驱）的 next 跨过待删节点，指向待删的下一个。
        //   - second->next：待删节点本身。
        //   - second->next->next：待删节点的下一个（也可能是 nullptr，比如删最后一个节点）。
        //   - 这一句直接覆盖 second->next，等价于把待删节点从链表里「摘掉」。
        //   - 这里没有 delete 待删节点本身（力扣后台会回收），规范写法可存下指针再 delete。
        second->next = second->next->next;

        // 先存好返回值：dummy->next 就是删除后的新头节点。
        //   - 为什么不返回 head？因为 head 本身可能就是被删的那个（删第 1 个节点时）。
        //   - dummy->next 在所有情况下都指向当前的新头。
        ListNode* ans = dummy->next;

        // 释放哑节点：dummy 是我们 new 出来的，用完要 delete 防止内存泄漏。
        //   - 注意 delete 的是 dummy 自己，不是 ans！ans 是链表的真实节点，不能动。
        //   - 力扣不强制，但这是好习惯。
        delete dummy;

        return ans;
    }
};
```

## 复杂度

- **时间**：O(n)，n 为节点数。
  - `first` 先走 `n` 步，然后 `first`、`second` 同步走到末尾。整体上 `first` 从 `head` 一直走到 `nullptr`，**每个节点至多被访问一次**，合计一趟遍历。满足「进阶：一趟扫描」要求。
- **空间**：O(1)
  - 只用了 `dummy` / `first` / `second` / `ans` 几个指针变量，外加一个 `dummy` 节点（常数空间），没有开新链表或递归栈。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么非要用「哑节点」，不用行不行？

理论上可以不用，但**删头节点时必须特判**，代码会丑。

不用哑节点的写法里，删一个节点要靠 `前驱->next = 前驱->next->next`。但删 `head` 时根本没有前驱，只能单独写 `head = head->next; return head;`，跟删中间节点是两套逻辑。引入哑节点后，`head` 也有了前驱（dummy），两种情况合并成一套，不用特判。

双指针法尤其依赖哑节点：`second` 最终要停在前驱上，删头节点时前驱就是 dummy——没有 dummy，`second` 就没地方站。

口诀：**链表题凡是动头节点（增/删/翻），先 new 一个 dummy 站在 head 前面，最后返回 `dummy->next`**。这是链表题最常用的套路之一，和 206 反转链表里 `prev = nullptr` 是「尾节点 next 必须置空」一个道理。

### Q2：快指针 `first` 到底先走 `n` 步还是 `n+1` 步？

**取决于 `first` 的起点**，关键是让最终 `second` 停在「前驱」上。

- 本解法 `first` 从 **head** 出发，先走 **n** 步，`second` 从 **dummy** 出发：间距 n，最后 `second` 停在前驱。✓
- 有的写法 `first` 从 **dummy** 出发，先走 **n+1** 步，`second` 也从 **dummy** 出发：间距 n+1，但 first 多一个 dummy 起点的偏移，效果等价，最后 `second` 也停在前驱。

两种都对，只要 `first`、`second` 起点一致、制造出的「间距」让 `second` 落在「前驱」即可。本解法选 `first=head` 走 n 步，是因为它和「倒数第 n 个的前驱距离末尾 n」这个直观意义直接对应，好记。

### Q3：while 循环条件为什么是 `while (first)` 而不是 `while (first->next)`？

**这是决定 `second` 最终停在哪一句的关键**。

- `while (first)`：first 越过最后一个节点变 `nullptr` 才停。此时 first 多走一步，second 也多走一步，**second 停在「待删节点的前驱」上**。这正是我们要的——删除操作 `second->next = second->next->next` 需要前驱。
- `while (first->next)`：first 停在最后一个节点（还没越过）就停。second 少走一步，会停在「待删节点本身」上。此时 `second->next` 是待删节点的下一个，执行 `second->next = second->next->next` 会删错节点。

所以**判 `first`（不是 `first->next`）才能让 second 停在前驱**。和 141 环形链表里「`fast && fast->next` 连判两次」不同，这里我们要的就是 first 走到 `nullptr`，判一次 `first` 即可。

### Q4：删除节点后要不要 `delete` 那个被摘掉的节点？

力扣环境里**不强制**，后台会自动回收，所以 `second->next = second->next->next` 直接覆盖就够 AC。但工程规范上，被摘掉的节点是堆内存，应该 `delete`：

```cpp
ListNode* toDelete = second->next;
second->next = second->next->next;
delete toDelete;
```

力扣判定只看链表结构（节点间的 `next` 关系）和返回值，不看你是否释放内存，所以两种写法都能过。刷题时为了代码简洁可以不 delete；面试时提到「这里可以 delete 一下被删节点」会加分。

注意：我们 `new` 出来的 **dummy 必须单独 delete**（如主代码所示），因为它不是链表本身的节点，不删就真泄漏了。

## 复盘

- **核心套路：「快慢指针制造固定间距，然后同步平移」**。这是双指针家族里和「判环」(141)、「找中点」(876) 并列的经典用法：两个指针以特定方式拉开固定距离后，再以相同速度前进，利用间距不变性，当前面那个到达参考点（末尾/中点）时，后面那个自然停在目标位置。这种「先拉开、再同步」的模式可迁移到很多「找倒数第 k 个」「找倒数第 k 个的前驱」「链表后半段处理」类题目。
- **哑节点（哨兵）是链表题的万能起手式**。凡涉及增/删头节点的操作，统一 `dummy = new ListNode(0, head); ...; return dummy->next;`，能消掉所有 `head` 特判。后续做 21 合并两个有序链表、2 两数相加、234 回文链表、24 两两交换、25 K 个一组翻转都会反复用到。
- **一次遍历 vs 两次遍历的本质区别**：两次遍历靠「先求长度」把倒数下标换算成正数下标，直观但扫两趟；双指针靠「固定间距 + 同步平移」，用 `n` 步拉开代替事先知道总长，省掉一趟。两者时间都是 O(n)，常数上双指针更优。
- **链表删除三件套**：①找前驱；②`prev->next = prev->next->next` 跳过待删；③(可选)`delete` 被删节点。只要前驱找对了，删除一行搞定。难点永远在「怎么找到前驱」，而这正是双指针 + dummy 解决的部分。

### 解法二：计算链表长度（两次遍历，对比用）

官方「方法一」。第一趟数出链表总长 `length`，于是倒数第 `n` 个 = 正数第 `length - n + 1` 个；第二趟走到「正数第 `length - n` 个」（待删的前驱）执行删除。

```cpp
class Solution {
public:
    // 辅助函数：求链表长度。head 当游标一路 next 走到 nullptr，走一步 length++。
    //   - 单链表只能顺序遍历，求长度 O(length)。
    int getLength(ListNode* head) {
        int length = 0;
        while (head) {
            ++length;
            head = head->next;
        }
        return length;
    }

    ListNode* removeNthFromEnd(ListNode* head, int n) {
        // 同样用哑节点 dummy 统一处理删头节点的情况。
        ListNode* dummy = new ListNode(0, head);
        int length = getLength(head);       // 第一趟：求总长
        ListNode* cur = dummy;
        // 第二趟：走到「待删节点的前驱」。
        //   - 倒数第 n 个 = 正数第 length-n+1 个（下标从1），其前驱是正数第 length-n 个。
        //   - cur 从 dummy 出发，走 length-n 步即停在前驱。
        for (int i = 1; i < length - n + 1; ++i) {
            cur = cur->next;
        }
        cur->next = cur->next->next;        // 删除
        ListNode* ans = dummy->next;
        delete dummy;
        return ans;
    }
};
```

- **时间**：O(n)，扫两趟（求长度一趟 + 找前驱一趟），常数倍于双指针法。
- **空间**：O(1)，只有几个指针和一个 dummy。
- **对比**：思路最直白（求长度 → 换算下标 → 走到前驱），第一次做最容易想到；但扫两趟，不满足「进阶：一趟扫描」。掌握双指针法后，这种解法当对照即可。
