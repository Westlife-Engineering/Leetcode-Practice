# 21 合并两个有序链表

- 难度：简单
- 标签：**递归**、**链表**
- 力扣链接：https://leetcode.cn/problems/merge-two-sorted-lists/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「合并两个有序链表」（slug：`he-bing-liang-ge-you-xu-lian-biao-by-leetcode-solu`）。正文主解是 **迭代法（哑节点/哨兵节点 + 逐一比较接上）**，时间 O(n+m)、空间 O(1)，是链表合并题的标准写法；官方「方法一：递归」放在「复盘」章节作对比。

## 题目描述

将两个升序链表合并为一个新的 **升序** 链表并返回。新链表是通过拼接给定的两个链表的所有节点组成的。

**示例 1：**

```
输入：l1 = [1,2,4], l2 = [1,3,4]
输出：[1,1,2,3,4,4]
```

**示例 2：**

```
输入：l1 = [], l2 = []
输出：[]
```

**示例 3：**

```
输入：l1 = [], l2 = [0]
输出：[0]
```

**提示：**

- 两个链表的节点数目范围是 `[0, 50]`
- `-100 <= Node.val <= 100`
- `l1` 和 `l2` 均按 **非递减顺序** 排列

## 思路

> 本题主要参考力扣官方题解的「方法二：迭代」。

### 合并两个有序链表 = 归并排序里的 merge 步骤

如果你做过归并排序，对这道题会非常眼熟：归并排序的「合并两个有序子数组」那一步，就是用两个指针分别扫两条有序序列，每次挑较小的那一个放进结果。这里只是把「数组」换成了「链表」——思路完全一样。

核心动作就一句：**比较 l1、l2 当前节点谁的值小，把那个节点接到结果末尾，然后那条链表的指针往后走一格**。重复到其中一条链表走完。

### 为什么需要「哑节点 / 哨兵节点」dummy？

链表题最烦的一点是**头节点要特判**。合并后的新链表头到底是 `l1` 还是 `l2`？得先比一次才知道；万一某条链表一开始就是空，头节点又得换一套逻辑。这些「第一个节点怎么办」的判断散落在代码各处，又容易写错。

**哑节点（dummy node，也叫哨兵节点）** 就是来消除这个特判的：在真正的结果链表前面，先**虚构一个假头节点**，让 `prev` 指针从它开始往后接。这样一来，**每一次「把节点接到 `prev` 后面」的操作都一模一样，包括第一个节点**——没有任何特殊分支。最后只要返回 `dummy->next`，就是真正的合并链表头。

> 口诀：**只要题目要返回「新链表的头」而你又不知道头是谁，就先开个 dummy**。这是链表题最高频的套路之一。

### 算法步骤（迭代法）

1. 开一个哑节点 `preHead`（值随便填，比如 `-1`，反正不参与比较），`prev` 指针指向它。
2. 当 `l1` 和 `l2` **都还没空**时循环：
   - 比较 `l1->val` 和 `l2->val`，把值小的那个节点接到 `prev->next`，并把那条链表的指针往后移一位。
   - `prev` 往后走一位（`prev = prev->next`），始终指向「结果链表的当前末尾」。
3. 循环结束时 `l1`、`l2` 至多有一条还没空。因为两条原链表都是升序的，**剩下的整段一定都比已合并部分大**，直接整条接上去就行：`prev->next = l1 == nullptr ? l2 : l1`。
4. 返回 `preHead->next`（跳过那个假头）。

### 手动推导 `1->2->4` 和 `1->3->4` 的合并过程

```
初始  prev=dummy(-1)   l1: 1 -> 2 -> 4      l2: 1 -> 3 -> 4
      结果链：dummy -> (空)

第1轮  1 vs 1，取 l1 的 1：prev->next = 1(l1)，l1=2，prev=1
      结果链：dummy -> 1    l1: 2 -> 4        l2: 1 -> 3 -> 4

第2轮  2 vs 1，取 l2 的 1：prev->next = 1(l2)，l2=3，prev=1(l2)
      结果链：dummy -> 1 -> 1   l1: 2 -> 4   l2: 3 -> 4

第3轮  2 vs 3，取 l1 的 2：prev->next = 2，l1=4，prev=2
      结果链：dummy -> 1 -> 1 -> 2   l1: 4   l2: 3 -> 4

第4轮  4 vs 3，取 l2 的 3：prev->next = 3，l2=4，prev=3
      结果链：dummy -> 1 -> 1 -> 2 -> 3   l1: 4   l2: 4

第5轮  4 vs 4，取 l1 的 4：prev->next = 4，l1=nullptr，prev=4
      结果链：dummy -> 1 -> 1 -> 2 -> 3 -> 4   l1: 空   l2: 4

循环结束（l1 为空）。把 l2 剩下整段接上：prev->next = l2 = 4
      结果链：dummy -> 1 -> 1 -> 2 -> 3 -> 4 -> 4

返回 preHead->next，即 1 -> 1 -> 2 -> 3 -> 4 -> 4  ✓
```

注意「第 5 轮」两个值相等时取哪边都行（都相等嘛），官方代码用的是 `else` 分支（即 `l1->val < l2->val` 不成立时取 `l2`），所以相等时走 `l2`，结果一样正确。我下面代码沿用官方写法。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 * *     int val;             // 节点存的值
 * *     ListNode *next;      // 指向下一个节点的指针；最后一个节点的 next == nullptr
 * *     ListNode() : val(0), next(nullptr) {}                       // 默认构造
 * *     ListNode(int x) : val(x), next(nullptr) {}                  // 只给值的构造
 * *     ListNode(int x, ListNode *next) : val(x), next(next) {}     // 全参数构造
 * * };
 */
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
        // 哑节点（哨兵节点）preHead：在真正结果链表前面「虚构」一个假头，
        //   - 作用：消除「合并后头节点到底是谁」的特判。有了它之后，
        //     每一次「把节点接到 prev 后面」的操作都完全统一，包括接第一个节点。
        //   - 值填 -1 只是占位，它不参与任何比较（真正的比较发生在 l1/l2 之间），
        //     题目数据范围是 -100~100，填 -1 不会和真实节点值产生歧义，随便填不影响。
        //   - 注意必须用 new 在堆上创建：如果写 ListNode preHead(-1);（栈对象），
        //     函数返回后这个对象就被销毁了，preHead->next 也跟着失效，会得到野指针。
        //   - 力扣判题环境不在乎这点内存泄漏；工程代码里记得在返回前把它 delete 掉。
        ListNode* preHead = new ListNode(-1);

        // prev：始终指向「结果链表的当前末尾节点」，下一个该被接上的位置就是 prev->next。
        //   - 初始指向 preHead，因为还没接任何节点，末尾就是那个假头。
        //   - 循环里每接上一个节点，prev 就往后走一位。
        ListNode* prev = preHead;

        // 循环条件：两条链表都还没走到空。一旦有一条走空，while 就退出，
        //   剩下那条的整段在循环外一次性接上（见下面那句）。
        while (l1 != nullptr && l2 != nullptr) {
            // 比较两个当前节点的值，把较小的那个接到 prev 后面。
            //   - 注意这里是「把节点本身接过去」，不是新建节点、不是拷贝值！
            //     我们直接复用 l1/l2 原来的节点，只改它们的 next 指向，O(1) 重排。
            //   - 注意是 l1->val < l2->val（严格小于），所以相等时走 else 分支取 l2，
            //     两种取法结果都对（值相等嘛），只是稳定性的细节区别。
            if (l1->val < l2->val) {
                prev->next = l1;   // 把 l1 当前节点接到结果末尾
                l1 = l1->next;     // l1 指针往后走一位（注意必须先接再走，否则丢了）
            } else {
                prev->next = l2;   // 把 l2 当前节点接到结果末尾
                l2 = l2->next;     // l2 指针往后走一位
            }
            prev = prev->next;     // prev 往后走一位，始终指向结果链表的末尾
        }

        // 循环结束时 l1、l2 至多有一个非空。因为两条原链表都是升序的，
        //   剩下的整段一定都 ≥ 已合并部分，直接整条接上去即可，无需再逐个比较。
        //   - 三目运算 l1 == nullptr ? l2 : l1：l1 空就接 l2，否则接 l1。
        //   - 即使 l1、l2 都空，这里接一个 nullptr 也无害（prev->next 本来就该是空）。
        prev->next = l1 == nullptr ? l2 : l1;

        // 返回真正的合并链表头：跳过那个假头 preHead。
        //   - 不能返回 preHead！它是个我们虚构的、值为 -1 的节点，不属于答案。
        return preHead->next;
    }
};
```

## 复杂度

- **时间**：O(n + m)
  - `while` 循环每轮把 `l1` 或 `l2` 往后推一位，循环总次数不超过两条链表长度之和；循环外接剩余链表是 O(1)。共 O(n+m)。
- **空间**：O(1)
  - 只开了 `preHead`、`prev` 两个指针变量（哑节点本身只占 1 个节点的常数空间）；没有新建链表、没有递归栈。这是迭代法相比递归法的最大优势。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么一定要用哑节点 `preHead`，不能直接拿 `l1` 或 `l2` 当结果头吗？

可以不用，但代码会丑很多、还容易写错。

不用哑节点时，**第一个节点必须特判**：先比较 `l1->val` 和 `l2->val`，决定结果头到底是谁（这步本身没问题），但紧接着还要把「头节点指针」单独存起来，后面循环里又得改 `prev->next`。第一个节点的接法和后续节点的接法不一样，就得写两套逻辑，边界（空链表、单节点）也更容易漏。

**哑节点的作用就是把「第一个节点」和「后续节点」的接法统一**：第一轮循环里 `prev = preHead`，`prev->next = 较小节点`，和后面每一轮**完全一样**。不用特判，不用想头是谁。最后 `return preHead->next` 一刀切。这就是「哨兵简化头部处理」的威力。

### Q2：循环结束后的 `prev->next = l1 == nullptr ? l2 : l1` 是什么意思？为什么要接剩余链表？

`while (l1 && l2)` 只在**两条都非空**时循环。一旦有一条走空，循环就退出了，但另一条可能还剩一长串没处理。

关键观察：**两条原链表都是升序的**。已经合并进结果的部分是当前为止较小的那些值，而剩下那条非空链表里的所有值，都 ≥ 已经处理过的最大值（否则它早就在循环里被挑走了）。所以**剩下的整段直接整条接在末尾就行，不用再逐个比较**。

`l1 == nullptr ? l2 : l1` 是三目运算：l1 走空了就接 l2 那条，否则接 l1 那条。哪怕两条都空，接个 `nullptr` 也正好是结果链表该有的结尾。

### Q3：`new ListNode(-1)` 开出来的哑节点要不要 `delete`？不释放会内存泄漏吗？

**力扣判题环境不用管**，判题机每次跑完整个进程就回收了，泄漏无所谓，官方代码也是这么写的。

**工程代码里建议释放**。但要注意释放时机：必须在 `return preHead->next` **之前**把 `preHead` 存的临时指针先记下来（比如 `ListNode* ans = preHead->next; delete preHead; return ans;`），不能先 return 再去碰 `preHead`——那就 use-after-free 了。

还有一种避免泄漏的写法是**用栈对象当哑节点**：`ListNode preHead(-1); ListNode* prev = &preHead;`，函数返回时栈对象自动析构，不用手动 delete。缺点是写法上稍绕（要取地址 `&preHead`），力扣上不常见。本题照官方用 `new` 即可。

### Q4：两个链表都是空、或者其中一个是空，这套代码还对吗？

都对，**天然覆盖，不用特判**：

- **两个都空** `l1 = l2 = nullptr`：`while` 不进循环，`prev->next = l1 == nullptr ? l2 : l1` 算出 `l2`（也是空），返回 `preHead->next = nullptr`，即空链表，正确（示例 2）。
- **l1 空、l2 非空**：`while` 不进，`prev->next = l2`，把 l2 整条接上，返回 l2，正确（示例 3）。
- **l1 非空、l2 空**：`while` 不进，条件 `l1 == nullptr` 不成立，`prev->next = l1`，返回 l1，正确。

这正是哑节点 + `while(l1 && l2)` 写法的优点：边界情况不用单独写分支。

## 复盘

- **核心套路**：**「哑节点 / 哨兵节点 简化链表头部处理」** 是链表题最高频的可迁移技巧。只要题目让你「返回一条新链表的头」、而头节点又要靠比较/判断才能确定时，就先开个 dummy，让一切操作统一。后续的「删除链表的倒数第 N 个节点」(19)、「两两交换链表中的节点」(24)、「K 个一组翻转链表」(25)、「LRU 缓存」(146) 都会反复用到。
- **「归并 merge」套路**：本题本质就是归并排序的 merge 步骤搬到链表上。这个「双指针比大小、取小者后移」的模式后面还会在「合并 K 个升序链表」(23)、「排序链表」(148) 里复用——23 题是 K 条链表两两用本题的 merge 合并，148 题是对链表做归并排序时内部要用 merge。把本题写熟，是这两道题的基础。
- **链表操作口诀**：
  1. **先接再走**（`prev->next = l1; l1 = l1->next;`，顺序不能反，否则丢节点）。
  2. **哑节点统一头部**（不用特判第一个节点）。
  3. **剩余整段一次接**（利用「升序」性质，不用逐个比）。
- **迭代 vs 递归**：本题迭代法 O(1) 空间、写法固定，是首选；递归法代码更短但 O(n+m) 栈空间，链表很长时有栈溢出风险（虽然本题节点数 ≤ 50，递归也安全，但养成用迭代的习惯更稳）。见下面解法二。

### 解法二：递归法（对比用，非主解）

官方「方法一」。思路是把 merge 操作**递归定义**：两个链表头部值较小的一个节点，与「剩下的两条链表的 merge 结果」拼接。

具体说，`mergeTwoLists(l1, l2)`：

- 递归基：`l1` 空就返回 `l2`；`l2` 空就返回 `l1`（空链表不用合并，直接返回另一条）。
- 否则比较 `l1->val` 和 `l2->val`：
  - `l1->val < l2->val`：`l1` 较小，它应该是结果头，它的 `next` 应该是 `mergeTwoLists(l1->next, l2)`（l1 往后挪一位，继续和 l2 合并），返回 `l1`。
  - 否则：`l2` 较小（或相等），`l2->next = mergeTwoLists(l1, l2->next)`，返回 `l2`。

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
        // 整体是一条 if / else if / else if / else 链，覆盖四种情况：
        //   l1 空 → 返回 l2；l2 空 → 返回 l1；l1 较小 → l1 当头；否则 → l2 当头。
        if (l1 == nullptr) {
            // 递归基 1：l1 为空，没什么可合并的，直接把 l2 整条返回（l2 也空时返回 nullptr）。
            return l2;
        } else if (l2 == nullptr) {
            // 递归基 2：l2 为空，对称地返回 l1。
            return l1;
        } else if (l1->val < l2->val) {
            // 两条都非空且 l1 头较小：l1 当结果头，它的 next 由 (l1->next, l2) 继续合并得到。
            l1->next = mergeTwoLists(l1->next, l2);
            return l1;
        } else {
            // l2 头较小或相等：l2 当结果头，它的 next 由 (l1, l2->next) 继续合并得到。
            l2->next = mergeTwoLists(l1, l2->next);
            return l2;
        }
    }
};
```

> 这就是官方「方法一」的原版写法，一条 `if / else if / else if / else` 链，把「两个递归基 + 两个递归步」合并到一起，无需单独写递归基分支。

- **时间**：O(n + m)，每次递归去掉 `l1` 或 `l2` 的一个节点，递归总深度不超过 n+m。
- **空间**：O(n + m)，递归调用栈的深度等于合并后链表长度。**这是递归法相比迭代法的主要劣势**。
- **对比**：递归法代码最短、思路最优雅（直接把数学定义翻译成代码），但空间开销大。链表很短（本题 ≤ 50）时无所谓，但「合并 K 个升序链表」(23) 里如果用递归 merge 会叠多层栈，迭代更稳妥。面试/工程里优先迭代法。
