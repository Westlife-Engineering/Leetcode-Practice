# 234 回文链表

- 难度：简单
- 标签：栈、递归、**链表**、**双指针**
- 力扣链接：https://leetcode.cn/problems/palindrome-linked-list/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「方法三：快慢指针」。正文主解是 **快慢指针找中点 + 反转后半部分 + 双指针比较**（官方推荐，O(n) 时间 O(1) 空间）；把值复制到数组再判回文的 O(n) 空间做法放在「复盘」作对比。

## 题目描述

给你一个单链表的头节点 `head` ，请你判断该链表是否为回文链表。如果是，返回 `true` ；否则，返回 `false` 。

**示例 1：**

```
输入：head = [1,2,2,1]
输出：true
```

**示例 2：**

```
输入：head = [1,2]
输出：false
```

**提示：**

- 链表中节点数目在范围 `[1, 10^5]` 内
- `0 <= Node.val <= 9`

**进阶：** 你能否用 `O(n)` 时间复杂度和 `O(1)` 空间复杂度解决此题？

## 思路

> 本题主要参考力扣官方题解的「快慢指针」做法。

判断回文，最朴素的直觉是「两头往中间比」——首元素等于尾元素、第二个等于倒数第二个……一路比到中间。但**单链表只能往后走，不能往前回退**，更没有 O(1) 地「跳到尾节点」的能力（数组能 `nums[i]` 随机访问，链表不行）。所以「两头往中间比」这套数组的双指针打法**没法直接搬过来**。

**最直白的做法（数组法，O(n) 空间）**：扫一遍链表，把每个节点的值 `push` 进一个 `vector<int>`，然后在这个数组上跑经典的两头双指针判回文。思路最简单，但额外开了 O(n) 的数组，**不满足进阶的 O(1) 空间**。这个做法放「复盘」里对比。

**核心思想（要 O(1) 空间，只能在链表本身上动手脚）**：把链表「切成前后两半」，把后半段**反转**过来，反转后的后半段就变成了「从中间向尾部」的顺序，正好可以和「从头向中间」的前半段逐节点对比——等价于「两头往中间比」。

拆成三步：

1. **找中点** → 快慢指针。
2. **反转后半部分** → 复用 206「反转链表」的迭代写法。
3. **前半 vs 反转后的后半，逐一比较** → 两个指针同步往后走。

**快慢指针找中点的原理**：设两个指针 `slow` 和 `fast` 都从头出发，`slow` 每次走 1 步，`fast` 每次走 2 步。当 `fast` 走到链表末尾时，`slow` 刚好在中间。原因是 `fast` 的速度是 `slow` 的 2 倍，相同时间内 `fast` 走过的路程也是 `slow` 的 2 倍——若链表长 n，`fast` 走 n、`slow` 走 n/2，正好到中点。

**奇偶长度的处理**（这是本题最容易绕晕的地方，详见 Q2）：循环条件写成 `fast->next != nullptr && fast->next->next != nullptr`，让 `slow` 停在**前半段的最后一个节点**（而不是后半段的第一个）：

- 长度 4（`1->2->2->1`）：`slow` 停在第 2 个节点（前 2 个是前半段，后 2 个是后半段）。
- 长度 3（`1->2->1`）：`slow` 停在第 2 个节点（前半段 `1->2`，后半段 `1`）——**中间那个节点被划到前半段，比较时后半段更短，天然不参与比较**，不影响回文判断（正中间的元素自己和自己对称）。

**手动推导 `1->2->2->1`（长度 4）的完整过程**：

```
原链表:  1 -> 2 -> 2 -> 1 -> nullptr
节点编号:①    ②    ③    ④

【第 1 步：找中点 endOfFirstHalf】
初始  slow=①  fast=①
       fast->next=② ≠null, fast->next->next=③ ≠null → 继续
       slow=②  fast=③
       fast->next=④ ≠null, fast->next->next=null → 停！
结果:  firstHalfEnd = slow = ②        （前半段 ①->② ）

【第 2 步：反转后半段 reverseList(②->next = ③)】
反转 ③->④ 之前:  ③ -> ④ -> nullptr
反转后:          ④ -> ③ -> nullptr, 返回新头 ④
此时链表实际形态（前半段没动，后半段被反转）:
       ① -> ② ─┐
                └─> nullptr   （②->next 仍指向 ③，但反转时 ③->next 被改成 nullptr）
       ④ -> ③ -> nullptr     （secondHalfStart = ④）
注意: 物理上 ②->next 还指向 ③，但比较只看 p1、p2 两条独立链。

【第 3 步：比较 p1=①(前半头) vs p2=④(反转后的后半头)】
       p1:①->②       p2:④->③
第 1 次: p1->val=1, p2->val=1 → 相等，p1=②, p2=③
第 2 次: p1->val=2, p2->val=2 → 相等，p1=nullptr-ish, p2=nullptr
p2 走到 nullptr → 循环结束，result=true ✓

【第 4 步：还原链表 reverseList(secondHalfStart=④)】
把后半段再反转回去，恢复成原链表 ①->②->③->④。
返回 result = true。
```

**为什么官方代码要比对完之后再 `reverseList` 还原一次？** 因为题目里传入的 `head` 指针在调用方（力扣的测试代码）那里可能还会被用到。虽然力扣判回文这题不严格要求还原，但「把链表改回去」是好习惯，避免破坏输入数据（详见 Q3）。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode() : val(0), next(nullptr) {}
 *     ListNode(int x) : val(x), next(nullptr) {}
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}
 * };
 */
class Solution {
public:
    bool isPalindrome(ListNode* head) {
        // 空链表严格说题目不会给（节点数 >= 1），但官方加了这道保险：
        //   - nullptr 在 C++ 里是「空指针字面量」，类型是 std::nullptr_t，
        //     能隐式转换成任意指针类型。比较时写 head == nullptr 比 head == NULL 更现代（C++11 起）。
        if (head == nullptr) {
            return true;
        }

        // 第 1 步：找到前半段的尾节点（中点偏左那个）。
        //   endOfFirstHalf 返回的是「前半段最后一个节点」，不是后半段第一个。
        ListNode* firstHalfEnd = endOfFirstHalf(head);
        // 第 2 步：反转后半部分链表，返回反转后的新头（原链表尾节点）。
        //   firstHalfEnd->next 才是后半段的起点。
        ListNode* secondHalfStart = reverseList(firstHalfEnd->next);

        // 第 3 步：双指针逐一比较前半段 vs 反转后的后半段。
        //   - p1 从原链表头 head 出发，往后走（前半段方向：头 -> 中点）。
        //   - p2 从反转后的后半段头 secondHalfStart 出发，往后走（反转后半段方向：原尾 -> 中点）。
        //   - 两者同步前进，等价于「从链表两端往中间比」。
        ListNode* p1 = head;
        ListNode* p2 = secondHalfStart;
        bool result = true;                 // 用标志位记录结果，而不是直接 return：
                                            //   这样可以在 return 之前先把链表还原（见第 4 步）。
        while (result && p2 != nullptr) {   // 循环条件看 p2：反转后的后半段更短（奇数长度时），
                                            //   p2 先到 nullptr 就停，中间那个孤立节点不必比。
            if (p1->val != p2->val) {
                result = false;             // 这里不直接 return，是为了能走到下面的还原逻辑。
            }
            p1 = p1->next;
            p2 = p2->next;
        }

        // 第 4 步：还原链表（把后半段再反转回去，恢复原结构）。
        //   - 这一步对本题的 AC 不是必需的，但避免破坏调用方传入的链表，是好习惯。
        //   - 再调一次 reverseList 即可：反转两次等于没反转。
        firstHalfEnd->next = reverseList(secondHalfStart);
        return result;
    }

private:
    // 反转整条链表，返回反转后的新头节点。迭代版，O(n) 时间 O(1) 空间。
    //   思路：用 prev/curr 两个指针，逐个把每个节点的 next 指向前一个节点。
    //   - prev：始终指向「已经反转好的那一段的头」（初始为空，因为反转后原头要变尾，指向 null）。
    //   - curr：当前正在处理的节点。
    //   - nextTemp：先存住 curr 的下一个节点，否则改 curr->next 后就找不到原后继了。
    //   这个函数和第 206 题「反转链表」一模一样，可复用。
    ListNode* reverseList(ListNode* head) {
        ListNode* prev = nullptr;           // 反转后链表的头；初始 nullptr（原尾的 next 应为空）
        ListNode* curr = head;
        while (curr != nullptr) {
            ListNode* nextTemp = curr->next; // 暂存下一个节点
            curr->next = prev;               // 掉头：当前节点指向「前一个」
            prev = curr;                     // prev 前进一位
            curr = nextTemp;                 // curr 前进一位
        }
        return prev;                         // 循环结束时 curr=nullptr，prev 就是新头（原尾）
    }

    // 快慢指针找「前半段尾节点」。
    //   - slow 每次走 1 步，fast 每次走 2 步。
    //   - 循环条件 fast->next && fast->next->next：
    //       * 偶数长度 n：fast 最后停在倒数第 2 个节点，slow 停在第 n/2 个（前半段尾）。
    //       * 奇数长度 n：fast 最后停在倒数第 1 个节点，slow 停在第 (n+1)/2 个（中间偏左）。
    //   - 注意循环条件看的是 fast->next / fast->next->next 而不是 fast 本身，
    //     这是让 slow「落在前半段尾」的关键（见 Q2 详述）。
    ListNode* endOfFirstHalf(ListNode* head) {
        ListNode* fast = head;
        ListNode* slow = head;
        while (fast->next != nullptr && fast->next->next != nullptr) {
            fast = fast->next->next;        // fast 走 2 步
            slow = slow->next;              // slow 走 1 步
        }
        return slow;
    }
};
```

## 复杂度

- **时间**：O(n)，n 是链表节点数。
  - 找中点：slow 走了约 n/2 步，O(n)。
  - 反转后半段：遍历约 n/2 个节点，O(n)。
  - 比较：最多比 n/2 次，O(n)。
  - 还原链表：再反转一次，O(n)。
  - 总计 O(4n) = O(n)。
- **空间**：O(1)。
  - 只用了 `firstHalfEnd / secondHalfStart / p1 / p2 / prev / curr / nextTemp` 等几个指针变量，常数个。
  - 反转和比较都是**就地改链表指针**，没有开数组，也没有用递归栈（递归法会因调用栈占 O(n) 空间）。
  - 满足「进阶」的 O(1) 空间要求。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么要反转「后半部分」而不是「前半部分」？

两个方向理论上都能做，但**反转后半段更省事**：

- 反转操作需要「从头一路走到尾」改指针。前半段从头 `head` 出发，能自然走完前半段；但如果要反转前半段，得先知道前半段到哪结束——这本身又依赖找中点。
- 反转后半段：用 `firstHalfEnd->next` 直接拿到后半段的头，`reverseList` 它即可，前半段结构完全没动。
- 比较时，前半段从原 `head` 开始顺着原指针走（没被改过，方向还是向后的）；后半段被反转后方向变成「向头部」，两者方向相对，正好两头往中间比。

如果反过来反转前半段，比较时前半段方向变成「向头」，后半段方向「向尾」，也行但代码不如现在直观。官方和绝大多数题解都选反转后半段。

### Q2：快慢指针找的到底是哪个「中点」？奇数长度怎么处理？

这是本题最绕的点。关键在循环条件 `fast->next != nullptr && fast->next->next != nullptr`（**看的是 fast 的后继**，不是 fast 本身）。这导致 slow 落在**前半段的最后一个节点**：

- 长度 4（`1->2->2->1`）：
  - 初始 slow=①, fast=①。fast->next=②, fast->next->next=③ 都非空 → slow=②, fast=③。fast->next=④ 非空但 fast->next->next=null → 停。slow=②（前半段尾）。
- 长度 5（`1->2->3->2->1`）：
  - 初始 slow=①, fast=① → slow=②, fast=③ → slow=③, fast=⑤。fast->next=null → 停。slow=③（正中间那个）。
  - 此时前半段 `1->2->3`，后半段反转后 `1->2`（中间的 3 被划进前半段，但不参与比较，因为后半段更短、p2 先到 null）。

**奇数长度的中间节点天然是「和自己对称」的**，划到前半段也好、后半段也好都不影响判断——因为比较循环以 `p2 != nullptr` 为终止条件，短的那条先走完就停，多的那个中间节点自动被忽略。

如果把循环条件改成 `fast != nullptr && fast->next != nullptr`（看 fast 本身），slow 会落在**后半段的第一个节点**，这时 `firstHalfEnd` 的语义就变了，后面 `reverseList` 的入参和比较逻辑都要相应调整，容易写错。**记住官方这个写法：slow 落在前半段尾。**

### Q3：比较完之后那段「还原链表」的代码必须写吗？

**对力扣 AC 不是必须的**。删掉 `firstHalfEnd->next = reverseList(secondHalfStart);` 这一行，结果照样对，照样能过。

写它的目的是**不破坏调用方传入的链表结构**。反转后半段相当于把原链表「剪开又缝上」，如果不还原，调用方拿到的 `head` 后面会接一个被反转过的尾巴。力扣这道题判完就丢，看不出来；但在工程代码里、或者后续还要复用这条链表时，破坏输入是大忌。

官方题解保留还原步骤是「正确且负责任」的写法。为了能在 `return result` 之前完成还原，主函数里用 `bool result` 标志位而不是直接 `return false`——发现不匹配时先记下来、继续走完，最后统一还原 + 返回。

### Q4：单节点链表、空链表怎么处理？

- **单节点**（`head = [1]`）：`endOfFirstHalf` 中循环条件 `fast->next != nullptr` 直接为假（fast->next 是 null），不进循环，返回 slow=head。`reverseList(firstHalfEnd->next)` = `reverseList(nullptr)` 返回 nullptr。比较循环 `p2 != nullptr` 不进，`result` 保持 true。正确。
- **空链表**：题目保证节点数 ≥ 1，实际不会传入。官方代码开头 `if (head == nullptr) return true;` 是防御性写法（空链表视为「真空回文」），保证代码鲁棒。

所以**不用特判单节点**，现有逻辑自然处理。

## 复盘

- **核心套路 ——「快慢指针找中点 + 链表反转」组合技**：这是链表题里**最高频的两个原子操作的组合**，务必熟练：
  - **快慢指针找中点**：用途极广——876「链表的中间结点」、143「重排链表」、本题，都是同一套写法。
  - **链表反转**：206「反转链表」的迭代模板，本题直接复用。
  - 把两个原子操作拼起来就能解「需要在链表上做对称/两端操作」的题。下次遇到链表 + 「两端」「中间」「对称」这类关键词，先想到这个组合。

- **「单链表不能随机访问」的处理范式**：凡是要「从两头往中间」或「反向遍历」的需求，单链表上有三条路：
  1. 复制到数组（O(n) 空间，最简单，本题复盘的解法二）。
  2. 递归（利用调用栈天然反向，但栈空间 O(n)，官方方法二，不推荐）。
  3. 反转部分链表（O(1) 空间，最优，本题主解）。
  面试/力扣里看到「进阶：O(1) 空间」，基本就是暗示走第 3 条。

- **易错点**：
  - 快慢指针的循环条件写错位置（看 fast 本身 vs 看 fast->next），导致 slow 落点不对。
  - 反转时忘存 `nextTemp`，改 `curr->next` 后丢了后继节点。
  - 奇数长度时不知道中间节点怎么处理（答案：不用管，p2 先到 null 自动停）。

### 解法二：数组法（O(n) 空间，对比用）

官方方法一。最直观：遍历链表把值塞进 `vector`，然后在数组上跑两头双指针。代码极短，但用了 O(n) 额外空间，**不满足进阶要求**。

```cpp
class Solution {
public:
    bool isPalindrome(ListNode* head) {
        vector<int> vals;                       // vector<int>：C++ STL 动态数组，连续内存，下标访问 O(1)。
        while (head != nullptr) {
            // emplace_back：在尾部「原地构造」一个元素。
            //   - 比起 push_back(head->val)，emplace_back 少一次移动/拷贝（直接在容器里构造）。
            //   - 对 int 这种基本类型差别可忽略，但对复杂对象 emplace 更高效。
            //   - 参数列表直接传给元素类型的构造函数。
            vals.emplace_back(head->val);
            head = head->next;
        }
        // 两头双指针：i 从头、j 从尾，往中间靠，逐对比较。
        //   - 注意 j 初始化成 (int)vals.size() - 1，强转 int 避免有符号/无符号比较警告。
        //   - 终止条件 i < j：相遇或交错时就比完了，不用比中间那个（奇数长度）。
        for (int i = 0, j = (int)vals.size() - 1; i < j; ++i, --j) {
            if (vals[i] != vals[j]) {
                return false;
            }
        }
        return true;
    }
};
```

- **时间**：O(n)（遍历一次 + 双指针扫半次）。
- **空间**：O(n)（额外开了 `vector` 存所有节点值）。
- **对比**：写起来最短、最不容易出错，适合先写出正确解再优化。但面试问到「能否 O(1) 空间」时，就得切回主解的快慢指针 + 反转做法。
