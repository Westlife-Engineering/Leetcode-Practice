# 142 环形链表 II

- 难度：中等
- 标签：哈希表、**链表**、**双指针**
- 力扣链接：https://leetcode.cn/problems/linked-list-cycle-ii/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「环形链表 II」（slug：`huan-xing-lian-biao-ii-by-leetcode-solution`）。正文主解是 **快慢指针 + 数学推导找入环点（两次相遇）**，时间 O(n)、空间 O(1)，正好满足题目「进阶」对 O(1) 空间的要求；哈希表解法更直观但要 O(n) 空间，放在「复盘」章节作对比。

## 题目描述

给定一个链表的头节点  `head` ，返回链表开始入环的第一个节点。 如果链表无环，则返回 `null`。

如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。如果 pos 是 -1，则在该链表中没有环。注意：pos 不作为参数进行传递，仅仅是为了标识链表的实际情况。

**不允许修改** 链表。

**示例 1：**

```
输入：head = [3,2,0,-4], pos = 1
输出：返回索引为 1 的链表节点
解释：链表中有一个环，其尾部连接到第二个节点。
```

**示例 2：**

```
输入：head = [1,2], pos = 0
输出：返回索引为 0 的链表节点
解释：链表中有一个环，其尾部连接到第一个节点。
```

**示例 3：**

```
输入：head = [1], pos = -1
输出：返回 null
解释：链表中没有环。
```

**提示：**

- 链表中节点的数目范围在范围 `[0, 10^4]` 内
- `-10^5 <= Node.val <= 10^5`
- pos 的值为 -1 或者链表中的一个有效索引

**进阶：** 你是否可以使用 `O(1)` 空间解决此题？

## 思路

> 本题主要参考力扣官方题解的「方法二：快慢指针」。

### 先想最直观的做法：哈希表记录见过的节点

最朴素的想法：从头开始一个个走，每到一个节点就去「见过的节点集合」里查一下——查到了说明这个节点就是入环点（第一次重复访问的节点一定是入环点），查不到就把它加进集合继续走。走到 `nullptr` 就说明没环。

这个做法对、也好懂，但要开一个存所有节点的集合，**空间 O(n)**，不满足「进阶」的 O(1) 要求。所以正文不采用它，留到复盘对比。

### 官方主解：快慢指针 + 数学找入环点（O(1) 空间）

整个算法分**两个阶段**，核心难点在第二阶段的数学推导：

- **阶段一（和 141 题一模一样）**：快慢指针从 head 同时出发，慢指针走 1 步、快指针走 2 步，若有环它们一定在环里某个点相遇。
- **阶段二（本题独有的关键）**：把其中一个指针挪回 head，然后两个指针**同速**（都走 1 步）前进，它们再次相遇的地方**就是入环点**。

阶段一是 141 题的结论（有环必相遇），难点全在阶段二——**凭什么同速走就一定在入环点相遇？** 下面用数学说清楚。

### 核心推导：为什么「一个回 head + 两个同速走」就能在入环点相遇？

先给三段距离起名字（建议对着下图看）：

```
          a          b
head ─────────►●─────►●(相遇点)
               │      │
               └──c───┘   ← 环

a：head 到入环点的距离（环外那段）
b：入环点到相遇点的距离（沿前进方向）
c：相遇点到入环点的距离（沿前进方向，剩下的那段环）
所以 b + c = 环长
```

**第一步：列方程。**

设快指针在相遇时已经在环里转了 n 圈（n ≥ 1，因为快指针要比慢指针多绕才能追上）。

- 慢指针走过的距离 = `a + b`（出环外、再走到相遇点）。
- 快指针走过的距离 = `a + n(b + c) + b`（出环外、转 n 整圈、再多走一段 b 到相遇点），整理成 `a + (n+1)b + nc`。

快指针速度是慢指针的 2 倍，所以**快指针走过的距离 = 2 × 慢指针走过的距离**：

```
a + (n+1)b + nc = 2(a + b)
```

**第二步：化简，目标是把 `a`（head 到入环点的距离）表达出来。**

```
a + (n+1)b + nc = 2a + 2b
        (n+1)b + nc = a + 2b          ← 两边减 a
                  a = (n+1)b + nc − 2b
                    = (n−1)b + nc
                    = c + (n−1)(b + c)   ← 提一个 (b+c) 出来
```

得到核心式子：

```
a = c + (n − 1)(b + c)
```

**第三步：解释这个式子的几何含义——这是整个算法的灵魂。**

`b + c` 就是**环长**。所以右边 `c + (n−1)(b+c)` 的意思是：**先从相遇点往前走 `c` 步（正好回到入环点），再多绕 `(n−1)` 整圈（绕整圈不影响位置，又回到入环点）**。

也就是说：**从相遇点出发，再走 `c + (n−1)·环长` 步，一定会落在入环点上**。而左边 `a` 是「从 head 走到入环点的距离」。

把这两件事拼起来：

- 一个指针从 **head** 出发，走 `a` 步 → 到入环点；
- 一个指针从 **相遇点** 出发，走 `c + (n−1)·环长` 步 → 也到入环点（因为绕整圈不改变位置，相当于走 `c` 步）。

两个式子用的是同一个 `a = c + (n−1)(b+c)`，说明：**两个指针同速前进、走同样多步时，会在入环点同时到达**。绕整圈那 `(n−1)` 圈不用管——它只是让「相遇点出发的指针」在环里多溜达几圈，但每次溜达完又回到入环点，不影响相遇位置。

> 如果觉得 n 圈绕脑，可以取最简单的 n=1 情况帮助记忆：此时 `a = c`，即「head 到入环点」正好等于「相遇点到入环点」。两个指针同速走 `a`（=`c`）步，一个从 head、一个从相遇点，恰好都落在入环点。一般情况只是相遇点那个指针多绕了几整圈，结论不变。

### 算法流程总结

1. `slow = fast = head`。
2. 循环：`slow` 走 1 步，`fast` 走 2 步。
   - 若 `fast` 或 `fast->next` 为 `nullptr`：说明走到链表尾，**无环**，返回 `nullptr`。
   - 若 `slow == fast`：找到相遇点，跳出循环进入阶段二。
3. 阶段二：`ptr = head`，让 `ptr` 和 `slow` 都每次走 1 步，**它们再次相等的位置就是入环点**，返回它。

### 手动推导示例 1：`head = [3,2,0,-4], pos = 1`

```
链表：3 -> 2 -> 0 -> -4 ->(回到 2)
入环点是节点 2（索引 1）。

阶段一（找相遇点）：
  初始  slow=3, fast=3
  第1步 slow=2,  fast=0       （快走两步：3→2→0）
  第2步 slow=0,  fast=2       （快走两步：0→-4→2，已转圈）
  第3步 slow=-4, fast=-4      相遇！相遇点 = 节点 -4

  此时 a=1（head 3 到入环点 2 的距离）
       b=2（入环点 2 → 0 → -4，走了 2 步）
       c=1（相遇点 -4 到入环点 2，走 1 步）
  验证：a = c + (n-1)(b+c) → 1 = 1 + (n-1)·3 → n=1 ✓

阶段二（找入环点）：
  ptr=head=3, slow=相遇点=-4
  同走 1 步：ptr=2, slow=2    再次相遇在节点 2 ✓
  返回节点 2（索引 1），与预期一致。
```

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;             // 节点存的值
 *     ListNode *next;      // 指向下一个节点的指针；最后一个节点的 next == nullptr
 *     ListNode(int x) : val(x), next(nullptr) {}
 * };
 */
class Solution {
public:
    ListNode *detectCycle(ListNode *head) {
        // slow / fast：快慢双指针，都从 head 出发。
        //   - slow 每次走 1 步，fast 每次走 2 步。
        //   - 若有环，fast 一定会在环内追上 slow（141 题的结论）。
        //   - 若无环，fast 会先走到 nullptr，循环自然结束，函数末尾返回 nullptr。
        ListNode *slow = head, *fast = head;

        // 阶段一：找相遇点。
        // while 条件用 fast（而不是 fast->next）是因为循环体里会先访问 fast->next
        // 再判断，进入循环前必须保证 fast 本身不为 nullptr。
        while (fast != nullptr) {
            // slow 安全地往前走 1 步。只要 fast 还在（非空），slow 必然非空
            // （slow 在 fast 后面，不可能比 fast 先到尾部）。
            slow = slow->next;

            // fast 要走 2 步，必须先确认第 1 步落地后还有第 2 步可走。
            //   - 若 fast->next == nullptr，说明链表到这就到尾了，无环，直接返回 nullptr。
            //   - 这一句是「无环情况」的关键出口：无环时 fast 一定会先碰到 nullptr，
            //     而 slow（走 1 步）还在后面，二者永远不可能相等，所以靠这里返回。
            if (fast->next == nullptr) {
                return nullptr;
            }
            // fast 往前走 2 步：先到 next，再到 next->next。
            //   - 因为上一句已经确认 fast->next 非空，所以 fast->next->next 解引用安全
            //     （它可能是 nullptr，这没关系，下一轮 while 会拦住）。
            fast = fast->next->next;

            // 快慢指针相遇 → 链表有环，此时 slow 停在「相遇点」上。
            //   - 注意 141 题到这一步就可以 return true 了；本题还要继续找入环点。
            if (fast == slow) {
                // 阶段二：找入环点。
                // ptr：新开一个指针放回 head。让 ptr 和 slow「同速（各走 1 步）」前进。
                //   - 数学已证：head 到入环点距离 a = c + (n-1)·环长（c 是相遇点到入环点距离）。
                //   - 所以两个指针同速走，一定会在入环点首次相遇（相遇时 ptr == slow）。
                ListNode *ptr = head;
                while (ptr != slow) {
                    ptr = ptr->next;     // 从 head 一端往前走
                    slow = slow->next;   // 从相遇点一端往前走（可能在环里绕圈，但最终落在入环点）
                }
                // 循环跳出时 ptr == slow，这个节点就是入环点，返回它。
                return ptr;
            }
        }
        // while 正常结束（fast 走到 nullptr），说明无环，返回 nullptr。
        return nullptr;
    }
};
```

## 复杂度

- **时间**：O(n)，其中 n 为链表中节点的数目。
  - 阶段一找相遇点：`slow` 走过的距离不超过环长（详见下方 Q2），`fast` 走过的距离不超过 2 倍环长，二者合计不超过节点总数 n 的量级。
  - 阶段二找入环点：`ptr` 从 head 出发，最多走到入环点，距离 ≤ a ≤ n。
  - 两阶段合计 O(n) + O(n) = O(n)。
- **空间**：O(1)
  - 只用了 `slow` / `fast` / `ptr` 三个指针变量，没有哈希表等额外数据结构。**满足题目「进阶」对 O(1) 空间的要求**。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么会有 `a = c + (n−1)(b+c)` 这个关系？背后逻辑是啥？

这是整套算法的根基。三步走：

1. **设三段距离**：a = head 到入环点，b = 入环点到相遇点，c = 相遇点到入环点。`b + c = 环长`。
2. **用「快走的是慢的 2 倍」列方程**：慢指针走 `a+b`，快指针走 `a + n(b+c) + b`（n 是快指针多绕的圈数，n ≥ 1），于是 `a+(n+1)b+nc = 2(a+b)`。
3. **化简把 a 单独留在左边**：得到 `a = c + (n−1)(b+c)`。

这个式子的妙处在于把「head 到入环点的距离 a」拆成了「相遇点出发的某段路程」。右边 = `c`（相遇点走 c 步正好回到入环点）+ `(n−1)` 整圈（绕圈不影响落点）。所以从相遇点出发走这么多步、和从 head 出发走 a 步，**终点是同一个点（入环点）**，步数也相等，两个指针同速走自然在那里相遇。

### Q2：为什么慢指针走的不超过 2 圈就一定会和快指针相遇？

慢指针一旦进入环，到被快指针追上，走过的环内距离**不会超过 2 圈**（实际上严格小于 2 圈）。直观理解：

- 慢指针刚进环的那一刻，快指针已经在环里某个位置了。
- 每走一轮，慢指针前进 1 格、快指针前进 2 格，**快指针相对慢指针每轮多走 1 格**（即相对速度是 1 格/轮）。
- 环上两点的最大距离是 `环长`（一圈），所以快指针以相对速度 1 格/轮去追，**最多再追 `环长` 格**就一定能追上。
- 这段时间里慢指针最多走 `环长` 格（≤ 一圈）。加上慢指针进环前走的那段 a，慢指针走过的总距离不超过 `a + 环长 ≤ n`。

所以阶段一一定是 O(n) 内结束，不会无限转圈。关键就是**相对速度恒为 1**——这也是为什么快慢指针一个走 2 步、一个走 1 步能保证相遇；如果快指针走 3 步、慢指针走 1 步，相对速度是 2，**有可能在某些偶数长度的环上永远错开而追不上**（141 题的经典坑）。

### Q3：第一次相遇之后，为什么要「把一个指针挪回 head」？不能直接用相遇点推吗？

这正是这道题和 141 题的分水岭。141 题只要判断「有没有环」，相遇了就够了；但 142 题要找「入环点」，光知道相遇点不够——因为相遇点 `b` 和入环点之间没有直接的简单关系，它取决于 a、b、c 三段距离的比例。

但经过数学推导，`a = c + (n−1)(b+c)` 把这个问题转化为：**两个指针从 head 和相遇点出发同速走，会在入环点相遇**。这一步「挪回 head」的目的是制造一个「已知起点」（head 的距离 a 是可数的），让数学关系能落地为代码。本质上就是利用了 head 是链表的固定原点，把「找入环点」变成「两个已知起点同速走首次相遇」。

### Q4：链表无环时（示例 3），代码怎么处理？为什么不会死循环？

看阶段一的 `while (fast != nullptr)` 循环：

- 无环链表，`fast` 每次走 2 步，会比 `slow` 更快走到链表尾。
- 每轮先检查 `if (fast->next == nullptr)`：如果 `fast` 已经是倒数第一个节点，下一步走 2 步会越界，这里直接 `return nullptr` 拦住。
- 否则 `fast` 往前走 2 步。若走到 `nullptr`，下一轮 `while (fast != nullptr)` 判否，循环结束，函数走到末尾 `return nullptr`。

两条出口都能正确返回 `nullptr`，且 `fast` 始终单向前进，不会死循环。**无环时 `slow` 和 `fast` 永远不会相等**（fast 一直在前面），所以不会误进阶段二。

## 复盘

- **核心套路**：**「快慢指针 + 数学推导找特征点」** 是环形结构上的通用技巧。先用快慢指针（步速 2:1）锁定环内某个基准点（相遇点），再借助「快走的是慢的整数倍」列方程，把「未知特征点（入环点）」表达成「从已知起点出发的等长路径」，从而用第二次同速相遇定位它。同型题还有 **287 寻找重复数**（把数组下标当成隐式链表，重复值就是入环点）、**202 快乐数**（也用快慢指针判环）——都是这套思路。
- **两阶段模板**：很多「环形链表」题可以套这个模板——**阶段一快慢判环找相遇点 → 阶段二数学转化找入环点**。把 141（判环）和 142（找入环点）当成一对来记：141 用阶段一就够，142 多走一个阶段二。
- **141 → 142 的递进**：141 是「判断有没有环」，142 是「定位入环点」。142 的代码就是把 141 的 `return true` 换成「阶段二找入环点」，其余完全一致。复习时两题一起看。
- **「相对速度」思维**：快慢指针问题的本质常常是看「相对速度」。本题快比慢多 1 格/轮，所以追上最多要一圈；推广到其他追及问题，先算相对速度往往能快速判断是否可解。

### 解法二：哈希集合（对比用，非主解）

官方「方法一」。思路最直接：遍历链表，每访问一个节点就去哈希集合里查，查到就返回它（第一次重复访问的节点一定是入环点）；查不到就加入集合继续走。走到 `nullptr` 说明无环。

```cpp
class Solution {
public:
    ListNode *detectCycle(ListNode *head) {
        // unordered_set<ListNode*>：基于哈希表的集合，存「指针」。
        //   - 查找/插入/删除均摊 O(1)（比 set 的 O(log n) 快）。
        //   - key 是 ListNode*（指针本身，不是节点内容），所以判断的是「同一个节点地址」。
        //   - 这里用 visited 记录「已经路过」的所有节点。
        unordered_set<ListNode *> visited;
        while (head != nullptr) {
            // visited.count(head)：返回集合中等于 head 的元素个数（0 或 1）。
            //   - count == 1 说明这个节点之前见过 → 它就是入环点（首次重复访问）。
            if (visited.count(head)) {
                return head;
            }
            // visited.insert(head)：把当前节点地址加入集合。
            visited.insert(head);
            head = head->next;   // 沿链表前进
        }
        // 走到 nullptr 说明链表无环。
        return nullptr;
    }
};
```

- **时间**：O(n)，每个节点访问一次，哈希操作均摊 O(1)。
- **空间**：O(n)，最坏要把所有节点都存进集合。**这是它相对快慢指针解法的唯一劣势**——不满足题目「进阶」的 O(1) 空间。
- **对比**：哈希法**思路最直白、最不容易写错**，适合面试时先说出来的「保底解法」；快慢指针法**空间最优、数学更巧妙**，是面试官想听的「进阶解法」。两套都该会，先哈希保底、再用快慢指针优化空间。
