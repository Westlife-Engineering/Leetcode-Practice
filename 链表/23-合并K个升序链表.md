# 23 合并 K 个升序链表

- 难度：困难
- 标签：**链表**、**分治**、**堆（优先队列）**、归并排序
- 力扣链接：https://leetcode.cn/problems/merge-k-sorted-lists/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「合并K个排序链表」（slug：`he-bing-kge-pai-xu-lian-biao-by-leetcode-solutio-2`）。正文主解是 **优先队列（小根堆）**——把 k 条链表各自当前的「头节点」放进小根堆，每次弹出最小的接上结果、再把它在该链表的 `next` 入堆；时间 O(N log k)、空间 O(k)。这和 21 题「合并两个有序链表」的思想一脉相承，只是「从 2 个头里选最小」升级成「从 k 个头里选最小」，于是把选最小这一步交给堆。官方「方法一：顺序合并」「方法二：分治合并」放在「复盘」章节作对比。

## 题目描述

给你一个链表数组，每个链表都已经按 **升序** 排列。

请你将所有链表合并到一个升序链表中，返回合并后的链表。

**示例 1：**

```
输入：lists = [[1,4,5],[1,3,4],[2,6]]
输出：[1,1,2,3,4,4,5,6]
解释：链表数组如下：
[
  1->4->5,
  1->3->4,
  2->6
]
将它们合并到一个有序链表中得到。
1->1->2->3->4->4->5->6
```

**示例 2：**

```
输入：lists = []
输出：[]
```

**示例 3：**

```
输入：lists = [[]]
输出：[]
```

**提示：**

- `k == lists.length`
- `0 <= k <= 10^4`
- `0 <= lists[i].length <= 500`
- `-10^4 <= lists[i][j] <= 10^4`
- `lists[i]` 按 **升序** 排列
- `lists[i].length` 的总和不超过 `10^4`

## 思路

> 本题主要参考力扣官方题解的「方法三：使用优先队列合并」。

### 从「合并两个」到「合并 k 个」

21 题合并 **两条** 有序链表时，做法是两个指针各扫一条，每次比一下两个当前节点、取小者接上。那里「选最小」只需要比一次（2 个里选小），所以一个 `if` 就够。

到了 k 条链表，问题变成了：**每一步都要从 k 条链表各自的当前头里，挑出最小的那一个**。直接套 21 题的思路，就得每轮扫一遍 k 个头找最小——k 很大时这步是 O(k)，一共要做 N 次（N 是所有节点总数），总时间 O(kN)，`k=10^4` 时会超时（官方「方法一：顺序合并」是把已经合并的结果和下一条链表两两 merge，更糟，是 O(k²N)，但思路同样偏慢）。

### 关键观察：「每轮从 k 个候选里取最小」是堆的主场

把 k 条链表当前的头节点看成 k 个候选，每轮要从里面取最小的。这个操作天然契合 **堆（优先队列）**：

- **取最小**：小根堆的堆顶就是最小值，O(log k) 弹出（默认 `priority_queue` 是大根堆，要改成小根堆，见代码注释）。
- **补充新候选**：取出一个节点后，它所在链表的下一个节点成了新的候选，O(log k) 入堆。

堆里**始终维护「每条非空链表当前的第一个节点」**——一共最多 k 个元素，所以堆的大小 ≤ k，单次 push/pop 是 O(log k)。

### 算法步骤（优先队列 / 小根堆）

1. 开一个小根堆，把 k 条链表**各自当前的头节点**（非空的）全推进堆里。注意推进去的是 `ListNode*`，比较的依据是节点值 `val`。
2. 开一个哑节点 `head` 和尾指针 `tail = &head`，准备往后接结果。
3. 当堆非空时循环：
   - `top()` 取出堆顶（当前最小节点），`pop()` 弹掉它。
   - 把这个节点接到 `tail->next`，`tail` 往后走一格。
   - 如果这个节点还有 `next`，把 `next` 推进堆里（这条链表的下一个候选）。
4. 堆空 = 所有节点都接完了，返回 `head.next`（跳过哑节点）。

### 手动推导 `[[1,4,5],[1,3,4],[2,6]]` 的合并过程

为了看得清楚，下面把堆写成「按 val 升序」的队列（实际堆顶在左）：

```
初始：三条链表
  L1: 1 -> 4 -> 5
  L2: 1 -> 3 -> 4
  L3: 2 -> 6

把三条链表的头都入堆（按 val 升序排）：
  堆: [(1,L1), (1,L2), (2,L3)]
  结果链：head -> (空)，tail = head

第1轮  堆顶 (1,L1)：弹出，接到 tail 后
       堆变: [(1,L2), (2,L3)]
       L1 的 next=4 入堆: 堆变: [(1,L2), (2,L3), (4,L1)]
       结果链：head -> 1，tail=1

第2轮  堆顶 (1,L2)：弹出接上
       堆: [(2,L3), (4,L1)]
       L2 的 next=3 入堆: 堆: [(2,L3), (3,L2), (4,L1)]
       结果链：head -> 1 -> 1，tail=1

第3轮  堆顶 (2,L3)：弹出接上
       堆: [(3,L2), (4,L1)]
       L3 的 next=6 入堆: 堆: [(3,L2), (4,L1), (6,L3)]
       结果链：head -> 1 -> 1 -> 2，tail=2

第4轮  堆顶 (3,L2)：弹出接上
       堆: [(4,L1), (6,L3)]
       L2 的 next=4 入堆: 堆: [(4,L1), (4,L2), (6,L3)]
       结果链：head -> 1 -> 1 -> 2 -> 3，tail=3

第5轮  堆顶 (4,L1)：弹出接上
       堆: [(4,L2), (6,L3)]
       L1 的 next=5 入堆: 堆: [(4,L2), (5,L1), (6,L3)]
       结果链：head -> 1 -> 1 -> 2 -> 3 -> 4，tail=4

第6轮  堆顶 (4,L2)：弹出接上
       堆: [(5,L1), (6,L3)]
       L2 的 next=null，不入堆
       结果链：head -> 1 -> 1 -> 2 -> 3 -> 4 -> 4，tail=4

第7轮  堆顶 (5,L1)：弹出接上
       堆: [(6,L3)]
       L1 的 next=null，不入堆
       结果链：head -> 1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5，tail=5

第8轮  堆顶 (6,L3)：弹出接上
       堆: 空
       L3 的 next=null，不入堆
       结果链：head -> 1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6，tail=6

堆空，循环结束。返回 head.next = 1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6  ✓
```

每次入堆/出堆 O(log k)（k=3，log 3≈1.6），一共 N=8 个节点各出堆一次，所以总时间 O(N log k)。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 * *     int val;             // 节点存的值
 * *     ListNode *next;      // 指向下一个节点的指针；最后一个节点的 next == nullptr
 * * *   ListNode() : val(0), next(nullptr) {}                       // 默认构造
 * * * * ListNode(int x) : val(x), next(nullptr) {}                  // 只给值的构造
 * * * * ListNode(int x, ListNode *next) : val(x), next(next) {}     // 全参数构造
 * * };
 */
class Solution {
public:
    // 堆里存的元素类型：既要记住节点值（用来比大小），也要记住节点指针（接上结果、找它的 next）。
    //   - 为什么不直接存 ListNode*，让 priority_queue 自己按 ptr->val 比？
    //     因为 priority_queue 默认的比较器对 ListNode* 是「按指针地址比」（C++ 内置指针
    //     没有 < 的语义关联到所指对象），比的是内存地址而不是 val，结果完全错乱。
    //     所以我们要么自定义比较器（见 Q&A 里 lambda 的写法），要么包一层结构体自己重载 <。
    //   - 官方选了「包结构体 + 重载 operator<」这条路，更直观，下面照这个写。
    struct Status {
        int val;          // 节点的值，堆按它排序
        ListNode *ptr;    // 节点本身的指针，弹出时要用它接链表、取 next
        // 重载 operator<：STL 容器（含 priority_queue）里「比大小」就走这个函数。
        //   - 注意返回的是 val > rhs.val（**大于号**），这就是「把小根堆伪装出来」的关键：
        //     STL 的 priority_queue 默认是「大根堆」，它用 operator< 判优先级，
        //     「a < b 为真」意味着 b 优先级更高、b 排在堆顶。
        //     我们想让「值小的」排在堆顶，所以就让「我的 val 更大时，对方优先级更高」，
        //     即 val > rhs.val 时返回 true（说「我比你小」让对方上浮到堆顶）。
        //   - 口诀：**要小根堆，就让 operator< 用 > 比较**（反着写）。
        //     大根堆（默认）的 operator< 才用 < 比较。
        //   - 返回类型和 const 修饰都是 STL 比较器的标准写法，照抄即可。
        bool operator < (const Status &rhs) const {
            return val > rhs.val;
        }
    };

    // priority_queue<Status>：STL 优先队列，默认就是「大根堆」语义。
    //   - 完整签名是 priority_queue<T, Container = vector<T>, Compare = less<T>>，
    //     默认底层用 vector 存元素、用 less<T> 当比较器。
    //   - less<T> 对自定义类型会调用 T::operator<（我们上面重载过），
    //     「a < b 为真」时 b 排前面 → 默认大根堆：最大的元素在 top()。
    //   - 我们靠把 operator< 反着写（val > rhs.val），骗它「值小者优先级高」，
    //     于是 top() 拿到的其实是 val 最小的，相当于小根堆。这是一种很省事的写法。
    //   - 另一种写法是不重载 operator<，直接传自定义 Compare（见 Q&A），效果一样。
    //   - 成员变量（而不是函数内局部变量）：这里写成类的成员 q，纯粹是官方代码风格。
    //     放进 mergeKLists 函数体里当局部变量也完全可以，而且更干净（函数结束自动析构、
    //     不会在多次调用间残留），实际下面 main 解法逻辑等价。
    priority_queue<Status> q;

    ListNode* mergeKLists(vector<ListNode*>& lists) {
        // 第 1 步：把每条链表当前的头节点（非空的）入堆。
        //   - 必须判 if (node)：链表可能为空（lists 里混着 nullptr），
        //     空链表没有「当前头」，不能入堆（否则解引用 node->val 直接段错误）。
        //   - 入堆元素是 {node->val, node}：用列表初始化 Status，val 填节点值、ptr 填节点指针。
        //   - 这一步把 k 条链表的 k 个头都放进了堆，堆大小 ≤ k，建立 O(k log k)。
        for (auto node : lists) {
            if (node) q.push({node->val, node});
        }

        // head：哑节点（哨兵节点），在真正结果链表前面虚构一个假头。
        //   - 作用和 21 题、148 题的 dummy 完全一样：消除「合并后头是谁」的特判。
        //     每一轮「tail->next = 弹出的节点」的操作完全统一，包括接第一个节点。
        //   - 注意官方这里写的是「栈对象」ListNode head（不是 new 出来的），
        //     所以配 tail = &head（取地址）。函数返回时栈对象自动析构，不用 delete，
        //     比 new 的写法更省心（不会有内存泄漏），是工程上更推荐的做法。
        //   - head.val 不初始化也没关系，它不参与比较。
        ListNode head, *tail = &head;

        // 第 2 步：堆非空时循环，每轮弹最小、接结果、补新候选。
        while (!q.empty()) {
            // top()：取堆顶（当前 val 最小的元素），O(1)，不弹出。
            // pop()：弹出堆顶，O(log k)（堆大小 ≤ k）。
            //   - 注意 STL 里这俩是分开的：top 拿值、pop 删除，pop 不返回任何东西。
            //     这是 priority_queue 一个常被新手吐槽的设计（不像别的语言 poll() 一步到位）。
            //   - f 是 Status 类型的副本，弹出来后它存的 ptr 就是当前最小节点。
            auto f = q.top(); q.pop();
            // 把这个最小节点接到 tail 后面（复用原节点，不 new 新节点，O(1)）。
            tail->next = f.ptr;
            // tail 往后走一格，始终指向结果链表的当前末尾。
            //   - 注意这里和 21 题的区别：21 题接完节点后 prev=prev->next，
            //     这里等价：tail = tail->next，但直接用 tail = f.ptr 更直观（就是刚接上的那个节点）。
            tail = tail->next;
            // 如果这个节点还有 next，就把 next 入堆（这条链表的下一个候选）。
            //   - 判 f.ptr->next 非空再 push：节点没了说明这条链表已经全部入结果了，
            //     不再往堆里添东西，堆会自然缩到 0。
            //   - 入堆的 val 是下一个节点的值，不是当前 f.ptr 的值，别写错。
            if (f.ptr->next) q.push({f.ptr->next->val, f.ptr->next});
        }

        // 返回真正的结果头：跳过哑节点。
        //   - 注意是 head.next 而不是 &head（哑节点本身不是答案）。
        return head.next;
    }
};
```

## 复杂度

- **时间**：O(N log k)
  - 每个节点恰好入堆一次、出堆一次，共 N 次（N 是所有链表节点总数，题目保证 `Σlists[i].length ≤ 10^4`）。
  - 堆的大小始终 ≤ k（k 是链表条数），单次 push/pop 是 O(log k)。
  - 总时间 O(N log k)。比顺序合并的 O(k²N)、逐个扫描找最小的 O(kN) 都优。
- **空间**：O(k)
  - 堆里最多同时存 k 个元素（每条链表贡献一个当前头）。
  - 哑节点只占常数空间，递归/调用栈无额外开销（纯迭代）。
  - 注意：题目没要求常数空间，O(k) 是本题各解法里最常被接受的代价。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：`priority_queue` 默认是大根堆，怎么改成小根堆？

这是本题最容易卡的地方，分两种改法：

**改法 A（官方用的）：自定义元素类型，把 `operator<` 反着写。**

STL 的 `priority_queue<T>` 默认比较器是 `less<T>`，它内部调 `T::operator<`。判断逻辑是「a < b 为真 → b 优先级更高 → b 在堆顶」，所以默认把「最大的」放堆顶（大根堆）。

我们要的是「值最小的放堆顶」，那就**让 `operator<` 在「我的值更大」时返回真**，骗它把值小的当「优先级高」顶上去：

```cpp
struct Status {
    int val;
    ListNode *ptr;
    bool operator < (const Status &rhs) const {
        return val > rhs.val;   // 反着写！大于号 → 小根堆
    }
};
priority_queue<Status> q;   // 不用再传比较器，靠 operator< 自动生效
```

口诀：**小根堆，operator< 里写 >**。

**改法 B：元素类型不变，显式传一个「小根堆比较器」当第三个模板参数。**

```cpp
// 法 B1：用现成的 greater（仅适用于内置类型/有 > 的类型，比如存 int）
priority_queue<int, vector<int>, greater<int>> minHeap;   // 小根堆，存 int

// 法 B2：自定义结构体比较器（存指针、按 ptr->val 比时用这种）
struct Cmp {
    bool operator()(ListNode* a, ListNode* b) const {
        return a->val > b->val;   // 同样：返回 > 让 val 小的排前面
    }
};
priority_queue<ListNode*, vector<ListNode*>, Cmp> q;   // 存裸指针 + 自定义比较器
```

`greater<T>`、自定义结构体重载 `operator()(a,b)`、还有 lambda 写法（见 Q3），三者的判断规则都是 **「返回 true 时，第二个参数 b 优先级更高、排堆顶」**。想让 val 小的排堆顶，就写 `a->val > b->val`（a 的 val 更大时让 b 赢）。这一条记牢，所有堆题都不会绕晕。

### Q2：堆里为什么存指针 `ListNode*`（包在 `Status` 里），不直接存节点值 `int`？

因为光知道「当前最小值是多少」没用，得知道「这个最小值在哪个节点」，才能把它接到结果链表上、并且顺着它的 `next` 找到这条链表的下一个候选。

如果堆里只存 `int`（值），弹出 1 你只知道「当前最小是 1」，但不知道这个 1 属于 L1 还是 L2（示例里两条链表头都是 1），没法往下走。所以必须把**节点本身**存进去。又因为比较器不能直接对裸指针按 `val` 比（见 Q1 代码注释：指针的内置 `<` 比的是地址），所以要么包一层 `struct Status{int val; ListNode* ptr;}` 自己重载比较，要么给 `priority_queue` 传自定义比较器 `Cmp`。官方代码选了前者。

### Q3：自定义比较器用 lambda 怎么写？和结构体重载 `operator<` 有什么区别？

能用 lambda，但写法稍绕：`priority_queue` 的第三个模板参数要求是「类型」，而 lambda 是「值」，所以要先 `decltype` 出类型、再把 lambda 对象传给构造函数。完整代码：

```cpp
auto cmp = [](ListNode* a, ListNode* b) { return a->val > b->val; };
// decltype(cmp) 是 lambda 的类型，priority_queue 要拿它当模板参数；
// 第二个参数 vector<ListNode*> 是底层容器（priority_queue 默认就用 vector）；
// 最后一个 cmp 是把 lambda 对象传进去当比较器。
priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> q(cmp);
```

- **结构体重载 `operator<`（法 A）**：写法干净，类型自洽，不用 `decltype` 那一串，是力扣上最常见的写法。
- **lambda（法 B3）**：适合「比较逻辑只用一次、不想专门起个结构体名」的场景，但模板参数那一串啰嗦，新手容易抄错。
- **结论**：力扣上推荐结构体重载（官方写法）或自定义 `Cmp` 结构体；lambda 知道有这么个写法即可，别死记模板顺序。

### Q4：堆法和 21 题「合并两个有序链表」是什么关系？

21 题是 k=2 的特例，主解是「两个指针各扫一条，`if` 比一下取小者」，因为「2 选 1」只要 O(1)，没必要上堆。

本题是 k 很大的一般情况，「k 选 1」用 `if` 扫一遍要 O(k)，所以把「选最小」这步换成堆，单次 O(log k)。**堆法就是 21 题的双指针比大小，在 k 路情形下的推广**——本质都是「每次从 k 个候选里挑最小、该候选所在链表头后移一位」。理解了 21 题，本题只是在「挑最小」这一步换了工具。

另外官方「方法二：分治合并」是另一条思路：不引入堆，而是把 k 条链表两两用 21 题的 `merge` 合并（像锦标赛），也是 O(N log k)，见复盘里的解法二。

## 复盘

- **可迁移套路**：**「K 路合并用小根堆」** 是一类高频模式。凡是要「从 k 个有序源里不断挑出全局最小/最大」的场景，都把每个源的当前候选放进堆，每次弹极值、补该源下一个候选。后面会反复出现：
  - **K 路合并链表/数组**（本题）、**合并 k 个有序数组**（外部排序归并段、merge k sorted arrays）。
  - **数据流前 K 大/小**（215 数组中第 K 个最大元素、347 前 K 个高频元素、295 数据流中位数）——堆大小固定为 k。
  - **任务调度/贪心**（如「最接近原点的 K 个点」、会议室「最小会议间数」）。
  口诀：**「多个有序源，要全局极值 → 小/大根堆」**。
- **链表题技巧再强化**：
  1. **哑节点统一头部**：本题 `head` + `tail = &head` 让第一轮接节点和后面每一轮操作完全一样，21、148 都同款。
  2. **复用原节点、不新建链表**：`tail->next = f.ptr` 直接挪原节点指针，O(1) 重排，O(1) 额外空间（除了堆本身）。
  3. **栈对象哑节点更省心**：官方这里用 `ListNode head;`（栈对象）而非 `new ListNode()`，函数返回自动析构，无内存泄漏，比 21 题的 `new` 写法更适合工程。
- **STL 优先队列小结**（本题重点）：`priority_queue<T>` 默认大根堆；要小根堆就「自定义类型的 `operator<` 里写 `>`」，或传 `greater<T>`（内置类型）/ 自定义 `Cmp` 结构体 / lambda；`top()` 取堆顶不弹出、`pop()` 弹出不返回、`push()` 入堆，三者都是 O(log n)（top 是 O(1)）。

### 解法二：分治合并（对比用，非主解）

官方「方法二」。思路是不引入堆，**把 k 条链表两两用 21 题的 `mergeTwoLists` 合并**：先两两配对合并成 k/2 条，再两两合并成 k/4 条……每合并一轮链表条数减半，共 O(log k) 轮，每轮所有节点各被 merge 一次（总工作量 O(N)），所以也是 **O(N log k) 时间**，空间 O(log k)（递归调用栈深度）。

和堆法比，分治法**不依赖 STL 容器、纯链表操作**，对不熟 `priority_queue` 的人更友好；但多了 O(log k) 的递归栈，且代码要自己写 `merge` 递归分治。两条路复杂度同阶，任选其一。下面是官方代码：

```cpp
class Solution {
public:
    // mergeTwoLists：合并两条有序链表，和 21 题迭代法完全一样。
    //   - 这里用了栈对象 ListNode head 当哑节点（取地址 &head），不是 new。
    ListNode* mergeTwoLists(ListNode *a, ListNode *b) {
        if ((!a) || (!b)) return a ? a : b;   // 一条空就返回另一条
        ListNode head, *tail = &head, *aPtr = a, *bPtr = b;
        while (aPtr && bPtr) {
            if (aPtr->val < bPtr->val) {
                tail->next = aPtr; aPtr = aPtr->next;
            } else {
                tail->next = bPtr; bPtr = bPtr->next;
            }
            tail = tail->next;
        }
        tail->next = (aPtr ? aPtr : bPtr);    // 剩下整段接上
        return head.next;
    }

    // 分治：对 lists[l..r] 这段范围（闭区间）合并，返回合并后的头。
    //   - l == r：只剩一条，直接返回它（递归基）。
    //   - l > r ：范围空（lists 为空数组时会发生），返回 nullptr。
    //   - 否则切中点 mid，左半 [l,mid]、右半 [mid+1,r] 各自递归合并，再两条 merge。
    ListNode* merge(vector<ListNode*>& lists, int l, int r) {
        if (l == r) return lists[l];
        if (l > r) return nullptr;
        int mid = (l + r) >> 1;
        return mergeTwoLists(merge(lists, l, mid), merge(lists, mid + 1, r));
    }

    ListNode* mergeKLists(vector<ListNode*>& lists) {
        // 入口：对整个 lists[0..k-1] 做分治合并。
        return merge(lists, 0, lists.size() - 1);
    }
};
```

- **时间**：O(N log k)，分治 log k 层，每层所有节点 merge 总工作量 O(N)。
- **空间**：O(log k)，递归调用栈深度（每层占常数空间，不存节点本身）。
- **对比堆法**：堆法 O(N log k) 时间、O(k) 空间（堆存 k 个头）；分治法 O(N log k) 时间、O(log k) 空间（递归栈）。分治空间略优（log k < k），但堆法思路更直白、是「K 路合并」的通用模式（换到「合并 k 个有序数组」也照样成立），所以正文选堆法做主解。两种都要会。
