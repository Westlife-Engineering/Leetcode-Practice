# 206 反转链表

- 难度：简单
- 标签：**递归**、**链表**
- 力扣链接：https://leetcode.cn/problems/reverse-linked-list/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「反转链表」（slug：`fan-zhuan-lian-biao-by-leetcode-solution-d1k2`）。正文主解是 **迭代法（prev/curr 三指针翻转）**，时间 O(n)、空间 O(1)，是链表题里最经典的写法；递归法放在「复盘」章节作对比。

## 题目描述

给你单链表的头节点 `head` ，请你反转链表，并返回反转后的链表。

**示例 1：**

```
输入：head = [1,2,3,4,5]
输出：[5,4,3,2,1]
```

**示例 2：**

```
输入：head = [1,2]
输出：[2,1]
```

**示例 3：**

```
输入：head = []
输出：[]
```

**提示：**

- 链表中节点的数目范围是 `[0, 5000]`
- `-5000 <= Node.val <= 5000`

**进阶：** 链表可以选用迭代或递归方式完成反转。你能否用两种方法解决这道题？

## 思路

> 本题主要参考力扣官方题解的「方法一：迭代」。

### 反转的本质：把每个节点的 `next` 掉个头

链表的"形状"完全由每个节点的 `next` 指针决定。`1 -> 2 -> 3` 长成这样，是因为 `1.next = 2`、`2.next = 3`、`3.next = nullptr`。

要把它反转成 `3 -> 2 -> 1`，本质就是：

- `2.next` 改成 `1`（本来是 `3`）
- `3.next` 改成 `2`（本来是 `nullptr`）
- `1.next` 改成 `nullptr`（本来是 `2`）

换句话说：**每个节点的 `next` 都改成指向它原来的「前一个」节点**。整条链的指向一掉头，顺序就反过来了。

### 为什么需要 `prev` 指针？

翻转动作是 `curr->next = prev`（把当前节点的 `next` 指向前一个节点）。这里 `prev` 必须显式存着，因为单链表**只能往后走，不能往回走**——一旦改了 `curr->next`，原本的下一个节点就"丢了线索"，必须靠额外变量把"前一个节点"和"下一个要处理的节点"都记牢。

### 为什么不能直接 `curr->next = prev` 就完事？

如果只写一句 `curr->next = prev`，那么 `curr` 原本指向的下一个节点就再也找不回来了（`curr->next` 已经被覆盖成 `prev`，回不去了）。链表从这里断成两截，后面的节点全丢了。

**正确做法**：在改 `curr->next` **之前**，先用一个临时变量 `next` 把 `curr` 原来的下一个节点存起来，等翻转完再让 `curr = next` 继续往下处理。这就是为什么要三个指针配合：

- `prev`：已经翻转好的那一段的**头节点**（初始时还没有翻转任何东西，所以是 `nullptr`）。
- `curr`：**当前正在翻转的节点**。
- `next`：**临时变量**，保存 `curr` 原来的下一个节点，防止改指针后丢失。

### 三指针的协作（每轮循环做 4 件事）

```
next = curr->next;   // 1. 先存住 curr 的下一个节点（否则下一步就丢了）
curr->next = prev;   // 2. 翻转：让 curr 掉头指向 prev
prev = curr;         // 3. prev 往前走一格，吃进刚翻转好的 curr
curr = next;         // 4. curr 往前走一格，去处理刚才存好的 next
```

循环条件是 `while (curr)`——只要还有节点没处理就继续。当 `curr` 变成 `nullptr` 时，所有节点都翻完了，此时 `prev` 恰好指向新的头节点（原来的尾节点）。

### 手动推导 `1 -> 2 -> 3 -> 4 -> 5` 的翻转过程

```
初始：prev=nullptr, curr=1     链表：nullptr  1 -> 2 -> 3 -> 4 -> 5 -> nullptr

第1轮：
  next = 2          （存住）
  1->next = nullptr （1 掉头指向 prev=nullptr）
  prev = 1          （prev 吃进 1）
  curr = 2          （curr 去处理 2）
  状态：nullptr <- 1   2 -> 3 -> 4 -> 5 -> nullptr

第2轮：
  next = 3
  2->next = 1       （2 掉头指向 1）
  prev = 2
  curr = 3
  状态：nullptr <- 1 <- 2   3 -> 4 -> 5 -> nullptr

第3轮：
  next = 4
  3->next = 2
  prev = 3
  curr = 4
  状态：nullptr <- 1 <- 2 <- 3   4 -> 5 -> nullptr

第4轮：
  next = 5
  4->next = 3
  prev = 4
  curr = 5
  状态：nullptr <- 1 <- 2 <- 3 <- 4   5 -> nullptr

第5轮：
  next = nullptr    （5 的下一个是空）
  5->next = 4       （5 掉头指向 4）
  prev = 5
  curr = nullptr    （curr 变空，循环结束）

最终：prev = 5，返回 prev，链表 = 5 -> 4 -> 3 -> 2 -> 1 -> nullptr  ✓
```

可以看到：**`prev` 始终是「已经翻转好的那一段的新头」**，循环结束时它正好是整条链翻转后的头节点，所以函数 `return prev`。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;             // 节点存的值
 *     ListNode *next;      // 指向下一个节点的指针；最后一个节点的 next == nullptr
 *     ListNode() : val(0), next(nullptr) {}                       // 默认构造
 *     ListNode(int x) : val(x), next(nullptr) {}                  // 只给值的构造
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}     // 全参数构造
 * };
 */
class Solution {
public:
    ListNode* reverseList(ListNode* head) {
        // prev：指向「已经翻转好的那一段的头」。
        //   - 初始为 nullptr，这一点非常关键：原来的头节点翻转后应该变成尾节点，
        //     尾节点的 next 必须是 nullptr。让 prev 从 nullptr 开始，
        //     第一轮循环里 curr(=原头)->next = prev(=nullptr) 正好完成这件事。
        //   - 不要初始化成 head！否则原头节点的 next 会指向自己，链表成环。
        ListNode* prev = nullptr;

        // curr：当前正在翻转的节点，从 head 开始往后走。
        ListNode* curr = head;

        // 只要 curr 还有节点要处理就继续；curr 变 nullptr 表示全翻完了。
        while (curr) {
            // next：临时变量，保存 curr 原来的下一个节点。
            //   - 为什么必须先存？因为下一句 curr->next = prev 会覆盖掉 curr->next，
            //     如果不提前存，原来的下一个节点就再也找不回来了，链表从中间断裂。
            //   - 这是一个独立的局部变量，每轮循环重新赋值，不跨轮积累。
            ListNode* next = curr->next;

            // 翻转的核心：让 curr 掉头，指向它原来的「前一个」节点 prev。
            //   - 注意顺序：这一句必须在「保存 next 之后」和「推进 prev 之前」执行，
            //     否则要么丢节点（没存 next），要么 prev 没更新就用了旧值。
            curr->next = prev;

            // prev 前进：吃进刚翻转好的 curr，变成「已翻转段的新头」。
            //   - 必须在 curr = next 之前更新 prev，否则 prev 会跟着 curr 一起跳过头。
            prev = curr;

            // curr 前进：去处理刚才临时存好的 next 节点。
            //   - 注意不是 curr = curr->next！因为上一句已经把 curr->next 改成 prev 了，
            //     这里必须用临时变量 next，否则死循环。
            curr = next;
        }

        // 循环结束时 curr == nullptr，prev 指向翻转后的新头节点（原尾节点）。
        //   - 注意返回的是 prev，不是 head！head 现在是尾节点了。
        return prev;
    }
};
```

## 复杂度

- **时间**：O(n)
  - `curr` 从 `head` 走到 `nullptr`，每个节点恰好被访问一次，每轮循环做 4 次指针赋值（O(1)）。
- **空间**：O(1)
  - 只用了 `prev` / `curr` / `next` 三个指针变量，没有开新链表或递归栈。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么 `prev` 要初始化成 `nullptr`，而不是 `head`？

因为**翻转后原头节点要变成尾节点，尾节点的 `next` 必须是 `nullptr`**。

看第一轮循环：`curr = head`（原头），`curr->next = prev`。如果 `prev = nullptr`，那么原头节点的 `next` 被正确设成 `nullptr`，符合"翻转后它就是尾"。

如果错误地 `prev = head`，那第一轮 `head->next = head`，原头节点指向自己，链表瞬间成环，`while(curr)` 会死循环或越界。

口诀：**`prev` 代表「已翻好段的头」，开始时还没翻任何东西，所以是 `nullptr`**。

### Q2：为什么不能省掉临时变量 `next`，直接 `curr = curr->next`？

因为 `curr->next` 在循环里**已经被改掉了**（`curr->next = prev`）。

如果省掉 `next`，写成这样：

```cpp
curr->next = prev;
prev = curr;
curr = curr->next;   // 错！此时 curr->next 已经等于 prev，等于又退回去了
```

第三行 `curr->next` 现在是 `prev`（刚被改的），所以 `curr` 会"倒退"回 `prev`，下一轮又翻一遍，死循环。

**临时变量 `next` 就是为了在改指针之前把"原来的下一个"抢出来。** 这是单链表翻转最常见的踩坑点，记住"先存再改"的顺序就行。

### Q3：空链表和只有一个节点的链表怎么办？

- **空链表** `head == nullptr`：`curr = nullptr`，`while(curr)` 直接不进循环，返回 `prev`（也是 `nullptr`），正确。
- **单节点** `head` 只有一个节点：进循环一轮，`next = nullptr`、`curr->next = prev(nullptr)`、`prev = curr`、`curr = nullptr`，循环结束返回 `prev`，即那个唯一节点，正确。

所以这套写法**天然覆盖边界情况，不需要特判**。这也是为什么循环条件用 `while (curr)` 而不是 `while (curr->next)`——后者会在空链表上解引用空指针直接崩。

### Q4：函数返回 `prev`，那原来的 `head` 去哪了？

`head` 指针本身没动，它还指向原来的头节点。**只是那个节点的 `next` 被改成了 `nullptr`**（因为它是第一个被翻转的，当时 `prev` 是 `nullptr`），所以现在它变成了尾节点。

翻转后的链表头是原来的尾节点，也就是循环结束时 `prev` 所指的位置。所以**返回值必须是 `prev`，不能返回 `head`**——`head` 现在是尾巴。

## 复盘

- **核心套路**：**「链表翻转是所有链表题的原子操作」**。后续的「K 个一组翻转链表」(25)、「两两交换链表中的节点」(24)、「回文链表」(234)、「删除倒数第 N 个节点」(19)、「反转链表 II」(92) 等题，本质都是在「206 反转链表」外面套一层逻辑。把这套 `prev/curr/next` 三指针写法背熟，是做链表题的基本功。
- **记忆口诀**：
  1. **prev 从空起**（`prev = nullptr`，保证原头变尾）。
  2. **先存再改**（`next = curr->next` 在 `curr->next = prev` 之前）。
  3. **prev 先 curr 后**（`prev = curr` 在 `curr = next` 之前）。
  4. **返回 prev 不是 head**。
- **不变式思维**：循环每一步，`prev` 始终指向「已翻转段的头」，`curr` 始终指向「未翻转段的头」。只要维护好这个不变式，循环结束 `curr == nullptr` 时，`prev` 自然就是答案。链表题大量使用这种"画清楚每根指针此刻代表什么"的思考方式。
- **指针图示**：做链表题强烈建议在纸上画方框箭头，每改一根指针就重画一次状态。光看代码很容易把 `curr`、`prev`、`next` 三个指针搞混。

### 解法二：递归法（对比用，非主解）

官方「方法二」。思路：**先递归翻转后面的部分，再把当前节点接到翻转后链表的尾部**。

具体说，`reverseList(head)` 假设能把 `head->next` 开头的子链表翻转好，并返回翻转后的新头 `newHead`。那么 `head` 这个节点应该接在哪里？原本 `head->next` 是子链表的头，翻转后子链表的头变成了 `newHead`，而原来的 `head->next` 节点变成了翻转后子链表的**尾**。所以：

- `head->next->next = head`：让翻转后子链表的尾（即 `head->next`）反过来指向 `head`，把 `head` 接上。
- `head->next = nullptr`：`head` 现在是整条翻转链的尾，`next` 必须置空。

递归基：`head` 为空或只有一个节点时，直接返回 `head`（不用翻）。

```cpp
class Solution {
public:
    ListNode* reverseList(ListNode* head) {
        // 递归基：空链表或只剩一个节点，直接返回它本身，无需翻转。
        //   - !head 覆盖空链表；!head->next 覆盖单节点。
        if (!head || !head->next) {
            return head;
        }
        // 递归翻转 head->next 开头的子链表，newHead 是翻转后的新头（原尾节点）。
        ListNode* newHead = reverseList(head->next);
        // 这一句最绕：head->next 在子链表翻转后变成了那条子链表的「尾」，
        // 让它的 next 指回 head，相当于把 head 接到翻转后链表的尾部。
        //   - 注意 head->next 此时指向的是「原子链表的头」，也就是「翻转后子链表的尾」。
        head->next->next = head;
        // head 现在是整条翻转链的尾，next 置空，避免成环。
        head->next = nullptr;
        // newHead 始终是翻转后的头（一路从原尾节点传回来），返回它。
        return newHead;
    }
};
```

- **时间**：O(n)，递归遍历每个节点一次。
- **空间**：O(n)，递归深度等于链表长度，系统调用栈要开 O(n)。**这是递归法相比迭代法的主要劣势**——链表很长（5000 节点）时有栈溢出风险。
- **对比**：迭代法 O(1) 空间、写法固定，是首选；递归法代码更短、思路更巧妙，但空间开销大，且 `head->next->next = head` 这一句对新手很绕。面试/工程里优先迭代法。

> 进阶问题「你能否用两种方法解决这道题？」——答案就是上面这两种。掌握迭代法即可，递归法理解到「先翻后面、再把当前接尾」的程度就够了。
