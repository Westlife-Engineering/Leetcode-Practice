# 138 随机链表的复制

- 难度：中等
- 标签：**哈希表**、**链表**
- 力扣链接：https://leetcode.cn/problems/copy-list-with-random-pointer/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「复制带随机指针的链表」（slug：`fu-zhi-dai-sui-ji-zhi-zhen-de-lian-biao-rblsf`）。正文主解是 **原地复制 + 拆分**（官方方法二），O(n) 时间、O(1) 额外空间，是「进阶」要求（常量空间）的正解；哈希表解法（O(n) 空间，更直观）放在「复盘」作对比。

## 题目描述

给你一个长度为 `n` 的链表，每个节点包含一个额外增加的随机指针 `random` ，该指针可以指向链表中的任何节点或空节点。

构造这个链表的 **深拷贝**。 深拷贝应该正好由 `n` 个 **全新** 节点组成，其中每个新节点的值都设为其对应的原节点的值。新节点的 `next` 指针和 `random` 指针也都应指向复制链表中的新节点，并使原链表和复制链表中的这些指针能够表示相同的链表状态。复制链表中的指针都不应指向原链表中的节点 。

例如，如果原链表中有 `X` 和 `Y` 两个节点，其中 `X.random --> Y` 。那么在复制链表中对应的两个节点 `x` 和 `y` ，同样有 `x.random --> y` 。

返回复制链表的头节点。

用一个由 `n` 个节点组成的链表来表示输入/输出中的链表。每个节点用一个 `[val, random_index]` 表示：

- `val`：一个表示 `Node.val` 的整数。
- `random_index`：随机指针指向的节点索引（范围从 `0` 到 `n-1`）；如果不指向任何节点，则为 `null` 。

你的代码 **只** 接受原链表的头节点 `head` 作为传入参数。

**示例 1：**

```
输入：head = [[7,null],[13,0],[11,4],[10,2],[1,0]]
输出：[[7,null],[13,0],[11,4],[10,2],[1,0]]
```

**示例 2：**

```
输入：head = [[1,1],[2,1]]
输出：[[1,1],[2,1]]
```

**示例 3：**

```
输入：head = [[3,null],[3,0],[3,null]]
输出：[[3,null],[3,0],[3,null]]
```

**提示：**

- `0 <= n <= 1000`
- `-10^4 <= Node.val <= 10^4`
- `Node.random` 为 `null` 或指向链表中的节点。

**进阶：** 你能在一个带 `O(1)` 额外空间的算法中完成吗？（注意：返回值不计入空间复杂度。）

> 关于节点结构：本题的节点类是 `Node`（不是普通链表的 `ListNode`），它有**三个**字段——`int val`（值）、`Node* next`（下一个节点）、`Node* random`（随机指针，可指向链表里任意一个节点，也可以是 `null`）。`random` 是和 `next` 并列的第二根指针，这就是「随机链表」和普通单链表唯一的区别。
>
> 关于「深拷贝」：要造出 `n` 个**全新的** `Node` 对象，它们之间的 `next`/`random` 关系和原链表完全对应，但**新节点的指针不能指向原链表的任何节点**（反过来也不行）。可以理解为「结构一样，但每个节点都是新建的，互不共享」。

## 思路

> 本题主要参考力扣官方题解的「方法二：迭代 + 节点拆分」。

### 为什么普通复制不行？

如果是普通单链表，复制太简单了：一边遍历原链表、一边 `new` 新节点串起来就行。问题出在 `random` 这根指针上。

遍历到节点 `X` 想给它配的新节点 `x` 设置 `x.random` 时，你需要知道「`X.random` 指向的原节点 `Y`，它对应的新节点 `y` 是哪一个」。可这时 `Y` 可能：

- 在 `X` 的**前面**（已经处理过）——但你也未必记得住它的新节点在哪；
- 在 `X` 的**后面**（还没创建）——你连 `y` 都还没 `new` 出来，根本没法指；
- 就是 `X` **自己**（`X.random == X`）——得指向自己的新节点 `x`。

也就是说，**复制一个节点的 `random` 依赖「原 random 目标节点对应的新节点」已经存在**。但原链表的 `random` 是乱跳的，没法保证按顺序遍历时目标新节点恰好都建好了。这是本题唯一的难点。

### 解法一（直观、放复盘）：哈希表记录映射

最自然的想法：用一张哈希表 `cachedNode` 记录「原节点 → 新节点」的映射。

- 第一遍遍历：把每个原节点都 `new` 一个新节点出来，存进 `cachedNode[原] = 新`；
- 第二遍遍历：对每个原节点 `X`，查它的 `next` 和 `random` 指向谁（设为 `N` 和 `R`），然后把新节点 `x` 的 `next`/`random` 设为 `cachedNode[N]` / `cachedNode[R]`。

（也可以像官方方法一那样用**回溯 + 哈希**：递归地 `copyRandomList(X.next)` 和 `copyRandomList(X.random)`，靠哈希表避免重复拷贝。思路同源，本质都是「原→新」映射。）

哈希法时间 O(n)、空间 O(n)（哈希表存了所有节点），能 AC，但**不满足「进阶」的 O(1) 空间要求**。

### 解法二（主解、O(1) 空间）：原地复制 + 拆分

关键技巧：**别用哈希表记映射，让「新节点」直接贴在「原节点」后面**，原节点本身就能当「映射表」用。三步走：

**第一步：每个原节点后面，插一个它的复制节点。**

遍历原链表，对每个原节点 `X`，新建 `X'`（值相同），插到 `X` 和 `X.next` 之间：

```
原来：  ... -> X -> N -> ...
插入后：... -> X -> X' -> N -> ...
```

整条链表变成「原节点、新节点」交错排列：

```
原链表：  A -> B -> C -> nullptr
第一步后：A -> A' -> B -> B' -> C -> C' -> nullptr
```

注意此时所有新节点 `A' B' C'` 的 `random` 都还是默认的空，第二步才设。

**第二步：给每个新节点设置 `random`。**

再遍历（注意步长变成 2：`node = node->next->next`，跳过新节点只走原节点）。对每个原节点 `X`，它后面紧跟的就是新节点 `X'`（即 `node->next`）。

`X.random` 指向某个原节点 `Y`，那 `Y` 后面紧跟的就是 `Y'`（即 `node->random->next`）。所以：

```
X'.random = (X.random != nullptr) ? X.random.next : nullptr
        = (X.random != nullptr) ? node->random->next : nullptr
```

**为什么要判空？** 因为 `X.random` 可能是 `nullptr`（题目明确说 `random` 可为空），这时 `X'.random` 也应该是 `nullptr`，但如果你不判空直接写 `node->random->next`，就会解引用空指针，段错误。

**第三步：拆分，把新节点串成独立链表，同时还原原链表。**

再遍历一遍（这次步长恢复成 1：`node = node->next`，因为要同时整理两条链）。对每个原节点 `X`，它后面是 `X'`，`X'` 后面是下一个原节点 `N`（如果还有的话）：

```
拆分前：X -> X' -> N -> N' -> ...
        X->next  要改回 X' 后面那个，即 N       （恢复原链表）
        X'->next 要改成 N 后面那个，即 N'        （串起复制链表）
```

代码里用 `nodeNew = node->next` 抓住新节点，然后：

- `node->next = node->next->next;`（`X.next` 跳过 `X'` 指向 `N`，恢复原链表）；
- `nodeNew->next = (nodeNew->next != nullptr) ? nodeNew->next->next : nullptr;`（`X'.next` 指向 `N'`，串复制链表；最后一个新节点 `next` 置空）。

循环结束后，原链表恢复原状，新节点也串成了一条完整的复制链表，返回 `headNew = head->next`（复制链表的头）。

> **为什么最后一步要同时恢复原链表？** 题目只要求返回复制链表，理论上原链表改没改不影响判题。但把原链表的 `next` 指针恢复回去是好习惯——这样函数调用后原链表保持不变，不会留下「交错」的脏状态。官方解法选择了把两边都整干净。

### 手动推导示例 1

原链表（`[val, random_index]`）：`[[7,null],[13,0],[11,4],[10,2],[1,0]]`。节点下标从 0 开始：

```
节点0 (val=7,  random=null)
节点1 (val=13, random=节点0)
节点2 (val=11, random=节点4)
节点3 (val=10, random=节点2)
节点4 (val=1,  random=节点0)
next 关系：0->1->2->3->4->nullptr
```

**第一步（每个原节点后插复制节点）：**

```
0(7) -> 0'(7) -> 1(13) -> 1'(13) -> 2(11) -> 2'(11) -> 3(10) -> 3'(10) -> 4(1) -> 4'(1) -> nullptr
```

**第二步（设 random）：**

```
节点0.random=null   → 0'.random=null
节点1.random=节点0  → 1'.random=节点0.next=0'      （0' 紧跟在节点0后）
节点2.random=节点4  → 2'.random=节点4.next=4'
节点3.random=节点2  → 3'.random=节点2.next=2'
节点4.random=节点0  → 4'.random=节点0.next=0'
```

这就是「原地映射」的妙处：**`Y'` 永远紧跟在 `Y` 后面**，所以 `X.random` 指向 `Y`，新链表里 `X'` 就该指向 `Y.next`（即 `Y'`）。不用任何额外数据结构。

**第三步（拆分）：** 把 `0'1'2'3'4'` 串起来、把原链表 `01234` 还原。新链表的 random 关系正好对应原链表（`1'.random=0'`、`2'.random=4'`、`3'.random=2'`、`4'.random=0'`、`0'.random=null`），输出正确。

## 代码

```cpp
/*
 * Definition for a Node.
 * struct Node {
 *     int val;         // 节点存的值
 *     Node* next;      // 指向下一个节点的指针；最后一个节点的 next == nullptr
 *     Node* random;    // 随机指针：可指向链表中任意一个节点，也可以是 nullptr（这是「随机链表」和普通链表唯一的区别）
 *     Node(int x) : val(x), next(nullptr), random(nullptr) {}  // 只给 val，两根指针默认置空
 *     Node() : val(0), next(nullptr), random(nullptr) {}
 *     Node(int x, Node* next, Node* random) : val(x), next(next), random(random) {}
 * };
 */
class Solution {
public:
    Node* copyRandomList(Node* head) {
        // 边界特判：空链表直接返回空。
        //   - 没有节点可复制，返回 nullptr 即可。
        //   - 这一句也保证后面 head->next、head->val 等访问不会解引用空指针。
        if (head == nullptr) {
            return nullptr;
        }

        // ============ 第一步：在每个原节点后插入它的复制节点 ============
        // 遍历原链表（注意步长是 2：跳过刚插入的新节点，只走原节点）。
        //   - 初始 node = head（第一个原节点）。
        //   - 每轮处理完原节点 node 后，下一个要处理的原节点是 node->next->next
        //     （因为 node->next 现在是新节点 nodeNew，nodeNew->next 才是下一个原节点）。
        for (Node* node = head; node != nullptr; node = node->next->next) {
            // new Node(node->val)：在堆上新建一个 Node，val 复制原节点的值。
            //   - new 返回 Node*（指向新对象的指针）；该新对象的 next/random 此时是构造默认的 nullptr。
            //   - 注意不是复制原节点对象本身，而是 new 一个全新对象——这正是「深拷贝」的要求。
            Node* nodeNew = new Node(node->val);
            // 把 nodeNew 插到 node 和 node->next 之间：
            //   - nodeNew->next 先接上原来 node 后面的节点（暂存，否则下一步覆盖就丢了）；
            //   - 再让 node->next 指向 nodeNew。
            //   - 顺序和「反转链表」里一样：先存后改，避免断链。
            nodeNew->next = node->next;
            node->next = nodeNew;
        }

        // ============ 第二步：给每个复制节点设置 random 指针 ============
        // 仍遍历原节点（步长 2）。
        for (Node* node = head; node != nullptr; node = node->next->next) {
            // node->next 是第一步刚插入的复制节点 nodeNew。
            Node* nodeNew = node->next;
            // 关键技巧：node->random 指向某个原节点 Y，Y 后面紧跟的就是 Y 的复制节点 Y'。
            //   - 即 nodeNew->random 应该指向 node->random->next（也就是 Y'）。
            //   - 必须判空！node->random 可能是 nullptr（题目允许 random 为空），
            //     这时 nodeNew->random 也应为 nullptr；若不判空直接 node->random->next 会段错误。
            //   - 三目运算符 (cond) ? a : b：cond 成立取 a，否则取 b。这里把判空和赋值写成一句。
            nodeNew->random = (node->random != nullptr) ? node->random->next : nullptr;
        }

        // ============ 第三步：拆分——把复制节点串成独立链表，同时还原原链表 ============
        // headNew：复制链表的头节点，就是 head 后面紧跟的那个新节点。
        Node* headNew = head->next;
        // 这一步遍历步长恢复成 1（node = node->next）：因为要同时整理「原链表」和「复制链表」两条链，
        // 而整理后 node->next 会变回「下一个原节点」，所以正常往后走即可。
        for (Node* node = head; node != nullptr; node = node->next) {
            // nodeNew：当前原节点后面的复制节点。
            Node* nodeNew = node->next;
            // 恢复原链表：让 node->next 跳过 nodeNew，指向下一个原节点。
            //   - node->next->next 当前是下一个原节点（第一步里插入了 nodeNew，所以 node->next=nodeNew，
            //     nodeNew->next=下一个原节点）。这一句把 node->next 改回「下一个原节点」。
            node->next = node->next->next;
            // 串复制链表：nodeNew->next 当前是下一个原节点，要改成「下一个复制节点」。
            //   - 下一个复制节点 = 下一个原节点的 next（即「下一个原节点」紧跟的那个复制节点）。
            //   - 等价于 nodeNew->next->next（先到下一个原节点，再取它后面那个复制节点）。
            //   - 判空：最后一个复制节点的后面没有「下一个原节点」了（nodeNew->next 已经是 nullptr），
            //     此时 nodeNew->next 保持 nullptr，正好是复制链表的尾巴。
            nodeNew->next = (nodeNew->next != nullptr) ? nodeNew->next->next : nullptr;
        }

        // 返回复制链表的头节点（原链表已被还原成原样，互不影响）。
        return headNew;
    }
};
```

## 复杂度

- **时间**：O(n)，n 为节点数。
  - 三个 `for` 循环各遍历链表一次，每个节点在每个循环里被访问一次，总共约 3n 次操作，线性级别。
- **空间**：O(1)
  - 只用了 `node`、`nodeNew`、`headNew` 等几个指针变量，**没有哈希表、没有递归栈**，额外空间是常数。
  - 注意：题目说「返回值不计入空间复杂度」，所以新建的 `n` 个节点（结果本身）不算进 O(1) 里。真正用到的「额外」辅助空间只有那几个指针，满足「进阶」要求。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：第二步设置 `random` 时为什么一定要判空？

因为**原节点的 `random` 可能是 `nullptr`**。题目明确说 `Node.random` 为 `null` 或指向链表中的节点——空是合法的。

代码里这句：

```cpp
nodeNew->random = (node->random != nullptr) ? node->random->next : nullptr;
```

如果 `node->random` 是空，你还直接写 `node->random->next`，就是对空指针解引用，立刻段错误。所以必须先判空：`random` 为空时，新节点的 `random` 也设成空；非空时才取 `node->random->next`（即对应的新节点）。

口诀：**链表题凡是要 `->next`，先想这根指针会不会是空**。本题的 `random` 尤其要注意，它比 `next` 更容易为空。

### Q2：拆分（第三步）时，怎么区分「原节点」和「复制节点」？

靠**位置规律**：第一步插入后，链表是「原、新、原、新…」严格交错的，**每个原节点后面紧跟的就是它的复制节点**。

所以第三步里：

- `node` 永远是**原节点**（从 `head` 出发，整理后 `node->next` 自然变成下一个原节点，所以步长是 1）；
- `nodeNew = node->next` 永远是**当前复制节点**（紧跟在 `node` 后面）。

不需要任何标记或哈希表来区分两者，**交错结构本身就是「原→新」的映射**。这也是这个算法能省掉哈希表的根本原因。

### Q3：为什么这个算法是 O(1) 额外空间？不是还 `new` 了 n 个节点吗？

空间复杂度分两类：

- **结果空间**：返回值（这里是 n 个新节点）**不计入**空间复杂度——这是力扣的约定，题目里也写了「返回值不计入空间复杂度」。
- **辅助空间**：算法为了算出结果而**额外**申请的、用完就丢的临时空间。本算法只用了几个指针变量（`node`、`nodeNew`、`headNew`），数量是常数，跟 n 无关，所以是 O(1)。

对比哈希表法：哈希表里存的「原→新」映射是**辅助**用的（不是结果的一部分），它有 n 条记录，所以哈希法是 O(n) 辅助空间。原地法巧妙地「借用原链表节点本身的 `next` 指针」来当映射表，省掉了这张哈希表。

### Q4：如果某个节点的 `random` 指向它自己怎么办？

完全没问题。设原节点 `X` 满足 `X.random == X`。

- 第一步后，`X` 后面紧跟 `X'`。
- 第二步：`X'.random = X.random->next = X->next = X'`。也就是 **`X'` 的 random 也指向它自己**，结构和原节点完全对应，正确。

类似地，`random` 指向前面的节点、指向后面的节点、指向 null，这套算法都能处理——因为它只依赖「新节点紧跟在原节点后」这一条不变关系，而这条关系对链表里所有节点一视同仁。

## 复盘

- **核心套路：「链表原地操作 + 用节点本身的指针当临时映射」**。凡是要「记录节点间对应关系」又想省空间的链表题，都可以想：能不能**改造链表的结构**（比如在节点间插入临时节点、或暂时改写 `next` 指针），让结构本身承载「映射」信息，最后再恢复？这是「原地算法」在链表题里的典型套路。类似的还有「148 排序链表」（断链合并）、「160 相交链表」（拼接两条链）等。
- **关键记忆点**：
  1. **三步走顺序固定**：先插复制节点（建映射）→ 再设 random（用映射）→ 最后拆分（清映射 + 还原）。
  2. **前两个循环步长是 2**（`node->next->next`，跳过新节点只走原节点），**第三个循环步长是 1**（同时整理两条链，整理后 `node->next` 自然指向下一个原节点）。
  3. **设 random 必判空**（`node->random` 可能为 `nullptr`）。
  4. **拆分时两句顺序**：先恢复 `node->next`（原链表），再设 `nodeNew->next`（复制链表）——但注意设 `nodeNew->next` 时用的是 `nodeNew->next`（指向下一个原节点）而不是已被改写的 `node->next`，所以两句话里引用的值互不干扰。
- **何时用哈希法、何时用原地法**：
  - 面试/手撕时如果对方没强调空间，**哈希法更好写、更不容易出 bug**，先写哈希法稳住，再口头提一句「还可以原地 O(1) 空间」。
  - 题目明确要 O(1) 空间（本题「进阶」），或追求最优解，用原地法。
  - 两者时间都是 O(n)，差距只在常数和空间。

### 解法二：哈希表 + 回溯（官方方法一，对比用、非主解）

官方方法一的写法，思路最直观：用一张 `unordered_map<Node*, Node*>` 记录「原节点 → 新节点」的映射，递归地复制 `next` 和 `random` 指向的节点，靠哈希表避免重复拷贝。

```cpp
class Solution {
public:
    // unordered_map<Node*, Node*> cachedNode：C++ STL 哈希表，key 和 value 都是「指向 Node 的指针」。
    //   - 含义：原节点指针 → 它对应的新节点指针（即「原→新」映射）。
    //   - 标准库对裸指针有 std::hash 特化，直接用地址做哈希，无需自定义哈希函数。
    //   - 插入/查找均摊 O(1)。这里作为成员变量，递归全程共享同一张表。
    //   - 注意：用裸指针 Node* 做 key 比的是「地址相等」（同一个原节点），不是比 val。
    unordered_map<Node*, Node*> cachedNode;

    Node* copyRandomList(Node* head) {
        // 递归基：原节点为空，返回空。
        if (head == nullptr) {
            return nullptr;
        }
        // count(head)：返回哈希表里 key 等于 head 的元素个数（map 里只能是 0 或 1）。
        //   - 用 !count(head) 判断「head 这个原节点还没复制过」。
        //   - 已经复制过则跳过 if，直接返回 cachedNode[head]（避免重复拷贝、避免无限递归）。
        if (!cachedNode.count(head)) {
            // 第一次遇到这个原节点：new 一个新节点，值复制原节点的 val。
            Node* headNew = new Node(head->val);
            // 先把「原 head → 新 headNew」存进哈希表，这一点很关键：
            //   - 下面递归 copyRandomList(head->next) 和 copyRandomList(head->random) 时，
            //     如果它们的 next/random 又指回 head，因为 cachedNode[head] 已经存在，会直接返回，
            //     从而正确处理「环」「自指」等情况，不会无限递归。
            cachedNode[head] = headNew;
            // 递归复制 next 指向的节点，并把结果接到新节点的 next。
            headNew->next = copyRandomList(head->next);
            // 递归复制 random 指向的节点，并把结果接到新节点的 random。
            headNew->random = copyRandomList(head->random);
        }
        // 返回 head 对应的新节点（要么刚 new 的，要么哈希表里已存在的）。
        return cachedNode[head];
    }
};
```

- **时间**：O(n)，每个原节点至多被「真正复制」一次（靠哈希表去重），递归访问的 next/random 目标节点合计均摊每点至多两次。
- **空间**：O(n)，哈希表存了所有 n 个原节点的映射，递归栈深度最坏也是 O(n)。**不满足「进阶」的 O(1) 空间要求**。
- **对比**：哈希法（尤其是这种递归写法）思路非常干净——「先复制自己、再递归复制两根指针指向的节点」，代码短、不容易错。缺点是 O(n) 空间 + 递归栈（链表很长时有栈溢出风险）。面试如果对方没强调空间，先写这个最稳；要 O(1) 空间再上原地法。
- **等价的迭代哈希写法**：也可以不递归，先一遍遍历把所有原节点 new 出来存进 `cachedNode`，再一遍遍历查表设 `next`/`random`。思路完全一样，只是把递归展开成两轮循环，省掉递归栈但哈希表空间不变。
