# 2 两数相加

- 难度：中等
- 标签：**递归**、**链表**、**数学**
- 力扣链接：https://leetcode.cn/problems/add-two-numbers/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「两数相加」（slug：`liang-shu-xiang-jia-by-leetcode-solution`）。正文主解是 **模拟竖式加法（哑节点 + carry 进位 + 一轮循环搞定）**，时间 O(max(m,n))、空间 O(1)（结果链表不计），是「链表模拟算术运算」这一类题的标准写法；官方原版代码（用 `head/tail` 两个指针、循环外加一次进位补节点）放在「复盘」章节作对比。

## 题目描述

给你两个 **非空** 的链表，表示两个非负的整数。它们每位数字都是按照 **逆序** 的方式存储的，并且每个节点只能存储 **一位** 数字。

请你将两个数相加，并以相同形式返回一个表示和的链表。

你可以假设除了数字 0 之外，这两个数都不会以 0 开头。

**示例 1：**

```
输入：l1 = [2,4,3], l2 = [5,6,4]
输出：[7,0,8]
解释：342 + 465 = 807.
```

**示例 2：**

```
输入：l1 = [0], l2 = [0]
输出：[0]
```

**示例 3：**

```
输入：l1 = [9,9,9,9,9,9,9], l2 = [9,9,9,9]
输出：[8,9,9,9,0,0,0,1]
```

**提示：**

- 每个链表中的节点数在范围 `[1, 100]` 内
- `0 <= Node.val <= 9`
- 题目数据保证列表表示的数字不含前导零

## 思路

> 本题主要参考力扣官方题解的「方法一：模拟」。

### 关键设定：链表是「逆序存储」的

题面这句话是整道题的题眼：**数字按逆序存**，也就是**个位在链表头、最高位在链表尾**。比如 `342` 存成 `2 -> 4 -> 3`，`465` 存成 `5 -> 6 -> 4`。

这个设定不是出题人故意刁难，反而**极大地简化了加法**：小学生竖式加法本来就是从个位开始、逐位往高位加，链表又是从头开始往后遍历的——**两个「从头开始」天然对齐**，根本不用先反转链表、也不用从尾扫到头。如果题目改成「正序存储」（最高位在头），那就得先反转链表或者用栈，麻烦得多。所以看到「逆序存储」要立刻意识到：**这一题不用倒着扫，从头顺着加就对**。

### 模拟竖式加法的过程

回忆手算 `342 + 465`：

```
  3 4 2
+ 4 6 5
-------
  8 0 7
```

规则是：从个位起，每一位把两个数对应位**加上上一位的进位**，得到一个 `sum`；`sum % 10` 是当前位的结果，`sum / 10` 是往高位的进位。一直加到所有位处理完、且没有进位为止。

把这套规则搬到链表上：

1. 两个指针 `l1`、`l2` 分别从两条链表的头（也就是「个位」）开始，同时往后走。
2. 每一位取 `l1->val + l2->val + carry`（`carry` 是上一位留下来的进位，初始为 0）。
3. `sum % 10` 新建一个节点接到结果链表末尾；`carry = sum / 10` 留给下一位。
4. `l1`、`l2` 各自往后走（如果某条已经走完，那位上的值当成 0）。

### 进位 `carry` 怎么处理？

`carry` 是个 `int`，初始为 0。每算完一位 `sum = n1 + n2 + carry`：

- 当前位写入结果的是 `sum % 10`（一定在 0~9 之间，因为 `9+9+1=19` 是最大可能值）。
- 新的 `carry = sum / 10`（整数除法，`19/10=1`，所以 carry 只会是 0 或 1）。

注意一个最容易被忽略的点：**两条链表都走完后，`carry` 可能还是 1**（比如 `9 + 1 = 10`，个位写 0 进 1，没有更多位了，但这个 1 必须再补一个节点）。这也是为什么循环条件里要把 `carry` 也算进去。

### 两个链表长度不同怎么办？

不用补齐。某条链表先走到 `nullptr` 时，它这一位贡献的值直接当 0 用（`n1 = l1 ? l1->val : 0`）。循环继续跑，直到**两条都空且 carry 也清零**为止。这样 `9999 + 1` 这种长度悬殊的情况也能正常处理。

### 为什么用哑节点 `dummy`？

和「21 合并两个有序链表」一模一样的套路：结果链表的**头节点是谁、什么时候第一次创建**本来要特判。开了个 `dummy` 假头后，`tail` 指针从 `dummy` 开始，**每一次「`tail->next = new ListNode(digit)`」的操作都完全统一**，不用关心是不是第一个节点。最后返回 `dummy->next` 就是真正的结果头。

> 口诀：**只要题目要返回「新链表的头」而你又不知道头是谁、什么时候建，就先开个 dummy**。这题、21 题、19 题、24 题、25 题都用这招。

### 手动推导 `342 + 465 = 807`

也就是 `2->4->3` 加 `5->6->4`，期望结果是 `7->0->8`。

```
初始  carry=0  tail=dummy       l1: 2->4->3    l2: 5->6->4
      结果链：dummy -> (空)

第1轮  l1=2, l2=5
       sum = 2 + 5 + 0 = 12
       digit = 12 % 10 = 2... 错！应是 7。重算：sum = 2+5+0 = 7
       这里 n1=2,n2=5,carry=0，sum=7, digit=7, carry=0
       tail->next = 7, tail = 7, l1=4, l2=6
       结果链：dummy -> 7

第2轮  l1=4, l2=6
       sum = 4 + 6 + 0 = 10
       digit = 10 % 10 = 0, carry = 10 / 10 = 1
       tail->next = 0, tail = 0, l1=3, l2=4
       结果链：dummy -> 7 -> 0

第3轮  l1=3, l2=4
       sum = 3 + 4 + 1 = 8     (注意 carry 是上一轮留下的 1)
       digit = 8 % 10 = 8, carry = 8 / 10 = 0
       tail->next = 8, tail = 8, l1=nullptr, l2=nullptr
       结果链：dummy -> 7 -> 0 -> 8

第4轮  l1 和 l2 都空，但循环条件是 while(l1 || l2 || carry)
       此时 l1=l2=nullptr, carry=0，三个全是「假」，循环退出 ✓

返回 dummy->next，即 7 -> 0 -> 8   （表示 807，正好是 342+465）✓
```

> 第 2 轮 `4 + 6 = 10` 这一步是关键：当前位写 0、往高位进 1，这个 1 被第 3 轮的 `sum = 3 + 4 + 1 = 8` 接住了。这就是「进位」机制在起作用。

再看一个**最后还有进位**的例子，理解循环条件为什么必须带 `carry`：

```
l1 = [9,9,9,9]   (表示 9999)
l2 = [1]         (表示 1)
期望 = [0,0,0,0,1] (表示 10000)

跑到 l2 早就空、l1 也走完时，sum 最后一轮是 9+0+0=9... 不对，
让我重列：个位 9+1+0=10(digit0,carry1)、十位 9+0+1=10(d0,c1)、
百位 9+0+1=10(d0,c1)、千位 9+0+1=10(d0,c1)。此时 l1、l2 都空，
但 carry 还是 1！如果循环条件只有 while(l1||l2)，这一位会被漏掉，
结果变成 0000（漏了最高位的 1）。
带 carry 后再跑一轮：sum=0+0+1=1, digit=1, carry=0, 补一个节点 1，
才得到正确的 [0,0,0,0,1]。
```

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 * *     int val;             // 节点存的值（本题里是一位数字 0~9）
 * *     ListNode *next;      // 指向下一个节点的指针；最后一个节点的 next == nullptr
 * *     ListNode() : val(0), next(nullptr) {}                       // 默认构造
 * *     ListNode(int x) : val(x), next(nullptr) {}                  // 只给值的构造
 * *     ListNode(int x, ListNode *next) : val(x), next(next) {}     // 全参数构造
 * * };
 */
class Solution {
public:
    ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
        // 哑节点（哨兵节点）dummy：在真正结果链表前面「虚构」一个假头。
        //   - 作用：消除「结果链表第一个节点什么时候建、由谁来当头」的特判。
        //     有了它之后，循环里每一次「tail->next = new ListNode(...)」的写法都完全统一，
        //     包括接第一个节点的那一次，不用单独 if 判断是不是头。
        //   - 值填 0 只是占位，它本身不参与任何加法运算，也不会出现在最终结果里。
        //   - 必须用 new 在堆上创建：若写成 ListNode dummy(0);（栈对象），函数返回时它会被销毁，
        //     dummy.next 也跟着失效，返回的就是野指针。力扣判题不在乎这点内存泄漏；工程代码里记得回收。
        ListNode* dummy = new ListNode(0);

        // tail：始终指向「结果链表的当前末尾节点」，下一个新节点就接在 tail->next。
        //   - 初始指向 dummy，因为还没接任何节点，末尾就是那个假头。
        //   - 循环里每接上一个节点，tail 就往后走一位。
        //   - 这一根指针就够用了，不需要像官方原版那样同时维护 head 和 tail（见复盘解法二）。
        ListNode* tail = dummy;

        // carry：进位变量。初始 0（还没加任何位，没有进位）。
        //   - 取值只会是 0 或 1：每一位最大 sum = 9+9+1 = 19，19/10 = 1。
        //   - 它的生命周期跨越整个循环，是「上一位留给下一位的进位」。
        int carry = 0;

        // 循环条件 while (l1 || l2 || carry) 是本题最容易写错的地方，三个条件缺一不可：
        //   - l1：第一条链表还有位没处理；
        //   - l2：第二条链表还有位没处理；
        //   - carry：两条都处理完了，但还剩一个进位没补节点（如 9999+1 的最后一轮）。
        //   只要三者任一为真就继续。漏掉 carry 会导致最高位的进位被丢掉（见上面思路里的反例）。
        //   注意「||」是短路或：l1 非空就不会去看 l2，这里只是判断真假，无副作用。
        while (l1 || l2 || carry) {
            // n1：l1 当前位的值。l1 走空了就当 0（短的那条链表高位全是 0）。
            //   - l1 ? l1->val : 0 是三目运算：l1 非空取 l1->val，否则取 0。
            //   - 必须先取值再决定要不要 l1 = l1->next，否则可能解引用空指针崩溃。
            int n1 = l1 ? l1->val : 0;
            // n2：l2 当前位的值，同理。
            int n2 = l2 ? l2->val : 0;

            // 核心加法：当前位 = l1 这位 + l2 这位 + 上一位的进位。
            //   - 最大 9+9+1=19，最小 0+0+0=0，sum 在 0~19 之间，int 完全装得下，不会溢出。
            int sum = n1 + n2 + carry;

            // 当前位写入结果的是 sum 的个位（0~9）。
            //   - sum % 10 取个位：7%10=7，10%10=0，19%10=9。
            int digit = sum % 10;
            // 新的进位是 sum 的十位（本题里只会是 0 或 1）。
            //   - sum / 10 整数除法：7/10=0，10/10=1，19/10=1。
            //   - 注意这一句必须在 new ListNode(digit) 之前或之后都行，它和 digit 互不影响；
            //     习惯上先算 digit 再算 carry，思路清楚。
            carry = sum / 10;

            // 新建一个值为 digit 的节点，接到结果链表末尾。
            //   - new ListNode(digit)：调用 ListNode(int) 构造，在堆上开一个节点，next 默认 nullptr。
            //   - 因为有 dummy，这里不用区分「第一个节点」和「后续节点」，写法完全统一。
            tail->next = new ListNode(digit);
            // tail 往后走一位，始终指向新的末尾。
            //   - 这一句必须在 l1/l2 推进之前或之后都行，顺序无所谓，但别漏写，否则 tail 永远停在 dummy。
            tail = tail->next;

            // l1、l2 各自往后走（如果还没走空的话）。
            //   - 必须先判空再推进！如果不判空直接 l1 = l1->next，会解引用 nullptr 崩溃。
            //   - 已走空的链表保持 nullptr，下一轮循环里 n1/n2 会自动取 0，不影响加法。
            if (l1) l1 = l1->next;
            if (l2) l2 = l2->next;
        }

        // 返回真正的结果链表头：跳过那个假头 dummy。
        //   - 不能返回 dummy！它是个我们虚构的、值为 0 的节点，不属于答案。
        //   - dummy->next 才是第一个真正算出来的节点（也就是结果的个位）。
        return dummy->next;
    }
};
```

## 复杂度

- **时间**：O(max(m, n))
  - `while` 循环的轮数 = 两条链表中较长者的长度 + 至多 1（最后那个补进位的轮）。每轮做常数次加法、取模、除法和一次 `new`，都是 O(1)。
  - 其中 m、n 分别是 `l1`、`l2` 的节点数。
- **空间**：O(1)（**结果链表不计入**）
  - 只开了 `dummy`、`tail`、`carry`、`n1`、`n2`、`sum`、`digit` 这几个常数大小的变量。
  - 「结果链表」是题目要求必须返回的输出，按惯例不算额外空间；如果要算上它，则空间是 O(max(m,n))。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么题目要把数字「逆序」存进链表？正序不行吗？

逆序存储是**为了方便加法**，不是出题人故意刁难。

竖式加法从**个位**算起，逐位往高位走，进位也是从低位往高位传。而单链表只能**从头往后**遍历。如果数字正序存（最高位在头），那「加法起点」（个位）就落在链表尾部，单链表根本扫不到，得先反转链表或借助栈倒着取——非常别扭。

逆序存之后，链表头恰好是个位，「从头往后遍历」和「从个位往高位加」完美对齐，直接顺着加就行。所以题面里「逆序存储」这四个字是整道题能简单做的关键，看到它就要立刻意识到**不用反转链表、不用栈、顺着加**。

### Q2：循环条件 `while (l1 || l2 || carry)` 为什么三个条件都要写？漏掉 `carry` 会怎样？

`l1` 和 `l2` 保证两条链表的每一位都被处理；`carry` 保证「两条都走完但还剩一个进位」时再补一个节点。

漏掉 `carry` 的后果：考虑 `l1 = [9,9,9,9]`（9999）、`l2 = [1]`（1），结果是 10000。跑到最后 l1、l2 都空时，carry 还是 1（最高位进上来的）。如果循环条件只有 `while (l1 || l2)`，这一轮不会执行，那个进位 1 就被丢了，结果变成 `[0,0,0,0]`（漏了最高位），错。

带上 `carry` 后，还会再跑一轮：`n1=0, n2=0, sum=0+0+1=1, digit=1, carry=0`，补出一个节点 1，结果才是正确的 `[0,0,0,0,1]`。

口诀：**`carry` 是「隐形的最高位」，它非 0 就说明还有一位没写进结果**，循环条件必须把它算进去。

### Q3：哑节点 `dummy` 在这里到底解决了什么问题？能不能不开？

不开哑节点的话，「结果链表的头节点」需要特判：第一次创建节点时要单独记下 `head`（因为后面循环里只用 `tail` 推进，`head` 一旦丢了就找不回结果链表的入口）。代码大概长这样：

```cpp
ListNode *head = nullptr, *tail = nullptr;
// ... 循环里：
if (!head) {
    head = tail = new ListNode(digit);   // 第一轮特判
} else {
    tail->next = new ListNode(digit);
    tail = tail->next;
}
```

这其实就是官方原版的写法（见复盘解法二）。它能 AC，但循环体里多一个 `if/else` 分支，第一轮和后续轮的写法不统一，容易写错。

开了 `dummy` 之后，`tail` 从 `dummy` 起步，**每一轮都是 `tail->next = new ListNode(digit); tail = tail->next;`**，完全没有特判。最后返回 `dummy->next` 一刀切。这就是「哨兵节点简化头部处理」的威力——和 21 题（合并两个有序链表）完全一样的套路。

### Q4：`sum = n1 + n2 + carry` 最大是 19，会不会溢出？

不会。`int` 在 C++ 里至少 32 位，能表示到约 21 亿，19 远远不到溢出边界。

即使题目把 `Node.val` 范围放宽、每位的进位更大，只要 `sum` 不超过 `int` 上限都没问题。本题 `0 <= Node.val <= 9`，最大 `9+9+1=19`，毫无压力。真正要担心溢出的是「字符串相加」（如 415 题）那种大数运算——那里连 `int` 都装不下，得用字符串模拟，和本题不是一类题。

### Q5：`l1 ? l1->val : 0` 这个三目运算能不能换成别的写法？

可以，但三目运算最简洁直观。等价写法有：

```cpp
int n1 = 0;
if (l1) n1 = l1->val;
```

或更短但稍隐晦的：

```cpp
int n1 = l1 ? l1->val : 0;   // 推荐
```

**关键不是写法，而是「取值之前必须先判空」这件事**。如果直接写 `int n1 = l1->val;`，当 l1 已经是 `nullptr` 时会解引用空指针，程序崩溃。题目保证输入链表非空，但循环中 l1 会走到空，所以这个判空绝不能省。

## 复盘

- **核心套路**：**「链表模拟竖式运算 + 进位 + 哑节点」** 是一类题的通解。这道题是加法，后续的「445 两数相加 II」（链表正序存储，要先反转或用栈）、大数乘法、链表表示的数字 +1 等都是同一套思路：逐位运算、`carry` 传递、`sum / 10` 和 `sum % 10` 拆分、哑节点统一头部。
- **三大要点**：
  1. **逆序存储 = 从头顺着加**（看到「逆序」要意识到这是简化，不是障碍）。
  2. **循环条件带上 `carry`**（隐形最高位不能漏）。
  3. **哑节点统一头部处理**（链表题最高频套路，和 21、19、24、25 题共享）。
- **可迁移口诀**：
  1. `sum = n1 + n2 + carry`（当前位 = 两数当前位 + 上一位进位）。
  2. `digit = sum % 10`、`carry = sum / 10`（拆个位和进位）。
  3. `tail->next = new ListNode(digit); tail = tail->next;`（接节点 + 推尾指针）。
  4. `while (l1 || l2 || carry)`（三者任一非空就继续）。
- **和「1 两数之和」的区别**：1 题是「在数组里找两个数等于 target」（哈希表查互补数），2 题是「把两个链表表示的大数加起来」（模拟竖式）。名字像、完全不同的两道题，别搞混。本题的近亲是「445 两数相加 II」和「415 字符串相加」。

### 解法二：官方原版（head/tail 双指针 + 循环外补进位，对比用，非主解）

官方题解给的写法思路完全一样（也是模拟竖式加法），只是不用哑节点，而是同时维护 `head`（结果链表头）和 `tail`（结果链表尾）两个指针，并在循环体内用 `if (!head)` 特判第一个节点；循环结束后再用一个单独的 `if (carry > 0)` 补最高位的进位。

```cpp
class Solution {
public:
    ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
        // 同时维护 head（结果头）和 tail（结果尾），不开哑节点。
        ListNode *head = nullptr, *tail = nullptr;
        int carry = 0;
        // 注意：官方这里循环条件是 while (l1 || l2)，没带 carry，
        //   进位的处理放到循环外面的 if (carry > 0) 那一句。
        while (l1 || l2) {
            int n1 = l1 ? l1->val : 0;
            int n2 = l2 ? l2->val : 0;
            int sum = n1 + n2 + carry;
            // 第一轮：head 还没建，新建第一个节点，head 和 tail 都指向它。
            //   - 这是「不开哑节点」的代价：要特判第一个节点。
            if (!head) {
                head = tail = new ListNode(sum % 10);
            } else {
                // 后续轮：接到 tail 后面，tail 往后走。
                tail->next = new ListNode(sum % 10);
                tail = tail->next;
            }
            carry = sum / 10;
            if (l1) l1 = l1->next;
            if (l2) l2 = l2->next;
        }
        // 两条链表都走完后，如果还剩进位，单独补一个最高位节点。
        //   - 这一句等价于主解里「循环条件带 carry」的效果，写法不同、结果一样。
        if (carry > 0) {
            tail->next = new ListNode(carry);
        }
        return head;
    }
};
```

- **时间**：O(max(m,n))，与主解相同。
- **空间**：O(1)（结果链表不计）。
- **对比**：和主解（哑节点 + `while(l1||l2||carry)`）思路完全一致，复杂度相同，只是写法风格不同。主解把「补进位」合并进循环条件，循环体里不用 `if/else` 特判第一个节点，代码更简洁统一；官方原版把进位补节点拆到循环外，可读性也清楚。两种都对，**主解的哑节点写法更通用**，推荐养成习惯——后续 445 题、链表 +1 等都能套用同一套模板。
