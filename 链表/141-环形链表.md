# 141 环形链表

- 难度：简单
- 标签：哈希表、**链表**、**双指针**
- 力扣链接：https://leetcode.cn/problems/linked-list-cycle/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「环形链表」（slug：`huan-xing-lian-biao-by-leetcode-solution`）。正文主解是 **Floyd 快慢指针（龟兔赛跑）**，O(n) 时间、O(1) 空间，是「进阶」要求（常量内存）的正解；哈希集合解法（O(n) 空间）放在「复盘」作对比。

## 题目描述

给你一个链表的头节点 `head`，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（索引从 0 开始）。**注意：`pos` 不作为参数进行传递**。仅仅是为了标识链表的实际情况。

如果链表中存在环，则返回 `true`。否则，返回 `false`。

**示例 1：**

```
输入：head = [3,2,0,-4], pos = 1
输出：true
解释：链表中有一个环，其尾部连接到第二个节点。
```

**示例 2：**

```
输入：head = [1,2], pos = 0
输出：true
解释：链表中有一个环，其尾部连接到第一个节点。
```

**示例 3：**

```
输入：head = [1], pos = -1
输出：false
解释：链表中没有环。
```

**提示：**

- 链表中节点的数目范围是 `[0, 10^4]`
- `-10^5 <= Node.val <= 10^5`
- `pos` 为 `-1` 或者链表中的一个 **有效索引**。

**进阶：** 你能用 `O(1)`（即，常量）内存解决此问题吗？

> 关于 `pos`：它**只是题目用来描述「环长什么样」的工具**，不是你函数的入参。函数签名只有 `hasCycle(ListNode *head)`，你拿不到 `pos`，必须靠遍历链表本身去发现「尾节点又指回了前面某个节点」。`pos = -1` 表示无环，`pos = k` 表示尾节点指向第 `k` 个节点（下标从 0 开始）。示例 1 里 `pos = 1`，意思是尾巴 `-4` 的 `next` 指回节点 `2`。

## 思路

> 本题主要参考力扣官方题解的「方法二：快慢指针」（Floyd 判圈算法 / 龟兔赛跑）。

先厘清「有环」的定义：链表里存在某个节点，它的 `next` 指针最终能绕回来再次到达自己（或绕回来经过自己）。换句话说，**沿 `next` 一路走下去永远不会遇到 `nullptr`**——尾节点不指向空，而是指向链表中某个已有节点，形成一个圈。

注意判断的是「指针/节点是否被重复到达」，不是「值」是否重复。比如 `[1,2,3,1]` 末尾的 `1` 如果是全新节点、`next` 是空，那也不是环；判断依据是 `next` 指针连成了圈。

下面由浅入深看两种做法。

### 解法一：哈希集合（直观但费空间）

最容易想到：遍历链表，把走过的每个节点指针都记进一个哈希集合。每到一个新节点，先查它是不是已经在集合里——

- 在 → 说明之前走过，绕回来了，**有环**；
- 不在 → 把它加入集合，继续往后走。

如果一路走到 `nullptr`，说明链表有尽头，**无环**。

这个方法时间 O(n)、空间 O(n)（集合要存所有节点指针）。能 AC，但「进阶」要求 O(1) 内存，所以哈希法不是最优解，放在「复盘」里作对比。

### 解法二：快慢指针（Floyd 判圈，官方主解）

核心想法：**让两个速度不同的指针在链表上赛跑，如果有环，快的那个一定会从后面追上慢的那个。**

设两个指针都从链表出发：

- `slow`（乌龟）：每次走 **1 步**，`slow = slow->next`；
- `fast`（兔子）：每次走 **2 步**，`fast = fast->next->next`。

**如果没有环**：链表是一条直线，`fast` 跑得快，会**先到达 `nullptr`**（尾巴）。此时直接返回 `false`，无需再跑。

**如果有环**：`fast` 比 `slow` 先进环，进环后就在圈里转。等 `slow` 也进环后，两者都在圈里跑，由于 `fast` 速度快，**一定会从后面追上 `slow`**（相遇），此时 `slow == fast`，返回 `true`。

### 关键问题：为什么「一定能追上」，不会「跨过去」？

这是快慢指针判环最核心、也最容易卡的点。答案在于**速度差恰好是 1**。

想象 `slow` 和 `fast` 都已经在环里。设环长为 `c`，某一时刻两者在环上的「间距」是 `d`（沿前进方向，`fast` 在 `slow` 前面 `d` 步，`0 <= d < c`）。每走一轮：

- `slow` 前进 1 步，`fast` 前进 2 步；
- 所以**每一轮，`fast` 相对 `slow` 多走 1 步**，即两者间距**每轮缩短 1**（在环里「相对速度」是 1）。

间距从 `d` 一路递减：`d → d-1 → d-2 → … → 0`。**当间距变成 0，两者就重合了（相遇）**。

为什么不会「跨过去」？因为每轮只缩短 1，间距是连续整数地减小，**一定会精确地经过 0**，不会从 1 直接跳到 -1（即不会越过）。这正是「快指针走 2 步、慢指针走 1 步」的妙处：速度差 1 保证相遇精确命中。

如果快指针走 3 步、慢指针走 1 步（速度差 2），间距每轮缩短 2，就可能从 1 跳到 -1（相对位置跨过去了），在某些环长下会永远错开、永不相遇——所以**别贪快，2 步和 1 步是最稳的**。

> 手动推导（示例 1：`3 -> 2 -> 0 -> -4 ->（指回2）`，环 = `2 -> 0 -> -4 -> 2`）：
> ```
> 初始：slow=3, fast=3   （官方把 slow=head, fast=head->next，等价于下文）
>       slow=2, fast=0   （slow 走1到2，fast 走2到0）
>       slow=0, fast=2   （slow 走1到0，fast 走2：0->-4->2）
>       slow=-4, fast=-4 （slow 走1到-4，fast 走2：2->0->-4）→ slow==fast，相遇！返回 true ✓
> ```
> 可以看到 `fast` 每轮比 `slow` 多走 1 步，差距稳步缩小，最终精确重合。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;             // 节点存的值
 *     ListNode *next;      // 指向下一个节点的指针；无环时末节点 next == nullptr；
 *                          //   有环时某节点 next 指回链表中已有的节点形成圈
 *     ListNode(int x) : val(x), next(NULL) {}  // 构造函数：只初始化 val，next 默认空
 * };
 */
class Solution {
public:
    bool hasCycle(ListNode *head) {
        // 边界特判：空链表 或 只有一个节点且不指向自己，必然无环。
        //   - head == nullptr：空链表，没有节点，不可能有环。
        //   - head->next == nullptr：只有一个节点且它的 next 是空，尾巴没接回任何地方，无环。
        //   - 这一判同时也保证下面 fast = head->next 和 fast->next->next 不会解引用空指针。
        //     如果不拦掉单节点无环的情况，进 while 前慢指针在 head、快指针在 nullptr，
        //     虽然循环条件能挡住，但为了清晰官方选择开头先特判。
        if (head == nullptr || head->next == nullptr) {
            return false;
        }

        // ListNode* slow / fast：声明两个「指向 ListNode 的指针」。
        //   - 注意是指针（地址），不是值。后面 slow == fast 比的是「是否指向同一个节点」。
        //   - 官方初始化：slow 在 head，fast 在 head->next（错开一格）。
        //     为什么要错开？因为下面用的是 while(slow != fast)，如果两者都从 head 出发，
        //     一开始 slow==fast 就成立，循环根本进不去。错开一格相当于「先让两者各走一步」，
        //     再开始判断是否相遇。等价写法：两者都从 head 出发 + 用 do-while 循环。
        ListNode* slow = head;
        ListNode* fast = head->next;

        // 循环条件：slow != fast（还没相遇就继续跑）。
        //   - 相遇（slow == fast）：说明快指针绕回来追上了慢指针，有环，退出后返回 true。
        //   - 快指针到头（见循环体内）：无环，退出后返回 false。
        while (slow != fast) {
            // fast 走得快，它先碰到链表尾部。每轮都要检查 fast 和 fast->next 是否为空：
            //   - fast == nullptr：快指针已经走到末尾（当前节点是空）。
            //   - fast->next == nullptr：快指针的下一个是空（fast 站在最后一个节点上，
            //     它一次要走 2 步，但第 2 步踩空了，说明链表有尽头）。
            //   - 这两个条件缺一不可：
            //     * 只判 fast 不判 fast->next：当 fast 站在尾节点时 fast != nullptr，
            //       但 fast->next->next 会解引用 nullptr，崩。
            //     * 只判 fast->next 不判 fast：fast 本身是 nullptr 时 fast->next 直接段错误。
            //   - 一旦发现到头，说明没环，直接返回 false。
            if (fast == nullptr || fast->next == nullptr) {
                return false;
            }

            // 慢指针走 1 步：slow = slow->next。
            //   - slow->next：通过指针访问结构体成员 next（slow 是 ListNode*，用 ->）。
            slow = slow->next;

            // 快指针走 2 步：fast = fast->next->next。
            //   - 上面已经保证 fast 和 fast->next 都非空，所以这里两次解引用安全。
            //   - 走 2 步是关键：让快指针每轮比慢指针多走 1 步，保证有环时一定能精确追上
            //     （速度差为 1，不会跨过；详见思路部分）。
            fast = fast->next->next;
        }

        // 走出 while 说明 slow == fast（相遇），有环。
        return true;
    }
};
```

## 复杂度

- **时间**：O(n)，n 为节点数。
  - 无环时：`fast` 先到尾部，每个节点至多被访问两次（`fast` 跳得快，扫过的节点数 ≤ 2n）。
  - 有环时：`fast` 比 `slow` 每轮多走 1 步，进入环后两者间距每轮缩小 1，初始间距不超过环长（≤ n），至多 n 轮相遇。
- **空间**：O(1)
  - 只用了 `slow`、`fast` 两个指针变量，没有额外数据结构，满足「进阶」的常量内存要求。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么 while 循环条件是 `while (slow != fast)`，而不是 `while (fast)`？

两者侧重点不同：

- `while (fast)`（或 `while (fast && fast->next)`）关注的是「快指针还没到头」——只要没到头就继续跑。这种写法把「是否到头」作为主循环条件，「是否相遇」放进循环体里判断。
- `while (slow != fast)`（本题官方写法）关注的是「快慢还没相遇」——只要没相遇就继续跑。这种写法把「是否相遇」作为主循环条件，「是否到头」放进循环体里判断。

两种写法等价、都对。官方选 `slow != fast` 是因为相遇是本题的核心判定（有环 ↔ 相遇），把它放在主循环条件更直观地表达「跑到相遇为止」。

注意：用 `while (slow != fast)` 时，**初始必须让 `slow` 和 `fast` 错开**（`slow = head, fast = head->next`）。否则两者都从 `head` 出发，循环条件一开始就为假，根本进不去循环，会错误地直接返回 `true`。如果非要让两者都从 `head` 出发，那就得改用 `do-while`，保证循环体至少执行一次。

### Q2：循环体里为什么要同时判 `fast == nullptr` 和 `fast->next == nullptr`？只判一个行不行？

不行，**两个都要判，少一个都会段错误**。

- `fast` 一次要走 2 步（`fast->next->next`）。走这 2 步之前，必须保证「第 1 步踩的节点」和「第 2 步踩的节点」都不是空。
- `fast == nullptr` 检查的是「当前节点」是否为空（对应 `fast->next` 这第 1 步会踩空）。
- `fast->next == nullptr` 检查的是「下一个节点」是否为空（对应 `fast->next->next` 这第 2 步会踩空）。

举例：链表 `1 -> 2 -> nullptr`（无环）。

- 假设只判 `fast == nullptr`：当 `fast` 站在节点 `2` 时，`fast != nullptr` 成立，于是进入 `fast = fast->next->next`，但 `fast->next` 是 `nullptr`，解引用 `nullptr->next` 直接崩。
- 假设只判 `fast->next == nullptr`：当 `fast` 本身已经是 `nullptr` 时，`fast->next` 这一步访问就崩了。

所以两个判空合在一起，才能完整覆盖「快指针走 2 步可能踩空」的所有情况。这是链表题里非常常见的「连判两次」模式，记住**凡是要 `fast->next->next`，前面就得判 `fast && fast->next`**。

### Q3：为什么快指针走 2 步、慢指针走 1 步？让快指针走 3 步、4 步不是更快相遇吗？

**速度差必须是 1**，否则可能永远错开、永不相遇。

有环时，两者都在环里，每轮「相对速度」= 快指针步数 − 慢指针步数。

- 快 2 慢 1：相对速度 1，间距每轮减 1，**一定能精确减到 0**（相遇）。因为间距是整数，从任意正整数每次减 1，必然经过 0。
- 快 3 慢 1：相对速度 2，间距每轮减 2。如果初始间距是偶数，会减到 0（相遇）；但如果初始间距是奇数，会从 1 直接跳到 -1（相对位置跨过去了），**可能永远不相遇**（取决于环长和初始位置，某些配置下快慢指针会无限错开）。

所以「快 2 慢 1」不是随便选的，它是**保证一定相遇的最小速度差配置**。走更多步反而可能失效，得不偿失。

### Q4：空链表和单节点链表怎么办？为什么开头要特判？

- **空链表** `head == nullptr`：没有节点，不可能有环，返回 `false`。
- **单节点** `head` 只有一个节点：如果它的 `next` 指向自己（`head->next == head`），那是环（自环），但这种情况 `head->next != nullptr`，会跳过特判进入正常流程——`slow = head`、`fast = head->next = head`，于是 `slow == fast` 立刻成立，`while` 不进，返回 `true`，正确。如果它的 `next` 是空（不是环），特判 `head->next == nullptr` 命中，返回 `false`，正确。

所以开头的特判 `if (head == nullptr || head->next == nullptr)` 主要挡两类：**空链表** 和 **单节点且不构成自环**。这两类直接返回 `false` 省得后面啰嗦；真正可能成环的情况（包括自环）交给快慢指针正常处理。

**注意**：特判里返回 `false` 看似没区分「自环」，但单节点自环的 `head->next == head` 不等于 `nullptr`，所以特判条件 `head->next == nullptr` 不成立，自环不会被错误拦截，会进 while 正确判出 `true`。

## 复盘

- **核心套路：「快慢指针判环」（Floyd 判圈算法 / 龟兔赛跑）**。凡是「序列里可能有圈/循环/重复」的判断，都可以套这个模式：两个速度不同的指针同向跑，有环必相遇、无环快指针先到头。这是链表题的看家本领之一，和「206 反转链表」「160 相交链表」并列。
- **可迁移场景**：
  - **142 环形链表 II**（找环的入口）：在 141 判出有环后，把一个指针拨回 `head`，两个同速走，再次相遇点就是环入口（数学结论）。
  - **287 寻找重复数**：把数组看成「i → nums[i]」的隐式链表，重复数就是环入口，直接套 Floyd。
  - **202 快乐数**：反复平方求和，「不快乐」的数会陷入循环圈，快慢指针判环。
- **关键记忆点**：
  1. **速度差为 1**（快 2 慢 1），保证相遇精确命中、不会跨过。
  2. **`fast && fast->next` 连判两次**，因为快指针要走 2 步，2 步都可能踩空。
  3. **`while (slow != fast)` 写法要错开起点**（`fast = head->next`），否则进不去循环。
- **判等用指针（地址）不用值**：和 160 相交链表一样，判断「同一个节点」永远靠指针相等，光比 `val` 会把「不同位置的同值节点」误判。本题尤其要警惕——有环的标志是 `next` 指针连成圈，不是值重复。

### 解法二：哈希集合（对比用，非主解）

官方题解「方法一」的写法，思路最直观：遍历链表，把每个走过的节点指针塞进 `unordered_set`，遇到已在集合里的节点就是有环，一路走到 `nullptr` 就是没环。

```cpp
class Solution {
public:
    bool hasCycle(ListNode *head) {
        // unordered_set<ListNode*>：C++ STL 哈希集合，存「指向 ListNode 的指针」。
        //   - 底层是哈希表，插入/查找均摊 O(1)。
        //   - 集合里存的是「地址」，所以判等靠指针相等（正好对应「同一个节点被重复访问」），
        //     不是比 val。这点和题目要求一致。
        //   - 模板参数是 ListNode*（指针类型）。标准库对裸指针有 std::hash 特化，
        //     直接用地址做哈希，无需自定义哈希函数。
        unordered_set<ListNode*> seen;

        // 遍历链表，head 当游标，一路往后走。
        while (head != nullptr) {
            // count(x)：返回集合中等于 x 的元素个数（set 里只能是 0 或 1）。
            //   - 用 count 判「在不在」比 find 解引用更简洁：0 表示不在、1 表示在。
            //   - 等价写法：seen.find(head) != seen.end()。
            if (seen.count(head)) {
                return true;        // 当前节点之前走过 → 绕回来了 → 有环。
            }
            seen.insert(head);      // insert：把当前节点指针塞进集合。
            head = head->next;      // 沿 next 走到下一个节点。
        }
        return false;               // 走到 nullptr 了 → 没环。
    }
};
```

- **时间**：O(n)，每个节点至多访问一次，集合操作均摊 O(1)。
- **空间**：O(n)，集合里最多存全部节点指针。**不满足「进阶」的 O(1) 内存要求**。
- **对比**：比快慢指针好想、好写，第一次做最容易想到。但多用 O(n) 空间，面试或刷 Hot 100 时优先 Floyd 快慢指针；时间紧迫或图稳可用哈希法。两者时间复杂度同级。
