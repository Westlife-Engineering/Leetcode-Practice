## 题目描述

给你两个单链表的头节点 `headA` 和 `headB`，请你找出并返回两个单链表相交的起始节点。如果两个链表不存在相交节点，返回 `null`。

题目数据 **保证** 整个链式结构中不存在环。

**注意**，函数返回结果后，链表必须**保持其原始结构**。

**自定义评测：**

评测系统的输入如下（你设计的程序 **不适用** 此输入）：

- `intersectVal` - 相交的起始节点的值。如果不存在相交节点，这一值为 `0`
- `listA` - 第一个链表
- `listB` - 第二个链表
- `skipA` - 在 `listA` 中（从头节点开始）跳到交叉节点的节点数
- `skipB` - 在 `listB` 中（从头节点开始）跳到交叉节点的节点数

评测系统将根据这些输入创建链式数据结构，并将两个头节点 `headA` 和 `headB` 传递给你的程序。如果程序能够正确返回相交节点，那么你的解决方案将被视作正确答案。

**示例 1：**

```

解释：相交节点的值为 8 （注意，如果两个链表相交则不能为 0）。
从各自的表头开始算起，链表 A 为 [4,1,8,4,5]，链表 B 为 [5,6,1,8,4,5]。
在 A 中，相交节点前有 2 个节点；在 B 中，相交节点前有 3 个节点。
— 请注意相交节点的值不为 1，因为在链表 A 和链表 B 之中值为 1 的节点（A 中第二个节点和 B 中第三个节点）是不同的节点。换句话说，它们在内存中指向两个不同的位置，而链表 A 和链表 B 中值为 8 的节点（A 中第三个节点，B 中第四个节点）在内存中指向相同的位置。
```

**示例 2：**

```
输入：intersectVal = 2, listA = [1,9,1,2,4], listB = [3,2,4], skipA = 3, skipB = 1
输出：Intersected at '2'
解释：相交节点的值为 2 （注意，如果两个链表相交则不能为 0）。
从各自的表头开始算起，链表 A 为 [1,9,1,2,4]，链表 B 为 [3,2,4]。
在 A 中，相交节点前有 3 个节点；在 B 中，相交节点前有 1 个节点。
```

**示例 3：**

```
输入：intersectVal = 0, listA = [2,6,4], listB = [1,5], skipA = 3, skipB = 2
输出：No intersection
解释：从各自的表头开始算起，链表 A 为 [2,6,4]，链表 B 为 [1,5]。
由于这两个链表不相交，所以 intersectVal 必须为 0，而 skipA 和 skipB 可以是任意值。
这两个链表不相交，因此返回 null。
```

**提示：**

- `listA` 中节点数目为 `m`
- `listB` 中节点数目为 `n`
- `1 <= m, n <= 3 * 10^4`
- `1 <= Node.val <= 10^5`
- `0 <= skipA <= m`
- `0 <= skipB <= n`
- 如果 `listA` 和 `listB` 没有交点，`intersectVal` 为 `0`
- 如果 `listA` 和 `listB` 有交点，`intersectVal == listA[skipA] == listB[skipB]`

**进阶：** 你能否设计一个时间复杂度 `O(m + n)`、仅用 `O(1)` 内存的解决方案？

## 思路

> 本题主要参考力扣官方题解的「方法二：双指针」做法。

先厘清「相交」到底指什么。两个单链表如果在某个节点合并、之后共享同一段尾部，那么这个汇合点就是「相交的起始节点」。题目给的关键约束有两条：

1. **相交是「引用相等」而不是「值相等」**——必须是指针指向内存中**同一个 `ListNode` 对象**，而不是「两个不同的节点恰好 `val` 一样」。示例 1 里反复强调「值为 1 的节点是不同的节点（两个内存位置），值为 8 的节点是同一个节点（一个内存位置）」。所以判断相等要用指针 `==`，不能比 `val`。
2. **整个链式结构无环**——这点很重要，它保证了后面双指针来回切换不会死循环。

下面由浅入深看几种做法。

**暴力 O(mn)**：对 `headA` 的每个节点，去 `headB` 里从头扫一遍看有没有**指针相同**的节点。能做对，但 O(m×n)，m、n 都到 3×10^4 时完全不可接受。

**哈希集合 O(m+n) / O(m)**：先用一个集合把 `headA` 的所有节点指针存下来，再遍历 `headB`，遇到的第一个「在集合里」的节点就是交点。时间降到线性，但要 O(m) 额外空间，不满足「进阶」的 O(1) 内存要求。（复盘里有代码。）

**双指针（官方主解，浪漫相遇）—— O(m+n) / O(1)**：核心想法是「**让两个指针走过的总路程相等**，那么它们就一定会在交点同步汇合」。

设：
- `headA` 的「独有前段」长 `a`，`headB` 的「独有前段」长 `b`，两链表「共享后段」长 `c`；
- 于是 `headA` 总长 `m = a + c`，`headB` 总长 `n = b + c`。

让指针 `pA` 从 `headA` 出发，指针 `pB` 从 `headB` 出发，各自一步一步走：

- `pA` 走完 `headA`（`a + c` 步）到达末尾 `nullptr` 时，**转去 `headB` 的头**继续走；
- `pB` 走完 `headB`（`b + c` 步）到达末尾 `nullptr` 时，**转去 `headA` 的头**继续走。

关键观察：

```
pA 的轨迹：headA 的 a 个独有节点 → c 个共享节点 → headB 的 b 个独有节点 → 交点
pB 的轨迹：headB 的 b 个独有节点 → c 个共享节点 → headA 的 a 个独有节点 → 交点
```

两者在到达交点时走过的步数分别是：

```
pA：a + c + b
pB：b + c + a
```

而 **`a + c + b == b + c + a`**（加法交换律），所以两个指针**走的步数完全相同**，又都是一步一走，自然**在同一时刻到达交点**，于是 `pA == pB` 触发退出，返回这个节点。

直观地说：你把 `headA` 走到尽头时换到 `headB` 起点重来，相当于「补」了 `headB` 那段独有前段；`headB` 反之亦然。两条不同长度的路，用「交换跑道」的方式把彼此的长度差**抹平**了。

**如果两链表不相交**呢？此时没有共享段（`c = 0`），`pA` 走 `a + b = m + n` 步、`pB` 走 `b + a = n + m` 步后，两个指针会**同时走到 `nullptr`**，于是 `pA == pB == nullptr`，循环照样退出，返回 `nullptr`。无论相交与否，算法都正确终止。

> 为什么不会无限循环？因为题目保证「整个链式结构无环」。`pA`、`pB` 各自最多把 `headA + headB` 串起来走一遍（`m + n` 步），没有环就不会在中间打转，必定在有限步内退出。

这就是「浪漫相遇」名字的由来：两个指针各自绕了对方一趟，在交点（或终点）重逢。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;         // 节点存的值
 *     ListNode *next;  // 指向下一个节点的指针；末节点的 next == nullptr
 *     ListNode(int x) : val(x), next(NULL) {}  // 构造函数：只初始化 val，next 默认空
 * };
 */
class Solution {
public:
    ListNode *getIntersectionNode(ListNode *headA, ListNode *headB) {
        // 边界：任一链表为空就不可能相交，直接返回 nullptr。
        //   - 后面双指针的「末尾切换」逻辑在 headA 或 headB 为空时无法正常工作，
        //     所以这里先拦掉，保证进入循环时两条链表都非空。
        if (headA == nullptr || headB == nullptr) {
            return nullptr;
        }

        // 两个指针，分别从各自的头节点出发。
        //   - ListNode *pA = headA：声明一个「指向 ListNode 的指针」pA，初始化为 headA。
        //   - 注意是指针（地址）相等，不是 val 相等。题目要求的「相交」就是两个节点是
        //     内存中同一个对象（同一个地址），所以后面 pA == pB 比的是地址。
        ListNode *pA = headA, *pB = headB;

        // 循环条件：pA != pB。
        //   - 相交时：两指针会在交点（同一地址）相遇，pA == pB 成立，退出，返回该节点。
        //   - 不相交时：两指针最终同时走到 nullptr，pA == pB == nullptr 也成立，退出，返回 nullptr。
        //   - 所以循环里不需要区分「相遇在交点」还是「相遇在 nullptr」，退出后直接返回 pA 即可。
        while (pA != pB) {
            // 三目运算符 cond ? A : B：cond 为真取 A，为假取 B。
            //   - pA == nullptr ? headB : pA->next
            //     含义：「pA 还没走到当前链表末尾（非空）」就正常往后走一步（pA->next）；
            //           「pA 已经走到末尾（nullptr）」就跳到另一条链表 headB 的头节点重来。
            //   - pA->next：通过指针访问结构体成员 next。pA 是 ListNode*，
            //     所以用 ->（等价于 (*pA).next）。末节点 next 为 nullptr。
            //   - 这一行的精妙之处：走到 nullptr 时「无缝衔接」到另一条链表，
            //     相当于把 pA 的行走路径接成了 headA→(nullptr)→headB，总长 = a+c+b。
            pA = pA == nullptr ? headB : pA->next;
            // pB 同理：走到末尾就换到 headA 重来，总长 = b+c+a。
            //   - 注意是「互换」：pA 的末尾接 headB，pB 的末尾接 headA。
            //     这样 pA、pB 走过的总步数才能在交点处相等（a+c+b == b+c+a）。
            //     如果两个都接 headA 或都接 headB，就无法抹平长度差。
            pB = pB == nullptr ? headA : pB->next;
        }
        // 退出循环时 pA == pB：要么指向交点节点，要么都是 nullptr。
        return pA;
    }
};
```

## 复杂度

- **时间**：O(m + n)
  - 每个指针最多遍历 `headA + headB` 各一次（`m + n` 步）。相交时实际在交点就停了，更早退出；最坏（不相交）走满 `m + n` 步。
- **空间**：O(1)
  - 只用了 `pA`、`pB` 两个指针变量，没有额外数据结构。满足「进阶」的 O(1) 内存要求。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么不会死循环？指针来回切换难道不会一直转圈吗？

不会，前提是题目保证的「**整个链式结构无环**」。

`pA` 的行走路线是「`headA` 全程 → 切到 `headB` 全程」，`pB` 是「`headB` 全程 → 切到 `headA` 全程」。因为没有任何环，每条链表都是线性走到 `nullptr` 就结束，指针至多把 `headA + headB` 串起来各走一遍，总步数上界是 `m + n`，必定有限步内退出。

如果题目改成「可能有环」，这个写法就会死循环——那时得先用 Floyd 判圈（141 环形链表）处理。本题明确无环，所以安全。

### Q2：如果两个链表不相交，会怎么样？会不会一直找不到相等的点？

会**同时走到 `nullptr`**，然后 `pA == pB == nullptr` 成立，正常退出返回 `nullptr`。

推理：不相交时 `c = 0`，`pA` 走 `a + b = m + n` 步到达 `nullptr`，`pB` 走 `b + a = n + m` 步到达 `nullptr`。步数相同（`m + n == n + m`），速度相同（每轮各走一步），所以**同时**变成 `nullptr`。一旦两者都是 `nullptr`，循环条件 `pA != pB` 立即变假，退出。所以「不相交」不需要任何特判，算法自然处理。

（顺带一提：开头那句 `if (headA == nullptr || headB == nullptr) return nullptr;` 主要挡的是「某条链表一开始就是空」的退化情况——否则 `pA`、`pB` 可能一开始就都是 `nullptr` 或立刻切来切去，虽然结果也对，但官方为了清晰先把空链表单独拦掉。）

### Q3：为什么是「pA 末尾接 headB、pB 末尾接 headA」互换，而不是别的接法？

因为只有**互换**才能让两边走过的步数在交点处相等。

设 `headA` 独有段 `a`、共享段 `c`，`headB` 独有段 `b`、共享段 `c`：

- **互换（本解法）**：`pA` 走 `a + c + b`，`pB` 走 `b + c + a`。由于加法交换律 `a + c + b == b + c + a`，两边步数相等 → 在交点同步相遇。✓
- 如果 `pA` 末尾接 `headA` 自己（原地打转）：`pA` 永远在 `headA` 上转，走不到 `headB` 的独有段，无法抹平 `a` 和 `b` 的长度差，相交时步数不等，错过交点。
- 如果两边末尾都接 `headB`：`pB` 不再补 `headA` 的独有段，两边步数关系被破坏。

一句话：「互换跑道」就是为了**让每个指针都补上对方多出来的那段独有前段**，从而抹平长度差。

### Q4：代码里的 `a`、`b`、`c` 分别是什么？能在脑子里画个图吗？

设交点节点为 `c1`（示例里的那个）：

```
headA: [A1, A2, ..., Aa] → c1 → [共有 c-1 个] → null     （a 个独有 + c 个共有 = m）
headB: [B1, B2, ..., Bb] → c1 ↗                            （b 个独有 + c 个共有 = n）
                                   ↑ 从 c1 起两链表合并成同一条尾巴
```

- `a`：`headA` 在交点之前的独有节点数（示例 1 里 `skipA = 2`，即 `a = 2`）。
- `b`：`headB` 在交点之前的独有节点数（示例 1 里 `skipB = 3`，即 `b = 3`）。
- `c`：从交点 `c1` 到链表末尾的**共享**节点数（两链表合并后同一条尾巴的长度）。

所以 `m = a + c`、`n = b + c`，`pA` 走 `a+c+b`、`pB` 走 `b+c+a`，刚好相等。

## 复盘

- **核心套路：「双指针消除长度差」**。两个序列（链表、数组）要找公共部分，但起点位置/长度不同时，让两个指针**互相走完对方的路程**，就能把长度差抹平，从而在某点同步对齐。本题是这一套路的经典代表；后续「合并两个有序链表」「删除链表倒数第 N 个」等题也会用到「让一前一后/快慢错开」的双指针思想。
- **判「相交/相同」用指针（地址）相等，不用值相等**。链表题里「同一个节点」永远是地址相等；光比 `val` 会把「不同位置的同值节点」误判成交点。这是本题最容易踩的坑（示例 1 专门挖了这个陷阱）。
- **无环是双指针来回切换成立的前提**。看到「无环」保证时，可以放心让指针在多条链表间切换而不用担心死循环；如果题目可能带环，得先判圈。
- **O(1) 空间链表题的常用手段**：双指针（快慢、前后、互换跑道）、复用节点自身的 `next`/`val` 字段存信息（如 287 寻找重复数）。能用指针搞定就别开容器。

### 解法二：哈希集合（对比用，非主解）

官方题解「方法一」的写法，思路直白：把 `headA` 的所有节点指针塞进 `unordered_set`，再遍历 `headB`，第一个能在集合里查到的节点就是交点。

```cpp
class Solution {
public:
    ListNode *getIntersectionNode(ListNode *headA, ListNode *headB) {
        // unordered_set<ListNode*>：C++ STL 哈希集合，存「指向 ListNode 的指针」。
        //   - 底层是哈希表，插入/查找均摊 O(1)。
        //   - 集合里存的是「地址」，所以判等靠指针相等（正好对应「同一个节点」），
        //     不是比 val。这点和题目要求一致。
        //   - 注意：模板参数是 ListNode*（指针类型）。标准库对裸指针有 std::hash 特化，
        //     直接用地址做哈希，无需自定义哈希函数。
        unordered_set<ListNode *> visited;

        // 第一趟：遍历 headA，把每个节点指针都加入集合。
        ListNode *temp = headA;
        while (temp != nullptr) {
            visited.insert(temp);   // insert：把元素塞进集合，已存在则忽略。
            temp = temp->next;      // 沿 next 走到下一个节点。
        }

        // 第二趟：遍历 headB，找第一个已在集合里的节点。
        temp = headB;
        while (temp != nullptr) {
            // count(x)：返回集合中等于 x 的元素个数（set 里只能是 0 或 1）。
            //   - 用 count 判「在不在」比 find 解引用更简洁：count 返回 size_t，
            //     0 表示不在、1 表示在，直接当布尔条件用。
            //   - 等价写法：visited.find(temp) != visited.end()。
            if (visited.count(temp)) {
                return temp;        // headB 中第一个出现在 headA 集合里的节点 = 交点。
            }
            temp = temp->next;
        }
        return nullptr;             // headB 全程都没命中 → 不相交。
    }
};
```

- **时间**：O(m + n)，遍历 `headA` 和 `headB` 各一次，集合操作均摊 O(1)。
- **空间**：O(m)，集合里存了 `headA` 的全部节点指针。
- **对比**：比双指针好想、好写，但多用了 O(m) 空间，不满足「进阶」的 O(1) 内存。面试或刷 Hot 100 时优先双指针；时间紧迫或图稳可用哈希法。两者时间复杂度同级。
