# 24 两两交换链表中的节点

- 难度：中等
- 标签：**递归**、**链表**
- 力扣链接：https://leetcode.cn/problems/swap-nodes-in-pairs/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考力扣官方题解「两两交换链表中的节点」（slug：`liang-liang-jiao-huan-lian-biao-zhong-de-jie-di-91`）。正文主解是 **迭代法（哑节点 + temp/node1/node2 三指针逐对交换）**，时间 O(n)、空间 O(1)，是链表局部交换题的标准写法；官方「方法一：递归」放在「复盘」章节作对比。

## 题目描述

给你一个链表，两两交换其中相邻的节点，并返回交换后链表的头节点。你必须在不修改节点内部的值的情况下完成本题（即，只能进行节点交换）。

**示例 1：**

```
输入：head = [1,2,3,4]
输出：[2,1,4,3]
```

**示例 2：**

```
输入：head = []
输出：[]
```

**示例 3：**

```
输入：head = [1]
输出：[1]
```

**提示：**

- 链表中节点的数目在范围 `[0, 100]` 内
- `0 <= Node.val <= 100`

> 注意题目一句话：「**在不修改节点内部的值的情况下完成本题（即，只能进行节点交换）**」。这是故意强调不能走捷径——见思路里的「为什么不能只交换 val」。

## 思路

> 本题主要参考力扣官方题解的「方法二：迭代」。

### 「两两交换」到底是交换什么？

题意很直白：从链表头开始，**每两个相邻节点为一组，把它们颠倒顺序**，第三第四个也颠倒，依此类推。

- `1 -> 2 -> 3 -> 4` 变成 `2 -> 1 -> 4 -> 3`（1↔2 交换、3↔4 交换）
- `1 -> 2 -> 3 -> 4 -> 5` 变成 `2 -> 1 -> 4 -> 3 -> 5`（5 落单，不动）

### 为什么不能只交换 `val`？（题目明确禁止）

一个偷懒的念头：链表形状不动，只把相邻两个节点的 `val` 字段互换，不就达到「效果上交换」了吗？比如 `1 -> 2` 把 1、2 的值对调，看起来就是 `2 -> 1`。

**题目直接堵死了这条路**：「必须在不修改节点内部的值的情况下完成本题」。原因有两个：

1. 题目想考的是**指针操作**本身，交换 val 规避了难点，失去练习意义。
2. 真实场景里节点的「值」往往不是简单 int，可能挂着大对象、外部引用、唯一 ID，换值会破坏节点身份；只有真正搬动节点（改 `next` 指针）才是安全的。

所以必须**改指针、动结构**，下文所有操作都是改 `next`。

### 为什么需要哑节点 `dummyHead`？

回想 206 反转链表、21 合并有序链表，哑节点是用来消除「头节点特判」的。本题对哑节点的依赖**更强**：

看示例 1，交换后链表头从 `1` 变成了 `2`——**头节点本身就是被交换的对象**。如果不加哑节点，第一对节点的交换就得单独写一段（因为新头要从第二个节点里挑，而且它没有「前驱」可以挂）。后续每一对都有「前驱」，唯独第一对没有，这种不一致会逼你写两套逻辑。

加了哑节点 `dummyHead`（令 `dummyHead->next = head`）之后，**每一对节点都有一个前驱**，第一对的前驱就是 `dummyHead`。所有交换操作完全统一，不用任何特判。最后返回 `dummyHead->next` 就是新头。

> 口诀：**只要「头节点会被改掉 / 不知道新头是谁」，就开哑节点**。这是链表题最稳的套路。

### 逐对交换的指针操作：temp / node1 / node2 三指针

设当前已经走到某个位置 `temp`，它后面**两个待交换的节点**分别叫 `node1`、`node2`：

```
交换前：temp -> node1 -> node2 -> (剩下)
交换后：temp -> node2 -> node1 -> (剩下)
```

我们要把 `temp` 后面这段形状重排。注意**只动这三根指针**（`temp->next`、`node1->next`、`node2->next`），其余节点不动。

### 三步指针赋值完成交换（官方推荐顺序）

官方给出的三步是：

```
temp->next = node2;       // 第 1 步：temp 直接跳过 node1，指向 node2
node1->next = node2->next;// 第 2 步：node1 接到 node2 原来的下一个
node2->next = node1;      // 第 3 步：node2 反过来指向 node1
```

为什么是这个顺序？关键是**第 1 步必须最先做**：因为在改 `temp->next` 之前，`node2->next` 还指向原来的下一个节点（这是「剩下」那段的入口），第 2 步 `node1->next = node2->next` 才能把 node1 正确接到「剩下」段的开头。一旦先改了别的指针把 `node2->next` 覆盖掉，就找不到「剩下」段了。

交换完一对，令 `temp = node1`（node1 是交换后这对里的后一个，也就是下一对的前驱），继续处理下一对。

### 手动推导 `1 -> 2 -> 3 -> 4` 交换成 `2 -> 1 -> 4 -> 3` 的过程

```
初始  dummyHead -> 1 -> 2 -> 3 -> 4 -> nullptr
      temp=dummyHead

第1轮  temp=dummyHead, node1=1, node2=2
      第1步  temp->next = node2     dummyHead -> 2      （dummy 直接指 2）
      第2步  node1->next = node2->next   1 -> 3         （1 接到「剩下」段开头）
      第3步  node2->next = node1   2 -> 1               （2 反过来指 1）
      此时：dummyHead -> 2 -> 1 -> 3 -> 4 -> nullptr
      temp = node1 = 1     （推进到下一对的前驱）

第2轮  temp=1, node1=3, node2=4
      第1步  temp->next = node2     1 -> 4
      第2步  node1->next = node2->next   3 -> nullptr   （3 接到「剩下」段，即空）
      第3步  node2->next = node1   4 -> 3
      此时：dummyHead -> 2 -> 1 -> 4 -> 3 -> nullptr
      temp = node1 = 3     （推进）

循环检查：temp->next 是 nullptr，不满足「后面还有一对」，退出循环。

返回 dummyHead->next，即 2 -> 1 -> 4 -> 3 -> nullptr  ✓
```

可以看到每一轮只碰「temp + 它后面两个节点」三根指针的指向，其余节点纹丝不动，这就是「局部交换」。

## 代码

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;             // 节点存的值
 *     ListNode *next;      // 指向下一个节点的指针；最后一个节点的 next == nullptr
 *     ListNode() : val(0), next(nullptr) {}                       // 默认构造
 *     ListNode(int x) : val(x), next(nullptr) {}                  // 只给值的构造
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}     // 全参数构造
 * };
 */
class Solution {
public:
    ListNode* swapPairs(ListNode* head) {
        // 哑节点 dummyHead：在真正结果链表前面「虚构」一个假头，令它的 next 指向 head。
        //   - 作用：本题头节点本身会被交换，新链表头是原来的第二个节点。
        //     没有哑节点时第一对节点没有「前驱」，得单独写一段逻辑；
        //     有了 dummyHead，每一对都有统一的前驱（第一对的前驱就是 dummyHead），
        //     所有交换操作完全一致，零特判。
        //   - 值填 0 占位，不参与任何判断（节点值范围是 0~100，这里填什么都不影响，
        //     因为代码里从不读 dummyHead->val）。
        //   - 必须 new 在堆上：栈对象函数返回即销毁，会变野指针。
        ListNode* dummyHead = new ListNode(0);
        dummyHead->next = head;

        // temp：当前「走到的位置」，也是「下一对待交换节点的前驱」。
        //   - 初始指向 dummyHead，从假头开始往后一对一对地处理。
        //   - 每处理完一对，temp 推进到 node1（交换后这对里的后一个），成为下一对的前驱。
        ListNode* temp = dummyHead;

        // while 条件：temp 后面「至少还有两个节点」才值得交换。
        //   - temp->next != nullptr：后面至少有一个节点（node1 存在）。
        //   - temp->next->next != nullptr：后面至少有两个节点（node2 存在）。
        //   - 两个条件缺一不可，且必须用 && 短路求值：先判 temp->next 非空，
        //     才能安全地访问 temp->next->next，否则解引用空指针直接崩。
        //   - 奇数个节点时，最后一个落单节点不满足此条件，自动跳过、保持原位。
        while (temp->next != nullptr && temp->next->next != nullptr) {
            // node1 / node2：记录待交换的两个节点。
            //   - 必须在改指针之前先把它们「揪出来」存好，
            //     后面 temp->next 被改掉之后就只能靠这两个变量找到原节点了。
            ListNode* node1 = temp->next;
            ListNode* node2 = temp->next->next;

            // 三步指针赋值完成 node1 / node2 的交换。
            // 交换前：temp -> node1 -> node2 -> (剩下)
            // 交换后：temp -> node2 -> node1 -> (剩下)

            temp->next = node2;        // 第 1 步：temp 跳过 node1，直接指向 node2。
                                       //   - 必须最先做！此时 node2->next 还指向「剩下」段，
                                       //     第 2 步要用到这个信息，所以不能先动 node2->next。

            node1->next = node2->next; // 第 2 步：node1 接到「剩下」段的开头。
                                       //   - node2->next 是「剩下」段的入口，把它交给 node1。
                                       //   - 这一步必须在「第 3 步改 node2->next 之前」完成，
                                       //     否则 node2->next 已被覆盖成 node1，就丢了「剩下」段。

            node2->next = node1;       // 第 3 步：node2 反过来指向 node1，完成这对的颠倒。

            // temp 推进：node1 是交换后「这对里的后一个」，正是下一对的前驱。
            //   - 注意推进的是 node1 不是 node2：交换后顺序是 node2 在前、node1 在后，
            //     下一对在 node1 后面，所以前驱是 node1。
            temp = node1;
        }

        // 新链表头是 dummyHead->next（原来的第二个节点），先存下来。
        ListNode* ans = dummyHead->next;
        // 释放哑节点：官方写法，避免内存泄漏。
        //   - 必须先 ans = dummyHead->next 把真正头节点记下来，再 delete dummyHead，
        //     不能先 delete 再去读 dummyHead->next（那是 use-after-free）。
        //   - 力扣判题环境其实不在乎这点泄漏，工程代码里养成释放习惯更好。
        delete dummyHead;
        return ans;
    }
};
```

## 复杂度

- **时间**：O(n)
  - `temp` 从 `dummyHead` 出发，每轮循环往后推进两个节点（`temp = node1`，而 node1 距原 temp 隔了两个位置），整条链表最多被扫一遍。节点数为 n 时循环约 n/2 次，每次 O(1)，总计 O(n)。
- **空间**：O(1)
  - 只用了 `dummyHead` / `temp` / `node1` / `node2` / `ans` 这几个指针变量（哑节点本身只占 1 个节点的常数空间），没有新建链表、没有递归栈。这是迭代法相比递归法的最大优势。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么不能只交换 `val`，那样不是更简单吗？

题目**明确禁止**这么干：「必须在不修改节点内部的值的情况下完成本题（即，只能进行节点交换）」。

退一步说，即使题目不禁止，生产代码里也不该这么写。原因：

- 节点的「值」往往不是孤立数据，可能绑着外部引用、唯一 ID、大对象，换值会污染这些绑定关系；而换节点（改 `next`）保持了节点身份不变。
- 这道题的训练目的就是**练指针操作**，换 val 规避了全部难点，等于白做。

所以必须老老实实改 `next` 指针、动链表结构。

### Q2：三步指针赋值的顺序能换吗？为什么 `temp->next = node2` 必须最先做？

顺序**不能随便换**。关键是「不要在用完某个旧指针值之前就把它覆盖掉」。

看这三步分别用了哪些「旧值」：

```
第1步  temp->next = node2         ——只读 node2（指针变量本身），没读链上的旧字段，安全。
第2步  node1->next = node2->next  ——读了 node2->next 的「旧值」（指向「剩下」段）。
第3步  node2->next = node1        ——把 node2->next 覆盖成 node1。
```

**第 2 步依赖 `node2->next` 的旧值，而第 3 步会覆盖它**。所以第 2 步必须在第 3 步之前。第 1 步改的是 `temp->next`，只要在「读 `temp->next` 来定位 node2」之后就行，所以放最前面没问题。

口诀：**先读后写，谁被覆盖谁先被用**。在草稿上画一遍 `temp -> node1 -> node2 -> 剩下` 的方框图，标出每步改哪根、依赖哪根，顺序就一目了然了。

### Q3：while 条件 `temp->next != nullptr && temp->next->next != nullptr` 为什么两个都要写？少一个行不行？

两个都不能少，分别防两种崩/错：

- **少了第一个** `temp->next != nullptr`：直接访问 `temp->next->next` 可能解引用 `nullptr`（当 temp 是最后一个节点时），程序崩。而且 C++ 的 `&&` 是短路求值，必须先确认 `temp->next` 非空，才能安全读它的 `next`。
- **少了第二个** `temp->next->next != nullptr`：当 temp 后面只剩一个节点（奇数个链表的最后一个）时，`node2 = temp->next->next` 是 `nullptr`，后续 `node2->next = node1` 直接解引用空指针崩。

两个条件合起来表达「temp 后面**至少有两个节点**」，这才是「值得交换一对」的前提。奇数链表最后一个落单节点不满足条件，循环自然退出，它就留在原地——正好符合题意。

### Q4：奇数个节点时，最后一个节点怎么办？

**不用管，它自己留在原位**。

比如 `1 -> 2 -> 3 -> 4 -> 5`：前两轮处理完 `1↔2`、`3↔4`，此时 `temp` 推进到节点 3（交换后第二对的末尾）。检查 while 条件：`temp->next` 是节点 5（非空），但 `temp->next->next` 是 `nullptr`——只剩一个节点，不满足条件，循环退出。节点 5 保持原样，接在节点 4 后面，最终结果 `2 -> 1 -> 4 -> 3 -> 5`，正确。

所以 while 的双条件天然处理了「奇数尾巴」，不用单独写分支。这也是迭代法写起来干净的原因之一。

## 复盘

- **核心套路**：**「哑节点 + 链表局部交换」** 是一类非常通用的模式。凡是题目要求「按某种规则改写链表结构、且头节点可能被换掉」时，套路都是：开哑节点统一头部 → 用一个游走指针 `temp` 逐段推进 → 每段做固定的指针重排 → 返回 `dummyHead->next`。后续的「K 个一组翻转链表」(25) 是本题的强化版（一组 K 个而非固定 2 个），「反转链表 II」(92) 也是同一类局部改写，把本题的三步指针赋值练熟，这两道就只剩「分组条件」要处理了。
- **三指针协作口诀**（本题专属）：
  1. **先揪 node1/node2**（改指针前先把待交换节点记牢，否则 `temp->next` 一改就丢了）。
  2. **三步赋值有顺序**（`temp->next = node2` → `node1->next = node2->next` → `node2->next = node1`，被覆盖的字段先被用）。
  3. **temp 推进到 node1**（交换后这对里的后一个，才是下一对的前驱）。
  4. **while 双条件**（`temp->next` 和 `temp->next->next` 都非空，保证后面至少两个节点）。
- **不变式思维**：循环每一步，`temp` 始终指向「已处理段的末尾」+「下一对的前驱」，`temp` 之后的节点都还没动过。维护好这个不变式，循环结束时整条链就按对交换好了。
- **哑节点是链表题的万能起手**：206 反转、21 合并、19 删倒数第 N、24 本题、25 K 个一组翻转，全部用哑节点消除头节点特判。看到链表题先想「要不要开 dummy」，几乎不会错。
- **迭代 vs 递归**：迭代法 O(1) 空间、写法固定、不会栈溢出，是首选；递归法代码更短、思路更巧妙，但 O(n) 栈空间，链表很长（本题节点数 ≤ 100 还好，但如果是几千节点）有栈溢出风险。见下面解法二。

### 解法二：递归法（对比用，非主解）

官方「方法一」。思路是**把两两交换递归定义**：链表头两个节点交换后，第二个节点变成新头，第一个节点接到「剩余链表递归交换后的结果」上。

具体说，`swapPairs(head)`：

- 递归基：`head` 为空（空链表）或 `head->next` 为空（只剩一个节点），没法成对交换，直接返回 `head`。
- 否则记 `newHead = head->next`（第二个节点，交换后它当新头）。然后：
  - `head->next = swapPairs(newHead->next)`：原头节点接到「剩余链表（从第三个节点开始）交换后的结果」上。注意 `newHead->next` 就是原来的第三个节点（交换前 `head -> newHead -> newHead->next`）。
  - `newHead->next = head`：新头反过来指向原头，完成这对的颠倒。
  - 返回 `newHead`。

```cpp
class Solution {
public:
    ListNode* swapPairs(ListNode* head) {
        // 递归基：空链表或只剩一个节点，无法成对交换，原样返回。
        //   - !head 覆盖空链表（示例 2）。
        //   - !head->next 覆盖单节点（示例 3）和奇数链表的最后一个落单节点。
        if (head == nullptr || head->next == nullptr) {
            return head;
        }
        // newHead：原链表第二个节点，交换后它变成这一对的新头。
        ListNode* newHead = head->next;
        // 原头节点 head 接到「剩余链表递归交换后的结果」上。
        //   - newHead->next 是原来的第三个节点（交换前 head -> newHead -> newHead->next）。
        //   - 从它开始的剩余链表交给 swapPairs 递归处理。
        head->next = swapPairs(newHead->next);
        // 新头 newHead 反过来指向原头 head，完成这对颠倒。
        newHead->next = head;
        // newHead 始终是这对的新头（也是整条链递归回来后的头），返回它。
        return newHead;
    }
};
```

- **时间**：O(n)，递归遍历每个节点一次（每层处理两个节点）。
- **空间**：O(n)，递归深度等于链表对数，约 n/2 层，系统调用栈要开 O(n)。**这是递归法相比迭代法的主要劣势**。
- **对比**：递归法代码最短、思路最巧妙（直接把「两两交换」的定义翻译成代码），不用写哑节点和指针三步赋值；但空间开销大、且对新手「先递归后面再接上」的脑回路比较绕。链表短（本题 ≤ 100）时两种都安全，面试/工程里优先迭代法。
