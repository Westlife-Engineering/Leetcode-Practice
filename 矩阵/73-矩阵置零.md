# 73 矩阵置零

- 难度：中等
- 标签：**数组**、哈希表、**矩阵**
- 力扣链接：https://leetcode.cn/problems/set-matrix-zeroes/?envType=study-plan-v2&envId=top-100-liked

> 说明：本题参考[力扣官方题解](https://leetcode.cn/problems/set-matrix-zeroes/solution/ju-zhen-zhi-ling-by-leetcode-solution-9ll7/)的三种做法。正文主解是 **方法三：使用一个标记变量（O(1) 空间）**——用矩阵的第一行、第一列自身当「标记数组」，再额外用一个 `bool` 标记第一列是否原本含 0。「两标记数组（O(m+n) 空间）」见文末「复盘」作思路铺垫。

## 题目描述

给定一个 *m* x *n* 的矩阵，如果一个元素为 0 ，则将其所在行和列的所有元素都设为 0 。请使用 **原地** 算法。

**示例 1：**

```
输入：matrix = [[1,1,1],[1,0,1],[1,1,1]]
输出：[[1,0,1],[0,0,0],[1,0,1]]
```

**示例 2：**

```
输入：matrix = [[0,1,2,0],[3,4,5,2],[1,3,1,5]]
输出：[[0,0,0,0],[0,4,5,0],[0,3,1,0]]
```

**提示：**

- `m == matrix.length`
- `n == matrix[0].length`
- `1 <= m, n <= 200`
- `-2^31 <= matrix[i][j] <= 2^31 - 1`

**进阶：**

- 一个直观的解决方案是使用  O(*mn*)  的额外空间，但这并不是一个好的解决方案。
- 一个简单的改进方案是使用 O(*m* + *n*) 的额外空间，但这仍然不是最好的解决方案。
- 你能想出一个仅使用常量空间的解决方案吗？

## 思路

> 本题参考力扣官方「方法三：使用一个标记变量」。

### 关键陷阱：为什么不能边扫边置零？

最容易踩的坑：看到 `(i,j)` 是 0，立刻把第 `i` 行和第 `j` 列全刷成 0。这样会把**后来才扫到的格子也刷成 0**，而这些 0 是「我们制造的」，不是「输入里的 0」，扫到它们时又会把更多行列刷成 0——很快整张矩阵变成全 0。

所以必须先把「哪些行、哪些列要置零」**记下来**，等扫描结束后，再根据记录去刷。问题就变成：**记录用的额外空间能压到多小？**

### 朴素做法：两个标记数组（O(m+n) 空间）

开 `row[m]`、`col[n]` 两个 bool 数组。扫一遍，遇到 `matrix[i][j]==0` 就置 `row[i]=true, col[j]=true`；再扫一遍，凡 `row[i]||col[j]` 为真的格子就刷成 0。这是进阶里说的「O(m+n) 空间」解，代码见「复盘」。正确性最直观，但要 O(m+n) 额外空间。

### 用第一行第一列当标记数组（O(1) 空间）

观察：标记数组 `row[]`、`col[]` 每个元素只占一个 bool，而矩阵**本身就有一行一列**可以借来存这些 bool：

- 用 `matrix[0][j]`（第一行）记录 **第 `j` 列** 是否要置零；
- 用 `matrix[i][0]`（第一列）记录 **第 `i` 行** 是否要置零。

这样 `row[]` 和 `col[]` 就「内嵌」进矩阵里了，额外空间省到 O(1)。

但有两个细节要单独处理：

1. **第一行、第一列本身要不要置零？** 它们被借去当标记后，自身的原始 0 信息会被覆盖，需要先用独立变量记下来。
2. **`matrix[0][0]` 一个格子要同时承担「标记第一行」和「标记第一列」两种含义，会冲突。** 必须拆分职责。

### 第一列单独用一个变量标记（方法三的核心）

官方方法二的写法是开**两个**变量 `flag_row0`、`flag_col0` 分别记第一行、第一列自身是否含 0。方法三进一步把它压成**一个**变量：

- 令 `matrix[0][0]` 这个格子专职标记 **第一行** 是否含 0；
- 另开一个 `bool flag_col0` 专门记 **第一列** 是否含 0（因为 `matrix[0][0]` 已被第一行占用，不能再来标记第一列）。

整个流程（与官方方法三一致）：

1. **扫描 + 打标记**（一遍）：从上到下逐行扫。
   - 对每一行 `i`：先看 `matrix[i][0]`，若为 0 则 `flag_col0 = true`（第一列自身有 0）。
   - 再从 `j=1` 扫到 `n-1`：若 `matrix[i][j]==0`，就把标记写到第一行第一列——`matrix[i][0]=0`（标记第 i 行）、`matrix[0][j]=0`（标记第 j 列）。
2. **根据标记回填**（从最后一行倒序往上）：对每一行 `i`（从 `m-1` 到 `0`），从 `j=1` 到 `n-1`：若 `matrix[i][0]==0 || matrix[0][j]==0`，则 `matrix[i][j]=0`。回填完内部格子后，再按 `flag_col0` 决定 `matrix[i][0]` 是否刷 0。

### 为什么回填要「从最后一行倒序」？

这是方法三最容易写错的地方。原因：`matrix[0][j]` 是**标记第 j 列**用的，它**自己**也属于「需要被标记决定是否置零」的第一行。如果先处理第 0 行，把 `matrix[0][j]` 提前刷成 0，后面别的行就分不清「这个 0 是原本的标记」还是「被刷出来的」，所有列都会被错误置零。

倒序（从下往上）的好处：**处理完所有内部格子后，最后才轮到第 0 行**。每行内部又是「先用 `matrix[0][j]` 的值判断，再用 `flag_col0` 决定第一列格子的命运」，不会把标记位提前毁掉。所以扫描顺序不能乱。

### 手动推导一个例子

`matrix = [[1,1,1],[1,0,1],[1,1,1]]`（示例 1）：

```
步骤 1：扫描打标记
i=0: matrix[0][0]=1，flag_col0 不动；j=1,2 扫描无 0 → 不写标记
i=1: matrix[1][0]=1，flag_col0 不动；j=1 时 matrix[1][1]=0 → matrix[1][0]=0, matrix[0][1]=0
i=2: matrix[2][0]=1，flag_col0 不动；j=1,2 扫描无 0 → 不写标记

此时矩阵（注意首行首列已是标记）：
 1  0  1      ← matrix[0][1]=0 是「标记第1列要置零」
 0  0  1      ← matrix[1][0]=0 是「标记第1行要置零」
 1  1  1
flag_col0 = false

步骤 2：倒序回填
i=2: j=1 → matrix[2][0]=1 但 matrix[0][1]=0 → matrix[2][1]=0
     j=2 → matrix[2][0]||matrix[0][2] 都非零 → 不动
     flag_col0=false → matrix[2][0] 不刷
i=1: j=1 → matrix[1][0]=0 → matrix[1][1]=0
     j=2 → matrix[1][0]=0 → matrix[1][2]=0
     flag_col0=false → matrix[1][0] 不刷（但本来就是 0）
i=0: j=1 → matrix[0][0]||matrix[0][1]=0 → matrix[0][1]=0（已经是0）
     j=2 → 都非零 → 不动
     flag_col0=false → matrix[0][0] 不刷

结果：[[1,0,1],[0,0,0],[1,0,1]] ✓
```

## 代码

```cpp
class Solution {
public:
    // void 返回：原地修改 matrix，不返回新矩阵。
    // vector<vector<int>>&：二维动态数组的引用（外层是行、内层是列）。
    //   传引用避免拷贝整张矩阵；方法内部直接改调用方传入的那份。
    void setZeroes(vector<vector<int>>& matrix) {
        // size()：vector 元素个数；二维矩阵的 size() 是行数 m。
        int m = (int)matrix.size();
        // matrix[0].size()：第 0 行的列数 n（题目保证每行列数相同）。
        int n = (int)matrix[0].size();

        // flag_col0：唯一一个额外标记变量，记录「第一列自身原本是否含 0」。
        //   为什么只标记第一列？因为 matrix[0][0] 已被借去标记「第一行」，
        //   没法再兼任「第一列」，所以第一列的状态只能用独立变量存。
        bool flag_col0 = false;

        // —— 第一遍：从上往下逐行扫描，把标记写到第一行、第一列 ——
        for (int i = 0; i < m; i++) {
            // 先看第 i 行第 0 列：若是 0，则第一列自身含 0，记到 flag_col0。
            //   注意这是「读原始数据」，必须在写标记之前完成。
            if (!matrix[i][0]) {           // !x 等价于 x==0（对 int）
                flag_col0 = true;
            }
            // j 从 1 开始：第 0 列单独由 flag_col0 管，不重复处理。
            for (int j = 1; j < n; j++) {
                if (!matrix[i][j]) {
                    // matrix[i][0]=0：用「第 i 行第 0 列」标记「第 i 行要置零」
                    // matrix[0][j]=0：用「第 0 行第 j 列」标记「第 j 列要置零」
                    //   即把首行/首列当成 row[]/col[] 标记数组来用。
                    matrix[i][0] = matrix[0][j] = 0;
                }
            }
        }

        // —— 第二遍：根据标记回填内部格子，必须倒序（从最后一行往上）——
        // 倒序的原因：matrix[0][j] 既是「第 j 列的标记」又属于「第一行」，
        //   若先处理第 0 行会把这些标记提前刷成 0，污染后续判断。
        for (int i = m - 1; i >= 0; i--) {
            // j 仍从 1 开始：第 0 列由下面的 flag_col0 单独处理。
            for (int j = 1; j < n; j++) {
                // 若「第 i 行有标记」或「第 j 列有标记」任一成立 → 这个格子置零。
                if (!matrix[i][0] || !matrix[0][j]) {
                    matrix[i][j] = 0;
                }
            }
            // 内部格子回填完，再处理这一行的第 0 列（第一列自身）。
            //   必须放在内部格子之后：matrix[i][0] 是「第 i 行的标记」，
            //   若先把它刷成 0，上面 j 循环里 !matrix[i][0] 会恒真、把整行误刷。
            if (flag_col0) {
                matrix[i][0] = 0;
            }
        }
    }
};
```

## 复杂度

- **时间**：O(m×n)。两个嵌套循环各扫一遍矩阵，每格 O(1)，合计至多遍历矩阵两次。
- **空间**：O(1)。只额外用了 `flag_col0` 一个 bool 变量；标记信息全存在矩阵首行首列自身里。

## 疑惑 / 卡点

> 这块记录做题时和 AI 的问答，方便以后回顾。随做题提问持续更新。

### Q1：为什么不能边扫边把行列刷成 0？

因为刷出来的 0 是「我们制造的」，会被后面的扫描误判为「输入里的 0」。比如 `matrix[0][0]=0` 时立刻把第一行第一列全刷成 0，扫到刚刷成 0 的 `(1,0)` 时又会把第 1 行、第 0 列全刷成 0……连锁反应下整张矩阵很快全 0。**正确做法是先记录、再统一刷**：扫一遍只写标记，第二遍才据标记置零，这样置零动作不会再被当成输入。

### Q2：为什么第一列要用单独的变量 `flag_col0` 标记，第一行却不用？

因为 `matrix[0][0]` 这个格子被借去当标记位了，它只能承担一种含义。官方方法三让 `matrix[0][0]` 专职标记**第一行**是否含 0（第一行自身的标记就存在第一行里），那么**第一列**就没格子可记了——第一列上方的 `matrix[0][0]` 已经被第一行占用。所以第一列的状态只能另开一个变量 `flag_col0` 存。

对比官方方法二（见「复盘」思路）开了**两个**变量 `flag_row0`、`flag_col0`，分别记第一行、第一列，代价是比方法三多一个变量。方法三是把「记第一行」这件事也塞回了 `matrix[0][0]`，省到只剩一个变量。

### Q3：回填时扫描顺序（正序 vs 倒序）真的有影响吗？

**有，而且方法三必须倒序**。关键在于 `matrix[0][j]` 身兼两职：既是「第 j 列的标记」，本身又属于「第一行」。若正序（先 `i=0`）回填，处理第 0 行时会按标记把某些 `matrix[0][j]` 刷成 0，但这些 0 是「刷出来的」，不是原始标记；后面别的行 `i>0` 读 `matrix[0][j]` 时会把它们当成「第 j 列要置零」的真标记，于是**不该置零的列也被错误刷成 0**。倒序让第 0 行最后处理，其它行读到的 `matrix[0][j]` 都还是干净的原始标记，不会污染。

同理，每一行内部也要「先回填 `j>=1` 的内部格子，最后才动 `matrix[i][0]`」，否则把行标记位提前刷成 0 会误刷整行。

### Q4：`matrix[i][0] = matrix[0][j] = 0;` 这种连等号写法合法吗？要注意什么？

合法。C++ 里赋值运算符 `=` 是**右结合**且**返回左侧对象的引用**，所以 `a = b = 0;` 等价于 `a = (b = 0);`：先把 0 赋给 `b`，`b=0` 这个子表达式的值是 `b` 赋值后的值（0），再赋给 `a`。两个 int 都会被置 0。对 `int` 这种内置类型完全没问题；对**自定义类型**（重载了 `operator=`）要注意返回的是引用还是值，但本题不涉及。属于简洁但用得不多的小技巧，嫌不直观分开写两行也行。

## 复盘

### 可迁移套路

- **「用原数组自身当标记 / 就地存储」**：当题目要求 O(1) 额外空间、又需要记录一组布尔状态时，先看看**输入数组里有没有空闲格子**可以借。本题借了首行首列；类似的经典题有：
  - `41. 缺失的第一个正数`：用数组下标 + 正负号标记「数字 k 是否出现过」；
  - `287. 寻找重复数`：用「把值当索引、标负」来就地记录访问。
- **「标记位被借用 → 用独立变量补回被覆盖的信息」**：本题第一列的信息被标记覆盖了，所以先用 `flag_col0` 读出来。凡是「就地存标记」都要警惕「被借用的格子原本的信息怎么办」。
- **「读取顺序避免自污染」**：就地存储的标记位同时也是数据，回填顺序（倒序 / 分阶段）必须保证「读标记」阶段不被「写数据」破坏。

### 解法二：两个标记数组（官方方法一，O(m+n) 空间）

最直观的做法。开 `row[m]`、`col[n]` 两个 bool 数组分别记「哪些行、哪些列含 0」，扫两遍即可。额外空间 O(m+n)，作为「进阶」里提到的「简单改进方案」，是理解 O(1) 思路（首行首列当标记数组）的跳板。

```cpp
class Solution {
public:
    void setZeroes(vector<vector<int>>& matrix) {
        int m = (int)matrix.size();
        int n = (int)matrix[0].size();
        // vector<int> row(m)：长度 m、初值 0 的 int 数组，当 bool 标记用。
        //   row[i]!=0 表示「第 i 行要置零」。用 int 而非 vector<bool> 是官方原写法。
        vector<int> row(m), col(n);
        // 第一遍：扫描，写标记
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (!matrix[i][j]) {
                    row[i] = col[j] = true;
                }
            }
        }
        // 第二遍：据标记回填
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (row[i] || col[j]) {
                    matrix[i][j] = 0;
                }
            }
        }
    }
};
```

- 时间：O(m×n)
- 空间：O(m+n)

> 官方方法二（用首行首列当标记 + 两个 flag 变量 `flag_row0`/`flag_col0`）介于方法一和方法三之间，空间也是 O(1) 但多用一个变量；思路已在「Q2」里对比过，这里不再贴代码，正文主解直接用最优的方法三。
